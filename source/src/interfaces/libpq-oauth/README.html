src/interfaces/libpq-oauth/README
1libpq-oauth is an optional module implementing the Device Authorization flow for
2OAuth clients (RFC 8628). It is maintained as its own shared library in order to
3isolate its dependency on libcurl. (End users who don't want the Curl dependency
4can simply choose not to install this module.)
5
6If a connection string allows the use of OAuth, and the server asks for it, and
7a libpq client has not installed its own custom OAuth flow, libpq will attempt
8to delay-load this module using dlopen() and the following ABI. Failure to load
9results in a failed connection.
10
11= Load-Time ABI =
12
13As of v19, this module ABI is public and cannot change incompatibly without also
14changing the entry points. Both libpq and libpq-oauth must gracefully handle
15situations where the other library is of a different release version, past or
16future, since upgrades to the libraries may happen in either order.
17
18(Don't assume that package version dependencies from libpq-oauth to libpq will
19simplify the situation! Since libpq delay-loads libpq-oauth, we still have to
20handle cases where a long-running client application has a libpq that's older
21than a newly upgraded plugin.)
22
23The module exports the following symbol:
24
25- int pg_start_oauthbearer(PGconn *conn, PGoauthBearerRequestV2 *request);
26
27The module then behaves as if it had received a PQAUTHDATA_OAUTH_BEARER_TOKEN_V2
28request via the PQauthDataHook API, and it either fills in an existing token or
29populates the necessary callbacks for a token to be obtained asynchronously.
30(See the documentation for PGoauthBearerRequest.) The function returns zero on
31success and nonzero on failure.
32
33Additionally, libpq-oauth relies on libpq's libpq_gettext(), which must be
34injected by libpq using this initialization function before the flow is run:
35
36- void libpq_oauth_init(libpq_gettext_func gettext_impl);
37
38= Static Build =
39
40The static library libpq.a does not perform any dynamic loading. If the builtin
41flow is enabled, the application is expected to link against libpq-oauth.a to
42provide the necessary symbol, or else implement pg_start_oauthbearer() itself.
