17 <refnamediv>
18  <refname>CREATE PROPERTY GRAPH</refname>
19  <refpurpose>define a new SQL-property graph</refpurpose>
20 </refnamediv>
21
22 <refsynopsisdiv>
23<synopsis>
24CREATE [ TEMP | TEMPORARY ] PROPERTY GRAPH <replaceable class="parameter">name</replaceable>
25    [ {VERTEX|NODE} TABLES ( <replaceable class="parameter">vertex_table_definition</replaceable> [, ...] ) ]
26    [ {EDGE|RELATIONSHIP} TABLES ( <replaceable class="parameter">edge_table_definition</replaceable> [, ...] ) ]
27
28<phrase>where <replaceable class="parameter">vertex_table_definition</replaceable> is:</phrase>
29
30    <replaceable class="parameter">vertex_table_name</replaceable> [ AS <replaceable class="parameter">alias</replaceable> ] [ KEY ( <replaceable class="parameter">column_name</replaceable> [, ...] ) ] [ <replaceable class="parameter">element_table_label_and_properties</replaceable> ]
31
32<phrase>and <replaceable class="parameter">edge_table_definition</replaceable> is:</phrase>
33
34    <replaceable class="parameter">edge_table_name</replaceable> [ AS <replaceable class="parameter">alias</replaceable> ] [ KEY ( <replaceable class="parameter">column_name</replaceable> [, ...] ) ]
35        SOURCE [ KEY ( <replaceable class="parameter">column_name</replaceable> [, ...] ) REFERENCES ] <replaceable class="parameter">source_table</replaceable> [ ( <replaceable class="parameter">column_name</replaceable> [, ...] ) ]
36        DESTINATION [ KEY ( <replaceable class="parameter">column_name</replaceable> [, ...] ) REFERENCES ] <replaceable class="parameter">dest_table</replaceable> [ ( <replaceable class="parameter">column_name</replaceable> [, ...] ) ]
37        [ <replaceable class="parameter">element_table_label_and_properties</replaceable> ]
38
39<phrase>and <replaceable class="parameter">element_table_label_and_properties</replaceable> is either:</phrase>
40
41    NO PROPERTIES | PROPERTIES ALL COLUMNS | PROPERTIES ( { <replaceable class="parameter">expression</replaceable> [ AS <replaceable class="parameter">property_name</replaceable> ] } [, ...] )
42
43<phrase>or:</phrase>
44
45   { { LABEL <replaceable class="parameter">label_name</replaceable> | DEFAULT LABEL } [ NO PROPERTIES | PROPERTIES ALL COLUMNS | PROPERTIES ( { <replaceable class="parameter">expression</replaceable> [ AS <replaceable class="parameter">property_name</replaceable> ] } [, ...] ) ] } [...]
46</synopsis>

49 <refsect1>
50  <title>Description</title>
51
52  <para>
53   <command>CREATE PROPERTY GRAPH</command> defines a property graph.  A
54   property graph consists of vertices and edges, together called elements,
55   each with associated labels and properties, and can be queried using the
56   <literal>GRAPH_TABLE</literal> clause of <xref linkend="sql-select"/> with
57   a special path matching syntax.  The data in the graph is stored in regular
58   tables (or views, foreign tables, etc.).  Each vertex or edge corresponds
59   to a table.  The property graph definition links these tables together into
60   a graph structure that can be queried using graph query techniques.
61  </para>
62
63  <para>
64   <command>CREATE PROPERTY GRAPH</command> does not physically materialize a
65   graph.  It is thus similar to <command>CREATE VIEW</command> in that it
66   records a structure that is used only when the defined object is queried.
67  </para>
68
69  <para>
70   If a schema name is given (for example, <literal>CREATE PROPERTY GRAPH
71   myschema.mygraph ...</literal>) then the property graph is created in the
72   specified schema.  Otherwise it is created in the current schema.
73   Temporary property graphs exist in a special schema, so a schema name
74   cannot be given when creating a temporary property graph.  Property graphs
75   share a namespace with tables and other relation types, so the name of the
76   property graph must be distinct from the name of any other relation (table,
77   sequence, index, view, materialized view, or foreign table) in the same
78   schema.
79  </para>

82 <refsect1>
83  <title>Parameters</title>
84
85  <variablelist>
86   <varlistentry>
87    <term><replaceable class="parameter">name</replaceable></term>
88    <listitem>
89     <para>
90      The name (optionally schema-qualified) of the new property graph.
91     </para>
92    </listitem>
93   </varlistentry>
94
95   <varlistentry>
96    <term><literal>VERTEX</literal>/<literal>NODE</literal></term>
97    <term><literal>EDGE</literal>/<literal>RELATIONSHIP</literal></term>
98    <listitem>
99     <para>
100      These keywords are synonyms, respectively.
101     </para>
102    </listitem>
103   </varlistentry>
104
105   <varlistentry>
106    <term><replaceable class="parameter">vertex_table_name</replaceable></term>
107    <listitem>
108     <para>
109      The name of a table that will contain vertices in the new property
110      graph.
111     </para>
112    </listitem>
113   </varlistentry>
114
115   <varlistentry>
116    <term><replaceable class="parameter">edge_table_name</replaceable></term>
117    <listitem>
118     <para>
119      The name of a table that will contain edges in the new property graph.
120     </para>
121    </listitem>
122   </varlistentry>
123
124   <varlistentry>
125    <term><replaceable class="parameter">alias</replaceable></term>
126    <listitem>
127     <para>
128      A unique identifier for the vertex or edge table.  This defaults to the
129      name of the table.  Aliases must be unique in a property graph
130      definition (across all vertex table and edge table definitions).
131      (Therefore, if a table is used more than once as a vertex or edge table,
132      then an explicit alias must be specified for at least one of them to
133      distinguish them.)
134     </para>
135    </listitem>
136   </varlistentry>
137
138   <varlistentry>
139    <term><literal>KEY ( <replaceable class="parameter">column_name</replaceable> [, ...] )</literal></term>
140    <listitem>
141     <para>
142      A set of columns that uniquely identifies a row in the vertex or edge
143      table.  Defaults to the primary key.
144     </para>
145    </listitem>
146   </varlistentry>
147
148   <varlistentry>
149    <term><replaceable class="parameter">source_table</replaceable></term>
150    <term><replaceable class="parameter">dest_table</replaceable></term>
151    <listitem>
152     <para>
153      The vertex tables that the edge table is linked to.  These refer to the
154      aliases of the source and destination vertex tables respectively.
155     </para>
156    </listitem>
157   </varlistentry>
158
159   <varlistentry>
160    <term><literal>KEY ( <replaceable class="parameter">column_name</replaceable> [, ...] ) REFERENCES ... ( <replaceable class="parameter">column_name</replaceable> [, ...] )</literal></term>
161    <listitem>
162     <para>
163      Two sets of columns that connect the edge table and the source or
164      destination vertex table, like in a foreign-key relationship.  If a
165      foreign-key constraint between the two tables exists, it is used by
166      default.
167     </para>
168    </listitem>
169   </varlistentry>
170
171   <varlistentry>
172    <term><replaceable class="parameter">element_table_label_and_properties</replaceable></term>
173    <listitem>
174     <para>
175      Defines the labels and properties for the element (vertex or edge)
176      table.  Each element has at least one label.  By default, the label is
177      the same as the element table alias.  This can be specified explicitly
178      as <literal>DEFAULT LABEL</literal>.  Alternatively, one or more freely
179      chosen label names can be specified.  (Label names do not have to be
180      unique across a property graph.  It can be useful to assign the same
181      label to different elements.)  Each label has a list (possibly empty) of
182      properties.  By default, all columns of a table are automatically
183      exposed as properties.  This can be specified explicitly as
184      <literal>PROPERTIES ALL COLUMNS</literal>.  Alternatively, a list of
185      expressions, which can refer to the columns of the underlying table, can
186      be specified as properties.  If the expressions are not a plain column
187      reference, then an explicit property name must also be specified.
188     </para>
189    </listitem>
190   </varlistentry>
191  </variablelist>

194 <refsect1 id="sql-create-property-graph-notes">
195  <title>Notes</title>
196
197  <para>
198   The following consistency checks must be satisfied by a property graph definition:
199
200   <itemizedlist>
201    <listitem>
202     <para>
203      In a property graph, labels with the same name applied to different
204      property graph elements must have the same number of properties and
205      those properties must have the same names.  For example, the following
206      would be allowed:
207<programlisting>
208CREATE PROPERTY GRAPH g1
209    VERTEX TABLES (
210        v1 LABEL foo PROPERTIES (x, y),
211        v2 LABEL foo PROPERTIES (x, y)
212    ) ...
213</programlisting>
214      but this would not:
215<programlisting>
216CREATE PROPERTY GRAPH g1
217    VERTEX TABLES (
218        v1 LABEL foo PROPERTIES (x, y),
219        v2 LABEL foo PROPERTIES (z)
220    ) ...
221</programlisting></para>
222    </listitem>
223
224    <listitem>
225     <para>
226      In a property graph, all properties with the same name must have the
227      same data type, independent of which label they are on.  For example,
228      this would be allowed:
229<programlisting>
230CREATE TABLE v1 (a int, b int);
231CREATE TABLE v2 (a int, b int);
232
233CREATE PROPERTY GRAPH g1
234    VERTEX TABLES (
235        v1 LABEL foo PROPERTIES (a, b),
236        v2 LABEL bar PROPERTIES (a, b)
237    ) ...
238</programlisting>
239      but this would not:
240<programlisting>
241CREATE TABLE v1 (a int, b int);
242CREATE TABLE v2 (a int, b varchar);
243
244CREATE PROPERTY GRAPH g1
245    VERTEX TABLES (
246        v1 LABEL foo PROPERTIES (a, b),
247        v2 LABEL bar PROPERTIES (a, b)
248    ) ...
249</programlisting></para>
250    </listitem>
251
252    <listitem>
253     <para>
254      For each property graph element, all properties with the same name must
255      have the same expression for each label.  For example, this would be
256      allowed:
257<programlisting>
258CREATE PROPERTY GRAPH g1
259    VERTEX TABLES (
260        v1 LABEL foo PROPERTIES (a * 2 AS x) LABEL bar PROPERTIES (a * 2 AS x)
261    ) ...
262</programlisting>
263      but this would not:
264<programlisting>
265CREATE PROPERTY GRAPH g1
266    VERTEX TABLES (
267        v1 LABEL foo PROPERTIES (a * 2 AS x) LABEL bar PROPERTIES (a * 10 AS x)
268    ) ...
269</programlisting></para>
270    </listitem>
271
272   </itemizedlist>
273  </para>
274
275  <para>
276   Property graphs are queried using the <literal>GRAPH_TABLE</literal> clause
277   of <xref linkend="sql-select"/>.
278  </para>
279
280  <para>
281   Access to the base relations underlying the <literal>GRAPH_TABLE</literal>
282   clause is determined by the permissions of the user executing the query,
283   rather than the property graph owner. Thus, the user of a property graph must
284   have the relevant permissions on the property graph and base relations
285   underlying the <literal>GRAPH_TABLE</literal> clause.
286  </para>
287 </refsect1>

296    EDGE TABLES (e1 SOURCE v1 DESTINATION v2,
297                 e2 SOURCE v1 DESTINATION v3);
298</programlisting></para>
