38 <refsect1>
39  <title>Description</title>
40
41  <para>
42   <command>CREATE SCHEMA</command> enters a new schema
43   into the current database.
44   The schema name must be distinct from the name of any existing schema
45   in the current database.
46  </para>
47
48  <para>
49   A schema is essentially a namespace:
50   it contains named objects (tables, data types, functions, and operators)
51   whose names can duplicate those of other objects existing in other
52   schemas.  Named objects are accessed either by <quote>qualifying</quote>
53   their names with the schema name as a prefix, or by setting a search
54   path that includes the desired schema(s).  A <literal>CREATE</literal> command
55   specifying an unqualified object name creates the object
56   in the current schema (the one at the front of the search path,
57   which can be determined with the function <function>current_schema</function>).
58  </para>
59
60  <para>
61   Optionally, <command>CREATE SCHEMA</command> can include subcommands
62   to create objects within the new schema.  The subcommands are treated
63   essentially the same as separate commands issued after creating the
64   schema, except that if the <literal>AUTHORIZATION</literal> clause is used,
65   all the created objects will be owned by that user.
66  </para>
67 </refsect1>

69 <refsect1>
70  <title>Parameters</title>
71
72    <variablelist>
73     <varlistentry>
74      <term><replaceable class="parameter">schema_name</replaceable></term>
75      <listitem>
76       <para>
77        The name of a schema to be created.  If this is omitted, the
78        <replaceable class="parameter">user_name</replaceable>
79        is used as the schema name.  The name cannot
80        begin with <literal>pg_</literal>, as such names
81        are reserved for system schemas.
82       </para>
83      </listitem>
84     </varlistentry>
85
86     <varlistentry>
87      <term><replaceable class="parameter">user_name</replaceable></term>
88      <listitem>
89       <para>
90        The role name of the user who will own the new schema.  If omitted,
91        defaults to the user executing the command.  To create a schema
92        owned by another role, you must be able to
93        <literal>SET ROLE</literal> to that role.
94       </para>
95      </listitem>
96     </varlistentry>
97
98     <varlistentry>
99      <term><replaceable class="parameter">schema_element</replaceable></term>
100      <listitem>
101       <para>
102        An SQL statement defining an object to be created within the
103        schema. Currently, only
104        <command>CREATE AGGREGATE</command>,
105        <command>CREATE COLLATION</command>,
106        <command>CREATE DOMAIN</command>,
107        <command>CREATE FUNCTION</command>,
108        <command>CREATE INDEX</command>,
109        <command>CREATE OPERATOR</command>,
110        <command>CREATE PROCEDURE</command>,
111        <command>CREATE SEQUENCE</command>,
112        <command>CREATE TABLE</command>,
113        <command>CREATE TEXT SEARCH CONFIGURATION</command>,
114        <command>CREATE TEXT SEARCH DICTIONARY</command>,
115        <command>CREATE TEXT SEARCH PARSER</command>,
116        <command>CREATE TEXT SEARCH TEMPLATE</command>,
117        <command>CREATE TRIGGER</command>,
118        <command>CREATE TYPE</command>,
119        <command>CREATE VIEW</command>,
120        and <command>GRANT</command> are accepted as clauses
121        within <command>CREATE SCHEMA</command>. Other kinds of objects may
122        be created within the schema in separate commands after the schema
123        is created.
124       </para>
125      </listitem>
126     </varlistentry>
127
128     <varlistentry>
129      <term><literal>IF NOT EXISTS</literal></term>
130      <listitem>
131       <para>
132        Do nothing (except issuing a notice) if a schema with the same name
133        already exists.  <replaceable class="parameter">schema_element</replaceable>
134        subcommands cannot be included when this option is used.
135       </para>
136      </listitem>
137     </varlistentry>
138    </variablelist>

141 <refsect1>
142  <title>Notes</title>
143
144  <para>
145   To create a schema, the invoking user must have the
146   <literal>CREATE</literal> privilege for the current database.
147   (Of course, superusers bypass this check.)
148  </para>
149
150  <para>
151   The <replaceable class="parameter">schema_element</replaceable>
152   subcommands, if any, are executed in the order they are written.
153   An exception is that foreign key constraint clauses in <command>CREATE
154   TABLE</command> subcommands are postponed and added at the end.
155   This allows circular foreign key references, which are sometimes useful.
156  </para>
157 </refsect1>

159 <refsect1>
160  <title>Examples</title>
161
162  <para>
163   Create a schema:
164<programlisting>
165CREATE SCHEMA myschema;
166</programlisting>
167  </para>
168
169  <para>
170   Create a schema for user <literal>joe</literal>; the schema will also be
171   named <literal>joe</literal>:
172<programlisting>
173CREATE SCHEMA AUTHORIZATION joe;
174</programlisting>
175  </para>
176
177  <para>
178   Create a schema named <literal>test</literal> that will be owned by user
179   <literal>joe</literal>, unless there already is a schema named <literal>test</literal>.
180   (It does not matter whether <literal>joe</literal> owns the pre-existing schema.)
181<programlisting>
182CREATE SCHEMA IF NOT EXISTS test AUTHORIZATION joe;
183</programlisting>
184  </para>
185
186  <para>
187   Create a schema and create a table and view within it:
188<programlisting>
189CREATE SCHEMA hollywood
190    CREATE TABLE films (title text, release date, awards text[])
191    CREATE VIEW winners AS
192        SELECT title, release FROM films WHERE awards IS NOT NULL;
193</programlisting>
194   Notice that the individual subcommands do not end with semicolons.
195  </para>
196
197  <para>
198   The following is an equivalent way of accomplishing the same result:
199<programlisting>
200CREATE SCHEMA hollywood;
201CREATE TABLE hollywood.films (title text, release date, awards text[]);
202CREATE VIEW hollywood.winners AS
203    SELECT title, release FROM hollywood.films WHERE awards IS NOT NULL;
204</programlisting></para>
205

208 <refsect1>
209  <title>Compatibility</title>
210
211  <para>
212   The SQL standard allows a <literal>DEFAULT CHARACTER SET</literal> clause
213   in <command>CREATE SCHEMA</command>, as well as more subcommand
214   types than are presently accepted by
215   <productname>PostgreSQL</productname>.
216  </para>
217
218  <para>
219   Some other SQL implementations attempt to allow more kinds of forward
220   references to objects defined in
221   later <replaceable class="parameter">schema_element</replaceable>
222   subcommands than just foreign key constraints.  This is difficult or
223   impossible to do correctly in general, and it is not clear that the SQL
224   standard requires any such behavior except for foreign keys.
225  </para>
226
227  <para>
228   According to the SQL standard, the owner of a schema always owns
229   all objects within it.  <productname>PostgreSQL</productname>
230   allows schemas to contain objects owned by users other than the
231   schema owner.  This can happen only if the schema owner grants the
232   <literal>CREATE</literal> privilege on their schema to someone else, or a
233   superuser chooses to create objects in it.
234  </para>
235
236  <para>
237   The <literal>IF NOT EXISTS</literal> option is a
238   <productname>PostgreSQL</productname> extension.
239  </para>
