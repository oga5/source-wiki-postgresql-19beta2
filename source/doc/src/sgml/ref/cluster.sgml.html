17 <refnamediv>
18  <refname>CLUSTER</refname>
19  <refpurpose>cluster a table according to an index</refpurpose>
20 </refnamediv>
21
22 <refsynopsisdiv>
23<synopsis>
24CLUSTER [ ( <replaceable class="parameter">option</replaceable> [, ...] ) ] [ <replaceable class="parameter">table_name</replaceable> [ USING <replaceable class="parameter">index_name</replaceable> ] ]
25
26<phrase>where <replaceable class="parameter">option</replaceable> can be one of:</phrase>
27
28    VERBOSE [ <replaceable class="parameter">boolean</replaceable> ]
29</synopsis>
30 </refsynopsisdiv>
31
32 <refsect1>
33  <title>Description</title>
34
35  <para>
36   The <command>CLUSTER</command> command is equivalent to
37   <xref linkend="sql-repack"/> with a <literal>USING INDEX</literal>
38   clause.  See there for more details.
39  </para>
40 </refsect1>
41
42 <refsect1>
43  <title>Parameters</title>
44
45  <variablelist>
46   <varlistentry>
47    <term><replaceable class="parameter">table_name</replaceable></term>
48    <listitem>
49     <para>
50      The name (possibly schema-qualified) of a table.
51     </para>
52    </listitem>
53   </varlistentry>
54
55   <varlistentry>
56    <term><replaceable class="parameter">index_name</replaceable></term>
57    <listitem>
58     <para>
59      The name of an index.
60     </para>
61    </listitem>
62   </varlistentry>
63
64   <varlistentry>
65    <term><literal>VERBOSE</literal></term>
66    <listitem>
67     <para>
68      Prints a progress report as each table is clustered
69      at <literal>INFO</literal> level.
70     </para>
71    </listitem>
72   </varlistentry>
73
74   <varlistentry>
75    <term><replaceable class="parameter">boolean</replaceable></term>
76    <listitem>
77     <para>
78      Specifies whether the selected option should be turned on or off.
79      You can write <literal>TRUE</literal>, <literal>ON</literal>, or
80      <literal>1</literal> to enable the option, and <literal>FALSE</literal>,
81      <literal>OFF</literal>, or <literal>0</literal> to disable it.  The
82      <replaceable class="parameter">boolean</replaceable> value can also
83      be omitted, in which case <literal>TRUE</literal> is assumed.
84     </para>
85    </listitem>
86   </varlistentry>
87  </variablelist>

90 <refsect1>
91  <title>Notes</title>
92
93   <para>
94    To cluster a table, one must have the <literal>MAINTAIN</literal> privilege
95    on the table.
96   </para>
97
98   <para>
99    While <command>CLUSTER</command> is running, the <xref
100    linkend="guc-search-path"/> is temporarily changed to <literal>pg_catalog,
101    pg_temp</literal>.
102   </para>
103
104   <para>
105    Because <command>CLUSTER</command> remembers which indexes are clustered,
106    one can cluster the tables one wants clustered manually the first time,
107    then set up a periodic maintenance script that executes
108    <command>CLUSTER</command> without any parameters, so that the desired tables
109    are periodically reclustered.
110   </para>
111
112  <para>
113    Each backend running <command>CLUSTER</command> will report its progress
114    in the <structname>pg_stat_progress_cluster</structname> view. See
115    <xref linkend="cluster-progress-reporting"/> for details.
116  </para>
117
118   <para>
119    Clustering a partitioned table clusters each of its partitions using the
120    partition of the specified partitioned index.  When clustering a partitioned
121    table, the index may not be omitted.  <command>CLUSTER</command> on a
122    partitioned table cannot be executed inside a transaction block.
123   </para>
124
125 </refsect1>

127 <refsect1>
128  <title>Examples</title>
129
130  <para>
131   Cluster the table <structname>employees</structname> on the basis of
132   its index <literal>employees_ind</literal>:
133<programlisting>
134CLUSTER employees USING employees_ind;
135</programlisting>
136  </para>
137
138  <para>
139   Cluster the <structname>employees</structname> table using the same
140   index that was used before:
141<programlisting>
142CLUSTER employees;
143</programlisting>
144  </para>
145
146  <para>
147   Cluster all tables in the database that have previously been clustered:
148<programlisting>
149CLUSTER;
150</programlisting></para>
151 </refsect1>

153 <refsect1>
154  <title>Compatibility</title>
155
156  <para>
157   There is no <command>CLUSTER</command> statement in the SQL standard.
158  </para>
159
160  <para>
161   The following syntax was used before <productname>PostgreSQL</productname>
162   17 and is still supported:
163<synopsis>
164CLUSTER [ VERBOSE ] [ <replaceable class="parameter">table_name</replaceable> [ USING <replaceable class="parameter">index_name</replaceable> ] ]
165</synopsis>
166  </para>
167
168  <para>
169   The following syntax was used before <productname>PostgreSQL</productname>
170   8.3 and is still supported:
171<synopsis>
172CLUSTER <replaceable class="parameter">index_name</replaceable> ON <replaceable class="parameter">table_name</replaceable>
173</synopsis>
174  </para>
