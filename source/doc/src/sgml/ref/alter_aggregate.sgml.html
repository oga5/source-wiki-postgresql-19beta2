18  <refname>ALTER AGGREGATE</refname>
19  <refpurpose>change the definition of an aggregate function</refpurpose>

22 <refsynopsisdiv>
23<synopsis>
24ALTER AGGREGATE <replaceable>name</replaceable> ( <replaceable>aggregate_signature</replaceable> ) RENAME TO <replaceable>new_name</replaceable>

37 <refsect1>
38  <title>Description</title>
39
40  <para>
41   <command>ALTER AGGREGATE</command> changes the definition of an
42   aggregate function.
43  </para>
44
45  <para>
46   You must own the aggregate function to use <command>ALTER AGGREGATE</command>.
47   To change the schema of an aggregate function, you must also have
48   <literal>CREATE</literal> privilege on the new schema.
49   To alter the owner, you must be able to <literal>SET ROLE</literal> to the
50   new owning role, and that role must have <literal>CREATE</literal>
51   privilege on the aggregate function's schema.
52   (These restrictions enforce that altering
53   the owner doesn't do anything you couldn't do by dropping and recreating
54   the aggregate function.  However, a superuser can alter ownership of any
55   aggregate function anyway.)
56  </para>
57 </refsect1>

139 <refsect1>
140  <title>Notes</title>
141
142   <para>
143    The recommended syntax for referencing an ordered-set aggregate
144    is to write <literal>ORDER BY</literal> between the direct and aggregated
145    argument specifications, in the same style as in
146    <link linkend="sql-createaggregate"><command>CREATE AGGREGATE</command></link>.  However, it will also work to
147    omit <literal>ORDER BY</literal> and just run the direct and aggregated
148    argument specifications into a single list.  In this abbreviated form,
149    if <literal>VARIADIC "any"</literal> was used in both the direct and
150    aggregated argument lists, write <literal>VARIADIC "any"</literal> only once.
151   </para>
152 </refsect1>
153
154 <refsect1>
155  <title>Examples</title>
156
157  <para>
158   To rename the aggregate function <literal>myavg</literal> for type
159   <type>integer</type> to <literal>my_average</literal>:
160<programlisting>
161ALTER AGGREGATE myavg(integer) RENAME TO my_average;
162</programlisting>
163  </para>
164
165  <para>
166   To change the owner of the aggregate function <literal>myavg</literal> for type
167   <type>integer</type> to <literal>joe</literal>:
168<programlisting>
169ALTER AGGREGATE myavg(integer) OWNER TO joe;
170</programlisting>
171  </para>
172
173  <para>
174   To move the ordered-set aggregate <literal>mypercentile</literal> with
175   direct argument of type <type>float8</type> and aggregated argument
176   of type <type>integer</type> into schema <literal>myschema</literal>:
177<programlisting>
178ALTER AGGREGATE mypercentile(float8 ORDER BY integer) SET SCHEMA myschema;
179</programlisting>
180   This will work too:
181<programlisting>
182ALTER AGGREGATE mypercentile(float8, integer) SET SCHEMA myschema;
183</programlisting></para>
184 </refsect1>
185
186 <refsect1>
187  <title>Compatibility</title>
188
189  <para>
190   There is no <command>ALTER AGGREGATE</command> statement in the SQL
191   standard.
192  </para>
