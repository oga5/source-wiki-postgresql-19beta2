17 <refnamediv>
18  <refname>CREATE TABLE AS</refname>
19  <refpurpose>define a new table from the results of a query</refpurpose>
20 </refnamediv>
21
22 <refsynopsisdiv>
23<synopsis>
24CREATE [ <replaceable>persistence_mode</replaceable> ] TABLE [ IF NOT EXISTS ] <replaceable>table_name</replaceable>
25    [ ( <replaceable>column_name</replaceable> [, ...] ) ]
26    [ USING <replaceable class="parameter">method</replaceable> ]
27    [ WITH ( <replaceable class="parameter">storage_parameter</replaceable> [= <replaceable class="parameter">value</replaceable>] [, ... ] ) | WITHOUT OIDS ]
28    [ ON COMMIT { PRESERVE ROWS | DELETE ROWS | DROP } ]
29    [ TABLESPACE <replaceable class="parameter">tablespace_name</replaceable> ]
30    AS <replaceable>query</replaceable>
31    [ WITH [ NO ] DATA ]
32
33<phrase>where <replaceable>persistence_mode</replaceable> is:</phrase>
34
35{ [ GLOBAL | LOCAL ] { TEMPORARY | TEMP } } | UNLOGGED
36</synopsis>
37 </refsynopsisdiv>

39 <refsect1>
40  <title>Description</title>
41
42  <para>
43   <command>CREATE TABLE AS</command> creates a table and fills it
44   with data computed by a <command>SELECT</command> command.
45   The table columns have the
46   names and data types associated with the output columns of the
47   <command>SELECT</command> (except that you can override the column
48   names by giving an explicit list of new column names).
49  </para>
50
51  <para>
52   <command>CREATE TABLE AS</command> bears some resemblance to
53   creating a view, but it is really quite different: it creates a new
54   table and evaluates the query just once to fill the new table
55   initially.  The new table will not track subsequent changes to the
56   source tables of the query.  In contrast, a view re-evaluates its
57   defining <command>SELECT</command> statement whenever it is
58   queried.
59  </para>
60
61  <para>
62   <command>CREATE TABLE AS</command> requires <literal>CREATE</literal>
63   privilege on the schema used for the table.
64  </para>
65 </refsect1>

67 <refsect1>
68  <title>Parameters</title>
69
70  <variablelist>
71   <varlistentry>
72    <term><literal>GLOBAL</literal> or <literal>LOCAL</literal></term>
73    <listitem>
74     <para>
75      Ignored for compatibility.  Use of these keywords is deprecated;
76      refer to <xref linkend="sql-createtable"/> for details.
77     </para>
78    </listitem>
79   </varlistentry>
80  </variablelist>
81
82  <variablelist>
83   <varlistentry>
84    <term><literal>TEMPORARY</literal> or <literal>TEMP</literal></term>
85    <listitem>
86     <para>
87      If specified, the table is created as a temporary table.
88      Refer to <xref linkend="sql-createtable"/> for details.
89     </para>
90    </listitem>
91   </varlistentry>
92
93   <varlistentry>
94    <term><literal>UNLOGGED</literal></term>
95    <listitem>
96     <para>
97      If specified, the table is created as an unlogged table.
98      Refer to <xref linkend="sql-createtable"/> for details.
99     </para>
100    </listitem>
101   </varlistentry>
102
103   <varlistentry>
104    <term><literal>IF NOT EXISTS</literal></term>
105    <listitem>
106     <para>
107      Do not throw an error if a relation with the same name already
108      exists; simply issue a notice and leave the table unmodified.
109     </para>
110    </listitem>
111   </varlistentry>
112
113   <varlistentry>
114    <term><replaceable>table_name</replaceable></term>
115    <listitem>
116     <para>
117      The name (optionally schema-qualified) of the table to be created.
118     </para>
119    </listitem>
120   </varlistentry>
121
122   <varlistentry>
123    <term><replaceable>column_name</replaceable></term>
124    <listitem>
125     <para>
126      The name of a column in the new table.  If column names are not
127      provided, they are taken from the output column names of the query.
128     </para>
129    </listitem>
130   </varlistentry>
131
132   <varlistentry>
133    <term><literal>USING <replaceable class="parameter">method</replaceable></literal></term>
134    <listitem>
135     <para>
136      This optional clause specifies the table access method to use to store
137      the contents for the new table; the method needs be an access method of
138      type <literal>TABLE</literal>. See <xref linkend="tableam"/> for more
139      information.  If this option is not specified, the default table access
140      method is chosen for the new table. See <xref
141      linkend="guc-default-table-access-method"/> for more information.
142     </para>
143    </listitem>
144   </varlistentry>
145
146   <varlistentry>
147    <term><literal>WITH ( <replaceable class="parameter">storage_parameter</replaceable> [= <replaceable class="parameter">value</replaceable>] [, ... ] )</literal></term>
148    <listitem>
149     <para>
150      This clause specifies optional storage parameters for the new table;
151      see <xref linkend="sql-createtable-storage-parameters"/> in the
152      <xref linkend="sql-createtable"/> documentation for more
153      information.   For backward-compatibility the <literal>WITH</literal>
154      clause for a table can also include <literal>OIDS=FALSE</literal> to
155      specify that rows of the new table should contain no OIDs (object
156      identifiers), <literal>OIDS=TRUE</literal> is not supported anymore.
157     </para>
158    </listitem>
159   </varlistentry>
160
161   <varlistentry>
162    <term><literal>WITHOUT OIDS</literal></term>
163    <listitem>
164     <para>
165      This is backward-compatible syntax for declaring a table
166      <literal>WITHOUT OIDS</literal>, creating a table <literal>WITH
167      OIDS</literal> is not supported anymore.
168     </para>
169    </listitem>
170   </varlistentry>
171
172   <varlistentry>
173    <term><literal>ON COMMIT</literal></term>
174    <listitem>
175     <para>
176      The behavior of temporary tables at the end of a transaction
177      block can be controlled using <literal>ON COMMIT</literal>.
178      The three options are:
179
180      <variablelist>
181       <varlistentry>
182        <term><literal>PRESERVE ROWS</literal></term>
183        <listitem>
184         <para>
185          No special action is taken at the ends of transactions.
186          This is the default behavior.
187         </para>
188        </listitem>
189       </varlistentry>
190
191       <varlistentry>
192        <term><literal>DELETE ROWS</literal></term>
193        <listitem>
194         <para>
195          All rows in the temporary table will be deleted at the end
196          of each transaction block.  Essentially, an automatic <link
197          linkend="sql-truncate"><command>TRUNCATE</command></link> is done
198          at each commit.
199         </para>
200        </listitem>
201       </varlistentry>
202
203       <varlistentry>
204        <term><literal>DROP</literal></term>
205        <listitem>
206         <para>
207          The temporary table will be dropped at the end of the current
208          transaction block.
209         </para>
210        </listitem>
211       </varlistentry>
212      </variablelist></para>
213    </listitem>
214   </varlistentry>
215
216   <varlistentry>
217    <term><literal>TABLESPACE <replaceable class="parameter">tablespace_name</replaceable></literal></term>
218    <listitem>
219     <para>
220      The <replaceable class="parameter">tablespace_name</replaceable> is the name
221      of the tablespace in which the new table is to be created.
222      If not specified,
223      <xref linkend="guc-default-tablespace"/> is consulted, or
224      <xref linkend="guc-temp-tablespaces"/> if the table is temporary.
225     </para>
226    </listitem>
227   </varlistentry>
228
229   <varlistentry>
230    <term><replaceable>query</replaceable></term>
231    <listitem>
232     <para>
233      A <link linkend="sql-select"><command>SELECT</command></link>, <link
234      linkend="sql-table"><command>TABLE</command></link>, or <link linkend="sql-values"><command>VALUES</command></link>
235      command, or an <link linkend="sql-execute"><command>EXECUTE</command></link> command that runs a
236      prepared <command>SELECT</command>, <command>TABLE</command>, or
237      <command>VALUES</command> query.
238     </para>
239    </listitem>
240   </varlistentry>
241
242   <varlistentry>
243    <term><literal>WITH [ NO ] DATA</literal></term>
244    <listitem>
245     <para>
246      This clause specifies whether or not the data produced by the query
247      should be copied into the new table.  If not, only the table structure
248      is copied.  The default is to copy the data.
249     </para>
250    </listitem>
251   </varlistentry>
252
253  </variablelist>

256 <refsect1>
257  <title>Notes</title>
258
259  <para>
260   This command is functionally similar to <xref
261   linkend="sql-selectinto"/>, but it is
262   preferred since it is less likely to be confused with other uses of
263   the <command>SELECT INTO</command> syntax. Furthermore, <command>CREATE
264   TABLE AS</command> offers a superset of the functionality offered
265   by <command>SELECT INTO</command>.
266  </para>
267 </refsect1>
268
269 <refsect1>
270  <title>Examples</title>
271
272  <para>
273   Create a new table <structname>films_recent</structname> consisting of only
274   recent entries from the table <structname>films</structname>:
275
276<programlisting>
277CREATE TABLE films_recent AS
278  SELECT * FROM films WHERE date_prod &gt;= '2002-01-01';
279</programlisting>
280  </para>
281
282  <para>
283   To copy a table completely, the short form using
284   the <literal>TABLE</literal> command can also be used:
285
286<programlisting>
287CREATE TABLE films2 AS
288  TABLE films;
289</programlisting>
290  </para>
291
292  <para>
293   Create a new temporary table <structname>films_recent</structname>, consisting of
294   only recent entries from the table <structname>films</structname>, using a
295   prepared statement.  The new table will be dropped at commit:
296
297<programlisting>
298PREPARE recentfilms(date) AS
299  SELECT * FROM films WHERE date_prod &gt; $1;
300CREATE TEMP TABLE films_recent ON COMMIT DROP AS
301  EXECUTE recentfilms('2002-01-01');
302</programlisting></para>
303 </refsect1>

305 <refsect1>
306  <title>Compatibility</title>
307
308  <para>
309   <command>CREATE TABLE AS</command> conforms to the <acronym>SQL</acronym>
310   standard.  The following are nonstandard extensions:
311
312   <itemizedlist spacing="compact">
313    <listitem>
314     <para>
315      The standard requires parentheses around the subquery clause; in
316      <productname>PostgreSQL</productname>, these parentheses are
317      optional.
318     </para>
319    </listitem>
320
321    <listitem>
322     <para>
323      In the standard, the <literal>WITH [ NO ] DATA</literal> clause
324      is required; in PostgreSQL it is optional.
325     </para>
326    </listitem>
327
328    <listitem>
329     <para><productname>PostgreSQL</productname> handles temporary tables in a way
330      rather different from the standard; see
331      <xref linkend="sql-createtable"/>
332      for details.
333     </para>
334    </listitem>
335
336    <listitem>
337     <para>
338      The <literal>WITH</literal> clause is a <productname>PostgreSQL</productname>
339      extension; storage parameters are not in the standard.
340     </para>
341    </listitem>
342
343    <listitem>
344     <para>
345      The <productname>PostgreSQL</productname> concept of tablespaces is not
346      part of the standard.  Hence, the clause <literal>TABLESPACE</literal>
347      is an extension.
348     </para>
349    </listitem>
350   </itemizedlist></para>
