18  <refname>CHECKPOINT</refname>
19  <refpurpose>force a write-ahead log checkpoint</refpurpose>
20 </refnamediv>
21
22 <refsynopsisdiv>
23<synopsis>
24CHECKPOINT [ ( option [, ...] ) ]
25
26<phrase>where <replaceable class="parameter">option</replaceable> can be one of:</phrase>
27
28    FLUSH_UNLOGGED [ <replaceable class="parameter">boolean</replaceable> ]
29    MODE { FAST | SPREAD }
30</synopsis>
31 </refsynopsisdiv>
32
33 <refsect1>
34  <title>Description</title>
35
36  <para>
37   A checkpoint is a point in the write-ahead log sequence at which
38   all data files for permanent relations have been updated to reflect the
39   information in the log.  All data for permanent relation files will be
40   flushed to disk.  Dirty buffers of unlogged relations are not flushed unless
41   <literal>FLUSH_UNLOGGED</literal> is specified.  Refer to
42   <xref linkend="wal-configuration"/> for more details about what happens
43   during a checkpoint.
44  </para>
45
46  <para>
47   By default, the <command>CHECKPOINT</command> command forces a fast
48   checkpoint when the command is issued, without waiting for a
49   regular checkpoint scheduled by the system (controlled by the settings in
50   <xref linkend="runtime-config-wal-checkpoints"/>).
51   To request the checkpoint be spread over a longer interval, set the
52   <literal>MODE</literal> option to <literal>SPREAD</literal>.
53   <command>CHECKPOINT</command> is not intended for use during normal
54   operation.
55  </para>
56
57  <para>
58   The server may consolidate concurrently requested checkpoints.  Such
59   consolidated requests will contain a combined set of options.  For example,
60   if one session requests a fast checkpoint and another requests a spread
61   checkpoint, the server may combine those requests and perform one fast
62   checkpoint.
63  </para>
64
65  <para>
66   If executed during recovery, the <command>CHECKPOINT</command> command
67   will force a restartpoint (see <xref linkend="wal-configuration"/>)
68   rather than writing a new checkpoint.
69  </para>
70
71  <para>
72   Only superusers or users with the privileges of
73   the <xref linkend="predefined-role-pg-checkpoint"/>
74   role can call <command>CHECKPOINT</command>.
75  </para>
76 </refsect1>

78 <refsect1>
79  <title>Parameters</title>
80
81  <variablelist>
82   <varlistentry>
83    <term><literal>FLUSH_UNLOGGED</literal></term>
84    <listitem>
85     <para>
86      Normally, <command>CHECKPOINT</command> does not flush dirty buffers of
87      unlogged relations.  This option, which is disabled by default, enables
88      flushing unlogged relations to disk.
89     </para>
90    </listitem>
91   </varlistentry>
92
93   <varlistentry>
94    <term><literal>MODE</literal></term>
95    <listitem>
96     <para>
97      When set to <literal>FAST</literal>, which is the default, the requested
98      checkpoint will be completed as fast as possible, which may result in a
99      significantly higher rate of I/O during the checkpoint.
100     </para>
101     <para>
102      <literal>MODE</literal> can also be set to <literal>SPREAD</literal> to
103      request the checkpoint be spread over a longer interval (controlled via
104      the settings in <xref linkend="runtime-config-wal-checkpoints"/>), like a
105      regular checkpoint scheduled by the system.  This can reduce the rate of
106      I/O during the checkpoint.
107     </para>
108    </listitem>
109   </varlistentry>
110
111   <varlistentry>
112    <term><replaceable class="parameter">boolean</replaceable></term>
113    <listitem>
114     <para>
115      Specifies whether the selected option should be turned on or off.
116      You can write <literal>TRUE</literal>, <literal>ON</literal>, or
117      <literal>1</literal> to enable the option, and <literal>FALSE</literal>,
118      <literal>OFF</literal>, or <literal>0</literal> to disable it.  The
119      <replaceable class="parameter">boolean</replaceable> value can also
120      be omitted, in which case <literal>TRUE</literal> is assumed.
121     </para>
122    </listitem>
123   </varlistentry>
124  </variablelist>
125 </refsect1>
