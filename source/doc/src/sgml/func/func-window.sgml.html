2  <title>Window Functions</title>
3
4  <indexterm zone="functions-window">
5   <primary>window function</primary>
6   <secondary>built-in</secondary>
7  </indexterm>
8
9  <para>
10   <firstterm>Window functions</firstterm> provide the ability to perform
11   calculations across sets of rows that are related to the current query
12   row.  See <xref linkend="tutorial-window"/> for an introduction to this
13   feature, and <xref linkend="syntax-window-functions"/> for syntax
14   details.
15  </para>
16
17  <para>
18   The built-in window functions are listed in
19   <xref linkend="functions-window-table"/>.  Note that these functions
20   <emphasis>must</emphasis> be invoked using window function syntax, i.e., an
21   <literal>OVER</literal> clause is required.
22  </para>
23
24  <para>
25   In addition to these functions, any built-in or user-defined
26   ordinary aggregate (i.e., not ordered-set or hypothetical-set aggregates)
27   can be used as a window function; see
28   <xref linkend="functions-aggregate"/> for a list of the built-in aggregates.
29   Aggregate functions act as window functions only when an <literal>OVER</literal>
30   clause follows the call; otherwise they act as plain aggregates
31   and return a single row for the entire set.
32  </para>

233  <para>
234   All of the functions listed in
235   <xref linkend="functions-window-table"/> depend on the sort ordering
236   specified by the <literal>ORDER BY</literal> clause of the associated window
237   definition.  Rows that are not distinct when considering only the
238   <literal>ORDER BY</literal> columns are said to be <firstterm>peers</firstterm>.
239   The four ranking functions (including <function>cume_dist</function>) are
240   defined so that they give the same answer for all rows of a peer group.
241  </para>
242
243  <para>
244   Note that <function>first_value</function>, <function>last_value</function>, and
245   <function>nth_value</function> consider only the rows within the <quote>window
246   frame</quote>, which by default contains the rows from the start of the
247   partition through the last peer of the current row.  This is
248   likely to give unhelpful results for <function>last_value</function> and
249   sometimes also <function>nth_value</function>.  You can redefine the frame by
250   adding a suitable frame specification (<literal>RANGE</literal>,
251   <literal>ROWS</literal> or <literal>GROUPS</literal>) to
252   the <literal>OVER</literal> clause.
253   See <xref linkend="syntax-window-functions"/> for more information
254   about frame specifications.
255  </para>
256
257  <para>
258   When an aggregate function is used as a window function, it aggregates
259   over the rows within the current row's window frame.
260   An aggregate used with <literal>ORDER BY</literal> and the default window frame
261   definition produces a <quote>running sum</quote> type of behavior, which may or
262   may not be what's wanted.  To obtain
263   aggregation over the whole partition, omit <literal>ORDER BY</literal> or use
264   <literal>ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING</literal>.
265   Other frame specifications can be used to obtain other effects.
266  </para>
267
268  <para>
269   The <literal>null treatment</literal> option must be one of:
270<synopsis>
271RESPECT NULLS
272IGNORE NULLS
273</synopsis>
274   If unspecified, the default is <literal>RESPECT NULLS</literal> which includes NULL
275   values in any result calculation. <literal>IGNORE NULLS</literal> ignores NULL values.
276   This option is only allowed for the following functions: <function>lag</function>,
277   <function>lead</function>, <function>first_value</function>, <function>last_value</function>,
278   <function>nth_value</function>.
279  </para>
280
281  <note>
282   <para>
283    The SQL standard defines a <literal>FROM FIRST</literal> or <literal>FROM LAST</literal>
284    option for <function>nth_value</function>. This is not implemented in
285    <productname>PostgreSQL</productname>: only the default <literal>FROM FIRST</literal>
286    behavior is supported. (You can achieve the result of <literal>FROM LAST</literal> by
287    reversing the <literal>ORDER BY</literal>
288    ordering.)
289   </para>
290  </note>
