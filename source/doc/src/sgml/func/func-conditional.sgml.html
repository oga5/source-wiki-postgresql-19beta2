12  <para>
13   This section describes the <acronym>SQL</acronym>-compliant conditional expressions
14   available in <productname>PostgreSQL</productname>.
15  </para>
16
17  <tip>
18   <para>
19    If your needs go beyond the capabilities of these conditional
20    expressions, you might want to consider writing a server-side function
21    in a more expressive programming language.
22   </para>
23  </tip>
24
25   <note>
26    <para>
27     Although <token>COALESCE</token>, <token>GREATEST</token>, and
28     <token>LEAST</token> are syntactically similar to functions, they are
29     not ordinary functions, and thus cannot be used with explicit
30     <token>VARIADIC</token> array arguments.
31    </para>
32   </note>
33
34  <sect2 id="functions-case">
35   <title><literal>CASE</literal></title>
36
37  <para>
38   The <acronym>SQL</acronym> <token>CASE</token> expression is a
39   generic conditional expression, similar to if/else statements in
40   other programming languages:
41
42<synopsis>
43CASE WHEN <replaceable>condition</replaceable> THEN <replaceable>result</replaceable>
44     <optional>WHEN ...</optional>
45     <optional>ELSE <replaceable>result</replaceable></optional>
46END
47</synopsis>
48
49   <token>CASE</token> clauses can be used wherever
50   an expression is valid.  Each <replaceable>condition</replaceable> is an
51   expression that returns a <type>boolean</type> result.  If the condition's
52   result is true, the value of the <token>CASE</token> expression is the
53   <replaceable>result</replaceable> that follows the condition, and the
54   remainder of the <token>CASE</token> expression is not processed.  If the
55   condition's result is not true, any subsequent <token>WHEN</token> clauses
56   are examined in the same manner.  If no <token>WHEN</token>
57   <replaceable>condition</replaceable> yields true, the value of the
58   <token>CASE</token> expression is the <replaceable>result</replaceable> of the
59   <token>ELSE</token> clause.  If the <token>ELSE</token> clause is
60   omitted and no condition is true, the result is null.
61  </para>
62
63   <para>
64    An example:
65<screen>
66SELECT * FROM test;
67
68 a
69---
70 1
71 2
72 3
73
74
75SELECT a,
76       CASE WHEN a=1 THEN 'one'
77            WHEN a=2 THEN 'two'
78            ELSE 'other'
79       END
80    FROM test;
81
82 a | case
83---+-------
84 1 | one
85 2 | two
86 3 | other
87</screen>
88   </para>
89
90  <para>
91   The data types of all the <replaceable>result</replaceable>
92   expressions must be convertible to a single output type.
93   See <xref linkend="typeconv-union-case"/> for more details.
94  </para>
95
96  <para>
97   There is a <quote>simple</quote> form of <token>CASE</token> expression
98   that is a variant of the general form above:
99
100<synopsis>
101CASE <replaceable>expression</replaceable>
102    WHEN <replaceable>value</replaceable> THEN <replaceable>result</replaceable>
103    <optional>WHEN ...</optional>
104    <optional>ELSE <replaceable>result</replaceable></optional>
105END
106</synopsis>
107
108   The first
109   <replaceable>expression</replaceable> is computed, then compared to
110   each of the <replaceable>value</replaceable> expressions in the
111   <token>WHEN</token> clauses until one is found that is equal to it.  If
112   no match is found, the <replaceable>result</replaceable> of the
113   <token>ELSE</token> clause (or a null value) is returned.  This is similar
114   to the <function>switch</function> statement in C.
115  </para>
116
117   <para>
118    The example above can be written using the simple
119    <token>CASE</token> syntax:
120<screen>
121SELECT a,
122       CASE a WHEN 1 THEN 'one'
123              WHEN 2 THEN 'two'
124              ELSE 'other'
125       END
126    FROM test;
127
128 a | case
129---+-------
130 1 | one
131 2 | two
132 3 | other
133</screen>
134   </para>
135
136   <para>
137    A <token>CASE</token> expression does not evaluate any subexpressions
138    that are not needed to determine the result.  For example, this is a
139    possible way of avoiding a division-by-zero failure:
140<programlisting>
141SELECT ... WHERE CASE WHEN x &lt;&gt; 0 THEN y/x &gt; 1.5 ELSE false END;
142</programlisting>
143   </para>
144
145   <note>
146    <para>
147     As described in <xref linkend="syntax-express-eval"/>, there are various
148     situations in which subexpressions of an expression are evaluated at
149     different times, so that the principle that <quote><token>CASE</token>
150     evaluates only necessary subexpressions</quote> is not ironclad.  For
151     example a constant <literal>1/0</literal> subexpression will usually result in
152     a division-by-zero failure at planning time, even if it's within
153     a <token>CASE</token> arm that would never be entered at run time.
154    </para>
155   </note>

158  <sect2 id="functions-coalesce-nvl-ifnull">
159   <title><literal>COALESCE</literal></title>
160
161  <indexterm>
162   <primary>COALESCE</primary>
163  </indexterm>
164
165  <indexterm>
166   <primary>NVL</primary>
167  </indexterm>
168
169  <indexterm>
170   <primary>IFNULL</primary>
171  </indexterm>
172
173<synopsis>
174<function>COALESCE</function>(<replaceable>value</replaceable> <optional>, ...</optional>)
175</synopsis>
176
177  <para>
178   The <function>COALESCE</function> function returns the first of its
179   arguments that is not null.  Null is returned only if all arguments
180   are null.  It is often used to substitute a default value for
181   null values when data is retrieved for display, for example:
182<programlisting>
183SELECT COALESCE(description, short_description, '(none)') ...
184</programlisting>
185   This returns <varname>description</varname> if it is not null, otherwise
186   <varname>short_description</varname> if it is not null, otherwise <literal>(none)</literal>.
187  </para>
188
189   <para>
190    The arguments must all be convertible to a common data type, which
191    will be the type of the result (see
192    <xref linkend="typeconv-union-case"/> for details).
193   </para>
194
195   <para>
196    Like a <token>CASE</token> expression, <function>COALESCE</function> only
197    evaluates the arguments that are needed to determine the result;
198    that is, arguments to the right of the first non-null argument are
199    not evaluated.  This SQL-standard function provides capabilities similar
200    to <function>NVL</function> and <function>IFNULL</function>, which are used in some other
201    database systems.
202   </para>
203  </sect2>

205  <sect2 id="functions-nullif">
206   <title><literal>NULLIF</literal></title>
207
208  <indexterm>
209   <primary>NULLIF</primary>
210  </indexterm>
211
212<synopsis>
213<function>NULLIF</function>(<replaceable>value1</replaceable>, <replaceable>value2</replaceable>)
214</synopsis>
215
216  <para>
217   The <function>NULLIF</function> function returns a null value if
218   <replaceable>value1</replaceable> equals <replaceable>value2</replaceable>;
219   otherwise it returns <replaceable>value1</replaceable>.
220   This can be used to perform the inverse operation of the
221   <function>COALESCE</function> example given above:
222<programlisting>
223SELECT NULLIF(value, '(none)') ...
224</programlisting>
225   In this example, if <literal>value</literal> is <literal>(none)</literal>,
226   null is returned, otherwise the value of <literal>value</literal>
227   is returned.
228  </para>
229
230  <para>
231   The two arguments must be of comparable types.
232   To be specific, they are compared exactly as if you had
233   written <literal><replaceable>value1</replaceable>
234   = <replaceable>value2</replaceable></literal>, so there must be a
235   suitable <literal>=</literal> operator available.
236  </para>
237
238  <para>
239   The result has the same type as the first argument &mdash; but there is
240   a subtlety.  What is actually returned is the first argument of the
241   implied <literal>=</literal> operator, and in some cases that will have
242   been promoted to match the second argument's type.  For
243   example, <literal>NULLIF(1, 2.2)</literal> yields <type>numeric</type>,
244   because there is no <type>integer</type> <literal>=</literal>
245   <type>numeric</type> operator,
246   only <type>numeric</type> <literal>=</literal> <type>numeric</type>.
247  </para>
248

251  <sect2 id="functions-greatest-least">
252   <title><literal>GREATEST</literal> and <literal>LEAST</literal></title>
253
254  <indexterm>
255   <primary>GREATEST</primary>
256  </indexterm>
257  <indexterm>
258   <primary>LEAST</primary>
259  </indexterm>
260
261<synopsis>
262<function>GREATEST</function>(<replaceable>value</replaceable> <optional>, ...</optional>)
263</synopsis>
264<synopsis>
265<function>LEAST</function>(<replaceable>value</replaceable> <optional>, ...</optional>)
266</synopsis>
267
268   <para>
269    The <function>GREATEST</function> and <function>LEAST</function> functions select the
270    largest or smallest value from a list of any number of expressions.
271    The expressions must all be convertible to a common data type, which
272    will be the type of the result
273    (see <xref linkend="typeconv-union-case"/> for details).
274   </para>
275
276   <para>
277    NULL values in the argument list are ignored.  The result will be NULL
278    only if all the expressions evaluate to NULL.  (This is a deviation from
279    the SQL standard.  According to the standard, the return value is NULL if
280    any argument is NULL.  Some other databases behave this way.)
281   </para>
282  </sect2>
