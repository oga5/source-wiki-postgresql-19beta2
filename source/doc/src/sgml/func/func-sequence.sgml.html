2  <title>Sequence Manipulation Functions</title>
3
4  <indexterm>
5   <primary>sequence</primary>
6  </indexterm>
7
8  <para>
9   This section describes functions for operating on <firstterm>sequence
10   objects</firstterm>, also called sequence generators or just sequences.
11   Sequence objects are special single-row tables created with <xref
12   linkend="sql-createsequence"/>.
13   Sequence objects are commonly used to generate unique identifiers
14   for rows of a table.  The sequence functions, listed in <xref
15   linkend="functions-sequence-table"/>, provide simple, multiuser-safe
16   methods for obtaining successive sequence values from sequence
17   objects.
18  </para>

37        <indexterm>
38         <primary>nextval</primary>
39        </indexterm>
40        <function>nextval</function> ( <type>regclass</type> )
41        <returnvalue>bigint</returnvalue>
42       </para>
43       <para>
44        Advances the sequence object to its next value and returns that value.
45        This is done atomically: even if multiple sessions
46        execute <function>nextval</function> concurrently, each will safely
47        receive a distinct sequence value.
48        If the sequence object has been created with default parameters,
49        successive <function>nextval</function> calls will return successive
50        values beginning with 1.  Other behaviors can be obtained by using
51        appropriate parameters in the <xref linkend="sql-createsequence"/>
52        command.
53      </para>
54       <para>
55        This function requires <literal>USAGE</literal>
56        or <literal>UPDATE</literal> privilege on the sequence.
57       </para></entry>
58      </row>
59
60      <row>
61       <entry role="func_table_entry"><para role="func_signature">
62        <indexterm>
63         <primary>setval</primary>
64        </indexterm>
65        <function>setval</function> ( <type>regclass</type>, <type>bigint</type> <optional>, <type>boolean</type> </optional> )
66        <returnvalue>bigint</returnvalue>
67       </para>
68       <para>
69        Sets the sequence object's current value, and optionally
70        its <structfield>is_called</structfield> flag.  The two-parameter
71        form sets the sequence's <structfield>last_value</structfield> field to the
72        specified value and sets its <structfield>is_called</structfield> field to
73        <literal>true</literal>, meaning that the next
74        <function>nextval</function> will advance the sequence before
75        returning a value.  The value that will be reported
76        by <function>currval</function> is also set to the specified value.
77        In the three-parameter form, <structfield>is_called</structfield> can be set
78        to either <literal>true</literal>
79        or <literal>false</literal>.  <literal>true</literal> has the same
80        effect as the two-parameter form. If it is set
81        to <literal>false</literal>, the next <function>nextval</function>
82        will return exactly the specified value, and sequence advancement
83        commences with the following <function>nextval</function>.
84        Furthermore, the value reported by <function>currval</function> is not
85        changed in this case.  For example,
86<programlisting>
87SELECT setval('myseq', 42);           <lineannotation>Next <function>nextval</function> will return 43</lineannotation>
88SELECT setval('myseq', 42, true);     <lineannotation>Same as above</lineannotation>
89SELECT setval('myseq', 42, false);    <lineannotation>Next <function>nextval</function> will return 42</lineannotation>
90</programlisting>
91        The result returned by <function>setval</function> is just the value of its
92        second argument.
93       </para>
94       <para>
95        This function requires <literal>UPDATE</literal> privilege on the
96        sequence.
97       </para></entry>
98      </row>

101       <entry role="func_table_entry"><para role="func_signature">
102        <indexterm>
103         <primary>currval</primary>
104        </indexterm>
105        <function>currval</function> ( <type>regclass</type> )
106        <returnvalue>bigint</returnvalue>
107       </para>
108       <para>
109        Returns the value most recently obtained
110        by <function>nextval</function> for this sequence in the current
111        session.  (An error is reported if <function>nextval</function> has
112        never been called for this sequence in this session.)  Because this is
113        returning a session-local value, it gives a predictable answer whether
114        or not other sessions have executed <function>nextval</function> since
115        the current session did.
116       </para>
117       <para>
118        This function requires <literal>USAGE</literal>
119        or <literal>SELECT</literal> privilege on the sequence.
120       </para></entry>
121      </row>
122
123      <row>
124       <entry role="func_table_entry"><para role="func_signature">
125        <indexterm>
126         <primary>lastval</primary>
127        </indexterm>
128        <function>lastval</function> ()
129        <returnvalue>bigint</returnvalue>
130       </para>
131       <para>
132        Returns the value most recently returned by
133        <function>nextval</function> in the current session. This function is
134        identical to <function>currval</function>, except that instead
135        of taking the sequence name as an argument it refers to whichever
136        sequence <function>nextval</function> was most recently applied to
137        in the current session. It is an error to call
138        <function>lastval</function> if <function>nextval</function>
139        has not yet been called in the current session.
140       </para>
141       <para>
142        This function requires <literal>USAGE</literal>
143        or <literal>SELECT</literal> privilege on the last used sequence.
144       </para></entry>
145      </row>

148       <entry role="func_table_entry" id="func-pg-get-sequence-data"><para role="func_signature">
149        <indexterm>
150         <primary>pg_get_sequence_data</primary>
151        </indexterm>
152        <function>pg_get_sequence_data</function> ( <type>regclass</type> )
153        <returnvalue>record</returnvalue>
154        ( <parameter>last_value</parameter> <type>bigint</type>,
155        <parameter>is_called</parameter> <type>bool</type>,
156         <parameter>page_lsn</parameter> <type>pg_lsn</type> )
157       </para>
158       <para>
159        Returns information about the sequence.
160        <structfield>last_value</structfield> is the last sequence value
161        written to disk. If caching is used, this value can be greater than the
162        last value handed out from the sequence.
163        <structfield>is_called</structfield> indicates whether the sequence has
164        been used. <structfield>page_lsn</structfield> is the LSN corresponding
165        to the most recent WAL record that modified this sequence relation.
166        This function returns a row of NULL values if the specified relation
167        OID does not exist, if it is not a sequence, if the current user lacks
168        <literal>SELECT</literal> privilege on the sequence, if the sequence
169        is another session's temporary sequence, or if it is an unlogged
170        sequence on a standby server.
171       </para>
172       <para>
173        This function is primarily intended for internal use by pg_dump and by
174        logical replication to synchronize sequences.
175       </para></entry>

181  <caution>
182   <para>
183    To avoid blocking concurrent transactions that obtain numbers from
184    the same sequence, the value obtained by <function>nextval</function>
185    is not reclaimed for re-use if the calling transaction later aborts.
186    This means that transaction aborts or database crashes can result in
187    gaps in the sequence of assigned values.  That can happen without a
188    transaction abort, too.  For example an <command>INSERT</command> with
189    an <literal>ON CONFLICT</literal> clause will compute the to-be-inserted
190    tuple, including doing any required <function>nextval</function>
191    calls, before detecting any conflict that would cause it to follow
192    the <literal>ON CONFLICT</literal> rule instead.
193    Thus, <productname>PostgreSQL</productname> sequence
194    objects <emphasis>cannot be used to obtain <quote>gapless</quote>
195    sequences</emphasis>.
196   </para>
197
198   <para>
199    Likewise, sequence state changes made by <function>setval</function>
200    are immediately visible to other transactions, and are not undone if
201    the calling transaction rolls back.
202   </para>
203
204   <para>
205    If the database cluster crashes before committing a transaction
206    containing a <function>nextval</function>
207    or <function>setval</function> call, the sequence state change might
208    not have made its way to persistent storage, so that it is uncertain
209    whether the sequence will have its original or updated state after the
210    cluster restarts.  This is harmless for usage of the sequence within
211    the database, since other effects of uncommitted transactions will not
212    be visible either.  However, if you wish to use a sequence value for
213    persistent outside-the-database purposes, make sure that the
214    <function>nextval</function> call has been committed before doing so.
215   </para>
216  </caution>
217
218  <para>
219   The sequence to be operated on by a sequence function is specified by
220   a <type>regclass</type> argument, which is simply the OID of the sequence in the
221   <structname>pg_class</structname> system catalog.  You do not have to look up the
222   OID by hand, however, since the <type>regclass</type> data type's input
223   converter will do the work for you.  See <xref linkend="datatype-oid"/>
224   for details.
225  </para>
