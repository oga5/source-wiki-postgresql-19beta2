4 <title>spi &mdash; Server Programming Interface features/examples</title>
5
6 <indexterm zone="contrib-spi">
7  <primary>SPI</primary>
8  <secondary>examples</secondary>
9 </indexterm>
10
11 <para>
12  The <application>spi</application> module provides several workable examples
13  of using the <link linkend="spi">Server Programming Interface</link>
14  (<acronym>SPI</acronym>) and triggers.  While these functions are of
15  some value in
16  their own right, they are even more useful as examples to modify for
17  your own purposes.  The functions are general enough to be used
18  with any table, but you have to specify table and field names (as described
19  below) while creating a trigger.
20 </para>
21
22 <para>
23  Each of the groups of functions described below is provided as a
24  separately-installable extension.
25 </para>
26
27 <sect2 id="contrib-spi-refint">
28  <title>refint &mdash; Functions for Implementing Referential Integrity</title>
29
30  <para>
31   <function>check_primary_key()</function> and
32   <function>check_foreign_key()</function> are used to check foreign key constraints.
33   (This functionality is long since superseded by the built-in foreign
34   key mechanism, of course, but the module is still useful as an example.)
35  </para>
36
37  <note>
38   <para>
39    <filename>refint</filename> requires a
40    <link linkend="ddl-schemas-patterns">secure schema usage pattern</link> and
41    data types where the equality operator is named <literal>=</literal>.
42   </para>
43  </note>
44
45  <para>
46   <function>check_primary_key()</function> checks the referencing table.
47   To use, create an <literal>AFTER INSERT OR UPDATE</literal> trigger using this
48   function on a table referencing another table. Specify as the trigger
49   arguments: the referencing table's column name(s) which form the foreign
50   key, the referenced table name, and the column names in the referenced table
51   which form the primary/unique key.  To handle multiple foreign
52   keys, create a trigger for each reference.
53  </para>
54
55  <note>
56   <para>
57    The <emphasis>referenced</emphasis> table name and column name arguments to
58    <function>check_primary_key()</function> are copied as-is into internally
59    generated SQL statements and therefore must be double-quoted by the user as
60    necessary in the <command>CREATE TRIGGER</command> command.  See
61    <xref linkend="sql-syntax-identifiers"/> for more information about quoting
62    SQL identifiers.  Conversely, the <emphasis>referencing</emphasis> table
63    column name arguments should not be double quoted.  See the following mock
64    example of proper use of <function>check_primary_key()</function>:
65<programlisting>
66CREATE TRIGGER mytrigger
67AFTER INSERT OR UPDATE ON referencing_table
68FOR EACH ROW EXECUTE PROCEDURE
69check_primary_key (
70    'column A', 'column B',         -- referencing table columns
71    'myschema."referenced table"',  -- referenced table
72    '"column A"', '"column B"'      -- referenced table columns
73);
74</programlisting>
75   </para>
76  </note>
77
78  <para>
79   <function>check_foreign_key()</function> checks the referenced table.
80   To use, create an <literal>AFTER DELETE OR UPDATE</literal> trigger using this
81   function on a table referenced by other table(s).  Specify as the trigger
82   arguments: the number of referencing tables for which the function has to
83   perform checking, the action if a referencing key is found
84   (<literal>cascade</literal> &mdash; to delete the referencing row,
85   <literal>restrict</literal> &mdash; to abort transaction if referencing keys
86   exist, <literal>setnull</literal> &mdash; to set referencing key fields to null),
87   the referenced table's column names which form the primary/unique key, then
88   the referencing table name and column names (repeated for as many
89   referencing tables as were specified by first argument).  Note that the
90   primary/unique key columns should be marked NOT NULL and should have a
91   unique index.
92  </para>
93
94  <note>
95   <para>
96    The <emphasis>referencing</emphasis> table name and column name arguments
97    to <function>check_foreign_key()</function> are copied as-is into
98    internally generated SQL statements and therefore must be double-quoted by
99    the user as necessary in the <command>CREATE TRIGGER</command> command.
100    See <xref linkend="sql-syntax-identifiers"/> for more information about
101    quoting SQL identifiers.  Conversely, the <emphasis>referenced</emphasis>
102    table column name arguments should not be double quoted.  See the following
103    mock example of proper use of <function>check_foreign_key()</function>:
104<programlisting>
105CREATE TRIGGER mytrigger
106AFTER DELETE OR UPDATE ON referenced_table
107FOR EACH ROW EXECUTE PROCEDURE
108check_foreign_key (
109    1,                              -- number of referencing tables
110    'cascade',                      -- action
111    'column A', 'column B',         -- referenced table columns
112    'myschema."referencing table"', -- referencing table
113    '"column A"', '"column B"'      -- referencing table columns
114);
115</programlisting>
116   </para>
117  </note>
118
119  <para>
120   Note that if these triggers are executed from
121   another <literal>BEFORE</literal> trigger, they can fail unexpectedly. For
122   example, if a user inserts row1 and then the <literal>BEFORE</literal>
123   trigger inserts row2 and calls a trigger with the
124   <function>check_foreign_key()</function>,
125   the <function>check_foreign_key()</function>
126   function will not see row1 and will fail.
127  </para>
128
129  <para>
130   There are examples in <filename>refint.example</filename>.
131  </para>
132 </sect2>

134 <sect2 id="contrib-spi-autoinc">
135  <title>autoinc &mdash; Functions for Autoincrementing Fields</title>
136
137  <para>
138   <function>autoinc()</function> is a trigger that stores the next value of
139   a sequence into an integer field.  This has some overlap with the
140   built-in <quote>serial column</quote> feature, but it is not the same.
141   The trigger will replace the field's value only if that value is
142   initially zero or null (after the action of the SQL statement that
143   inserted or updated the row).  Also, if the sequence's next value is
144   zero, <function>nextval()</function> will be called a second time in
145   order to obtain a non-zero value.
146  </para>
147
148  <para>
149   To use, create a <literal>BEFORE INSERT</literal> (or optionally <literal>BEFORE
150   INSERT OR UPDATE</literal>) trigger using this function.  Specify two
151   trigger arguments: the name of the integer column to be modified,
152   and the name of the sequence object that will supply values.
153   (Actually, you can specify any number of pairs of such names, if
154   you'd like to update more than one autoincrementing column.)
155  </para>
156
157  <para>
158   There is an example in <filename>autoinc.example</filename>.
159  </para>
160
161 </sect2>

163 <sect2 id="contrib-spi-insert-username">
164  <title>insert_username &mdash; Functions for Tracking Who Changed a Table</title>
165
166  <para>
167   <function>insert_username()</function> is a trigger that stores the current
168   user's name into a text field.  This can be useful for tracking
169   who last modified a particular row within a table.
170  </para>
171
172  <para>
173   To use, create a <literal>BEFORE INSERT</literal> and/or <literal>UPDATE</literal>
174   trigger using this function.  Specify a single trigger
175   argument: the name of the text column to be modified.
176  </para>
177
178  <para>
179   There is an example in <filename>insert_username.example</filename>.
180  </para>
181
182 </sect2>

184 <sect2 id="contrib-spi-moddatetime">
185  <title>moddatetime &mdash; Functions for Tracking Last Modification Time</title>
186
187  <para>
188   <function>moddatetime()</function> is a trigger that stores the current
189   time into a <type>timestamp</type> field.  This can be useful for tracking
190   the last modification time of a particular row within a table.
191  </para>
192
193  <para>
194   To use, create a <literal>BEFORE UPDATE</literal>
195   trigger using this function.  Specify a single trigger
196   argument: the name of the column to be modified.
197   The column must be of type <type>timestamp</type> or <type>timestamp with
198   time zone</type>.
199  </para>
200
201  <para>
202   There is an example in <filename>moddatetime.example</filename>.
203  </para>
