目的

IndexPath（インデックススキャンおよびインデックスオンリースキャン）に対する起動コスト、総コスト、出力行数、および並列実行パラメータを算出します。

シグネチャまたは形状

  • シグネチャ: void cost_index(IndexPath *path, PlannerInfo *root, double loop_count, bool partial_path)

入力と出力

  • **引数**:
  • IndexPath *path: コスト、行数、並列ワーカー数などの計算結果を直接書き込む対象のインデックスパス構造体。
  • PlannerInfo *root: プランナのグローバル情報。
  • double loop_count: このインデックスパスが繰り返し実行される推定回数。
  • bool partial_path: このパスが並列実行用の部分パス（Partial Path）であるかどうかを示すフラグ。
  • **戻り値**: なし（path 構造体のメンバを直接書き換える）。

前提条件と不変条件

  • **対象リレーションの制限**:
  • 対象となるリレーション（baserel）はベースリレーションでなければならず、baserel->relid > 0 かつ baserel->rtekind == RTE_RELATION である必要があります。
  • baserel のノードタイプは RelOptInfo、index のノードタイプは IndexOptInfo でなければなりません。

アルゴリズムまたは振る舞い

1. **行数と修飾条件（qpquals）の特定**:

  • パスにパラメータ情報（path->path.param_info）が存在する場合は、出力行数（path->path.rows）に ppi_rows を設定し、リレーションの制限条件およびパラメータ化条件からインデックスに含まれない条件（qpquals）を抽出します。
  • パラメータ情報がない場合は、出力行数に baserel->rows を設定し、リレーションの制限条件のみから qpquals を抽出します。

    • 2. **無効化マスクの判定**:

  • スキャン種別（インデックスオンリースキャンか通常のインデックススキャンか）および部分パスフラグに基づいて enable_mask を構成し、ベースリレーションのマスク（baserel->pgs_mask）と比較して、無効化されている場合は path->path.disabled_nodes を 1 に、有効な場合は 0 に設定します。

    • 3. **インデックスアクセスメソッド固有のコスト見積もり**:

  • インデックスのアクセスメソッド固有のコスト見積もり関数（amcostestimate）を呼び出し、インデックス自体の起動コスト、総コスト、選択度、相関、およびインデックスページ数を取得します。
  • 取得した総コストと選択度を path->indextotalcost および path->indexselectivity に保存し、インデックス自体の起動コストと実行コストを全体のコストに加算します。

    • 4. **ヒープタプル・ページフェッチ数の算出とI/Oコスト評価**:

  • 選択度とベースリレーションのタプル数から tuples_fetched を算出し、clamp_row_est でクランプします。
  • テーブルスペースのページコスト（シーケンシャルおよびランダム）を取得します。
  • loop_count が 1 より大きい場合とそうでない場合で分岐し、Mackert-Lohman 公式（index_pages_fetched）や完全相関の場合の計算を行い、インデックスオンリースキャンの場合は可視性マップ（allvisfrac）に基づいてヒープフェッチ数を削減します。

    • 5. **並列ワーカー数の計算（部分パスの場合）**:

  • partial_path が有効な場合、compute_parallel_worker を呼び出して必要な並列ワーカー数を決定します。
  • ワーカー数が 0 以下である場合は、これ以上の計算を行わずに処理を終了（早期リターン）します。
  • ワーカー数が 1 以上の場合は、path->path.parallel_aware を true に設定します。

    • 6. **相関に基づくI/Oコストの補間**:

  • インデックスの相関の二乗（csquared）を用いて、最大I/Oコスト（無相関）と最小I/Oコスト（完全相関）の間を線形補間し、実行コスト（run_cost）に加算します。

    • 7. **CPUコストとターゲット評価コストの加算**:

  • cost_qual_eval を用いて qpquals の評価コストを算出し、起動コストおよびタプルごとのCPUコストに加算します。
  • パスに付随するターゲットリスト（pathtarget）のコストを加算します。

    • 8. **並列処理の補正と最終コストの格納**:

  • 並列ワーカーが使用される場合、get_parallel_divisor を用いて出力行数とCPU実行コストを分割・調整します。
  • 最終的な起動コストと総コストを path->path.startup_cost および path->path.total_cost に書き込みます。

失敗モードと境界条件

  • **アサーションによる強制終了**:
  • 渡された baserel または index が適切なノードタイプ（RelOptInfo / IndexOptInfo）でない場合、または baserel->relid <= 0 もしくは baserel->rtekind != RTE_RELATION の場合は、アサーション（Assert）によりプロセスが強制終了します。
  • **並列ワーカー割り当て不可による早期リターン**:
  • partial_path が true のとき、compute_parallel_worker の結果が 0 以下（並列ワーカーを割り当てられない）と判定された場合、関数はコストや行数の計算を完了せずにその場で早期リターンします。この場合、パスのコストや行数は未設定または不完全な状態のままとなり、呼び出し元でこのパスが破棄されることを前提としています。
  • **インデックスオンリースキャンにおける並列度判定の境界調整**:
  • indexonly（インデックスオンリースキャン）かつ partial_path が有効な場合、ヒープからフェッチするページ数が極めて小さくなり、並列実行が不当に除外されるのを防ぐため、rand_heap_pages を -1 に設定して compute_parallel_worker に渡します。
  • **可視性マップによるページフェッチ数のゼロクランプ**:
  • indexonly の場合、pages_fetched に (1.0 - baserel->allvisfrac) を乗算して ceil で切り上げます。もし allvisfrac が 1.0（すべてのヒープページが可視）の場合、pages_fetched は 0 にクランプされ、最小I/Oコスト（min_IO_cost）も 0 に設定されます。
  • **ループ回数によるI/Oコスト計算の分岐**:
  • loop_count > 1 の場合、複数回スキャンによるキャッシュ効果を考慮して index_pages_fetched に tuples_fetched * loop_count を渡してスケールアップした後に loop_count で除算してプロレート（按分）します。一方、loop_count <= 1 の場合は、完全相関時の最小I/Oコストとして、最初の1ページに spc_random_page_cost を適用し、残りのページに spc_seq_page_cost を適用する補正を行います。
