定義

  • 種別: 列挙値（pushdown_safe_type の一員）
  • 定義箇所: src/backend/optimizer/path/allpaths.c

目的

サブクエリに対するクエリ条件（修飾句）のプッシュダウン安全性評価において、通常の WHERE 句などへのプッシュダウンは安全ではないものの、WindowClause の実行条件（ランコンディション）としてであれば適用可能であることを示す。

シグネチャまたは形状

/* allpaths.c 内の pushdown_safe_type 列挙型で定義される定数 */
PUSHDOWN_WINDOWCLAUSE_RUNCOND

入力と出力

  • 入力: なし（静的定数のため、直接の入力引数は存在しない）。
  • 出力: サブクエリのプッシュダウン安全性を評価する関数（subquery_is_pushdown_safe など）の戻り値として、pushdown_safe_type 型の評価結果を返す。

前提条件と不変条件

  • 本値が選択される前提として、評価対象の条件が通常のプッシュダウンに対しては「不安全（unsafe）」と判定されている必要がある。
  • WindowClause の実行条件として機能するためには、特定の不安全フラグ（例: UNSAFE_NOTIN_PARTITIONBY_CLAUSE など）の組み合わせや、ウィンドウ関数の評価順序に依存する制約を満たしている必要がある。

アルゴリズムまたは振る舞い

  • サブクエリのプッシュダウン可否を判定する際、ターゲットリストの列や条件の性質を検証する。
  • 通常の WHERE 句へのプッシュダウンが不安全と判断された場合でも、条件が WindowClause の実行条件として適合可能であれば、判定結果として PUSHDOWN_WINDOWCLAUSE_RUNCOND を設定する。
  • 呼び出し側（allpaths.c 内のパス生成処理など）は、この返り値を受け取った場合、通常のプッシュダウン処理（subquery_push_qual など）をスキップし、ウィンドウ関数の実行条件としての適用ルートへ処理を分岐させる。

関連データ構造

  • pushdown_safe_type (列挙型)
  • pushdown_safety_info (構造体)

失敗モードと境界条件

  • 通常のプッシュダウンとの混同: オプティマイザが PUSHDOWN_WINDOWCLAUSE_RUNCOND を PUSHDOWN_SAFE と同様に扱い、通常の WHERE 句としてサブクエリにプッシュダウンしてしまうと、ウィンドウ関数の計算前にフィルタが適用されてしまい、結果の整合性が失われる。
  • 致命的な不安全フラグの無視: pushdown_safety_info において、揮発性関数（UNSAFE_HAS_VOLATILE_FUNC）やセットを返す関数（UNSAFE_HAS_SET_FUNC）などの致命的な不安全フラグがセットされている場合、この境界条件は適用できず、完全に不安全（PUSHDOWN_UNSAFE）として扱われなければならない。
  • 型不一致（UNSAFE_TYPE_MISMATCH）: ターゲットリストと条件の型が一致しない場合など、実行条件としても適用できない境界条件が存在し、その場合はプッシュダウンが完全に拒否される。
