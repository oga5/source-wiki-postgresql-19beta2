目的

パーティション分割された2つの結合元リレーションの間で、対応する子パーティション同士の結合（パーティションワイズ結合）を調整し、子結合リレーションの探索やパスの生成を行う。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーのグローバル情報。
  • RelOptInfo *rel1: 1つ目の結合元リレーション。
  • RelOptInfo *rel2: 2つ目の結合元リレーション。
  • RelOptInfo *joinrel: 対象となる親の結合リレーション。
  • SpecialJoinInfo *parent_sjinfo: 親結合の特殊結合情報（アウタージョインなど）。
  • List *parent_restrictlist: 親結合に適用される制限条項のリスト。
  • 戻り値: なし（void）

前提条件と不変条件

  • 再帰呼び出しや深層パーティション階層によるスタックオーバーフローを防ぐため、実行開始時に check_stack_depth() を呼び出す。
  • 結合リレーションのパーティションスキームが未定義であるかパーティション数が0の場合は何も行わずにリターンする。
  • 結合リレーションおよび両方の結合元リレーションにおいて、パーティションワイズ結合の考慮フラグ（consider_partitionwise_join）が有効であること、かつ双方のリレーションがパーティション化されている必要がある。
  • 結合元リレーション同士が重複するリレーション集合（relids）を持ってはならない。

アルゴリズムまたは振る舞い

1. 初期チェックと境界設定:

  • スタック深度を検証した後、結合リレーションおよび結合元リレーションがパーティションワイズ結合の条件を満たしているかをアサーションやガード条件で検証する。
  • compute_partition_bounds を呼び出して、両リレーションのパーティション境界を計算し、parts1 と parts2 のリストを取得する。
  • パーティション境界がマージされている場合は、リストの先頭セルを反復用のポインタとして保持する。

2. 各パーティションペアに対するループ処理:

  • joinrel->nparts の回数だけループを回し、各子パーティションのペア（child_rel1 と child_rel2）を順次取得する。
  • 子リレーションの一方または双方が空（またはダミーリレーション）である場合、親の結合タイプ（JOIN_INNER、JOIN_SEMI、JOIN_LEFT、JOIN_ANTI、JOIN_FULL）に基づいて、該当する結合セグメントをスキップするか判定する。予期しない結合タイプの場合はエラーとする。
  • 子リレーションのいずれかが完全にプッシュダウンなどで消失して NULL となっている場合は、パーティションワイズ結合を継続できないため、親 joinrel のパーティション数 nparts を 0 に設定して関数を終了する。
  • 単純リレーション側の子リレーションでパーティションワイズ結合が考慮されない設定（ダミーリレーション等）の場合は、同様に nparts を 0 に設定して失敗とする。

3. 子結合リレーションの構築とパス生成:

  • build_child_join_sjinfo を用いて、親の SpecialJoinInfo から子結合用の child_sjinfo を構築する。
  • find_appinfos_by_relids と adjust_appendrel_attrs を用いて、親の制限リストを子結合用に調整する。
  • 子結合の RelOptInfo（child_joinrel）が存在しない場合は、build_child_join_rel を呼び出して新しく構築し、親の part_rels、live_parts、all_partrels を更新する。
  • グループ化結合関係が必要な場合は make_grouped_join_rel を呼び出して構築する。
  • populate_joinrel_with_paths を呼び出して、子結合リレーションに対するパスを追加する。

4. メモリの解放:

  • 数千に及ぶパーティションが存在する場合のメモリ圧迫を防ぐため、ループの各反復の末尾で、appinfos の解放、child_relids のビットマップ解放、および free_child_join_sjinfo による子用特殊結合情報の解放を確実に行う。

失敗モードと境界条件

  • パーティション分割された結合リレーションの part_scheme が不一致であるか、あるいは結合元リレーションのいずれかがパーティション化されていない場合、処理は何もせずに早期リターンする。
  • サポートされていない結合タイプ（parent_sjinfo->jointype）に遭遇した場合、elog(ERROR, ...) によりエラーが送出される。
