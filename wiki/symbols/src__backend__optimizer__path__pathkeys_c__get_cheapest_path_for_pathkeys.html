目的

指定されたパスキーリストやパラメータ制約、並行性要件を満たす候補パス群 (paths) の中から、コスト基準 (cost_criterion) に従って最も安価なパスを選択して返す。

シグネチャまたは形状

  • シグネチャ: Path * get_cheapest_path_for_pathkeys(List *paths, List *pathkeys, Relids required_outer, CostSelector cost_criterion, bool require_parallel_safe)

入力と出力

  • 引数:
  • List *paths: 評価対象となる Path 構造体のリスト。
  • List *pathkeys: 満たすべき順序要件を表すパスキーのリスト。
  • Relids required_outer: 許容される外部パラメータ（リレーションIDの集合）。
  • CostSelector cost_criterion: コスト比較に用いる基準（開始コストまたは総コスト）。
  • bool require_parallel_safe: 真の場合、並行安全 (parallel_safe) でないパスを厳格に除外する。
  • 戻り値:
  • Path *: 条件を満たし、かつこれまでの最安値より安価であった最適な Path ポインタ。条件を満たすパスが存在しない場合は NULL。

前提条件と不変条件

  • 各候補パスの path->pathkeys および要求される pathkeys が正しく構成されていること。
  • 既にマッチしたパスが存在する場合、後続の候補パスがそれよりも安価であるかどうかの判定に compare_path_costs が用いられる。

アルゴリズムまたは振る舞い

1. matched_path を NULL に初期化する。 2. paths リストの各要素を foreach ループで走査する。 3. 各候補パス (Path *path) について、require_parallel_safe が真かつ path->parallel_safe が偽である場合は、該当パスをスキップする。 4. 既に matched_path が見つかっている場合、コスト比較 (compare_path_costs(matched_path, path, cost_criterion) <= 0) を行い、新しいパスのコストが既存の matched_path と同等かそれより高価である場合はスキップする（コスト比較をパスキー比較より先に実行する）。 5. pathkeys_contained_in(pathkeys, path->pathkeys) により、候補パスのパスキーが要求されたパスキー群を含んでいるかを検証する。 6. さらに bms_is_subset(PATH_REQ_OUTER(path), required_outer) により、外部リレーションの要求が制約内に収まっているかを検証する。 7. 上記の条件をすべて満たした場合、matched_path を現在の path に更新する。 8. ループ終了後、最終的に選択された matched_path を返す。

失敗モードと境界条件

  • 条件に一致するパスが paths 内に一つも存在しない、あるいはすべてのパスが並行安全性や外部リレーションの制約、パスキー包含条件のいずれかで弾かれた場合、戻り値は NULL となる。

保守担当者向けメモ

  • コスト比較はパスキーの比較よりも計算コストが低いため、処理効率を最適化する順序として先にコスト評価が行われている。
