目的

テーブルサンプル句（tablesample）を持つベースリレーションのサンプルスキャンパスに対する起動コスト、総コスト、および出力行数を算出します。

入力と出力

  • 引数:
  • Path *path: コストと行数を設定する対象のパス構造体
  • PlannerInfo *root: プランナーのグローバル情報
  • RelOptInfo *baserel: 対象のベースリレーション情報
  • ParamPathInfo *param_info: パラメータ化されたパスの情報（存在する場合）
  • 戻り値: なし（引数の path フィールドを直接書き換えます）

前提条件と不変条件

  • 対象の baserel のリレーションID（relid）が 0 より大きく、対応する範囲変数エントリが RTE_RELATION かつ tablesample 句を持つこと。
  • サンプル句のハンドラから取得した TsmRoutine が有効であること。

アルゴリズムまたは振る舞い

1. **前提の検証と取得**: アサーションによりベースリレーションとテーブルサンプル句の存在を確認し、GetTsmRoutine を介してサンプリングメソッドのルーチン構造体を取得します。 2. **行数の設定**: param_info が指定されている場合は param_info->ppi_rows を、そうでない場合は baserel->rows を path->rows に設定します。 3. **ページコストの決定**: テーブルスペースのページコスト（ランダムおよびシーケンシャル）を取得し、サンプリングメソッドが NextSampleBlock を使用する場合はランダムページコスト、それ以外の場合はシーケンシャルページコストを spc_page_cost とします。 4. **ディスクコストの計算**: サンプリングメソッドが訪問するページ数（baserel->pages）と spc_page_cost を乗算して run_cost に加算します。 5. **CPUコストの計算**: 制限条件の評価コストを get_restriction_qual_cost で取得し、起動コストとタプルあたりのCPUコスト（cpu_tuple_cost + qpqual_cost.per_tuple）を算出して run_cost に加算します。 6. **ターゲットリストと有効性の評価**: ターゲットリストの評価コストを起動コストおよび総コストに反映させ、並列ワーカー数やベースリレーションのマスク情報に基づき path->disabled_nodes を設定した後、最終的な startup_cost と total_cost を path に書き込みます。

失敗モードと境界条件

  • baserel->relid が 0 以下である場合や、対応する RangeTblEntry が存在しない、または tablesample が NULL の場合はアサーション違反により失敗します。
