目的

パーティションテーブルの範囲テーブルエントリ（RTE）を再帰的に展開し、生存するパーティションごとに子オブジェクト（RTE、AppendRelInfo、RelOptInfo）の構築やパーティションプルーニングを行う。

シグネチャまたは形状

  • シグネチャ: static void expand_partitioned_rtentry(PlannerInfo *root, RelOptInfo *relinfo, RangeTblEntry *parentrte, Index parentRTindex, Relation parentrel, Bitmapset *parent_updatedCols, PlanRowMark *top_parentrc, LOCKMODE lockmode)

入力と出力

  • 引数:
  • root: プランナ全体の情報が格納されている PlannerInfo 構造体へのポインタ。
  • relinfo: 親リレーションのオプティマイザ情報が格納されている RelOptInfo 構造体へのポインタ。
  • parentrte: 親テーブルの範囲テーブルエントリ（RangeTblEntry）。
  • parentRTindex: 親リレーションの範囲テーブルインデックス（Index）。
  • parentrel: 親リレーションの Relation 構造体。
  • parent_updatedCols: 親リレーションにおける更新対象列のビットマップ（Bitmapset）。
  • top_parentrc: 行マーク情報が格納されている PlanRowMark。
  • lockmode: リレーションオープン時に取得するロックモード（LOCKMODE）。
  • 戻り値: なし（void）

前提条件と不変条件

  • parentrte->inh が真であること。
  • パーティションテーブルにはパーティション記述子（PartitionDesc）が存在すること。
  • relinfo->part_rels が初期状態では NULL であること。

アルゴリズムまたは振る舞い

1. スタック深度のチェック（check_stack_depth）を行う。 2. パーティションディレクトリから親リレーションのパーティション記述子（partdesc）を取得し、存在することを確認する。 3. パーティション数が 0 の場合はそのまま終了する。 4. 親リレーションに割り当てられた制限条件を用いてパーティションプルーニング（prune_append_rel_partitions）を実行し、生存するパーティションのインデックスを relinfo->live_parts に格納する。 5. 生存するパーティションが存在する場合、プランナ配列（expand_planner_arrays）を拡張し、親リレーションの relinfo->part_rels にパーティション用 RelOptInfo ポインタ配列領域を確保する。 6. relinfo->live_parts に含まれる各パーティションについて、次の処理をループで実行する：

  • パーティションを try_table_open でオープンする。失敗（切り離し・削除済みなど）した場合は生存パーティションから除外して続行する。
  • 他セッションの一時リレーションである場合はエラーとする。
  • expand_single_inheritance_child を呼び出して子 RTE、AppendRelInfo、必要に応じ PlanRowMark を作成する。
  • build_simple_rel を呼び出して子リレーションの RelOptInfo を構築し、親の part_rels と all_partrels に登録する。
  • 子リレーションがさらにパーティションテーブルである場合、列権限を変換した上で expand_partitioned_rtentry を再帰的に呼び出す。
  • ロックを保持したまま子リレーションをクローズする（table_close(childrel, NoLock)）。

失敗モードと境界条件

  • パーティションが最近デタッチされてドロップされた場合、try_table_open が失敗し NULL を返すため、当該パーティションは生存リストから除外されて処理がスキップされる。
  • 他セッションのテンポラリリレーションがパーティションとして検出された場合は、elog(ERROR) によりエラー終了する。
