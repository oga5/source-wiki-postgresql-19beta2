目的

指定されたベースリレーションの有効な外部キー制約をリレーションキャッシュから抽出し、クエリ内の参照先レンジテーブルエントリ（RTE）と照合した上で、プランナが結合最適化に利用する ForeignKeyOptInfo 構造体を構築して PlannerInfo->fkey_list に追加します。

シグネチャまたは形状

  • シグネチャ: static void get_relation_foreign_keys(PlannerInfo *root, RelOptInfo *rel, Relation relation, bool inhparent)

入力と出力

  • 引数:
  • PlannerInfo *root: プラン全体の情報を保持する構造体ポインタ。新しく生成された ForeignKeyOptInfo が root->fkey_list に追加されます。
  • RelOptInfo *rel: 対象リレーションのプランナ用最適化情報構造体。
  • Relation relation: 対象リレーションのリレーションキャッシュ構造体。
  • bool inhparent: 対象が継承ツリーの親テーブルであるかを示すフラグ。
  • 戻り値: なし（void）

前提条件と不変条件

  • 対象リレーションが基本リレーション（RELOPT_BASEREL）であり、かつクエリのレンジテーブル（rtable）に2つ以上のエントリが存在する場合のみ処理を行います。
  • 継承ツリーの親テーブル（inhparent が真）である場合は、外部キー情報の抽出を行わずに即座にリターンします。
  • キャッシュから取得した外部キーの制約関係元 ID（conrelid）は、常に処理対象の relation の OID と一致していなければなりません。

アルゴリズムまたは振る舞い

1. **早期リターン判定**:

  • rel->reloptkind が RELOPT_BASEREL でない場合、またはクエリの rtable 長が 2 未満である場合は処理を終了します。
  • inhparent が真である場合も処理を終了します。

    • 2. **外部キー一覧の取得**:

  • RelationGetFKeyList(relation) を呼び出して、リレーションキャッシュから該当リレーションの外部キーキャッシュリスト（cachedfkeys）を取得します。

    • 3. **外部キーの走査と照合**:

  • 取得した cachedfkeys の各要素についてループを開始します。
  • 制約が現在有効化されていない場合（!cachedfk->conenforced）はスキップします。
  • クエリの rtable を走査し、参照先テーブル（confrelid）に一致し、かつ継承親（rte->inh）ではなく、自身との自己結合（rti == rel->relid）ではない有効な RTE を検索します。

    • 4. **ForeignKeyOptInfo の構築と登録**:

  • 条件に一致する RTE が見つかった場合、makeNode(ForeignKeyOptInfo) で新規ノードを割り当てます。
  • 制限元・参照元のリレーション ID、キー数、およびキー列・演算子の配列データを memcpy でコピーします。
  • 一致・定数カウンタや等価クラスなどのフィールドをゼロクリアします。
  • 作成した ForeignKeyOptInfo を root->fkey_list に lappend で追加します。

失敗モードと境界条件

  • キャッシュから取得した外部キーリストはリレーションキャッシュに属しているため、キャッシュフラッシュによって消去される可能性があります。そのため、本関数内での追加のカタログアクセスは禁止されています。
