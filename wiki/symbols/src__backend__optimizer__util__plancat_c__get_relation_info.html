  • We need not lock the relation since it was already locked, either by
  • the rewriter or when expand_inherited_rtentry() added it to the query's
  • rangetable.

  • special-cased relkinds. This check prevents us from crashing later if,

目的

指定されたリレーションのシステムカタログからメタデータを取得し、プランナ用のリレーション情報構造体（RelOptInfo）を初期化する。

入力と出力

  • 引数:
  • PlannerInfo *root: クエリのプランニング情報へのポインタ
  • Oid relationObjectId: 対象リレーションの Oid
  • bool inhparent: 継承ツリーの親リレーションであるかどうかを示すフラグ
  • RelOptInfo *rel: 初期化対象のプランナ用リレーション情報構造体へのポインタ
  • 戻り値: なし（void）

前提条件と不変条件

  • 対象リレーションは、リライタまたは expand_inherited_rtentry() によってすでに適切なロックが取得されているため、関数内では NoLock でオープンされる。
  • rel->max_attr >= rel->min_attr が常に成立する。

アルゴリズムまたは振る舞い

1. **リレーションのオープンと検証**:

  • table_open(relationObjectId, NoLock) を呼び出してリレーションをオープンする。
  • テーブル AM が存在しない場合、外部テーブル（RELKIND_FOREIGN_TABLE）またはパーティションテーブル（RELKIND_PARTITIONED_TABLE）以外であればエラーを出力する。
  • リカバリ中の場合は、永続的でない（一時またはログなし）リレーションへのアクセスをエラーとして拒否する。

    • 2. **基本属性の設定**:

  • 属性の最小値・最大値、テーブルスペース、並列ワーカー数などの基本情報を RelOptInfo に設定し、属性ごとの必要性（attr_needed）および幅（attr_widths）の領域をゼロクリア確保する。

    • 3. **NOT NULL 制約の記録**:

  • 非パーティションの継承親以外の場合に、find_relation_notnullatts() を用いて NOT NULL 列の情報を設定する。

    • 4. **サイズの見積もり**:

  • 継承親でない場合は、estimate_rel_size() を呼び出してページ数、タプル数、可視フラクションを見積もる。

    • 5. **インデックス情報の構築**:

  • 継承親（パーティションテーブルを除く）や無視対象のシステムインデックスでない場合、RelationGetIndexList() からインデックスの Oid リストを取得する。
  • 各インデックスについて以下を実行する:
  • index_open() でインデックスをオープンする。
  • 無効なインデックス (indisvalid が偽) はスキップする。
  • 利用準備が完了していないインデックス (indcheckxmin が真かつトランザクションが古い) はスキップしつつ、トランジient なプランフラグを立てる。
  • IndexOptInfo ノードを割り当て、キー列、照合順序、演算子ファミリ、返却可否などの基本情報をコピーする。
  • パーティションインデックス以外の場合は、アクセスメソッドのルーチンや演算子クラスオプション、Bツリー等のソート順序プロパティ（sortopfamily, reverse_sort, nulls_first）を設定する。

失敗モードと境界条件

  • サポートされていないリレーション種別に対する table_open 後の AM チェック違反時に ERRCODE_WRONG_OBJECT_TYPE エラーが発生する。
  • リカバリ中における一時・ログなしリレーションへのアクセス時に ERRCODE_FEATURE_NOT_SUPPORTED エラーが発生する。
