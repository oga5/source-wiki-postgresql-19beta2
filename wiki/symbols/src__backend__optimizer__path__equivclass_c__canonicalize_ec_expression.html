~~~c Expr * canonicalize_ec_expression(Expr *expr, Oid req_type, Oid req_collation) { Oid expr_type = exprType((Node *) expr);

/*

  • For a polymorphic-input-type opclass, just keep the same exposed type.
  • RECORD opclasses work like polymorphic-type ones for this purpose.

    • */ if (IsPolymorphicType(req_type) || req_type == RECORDOID) req_type = expr_type;

/*

  • No work if the expression exposes the right type/collation already.

    • */ if (expr_type != req_type || exprCollation((Node *) expr) != req_collation) { /*

  • If we have to change the type of the expression, set typmod to -1,
  • since the new type may not have the same typmod interpretation.
  • When we only have to change collation, preserve the exposed typmod.

    • */ int32 req_typmod;

if (expr_type != req_type) req_typmod = -1; else req_typmod = exprTypmod((Node *) expr);

/*

  • Use applyRelabelType so that we preserve const-flatness. This is
  • important since eval_const_expressions has already been applied.

    • */ expr = (Expr *) applyRelabelType((Node *) expr, req_type, req_typmod, req_collation, COERCE_IMPLICIT_CAST, -1, false); }

return expr; } ~~~

目的

等価クラス（EquivalenceClass）内で扱われる式の型および照合順序（collation）を、要求される型・照合順序に適合するように正規化する。

シグネチャまたは形状

  • Expr * canonicalize_ec_expression(Expr *expr, Oid req_type, Oid req_collation)

入力と出力

  • 入力:
  • Expr *expr: 正規化対象の式
  • Oid req_type: 要求されるデータ型 OID
  • Oid req_collation: 要求される照合順序 OID
  • 戻り値:
  • Expr *: 正規化済み（必要に応じて RelabelType ノードでラップされた）式

前提条件と不変条件

  • 多態性入力型（polymorphic-input-type）の演算子クラスや RECORD 型の演算子クラスが指定された場合、要求型 req_type は式の元の型 expr_type に置換される。
  • 既に式が正しい型と照合順序を暴露している場合、式は変更されない。

アルゴリズムまたは振る舞い

1. exprType を用いて入力式 expr の型 (expr_type) を取得する。 2. req_type が多態性型（polymorphic type）であるか RECORDOID である場合、req_type を expr_type で上書きする。 3. 式が暴露する型 (expr_type) が req_type と異なるか、照合順序 (exprCollation) が req_collation と異なるかを比較する。 4. 異ならない場合はそのまま入力式を返す。 5. 異なる場合、型の変更有無に応じて req_typmod を決定する。型が変わる場合は -1 とし、型が変わらず照合順序のみ変わる場合は既存の typmod (exprTypmod) を保持する。 6. applyRelabelType を呼び出して定数のフラット性（const-flatness）を維持したまま、指定された型・typmod・照合順序に適合するノードに変換して返す。

失敗モードと境界条件

  • 該当する境界条件やエラーパスの特記事項はソースコード上に見当たらない。式が既に一致している場合の早期リターンや、多態性型の動的な読み替えが安全に行われる。
