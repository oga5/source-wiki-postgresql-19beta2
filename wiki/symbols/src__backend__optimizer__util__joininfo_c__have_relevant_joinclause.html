~~~c bool have_relevant_joinclause(PlannerInfo *root, RelOptInfo *rel1, RelOptInfo *rel2) { bool result = false; List *joininfo; Relids other_relids; ListCell *l;

/*

  • We could scan either relation's joininfo list; may as well use the
  • shorter one.

    • */ if (list_length(rel1->joininfo) <= list_length(rel2->joininfo)) { joininfo = rel1->joininfo; other_relids = rel2->relids; } else { joininfo = rel2->joininfo; other_relids = rel1->relids; }

foreach(l, joininfo) { RestrictInfo *rinfo = (RestrictInfo *) lfirst(l);

if (bms_overlap(other_relids, rinfo->required_relids)) { result = true; break; } }

/*

  • We also need to check the EquivalenceClass data structure, which might
  • contain relationships not emitted into the joininfo lists.

    • */ if (!result && rel1->has_eclass_joins && rel2->has_eclass_joins) result = have_relevant_eclass_joinclause(root, rel1, rel2);

return result; } ~~~

目的

指定された2つのリレーション（rel1 と rel2）の間に関連する結合条件または等価クラス（EquivalenceClass）の関係が存在するかを判定します。

シグネチャまたは形状

  • シグネチャ: bool have_relevant_joinclause(PlannerInfo *root, RelOptInfo *rel1, RelOptInfo *rel2)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーのグローバル情報
  • RelOptInfo *rel1: 判定対象の1つ目のリレーション
  • RelOptInfo *rel2: 判定対象の2つ目のリレーション
  • 戻り値:
  • bool: 関連する結合条件が存在する場合は true、それ以外の場合は false

前提条件と不変条件

  • 引数として渡される rel1 と rel2 は有効な RelOptInfo ポインタである必要があります。

アルゴリズムまたは振る舞い

1. **走査対象の選択**: 効率化のため、rel1 と rel2 のうち joininfo リストの長さが短い方のリレーションを選択し、もう一方のリレーションの識別子集合を other_relids とします。 2. **結合リストの走査**: 選択した joininfo リスト内の各 RestrictInfo 要素に対し、other_relids と rinfo->required_relids がビットマップ上で重複（オーバーラップ）するかを bms_overlap で確認します。 3. **条件の一致**: 重複する条件が見つかった場合は結果を true に設定し、ループを終了します。 4. **等価クラスの検証**: joininfo リスト側で条件が見つかっておらず、かつ両方のリレーションで has_eclass_joins が有効である場合は、have_relevant_eclass_joinclause を呼び出して等価クラス由来の関係をさらに検証します。 5. **結果の返却**: 最終的な判定結果（bool）を返します。
