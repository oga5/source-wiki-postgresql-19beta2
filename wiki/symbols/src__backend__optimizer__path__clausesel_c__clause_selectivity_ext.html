~~~c Selectivity clause_selectivity_ext(PlannerInfo *root, Node *clause, int varRelid, JoinType jointype, SpecialJoinInfo *sjinfo, bool use_extended_stats) { Selectivity s1 = 0.5; /* default for any unhandled clause type */ RestrictInfo *rinfo = NULL; bool cacheable = false;

if (clause == NULL) /* can this still happen? */ return s1;

if (IsA(clause, RestrictInfo)) { rinfo = (RestrictInfo *) clause;

/*

  • If the clause is marked pseudoconstant, then it will be used as a
  • gating qual and should not affect selectivity estimates; hence
  • return 1.0. The only exception is that a constant FALSE may be
  • taken as having selectivity 0.0, since it will surely mean no rows
  • out of the plan. This case is simple enough that we need not
  • bother caching the result.

    • */ if (rinfo->pseudoconstant) { if (!IsA(rinfo->clause, Const)) return (Selectivity) 1.0; }

/*

  • If possible, cache the result of the selectivity calculation for
  • the clause. We can cache if varRelid is zero or the clause
  • contains only vars of that relid --- otherwise varRelid will affect
  • the result, so mustn't cache. Outer join quals might be examined
  • with either their join's actual jointype or JOIN_INNER, so we need
  • two cache variables to remember both cases. Note: we assume the
  • result won't change if we are switching the input relations or
  • considering a unique-ified case, so we only need one cache variable
  • for all non-JOIN_INNER cases.

    • */ if (varRelid == 0 || rinfo->num_base_rels == 0 || (rinfo->num_base_rels == 1 && bms_is_member(varRelid, rinfo->clause_relids))) { /* Cacheable --- do we already have the result? */ if (jointype == JOIN_INNER) { if (rinfo->norm_selec >= 0) return rinfo->norm_selec; } else { if (rinfo->outer_selec >= 0) return rinfo->outer_selec; } ~~~

目的

単一のクエリ述語句（clause）に対する選択度（Selectivity）を拡張統計やキャッシュの考慮を含めて計算する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • Node *clause: 評価対象の条件式または RestrictInfo
  • int varRelid: 対象となるリレーションの識別子（0の場合は制限なし）
  • JoinType jointype: 結合種別（JOIN_INNER など）
  • SpecialJoinInfo *sjinfo: 特殊結合情報
  • bool use_extended_stats: 拡張統計情報を使用するかどうかを示すフラグ
  • 戻り値: Selectivity （計算された選択度値）

前提条件と不変条件

  • 引数 clause が NULL の場合はデフォルトの選択度（0.5）を返す。
  • 偽定数（pseudoconstant）としてマークされた RestrictInfo の場合、定数 FALSE でない限り選択度は 1.0 を返す。
  • キャッシュ可能な条件において、内部結合時の選択度は norm_selec に、それ以外の結合時の選択度は outer_selec にキャッシュされる。

アルゴリズムまたは振る舞い

1. 初期チェック:

  • clause が NULL の場合、デフォルト選択度 0.5 を返す。

    • 2. RestrictInfo の処理とキャッシュ確認:

  • clause が RestrictInfo の場合、pseudoconstant かつ非 Const であれば 1.0 を返す。
  • varRelid == 0 であるか、rinfo->num_base_rels == 0 であるか、あるいは rinfo->num_base_rels == 1 かつ varRelid が rinfo->clause_relids に含まれる場合は結果のキャッシュを試みる。
  • キャッシュが有効で既に計算済み（norm_selec >= 0 または outer_selec >= 0）であれば、キャッシュされた選択度をそのまま返す。
  • 内部評価用に clause を rinfo->orclause または rinfo->clause にアンラップする。

    • 3. 式ノード型に応じた選択度計算のディスパッチ:

  • Var: レベルおよび変数の関係IDが一致する場合、boolvarsel を呼び出す。
  • Const: ブール定数の値（またはNULLか否か）に基づき 0.0 または 1.0 を設定する。
  • Param: estimate_expression_value で値の置き換えを試み、定数であればそれに応じた選択度とする。
  • Not 節（is_notclause）：内部引数の選択度を算出し、その余事象（1.0 - s1）を計算する。
  • AND 節（is_andclause）：clauselist_selectivity_ext に委譲する。
  • OR 節（is_orclause）：clauselist_selectivity_or に委譲する。
  • 演算子句（is_opclause）および DistinctExpr: treat_as_join_clause の結果に応じて join_selectivity または restriction_selectivity を呼び出す。DistinctExpr の場合は結果の余事象をとる。
  • 関数句（is_funcclause）：サポート関数による選択度（function_selectivity）を試み、得られない場合は boolvarsel にフォールバックする。
  • ScalarArrayOpExpr: scalararraysel を呼び出す。
  • RowCompareExpr: rowcomparesel を呼び出す。
  • NullTest: nulltestsel を呼び出す。
  • BooleanTest: booltestsel を呼び出す。
  • CurrentOfExpr: 対象リレーションのタプル数に基づき高々1行の選択度（1.0 / crel->tuples）を算出する。
  • RelabelType および CoerceToDomain: 内部の引数式に対して再帰的に clause_selectivity_ext を呼び出す。
  • その他: boolvarsel によるフォールバックを行う。

    • 4. キャッシュの保存と返却:

  • cacheable が真である場合、結合種別に応じて rinfo->norm_selec または rinfo->outer_selec に算出した選択度を格納する。
  • 最終的な選択度 s1 を返す。

呼び出し元と呼び出し先

失敗モードと境界条件

  • 対象ノードがいずれの処理分岐にも合致しない場合、最終的なフォールバックとして boolvarsel が呼び出され、不適切な式であっても適切なデフォルト選択度が返される。
  • タプル数が 0 の CurrentOfExpr では、除算を避けるため選択度の更新を行わない。
