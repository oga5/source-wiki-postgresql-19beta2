目的

指定されたリレーションに対して利用可能なインデックスを順に走査し、制限条件や結合条件、EquivalenceClass、OR句の照合を行って通常のインデックスパスおよび各種ビットマップパス（BitmapHeapPathなど）を構築し、リレーションのパスリストへ登録する。

シグネチャまたは形状

void create_index_paths(PlannerInfo *root, RelOptInfo *rel)

入力と出力

  • **入力**:
  • PlannerInfo *root: クエリ全体のプランナ情報を保持する構造体ポインタ。
  • RelOptInfo *rel: 対象リレーションの最適化情報を保持する構造体ポインタ。
  • **戻り値**: なし (void)。

前提条件と不変条件

  • 対象リレーションのインデックスリスト（rel->indexlist）が空（NIL）の場合、インデックスパスの生成処理全体がスキップされる。
  • 各インデックスのキー列数は INDEX_MAX_KEYS 以下でなければならず、ループ内でアサーションにより保護されている。
  • クエリに適合しない部分インデックス（述語が存在し、かつ predOK が偽のもの）は処理対象から除外される。

アルゴリズムまたは振る舞い

1. **初期化と前提チェック**:

  • rel->indexlist が NIL の場合は即座に終了する。
  • ビットマップパス用のリスト変数（bitindexpaths, bitjoinpaths, joinorclauses）を NIL に初期化する。

2. **インデックスごとのループ処理**:

  • rel->indexlist の各 IndexOptInfo について、キー列数の上限アサーションを検証し、述語を満たさない部分インデックスをスキップする。
  • **制限条件の照合**: match_restriction_clauses_to_index を呼び出してインデックスに合致する制限条件を識別し、rclauseset を構築する。
  • **非パラメータ化パスの構築**: get_index_paths を呼び出し、制限条件から非パラメータ化インデックスパスを生成する。通常パスは直接追加され、ビットマップ用パスは bitindexpaths に蓄積される。
  • **結合条件の照合**: match_join_clauses_to_index により、 EquivalenceClass に未マージの「ルーズな」結合条件を識別し、jclauseset と後続用の joinorclauses を収集する。
  • **EquivalenceClass 結合条件の照合**: match_eclass_clauses_to_index により、EquivalenceClass からインデックスに合致する結合条件を eclauseset に抽出する。
  • **パラメータ化インデックスパスの考慮**: jclauseset または eclauseset が空でない場合、consider_index_join_clauses を呼び出してパラメータ化されたインデックスパスを生成し、bitjoinpaths に追加する。

3. **制限 OR 句のビットマップパス生成**:

  • リレーションの制限リスト（rel->baserestrictinfo）から generate_bitmap_or_paths を用いて BitmapOrPath を生成し、bitindexpaths に結合する。

4. **結合 OR 句のビットマップパス生成**:

  • 収集された joinorclauses から generate_bitmap_or_paths を用いて結合用の BitmapOrPath を生成し、bitjoinpaths に結合する。

5. **制限ビットマップパスの統合（BitmapHeapPath の生成）**:

  • bitindexpaths が空でない場合、choose_bitmap_and で最適なビットマップ修飾を決定し、create_bitmap_heap_path を介して BitmapHeapPath を作成して add_path でリレーションに登録する。
  • リレーションが並行処理を考慮可能で側副リレーションを持たない場合、create_partial_bitmap_paths を呼び出して部分ビットマップパスを生成する。

6. **結合ビットマップパスの統合**:

  • bitjoinpaths が空でない場合、各パスのパラメータ化要件（PATH_REQ_OUTER）の重複を排除したリスト（all_path_outers）を構築する。
  • パラメータ化セットごとに、必要な条件を満たすビットマップ結合パスおよび制限ビットマップパスを集約し、choose_bitmap_and で最良の AND 組み合わせを選択する。
  • get_loop_count を用いてループ見積もりを取得し、対応する BitmapHeapPath を生成して add_path でリレーションに登録する。

関連データ構造

  • PlannerInfo: クエリ全体のプランナ情報を保持する構造体。
  • RelOptInfo: リレーションの最適化に関する情報（インデックスリスト、制限条件など）を保持する構造体。
  • IndexOptInfo: 個々のインデックスに関するメタデータ（キー列数、部分インデックス述語など）を保持する構造体。
  • IndexClauseSet: インデックス列ごとの制限条件や結合条件のセットを管理する固定長配列ベースの構造体。
  • BitmapHeapPath: ビットマップスキャン結果のヒープアクセス経路を表現するパス構造体。

失敗モードと境界条件

  • リレーションにインデックスが存在しない場合（rel->indexlist == NIL）、早期リターンするためエラーや副作用は発生しない。
  • インデックスのキー列数が INDEX_MAX_KEYS を超える場合、アサーション違反により失敗する。
