目的

ジョイントリー（jointree）を再帰的に走査し、クエリ内に含まれるすべてのベース関係（base relations）に対応する RelOptInfo を構築する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体の情報を保持する構造体ポインタ
  • Node *jtnode: 走査対象のジョイントリーノード（RangeTblRef、FromExpr、または JoinExpr）
  • 戻り値: なし（void）

前提条件と不変条件

  • 引数 jtnode が NULL の場合、処理を行わずに即座にリターンする。

アルゴリズムまたは振る舞い

1. jtnode が NULL であるか検証し、該当する場合は直ちに処理を終了する。 2. jtnode のノード型を判定し、以下の分岐処理を実行する:

  • RangeTblRef の場合:
  • ノードからレンジテーブルのインデックス（rtindex）を取得する。
  • build_simple_rel を呼び出して、該当するベース関係の RelOptInfo を構築する。
  • FromExpr の場合:
  • 保持されている fromlist 内の各要素に対して、自身を再帰的に呼び出してベース関係の追加を行う。
  • JoinExpr の場合:
  • 結合の左引数（larg）と右引数（rarg）のそれぞれに対して、自身を再帰的に呼び出してベース関係の追加を行う。
  • 上記いずれにも該当しない場合:
  • elog(ERROR, ...) を呼び出して、認識できないノード型のエラーを送出する。

失敗モードと境界条件

  • サポートされていないノード型が渡された場合は、nodeTag(jtnode) のタグ値を含むエラーメッセージとともに ERROR レベルのログが送出され、処理が中断される。
