~~~c IncrementalSortPath * create_incremental_sort_path(PlannerInfo *root, RelOptInfo *rel, Path *subpath, List *pathkeys, int presorted_keys, double limit_tuples) { IncrementalSortPath *sort = makeNode(IncrementalSortPath); SortPath *pathnode = &sort->spath;

pathnode->path.pathtype = T_IncrementalSort; pathnode->path.parent = rel; /* Sort doesn't project, so use source path's pathtarget */ pathnode->path.pathtarget = subpath->pathtarget; pathnode->path.param_info = subpath->param_info; pathnode->path.parallel_aware = false; pathnode->path.parallel_safe = rel->consider_parallel && subpath->parallel_safe; pathnode->path.parallel_workers = subpath->parallel_workers; pathnode->path.pathkeys = pathkeys;

pathnode->subpath = subpath;

cost_incremental_sort(&pathnode->path, root, pathkeys, presorted_keys, subpath->disabled_nodes, subpath->startup_cost, subpath->total_cost, subpath->rows, subpath->pathtarget->width, 0.0, /* XXX comparison_cost shouldn't be 0? */ work_mem, limit_tuples);

sort->nPresortedCols = presorted_keys;

return sort; } ~~~

目的

IncrementalSortPath ノードを新しく割り当てて初期化し、インクリメンタルソートのコストを見積もって返す。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーのグローバル情報
  • RelOptInfo *rel: このパスの親リレーション
  • Path *subpath: 入力となる下位パス
  • List *pathkeys: 要求されるパスキーのリスト
  • int presorted_keys: プレソートされているキーの数
  • double limit_tuples: リミットタプル数
  • 戻り値:
  • IncrementalSortPath *: 初期化されたインクリメンタルソートパスノード

前提条件と不変条件

  • ソート演算子はプロジェクションを行わないため、作成されるパスの pathtarget にはサブパスの pathtarget がそのまま使用される。
  • 並列アウェアネス（parallel_aware）は常に false に設定される。
  • 並列安全性（parallel_safe）は、リレーションの並列考慮フラグとサブパスの並列安全性の両方が有効な場合にのみ有効となる。

アルゴリズムまたは振る舞い

  • IncrementalSortPath ノードを makeNode で割り当てる。
  • パスの種類を T_IncrementalSort に設定し、親リレーション、パラメータ情報、並列ワーカー数、パスキー、サブパスをそれぞれ割り当てられた値やサブパスのプロパティから設定する。
  • cost_incremental_sort を呼び出して、インクリメンタルソートパスの起動コストやトータルコストなどのコストパラメータを見積もる。
  • プレソートされた列の数を nPresortedCols に格納し、構築したパス構造体を返す。
