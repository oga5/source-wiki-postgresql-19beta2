目的

リレーション上の各部分インデックスの predOK フラグの評価と設定を行い、部分インデックスで暗黙的に成立する制限条件をインデックスの制限情報から整理する。

入力と出力

  • 引数:
  • PlannerInfo *root: クエリ全体のプランナ情報を格納する構造体へのポインタ。
  • RelOptInfo *rel: 対象リレーションの最適化情報を格納する構造体へのポインタ。
  • 戻り値: なし（void）。

前提条件と不変条件

  • rel はベースリレーションまたは「その他の」メンバーリレーション（シンプルリレーション）でなければならない（アサートで検証）。

アルゴリズムまたは振る舞い

1. 初期化と部分インデックスの有無の確認:

  • リレーションの全インデックスについて、各 index->indrestrictinfo を rel->baserestrictinfo と同じに初期化する。
  • インデックスに部分インデックス述語（indpred）が定義されているものが一つでもあるかを調べ、存在しない場合はそのまま処理を終了する。

2. 仮定可能句リスト（clauselist）の構築:

  • rel->baserestrictinfo のコピーをベースとして clauselist を初期化する。
  • リレーションの結合情報（joininfo）を走査し、各結合条件が当該リレーションへ移動可能（join_clause_is_movable_to が真）である場合、clauselist に追加する。
  • 等価クラス（Equivalence Class）から導出可能な結合条件について、子リレーションの場合は親の relid を除外するなど適切な otherrels を計算した上で、generate_join_implied_equalities を呼び出して clauselist に結合する。

3. ターゲット関係の判定:

  • 当該リレーションが UPDATE/DELETE/MERGE または SELECT FOR UPDATE のターゲット関係（all_result_relids または rowMarks に含まれる）であるかどうかを判定する。

4. 各部分インデックスの述語検証とインデックス制限情報の最適化:

  • リレーションの全インデックスを再度走査し、部分インデックス述語（indpred が非 NIL）を持つものを対象に処理を行う。
  • index->predOK がまだ真に設定されていない場合、predicate_implied_by(index->indpred, clauselist, false) を用いて述語が成立するかを判定し、結果を predOK に格納する。
  • 更新ターゲット関係である場合、あるいはインデックスがオプショナルキーを持たない（!index->amoptionalkey）場合は、制限情報の再計算を行わずに初期状態のままスキップする。
  • それ以外の場合、部分インデックスの述語によってすでに満たされている（含意されている）ベース制限条件を indrestrictinfo から除外するため、不変式（immutable）かつ部分インデックス述語から導出できない条件のみを抽出し直して index->indrestrictinfo を構築する。

失敗モードと境界条件

  • 部分インデックスが一つも存在しない場合、処理は前半の段階で早期リターンする。
  • ターゲット関係である場合や、インデックスがオプショナルキーを許可しない制約を持つ場合、インデックス制限情報の削減は安全性の観点からバイパスされる。
