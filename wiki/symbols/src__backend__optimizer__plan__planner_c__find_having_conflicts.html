ソース抜粋

~~~c static Bitmapset * find_having_conflicts(Query *parse, Index group_rtindex) { Bitmapset *result = NULL; having_grouping_ctx ctx; int idx;

if (parse->havingQual == NULL) return NULL;

ctx.parse = parse; ctx.group_rtindex = group_rtindex;

idx = 0; foreach_ptr(Node, clause, (List *) parse->havingQual) { if (expression_has_grouping_conflict(clause, having_var_grouping_eqop, &ctx)) result = bms_add_member(result, idx); idx++; }

return result; } ~~~

目的

Query の havingQual 内にある各句を走査し、指定されたグループ化の範囲やセマンティクスと競合（矛盾）する箇所を特定してビットマップセットとして返す。

入力と出力

  • 入力:
  • Query *parse: 解析済みのクエリ構造体
  • Index group_rtindex: グループ化対象のレンジテーブルインデックス
  • 戻り値:
  • Bitmapset *: 競合が検出された HAVING 句のインデックス位置（0始まり）を表すビットマップセット。競合がない場合や havingQual が NULL の場合は NULL を返す

前提条件と不変条件

  • parse が指す Query 構造体およびその havingQual は有効な状態であること。

アルゴリズムまたは振る舞い

1. クエリの havingQual が NULL であるかチェックし、NULL ならば直ちに NULL を返す。 2. 局所コンテキスト変数 having_grouping_ctx ctx を初期化し、ctx.parse に parse を、ctx.group_rtindex に group_rtindex を設定する。 3. インデックス変数 idx を 0 に初期化する。 4. parse->havingQual をリスト（List *）として扱い、foreach_ptr を用いて各 HAVING 句（Node *clause）を順番に走査する。 5. 各ループイテレーションにおいて、expression_has_grouping_conflict を呼び出し、現在の clause と having_var_grouping_eqop および &ctx を渡してグループ化の競合有無を判定する。 6. 競合が検出された場合、bms_add_member を使用して結果のビットマップセット result に現在のインデックス idx を追加する。 7. インデックス idx をインクリメントし、すべての句の走査が完了するまで繰り返す。 8. 構築された result ビットマップセットを返す。

失敗モードと境界条件

  • parse->havingQual が NULL の場合は早期に NULL を返し、ループ処理を行わない。
