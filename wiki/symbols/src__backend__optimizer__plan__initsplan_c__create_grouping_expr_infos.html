~~~c static void create_grouping_expr_infos(PlannerInfo *root) { List *exprs = NIL; List *sortgrouprefs = NIL; List *ecs = NIL; ListCell *lc, *lc1, *lc2, *lc3;

Assert(root->group_expr_list == NIL);

foreach(lc, root->processed_groupClause) { SortGroupClause *sgc = lfirst_node(SortGroupClause, lc); TargetEntry *tle = get_sortgroupclause_tle(sgc, root->processed_tlist); TypeCacheEntry *tce; Oid equalimageproc;

Assert(tle->ressortgroupref > 0);

/*

  • For now we only support plain Vars as grouping expressions.

    • */ if (!IsA(tle->expr, Var)) return;

/*

  • Eager aggregation is only possible if equality implies image
  • equality for each grouping key. Otherwise, placing keys with
  • different byte images into the same group may result in the loss of
  • information that could be necessary to evaluate upper qual clauses.

    • *

  • For instance, the NUMERIC data type is not supported, as values
  • that are considered equal by the equality operator (e.g., 0 and
  • 0.0) can have different scales.

    • */ tce = lookup_type_cache(exprType((Node *) tle->expr), TYPECACHE_BTREE_OPFAMILY); if (!OidIsValid(tce->btree_opf) || !OidIsValid(tce->btree_opintype)) return;

equalimageproc = get_opfamily_proc(tce->btree_opf, tce->btree_opintype, tce->btree_opintype, BTEQUALIMAGE_PROC);

/*

  • If there is no BTEQUALIMAGE_PROC, eager aggregation is assumed to
  • be unsafe. Otherwise, we call the procedure to check. We must be
  • careful to pass the expression's actual collation, rather than the
  • data type's default collation, to ensure that non-deterministic
  • collations are correctly handled.

    • */ if (!OidIsValid(equalimageproc) || !DatumGetBool(OidFunctionCall1Coll(equalimageproc, exprCollation((Node *) tle->expr), ObjectIdGetDatum(tce->btree_opintype)))) ~~~

目的

クエリの処理済みグループ化句（processed_groupClause）を走査し、各グループ化式がプレーンな Var であり、かつ同値演算子がバイト単位の画像同一性を保証できる（早期集約が可能である）条件を満たしている場合に、対応する GroupingExprInfo を構築して root->group_expr_list に登録する。

シグネチャまたは形状

  • シグネチャ: static void create_grouping_expr_infos(PlannerInfo *root)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーの全体情報を保持する構造体ポインタ。
  • 戻り値:
  • なし（void）

前提条件と不変条件

  • 実行開始時に root->group_expr_list は空（NIL）でなければならない。
  • 各ターゲットエントリのソートグループ参照番号（ressortgroupref）は 0 より大きくなければならない。

アルゴリズムまたは振る舞い

1. root->group_expr_list が空であることをアサートで検証する。 2. root->processed_groupClause の各 SortGroupClause 要素についてループを回し、対応するターゲットエントリ（TargetEntry）を取得する。 3. グループ化式がプレーンな Var ノードでない場合は、早期集約の候補収集を中断してリターンする。 4. グループ化式のデータ型に対する B-tree オペレータファミリの型キャッシュ（TypeCacheEntry）を取得し、有効なオペレータファミリおよびインデックス型が存在するか検証する。不適格な場合は中断してリターンする。 5. B-tree の画像同一性確認用プロシージャ（BTEQUALIMAGE_PROC）の OID を取得する。 6. プロシージャが存在しない場合、または式の実際のコレーションを渡して呼び出した結果が真を返さない場合は、早期集約が安全ではないと見なして中断・リターンする。 7. 条件を通過した式、ソートグループ参照番号、および等価クラスをそれぞれ一時リスト（exprs, sortgrouprefs, ecs）に蓄積する。 8. 蓄積されたリストを並行して走査し、各要素から GroupingExprInfo ノードを生成・初期化して root->group_expr_list に順番に追加する。
