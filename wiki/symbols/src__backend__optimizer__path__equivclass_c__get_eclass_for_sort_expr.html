目的

指定されたソート式（あるいは順序句式）に対応する同値クラス（EquivalenceClass）を既存のクラスから探索し、存在しない場合は必要に応じて新規作成して返す。

シグネチャまたは形状

  • シグネチャ: EquivalenceClass * get_eclass_for_sort_expr(PlannerInfo *root, Expr *expr, List *opfamilies, Oid opcintype, Oid collation, Index sortref, Relids rel, bool create_it)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体のグローバル情報
  • Expr *expr: 対象となる式
  • List *opfamilies: 演算子ファミリのリスト
  • Oid opcintype: 演算子クラスの入力データ型 OID
  • Oid collation: 照合順序（collation）OID
  • SortGroupClause などを識別する参照インデックスまたは 0
  • Relids rel: 関連するリレーション集合
  • bool create_it: 一致するものが見つからない場合に新規作成するかどうかを示すフラグ
  • 戻り値: 一致または新規作成された EquivalenceClass *。見つからず create_it が偽の場合は NULL

前提条件と不変条件

  • ソート/グループ化句のノードはトップレベルの式であるため、トップの JoinDomain に属すると見なされる。
  • ボラタイルな EquivalenceClass は、同じボラタイルな SortGroupClause への別の参照である場合を除き、マッチ対象から除外される。

アルゴリズムまたは振る舞い

1. **式の正規化**: canonicalize_ec_expression を用いて、入力式が正しいデータ型と照合順序を暴露するように調整する。 2. **既存の同値クラス走査**: root->eq_classes 内を順に走査し、ボラタイル性の制約、照合順序 (collation)、および演算子ファミリ (opfamilies) が一致する既存の EquivalenceClass (cur_ec) を探す。 3. **メンバーイテレーションによるマッチング**: setup_eclass_member_iterator と eclass_member_iterator_next を使用して、各 cur_ec のメンバーをスキャンする。

  • 子メンバー (em_is_child) の場合は、リレーションがリクエストと一致しない限り無視する。
  • 定数メンバー (em_is_const) の場合は、トップの JoinDomain と一致するもののみ対象とする。
  • データ型 (em_datatype) と式自体 (em_expr) が一致する場合は、その cur_ec を返す。

    • 4. **新規作成パス（一致がなく create_it が真の場合）**:

  • root->planner_cxt メモリコンテキストに切り替えた上で、新しい EquivalenceClass ノードを構築し初期化する。
  • ボラタイルかつ sortref == 0 の場合はエラー (ERROR) を発生させる。
  • pull_varnos で式内の変数リレーション識別子を取得し、add_eq_member で新しいメンバーを追加する。
  • ボラタイル関数、セット返却関数、集約句、ウィンドウ関数が含まれる場合は、定数フラグ (ec_has_const および em_is_const) をオフに修正する。
  • 新規作成した EquivalenceClass を root->eq_classes に追加する。
  • ECのマージがすでに完了している場合 (root->ec_merging_done) は、関連するベースリレーションの eclass_indexes に新しいインデックスを追加して後始末を行う。
  • 元のメモリコンテキストを復元し、新しく作成した EquivalenceClass を返す。

失敗モードと境界条件

  • ボラタイルな式でありながら sortref が 0 である不正な状態が検出された場合、elog(ERROR) によりエラー終了する。
  • 一致する既存の EquivalenceClass が存在せず、かつ create_it が偽である場合、関数は何も作成せずに NULL を返す。
