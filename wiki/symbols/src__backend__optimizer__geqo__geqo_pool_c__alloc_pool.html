ソース抜粋

~~~c Pool * alloc_pool(PlannerInfo *root, int pool_size, int string_length) { Pool *new_pool; Chromosome *chromo; int i;

/* pool */ new_pool = palloc_object(Pool); new_pool->size = pool_size; new_pool->string_length = string_length;

/* all chromosome */ new_pool->data = palloc_array(Chromosome, pool_size);

/* all gene */ chromo = (Chromosome *) new_pool->data; /* vector of all chromos */ for (i = 0; i < pool_size; i++) chromo[i].string = palloc_array(Gene, string_length + 1);

return new_pool; } ~~~

目的

GEQOの個体群プール構造体 (Pool) と、それに含まれる染色体配列および各染色体の遺伝子配列（Gene配列）のメモリを動的に割り当てて初期化する。

入力と出力

  • 入力:
  • PlannerInfo *root: プランナー情報へのポインタ。
  • int pool_size: プール内に保持する個体（染色体）の総数。
  • int string_length: 各染色体が持つ遺伝子文字列の長さ。
  • 出力:
  • 割り当ておよび初期化された Pool * 型の新しいプール構造体へのポインタを返す。

前提条件と不変条件

  • 割り当てられたメモリは現在のPostgreSQLメモリコンテキストに属し、解放には free_pool 等を通じた適切な pfree が必要となる。

アルゴリズムまたは振る舞い

1. palloc_object(Pool) を用いて Pool 構造体自体のメモリを割り当て、引数から渡された pool_size と string_length をフィールドに設定する。 2. palloc_array(Chromosome, pool_size) を用いて、指定されたプールサイズ分の染色体配列領域を確保し、new_pool->data に割り当てる。 3. ループ処理により、確保した各染色体（chromo[i]）に対して palloc_array(Gene, string_length + 1) を実行し、各遺伝子文字列の領域を割り当てる。 4. 構築した new_pool ポインタを呼び出し元へ返す。

失敗モードと境界条件

  • メモリ割り当て時に空き容量が不足している場合、PostgreSQLのメモリ管理機構によりエラーが発生する。

保守担当者向けメモ

  • プール内の染色体データの整合性を維持するため、領域の解放は対応する解放関数経由で確実に行うこと。
