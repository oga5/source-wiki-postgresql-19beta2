目的

指定された遺伝子ツアー（結合順序の候補）に基づいて結合ツリーを構築し、得られた実行計画の総コストを評価して適応度（fitness）として算出する。

入力と出力

  • 入力:
  • PlannerInfo *root: プランナのグローバル情報を格納する構造体ポインタ
  • Gene *tour: 結合順序を表す遺伝子配列（ツアー）
  • int num_gene: ツアー内の遺伝子（リレーション）数
  • 戻り値:
  • Cost: 有効な結合が見つかった場合は最安パスの総コスト、見つからない場合は DBL_MAX

前提条件と不変条件

  • 評価処理開始時に root->join_rel_level が NULL であること。
  • 実行中に割り当てられた一時メモリや root->join_rel_list に追加されたエントリは、関数終了時に入力前の状態に復元・回収されること。

アルゴリズムまたは振る舞い

1. メモリコンテキストの作成と切り替え: AllocSetContextCreate を用いて、gimme_tree 内の一時ストレージを保持する専用のプライベートメモリコンテキスト（"GEQO"）を作成し、現在のメモリコンテキストを切り替える。 2. プランナ状態の退避: root->join_rel_list の元の長さを保存し、root->join_rel_hash を一時的に NULL に設定する。 3. 結合ツリーの構築: gimme_tree(root, tour, num_gene) を呼び出し、指定されたツアーに沿った結合リレーション（結合ツリー）を構築する。 4. 適応度の計算:

  • 有効な結合リレーションが得られた場合は、その最安パスの総コスト（cheapest_total_path->total_cost）を適応度とする。
  • 結合が得られなかった場合は DBL_MAX を返す。

    • 5. 状態の復元とクリーンアップ:

  • root->join_rel_list を元の長さに切り詰め、root->join_rel_hash を元のハッシュテーブルに戻す。
  • メモリコンテキストを元のコンテキストに戻した上で、MemoryContextDelete により gimme_tree で取得したメモリを一括解放する。

失敗モードと境界条件

  • 有効な結合ツリー（joinrel）の構築に失敗した場合、適応度として DBL_MAX が返される。
  • ereport(ERROR) 等で異常終了した場合でも、プライベートメモリコンテキストがプランナの通常コンテキストの子として作成されているためメモリリークを防ぐ。
