単一のサブクエリレベル内にあるプランノード群を再帰的に走査し、プランノードごとに一意な plan_node_id を割り当てた上で、プラン種別に応じた参照関係や式（ターゲットリスト、修飾句、インデックス条件など）のレンジテーブルオフセット（rtoffset）を修正する。

シグネチャまたは形状

  • シグネチャ: static Plan * set_plan_refs(PlannerInfo *root, Plan *plan, int rtoffset)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体の情報を保持する構造体ポインタ。
  • Plan *plan: 処理対象のプランノード（またはサブツリーのルート）。
  • int rtoffset: レンジテーブルインデックスに加算すべきオフセット値。
  • 戻り値:
  • Plan *: 参照修正が行われたプランノードのポインタ。

前提条件と不変条件

  • 引数 plan が NULL の場合は、そのまま NULL が返される。
  • 訪れたすべての非 NULL プランノードに対して、root->glob->lastPlanNodeId++ から取得した一意な plan_node_id がインプレースで割り当てられる。

アルゴリズムまたは振る舞い

1. plan == NULL であるかをチェックし、真であれば NULL を返す。 2. プランノードの plan_node_id に root->glob->lastPlanNodeId++ の値を割り当てて一意なIDを付与する。 3. nodeTag(plan) を用いてプランの種類を判定し、分岐する。 4. スキャン系ノード（例: T_SeqScan, T_SampleScan, T_IndexScan, T_BitmapHeapScan, T_TidScan, T_TidRangeScan, T_FunctionScan, T_TableFuncScan, T_ValuesScan, T_CteScan, T_NamedTuplestoreScan, T_WorkTableScan など）の場合、スキャン対象のリレーションID（scanrelid）に rtoffset を加算し、ターゲットリストや修飾句（qual）、インデックス条件などの式リストに対して fix_scan_list や fix_scan_expr を適用して参照を修正する。 5. 特定の専用スキャン系ノード（T_IndexOnlyScan や T_SubqueryScan）の場合、専用の参照修正関数（set_indexonlyscan_references や set_subqueryscan_references）へ処理を委譲する。 6. 結合系ノード（T_NestLoop, T_MergeJoin, T_HashJoin）の場合、set_join_references を呼び出して結合条件や出力式の参照を修正する。 7. T_Gather および T_GatherMerge の場合、set_upper_references と set_param_references を順に呼び出す。 8. T_Hash の場合、set_hash_references を呼び出す。 9. T_Memoize の場合、ターゲットリストを子ノードから共有するため set_dummy_tlist_references を実行し、param_exprs に対して fix_scan_list を適用する。 10. T_Material, T_Sort, T_IncrementalSort, T_Unique, T_SetOp などのターゲットリストや修飾句を直接評価しないプラン型では、set_dummy_tlist_references を実行し、修飾句（plan->qual）が空（NIL）であることをアサートで検証する。

失敗モードと境界条件

  • plan が NULL の場合は正常に NULL が返される。
  • T_BitmapIndexScan では、ターゲットリストと修飾句が NIL であることがアサートによって検証される。
  • T_Material, T_Sort, T_IncrementalSort, T_Unique, T_SetOp などのプランノードでは、修飾句がアタッチされていないことが Assert(plan->qual == NIL) により強制される。
