~~~c PathKey * make_canonical_pathkey(PlannerInfo *root, EquivalenceClass *eclass, Oid opfamily, CompareType cmptype, bool nulls_first) { PathKey *pk; ListCell *lc; MemoryContext oldcontext;

/* Can't make canonical pathkeys if the set of ECs might still change */ if (!root->ec_merging_done) elog(ERROR, "too soon to build canonical pathkeys");

/* The passed eclass might be non-canonical, so chase up to the top */ while (eclass->ec_merged) eclass = eclass->ec_merged;

foreach(lc, root->canon_pathkeys) { pk = (PathKey *) lfirst(lc); if (eclass == pk->pk_eclass && opfamily == pk->pk_opfamily && cmptype == pk->pk_cmptype && nulls_first == pk->pk_nulls_first) return pk; }

/*

  • Be sure canonical pathkeys are allocated in the main planning context.
  • Not an issue in normal planning, but it is for GEQO.

    • */ oldcontext = MemoryContextSwitchTo(root->planner_cxt);

pk = makeNode(PathKey); pk->pk_eclass = eclass; pk->pk_opfamily = opfamily; pk->pk_cmptype = cmptype; pk->pk_nulls_first = nulls_first;

root->canon_pathkeys = lappend(root->canon_pathkeys, pk);

MemoryContextSwitchTo(oldcontext);

return pk; } ~~~

目的

指定された等価クラス、演算子ファミリー、比較型、およびNULL配置に基づき、重複のない一意な正規化済み PathKey を検索または新規作成する。

シグネチャまたは形状

  • シグネチャ: PathKey * make_canonical_pathkey(PlannerInfo *root, EquivalenceClass *eclass, Oid opfamily, CompareType cmptype, bool nulls_first)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • EquivalenceClass *eclass: 対象の等価クラス
  • Oid opfamily: 演算子ファミリーの OID
  • CompareType cmptype: 比較の型
  • bool nulls_first: NULL を先頭に配置するかどうか
  • 戻り値: PathKey * (正規化された PathKey 構造体へのポインタ)

前提条件と不変条件

  • 等価クラスの統合フェーズが完了していなければならない (root->ec_merging_done が真であること)。
  • 生成される正規化済みパスキーは、メインの計画コンテキスト (root->planner_cxt) に割り当てられ、クエリ内で一意にキャッシュされる。

アルゴリズムまたは振る舞い

1. **前提チェック**: root->ec_merging_done が偽である場合は、エラー (ERROR) を送出する。 2. **等価クラスの正規化**: 渡された eclass が既にマージされている場合、ec_merged をたどって最上位の等価クラスに置き換える。 3. **既存パスキーの検索**: root->canon_pathkeys リストを走査し、等価クラス、演算子ファミリー、比較型、NULL配置がすべて一致する既存の PathKey が存在するか確認する。一致するものが見つかった場合はそれを返す。 4. **新規作成と登録**:

  • メモリコンテキストを root->planner_cxt に切り替える。
  • PathKey ノードを新しく割り当て、各フィールドに引数の値 (eclass, opfamily, cmptype, nulls_first) を設定する。
  • 新規作成した PathKey を root->canon_pathkeys リストの末尾に追加する。
  • 元のメモリコンテキストを復元する。
  • 新規作成した PathKey を返す。

失敗モードと境界条件

  • root->ec_merging_done が偽の状態で呼び出された場合、elog(ERROR, ...) によりエラーが発生する。
