目的

ハッシュ結合のメモリ使用量が制限に達した際、ハッシュテーブルのバッチ数を倍増（nbatch を 2 倍）させ、既存のインメモリタプルを再パーティショニングして適切なバッチまたは一時ファイルへ振り分ける。

入力と出力

  • 引数: HashJoinTable hashtable（操作対象のハッシュ結合テーブル）
  • 戻り値: なし (void)

前提条件と不変条件

  • hashtable->growEnabled が真であること（偽の場合は何もせずにリターンする）
  • 整数オーバーフローやアロケーション制限を防ぐため、oldnbatch が安全なしきい値以下であること

アルゴリズムまたは振る舞い

1. **事前チェック**: 成長が無効化されている場合や、オーバーフローの恐れがある場合は処理を中断する。また、インメモリハッシュテーブル側のバッチサイズ（バケット数）増大で対応可能か ExecHashIncreaseBatchSize で試行し、可能であればそこで終了する。 2. **バッチファイル配列の準備**: 新しいバッチ数 nbatch = oldnbatch * 2 を計算する。初回スピル時は hashtable->spillCxt コンテキスト上で innerBatchFile および outerBatchFile のファイル配列を割り当て、一時テーブルスペースを準備する。2回目以降は既存の配列を repalloc0_array で拡張する。 3. **バケットの拡張**: 最適なバケット数(nbuckets_optimal)が現在のバケット数と異なる場合、バケット配列を拡張して更新する。その後、すべてのバケットポインタをゼロクリアし、既存のチャンクポインタを退避して hashtable->chunks をリセットする。 4. **既存チャンクの再スキャンと再配置**: 旧チャンク内の全タプルを走査し、各タプルのハッシュ値から新しいバケット番号とバッチ番号を再計算する。

  • 現在のバッチ (curbatch) に属するタプルは、新しく密なアロケーション (dense_alloc) でコピーを作成し、新しいバケットリストに繋ぎ直す。
  • 別のバッチに属するタプルは、対応する内部バッチファイルへ退避 (ExecHashJoinSaveTuple) し、消費メモリ量(spaceUsed)を減算する。
  • 割り込みチェック (CHECK_FOR_INTERRUPTS) を各ループで実行する。

    • 5. **旧チャンクの解放**: 処理済みの旧チャンクメモリを順次解放する。 6. **成長制御の更新**: タプルがすべてメモリに残った場合、またはすべてファイルへ退避された場合（nfreed == 0 || nfreed == ninmemory）、これ以上バッチ数を分割しても意味がないため hashtable->growEnabled = false に設定して今後の拡張を無効化する。

失敗モードと境界条件

  • ハッシュ値が同一のグループに偏り、すべてのタプルがメモリに残るかすべてファイルに落ちる場合、さらなるバッチ分割が無効化される。
  • 整数オーバーフローや許容最大アロケーションサイズを超える oldnbatch の場合は即座にリターンする。
