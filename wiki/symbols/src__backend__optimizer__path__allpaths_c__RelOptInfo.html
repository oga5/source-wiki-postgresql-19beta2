定義

静的解析ツールは src/backend/optimizer/path/allpaths.c:1 において RelOptInfo を関数として検出していますが、実際にはPostgreSQLオプティマイザ全体でリレーション情報を保持するために使用される主要な構造体（struct RelOptInfo）です。allpaths.c の冒頭（1〜69行目）には、この構造体に関連するサブクエリプッシュダウンの安全性評価用ワークスペース struct pushdown_safety_info や関連マクロが定義されています。

目的

PostgreSQLのクエリ最適化プロセスにおいて、ベースリレーション、結合リレーション、アペンドリレーションなどのメタデータ、アクセスパスのリスト、コスト、およびサイズ見積もり（行数や幅）を保持・管理することを目的とします。

入力と出力

  • 入力: allpaths.c 内のパス生成ルーチン（make_one_rel など）において、プランナー情報（PlannerInfo）やジョインリスト、および個々のベースリレーション情報が入力されます。
  • 出力: 最最適化プロセスを通じて、各リレーションに最適なアクセスパス（Path）が追加され、最終的にクエリ全体の最適な結合パスを持つ単一の RelOptInfo 構造体が構築されて返されます。

前提条件と不変条件

  • 各ベースリレーション（RELOPT_BASEREL）は、パス生成（set_base_rel_pathlists）が行われる前に、サイズ見積もり（set_base_rel_sizes）が完了していなければなりません。
  • 制約除外（Constraint Exclusion）により不要と判定されたリレーションは、空のパスを持つダミーリレーション（IS_DUMMY_REL）としてマークされます。

アルゴリズムまたは振る舞い

allpaths.c における RelOptInfo に関連する処理は、以下の段階を経て実行されます。

1. サイズ見積もりとパラレル判定: set_base_rel_sizes により、各ベースリレーションの行数と幅の見積もりが行われ、同時に並列実行の適格性（consider_parallel）が判定されます。 2. パスの生成: set_base_rel_pathlists により、シーケンシャルスキャンやインデックススキャンなどのアクセスパスが生成され、RelOptInfo のパスリストに追加されます。 3. サブクエリのプッシュダウン評価: サブクエリ型のリレーションに対しては、pushdown_safety_info 構造体を用いて、ターゲットリスト列に揮発性関数（UNSAFE_HAS_VOLATILE_FUNC）やセットを返す関数（UNSAFE_HAS_SET_FUNC）が含まれていないかなどの安全性をビットマスクで追跡し、安全な条件のみをプッシュダウンします。 4. 結合探索: standard_join_search などの結合探索アルゴリズムにより、複数の RelOptInfo が段階的に結合され、最終的な単一の RelOptInfo が構築されます。

関連データ構造

  • pushdown_safety_info: サブクエリの条件プッシュダウンの安全性を追跡するためのワークスペース構造体。
  • RestrictInfo: リレーションに適用される制限句や結合条件を保持する構造体。

失敗モードと境界条件

  • プッシュダウンの制限: サブクエリのターゲットリストに揮発性関数（UNSAFE_HAS_VOLATILE_FUNC）や型不一致（UNSAFE_TYPE_MISMATCH）が存在する場合、安全フラグが不適切となり、条件のプッシュダウンが制限されます。
  • ダミーリレーションの扱い: 制約除外によってリレーションが除外された場合、実質的なスキャンパスは生成されず、ダミーリレーションとして処理を早期終了させる必要があります。
