目的

述語式 (predicate) と制限節 (clause) がともに二項演算子式である場合に、一方が他方を論理的に含意するか、あるいは反駁するかを証明する。

シグネチャまたは形状

  • シグネチャ: static bool operator_predicate_proof(Expr *predicate, Node *clause, bool refute_it, bool weak)

入力と出力

  • 引数:
  • Expr *predicate: テスト対象となる述語式
  • Node *clause: 条件として与えられる比較節
  • bool refute_it: 含意ではなく反駁（refutation）を証明する場合は真
  • bool weak: 弱い含意／反駁として評価する場合は真
  • 戻り値:
  • bool: 証明に成功した場合は true、それ以外は false

前提条件と不変条件

  • 入力される predicate および clause は、それぞれ2つの引数を持つ二項演算子式（OpExpr）でなければならない。
  • 双方の演算子が持つ入力照合順序（collation inputcollid）は一致している必要がある。

アルゴリズムまたは振る舞い

1. 基本構造の検証: predicate および clause がともに演算子式であり、かつ引数の数がちょうど2つであるかを検証する。 2. 照合順序の確認: 双方の入力照合順序が一致していることを確認し、一致しない場合は false を返す。 3. サブ式の照合と演算子の正規化:

  • 左右のオペランドの組み合わせを比較し、同一のサブ式と定数（Const）の配置を特定する。
  • 定数が右側に位置するように必要に応じて get_commutator を用いて演算子を反転（commute）させる。
  • 全く一致しない、または両側が定数でないなどの場合は false を返す。

    • 4. NULL 値の処理:

  • clause_const が NULL の場合、厳格（strict）な演算子でなければ偽とし、弱い含意でなければ証明成功（真空的真）とする。
  • pred_const が NULL の場合、厳格な演算子であれば弱い含意または弱い反駁において成功とする。

    • 5. テスト演算子の導出と評価:

  • get_btree_test_op を用いて定数比較用のテスト演算子（test_op）を取得する。
  • 一時的なエグゼキュータ状態（EState）を構築し、メモリコンテキストを切り替えてテスト式（test_op を適用した Const 同士の比較式）を初期化・評価する。
  • 評価結果が NULL の場合は false を返し、それ以外は結果のブール値を返す。

    • 6. クリーンアップ: FreeExecutorState を呼び出して作成したエグゼキュータ状態と関連リソースを解放する。

呼び出し元と呼び出し先

  • 呼び出し先: get_commutator, operator_same_subexprs_proof, op_strict, get_btree_test_op, CreateExecutorState, MemoryContextSwitchTo, make_opclause, fix_opfuncids, ExecInitExpr, ExecEvalExprSwitchContext, FreeExecutorState, elog, DatumGetBool

失敗モードと境界条件

  • 述語や節が二項演算子式ではない場合、または引数の数が2つでない場合に false を返す。
  • 演算子の照合順序が異なる場合に false を返す。
  • 演算子のコミュータが存在せず OidIsValid が不成立の場合に false を返す。
  • 適切なテスト用演算子が取得できない場合に false を返す。
  • 式の評価結果が NULL である場合に false を返す。
