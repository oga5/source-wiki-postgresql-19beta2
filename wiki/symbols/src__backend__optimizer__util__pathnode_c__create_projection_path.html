目的

ProjectionPath ノードを生成・構築し、入力されたサブパスに対して射影（Projection）処理を適用するためのパス情報を初期化する。

シグネチャまたは形状

ProjectionPath * create_projection_path(PlannerInfo *root, RelOptInfo *rel, Path *subpath, PathTarget *target)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体のグローバル情報を格納する構造体へのポインタ。
  • RelOptInfo *rel: このパスが属するリレーション情報。
  • Path *subpath: 射影の入力となる配下のパス。
  • PathTarget *target: 要求されるターゲットリスト（射影内容）。
  • 戻り値:
  • ProjectionPath *: 構築された ProjectionPath ノードへのポインタ。

前提条件と不変条件

  • ProjectionPath の直上に別の ProjectionPath を重ねて配置してはならないという規則があり、入力 subpath がすでに ProjectionPath である場合は自動的に外側のノードが剥がされ、その内部のサブパスが使用される。
  • 剥がされたサブパスの親リレーションが現在のリレーション rel と一致していなければならない。
  • 射影操作自体はソート順を変更しないため、出力パスのソートキー（pathkeys）はサブパスのものがそのまま引き継がれる。

アルゴリズムまたは振る舞い

1. 既存 ProjectionPath の除去:

  • 引数 subpath が ProjectionPath であるかを判定し、該当する場合は親リレーションの一致をアサーションで確認した上で、配下の subpath を取り出す。

    • 2. 基本プロパティの設定:

  • パスタイプを T_Result に設定し、親リレーション、ターゲット、パラメータ情報、並行実行関連のプロータティ（parallel_aware、parallel_workers、およびリレーションの考慮・サブパスの安全性を満たす場合の parallel_safe）、およびパスキーを初期化する。

    • 3. 別個の Result ノードの要否判定（dummypp の決定）:

  • サブパス側が射影実行能力を持つ（is_projection_capable_path(subpath) が真）、あるいは射影能力がなくても望まれるターゲットの式リストが入力の生成する式リストと等しい（equal(oldtarget->exprs, target->exprs) が真）場合は、独立した Result ノードが不要と判断し、pathnode->dummypp = true に設定する。
  • この場合、コストはサブパスのコストをベースとし、ターゲットリストの置換差分（起動コストおよびタプルあたりのコスト変化）に合わせて調整される。
  • 上記条件のいずれも満たさない場合は、独立した Result ノードが必要であると判断して pathnode->dummypp = false とし、CPUタプルコストとターゲット評価コストを加算したコスト計算を行う。

    • 4. 結果返却:

  • 構築された ProjectionPath ポインタを返す。

失敗モードと境界条件

  • サブパスが多重に ProjectionPath でラップされている場合、実装上の規則により1つだけ剥がされる（2つ以上連続して存在しない前提）。
