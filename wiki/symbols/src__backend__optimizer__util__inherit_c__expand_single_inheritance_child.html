/*

  • Build an RTE for the child, and attach to query's rangetable list. We
  • copy most scalar fields of the parent's RTE, but replace relation OID,
  • relkind, and inh for the child. Set the child's securityQuals to
  • empty, because we only want to apply the parent's RLS conditions
  • regardless of what RLS properties individual children may have. (This
  • is an intentional choice to make inherited RLS work like regular
  • permissions checks.) The parent securityQuals will be propagated to
  • children along with other base restriction clauses, so we don't need to
  • do it here. Other infrastructure of the parent RTE has to be
  • translated to match the child table's column ordering, which we do
  • below, so a "flat" copy is sufficient to start with.

    • */ childrte = makeNode(RangeTblEntry); memcpy(childrte, parentrte, sizeof(RangeTblEntry)); Assert(parentrte->rtekind == RTE_RELATION); /* else this is dubious */ childrte->relid = childOID; childrte->relkind = childrel->rd_rel->relkind; /* A partitioned child will need to be expanded further. */ if (childrte->relkind == RELKIND_PARTITIONED_TABLE) { Assert(childOID != parentOID); childrte->inh = true; } else childrte->inh = false; childrte->securityQuals = NIL;

/*

  • Retrieve column not-null constraint information for the child relation
  • if its relation OID is different from the parent's.

    • */ if (childOID != parentOID) get_relation_notnullatts(root, childrel); ~~~

目的

単一の継承先またはパーティション先の子リレーションに対して、新しい範囲テーブルエントリ（RTE）の構築、追加情報構造体（AppendRelInfo）の作成、必要に応じた行マーク（PlanRowMark）および更新対象リレーション（Result Rel）の登録を網羅的に行う関数である。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報を保持する構造体ポインタ。
  • RangeTblEntry *parentrte: 親テーブルの範囲テーブルエントリポインタ。
  • Index parentRTindex: 親リレーションの範囲テーブルインデックス。
  • Relation parentrel: 親リレーションのオープン済みリレーション記述子。
  • PlanRowMark *top_parentrc: 最上位の親行マーク（指定がある場合）。
  • Relation childrel: 子リレーションのオープン済みリレーション記述子。
  • RangeTblEntry **childrte_p: 作成された子RTEの格納先ポインタ。
  • Index *childRTindex_p: 作成された子RTEのインデックスの格納先ポインタ。
  • 戻り値: なし（void）。

前提条件と不変条件

  • 親RTEの種類（rtekind）は RTE_RELATION でなければならない。
  • 割り当てられた子RTEインデックスは、呼び出し元が確保した simple_rel_array_size の範囲内であり、対応するスロットおよびアペンドリレーション配列の該当位置が空（NULL）でなければならない。

アルゴリズムまたは振る舞い

1. **子RTEの初期化とリンク**:

  • 親RTEを基準にメモリコピーを行い、子リレーションの OID、リレーション種別（relkind）、継承フラグ、セキュリティ条件（securityQuals を空に設定）、およびパーミッション情報を設定する。
  • クエリの rtable リストへ子RTEを追加し、リスト長から子RTインデックスを算出してポインタ経由で出力する。

    • 2. **列不null制約およびアペンド関係の構築**:

  • 親と子の OID が異なる場合、子リレーションの列不null制約情報を取得する。
  • make_append_rel_info を用いて親と子の AppendRelInfo を構築し、root->append_rel_list に追加する。
  • 親の tablesample 情報をオブジェクトコピーして子RTEに設定する。

    • 3. **列名エイリアスの構築**:

  • 子リレーションのタプル記述子走査し、削除済み列や親の列マッピング情報、実際の属性名をもとに子テーブル用の列名リストを作成し、子RTEの alias および eref に設定する。

    • 4. **プランナ配列への登録**:

  • simple_rte_array と append_rel_array の該当インデックス位置に、それぞれ子RTEと AppendRelInfo を格納する。

    • 5. **行マークの処理**:

  • top_parentrc が指定されている場合、子用の PlanRowMark を新規作成し、行マーク種別や強度、ウェイトポリシーを設定して root->rowMarks リストに追加する。
  • パーティショニングされた子テーブルの場合は isParent を真に設定する。

    • 6. **結果リレーション（Result Rel）の拡張**:

  • 親RTインデックスが root->all_result_relids に含まれる場合、子RTインデックスも all_result_relids に追加する。
  • 子リレーションがパーティションテーブルでない場合は、leaf_result_relids に追加した上で、 tableoid 属性への Var ノード作成および行識別子列の登録を行う。

失敗モードと境界条件

  • 親RTEの rtekind が RTE_RELATION 以外の場合、アサート違反により異常終了する。
  • 子RTインデックスが root->simple_rel_array_size を超えている場合、または該当スロットがすでに埋まっている場合にアサート違反が発生する。

保守担当者向けメモ

  • 子RTEの securityQuals は意図的に空（NIL）に設定される。これにより、個々の下位子テーブル固有のRLSプロパティに関わらず、親のRLS条件が適用される仕様となっている。
