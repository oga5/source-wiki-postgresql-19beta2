目的

新規に生成されたパスをリレーションの有効なパス一覧へ追加するか、既存の優越するパスとの比較により破棄するかを決定し、parent_rel->pathlist を維持・管理する。

シグネチャまたは形状

  • void add_path(RelOptInfo *parent_rel, Path *new_path)

入力と出力

  • 引数:
  • parent_rel: パスを追加または評価する対象のリレーション情報 (RelOptInfo *)
  • new_path: 評価・追加対象の新しいパス (Path *)
  • 戻り値: なし (void)

前提条件と不変条件

  • パラメータ化されたパスは、パスキーを持たないものとして扱われる。

アルゴリズムまたは振る舞い

1. **初期化と割り込み確認**:

  • 処理の開始時に CHECK_FOR_INTERRUPTS() を呼び出してクエリのキャンセル要求をチェックする。
  • new_path がパラメータを持つ場合は pathkeys を NIL として扱う変数 new_path_pathkeys を用意する。

    • 2. **既存パスとの走査とドミネーション判定**:

  • parent_rel->pathlist 内の既存パス (old_path) を順次ループで走査する。
  • compare_path_costs_fuzzily を用いて、標準の曖昧さ係数 (STD_FUZZ_FACTOR) でコストを比較する (costcmp)。
  • コスト結果が異なる場合 (COSTS_DIFFERENT) を除き、compare_pathkeys でパスキーを比較する (keyscmp)。
  • コスト比較、パスキー比較、要求外部リレーション集合の比較 (bms_subset_compare)、タプル数 (rows)、および並列安全性 (parallel_safe) の優劣を組み合わせて、新規パスが既存パスを優越するか (remove_old = true)、既存パスが新規パスを優越するか (accept_new = false) を判定する。
  • コストとパスキーと外部リレーションがすべて同等の場合は、並列安全性、タプル数、および非常に小さな許容値 (1.0000000001) によるファジィコスト比較の順で優先度を判定し、最終的に同点であれば既存パスを維持する。

    • 3. **既存パスの削除**:

  • 判定の結果 remove_old が真である場合、該当する既存パスを pathlist から削除し、それが IndexPath でない場合は pfree(old_path) でメモリを解放する。

    • 4. **挿入位置の決定**:

  • 既存パスが新規パスを優越せず、削除対象にもならない場合、無効ノード数 (disabled_nodes) または総コスト (total_cost) に基づいて、新規パスの挿入位置 (insert_at) を更新する。
  • 既存パスが new_path を完全に支配している (accept_new == false) と判定された場合は、ループを打ち切る。

    • 5. **新規パスの登録または拒否・解放**:

  • ループ終了後 accept_new が真のままであれば、決定された位置に new_path を list_insert_nth で挿入する。
  • accept_new が偽の場合は、新規パスの追加を拒否し、IndexPath でない場合に限り pfree(new_path) でメモリを解放する。

失敗モードと境界条件

  • 複数パス間でコストやパスキーが競合する場合、プラットフォームごとの丸め誤差による不安定なプラン変動を抑えるため、厳密な比較ではなくファジィ比較を用いる。
  • 複数の古いパスが単一の新しいパスに支配されて同時に破棄される場合がある。
  • 複数箇所で共有される可能性のある IndexPath ノードは、破棄時の pfree 対象から除外される。
