目的

単純なサブクエリを上位クエリの結合ツリーへ引き上げ、範囲テーブル、ターゲットリスト、および関連する相関情報をマージしてクエリ構造を平坦化する。

シグネチャまたは形状

  • シグネチャ: static Node * pull_up_simple_subquery(PlannerInfo *root, Node *jtnode, RangeTblEntry *rte, JoinExpr *lowest_outer_join, AppendRelInfo *containing_appendrel)

入力と出力

  • 引数:
  • PlannerInfo *root: 上位クエリのプランナ情報
  • Node *jtnode: 現在処理中のジョイントリーノード（通常は RangeTblRef）
  • RangeTblEntry *rte: 対象サブクエリに対応する範囲テーブルエントリ
  • JoinExpr *lowest_outer_join: 最も浅い外側結合のコンテキスト（存在する場合）
  • AppendRelInfo *containing_appendrel: 所属するアペンドリレーション情報（存在する場合）
  • 戻り値: 成功時は引き上げ結果を反映した結合ツリーノード（または失敗時の元の jtnode）を返す。

前提条件と不変条件

  • サブクエリの cteList は空（NIL）であること。
  • RTE_GRAPH_TABLE 型の子RTEが出現した場合は Assert(false) により検証される（発生してはならない）。

アルゴリズムまたは振る舞い

1. サブクエリの複製とPlannerInfo作成: サブクエリのモディフィイ可能なコピーを作成し、下位クエリ用の PlannerInfo (subroot) 構造体を初期化する。 2. サブクエリ内部の前処理:

  • preprocess_relation_rtes を呼び出してリレーションRTEの前処理（inhフラグのクリア、非NULL制約の収集、仮想生成列の展開）を行う。
  • replace_empty_jointree により空のFROM句をダミーの RTE_RESULT で置き換える。
  • サブクエリにサブリンクがある場合は pull_up_sublinks を実行し、関数RTEを preprocess_function_rtes でインライン化する。
  • pull_up_subqueries を再帰的に呼び出してサブクエリ内のさらなるサブクエリを引き上げる。

    • 3. 引き上げ可能性の再検証: is_simple_subquery およびアペンドメンバの安全性条件を満たすか再確認し、条件を満たさない場合は元の jtnode をそのまま返して処理を中断する。 4. ターゲットリストと変数の調整:

  • flatten_join_alias_vars によりサブクエリのターゲットリスト内の結合エイリアス変数を平坦化する。
  • OffsetVarNodes を用いてサブクエリ内の varno を上向きの範囲テーブルオフセット分だけオフセットし、IncrementVarSublevelsUp でレベルを1段階引き上げる。

    • 5. 変数置換とコンテキスト設定:

  • pullup_replace_vars_context (rvcontext) を初期化し、グループ化セットが存在する場合は REPLACE_WRAP_ALL オプションを設定する。
  • perform_pullup_replace_vars を呼び出して上位クエリからの参照をサブクエリの出力式に置換する。

    • 6. LATERALマーカーの伝播: 親RTEが lateral である場合、子RTEの種別に応じて child_rte->lateral = true を設定する（ただし RTE_GRAPH_TABLE ではアサートエラー）。 7. リレーションとリストの結合:

  • CombineRangeTables によりサブクエリの範囲テーブルとパーミッション情報を上位クエリに結合する。
  • rowMarks リストを結合する。
  • 必要に応じて substitute_phv_relids や fix_append_rel_relids によりプレースホルダ変数およびアペンドリレーション情報のrelidを修正する。
  • サブクエリの append_rel_list を上位の root->append_rel_list に連結する。

失敗モードと境界条件

  • サブクエリの再検証条件（is_simple_subquery またはアペンドメンバの安全性）が満たされなくなった場合、変更を行わずに元の jtnode を返して処理を放棄する。
  • child_rte->rtekind が RTE_GRAPH_TABLE の場合は、想定外のケースとして Assert(false) により強制終了する。
