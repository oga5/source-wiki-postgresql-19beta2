目的

マージ結合パスの妥当性を検証し、条件を満たす場合にコスト見積もりを経て結合関係（joinrel）へマージ結合パスを追加する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • RelOptInfo *joinrel: 構築対象の結合関係
  • Path *outer_path: 外側リレーションのパス
  • Path *inner_path: 内側リレーションのパス
  • List *pathkeys: 生成するパスのソート順（pathkeys）
  • List *mergeclauses: マージ結合に使用する制限条項のリスト
  • List *outersortkeys: 外側パスをソートするためのキーリスト
  • List *innersortkeys: 内側パスをソートするためのキーリスト
  • JoinType jointype: 結合のタイプ（JoinType）
  • JoinPathExtraData *extra: 結合パス構築に必要な拡張データ
  • bool is_partial: 部分的（Parallel）なパスであるかどうかを示すフラグ
  • 戻り値: なし（void）

前提条件と不変条件

  • is_partial が真の場合、処理は try_partial_mergejoin_path に委譲され即座に終了する。
  • 外部結合（outer join）を形成する場合、外部結合の識別子（ojrelid）が内側または外側パスの要求パラメータ（PATH_REQ_OUTER）に含まれていてはならない。

アルゴリズムまたは振る舞い

1. **部分パスの分岐**: is_partial が真であれば try_partial_mergejoin_path を呼び出して終了する。 2. **外部結合のパラメータチェック**: extra->sjinfo->ojrelid が設定されているとき、その ojrelid が inner_path または outer_path の要求パラメータに含まれている場合は不適格として破棄する。 3. **非ネストループ要求パラメータの算出**: calc_non_nestloop_required_outer(outer_path, inner_path) を用いて必要な外部リレーション集合を算出し、それが extra->param_source_rels と重複しない場合はメモリを解放して破棄する。 4. **ソートキーの最適化（明示的ソートの省略判定）**:

  • outersortkeys が指定されている場合、外側パスのパスキーにすでに含まれていれば outersortkeys を無効（NIL）にし、プレソートされたキー数を取得する。
  • innersortkeys が内側パスのパスキーに含まれている場合は innersortkeys を無効（NIL）にする。

    • 5. **初期コスト見積もり**: initial_cost_mergejoin を呼び出し、ワークスペース構造体にコストおよびワークスペース情報を算出する。 6. **パスの事前チェックと登録**:

  • add_path_precheck によりコストベースの事前検証を行い、合格した場合は create_mergejoin_path でマージ結合パスを生成して add_path で joinrel に登録する。
  • 拒否された場合は、割り当てられた required_outer のメモリを bms_free で解放する。

失敗モードと境界条件

  • パスが事前チェックやパラメータ検証で拒否された経路では、動的に確保された required_outer のビットマップセットが確実に解放される。
