目的

クエリの等価クラス（Equivalence Classes）の統合・マージが完了した安全なタイミングで、クエリの最終出力に必要なソート順を示す query_pathkeys およびその他の関連パスキーフィールドを計算・確定させるためのコールバック関数型です。

入力と出力

  • 入力:
  • PlannerInfo *root: プランナのビルド状態やクエリ情報を保持する構造体へのポインタ。
  • void *extra: コールバック関数に追加の文脈情報を渡すための任意のデータポインタ（qp_extra）。
  • 出力:
  • なし（戻り値の型は void）。ただし、副作用として root 内の query_pathkeys などのパスキーフィールドが設定されます。

前提条件と不変条件

  • 等価クラスの統合およびマージ処理が完全に完了している必要があります。等価クラスの統合が完了するまでは、パスキーを正規形式（canonical form）で構築することができません。
  • トリビアルなクエリ（FROM句のない SELECT など）の場合であっても、コールバック呼び出し前に root->ec_merging_done が true に設定されている必要があります。

アルゴリズムまたは振る舞い

query_planner の実行フローにおいて、以下の2つの経路のいずれかで呼び出されます。

1. トリビアルなクエリ経路（FROM句なしの SELECT や INSERT ... VALUES() など）:

  • 結合木（jointree）が単一の RTE_RESULT リレーションのみで構成されている場合、通常の結合最適化や等価クラス生成処理はバイパスされます。
  • この場合、root->ec_merging_done を true に設定した直後に、本コールバックが直接実行されます。

    • 2. 通常の結合プランニング経路:

  • ベースリレーションの構築、結合木の分解、外側結合句の再考（reconsider_outer_join_clauses）、および暗黙的等価関係の生成（generate_base_implied_equalities）が順次実行されます。
  • 等価クラスのマージがすべて完了した段階で、本コールバックが実行され、正規形式のパスキーが計算されます。

失敗モードと境界条件

等価クラスの構築やマージ（外側結合の再考などを含む）が完了する前に本コールバックが呼び出された場合、パスキーを正規形式で正しく構築できず、プランナが不正なソート順を生成するか、アサーションエラーを引き起こす可能性があります。そのため、呼び出しタイミングは厳密に制御されています。

  • FROM句を持たないクエリ（境界条件）:

    • SELECT 2+2 ORDER BY 1 のように、FROM句がなく結合処理が発生しないトリビアルなクエリであっても、ORDER BY などのソート順を解決するために本コールバックの実行が必要です。この境界条件に対応するため、query_planner は結合プランニングをバイパスする際にも、ダミーの等価クラス完了フラグ（root->ec_merging_done = true）を立てた上で必ず本コールバックを呼び出します。
