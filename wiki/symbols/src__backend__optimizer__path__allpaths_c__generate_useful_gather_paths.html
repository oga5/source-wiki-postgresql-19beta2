目的

指定されたリレーションに対して通常のGather（マージ）パスを生成するとともに、特定の使用可能な順序付け（useful pathkeys）に一致させるためのソートまたはインクリメンタルソート付きの GatherMerge パスを検討・追加する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナ全体の情報を格納する構造体ポインタ。
  • RelOptInfo *rel: 対象となるリレーション情報（RelOptInfo）。
  • bool override_rows: リレーションの行数見積もりを上書きするかどうかを指定するフラグ。
  • 戻り値: なし（void）。

前提条件と不変条件

  • リレーションの partial_pathlist が空（NIL）である場合、処理は即座に終了する。

アルゴリズムまたは振る舞い

1. 初期チェック: リレーションの partial_pathlist が NIL かどうかを判定し、空であれば何もせずにリターンする。 2. 行数上書き設定: override_rows が真の場合は、行数ポインタ (rowsp) をローカルの rows 変数に向ける。 3. 通常Gatherパスの生成: generate_gather_paths を呼び出して通常の gather および gather merge パスを生成する。 4. 興味深い順序付けの取得: get_useful_pathkeys_for_relation を用いて、対象リレーションに有用なパスキーのリスト (useful_pathkeys_list) を取得する。また、完全ソートパス用に partial_pathlist の先頭要素を cheapest partial path として保持する。 5. ソート済みパスの検討ループ:

  • useful_pathkeys_list の各要素と partial_pathlist の各サブパス（subpath）の組み合わせについて、pathkeys_count_contained_in を用いてパスキーの包含状況と事前ソート済みキー数を判定する。
  • サブパスがすでに完全にソートされている場合は、generate_gather_paths によってすでにgather mergeパスが作成されているためスキップする。
  • 最安のパス（cheapest_partial_path）ではなく、かつ事前ソートキーがゼロまたはインクリメンタルソートが無効である場合はスキップする。
  • 事前ソートキーがゼロである場合、あるいはインクリメンタルソートが無効である場合は create_sort_path を適用し、それ以外の場合は create_incremental_sort_path を適用してソート済みサブパスを構築する。
  • 構築されたサブパスに対して compute_gather_rows で行数を計算し、create_gather_merge_path を用いて GatherMerge パスを生成した上で、add_path によりリレーションのパスリストに追加する。

失敗モードと境界条件

  • リレーションに部分パス（partial_pathlist）が存在しない場合、パス生成を行わずに即座に復帰する。
