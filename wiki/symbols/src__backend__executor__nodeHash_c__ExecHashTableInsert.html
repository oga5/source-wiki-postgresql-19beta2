目的

与えられたタプルとハッシュ値に基づき、現在のバッチが一致する場合はインメモリのハッシュテーブルへタプルを挿入し、異なる場合は将来のバッチ用の一時ファイルへ保存する。

入力と出力

  • 引数:
  • HashJoinTable hashtable: 挿入先となるハッシュ結合テーブル構造体
  • TupleTableSlot *slot: 挿入するタプルを保持するスロット
  • uint32 hashvalue: 当該タプルのハッシュ値
  • 戻り値: なし（void）

前提条件と不変条件

  • 新規挿入されるハッシュタプルのタプル一致フラグ（tuple-matched flag）は常にクリアされる。
  • バッチファイルからリロードされたタプルであっても、バッチファイルへ送られる前に外側タプルと一致することはあり得ないため、挿入時のフラグリセットは維持される。

アルゴリズムまたは振る舞い

1. **タプルとバッチの取得**: スロットからミニマルタプルを抽出し、ハッシュ値から ExecHashGetBucketAndBatch を用いてバケット番号とバッチ番号を算出する。 2. **バッチ分岐**: 算出したバッチ番号が現在のバッチ（hashtable->curbatch）と一致するかどうかを判定する。 3. **インメモリハッシュテーブルへの挿入経路（batchno == hashtable->curbatch）**:

  • dense_alloc を用いて、HJTUPLE_OVERHEAD とタプル長を合わせたサイズ分の HashJoinTuple 領域を確保する。
  • ハッシュ値とタプルデータを新しく割り当てた構造体にコピーし、ヘッダーのタプル一致フラグをクリアする。
  • 該当バケットの先頭に生成した HashJoinTuple を接続する。
  • 単一バッチかつ (hashtable->totalTuples - hashtable->skewTuples) が閾値（nbuckets_optimal * NTUP_PER_BUCKET）を超過している場合、オーバーフロー安全性を確認した上で最適なバケット数を倍増させ、対応する log2_nbuckets_optimal をインクリメントする。
  • 使用メモリ量（spaceUsed）を更新し、ピーク値を維持した上で、許容メモリ（spaceAllowed）を超過した場合は ExecHashIncreaseNumBatches を呼び出してバッチ数を増やす。

    • 4. **一時ファイルへの保存経路（batchno != hashtable->curbatch）**:

  • バッチ番号が現在より後方であることを確認した上で、ExecHashJoinSaveTuple を使って該当バッチの一時ファイルへタプルを保存する。

    • 5. **クリーンアップ**: スロット抽出時に割り当てられたミニマルタプルを解放すべきフラグが立っている場合、heap_free_minimal_tuple で解放する。

失敗モードと境界条件

  • バケット数の拡張時に整数オーバーフローやアロケーションサイズ超過が発生しないよう、INT_MAX / 2 および MaxAllocSize の制限チェックが行われる。
  • 現在のバッチより前のバッチ番号が算出された場合はアサーション違反となる。
