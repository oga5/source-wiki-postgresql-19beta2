目的

集合演算ツリーの各ノード（RangeTblRef または SetOperationStmt）を再帰的にトラバーサルし、対応する RelOptInfo やターゲットリスト、パスを構築する。

シグネチャまたは形状

  • シグネチャ: static RelOptInfo * recurse_set_operations(Node *setOp, PlannerInfo *root, SetOperationStmt *parentOp, List *colTypes, List *colCollations, List *refnames_tlist, List **pTargetList, bool *istrivial_tlist)

入力と出力

  • 引数:
  • Node *setOp: 処理対象の集合演算ノード（RangeTblRef または SetOperationStmt）
  • PlannerInfo *root: プランナーのグローバル情報
  • SetOperationStmt *parentOp: 親の集合演算文（存在する場合）
  • List *colTypes: 要求されるカラムのデータ型リスト
  • List *colCollations: 要求されるカラムのコレーションリスト
  • List *refnames_tlist: 参照名解決用のターゲットリスト
  • List **pTargetList: 構築されたターゲットリストを格納するポインタの出力先
  • bool *istrivial_tlist: ターゲットリストが自明（trivial）かどうかを示すフラグの出力先
  • 戻り値: RelOptInfo *: 構築されたリレーション情報

前提条件と不変条件

  • 再帰呼び出しの開始時にスタックオーバーフローを防ぐための深さチェックが行われる。
  • リーフであるサブクエリ処理時点において、現在のクエリレベルで root->plan_params が使用されていない（空である）ことがアサートされる。

アルゴリズムまたは振る舞い

1. **初期化**: *istrivial_tlist を true に設定し、過度なネストによるスタックオーバーフローを防ぐため check_stack_depth() を実行する。 2. **ノード型による分岐**:

  • setOp が RangeTblRef の場合（リーフのサブクエリ）:
  • サブクエリの RelOptInfo を build_simple_rel で構築する。
  • subquery_planner を用いてサブクエリのパスを生成し、subroot を設定する。
  • プリミティブクエリに予期せぬ外部参照（root->plan_params）が含まれている場合は ERROR を送出する。
  • generate_setop_tlist でターゲットリストを算出し、create_pathtarget でリレーションのターゲット（reltarget）を構築して出力引数へ格納する。
  • setOp が SetOperationStmt の場合（内部ノード）:
  • 演算子の種類が SETOP_UNION の場合は generate_union_paths を呼び出し、それ以外の場合は generate_nonunion_paths を呼び出して rel を得る。
  • データの型やコレーションが要求されたものと一致しない場合、varno 0 を指定して generate_setop_tlist を再度実行し、create_pathtarget で投影ターゲットを生成した上で、rel の全通常パスおよび部分パスに対してそれぞれ投影（apply_projection_to_path または create_projection_path）を適用する。
  • postprocess_setop_rel を実行して後処理を行う。
  • その他の型の場合は、認識できないノードタイプとして ERROR を送出する。

    • 3. **終了**: 構築した rel を返す。

失敗モードと境界条件

  • サブクエリのプランニング時に予期せぬ外部参照（root->plan_params が非 NIL）が検出された場合、ERROR レベルのログが送出される。
  • 認識できないノードタグを持つ setOp が渡された場合、nodeTag を伴う ERROR が送出される。
  • 複雑な集合演算のネストによりスタック枯渇の恐れがある場合、check_stack_depth() により検出される。
