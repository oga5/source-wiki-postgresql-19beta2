~~~c static Expr * extract_or_clause(RestrictInfo *or_rinfo, RelOptInfo *rel) { List *clauselist = NIL; ListCell *lc;

/*

  • Scan each arm of the input OR clause. Notice we descend into
  • or_rinfo->orclause, which has RestrictInfo nodes embedded below the
  • toplevel OR/AND structure. This is useful because we can use the info
  • in those nodes to make is_safe_restriction_clause_for()'s checks
  • cheaper. We'll strip those nodes from the returned tree, though,
  • meaning that fresh ones will be built if the clause is accepted as a
  • restriction clause. This might seem wasteful --- couldn't we re-use
  • the existing RestrictInfos? But that'd require assuming that
  • selectivity and other cached data is computed exactly the same way for
  • a restriction clause as for a join clause, which seems undesirable.

    • */ Assert(is_orclause(or_rinfo->orclause)); foreach(lc, ((BoolExpr *) or_rinfo->orclause)->args) { Node *orarg = (Node *) lfirst(lc); List *subclauses = NIL; Node *subclause;

/* OR arguments should be ANDs or sub-RestrictInfos */ if (is_andclause(orarg)) { List *andargs = ((BoolExpr *) orarg)->args; ListCell *lc2;

foreach(lc2, andargs) { RestrictInfo *rinfo = lfirst_node(RestrictInfo, lc2);

if (restriction_is_or_clause(rinfo)) { /*

  • Recurse to deal with nested OR. Note we *must* recurse
  • here, this isn't just overly-tense optimization: we
  • have to descend far enough to find and strip all
  • RestrictInfos in the expression.

    • */ Expr *suborclause;

suborclause = extract_or_clause(rinfo, rel); if (suborclause) subclauses = lappend(subclauses, suborclause); } else if (is_safe_restriction_clause_for(rinfo, rel)) subclauses = lappend(subclauses, rinfo->clause); } } else { RestrictInfo *rinfo = castNode(RestrictInfo, orarg);

Assert(!restriction_is_or_clause(rinfo)); if (is_safe_restriction_clause_for(rinfo, rel)) subclauses = lappend(subclauses, rinfo->clause); ~~~

定義

目的

入力された結合OR条件（or_rinfo）の各アームを再帰的に走査し、指定されたリレーション（rel）のみを安全に参照する部分式を抽出して、新しい制限OR条件を構築する。

シグネチャまたは形状

  • static Expr * extract_or_clause(RestrictInfo *or_rinfo, RelOptInfo *rel)

入力と出力

  • 引数:
  • RestrictInfo *or_rinfo: 処理対象のOR結合条件を表す RestrictInfo。
  • RelOptInfo *rel: 制限条件の安全性を評価し抽出対象とする対象リレーション。
  • 戻り値:
  • Expr *: 抽出された部分式から組み立てられた新しいOR式。条件を満たす式が抽出できない場合は NULL を返す。

前提条件と不変条件

  • or_rinfo->orclause はトップレベルがOR構造（is_orclause が真）でなければならない。
  • AND節以外のアーム（orarg）を直接処理する場合、そのアームはネストしたOR節であってはならない。
  • 抽出元の RestrictInfo ノードは結果の式ツリーから取り除かれ、制限条件として採用される場合は新しい RestrictInfo ノードが再構築される。

アルゴリズムまたは振る舞い

1. **ORアームの走査**: or_rinfo->orclause の各引数（アーム）を foreach ループで順に処理する。 2. **AND節および部分式・ネストORの判定**:

  • アームがAND節である場合（is_andclause(orarg)）、そのAND引数リストを走査する。各要素がネストしたOR制限条件であれば extract_or_clause を再帰呼び出しし、安全な制限条件であれば is_safe_restriction_clause_for(rinfo, rel) で判定して subclauses に追加する。
  • アームがAND節以外である場合、RestrictInfo としてキャストし、ネストしたORではないことをアサートで確認した上で is_safe_restriction_clause_for(rinfo, rel) を満たす場合に subclauses に追加する。

    • 3. **アームごとの抽出結果チェック**: もしあるアームから何もサブ式が抽出できなかった場合（subclauses == NIL）、このOR条件全体は処理できないため NULL を返して終了する。 4. **サブ式のフラット化と結合**: 抽出されたサブ式を make_ands_explicit で結合し、結果がさらにORノードである場合はAND/ORのフラット性を保つためにその引数を clauselist に展開し、それ以外の場合は clauselist に追加する。 5. **最終的なOR式の構築**: すべてのアームから有効な制限条件が抽出できた場合、clauselist を make_orclause でラップして返し、一つも得られなかった場合は NULL を返す。

呼び出し元と呼び出し先

  • 呼び出し元:
  • extract_restriction_or_clauses
  • extract_or_clause (再帰呼び出し)
  • 呼び出し先:
  • is_safe_restriction_clause_for
  • make_ands_explicit
  • make_orclause

失敗モードと境界条件

  • **アームからの抽出失敗による全体の中断**: OR条件のいずれか1つのアーム（引数）から、対象リレーション rel にとって安全な制限条件（サブ式）が1つも抽出できなかった場合（subclauses == NIL）、OR条件全体の論理的整合性を保てなくなるため、処理を中断して即座に NULL を返す。
  • **非OR構造の入力**: 入力された or_rinfo->orclause がOR節でない場合、Assert(is_orclause(...)) によりアサーションエラーとなる。
  • **AND節以外での不正なネストOR**: AND節ではないアーム（orarg）を処理する際、それがネストしたOR節（restriction_is_or_clause(rinfo) が真）である場合は、想定外の構造であるため Assert(!restriction_is_or_clause(rinfo)) によりアサーションエラーとなる。
  • **抽出結果が空の場合の返却**: 最終的に構築された clauselist が NIL である場合、有効なOR式を構築できないため NULL を返す。

保守担当者向けメモ

  • 既存の RestrictInfo ノードの再利用は選択率やキャッシュデータの不整合を招くため行わず、本関数はノードを剥がした上で新しく構築する前提で設計されている。
