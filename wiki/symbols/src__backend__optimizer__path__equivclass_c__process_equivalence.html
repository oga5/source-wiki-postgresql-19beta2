目的

マージ結合可能な条件式を評価し、対応する同値クラス（EquivalenceClass）への登録、既存の同値クラス同士の統合、あるいは新たな同値クラスの作成を行うことで、等価関係を管理・構築します。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • RestrictInfo **p_restrictinfo: 評価対象の制限句へのポインタ
  • JoinDomain *jdomain: 結合ドメイン
  • 戻り値: bool （同値クラスの構築や結びつけに成功して等価関係が取り込まれた場合は true、X=X のように変換処理が行われた場合やセキュリティ上の理由で拒否された場合は false を返します）

前提条件と不変条件

  • 処理対象の RestrictInfo は、まだ同値クラス（eclass）を生成済みとしてマークされていない（left_ec == NULL かつ right_ec == NULL）必要があります。
  • 既存の同値クラスのマージが完了している状態（root->ec_merging_done が真）のとき、異なる同値クラス同士を統合しようとするとエラーが発生します。

アルゴリズムまたは振る舞い

1. **初期検証とセキュリティチェック**:

  • restrictinfo の左右の同値クラスポインタが NULL であることをアサートで確認します。
  • セキュリティレベルが 0 より大きく、かつ leakproof でない制限句は、延期される可能性があるため処理を中止して false を返します。

    • 2. **条件式からの情報抽出と正規化**:

  • 演算子句から左右の式（item1, item2）、演算子 OID、照合順序（collation）、およびリレーション ID を抽出します。
  • canonicalize_ec_expression を用いて、左右の入力式が指定された照合順序を正しく暴露するように調整します。

    • 3. **X=X 形式の条件の特例処理**:

  • item1 と item2 が等しい場合、同値クラスへの変換は行いません。
  • 演算子が strict である場合は IS NOT NULL の NullTest 制限句に置き換え、元の *p_restrictinfo を差し替えて false を返します。

    • 4. **既存同値クラスの走査と照合**:

  • 演算子の宣言上の入力型を取得します。
  • root->eq_classes を順に走査し、揮発性（volatile）でないこと、照合順序が一致すること、および btree 演算子ファミリが一致する既存の同値クラス（cur_ec）を探します。
  • 一致する cur_ec 内のメンバーを探索し、item1 または item2 に該当する既存メンバーが存在するか判定します。

    • 5. **照合結果に応じた分岐処理**:

  • **ケース 1（両方とも同じ同値クラスに存在する場合）**: すでに等価関係が既知であるため、ec_sources に restrictinfo を追加し、セキュリティ範囲を更新した上で、制限句に同値クラスと対応するメンバーを設定して true を返します。
  • **ケース 2（両方とも異なる同値クラスに存在する場合）**: すでにマージ完了状態であればエラー (elog) をスローします。それ以外の場合は、一方の同値クラスへもう一方のメンバー、ソース、および派生句を結合し、マージ元の同値クラスのリンクを設定して eq_classes リストから削除します。その後、制限句に統合後の同値クラスとメンバーを割り当てて true を返します。
  • **ケース 3（一方のみが見つかった場合）**: 見つからなかった側の式を add_eq_member で既存の同値クラスに追加し、ソースの追加とセキュリティ範囲の更新を行った上で制限句に結びつけます。

失敗モードと境界条件

  • root->ec_merging_done が真の状態で異なる既存同値クラス同士を統合しようとした場合、致命的エラー（ERROR）が発生します。
  • セキュリティレベルが 0 より大きくリークプルーフでない制限句が入力された場合、同値クラスへの登録は行われず false が返されます。
