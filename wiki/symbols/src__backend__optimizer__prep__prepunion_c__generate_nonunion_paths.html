目的

INTERSECT や EXCEPT（およびそれぞれの ALL 修飾付き）といった非 UNION 集合演算クエリに対する RelOptInfo および実行パス群を生成する。

入力と出力

  • 引数:
  • SetOperationStmt *op: 対象の集合演算ステータスツリーノード
  • PlannerInfo *root: プランナーのグローバル情報
  • List *refnames_tlist: 参照名解決用のターゲットリスト
  • List **pTargetList: 出力されるターゲットリストの格納先ポインタ
  • 戻り値:
  • RelOptInfo *: 集合演算結果を表現するリレーション情報

前提条件と不変条件

  • 子ノード側のタプル取得を強制するため、処理の先頭で root->tuple_fraction が一時的に 0.0 に設定される。

アルゴリズムまたは振る舞い

1. **子孫の再帰的処理**: 子ノード（op->larg と op->rarg）に対して recurse_set_operations を呼び出し、左右それぞれの部分リレーション、ターゲットリスト、および自明なターゲットリストフラグを取得する。 2. **ターゲットリストとグルーピングの識別**: generate_setop_tlist により SetOp プランノード用のターゲットリストを生成し、generate_setop_grouplist でグルーピング・ソート節を特定する。 3. **演算サポートの確認**: grouping_is_sortable と grouping_is_hashable を用いて、ソートまたはハッシュが可能かを判定する。どちらもサポートされない場合はエラーを報告する。 4. **子パスの構築と順序最適化**: サブクエリである子リレーションに対して build_setop_child_paths を実行して行数を見積もる。INTERSECT の場合は、ハッシュテーブルのサイズ最小化や空入力の高速パスを活用するため、行数（グループ数）が少ない方を左側にスワップする。 5. **ダミーリレーションの短絡処理**: 一方が空リレーション（ダミー）である場合、EXCEPT や INTERSECT の性質に応じて mark_dummy_rel を設定し、早期リターンする。 6. **パスの追加**: ハッシュが可能な場合は create_setop_path と add_path を用いてハッシュベースのパスを追加する。ソートが可能な場合は、必要に応じて create_sort_path を挿入した上でソートベースのパスを追加する。

失敗モードと境界条件

  • データ型がソートまたはハッシュのいずれか一方しかサポートしていない混在状態の場合、ERRCODE_FEATURE_NOT_SUPPORTED エラーを送出する。
  • 認識されない op->op 値が渡された場合、ERROR レベルの elog を引き起こす。
