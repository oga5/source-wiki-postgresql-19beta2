目的

have_relevant_joinclause 関数は、指定された2つのリレーション（rel1 と rel2）の間に関連する結合条件が存在するかどうかを検出します。結合条件は、その結合ステップで直接評価できないもの（例: 他のリレーションも含める必要のある条件）であっても、リレーション間を結合する理由として意図的に考慮されます。

シグネチャまたは形状

  • シグネチャ: bool have_relevant_joinclause(PlannerInfo *root, RelOptInfo *rel1, RelOptInfo *rel2)

入力と出力

  • 入力:
  • root: プランナー全体の情報を持つ PlannerInfo へのポインタ。
  • rel1: 判定対象の1つ目のリレーション情報 (RelOptInfo)。
  • rel2: 判定対象の2つ目のリレーション情報 (RelOptInfo)。
  • 出力:
  • bool: 関連する結合条件が存在する場合は true、それ以外の場合は false。

前提条件と不変条件

  • 効率化のため、rel1 と rel2 のうち要素数が少ない方の joininfo リストが走査対象に選択されます。

アルゴリズムまたは振る舞い

1. リスト長に基づく走査元選択: rel1->joininfo の長さと rel2->joininfo の長さを比較し、より短い方のリストを joininfo 変数に設定し、もう一方のリレーションの relids を other_relids に設定します。 2. 結合リストの走査: 選択した joininfo リスト内の各 RestrictInfo（rinfo）について、その required_relids が other_relids とオーバーラップするかどうかを bms_overlap で確認します。 3. 一致の検出: オーバーラップする RestrictInfo が見つかった場合、結果を true に設定してループを抜けます。 4. 同値クラスの確認: リスト内に該当する結合条件が見つからず、かつ両リレーションの has_eclass_joins フラグが真である場合、have_relevant_eclass_joinclause を呼び出して同値クラスデータ構造内の関係性を追加で確認します。

失敗モードと境界条件

  • joininfo リストが空である場合、リスト上の走査では一致が見つからないため、同値クラス結合の確認結果（または初期値の false）に依存します。
