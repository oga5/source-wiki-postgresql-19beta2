目的

サブクエリや値リストの引き上げ時に、上位クエリ内の変数（Var）参照をターゲットリストから展開された式に置換し、必要に応じてプレースホルダ変数（PlaceHolderVar）によるラップや結合の NULL 化関係（varnullingrels）の伝播を行うコールバック関数です。

入力と出力

  • 引数:
  • const Var *var: 置換対象の変数ノード。
  • replace_rte_variables_context *context: コールバック引数として pullup_replace_vars_context を保持するコンテキスト。
  • 戻り値:
  • Node *: 置換、ラップ、または varnullingrels の伝播が行われた新しい式ノード。

前提条件と不変条件

  • システム列（varattno < InvalidAttrNumber）は置換されず、そのままコピーして返されます。
  • キャッシュされたプレースホルダ変数は、 phlevelsup = 0 および phnullingrels = NULL を持つ状態でキャッシュされ、参照箇所に合わせて適宜調整されます。

アルゴリズムまたは振る舞い

1. システム列の除外: varattno がシステム列（InvalidAttrNumber 未満）である場合は、単純に copyObject(var) を返して終了します。 2. プレースホルダ要否の判定: 変数が空でない varnullingrels を持つか、あるいは呼び出し元からラップが指定されている場合（rcon->wrap_option != REPLACE_WRAP_NONE）に need_phv を真に設定します。 3. キャッシュの利用: need_phv が真かつ varattno が有効な範囲内でキャッシュが存在する場合、rcon->rv_cache[varattno] から複製を取得して後続の調整へ進みます。 4. ターゲットリストからの式生成: キャッシュミス時は ReplaceVarFromTargetList を呼び出し、ターゲットとなる RTE やターゲットリストから置換式 newnode を生成します。 5. ラップ判定: need_phv が有効な場合、以下の条件に従ってプレースホルダ変数によるラップが必要かを決定します。

  • REPLACE_WRAP_ALL 指定時、または全タプル参照（InvalidAttrNumber）の場合はラップします。
  • 単純な Var や PlaceHolderVar でレベルが 0 の場合、非ラテラルであれば原則ラップを回避し、ラテラル参照の場合は関連する nullingrels の包含関係を検証して必要に応じてラップします。
  • その他の式の場合、非厳格（non-strict）な関数を含まず、かつ nullable な変数を含む場合はラップを回避し、それ以外の場合は make_placeholder_expr でラップしてキャッシュに格納します。

    • 6. ヌリング関係の伝播: var->varnullingrels が存在する場合、newnode の種類（Var、PlaceHolderVar、またはその他の式）に応じて varnullingrels や phnullingrels を追加、あるいはラテラル参照に対する適切な add_nulling_relids 処理を行います。

失敗モードと境界条件

  • 無効な属性番号やキャッシュ範囲外のアクセスに対しては、適切なガード条件（varattno >= InvalidAttrNumber やリスト長との比較）によって安全にフォールバックまたはキャッシュバイパスが行われます。
