目的

ON CONFLICT 句の競合解決で使用する一意インデックスを推論・決定する。

シグネチャまたは形状

  • シグネチャ: List * infer_arbiter_indexes(PlannerInfo *root)

入力と出力

  • 引数: PlannerInfo *root (PlannerInfo 構造体へのポインタ)
  • 戻り値: List * (推論されたインデックスの OID リスト)

前提条件と不変条件

  • 対象のリレーションに対するロックは、リライータまたは expand_inherited_rtentry() によって事前に取得済みである必要があるため、関数内での追加のロック取得は不要である。
  • ON CONFLICT DO NOTHING において推論仕様や名前付き制約が指定されていない場合は、直ちに NIL を返す。

アルゴリズムまたは振る舞い

1. クエリの onConflict 情報を取得し、arbiterElems が空かつ constraint が InvalidOid の場合は NIL を返す。 2. root->parse->resultRelation からレンジテーブルエントリ（RangeTblEntry）を取得し、table_open を用いて対象リレーションをオープンする。 3. arbiterElems が指定されている場合、各要素を走査して単純な Var の場合は属性番号をビットマップ (inferAttrs) に追加し、式の場合は inferElems リストに蓄積する。全行を対象とする一意インデックス指定（属性番号が 0）の場合はエラーを報告する。 4. RelationGetIndexList を用いてリレーションのインデックスリストを取得し、各インデックスを index_open でオープンして保持する。 5. constraint が指定されている場合は、get_constraint_index で対応するインデックス OID を取得し、該当するインデックスリレーションから属性、式、述語情報を取得して照合用の設定を行う。 6. オープンしたインデックスのリストを反復処理し、indisready が偽のインデックスや、パーティショナルテーブルにおける indisvalid が偽のインデックスを除外する。 7. 指定された制約、一意性（indisunique）、除外制約（indisexclusion）、属性・式のマッチング、および照合順序・演算子クラスの一致を確認し、条件を満たすインデックスの OID を結果リストに追加する。

失敗モードと境界条件

  • arbiterElems において属性番号が 0（全行を対象とする仕様）のインデックス推論が指定された場合、フィーチャ非対応としてエラー（ERRCODE_FEATURE_NOT_SUPPORTED）を報告する。
  • ON CONFLICT 句で名前付き制約が指定されたにもかかわらず、対応するインデックスが存在しない場合はエラー（ERRCODE_WRONG_OBJECT_TYPE）を報告する。
  • 除外制約に対して ON CONFLICT DO UPDATE または ON CONFLICT DO SELECT アクションが指定された場合、サポート対象外としてエラーを報告する。
