~~~c static void set_base_rel_consider_startup(PlannerInfo *root) { /*

  • Since parameterized paths can only be used on the inside of a nestloop
  • join plan, there is usually little value in considering fast-start
  • plans for them. However, for relations that are on the RHS of a SEMI
  • or ANTI join, a fast-start plan can be useful because we're only going
  • to care about fetching one tuple anyway.

    • *

  • To minimize growth of planning time, we currently restrict this to
  • cases where the RHS is a single base relation, not a join; there is no
  • provision for consider_param_startup to get set at all on joinrels.
  • Also we don't worry about appendrels. costsize.c's costing rules for
  • nestloop semi/antijoins don't consider such cases either.

    • */ ListCell *lc;

foreach(lc, root->join_info_list) { SpecialJoinInfo *sjinfo = (SpecialJoinInfo *) lfirst(lc); int varno;

if ((sjinfo->jointype == JOIN_SEMI || sjinfo->jointype == JOIN_ANTI) && bms_get_singleton_member(sjinfo->syn_righthand, &varno)) { RelOptInfo *rel = find_base_rel(root, varno);

rel->consider_param_startup = true; } } } ~~~

目的

セミ結合（SEMI）またはアンチ結合（ANTI）の右側にある単一ベースリレーションに対して、パラメータ化されたパスの高速スタートアップ（fast-start）評価を有効化するかどうかを判定し、設定する。

入力と出力

  • 引数: PlannerInfo *root （プランナの全体情報を保持する構造体へのポインタ）
  • 戻り値: なし（void）

前提条件と不変条件

  • パラメータ化されたパスは通常ネストループ結合の内側で使用されるため高速スタートアップを考慮する価値は低いが、SEMI または ANTI 結合の右側にあるリレーションでは 1 タプルのみの取得に関心があるため有用となる。
  • 計画時間の増大を抑えるため、結合ではなく単一のベースリレーションが右側にある場合のみに制限され、結合リレーションやアペンドリレーションには適用されない。

アルゴリズムまたは振る舞い

  • root->join_info_list 内の各結合情報を順に走査する。
  • 各 SpecialJoinInfo の結合種別（jointype）が JOIN_SEMI または JOIN_ANTI であり、かつ右側構文ツリー（syn_righthand）が単一のベースリレーション（変数番号 varno）から構成されているかをチェックする。
  • 条件を満たす場合、対応するベースリレーションの RelOptInfo を find_base_rel により取得し、その consider_param_startup フラグを true に設定する。

失敗モードと境界条件

  • 結合の右側が複数リレーションによる結合である場合や、アペンドリレーションである場合は対象外となるため、フラグは変更されない。
