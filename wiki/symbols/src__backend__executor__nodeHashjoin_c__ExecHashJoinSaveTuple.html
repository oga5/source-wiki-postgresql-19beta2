~~~c void ExecHashJoinSaveTuple(MinimalTuple tuple, uint32 hashvalue, BufFile **fileptr, HashJoinTable hashtable) { BufFile *file = *fileptr;

/*

  • The batch file is lazily created. If this is the first tuple written to
  • this batch, the batch file is created and its buffer is allocated in
  • the spillCxt context, NOT in the batchCxt.

    • *

  • During the build phase, buffered files are created for inner batches.
  • Each batch's buffered file is closed (and its buffer freed) after the
  • batch is loaded into memory during the outer side scan. Therefore, it
  • is necessary to allocate the batch file buffer in a memory context
  • which outlives the batch itself.

    • *

  • Also, we use spillCxt instead of hashCxt for a better accounting of the
  • spilling memory consumption.

    • */ if (file == NULL) { MemoryContext oldctx = MemoryContextSwitchTo(hashtable->spillCxt);

file = BufFileCreateTemp(false); *fileptr = file;

MemoryContextSwitchTo(oldctx); }

BufFileWrite(file, &hashvalue, sizeof(uint32)); BufFileWrite(file, tuple, tuple->t_len); } ~~~

目的

メモリからあふれたハッシュ結合のタプル（インナーバッチのタプルなど）を、必要に応じて遅延作成される一時ファイルへ書き出して保存する。

入力と出力

  • 引数:
  • MinimalTuple tuple: 保存する対象の最小タプル
  • uint32 hashvalue: タプルに対応するハッシュ値
  • BufFile **fileptr: 書き込み先の一時ファイルポインタへの参照
  • HashJoinTable hashtable: ハッシュ結合テーブル構造体
  • 戻り値: なし（void）

前提条件と不変条件

  • バッチファイルは遅延作成され、最初のタプルが書き込まれるまで fileptr が指すファイルポインタは NULL である。
  • バッチファイルおよびそのバッファは、バッチ自体の生存期間を超えて持続させるため、バッチコンテキストではなく hashtable->spillCxt コンテキスト上に割り当てられる。

アルゴリズムまたは振る舞い

1. 引数 fileptr が指す BufFile が NULL であるか確認する。 2. NULL の場合、メモリコンテキストを hashtable->spillCxt に切り替え、一時ファイル（BufFileCreateTemp(false)）を新規作成して *fileptr に格納したのち、元のメモリコンテキストに戻す。 3. 一貫して、一時ファイルに対して先頭に hashvalue（uint32 サイズ）を書き込み、続いてタプル本体（tuple から tuple->t_len バイト）を書き込む。

失敗モードと境界条件

  • メモリコンテキストの切り替え時に hashtable->spillCxt が有効である必要がある。
  • BufFileCreateTemp または BufFileWrite の実行時にディスク容量不足やファイルシステムエラーなどの問題が発生した場合、ファイルストレージ層のエラー送出パスに従う。
