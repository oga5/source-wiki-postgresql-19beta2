目的

入力パスの pathkeys と照らし合わせて、GROUP BY キーおよび対応するグループ句の順序を再配置し、一致したプレフィックスの長さを返す。

シグネチャまたは形状

  • シグネチャ: static int group_keys_reorder_by_pathkeys(List *pathkeys, List **group_pathkeys, List **group_clauses, int num_groupby_pathkeys)

入力と出力

  • 引数:
  • pathkeys: 入力パスの順序を決定するパスキーのリスト
  • group_pathkeys: グループ化パスキー全体のリストへのポインタ
  • group_clauses: グループ句のリストへのポインタ
  • num_groupby_pathkeys: グループ化パスキーのうち探索対象とする先頭からの件数
  • 戻り値:
  • int: マッチングした GROUP BY キーのパスキー数

前提条件と不変条件

  • pathkeys または *group_pathkeys が空リストである場合、即座に 0 を返す。
  • 関連付けられたパスキーが存在する限り、ソートグループ句には有効な順序付け演算子が存在する。

アルゴリズムまたは振る舞い

1. pathkeys または *group_pathkeys が NIL の場合は 0 を返す。 2. *group_pathkeys に含まれる集約パスキーを除外するため、先頭 num_groupby_pathkeys 個の要素をコピーした grouping_pathkeys を作成する。 3. pathkeys の各要素を走査し、以下の条件のいずれかを満たす場合にループを打ち切る：

  • 現在のインデックスが num_groupby_pathkeys 以上である。
  • grouping_pathkeys 内に該当の pathkey が存在しない。
  • pathkey->pk_eclass->ec_sortref が 0 である。
  • get_sortgroupref_clause_noerr によるグループ句の取得に失敗する。

    • 4. 条件を満たすパスキーとソートグループ句を、それぞれ new_group_pathkeys と new_group_clauses に追加する。 5. 一致したパスキーの長さを n として保持する。 6. new_group_pathkeys および new_group_clauses を既存のリストと一意に結合し、*group_pathkeys と *group_clauses を更新する。 7. grouping_pathkeys を解放し、一致した件数 n を返す。

失敗モードと境界条件

  • root->group_pathkeys にグループ化パスキーと集約パスキーが混在している場合、集約パスキー側は ec_sortref がクエリのターゲットリストを参照しないため、num_groupby_pathkeys による制限によって不正な結果を防ぐ。
  • 基礎となるノード由来のパスキーが root->group_pathkeys に存在しても、処理対象の processed_groupClause に含まれない場合があるため、get_sortgroupref_clause_noerr で見つからない場合は処理を中断する。
