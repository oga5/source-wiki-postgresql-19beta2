目的

make_outerjoininfo は、外部結合（アウタージョイン）、セミジョイン、またはアンチジョインの計画に必要な情報を保持する SpecialJoinInfo 構造体を新規に作成し、初期化します。この関数は、クエリツリー内の行ロック句（FOR UPDATE や FOR SHARE など）の適用可否を検証し、結合順序の制約や、結合の左右両辺に必要な最小限のリレーションID集合（min_lefthand、min_righthand）を算出します。

入力と出力

  • 入力:
  • root: プランナのグローバル情報を保持する PlannerInfo 構造体へのポインタ。
  • left_rels: 結合の左辺（LHS）を構成する構文上のリレーションID集合（Relids）。
  • right_rels: 結合の右辺（RHS、ヌル許容側）を構成する構文上のリレーションID集合（Relids）。
  • inner_join_rels: 結合条件に含まれる内側結合リレーションの集合。
  • jointype: 結合の種別（JoinType）。ただし、JOIN_INNER および JOIN_RIGHT は除外されます。
  • ojrelid: 外部結合自体を識別するインデックス（存在しない場合は0）。
  • clause: 結合条件（JOIN/ON 句など）を表す式のリスト。
  • 出力:
  • 新規に割り当てられ、初期化された SpecialJoinInfo 構造体へのポインタ。

前提条件と不変条件

  • 前提条件:
  • 入力される jointype は JOIN_INNER または JOIN_RIGHT であってはなりません。右外部結合（RIGHT JOIN）は、この関数が呼び出される前段階で左右が入れ替えられている必要があります。
  • 不変条件:
  • 最終的に算出される min_lefthand および min_righthand は、いずれも空集合（empty）であってはなりません。
  • min_lefthand と min_righthand の間に重複するリレーションIDが存在してはなりません（互いに素である必要があります）。

アルゴリズムまたは振る舞い

1. ノードの生成と基本初期化: makeNode(SpecialJoinInfo) により構造体を割り当て、構文上の左右のリレーション集合（syn_lefthand、syn_righthand）、結合種別、および外部結合リレーションID（ojrelid）を設定します。 2. 行ロック句の検証: クエリの rowMarks リストを走査し、ヌル許容側となるリレーション（右辺、または完全外部結合における左辺）に対して FOR UPDATE や FOR SHARE などの行ロック句が指定されている場合は、エラーを発生させます。 3. セミジョイン情報の計算: compute_semijoin_info を呼び出し、セミジョインまたはアンチジョインに関する情報を設定します。 4. 完全外部結合（JOIN_FULL）の早期リターン: jointype が JOIN_FULL の場合、min_lefthand に left_rels のコピーを、min_righthand に right_rels のコピーを設定し、lhs_strict を false に設定して即座に返却します。 5. 結合条件の解析: pull_varnos を用いて結合条件（clause）から参照されている全リレーションID（clause_relids）を抽出し、find_nonnullable_rels を用いて条件が厳格（strict）であるリレーションID（strict_relids）を特定します。結合条件が左辺のリレーションに対して厳格であるかどうかの判定結果を lhs_strict に記録します。 6. 最小リレーション集合の初期計算: min_lefthand を clause_relids と left_rels の積集合として初期化します。また、min_righthand を clause_relids と inner_join_rels の和集合に対して、right_rels との積集合をとることで初期化します。 7. 既存の外部結合との順序制約の解決: root->join_info_list に登録されている既存の外部結合（otherinfo）を走査し、結合順序の制約を評価します。

  • 完全外部結合との重複: 既存の結合が JOIN_FULL であり、現在の結合の左辺または右辺と重複する場合、最適化障壁として機能するため、該当する側の最小リレーション集合にその完全外部結合の全構成リレーションおよび ojrelid を追加します。
  • 左辺に位置する下位外部結合: 現在の結合条件が下位外部結合の右辺を参照しており、かつ非厳格（non-strict）である場合や、プレースホルダ変数（PHV）の安全性に問題がある場合、または現在の結合がセミジョイン/アンチジョインである場合は、順序を維持するために下位外部結合の全リレーションを min_lefthand に追加します。条件を満たし結合の可換性（Commutation）が成立する場合は、順序制約を緩和します。
  • 右辺に位置する下位外部結合: 現在の結合条件が下位外部結合の右辺を参照している場合や、下位外部結合の左辺を参照していない場合、あるいはPHVの安全性、セミジョイン/アンチジョインの存在、下位外部結合の非厳格性などの要因がある場合は、順序を維持するために下位外部結合の全リレーションを min_righthand に追加します。可換性が成立する場合は、順序制約を緩和します。

    • 8. プレースホルダ変数（PHV）の評価位置の反映: root->placeholder_list を走査し、現在の結合の右辺（ヌル許容側）で評価されるべき PHV が存在する場合、その PHV の評価位置（ph_eval_at）を min_righthand に追加して、PHV が評価される前に結合が形成されるのを防ぎます。 9. 空集合のフォールバックと最終アサーション: min_lefthand または min_righthand が空のままである場合は、それぞれ left_rels または right_rels のコピーで補完します。最後に、両集合が空でなく、かつ重複がないことをアサートで検証します。

失敗モードと境界条件

  • サポート対象外のエラー:

    • 外部結合のヌル許容側（右辺、または完全外部結合における左辺）に位置するリレーションに対して、FOR UPDATE や FOR SHARE などの行ロック句が指定されている場合、実行エンジンがこれをサポートしていないため、ERRCODE_FEATURE_NOT_SUPPORTED エラー（"cannot be applied to the nullable side of an outer join"）を発生させます。
