目的

関係（Relation）内の指定されたタプルを新しいタプルで置換します。

入力と出力

  • 引数:
  • Relation relation: 更新対象のテーブル関係
  • const ItemPointerData *otid: 更新する旧タプルの物理位置（TID）
  • HeapTuple newtup: 書き込む新しいタプルデータ
  • CommandId cid: コマンドID
  • uint32 options pg_attribute_unused(): 更新オプション
  • Snapshot crosscheck: クロスチェック用スナップショット
  • bool wait: ロック競合時に待機するかどうか
  • TM_FailureData *tmfd: 失敗時の詳細情報格納先
  • LockTupleMode *lockmode: 獲得したタプルロックモードの格納先
  • TU_UpdateIndexes *update_indexes: インデックス更新要否の格納先
  • 戻り値: TM_Result（更新処理の結果ステータス）

前提条件と不変条件

  • otid は有効なアイテムポインタである必要があります。
  • newtup の属性数が関係のリレーションの属性数以下である必要があります。
  • TOAST用のスナップショットが存在している必要があります。
  • 並行操作中（Parallel Mode）の実行は許可されません。

アルゴリズムまたは振る舞い

1. **初期チェック**: アサーションによる検証および並行操作中の実行禁止チェックを行います。 2. **属性マップの取得**: ホットブロック、集約、キー、識別子キーに関するインデックス属性のビットマップを取得します。 3. **バッファのピン留めとロック**: 対象ブロックのバッファを読み込み、必要に応じて可視性マップをピン留めした上で、バッファを排他ロックします。 4. **アイテム状態の検証**: アイテムIDが正規の状態でない場合（同時プルーニングなど）はバッファを解放し、TM_Deleted を返します。 5. **変更カラムの特定とロックモード決定**: HeapDetermineColumnsInfo を用いて変更されたカラムを特定し、キーカラムが変更されていない場合は LockTupleNoKeyExclusive、変更されている場合は LockTupleExclusive を選択します。 6. **可視性判定と競合処理**: HeapTupleSatisfiesUpdate により旧タプルの可視性を確認し、他トランザクションによる変更中の場合は必要に応じて待機やマルチトランザクションの競合処理を行います。

失敗モードと境界条件

  • パラレル操作中に呼び出された場合、エラー（ERRCODE_INVALID_TRANSACTION_STATE）が発生します。
  • 不可視なタプルを更新しようとした場合、エラー（ERRCODE_OBJECT_NOT_IN_PREREQUISITE_STATE）が発生します。
  • 同時実行によるプルーニング等でアイテムが正規の状態でない場合、処理が中断され TM_Deleted が返されます。
