目的

サブクエリを持つ範囲テーブルエントリ（RTE）に対してプランを生成し、上位クエリからの制約条件のプッシュダウン処理、未使用出力列の削除、およびサブクエリの最終リレーションから得られた各パスに対応する SubqueryScanPath や部分的パスを外部リレーションへ追加する。

入力と出力

  • 引数:
  • PlannerInfo *root: 上位クエリレベルのプランナ情報
  • RelOptInfo *rel: 対象サブクエリの範囲リレーション情報
  • Index rti: 範囲テーブルインデックス
  • RangeTblEntry *rte: 対象のサブクエリに対応する範囲テーブルエントリ
  • 戻り値: なし（void）

前提条件と不変条件

  • 処理の実行中は、現在のクエリレベルで root->plan_params が NIL でなければならない（アサーションによる検証）。
  • 外部リレーションが並列処理を許可しており外部結合リリッドが空である場合、サブファイナルリレーション側の並列考慮フラグが真であるか部分パスリストが空でなければならない。

アルゴリズムまたは振る舞い

1. 初期化とコピー:

  • rte->subquery の複製を作成し、プランニングによって入力RTEの内容が破損するのを防ぐ。
  • rel->lateral_relids から required_outer を取得し、LATERALサブクエリの場合はパラメータ化されたものとして扱う。
  • safetyInfo 構造体をゼロクリアし、サブクエリのターゲットリスト長に応じた安全フラグ用配列を割り当てる。
  • rte->security_barrier が設定されている場合は、safetyInfo.unsafeLeaky を真にして漏洩性関数のプッシュダウンを禁止する。

2. 条件のプッシュダウン評価:

  • サブクエリに制限句が存在し、かつ subquery_is_pushdown_safe が真を返す場合、rel->baserestrictinfo の各制限句について安全性を検証してプッシュダウンを試みる。
  • 擬似定数（pseudoconstant）の条件はそのまま保持する。
  • PUSHDOWN_SAFE の場合は subquery_push_qual によりサブクエリへ条件をプッシュダウンする。
  • PUSHDOWN_WINDOWCLAUSE_RUNCOND の場合は、ウィンドウ関数を参照しかつ適切なWindowAgg実行条件として利用できるかを確認し、不適格な場合は上位クエリに残す。
  • PUSHDOWN_UNSAFE の場合は上位制限リストに維持する。
  • 作業用メモリ領域 safetyInfo.unsafeFlags を解放する。

3. 出力列の最適化とタプルフラクションの決定:

  • remove_unused_subquery_outputs を呼び出し、上位クエリで使用されていないサブクエリの出力列を削除・簡略化する。
  • 上位クエリが集約、グループ化、HAVING、distinct、ソート、または複数ベースリレーションを持つ場合は tuple_fraction を 0.0 とし、そうでない場合は root->tuple_fraction を引き継ぐ。

4. サブクエリのプラン生成:

  • choose_plan_name および subquery_planner を呼び出してサブクエリのサブツリーとパスを生成し、rel->subroot に格納する。
  • サブプランで必要とされるパラメータを rel->subplan_params に退避させ、root->plan_params をリセットする。

5. 制約除外とサイズ見積もり:

  • サブクエリの最終リレーションを取得し、制約除外により空（dummy）であると判定された場合は set_dummy_rel_pathlist を呼び出して処理を終了する。
  • そうでない場合は set_subquery_size_estimates により出力行数や幅の見積もりを設定する。
  • rel->reltarget->exprs がサブクエリのターゲットリストと一致し、順序通りの単純な Var 参照であるかを検出し、trivial_pathtarget フラグを設定する。

6. パスの追加:

  • サブファイナルリレーションの各通常パスについて、パスキーを上位表現に変換し、create_subqueryscan_path で生成したパスを add_path により外部リレーションに追加する。
  • 外部リレーションが並列処理を許可し、かつ required_outer が空である場合、部分パスリスト（partial_pathlist）に対しても同様にパスキー変換と create_subqueryscan_path を行い、add_partial_path で追加する。

失敗モードと境界条件

  • サブクエリの条件プッシュダウンが安全でない場合（subquery_is_pushdown_safe が偽を返す、または個別の条件が PUSHDOWN_UNSAFE と判定された場合）、条件はサブクエリへプッシュダウンされず、外部の SubqueryScan ノードの qpquals として評価される。
  • 制約除外によりサブクエリリレーションが空（dummy）と判定された場合、通常・部分パスの生成は行われず、ダミーリレーション用のパスリスト設定が行われて早期リターンする。

保守担当者向けメモ

  • subquery を処理する前に copyObject で複製を行っているのは、プランニングの過程でRTEの内容が書き換えられてしまうのを防ぐためである。
