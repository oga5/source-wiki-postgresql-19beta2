目的

与えられた条件式や OR 句、および関連するメタデータ（プッシュダウンフラグ、クローンフラグ、セキュリティレベル、リレーション識別子など）をラップし、クエリ最適化で使用する RestrictInfo ノードを構築して初期化する。

シグネチャまたは形状

RestrictInfo * make_plain_restrictinfo(PlannerInfo *root, Expr *clause, Expr *orclause, bool is_pushed_down, bool has_clone, bool is_clone, bool pseudoconstant, Index security_level, Relids required_relids, Relids incompatible_relids, Relids outer_relids)

入力と出力

  • 入力:
  • PlannerInfo *root: プランナーのグローバル情報コンテキスト
  • Expr *clause: ラップ対象の条件式（式ツリー）
  • Expr *orclause: 元となった OR 構造、または NULL
  • bool is_pushed_down: 外部結合等の外側にプッシュダウンされた条件かどうかのフラグ
  • bool has_clone: クローンが存在するかどうかのフラグ
  • bool is_clone: 本ノード自体がクローンであるかどうかのフラグ
  • bool pseudoconstant: 疑似定数（定数式）かどうかのフラグ
  • Index security_level: セキュリティ評価レベル
  • Relids required_relids: 本条件の評価に必須となるリレーションIDの集合、または NULL
  • Relids incompatible_relids: 互換性のないリレーションIDの集合
  • Relids outer_relids: 外側リレーションIDの集合
  • 出力:
  • RestrictInfo *: 初期化された新営の RestrictInfo ノードへのポインタ

前提条件と不変条件

  • security_level > 0 の場合、リークプルーフ性（leakproof）は contain_leaked_vars の結果に基づいて決定され、レベルが 0 の場合は偽（不明）に設定される。
  • 構築直後の RestrictInfo は、コスト、選択率、等価クラス、ハッシュ結合演算子などのキャッシュフィールドが未設定マーカー（-1 または InvalidOid、空リスト）で初期化される。

アルゴリズムまたは振る舞い

1. **ノードの基本設定**: makeNode(RestrictInfo) を用いてノードを割り当て、引数で渡された clause、orclause、is_pushed_down、pseudoconstant、has_clone、is_clone、security_level、incompatible_relids、outer_relids を格納し、can_join を初期値 false にする。 2. **セキュリティ属性と揮発性の初期化**: security_level > 0 の場合はリークプルーフ性を評価し、それ以外では false とし、揮発性（has_volatile）を VOLATILITY_UNKNOWN に設定する。 3. **演算子と関係識別子の解析 (分岐)**:

  • 条件が2引数のバイナリ演算子句（is_opclause かつ引数が2つ）の場合、左辺と右辺の変数（pull_varnos）から left_relids と right_relids を抽出し、その和集合を clause_relids とする。
  • さらに、左右の relids が空ではなく互いに重なりを持たない場合は、標準的な結合条件とみなして can_join を true に設定し、疑似定数でないことをアサートする。
  • バイナリ演算子句でない場合は、left_relids と right_relids を NULL とし、全体句の relids を直接抽出する。

    • 4. **必須リレーションとベース関係数の計算**: required_relids が指定されていなければ clause_relids を割り当てる。また、clause_relids から root->outer_join_rels を除外した差分からベース関係の数を算出し、num_base_rels に格納して一時的なビットマップセットを解放する。 5. **シリアル番号とキャッシュの初期化**: プランナー全体の最後のシリアル番号をインクリメントして rinfo_serial を割り当て、コスト、選択率、ハッシュ演算子、バケットサイズなどの各キャッシュフィールドに未設定値を代入して完了する。

失敗モードと境界条件

  • 引数に不正な式ツリーが渡された場合や、メモリ不足時には makeNode によりエラーや割り当て失敗が発生する可能性がある。

保守担当者向けメモ

  • 生成された RestrictInfo はプランナーのメモリコンテキストに割り当てられ、後続のコスト見積もりや最適化フェーズでキャッシュフィールドが適宜埋められる。
