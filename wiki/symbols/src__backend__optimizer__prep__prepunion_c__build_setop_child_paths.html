目的

集合演算（Set Operation）の子リレーションであるサブクエリに対して、各種のサブクエリジップパス、ソート済みパス、並列部分パスを構築し、推定グループ数を算出する。

シグネチャまたは形状

  • シグネチャ: static void build_setop_child_paths(PlannerInfo *root, RelOptInfo *rel, bool trivial_tlist, List *child_tlist, List *interesting_pathkeys, double *pNumGroups)

入力と出力

  • 引数:
  • PlannerInfo *root: 上位クエリのプランナ情報。
  • RelOptInfo *rel: 処理対象となる集合演算の子リレーション。
  • bool trivial_tlist: ターゲットリストが単純であるかどうかを示すフラグ。
  • List *child_tlist: 子リレーションのターゲットリスト。
  • List *interesting_pathkeys: 考慮すべき興味深いパスキーのリスト。
  • double *pNumGroups: グループ数の推定値を格納するための出力ポインタ（省略可能）。
  • 戻り値: void

前提条件と不変条件

  • 対象のリレーションは RTE_SUBQUERY 種別でなければならない（アサートで検証される）。
  • consider_parallel が偽である場合、子リレーションの最終リレーション (final_rel) には部分パス (partial_pathlist) が存在してはならない。

アルゴリズムまたは振る舞い

1. **前提チェックと等価関係の追加**:

  • リレーションの rtekind が RTE_SUBQUERY であることを確認する。
  • interesting_pathkeys が空でない場合、add_setop_child_rel_equivalences を呼び出して子リレーションの等価関係を追加する。

    • 2. **サイズおよび並列フラグの設定**:

  • set_subquery_size_estimates を呼び出して、対象リレーションの出力行数や幅などの見積もりを行う。
  • fetch_upper_rel を使って UPPERREL_FINAL のリレーションを取得し、その consider_parallel フラグを対象リレーションに伝播する。

    • 3. **パスの走査とパス生成**:

  • final_rel->pathlist に含まれる各サブパス (subpath) を順に走査する。
  • 入力リレーションがダミー (is_dummy_rel) である場合は mark_dummy_rel を呼び出して対象リレーションもダミーにマークする。
  • 最安パス (cheapest_input_path) と一致する場合は、ソートを要求しない安価な実装としてそのまま create_subqueryscan_path を用いて外部パスを作成し、add_path で追加する。
  • interesting_pathkeys が存在する場合、pathkeys_count_contained_in を用いて setop_pathkeys に対するソート状態を判定し、必要に応じて create_sort_path または create_incremental_sort_path を適用してソート済みパスを生成・追加する。

    • 4. **並列部分パスの処理**:

  • 並列実行が有効であり、ラテラル参照が存在せず、かつ final_rel->partial_pathlist が空でない場合、最安の部分サブパスを元に create_subqueryscan_path で部分パスを構築し、add_partial_path で追加する。

    • 5. **後処理とグループ数推定**:

  • postprocess_setop_rel を呼び出してリレーションの後処理を行う。
  • 呼び出し元から pNumGroups が要求されている場合、グループ化や集約の有無に応じて最安パスの行数を採用するか、あるいは estimate_num_groups を使って統計的なグループ数を算出して格納する。

失敗モードと境界条件

  • 子リレーションが RTE_SUBQUERY 以外のレンジテーブル種別である場合、アサート違反によりクラッシュする。
  • 最終リレーションが並列不可であるにもかかわらず部分パスが残存している場合、アサートによって検知される。
