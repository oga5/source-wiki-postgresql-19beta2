~~~c static Selectivity clauselist_selectivity_or(PlannerInfo *root, List *clauses, int varRelid, JoinType jointype, SpecialJoinInfo *sjinfo, bool use_extended_stats) { Selectivity s1 = 0.0; RelOptInfo *rel; Bitmapset *estimatedclauses = NULL; ListCell *lc; int listidx;

/*

  • Determine if these clauses reference a single relation. If so, and if
  • it has extended statistics, try to apply those.

    • */ rel = find_single_rel_for_clauses(root, clauses); if (use_extended_stats && rel && rel->rtekind == RTE_RELATION && rel->statlist != NIL) { /*

  • Estimate as many clauses as possible using extended statistics.

    • *

  • 'estimatedclauses' is populated with the 0-based list position
  • index of clauses estimated here, and that should be ignored below.

    • */ s1 = statext_clauselist_selectivity(root, clauses, varRelid, jointype, sjinfo, rel, &estimatedclauses, true); }

/*

  • Estimate the remaining clauses as if they were independent.

    • *

  • Selectivities for an OR clause are computed as s1+s2 - s1*s2 to account
  • for the probable overlap of selected tuple sets.

    • *

  • XXX is this too conservative?

    • */ listidx = -1; foreach(lc, clauses) { Selectivity s2;

listidx++;

/*

  • Skip this clause if it's already been estimated by some other
  • statistics above.

    • */ if (bms_is_member(listidx, estimatedclauses)) continue;

s2 = clause_selectivity_ext(root, (Node *) lfirst(lc), varRelid, jointype, sjinfo, use_extended_stats);

s1 = s1 + s2 - s1 * s2; }

~~~

目的

ORで結合された複数の条件（句）リスト全体の選択度を計算する。

入力と出力

  • **入力**:
  • PlannerInfo *root: プランナのグローバル情報。
  • List *clauses: ORで結合された条件（句）のリスト。
  • int varRelid: 関連する単一リレーションのID（存在しない場合は0）。
  • JoinType jointype: 結合のタイプ。
  • SpecialJoinInfo *sjinfo: 特殊結合情報。
  • bool use_extended_stats: 拡張統計情報を使用するかどうかを示すフラグ。
  • **出力**:
  • Selectivity: 計算された全体の選択度（0.0から1.0の範囲の浮動小数点数）。

前提条件と不変条件

  • use_extended_stats が有効であり、かつ条件リストが単一のリレーション（RTE_RELATION）のみを参照し、そのリレーションに拡張統計（statlist）が存在する場合にのみ、拡張統計を用いた選択度推定（statext_clauselist_selectivity）が試行される。
  • 拡張統計によって推定された条件は、インデックス（0ベース）が estimatedclauses ビットマップセットに記録され、後半の個別推定ループで重複して計算されないように制御される。

アルゴリズムまたは振る舞い

1. **単一リレーションの特定と拡張統計の適用**:

  • find_single_rel_for_clauses を呼び出して、条件リストが単一のリレーションを参照しているか判定する。
  • 条件を満たす場合、statext_clauselist_selectivity を呼び出して拡張統計による選択度 s1 を計算し、カバーされた条件のインデックスを estimatedclauses に格納する。

    • 2. **残余条件の個別推定と合成**:

  • リスト内の各条件を走査する。
  • 現在の条件のインデックスが estimatedclauses に含まれている場合は、既に拡張統計で評価済みであるためスキップする。
  • 含まれていない場合、clause_selectivity_ext を呼び出して個別選択度 s2 を計算する。
  • 選択されたタプル集合の重複を考慮し、OR結合の公式 s1 = s1 + s2 - s1 * s2 を用いて累積選択度 s1 を更新する。

    • 3. **結果の返却**:

  • 最終的に合成された選択度 s1 を返す。

失敗モードと境界条件

  • **空の条件リスト (clauses == NIL)**:
  • clauses が NIL の場合、find_single_rel_for_clauses は NULL を返し、拡張統計の適用はスキップされる。
  • 後半の foreach ループも実行されないため、初期値である s1 = 0.0 がそのまま返される。
  • **すべての条件が拡張統計でカバーされた場合**:
  • estimatedclauses にすべての条件インデックスが登録されるため、後半のループではすべての条件が bms_is_member によりスキップされ、拡張統計から得られた s1 がそのまま返される。
  • **独立性の仮定による過小・過大評価**:
  • 拡張統計でカバーされない条件同士は互いに独立であると仮定して s1 + s2 - s1 * s2 で合成される。
  • 条件間に強い相関（例: 同一列に対する異なる値のOR条件など、排他的な関係）がある場合、この独立性仮定に基づく重複排除（s1 * s2）は、実際の選択度に対して不正確な（過度に保守的な）見積もりを与える可能性がある。
  • **極端な選択度（0.0 または 1.0）の伝播**:
  • いずれかの条件の選択度 s2 が 1.0 に達した場合、公式 s1 + 1.0 - s1 * 1.0 により、全体の選択度 s1 は以降の条件に関わらず 1.0 に固定される。
  • 逆に、ある条件の選択度 s2 が 0.0 の場合、s1 + 0.0 - s1 * 0.0 となり、全体の選択度 s1 には影響を与えない。
