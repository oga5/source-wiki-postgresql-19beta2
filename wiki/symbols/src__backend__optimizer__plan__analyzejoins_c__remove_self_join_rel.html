Assert(toKeep->relid > 0); Assert(toRemove->relid > 0);

  • technique of removing/distributing restrictinfo is used here to attach
  • just appeared (for keeping relation) join clauses and avoid adding
  • duplicates of those that already exist in the joininfo list.

    • */ joininfos = list_copy(toRemove->joininfo); foreach_node(RestrictInfo, rinfo, joininfos) { remove_join_clause_from_rels(root, rinfo, rinfo->required_relids); ChangeVarNodesExtended((Node *) rinfo, toRemove->relid, toKeep->relid, 0, replace_relid_callback);

if (bms_membership(rinfo->required_relids) == BMS_MULTIPLE) jinfo_candidates = lappend(jinfo_candidates, rinfo); else binfo_candidates = lappend(binfo_candidates, rinfo); }

  • removing table just to simplify the replacement procedure: all of them
  • weren't connected to any keeping relations and need to be added to some
  • rels.

目的

自己結合排除（Self-Join Elimination: SJE）において、削除対象のベースリレーション (toRemove) に関連付けられている結合情報、ベース制限条件、等価クラス、ターゲットリスト、行マークなどの全条件や属性を保持側のリレーション (toKeep) へ統合・移行し、クエリ構造体やプランナー情報から toRemove を完全に排除する。

シグネチャまたは形状

static void remove_self_join_rel(PlannerInfo *root, PlanRowMark *kmark, PlanRowMark *rmark, RelOptInfo *toKeep, RelOptInfo *toRemove, List *restrictlist)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーのグローバル情報構造体。
  • PlanRowMark *kmark: 保持側リレーションの行マーク情報（存在する場合）。
  • PlanRowMark *rmark: 削除側リレーションの行マーク情報（存在する場合）。
  • RelOptInfo *toKeep: 保持する側のリレーション情報。
  • RelOptInfo *toRemove: 削除する側のリレーション情報。
  • List *restrictlist: 保持側に接続されておらず追加が必要な自己結合条件などのリスト。
  • 戻り値: なし (void)

前提条件と不変条件

  • 保持側と削除側のリレーションID (relid) はともに 0 より大きいこと。
  • 削除対象のリレーションは root->all_result_relids および root->leaf_result_relids のメンバーではないこと。

アルゴリズムまたは振る舞い

1. 結合情報の移管: 削除側リレーションの結合情報 (toRemove->joininfo) をコピーし、各制限情報の結合元リレーションから旧リレルを除去した上で、変数の変数番号（varno）を削除側から保持側へ置換する。その後、必要な結合情報リストとベース制限情報リストに分類する。 2. ベース制限条件の結合と置換: 引数で渡された restrictlist を削除側の基礎制限情報 (toRemove->baserestrictinfo) に結合し、同様に変数の変数番号を保持側に置換した上で、複数リレルか単一リレルかに応じて候補リストに振り分ける。 3. 非冗長条件の追加: 分類された候補リストから重複や冗長な条件を除外して、保持側の基本制限情報および結合情報に追加する。その後、一時的な候補リストを解放する。 4. 等価クラスの更新: 削除側が関与するすべての等価クラスに対し、メンバーおよびソースリスト内の削除側変数番号を保持側へ置換し、保持側の等価クラスインデックスに登録する。 5. ターゲットリストと属性必要性フラグの移管: 削除側のターゲットリスト式内の変数番号を保持側に置換し、保持側に存在しない場合は追加する。また、各属性の必要性ビットマップ (attr_needed) を調整・統合する。 6. 行マークの処理: 削除側にのみ行マークがある場合は保持側のリレルIDに付け替え、両方にある場合はマークの種類が一致することを確認した上で削除側の行マークをクエリの行マークリストから削除する。 7. クエリおよびプランナー構造全体の変数置換とクリーンアップ: RangeTblRef を除き、パースツリー、処理済みターゲットリストなどの全構造体で変数番号を置換し、クエリから削除側リレルに関する情報を除去する。最後に、単純リレーション配列およびRTE配列から削除側への参照を消去し、toRemove の RelOptInfo を解放する。 8. 依存関係の再構築: プレースホルダー、結合条件、等価クラス、およびラテラル参照における属性必要性ビットマップを再構築する。

失敗モードと境界条件

  • 保持側 (kmark) と削除側 (rmark) の両方に行マークが存在する場合、両者のマークの種類 (markType) が一致しない場合にアサーション違反で失敗する。
  • 削除側リレーションが結果リレーション (all_result_relids または leaf_result_relids) のメンバーである場合にアサーション違反となる。

保守担当者向けメモ

  • RangeTblRef ノードの varno 置換をこの関数内で実行すると後続の remove_rel_from_joinlist 等でエラーが発生するため、クエリ構造体の置換時には RangeTblRef が除外されるように設計されている。
