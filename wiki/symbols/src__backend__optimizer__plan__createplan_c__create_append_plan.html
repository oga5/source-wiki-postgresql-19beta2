目的

AppendPath に基づいて実行エンジン用の Append プランノードを構築し、必要に応じて子プランに対するソート、非同期実行マーキング、パーティションプルーニング情報の付与を行う。

入力と出力

  • 引数:
  • PlannerInfo *root: プランニング全体のコンテキスト情報。
  • AppendPath *best_path: 変換元の Append パス。
  • int flags: tlist の要件を指定するフラグ群。
  • 戻り値:
  • Plan *: 構築された Append プラン、またはダミーの Result プラン、あるいは射影用の Result プラン。

前提条件と不変条件

  • 子プランが存在しない場合、制約除外等により空であることが証明されているため、定数 FALSE のゲート条件を持つダミーの Result プランを返す。
  • 子プランのリストが存在する場合、すべての子プランは同一のターゲットリスト（tlist）を返す必要がある。
  • 順序付き Append の場合、各子プランのソート情報（ソート順序・列番号・演算子・照合順序・NULL配置）が Append 側の設定と完全に一致していなければならない。

アルゴリズムまたは振る舞い

1. **ダミープランの判定**: best_path->subpaths が空である場合、make_one_row_result を用いて定数 FALSE の修飾式を持つ Result プランを生成し、汎用パス情報をコピーして返す。 2. **Append ノードの初期化**:

  • build_path_tlist を使ってターゲットリストを構築する。
  • makeNode(Append) により Append プランを確保し、relids や child_append_relid_sets などの情報を設定する。

    • 3. **パスキーに基づくソート情報の準備**:

  • pathkeys が存在する場合、prepare_sort_from_pathkeys を実行してソートキー列情報を計算し、Append の tlist を調整する。

    • 4. **子プランのループ処理**:

  • best_path->subpaths の各子パスに対して create_plan_recurse を CP_EXACT_TLIST フラグ付きで再帰呼び出しし、子プランを生成する。
  • 順序付き Append の場合、各子プランに対して再度 prepare_sort_from_pathkeys を適用してソート情報の整合性を検証する。不一致が検知された場合はエラーログが出力される。
  • 子プランが十分な順序を満たしていない場合、プリソートキーの有無と enable_incremental_sort の有効性に応じて make_incrementalsort または make_sort を挿入し、コスト情報をラベル付けする。
  • 非同期 Append の条件を満たし mark_async_capable_plan が真を返す場合、非同期対応プランとしてマークし、カウンタをインクリメントする。

    • 5. **パーティションプルーニング情報の付与**:

  • enable_partition_pruning が有効な場合、ベースリレーションの制限条件やパラメータ化された条件を抽出し、make_partition_pruneinfo を呼び出して実行時プルーニング用のインデックスを設定する。

    • 6. **tlist の調整と完了**:

  • 汎用パス情報をコピーした後、ソートキーの追加によって tlist が変更され、かつ CP_EXACT_TLIST または CP_SMALL_TLIST フラグが要求されている場合は、inject_projection_plan を用いて元の tlist 長さに切り詰めた射影プランを挿入して返す。

失敗モードと境界条件

  • best_path->subpaths が空のケースでは、空のサブパスを持つリレーションに対応する定数 FALSE のダミープランが安全に生成される。
  • 順序付き Append において、子プランのターゲットリスト構造やソート演算子等のメタデータが Append 全体の設定と一致しない場合、elog(ERROR, ...) によりプラン生成が中断される。
