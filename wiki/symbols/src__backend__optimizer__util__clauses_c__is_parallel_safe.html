~~~c bool is_parallel_safe(PlannerInfo *root, Node *node) { max_parallel_hazard_context context; PlannerInfo *proot; ListCell *l;

/*

  • Even if the original querytree contained nothing unsafe, we need to
  • search the expression if we have generated any PARAM_EXEC Params while
  • planning, because those are parallel-restricted and there might be one
  • in this expression. But otherwise we don't need to look.

    • */ if (root->glob->maxParallelHazard == PROPARALLEL_SAFE && root->glob->paramExecTypes == NIL) return true; /* Else use max_parallel_hazard's search logic, but stop on RESTRICTED */ context.max_hazard = PROPARALLEL_SAFE; context.max_interesting = PROPARALLEL_RESTRICTED; context.safe_param_ids = NIL;

/*

  • The params that refer to the same or parent query level are considered
  • parallel-safe. The idea is that we compute such params at Gather or
  • Gather Merge node and pass their value to workers.

    • */ for (proot = root; proot != NULL; proot = proot->parent_root) { foreach(l, proot->init_plans) { SubPlan *initsubplan = (SubPlan *) lfirst(l);

context.safe_param_ids = list_concat(context.safe_param_ids, initsubplan->setParam); } }

return !max_parallel_hazard_walker(node, &context); } ~~~

目的

指定された式ノードが並列実行に対して安全（Parallel Safe）であるかどうかを判定する。

シグネチャまたは形状

  • シグネチャ: bool is_parallel_safe(PlannerInfo *root, Node *node)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報およびクエリ階層情報を保持する構造体ポインタ
  • Node *node: 並列安全性を検証する対象の式または構文ツリーノード
  • 戻り値:
  • bool: 式が並列安全である場合は true、そうでない場合は false

前提条件と不変条件

  • クエリ全体の最大並列危険度が PROPARALLEL_SAFE であり、かつ生成された PARAM_EXEC パラメータ型リスト (paramExecTypes) が NIL である場合、式ツリーを探索せずに直ちに true を返す。
  • 同じクエリレベルまたは親クエリレベルを参照するパラメータは並列安全とみなされ、Gather または Gather Merge ノードで計算されてワーカーに値が渡される。

アルゴリズムまたは振る舞い

1. クエリ全体の最大並列危険度(root->glob->maxParallelHazard)が PROPARALLEL_SAFE であり、かつ root->glob->paramExecTypes が NIL の場合は、そのまま true を返す。 2. 上記の条件に該当しない場合、最大並列危険度の検索コンテキスト（max_parallel_hazard_context）を初期化する。ここで max_hazard を PROPARALLEL_SAFE に、max_interesting を PROPARALLEL_RESTRICTED に設定し、safe_param_ids を NIL にする。 3. 現在のプランナ情報から親プランナ階層（parent_root）へ順に辿り、各階層の init_plans に含まれる SubPlan の setParam を safe_param_ids に結合する。 4. max_parallel_hazard_walker を対象ノードとコンテキストに対して実行し、その返り値（危険性が検出されたかどうか）の否定を返す。

呼び出し元と呼び出し先

  • 呼び出し先: max_parallel_hazard_walker

関連データ構造

  • PlannerInfo
  • max_parallel_hazard_context
  • SubPlan

失敗モードと境界条件

  • クエリプランニングの過程で PARAM_EXEC パラメータが生成されている場合、元のクエリツリーに危険な要素が含まれていないように見えても、式内部に並列制限付き（parallel-restricted）のパラメータが存在する可能性があるため、最適化済みパスであっても検索が省略されずに実行される。
