ソース抜粋

~~~c static Oid select_equality_operator(EquivalenceClass *ec, Oid lefttype, Oid righttype) { ListCell *lc;

foreach(lc, ec->ec_opfamilies) { Oid opfamily = lfirst_oid(lc); Oid opno;

opno = get_opfamily_member_for_cmptype(opfamily, lefttype, righttype, COMPARE_EQ); if (!OidIsValid(opno)) continue; /* If no barrier quals in query, don't worry about leaky operators */ if (ec->ec_max_security == 0) return opno; /* Otherwise, insist that selected operators be leakproof */ if (get_func_leakproof(get_opcode(opno))) return opno; } return InvalidOid; } ~~~

目的

指定された等価クラス（EquivalenceClass）が持つ演算子ファミリ群を走査し、与えられた左右のデータ型に一致する等価演算子の Oid を選択して返す。

入力と出力

  • 入力:
  • EquivalenceClass *ec: 対象の等価クラス
  • Oid lefttype: 左辺のデータ型 Oid
  • Oid righttype: 右辺のデータ型 Oid
  • 出力:
  • Oid: 条件に合致し、必要に応じたセキュリティ検証を満たした等価演算子の Oid。該当するものがない場合は InvalidOid を返す。

前提条件と不変条件

  • クエリ内にバリア条件（セキュリティバリア）が存在しない場合（ec->ec_max_security == 0）、演算子のリークプルーフ性（leakproof）の検証はスキップされる。
  • バリア条件が存在する場合、選択される演算子に対応する関数がリークプルーフである必要がある。

アルゴリズムまたは振る舞い

  • 等価クラスの ec_opfamilies リストを順番に走査し、各演算子ファミリから get_opfamily_member_for_cmptype を用いて指定の左右型と COMPARE_EQ に一致する演算子 Oid を取得する。
  • 取得した演算子 Oid が無効である場合は次のファミリへスキップする。
  • 演算子 Oid が有効な場合で、ec->ec_max_security == 0 のときは直ちにその演算子 Oid を返す。
  • ec->ec_max_security が 0 より大きい場合は、演算子の背後にある関数が get_func_leakproof(get_opcode(opno)) によってリークプルーフであると判定された場合にのみその演算子 Oid を返し、満たさない場合は走査を継続する。
  • ループ内で条件を満たす演算子が見つからないままリストの終端に達した場合、InvalidOid を返す。

失敗モードと境界条件

  • どの演算子ファミリからも一致する等価演算子が見つからない場合、あるいはセキュリティ要件（リークプルーフ性）を満たす演算子が存在しない場合は、最終的に InvalidOid が返される。
