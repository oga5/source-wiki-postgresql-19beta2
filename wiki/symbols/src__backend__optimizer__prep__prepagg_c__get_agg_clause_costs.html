~~~c void get_agg_clause_costs(PlannerInfo *root, AggSplit aggsplit, AggClauseCosts *costs) { ListCell *lc;

foreach(lc, root->aggtransinfos) { AggTransInfo *transinfo = lfirst_node(AggTransInfo, lc);

/*

  • Add the appropriate component function execution costs to
  • appropriate totals.

    • */ if (DO_AGGSPLIT_COMBINE(aggsplit)) { /* charge for combining previously aggregated states */ add_function_cost(root, transinfo->combinefn_oid, NULL, &costs->transCost); } else add_function_cost(root, transinfo->transfn_oid, NULL, &costs->transCost); if (DO_AGGSPLIT_DESERIALIZE(aggsplit) && OidIsValid(transinfo->deserialfn_oid)) add_function_cost(root, transinfo->deserialfn_oid, NULL, &costs->transCost); if (DO_AGGSPLIT_SERIALIZE(aggsplit) && OidIsValid(transinfo->serialfn_oid)) add_function_cost(root, transinfo->serialfn_oid, NULL, &costs->finalCost);

/*

  • These costs are incurred only by the initial aggregate node, so we
  • mustn't include them again at upper levels.

    • */ if (!DO_AGGSPLIT_COMBINE(aggsplit)) { /* add the input expressions' cost to per-input-row costs */ QualCost argcosts;

cost_qual_eval_node(&argcosts, (Node *) transinfo->args, root); costs->transCost.startup += argcosts.startup; costs->transCost.per_tuple += argcosts.per_tuple;

/*

  • Add any filter's cost to per-input-row costs.

    • *

  • XXX Ideally we should reduce input expression costs according
  • to filter selectivity, but it's not clear it's worth the
  • trouble.

    • */ if (transinfo->aggfilter) { cost_qual_eval_node(&argcosts, (Node *) transinfo->aggfilter, root); costs->transCost.startup += argcosts.startup; costs->transCost.per_tuple += argcosts.per_tuple; } }

~~~

目的

クエリの集約情報（aggtransinfos および agginfos）を走査し、遷移関数、結合関数、シリアライズ関数、デシリアライズ関数、最終関数、引数式、およびフィルタの実行コストを累積して集約コスト構造体（AggClauseCosts）に計算結果を設定する。さらに、ハッシュ集約などで必要となる遷移状態のメモリスペース見積もりを算出する。

シグネチャまたは形状

  • シグネチャ: void get_agg_clause_costs(PlannerInfo *root, AggSplit aggsplit, AggClauseCosts *costs)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報および集約情報（aggtransinfos, agginfos）を保持する構造体ポインタ
  • AggSplit aggsplit: 集約の分割状態（シリアライズ、デシリアライズ、結合、最終処理スキップなどの判定に使用）
  • AggClauseCosts *costs: 計算されたコストおよびメモリ見積もり結果を格納する出力先構造体ポインタ
  • 戻り値: なし（void）

前提条件と不変条件

  • root->aggtransinfos および root->agginfos に格納されている各要素が有効な AggTransInfo および AggInfo ノードを指していること。

アルゴリズムまたは振る舞い

1. 遷移情報の走査とトランジションコストの累積:

  • root->aggtransinfos リストを走査し、各 AggTransInfo について aggsplit の分割状態に応じた関数コストを costs->transCost または costs->finalCost に加算する。
  • DO_AGGSPLIT_COMBINE(aggsplit) が真の場合は combinefn_oid を costs->transCost に追加し、偽の場合は transfn_oid を追加する。
  • デシリアライズが有効かつ deserialfn_oid が有効な場合は costs->transCost に追加する。
  • シリアライズが有効かつ serialfn_oid が有効な場合は costs->finalCost に追加する。
  • 結合分割を行わない場合（!DO_AGGSPLIT_COMBINE(aggsplit)）、入力式（transinfo->args）および存在する場合はフィルタ（transinfo->aggfilter）の評価コストを計算し、costs->transCost の startup および per_tuple に加算する。

2. 遷移状態のメモリスペース見積もり:

  • 遷移型の値渡し特性（transtypeByVal）を確認する。
  • 非値渡し（pass-by-reference）の場合、aggtransspace が指定されていればそれを使い、特定関数（F_ARRAY_APPEND）やシステムカタログの平均幅（get_typavgwidth）から幅を求めてアライメント調整を行い、ポインタオーバーヘッド分を含めて costs->transitionSpace に加算する。
  • 値渡しであっても INTERNALOID の場合は特殊ケースとして扱い、指定された aggtransspace またはデフォルト値（ALLOCSET_DEFAULT_INITSIZE）を costs->transitionSpace に加算する。

3. 集約情報の走査と最終関数のコスト累積:

  • root->agginfos リストを走査し、各 AggInfo の最初の Aggref を取得する。
  • 最終処理をスキップせず、finalfn_oid が有効な場合はそのコストを costs->finalCost に追加する。
  • aggref->aggdirectargs が存在する場合、その評価コストを計算して costs->finalCost に加算する。
