目的

AppendPath ノードを新しく割り当てて初期化する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体の情報
  • RelOptInfo *rel: 対象のリレーション情報
  • AppendPathInput input: 通常サブパスおよび部分サブパス、子 append リレーション ID セットを保持する入力構造体
  • List *pathkeys: パスのソート順序を表すパスキーのリスト
  • Relids required_outer: 外部リレーションのパラメータ依存関係 ID セット
  • int parallel_workers: 並列ワーカー数
  • bool parallel_aware: 並列認識フラグ
  • double rows: 行数の見積もり値（0 未満の場合は自動計算値を使用）
  • 戻り値:
  • AppendPath *: 初期化された AppendPath ノードへのポインタ

前提条件と不変条件

  • parallel_aware が真である場合、parallel_workers は 0 より大きくなければならない。
  • pathnode の子パス群のパラメータ化要件は、すべて required_outer と一致していなければならない。
  • 並列認識（parallel_aware）が有効な Append パスは、並列安全（parallel_safe）でなければならない。
  • Append がパスキーを持つ場合、並列認識のサブパス順序を並べ替えてはならないため、pathkeys == NIL でなければならない。

アルゴリズムまたは振る舞い

1. makeNode(AppendPath) を用いて新しい AppendPath ノードを割り当てる。 2. input.child_append_relid_sets をノードへ設定し、パスタイプを T_Append に、親リレーションおよびターゲットを rel から設定する。 3. リレーションが塩基リレーション（RELOPT_BASEREL）かつ root が存在し、かつ input.subpaths が空でない場合は get_baserel_parampathinfo を呼び出してパラメータパス情報を構築し、そうでない場合は get_appendrel_parampathinfo にフォールバックする。 4. 並列認識フラグ、並列安全フラグ（rel->consider_parallel）、並列ワーカー数、パスキーをパス基本構造体に設定する。 5. parallel_aware が真の場合、pathkeys == NIL であることを検証した上で、通常サブパスを append_total_cost_compare で、部分サブパスを append_startup_cost_compare でそれぞれ降順にソートする。 6. first_partial_path に通常サブパスの長さを設定し、subpaths に通常サブパスと部分サブパスを結合したリストを格納する。 7. クエリ全体のリレーションと rel->relids が一致し、かつ root が存在する場合は root->limit_tuples を limit_tuples に設定し、それ以外の場合は -1.0 を設定する。 8. subpaths の各要素を走査し、すべてのサブパスの並列安全性を反映させて pathnode->path.parallel_safe を更新し、各子パスの必要外部パラメータが required_outer と一致することをアサートで検証する。 9. 子パスの数がちょうど 1 つであり、かつ子パスの並列認識状態が Append のそれと一致する場合、Append は何もしないノード（no-op）として扱われ、子パスの行数・コスト・パスキーを継承する。それ以外の場合は cost_append を呼び出してコスト計算を行う。 10. 呼び出し元が有効な行数見積もり（rows >= 0）を提供している場合は、計算された行数をその値で上書きする。 11. 完成した AppendPath ポインタを返す。

失敗モードと境界条件

  • parallel_aware が真かつ parallel_workers が 0 以下の場合、アサート違反により異常終了する。
  • パスキーが存在する状態で parallel_aware が真の場合、アサート違反により異常終了する。
  • 子パスのパラメータ化要件が required_outer と一致しない場合、アサート違反により異常終了する。
  • parallel_aware が真であるにもかかわらずパス全体の並列安全性が得られなかった場合、アサート違反により異常終了する。
