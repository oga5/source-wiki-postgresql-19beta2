~~~c static Plan * create_scan_plan(PlannerInfo *root, Path *best_path, int flags) { RelOptInfo *rel = best_path->parent; List *scan_clauses; List *gating_clauses; List *tlist; Plan *plan;

/*

  • Extract the relevant restriction clauses from the parent relation. The
  • executor must apply all these restrictions during the scan, except for
  • pseudoconstants which we'll take care of below.

    • *

  • If this is a plain indexscan or index-only scan, we need not consider
  • restriction clauses that are implied by the index's predicate, so use
  • indrestrictinfo not baserestrictinfo. Note that we can't do that for
  • bitmap indexscans, since there's not necessarily a single index
  • involved; but it doesn't matter since create_bitmap_scan_plan() will be
  • able to get rid of such clauses anyway via predicate proof.

    • */ switch (best_path->pathtype) { case T_IndexScan: case T_IndexOnlyScan: scan_clauses = castNode(IndexPath, best_path)->indexinfo->indrestrictinfo; break; default: scan_clauses = rel->baserestrictinfo; break; }

/*

  • If this is a parameterized scan, we also need to enforce all the join
  • clauses available from the outer relation(s).

    • *

  • For paranoia's sake, don't modify the stored baserestrictinfo list.

    • */ if (best_path->param_info) scan_clauses = list_concat_copy(scan_clauses, best_path->param_info->ppi_clauses);

/*

  • Detect whether we have any pseudoconstant quals to deal with. Then, if
  • we'll need a gating Result node, it will be able to project, so there
  • are no requirements on the child's tlist.

    • *

  • If this replaces a join, it must be a foreign scan or a custom scan,
  • and the FDW or the custom scan provider would have stored in the best
  • path the list of RestrictInfo nodes to apply to the join; check against
  • that list in that case.

    • */ if (IS_JOIN_REL(rel)) { List *join_clauses;

Assert(best_path->pathtype == T_ForeignScan || best_path->pathtype == T_CustomScan); if (best_path->pathtype == T_ForeignScan) join_clauses = ((ForeignPath *) best_path)->fdw_restrictinfo; ~~~

目的

create_scan_plan は、ベースリレーション（あるいは結合リレーションを置換するスキャン）に対するアクセスパス（Path）を入力として受け取り、対応する物理スキャン系の実行プラン（Plan）ノードを生成する関数です。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体のグローバル情報やコンテキストを格納する構造体ポインタ。
  • Path *best_path: 最適なアクセスパスを表す構造体ポインタ。
  • int flags: ターゲットリスト構築などを制御するためのフラグ群。
  • 戻り値:
  • Plan *: 生成されたスキャン計画（必要に応じてゲーティング用の Result ノードを含む）のポインタ。

前提条件と不変条件

  • 結合リレーション（IS_JOIN_REL(rel) が真）を置換するパスの場合、best_path のパスタイプは T_ForeignScan または T_CustomScan でなければなりません。

アルゴリズムまたは振る舞い

1. **スキャン条件（scan_clauses）の抽出**:

  • パスタイプが T_IndexScan または T_IndexOnlyScan の場合は、インデックスの述語に包含される条件を除外した indrestrictinfo を使用します。
  • その他のパスの場合は、親リレーションの基本制限条件 baserestrictinfo を使用します。
  • パラメータ化されたスキャンである場合は、外部リレーションから利用可能な結合条件（ppi_clauses）をコピーして scan_clauses に結合します。

2. **ゲーティング条件（gating_clauses）の検出**:

  • 結合リレーションの場合は、FDW制限情報またはカスタム制限情報に対して get_gating_quals を呼び出して擬似定数条件を検出します。
  • 単一リレーションの場合は、scan_clauses に対して get_gating_quals を呼び出します。
  • ゲーティング条件が存在する場合、子プランのターゲットリスト要件を緩和するため flags を 0 にリセットします。

3. **ターゲットリスト（tlist）の構築**:

  • flags が CP_IGNORE_TLIST のみである場合は、tlist を生成せず NULL とします。
  • 物理 tlist の利用が可能な場合、インデックスオンリースキャンではインデックスの tlist をコピーし、必要に応じてソートグループ参照のラベル付けを行います。
  • それ以外のテーブルスキャンでは build_physical_tlist を試行し、ドロップされた列などが原因で失敗した場合は通常の build_path_tlist にフォールバックします。
  • 物理 tlist が適用できない場合は、通常の方法で build_path_tlist を使って tlist を構築します。

4. **プランノードのディスパッチ生成**:

  • best_path->pathtype の値に応じて、以下の個別プラン生成関数を呼び出して物理プランを構築します:
  • T_SeqScan: create_seqscan_plan
  • T_SampleScan: create_samplescan_plan
  • T_IndexScan, T_IndexOnlyScan: create_indexscan_plan
  • T_BitmapHeapScan: create_bitmap_scan_plan
  • T_TidScan: create_tidscan_plan
  • T_TidRangeScan: create_tidrangescan_plan
  • T_SubqueryScan: create_subqueryscan_plan
  • T_FunctionScan: create_functionscan_plan
  • T_TableFuncScan: create_tablefuncscan_plan
  • T_ValuesScan: create_valuesscan_plan
  • T_CteScan: create_ctescan_plan
  • T_NamedTuplestoreScan: create_namedtuplestorescan_plan
  • T_Result: create_resultscan_plan
  • T_WorkTableScan: create_worktablescan_plan
  • T_ForeignScan: create_foreignscan_plan
  • T_CustomScan: create_customscan_plan

5. **ゲーティングプランのラップ**:

  • gating_clauses が存在する場合、生成されたプランに対して create_gating_plan を呼び出し、擬似定数を一度だけ評価する Result ノードを上部に挿入します。
