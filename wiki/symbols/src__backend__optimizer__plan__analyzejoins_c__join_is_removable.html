目的

左結合（Left Join）が削除可能かどうかを判定し、右辺のリレーションが一意（distinct）であることを証明できるかを検証します。

シグネチャまたは形状

  • シグネチャ: static bool join_is_removable(PlannerInfo *root, SpecialJoinInfo *sjinfo)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーのグローバル情報ツリー。
  • SpecialJoinInfo *sjinfo: 対象となる結合情報の構造体。
  • 戻り値:
  • bool: 結合が削除可能な場合は true、そうでない場合は false。

前提条件と不変条件

  • 対象の結合種別は JOIN_LEFT であり、かつ右辺が単一のベースリレーション（min_righthand が単一のメンバー）で構成されている必要があります。
  • クエリの実行結果リレーション（resultRelation）である左結合は排除の対象外となります。

アルゴリズムまたは振る舞い

1. **基本チェック**: 結合種別が JOIN_LEFT でない場合、または右辺が単一のベースリレーションでない場合、あるいは対象がクエリの結果リレーションである場合は false を返します。 2. **一意性サポートチェック**: 内部リレーション（innerrel）が明確な一意性をサポートしているかを rel_supports_distinctness で事前検証し、不可の場合は false を返します。 3. **属性の必要性チェック**: 内部リレーションの属性が結合の上流（押し下げられた条件を含む）で使用されていないかを max_attr から min_attr に向かって逆順で検証します。 4. **プレースホルダー変数（PHV）の検証**: root->placeholder_list を走査し、各 PlaceHolderInfo が内部リレーションをラテラル参照していないか、結合上流で必要とされないか、あるいは評価位置や包含式が条件に違反しないかをチェックします。 5. **結合条件（RestrictInfo）の収集**: 内部リレーションの joininfo リストを走査し、クローンではなく、かつ結合側にプッシュダウンされていない、マージ結合可能な条件句のうち、外部リレーションまたは擬似定数と一致するものを clause_list に収集します。 6. **一意性の証明**: 収集した clause_list をもとに rel_is_distinct_for を呼び出し、内部リレーションが一意であると証明できた場合に true を返します。

失敗モードと境界条件

  • sjinfo->jointype != JOIN_LEFT の場合、即座に false を返します。
  • sjinfo->min_righthand が単一のリレーションを表さない場合、bms_get_singleton_member が失敗し false を返します。
  • innerrelid が root->parse->resultRelation と一致する場合、MERGE等のクエリ構造上の制約により排除されず false を返します。
