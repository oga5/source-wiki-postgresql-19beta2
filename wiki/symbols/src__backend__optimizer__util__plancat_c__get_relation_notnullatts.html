目的

指定されたリレーションに定義されている有効な NOT NULL 制約の列番号を収集し、プランナのグローバル情報にあるハッシュテーブルにキャッシュとして格納する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランニング全体の情報とハッシュテーブルを保持する構造体ポインタ
  • Relation relation: 検査対象のリレーションを表す Relation 構造体ポインタ
  • 戻り値: なし (void)

前提条件と不変条件

  • リレーションのタプルディスクリプタに NOT NULL 制約が存在しない場合、処理は何も行わずに早期リターンする。
  • 該当リレーションのOIDに対応するハッシュエントリがすでに存在する場合も、処理は早期リターンする。
  • 各属性のヌル可能性状態 (attr->attnullability) は、不明 (ATTNULLABLE_UNKNOWN) であってはならないというアサーションを満たす必要がある。
  • 有効な NOT NULL 属性として追加される列は、ドロップされた列ではない（attr->attisdropped が偽である）。

アルゴリズムまたは振る舞い

1. **早期リターンチェック**: リレーションの rd_att->constr が NULL であるか、または has_not_null が偽である場合、処理を終了する。 2. **ハッシュテーブルの初期化**: root->glob->rel_notnullatts_hash が NULL の場合、Oidをキー、NotnullHashEntry をエントリサイズとするハッシュテーブルを hash_create で新規作成し、root->glob->rel_notnullatts_hash に設定する。 3. **エントリの検索と登録**: リレーションのOIDを使用してハッシュテーブルを hash_search (HASH_ENTER) で検索し、すでにエントリが存在している場合は早期リターンする。 4. **NOT NULL 列の収集**: リレーションの全属性をループで走査し、各属性のヌル可能性状態を確認する。

  • 状態が ATTNULLABLE_VALID である場合、bms_add_member を用いて対応する 1-オリジンの列番号をビットマップ notnullattnums に追加する。

    • 5. **ハッシュエントリの初期化**: 収集したビットマップ notnullattnums を新規作成されたハッシュエントリ (hentry->notnullattnums) に格納する。

失敗モードと境界条件

  • リレーションに制約情報が存在しない場合や has_not_null が有効でない場合は、ハッシュテーブルの作成を行わずに直ちにリターンする。
  • 指定されたリレーションのOIDに対するハッシュエントリが既にキャッシュ内に存在している場合、重複して走査・登録を行わず直ちにリターンする。
