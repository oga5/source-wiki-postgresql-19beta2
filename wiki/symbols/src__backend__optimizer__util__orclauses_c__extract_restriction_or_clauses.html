~~~c void extract_restriction_or_clauses(PlannerInfo *root) { Index rti;

/* Examine each baserel for potential join OR clauses */ for (rti = 1; rti < root->simple_rel_array_size; rti++) { RelOptInfo *rel = root->simple_rel_array[rti]; ListCell *lc;

/* there may be empty slots corresponding to non-baserel RTEs */ if (rel == NULL) continue;

Assert(rel->relid == rti); /* sanity check on array */

/* ignore RTEs that are "other rels" */ if (rel->reloptkind != RELOPT_BASEREL) continue;

/*

  • Find potentially interesting OR joinclauses. We can use any
  • joinclause that is considered safe to move to this rel by the
  • parameterized-path machinery, even though what we are going to do
  • with it is not exactly a parameterized path.

    • */ foreach(lc, rel->joininfo) { RestrictInfo *rinfo = (RestrictInfo *) lfirst(lc);

if (restriction_is_or_clause(rinfo) && join_clause_is_movable_to(rinfo, rel)) { /* Try to extract a qual for this rel only */ Expr *orclause = extract_or_clause(rinfo, rel);

/*

  • If successful, decide whether we want to use the clause,
  • and insert it into the rel's restrictinfo list if so.

    • */ if (orclause) consider_new_or_clause(root, rel, orclause, rinfo); } } } } ~~~

目的

クエリ内の各ベースリレーションを走査し、適用可能な結合OR条件から単一のリレーションのみを参照する制限OR条件を抽出して適用する。

入力と出力

  • 入力: PlannerInfo *root（プランナの全体情報へのポインタ）
  • 戻り値: なし (void)

前提条件と不変条件

  • root->simple_rel_array 内のリレーション配列要素に対して、非NULLであること、および rel->relid == rti の整合性が維持されていること。
  • 処理対象の rel->reloptkind は RELOPT_BASEREL であること。

アルゴリズムまたは振る舞い

1. **リレーション配列の走査**: root->simple_rel_array_size に基づきインデックス rti を 1 から順にインクリメントしながら、各ベースリレーション (RelOptInfo *rel) を取得する。 2. **スロットおよびリレーション種のフィルタリング**: スロットが空 (rel == NULL) である場合や、RELOPT_BASEREL 以外のRTE ("other rels") である場合はスキップする。 3. **結合情報 (joininfo) の順次確認**: 各ベースリレーションの rel->joininfo リスト内の結合条件 (RestrictInfo *rinfo) を走査する。 4. **OR条件および移動可能性の判定**: 該当する rinfo がOR条件であるか (restriction_is_or_clause(rinfo))、かつそのリレーションへ移動可能か (join_clause_is_movable_to(rinfo, rel)) を評価する。 5. **制限OR条件の抽出と適用**: 条件を満たす場合、対象リレーションのみに対する式を extract_or_clause(rinfo, rel) で抽出し、抽出に成功した (orclause != NULL) 場合は consider_new_or_clause(root, rel, orclause, rinfo) を呼び出してリレーションへの追加や選択率補正を行う。

失敗モードと境界条件

  • rel == NULL のスロットや RELOPT_BASEREL 以外のリレーションが検出された場合、該当要素の処理は無視され次のループへ進む。
  • 結合条件がOR句でない場合、あるいは指定リレーションへ移動可能でない場合は抽出処理が行われない。
  • extract_or_clause が式を抽出しなかった場合 (orclause が NULL) は、追加処理は実行されない。
