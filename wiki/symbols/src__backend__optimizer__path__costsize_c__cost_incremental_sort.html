目的

インクリメンタルソートパス（Incremental Sort）の実行コスト（起動コストおよびトータルコスト）を見積もり、指定されたパス構造体に設定する。

入力と出力

  • 引数:
  • Path *path: コストを設定する対象のパス構造体
  • PlannerInfo *root: プランナーのグローバル情報
  • List *pathkeys: パスのソート順序を規定するパスキーのリスト
  • int presorted_keys: プレソート済みのキーの数
  • int input_disabled_nodes: 入力パスの無効化ノード数
  • Cost input_startup_cost: 入力パスの起動コスト
  • Cost input_total_cost: 入力パスのトータルコスト
  • double input_tuples: 入力タプル数
  • int width: タプル幅（バイト数）
  • Cost comparison_cost: 比較演算あたりのCPUコスト
  • int sort_mem: ソートに使用可能なメモリ量（キロバイト単位）
  • double limit_tuples: リミット行数
  • 戻り値: なし（void）

前提条件と不変条件

  • presorted_keys は 0 より大きく、かつ pathkeys の総数未満でなければならない。
  • enable_incremental_sort が有効であること（アサーションで検証される）。
  • 渡された input_tuples が 2.0 未満の場合は、ゼロ除算や log(0) を防ぐために強制的に 2.0 以上に補正される。

アルゴリズムまたは振る舞い

1. 入力行数とグループ数の初期推計:

  • input_tuples が 2.0 未満の場合は 2.0 にクランプする。
  • デフォルトのグループ数推計として、input_tuples と DEFAULT_NUM_DISTINCT の小さい方を取る。

    • 2. プレソートキーの抽出と varno 0 の検出:

  • pathkeys を走査し、presorted_keys に達するまでプレソート式を抽出する。
  • 式の中に varno 0 を持つ Var が含まれている場合（generate_append_tlist 等に起因）、estimate_num_groups が失敗するため検出フラグ (unknown_varno) を立てて走査を中断し、デフォルトのグループ数推計を維持する。

    • 3. グループ数とグループあたりコストの算出:

  • unknown_varno が真でない場合は estimate_num_groups を呼び出してグループ数を精密に見積もる。
  • 1グループあたりのタプル数 (group_tuples = input_tuples / input_groups) および1グループあたりの入力実行コストを計算する。
  • cost_tuplesort を呼び出し、1グループあたりのソート起動コストと実行コストを算出する。

    • 4. 起動コストとトータルコストの合算:

  • 起動コスト (startup_cost) = 最初のグループのソート起動コスト + 入力パスの起動コスト + 最初のグループの入力実行コスト。
  • 実行コスト (run_cost) = 最初のグループのソート実行コスト + 残りのグループ群を処理するコスト（起動コストと実行コストの合算×残りのグループ数） + 残りのグループの入力実行コスト。
  • インクリメンタルソート固有のオーバーヘッド（グループ検出のためのコピー・比較コスト、および各グループ終了時に行われる tuplesort_reset に伴う cpu_tuple_cost）を run_cost に加算する。

    • 5. パスへの結果書き込み:

  • 計算された行数、無効化ノード数、起動コスト、およびトータルコスト（startup_cost + run_cost）を path に書き込む。

呼び出し元と呼び出し先

  • 呼び出し元: cost_append, create_incremental_sort_path, create_merge_append_path, initial_cost_mergejoin, label_incrementalsort_with_costsize
  • 呼び出し先: Assert, bms_is_member, cost_tuplesort, estimate_num_groups, lappend, pull_varnos

失敗モードと境界条件

  • presorted_keys が不正（0 以下、あるいは pathkeys の長所以上）な場合、Assert により異常終了する。
  • enable_incremental_sort が無効な状態で本関数が呼び出された場合、アサーション違反により失敗する。
