目的

INSERT クエリ等のターゲットリストを指定されたリレーションの全属性数および順序に一致するように展開・補完します。

シグネチャまたは形状

  • static List * expand_insert_targetlist(PlannerInfo *root, List *tlist, Relation rel)

入力と出力

  • 入力:
  • PlannerInfo *root: プランナーのグローバル情報
  • List *tlist: 既存のターゲットエントリ（TargetEntry）リスト
  • Relation rel: 対象リレーションの Relation 記述子
  • 出力:
  • List *: 展開および再番号付けされた新しいターゲットエントリリスト

前提条件と不変条件

  • 入力されるターゲットリストの非ジャンクエントリは、リレーションの属性順に正しく並べられていることが期待されます。
  • 残存するジャンクエントリ（resjunk が真のエントリ）は、すべての実属性の後に続く連番の resno を持つように再割り当てされます。

アルゴリズムまたは振る舞い

1. 初期化: ターゲットリストの先頭セルを取得し、リレーションの属性総数（numattrs）をリレーションキャッシュから取得します。 2. ユーザ属性の走査: 1 から numattrs までループし、各属性について対応する TargetEntry を決定します。

  • 既存のリストアイテムが存在し、かつそれがジャンク列ではなく現在の属性番号（attrno）と一致する場合は、既存の TargetEntry をそのまま流用し、リストの次のアイテムへ進めます。

    • 3. 欠落列の補完: 一致するエントリが見つからない場合、カラムの状態に応じて適切な NULL 式を生成します。

  • 属性がドロップされている場合（attisdropped）、INT4OID 型の NULL 定数式を生成します。
  • 生成列の場合（attgenerated）、ベース型の取得と型修飾子の解決を行った上で、ベース型の NULL 定数式を生成します。
  • 通常の列の場合、ドメイン制約を適用した NULL 式を生成し、必要に応じて定数式の評価（eval_const_expressions）を実行します。
  • 生成した式と属性名を用いて新しい TargetEntry を作成し、新しいターゲットリストに追加します。

    • 4. ジャンクエントリの処理: リレーション属性の走査後も残っているリストアイテムを走査します。

  • ジャンクでないエントリが含まれていた場合はエラーを送出します。
  • 必要に応じてエントリをコピーし、resno を現在の attrno に更新して新しいターゲットリストの末尾に追加し、attrno をインクリメントします。

    • 5. 終了: 構築された新しいターゲットリストを返します。

失敗モードと境界条件

  • ターゲットリストの残余部分に非ジャンクエントリを発見した場合、elog(ERROR, "targetlist is not sorted correctly") をスローして処理を中断します。
