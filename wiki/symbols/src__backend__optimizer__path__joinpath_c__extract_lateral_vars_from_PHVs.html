~~~c static List * extract_lateral_vars_from_PHVs(PlannerInfo *root, Relids innerrelids) { List *ph_lateral_vars = NIL; ListCell *lc;

/* Nothing would be found if the query contains no LATERAL RTEs */ if (!root->hasLateralRTEs) return NIL;

/*

  • No need to consider PHVs that are due to be evaluated at joinrels,
  • since we do not add Memoize nodes on top of joinrel paths.

    • */ if (bms_membership(innerrelids) == BMS_MULTIPLE) return NIL;

foreach(lc, root->placeholder_list) { PlaceHolderInfo *phinfo = (PlaceHolderInfo *) lfirst(lc); List *vars; ListCell *cell;

/* PHV is uninteresting if no lateral refs */ if (phinfo->ph_lateral == NULL) continue;

/* PHV is uninteresting if not due to be evaluated at innerrelids */ if (!bms_equal(phinfo->ph_eval_at, innerrelids)) continue;

/*

  • If the PHV does not reference any rels in innerrelids, use its
  • contained expression as a cache key rather than extracting the
  • Vars/PHVs from it and using those. This can be beneficial in cases
  • where the expression results in fewer distinct values to cache
  • tuples for.

    • */ if (!bms_overlap(pull_varnos(root, (Node *) phinfo->ph_var->phexpr), innerrelids)) { ph_lateral_vars = lappend(ph_lateral_vars, phinfo->ph_var->phexpr); continue; }

/* Fetch Vars and PHVs of lateral references within PlaceHolderVars */ vars = pull_vars_of_level((Node *) phinfo->ph_var->phexpr, 0); foreach(cell, vars) { Node *node = (Node *) lfirst(cell);

if (IsA(node, Var)) { Var *var = (Var *) node;

Assert(var->varlevelsup == 0);

if (bms_is_member(var->varno, phinfo->ph_lateral)) ph_lateral_vars = lappend(ph_lateral_vars, node); } ~~~

目的

クエリ内のプレースホルダ変数（PlaceHolderVar）およびプレースホルダ情報（PlaceHolderInfo）から、指定された内部リレーション（innerrelids）のメモ化キャッシュキーやパラメータとして利用すべき外部参照（ラテラル変数）のリストを抽出する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナ全体の情報構造体
  • Relids innerrelids: 内部側のリレーション識別子集合
  • 戻り値:
  • List *: 抽出されたラテラル変数のリスト（NIL の場合あり）

前提条件と不変条件

  • クエリに LATERAL 参照（hasLateralRTEs）が含まれていない場合、処理は行われない。
  • 結合関係（joinrel）上に Memoize ノードを配置しないため、複数リレーションにまたがる（BMS_MULTIPLE）評価対象の PHV は考慮対象外となる。
  • 走査される Var ノードの varlevelsup は 0 であることがアサーションで検証される。
  • 走査される PlaceHolderVar ノードの phlevelsup は 0 であることがアサーションで検証される。

アルゴリズムまたは振る舞い

1. 早期リターン判定:

  • root->hasLateralRTEs が偽である場合、NIL を返す。
  • innerrelids のメンバーシップが BMS_MULTIPLE である場合、結合リレーション上の評価とみなして NIL を返す。

    • 2. プレースホルダ情報の反復処理:

  • root->placeholder_list 内の各 PlaceHolderInfo（phinfo）について以下を順に評価する。
  • phinfo->ph_lateral が NULL であるか、phinfo->ph_eval_at が innerrelids と bms_equal で一致しない場合はスキップする。

    • 3. 式全体のキャッシュキー利用判定:

  • PHV 式自体が innerrelids 内のリレーションを全く参照しない（bms_overlap が偽）場合、含まれる変数ではなく phinfo->ph_var->phexpr 自体をキャッシュキー候補としてリストに追加し、次のループへ進む。

    • 4. 内部変数および PHV の抽出:

  • pull_vars_of_level を使用して、レベル 0 の式内から Var および PlaceHolderVar を抽出する。
  • 抽出された各ノードについて型を判定する:
  • Var の場合: var->varno が phinfo->ph_lateral に含まれていれば（bms_is_member）、リストに追加する。
  • PlaceHolderVar の場合: 対応する ph_eval_at が phinfo->ph_lateral のサブセットであれば（bms_is_subset）、リストに追加する。
  • その他の型の場合: Assert(false) により異常系として弾く。
  • 一時的に割り当てた変数のリストを list_free で解放する。

    • 5. 完了:

  • 収集した ph_lateral_vars リストを返す。

失敗モードと境界条件

  • 予期しないノード型が PHV 表現内に出現した場合、アサーション違反によりクラッシュする可能性がある。
