目的

与えられた外側パスと内側パスが部分並列マージ結合の要件を満たすかどうかを検証し、条件に適合する場合はマージ結合パスを構築して結合関係（joinrel）の部分パスリストへ追加する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • RelOptInfo *joinrel: 結合対象のリレーション情報
  • Path *outer_path: 外側の子パス
  • Path *inner_path: 内側の子パス
  • List *pathkeys: 生成するパスのパスキー
  • List *mergeclauses: マージ結合に使用する制限条項のリスト
  • List *outersortkeys: 外側パスに対するソートキーのリスト
  • List *innersortkeys: 内側パスに対するソートキーのリスト
  • JoinType jointype: 結合のタイプ（内部結合など）
  • JoinPathExtraData *extra: 追加の結合パスデータ
  • 戻り値: なし（void）

前提条件と不変条件

  • 結合関係 (joinrel) は相関リレーション（lateral relids）を持っていないこと。
  • 外側パス (outer_path) に要求される外部リレーションが存在しないこと（空であること）。

アルゴリズムまたは振る舞い

1. **前提条件の検証**:

  • joinrel->lateral_relids および外側パスの要求外部リレーション（PATH_REQ_OUTER(outer_path)）が空であることをアサートする。
  • 内側パスが要求する外部リレーション（PATH_REQ_OUTER(inner_path)）が空でない場合は、そのまま処理を中断してリターンする。

    • 2. **ソート済みキーの確認**:

  • outersortkeys が存在し、外側パスのパスキーに完全に含まれている場合は、outer_presorted_keys を設定して outersortkeys を NIL にクリアする。
  • innersortkeys が存在し、内側パスのパスキーに完全に含まれている場合は、innersortkeys を NIL にクリアする。

    • 3. **コストの見積もり**:

  • initial_cost_mergejoin を呼び出し、マージ結合の起動コストおよび総コストをワークスペースに算出する。

    • 4. **事前チェック**:

  • add_partial_path_precheck により、算出されたコストや無効化されたノード情報をもとに部分パスの追加価値を判定する。不適格な場合は処理を中断する。

    • 5. **パスの生成と追加**:

  • create_mergejoin_path を用いてマージ結合パスを生成し、add_partial_path を介して joinrel の部分パスリストへ登録する。

失敗モードと境界条件

  • 内側パスが外部リレーションを要求している場合 (!bms_is_empty(PATH_REQ_OUTER(inner_path))) は、パスを生成せず早期リターンする。
  • コスト事前チェック（add_partial_path_precheck）において十分な効率が見込めないと判断された場合も、パスを生成せずにリターンする。
