目的

inh フラグが設定された範囲テーブルエントリ（RTE）を拡張し、子テーブルの RTE、AppendRelInfo、RelOptInfo、および必要に応じて PlanRowMark やジャンク変数を作成・構築する。

シグネチャまたは形状

  • シグネチャ: void expand_inherited_rtentry(PlannerInfo *root, RelOptInfo *rel, RangeTblEntry *rte, Index rti)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナ全体の情報を保持する構造体へのポインタ
  • RelOptInfo *rel: 拡張対象の親リレーションのオプティマイザ情報
  • RangeTblEntry *rte: 拡張対象の範囲テーブルエントリ
  • Index rti: 範囲テーブルのインデックス（識別子）
  • 戻り値: なし（void）

前提条件と不変条件

  • 引数で渡された rte->inh が真でなければならない（呼び出し元エラーとなる）。
  • rte->rtekind が RTE_SUBQUERY の場合、あるいは RELKIND_PARTITIONED_TABLE である場合、または通常の継承テーブルである場合のいずれかに分岐する。

アルゴリズムまたは振る舞い

1. **RTE 種別の判定とサブクエリの委譲**:

  • rte->inh が有効であることをアサートで検証する。
  • rte->rtekind が RTE_SUBQUERY である場合は、expand_appendrel_subquery を呼び出して処理を委譲し、即座にリターンする。
  • それ以外の場合は rte->rtekind == RTE_RELATION であることをアサートする。

2. **親リレーションのオープンと行マークの更新**:

  • rte->relid から parentOID を取得し、リライトフェーズでロック取得済みなため NoLock で親リレーションを開く。
  • 親リレーションが FOR UPDATE または FOR SHARE に選択されている場合、対応する PlanRowMark の isParent を true に設定し、初期の allMarkTypes を退避する。

3. **パーティションテーブルまたは通常継承の展開分岐**:

  • 親リレーションの relkind が RELKIND_PARTITIONED_TABLE である場合、getRTEPermissionInfo でパーミッション情報を取得した後、expand_partitioned_rtentry を呼び出してパーティションツリーを再帰的に拡張・ロックする。
  • 従来型の継承テーブルである場合、find_all_inheritors により全継承メンバの OID リスト（inhOIDs）を取得する。
  • リストが空でないこと、および先頭要素が parentOID であることをアサートする。
  • expand_planner_arrays を呼び出して、プランナのシンプルリレーション配列などを拡張する。
  • 取得した各子 OID についてループを回し、親自身でなければ table_open でオープンする。
  • 他のバックエンドの一時テーブル（RELATION_IS_OTHER_TEMP）である場合は、安全性の観点からロックを解放してスキップする。
  • expand_single_inheritance_child を呼び出して子用の RTE、AppendRelInfo、行マークを作成し、build_simple_rel で子側の RelOptInfo を構築する。
  • 子リレーションをクローズする（ロックは保持）。

4. **追加ジャンク変数のトップレベルターゲットリストへの追加**:

  • 子の展開によって新たなマークタイプが必要になった場合、必要に応じて TID ジャンク変数、行全体（wholerow）ジャンク変数、または tableoid ジャンク変数を root->processed_tlist に追加し、親の reltarget へ反映する。

5. **クリーンアップ**:

  • 親リレーションをクローズする (table_close(oldrelation, NoLock))。

失敗モードと境界条件

  • rte->inh が偽の状態で呼び出された場合、冒頭の Assert(rte->inh) により失敗する。
  • 従来型継承の処理において、find_all_inheritors の結果が空である場合や先頭が親 OID でない場合、アサート違反となる。
  • 他のバックエンドのテンポラリテーブルが子に含まれる場合、バッファリング上の安全性の理由から、暗黙的にスキップされる。
