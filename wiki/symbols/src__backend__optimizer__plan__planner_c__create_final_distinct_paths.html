目的

クエリの DISTINCT 処理や DISTINCT ON に対する最終的な最適化パス（ソートベースまたはハッシュベース）を構築し、指定されたリレーションに追加する。

シグネチャまたは形状

  • シグネチャ: static RelOptInfo * create_final_distinct_paths(PlannerInfo *root, RelOptInfo *input_rel, RelOptInfo *distinct_rel)

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体の情報を保持する構造体。
  • RelOptInfo *input_rel: 入力となるリレーション。
  • RelOptInfo *distinct_rel: パスを追加する対象の DISTINCT リレーション。
  • 戻り値:
  • RelOptInfo *: パスが追加された distinct_rel を返す。

前提条件と不変条件

  • グループ化や集約が存在するか hasHavingQual が真の場合、DISTINCT 行数の見積もりには入力リレーションの行数（cheapest_input_path->rows）がそのまま使用される。
  • グループ化や集約がない場合は、processed_distinctClause とターゲットリストから抽出された式をもとに estimate_num_groups を用いて重複排除後の行数を見積もる。
  • DISTINCT ON クエリでは、DISTINCT と ORDER BY のうちより厳密な順序付けを適用する必要がある。

アルゴリズムまたは振る舞い

1. DISTINCT 行数の見積もり: クエリにグループ化、グループ化セット、集約、HAVING 句のいずれかがある場合は入力行数をそのまま使い、それ以外の場合は get_sortgrouplist_exprs と estimate_num_groups を用いて一意な行数を推定する。 2. ソートベース実装の検討:

  • grouping_is_sortable が成立する場合、needed_pathkeys（DISTINCT ON の有無に応じて sort_pathkeys または distinct_pathkeys を選択）を決定する。
  • 入力リレーションの各パス（pathlist）ループを回し、get_useful_pathkeys_for_distinct を通じて有用なパスキーのリストを取得する。
  • 各有用パスキーごとに make_ordered_path を呼び出して順序付きパスを生成する。
  • root->distinct_pathkeys が空（NIL）の場合は、すべてのタスクが同一であるとみなして LIMIT 1 パス（create_limit_path）を構築し、そうでない場合は create_unique_path を構築して distinct_rel に追加する。

    • 3. ハッシュベース実装の検討:

  • 代替パスが存在しない場合、あるいは DISTINCT ON が使用されておらず enable_hashagg が有効であればハッシュの許可フラグ（allow_hash）を立てる。
  • grouping_is_hashable が成立する場合に、ハッシュ集約パス（create_agg_path と AGG_HASHED）を生成して distinct_rel に追加する。

    • 4. 終了: すべてのパス候補を格納した distinct_rel を返して終了する。
