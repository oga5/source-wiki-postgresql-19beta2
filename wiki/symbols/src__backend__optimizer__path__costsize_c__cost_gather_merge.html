~~~c void cost_gather_merge(GatherMergePath *path, PlannerInfo *root, RelOptInfo *rel, ParamPathInfo *param_info, int input_disabled_nodes, Cost input_startup_cost, Cost input_total_cost, double *rows) { Cost startup_cost = 0; Cost run_cost = 0; Cost comparison_cost; double N; double logN;

/* Mark the path with the correct row estimate */ if (rows) path->path.rows = *rows; else if (param_info) path->path.rows = param_info->ppi_rows; else path->path.rows = rel->rows;

/*

  • Add one to the number of workers to account for the leader. This might
  • be overgenerous since the leader will do less work than other workers
  • in typical cases, but we'll go with it for now.

    • */ Assert(path->num_workers > 0); N = (double) path->num_workers + 1; logN = LOG2(N);

/* Assumed cost per tuple comparison */ comparison_cost = 2.0 * cpu_operator_cost;

/* Heap creation cost */ startup_cost += comparison_cost * N * logN;

/* Per-tuple heap maintenance cost */ run_cost += path->path.rows * comparison_cost * logN;

/* small cost for heap management, like cost_merge_append */ run_cost += cpu_operator_cost * path->path.rows;

/*

  • Parallel setup and communication cost. Since Gather Merge, unlike
  • Gather, requires us to block until a tuple is available from every
  • worker, we bump the IPC cost up a little bit as compared with Gather.
  • For lack of a better idea, charge an extra 5%.

    • */ startup_cost += parallel_setup_cost; run_cost += parallel_tuple_cost * path->path.rows * 1.05;

path->path.disabled_nodes = path->subpath->disabled_nodes + ((rel->pgs_mask & PGS_GATHER_MERGE) != 0 ? 0 : 1); path->path.startup_cost = startup_cost + input_startup_cost; path->path.total_cost = (startup_cost + run_cost + input_total_cost); } ~~~

目的

GatherMergePath 実行パスに対して、起動コスト、総コスト、出力行数、および無効化ノード数を算出・設定する。

入力と出力

  • 引数:
  • path: コストと行数を書き込む対象の GatherMergePath * 構造体
  • root: プラン全体の情報を持つ PlannerInfo * 構造体
  • rel: 対象リレーションの情報を保持する RelOptInfo * 構造体
  • param_info: パラメータ化パスの情報を保持する ParamPathInfo * 構造体（オプショナル）
  • input_disabled_nodes: サブパス側から持ち越される無効化ノード数
  • input_startup_cost: 入力側パスの起動コスト
  • input_total_cost: 入力側パスの総コスト
  • rows: 優先して適用する行数のポインタ（オプショナル）
  • 戻り値: なし（引数の path フィールドを直接更新する）

前提条件と不変条件

  • path->num_workers > 0 でなければならない（アサーションにより検証される）

アルゴリズムまたは振る舞い

1. **出力行数の決定**:

  • 引数 rows が有効な場合はその値を path->path.rows に設定する。
  • rows が NULL で param_info が存在する場合は param_info->ppi_rows を設定する。
  • いずれでもない場合は rel->rows を設定する。

    • 2. **ワーカー数に基づく係数の算出**:

  • リーダープロセス分を加算するため、総参加プロセス数 $N =$ path->num_workers $+ 1$ とする。
  • $N$ の対数 $\log_2(N)$ を算出し、タプル比較コスト comparison_cost を 2.0 * cpu_operator_cost として定義する。

    • 3. **コストの計算**:

  • ヒープ作成時の起動コストに comparison_cost * N * logN を加算する。
  • タプルごとのヒープ維持コストをランコストに加算する（path->path.rows * comparison_cost * logN）。
  • cost_merge_append と同様のヒープ管理に関する小規模なコスト（cpu_operator_cost * path->path.rows）をランコストに加算する。
  • Gather と異なり各ワーカーからのタプル待ちブロックが発生することを考慮し、IPCコストとして parallel_setup_cost を起動コストに加算し、さらにタプル転送コストを 5% 増しにしてランコストに加算する（parallel_tuple_cost * path->path.rows * 1.05）。

    • 4. **結果の反映**:

  • リレーションのマスク rel->pgs_mask と PGS_GATHER_MERGE のフラグ評価に基づき、無効化ノード数 disabled_nodes を計算して path->path.disabled_nodes に設定する。
  • 入力側の起動・総コストを加算した最終的な startup_cost と total_cost を path->path に格納する。

失敗モードと境界条件

  • path->num_workers が 0 以下の場合、Assert(path->num_workers > 0) により検証エラー（アサーション違反）となる。
