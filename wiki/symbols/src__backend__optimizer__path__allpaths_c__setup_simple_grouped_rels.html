目的

クエリの集約式リストとグループ化式リストの双方が存在する場合に、各単純ベースリレーションに対して早期集約（eager aggregation）用のグループ化リレーションを構築する。

シグネチャまたは形状

  • シグネチャ: static void setup_simple_grouped_rels(PlannerInfo *root)

入力と出力

  • 引数: PlannerInfo *root (プランナのグローバル情報を格納する構造体ポインタ)
  • 戻り値: void

前提条件と不変条件

  • root->agg_clause_list が NIL であるか、または root->group_expr_list が NIL である場合、早期集約は不可能なため何もせず早期リターンする。
  • simple_rel_array 内の非 NULL な各リレーション rel について、rel->relid == rti および IS_SIMPLE_REL(rel) が成立していなければならない。

アルゴリズムまたは振る舞い

1. root->agg_clause_list または root->group_expr_list のいずれかが NIL であるかを検査し、該当する場合は処理を終了する。 2. rti を 1 から root->simple_rel_array_size - 1 までインクリメントしながら走査する。 3. root->simple_rel_array[rti] からリレーション rel を取得する。スロットが NULL（非ベースリレーションのRTEに対応）の場合はスキップする。 4. rel の relid が rti と一致していること、および単純リレーションであることをアサーションで検証する。 5. build_simple_grouped_rel(root, rel) を呼び出し、単純グループ化リレーションを構築する。

呼び出し元と呼び出し先

  • 呼び出し元: make_one_rel (src/backend/optimizer/path/allpaths.c)
  • 呼び出し先: build_simple_grouped_rel (src/backend/optimizer/util/relnode.c)

関連データ構造

  • PlannerInfo: クエリ全体のプランニング状態を保持する構造体
  • RelOptInfo: リレーションのオプティマイザ向け情報を保持する構造体

失敗モードと境界条件

  • simple_rel_array のスロットが NULL である場合、非ベースリレーションのRTEスロットとみなして安全にスキップされる。
  • 配列の整合性やリレーション種別が期待値に反している場合、Assert によりデバッグ時検証エラーとなる。
