ソース抜粋

~~~c static PathKey * make_pathkey_from_sortop(PlannerInfo *root, Expr *expr, Oid ordering_op, bool reverse_sort, bool nulls_first, Index sortref, bool create_it) { Oid opfamily, opcintype, collation; CompareType cmptype;

/* Find the operator in pg_amop --- failure shouldn't happen */ if (!get_ordering_op_properties(ordering_op, &opfamily, &opcintype, &cmptype)) elog(ERROR, "operator %u is not a valid ordering operator", ordering_op);

/* Because SortGroupClause doesn't carry collation, consult the expr */ collation = exprCollation((Node *) expr);

return make_pathkey_from_sortinfo(root, expr, opfamily, opcintype, collation, reverse_sort, nulls_first, sortref, NULL, create_it); } ~~~

目的

指定されたソート演算子と式から、対応する演算子ファミリーと照合順序を解決し、make_pathkey_from_sortinfo を呼び出して PathKey オブジェクトを構築・取得する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • Expr *expr: ソート対象の式
  • Oid ordering_op: 順序付けに使用する演算子の OID
  • bool reverse_sort: 逆順ソートかどうかを示すフラグ
  • bool nulls_first: NULL を最初に配置するかどうかを示すフラグ
  • Index sortref: ソート参照インデックス
  • bool create_it: 該当する等価クラスやパスキーが存在しない場合に新規作成するかどうかを示すフラグ
  • 戻り値: 構築された PathKey *（見つからない場合や作成されない場合は NULL の可能性がある）

前提条件と不変条件

  • ordering_op は pg_amop カタログに登録された有効な順序付け演算子である必要がある。
  • SortGroupClause が照合順序を保持しないため、照合順序は expr から導出される。

アルゴリズムまたは振る舞い

1. get_ordering_op_properties を呼び出し、ordering_op に対応する演算子ファミリー (opfamily)、演算子クラスの入力型 (opcintype)、および比較型 (cmptype) を取得する。 2. 演算子プロパティの取得に失敗した場合は、エラーとして処理を中断する。 3. exprCollation を用いて、渡された expr のノードから照合順序 (collation) を取得する。 4. 取得したパラメータ (root、expr、opfamily、opcintype、collation、reverse_sort、nulls_first、sortref、NULL、create_it) を引数として make_pathkey_from_sortinfo を呼び出し、その結果を返す。

失敗モードと境界条件

  • ordering_op が有効な順序付け演算子でない場合、get_ordering_op_properties が偽を返し、ERROR レベルのログによって処理が中断される。
