ソース抜粋

~~~c Path * create_seqscan_path(PlannerInfo *root, RelOptInfo *rel, Relids required_outer, int parallel_workers) { Path *pathnode = makeNode(Path);

pathnode->pathtype = T_SeqScan; pathnode->parent = rel; pathnode->pathtarget = rel->reltarget; pathnode->param_info = get_baserel_parampathinfo(root, rel, required_outer); pathnode->parallel_aware = (parallel_workers > 0); pathnode->parallel_safe = rel->consider_parallel; pathnode->parallel_workers = parallel_workers; pathnode->pathkeys = NIL; /* seqscan has unordered result */

cost_seqscan(pathnode, root, rel, pathnode->param_info);

目的

シーケンシャルスキャン（T_SeqScan）を実行するための Path ノードを新しく生成し、初期化およびコスト計算を行う。

入力と出力

  • **入力**:
  • PlannerInfo *root: プランナーのグローバル情報。
  • RelOptInfo *rel: スキャン対象となるベースリレーションの情報。
  • Relids required_outer: このパスで必要とされる外部リレーションのID集合（パラメータ化パス用）。
  • int parallel_workers: 使用する並列ワーカー数。並列実行しない場合は 0。
  • **出力**:
  • Path *: 生成され、コスト見積もりが完了したシーケンシャルスキャンパスへのポインタ。

前提条件と不変条件

  • シーケンシャルスキャンは順序を保証しないアクセス手法であるため、生成されるパスの pathkeys は常に NIL に設定される。
  • parallel_aware フラグは、引数 parallel_workers が 0 より大きい場合にのみ true に設定される。
  • parallel_safe フラグは、対象リレーションの並列実行可能性を示す rel->consider_parallel の値がそのまま引き継がれる。

アルゴリズムまたは振る舞い

1. makeNode(Path) を呼び出して、新しい Path 構造体のメモリを割り当てる。 2. パスの基本属性を設定する。

  • pathtype を T_SeqScan に設定する。
  • parent に対象リレーション rel を設定する。
  • pathtarget にリレーションのターゲットリスト rel->reltarget を設定する。

    • 3. get_baserel_parampathinfo を呼び出して、パラメータ化されたパス情報を取得し、param_info に設定する。 4. 並列処理に関する設定を行う。

  • parallel_workers が 0 より大きいかどうかに基づいて parallel_aware を設定する。
  • parallel_safe に rel->consider_parallel をコピーする。
  • parallel_workers に引数の値を設定する。

    • 5. pathkeys を NIL に設定する。 6. cost_seqscan を呼び出して、パスの起動コストおよびトータルコストを計算し、pathnode に格納する。 7. 構築した pathnode を返す。

失敗モードと境界条件

  • **メモリ割り当て**: makeNode(Path) によるメモリ割り当てが失敗した場合、PostgreSQLのメモリ管理機構（palloc）を通じてエラーが発生し、トランザクションがアボートする。
  • **並列ワーカー数**: parallel_workers が 0 以下の場合は parallel_aware は false となり、非並列パスとして扱われる。
  • **パラメータ化情報**: required_outer が空（NULL）の場合、get_baserel_parampathinfo はパラメータ化されていない通常のパス情報を返す。
