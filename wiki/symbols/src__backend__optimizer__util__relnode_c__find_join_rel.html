~~~c RelOptInfo * find_join_rel(PlannerInfo *root, Relids relids) { /*

  • Switch to using hash lookup when list grows "too long". The threshold
  • is arbitrary and is known only here.

    • */ if (!root->join_rel_hash && list_length(root->join_rel_list) > 32) build_join_rel_hash(root);

/*

  • Use either hashtable lookup or linear search, as appropriate.

    • *

  • Note: the seemingly redundant hashkey variable is used to avoid taking
  • the address of relids; unless the compiler is exceedingly smart, doing
  • so would force relids out of a register and thus probably slow down the
  • list-search case.

    • */ if (root->join_rel_hash) { Relids hashkey = relids; JoinHashEntry *hentry;

hentry = (JoinHashEntry *) hash_search(root->join_rel_hash, &hashkey, HASH_FIND, NULL); if (hentry) return hentry->join_rel; } else { ListCell *l;

foreach(l, root->join_rel_list) { RelOptInfo *rel = (RelOptInfo *) lfirst(l);

if (bms_equal(rel->relids, relids)) return rel; } }

return NULL; } ~~~

目的

指定されたリレーション識別子（Relids）に対応する結合リレーションの RelOptInfo 構造体をプランナー情報から検索して返します。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーのグローバル情報コンテキスト。
  • Relids relids: 検索対象の結合リレーション群を表すビットマップ識別子。
  • 戻り値:
  • RelOptInfo *: 一致する結合リレーションのエントリ。見つからない場合は NULL。

前提条件と不変条件

  • root->join_rel_hash が未構築であり、かつ root->join_rel_list の要素数が 32 を超えた場合、検索処理の前にハッシュテーブルが自動的に構築されます。

アルゴリズムまたは振る舞い

1. ハッシュテーブルの遅延構築: root->join_rel_hash が存在せず、かつ root->join_rel_list のリスト長が 32 を超えているかを判定します。条件を満たす場合、build_join_rel_hash(root) を呼び出してハッシュテーブルへ切り替えます。 2. 検索方式の分岐:

  • root->join_rel_hash が有効な場合、hashkey 変数に relids をコピーした上で hash_search を用いてハッシュエントリ（JoinHashEntry）を検索します。エントリが存在すればその join_rel を返します。
  • root->join_rel_hash が NULL の場合、root->join_rel_list の各要素を線形走査し、bms_equal(rel->relids, relids) が真となる RelOptInfo を探索します。

    • 3. 終端: 一致するリレーションが見つかった場合はそれを返し、最後まで見つからない場合は NULL を返します。

失敗モードと境界条件

  • 該当する relids を持つ結合リレーションがまだ作成されていない場合、エラーとはならずに NULL が返されます。
