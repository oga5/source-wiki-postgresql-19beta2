目的

親リレーションの列権限または更新対象列を表すビットマップ（parent_privs）を、対応する子リレーションの列番号に変換して新しいビットマップを構築する。

入力と出力

  • 入力:
  • const Bitmapset *parent_privs: 親リレーションの列権限や属性を表すビットマップ
  • List *translated_vars: 親の列位置に対応する子リレーション側の Var ノードを格納したリスト
  • 出力:
  • Bitmapset *: 変換された子リレーション側の列権限ビットマップ

前提条件と不変条件

  • システム属性（FirstLowInvalidHeapAttributeNumber + 1 から 0 未満までの属性）は、すべてのテーブル間で同じ属性番号を持つため、そのままのオフセットで子ビットマップへ引き継がれる。

アルゴリズムまたは振る舞い

1. システム属性の処理:

  • FirstLowInvalidHeapAttributeNumber + 1 から 0 未満の範囲の各システム属性番号について、親のビットマップ（parent_privs）に含まれているかを判定する。
  • 含まれている場合、対応するビットを子リレーションのビットマップ（child_privs）に追加する。

    • 2. 行全体参照（Whole-Row Reference）の確認:

  • InvalidAttrNumber に対応する属性が親ビットマップに含まれているかを調べ、行全体への参照があるかどうかを whole_row フラグに保持する。

    • 3. ユーザ属性の変換:

  • ユーザ属性の基準位置（InvalidAttrNumber）から開始し、translated_vars リストを foreach で走査する。
  • 各要素から Var ノードを取得し、属性番号カウンタを進める。
  • Var ノードが NULL の場合は削除された列（dropped column）とみなしてスキップする。
  • 行全体参照（whole_row）が有効であるか、あるいは現在の属性番号が親ビットマップに含まれている場合、該当する Var ノードの属性番号（var->varattno）を調整した上で、子ビットマップに追加する。

    • 4. 結果の返却:

  • 構築された child_privs ビットマップを返す。

失敗モードと境界条件

  • translated_vars 内の要素が NULL（削除された列）である場合、エラーとせずに安全にスキップされる。
