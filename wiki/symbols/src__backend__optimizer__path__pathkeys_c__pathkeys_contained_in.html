ソース抜粋

~~~c bool pathkeys_contained_in(List *keys1, List *keys2) { switch (compare_pathkeys(keys1, keys2)) { case PATHKEYS_EQUAL: case PATHKEYS_BETTER2: return true; default: break; } return false; } ~~~

目的

2つのパスキーリスト間における包含関係を評価し、第一引数のパスキーリスト（keys1）が第二引数のパスキーリスト（keys2）に含まれるか、あるいは同等の要件を満たしているかを判定します。

入力と出力

  • 引数: List *keys1, List *keys2（比較対象のパスキーリスト）
  • 戻り値: bool（keys1 が keys2 に包含されるか等価である場合は true、それ以外の場合は false）

前提条件と不変条件

  • 入力されるふたつのパスキーリストは、事前に正規化された PathKey ノードのリストである必要があります。

アルゴリズムまたは振る舞い

  • 内部で compare_pathkeys(keys1, keys2) を呼び出し、ふたつのパスキーリストの構造を比較します。
  • 比較結果が PATHKEYS_EQUAL（両者が等しい）または PATHKEYS_BETTER2（keys2 の方がより詳細、あるいは keys1 が keys2 の要件を包含して満たしている）のいずれかである場合に true を返します。
  • その他の比較結果の場合は false を返します。

失敗モードと境界条件

  • エラー送出パスや特殊な境界条件のハンドリングは特に持たず、不整合なリスト構造が渡された場合の挙動は compare_pathkeys の実装依存となります。
