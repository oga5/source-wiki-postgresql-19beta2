目的

MergeAppendPath から実行時用の MergeAppend 計画ノードを構築し、各サブプランのソート要件の整合性チェックや必要に応じたソート/インクリメンタルソートノードの挿入を行う。

シグネチャまたは形状

  • static Plan * create_merge_append_plan(PlannerInfo *root, MergeAppendPath *best_path, int flags)

入力と出力

  • 入力:
  • PlannerInfo *root: プランナー全体の情報
  • MergeAppendPath *best_path: 最適パスとして選択された MergeAppendPath
  • int flags: ターゲットリスト要件を指定するフラグ
  • 出力:
  • Plan *: 構築された MergeAppend 計画ノード、または射影が追加された場合はラップされた Result 計画ノードを返す。

前提条件と不変条件

  • すべてのサブプランは、MergeAppend が期待するものと同一のソートキー列構造を返さなければならない。
  • best_path->path.param_info は NULL であり、パラメータ化された MergeAppend パスは現時点で生成されない。

アルゴリズムまたは振る舞い

1. **初期ノードの基本設定**:

  • Merge 用の MergeAppend ノードを確保し、build_path_tlist でターゲットリストを作成して初期の長さを記録する。
  • copy_generic_path_info を用いて、パスの基本コストやメタデータを計画にコピーする。
  • prepare_sort_from_pathkeys を実行して MergeAppend 自体のソート列情報 (numCols, sortColIdx, sortOperators, collations, nullsFirst) を計算し、ターゲットリストが変更されたかどうかを検出する。

    • 2. **サブプランの順次走査と調整**:

  • best_path->subpaths 内の各子パスに対して create_plan_recurse を呼び出し、CP_EXACT_TLIST フラグを指定して子プランを構築する。
  • 各サブプランに対しても prepare_sort_from_pathkeys を適用し、ソートキー情報を取り出す。
  • numCols や sortColIdx, sortOperators, collations, nullsFirst を相互比較し、子プランのターゲットリストが一致していることを検証する。
  • サブプランが十分にソートされていない場合 (pathkeys_count_contained_in が偽の場合)、有効なプリソートキーの有無やインクリメンタルソートの有効性に応じて make_incrementalsort または make_sort を呼び出してソートプランを挿入する。
  • 処理済みのサブプランを subplans リストに順次追加する。

    • 3. **パーティションプルーニング情報の構築**:

  • enable_partition_pruning が有効な場合、ベースリレーションの制限条件 (rel->baserestrictinfo) から実際の条件式を抽出し、存在すれば make_partition_pruneinfo を呼び出して node->part_prune_index に設定する。

    • 4. **ターゲットリスト調整と終了処理**:

  • node->mergeplans にサブプランリストを設定する。
  • ソート列追加によってターゲットリストが拡張され、かつ呼び出し元から CP_EXACT_TLIST または CP_SMALL_TLIST が要求されていた場合は、元の長さに切り詰めた上で inject_projection_plan を介して射影計画を挿入する。
  • それ以外の場合はそのまま計画ノードを返す。

失敗モードと境界条件

  • 子プランのソート列番号、ソート演算子、照合順序、または NULL ファーストの設定が MergeAppend 側と一致しない場合、エラーログ (elog(ERROR, ...)) が発生する。
  • パラメータ化されたパスが存在する場合、Assert(best_path->path.param_info == NULL) により異常終了する。
