/* Caller made a mistake if SpecialJoinInfo is the wrong one */ Assert(sjinfo->jointype == JOIN_SEMI); Assert(bms_equal(rel->relids, sjinfo->syn_righthand));

/* If result already cached, return it */ if (rel->unique_rel) return rel->unique_rel;

/* If it's not possible to unique-ify, return NULL */ if (!(sjinfo->semi_can_btree || sjinfo->semi_can_hash)) return NULL;

/*

  • relation for its parent. This can happen if all the RHS columns were
  • found to be equated to constants when unique-ifying the parent table,
  • leaving no columns to unique-ify.

    • */ if (IS_OTHER_REL(rel) && rel->top_parent->unique_rel == NULL) return NULL;

/*

  • When called during GEQO join planning, we are in a short-lived memory
  • context. We must make sure that the unique rel and any subsidiary data
  • structures created for a baserel survive the GEQO cycle, else the
  • baserel is trashed for future GEQO cycles. On the other hand, when we
  • are creating those for a joinrel during GEQO, we don't want them to
  • clutter the main planning context. Upshot is that the best solution is
  • to explicitly allocate memory in the same context the given RelOptInfo
  • is in.

目的

セミジョインの右側リレーションに対して重複排除（unique-ify）されたパスやリレーション（RelOptInfo）を構築・キャッシュする。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体の情報
  • RelOptInfo *rel: 対象のリレーション
  • SpecialJoinInfo *sjinfo: セミジョインの特殊結合情報
  • 戻り値:
  • RelOptInfo *: 重重複排除済みリレーション、または構築不可能な場合の NULL

前提条件と不変条件

  • sjinfo->jointype は JOIN_SEMI でなければならない。
  • rel->relids は sjinfo->syn_righthand と等しくなければならない。
  • 一意性のあるリレーションには部分的パスリスト（partial_pathlist）が存在してはならない（NIL であること）。

アルゴリズムまたは振る舞い

1. キャッシュ確認: リレーションの unique_rel が既に存在する場合はそれを直ちに返却する。 2. 可能性の検証: 一意化が可能であるか（sjinfo->semi_can_btree または sjinfo->semi_can_hash が有効か）を検証し、不可能であれば NULL を返す。子リレーションの場合で親の unique_rel が存在しない場合も NULL を返す。 3. メモリコンテキストの調整: リレーションが属するメモリコンテキストに一時的に切り替えてメモリ割り当てを行う。 4. リレーション構造体の複製と初期化: RelOptInfo ノードを新規作成して複製し、パス関連フィールドをクリアする。 5. ターゲットリストとパスキー/グループ句の構築:

  • 子リレーション（IS_OTHER_REL(rel)）の場合は、親リレーションの設定からターゲットリストをコピーし、appendrel属性をマルチレベルで調整する。
  • 通常のリレーションの場合は、セミジョインの右側式および演算子を走査し、順序付け演算子（sortop）やハッシュ演算子（eq_oper）を導出して sortPathkeys や groupClause を構築する。定数に等しい等価式などで冗長となった項目は削除する。
  • 有効な列が見つからず sortPathkeys と groupClause の両方が空の場合はメモリコンテキストを復元して NULL を返す。

    • 6. 一意パスの生成: create_final_unique_paths および create_partial_unique_paths を呼び出して最終パスを構築する。 7. 最適パスの選択とキャッシュ: set_cheapest を呼び出して最適パスを選択し、結果を rel->unique_rel 等にキャッシュしてコンテキストを復元した上で unique_rel を返す。

失敗モードと境界条件

  • sjinfo->semi_can_btree と sjinfo->semi_can_hash の双方が偽である場合は一意化不可能として NULL を返す。
  • 子リレーションの親で一意化に失敗している場合（親の unique_rel が NULL）は NULL を返す。
  • 全てのRHS列が定数に等置された結果として一意化すべき列が残らない場合は NULL を返す。
  • 順序付け演算子や互換ハッシュ演算子が見つからない場合はエラーログ（elog(ERROR, ...)）を出力する。
