目的

サブクエリや集約などの高度な機能を除外した基本的なクエリおよび結合操作を対象に、パスやプランの構築に関する中心的な処理を行う中核ルーチンとして機能する。

入力と出力

  • 入力: PlannerInfo *root（計画対象のクエリ記述）、query_pathkeys_callback qp_callback（クエリパスキー計算用コールバック）、void *qp_extra（コールバックに渡す追加データ）
  • 出力: トップレベル結合の RelOptInfo *（生存するパスの集合を保持するリレーション情報）

前提条件と不変条件

  • append_rel_list は subquery_planner によって事前にセットアップされているため、関数内初期化の対象外とする。
  • 結合木の fromlist は空であってはならない。

アルゴリズムまたは振る舞い

1. **初期化**:

  • root->join_rel_list などの各種プランナ内部リストを NIL や NULL にクリアし、初期化する。
  • setup_simple_rel_arrays(root) を呼び出し、ベースリレーションと AppendRelInfos にアクセスするための配列を準備する。

    • 2. **トリビアルケース（単一 Result リレーション）の判定と処理**:

  • 結合木の fromlist の要素数が 1 であり、かつそれが RangeTblRef で示される RTE_RESULT 関係である場合、通常パスをバイパスして専用処理を実行する。
  • build_simple_rel により直接 final_rel を作成し、条件に応じて並行処理の安全性を評価した上で GroupResultPath を追加する。
  • 最安パスの設定を行い、root->ec_merging_done = true とみなして qp_callback を実行したのち早期リターンする。

    • 3. **ベースリレーションと結合木の構築**:

  • add_base_rels_to_query でクエリ内のすべてのベースリレーションに対する RelOptInfo ノードを構築する。
  • 不要な GROUP BY 列の削除や、ターゲットリスト・プレースホルダ・等価クラスの構築、結合木の分解（deconstruct_jointree）を行う。

    • 4. **等価クラス・結合の最適化**:

  • reconsider_outer_join_clauses や外側結合・等価関係の生成、プレースホルダ入力レベルの修正、不要な結合やセミジョイン、自己結合の削除を順次実行する。
  • パスキーが正規形式で生成できる状態になったタイミングで qp_callback を実行して query_pathkeys などを計算する。

    • 5. **最終リレーション生成**:

  • 外部キー制約のマッチング、オプティマイザの集約設定、add_other_rels_to_query によるパーティション等の子リレーション（otherrels）の展開、行識別子変数の配布を行う。
  • 最終的に make_one_rel(root, joinlist) を呼び出してプライマリプランニングを完了し、結合のトップレベル RelOptInfo を取得・返却する。

失敗モードと境界条件

  • 結合木が単一の RTE_RESULT 関係である場合、通常の複雑な結合処理パスを完全にバイパスして早期リターンする。
