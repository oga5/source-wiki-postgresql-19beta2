目的

クエリプランナの結合解析処理において、不要と判定された左結合（Left Join）の右辺リレーションとその外部結合関係をクエリおよびプランナの内部データ構造から安全に排除し、関連するメタデータや制約を再構築する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報
  • int relid: 削除対象のベースリレーションID
  • SpecialJoinInfo *sjinfo: 該当する外部結合のメタデータ構造体
  • 戻り値: なし (void)

前提条件と不変条件

  • sjinfo->ojrelid は 0 以外の値（有効な外部結合リレーションID）でなければならない。

アルゴリズムまたは振る舞い

1. **結合リレーション集合の計算**: sjinfo の最小左側（min_lefthand）と最小右側（min_righthand）の和集合をとり、さらに外部結合リレーションID（ojrelid）をメンバーとして追加して対象の結合リレーションID集合（joinrelids）を求める。 2. **クエリからのリレーション削除**: remove_rel_def などの仕組みを呼び出し、クエリツリー構造体から対象の relid を除去する。 3. **コミューート可能な結合関係の収集**: プッシュダウン判定のために、joinrelids に加えて当該外部結合と可換（commutable）な上位および下位の外部結合リレーションID集合を結合し、join_plus_commute セットを構築する。 4. **結合情報リストの走査と再配分**: 対象リレーションの元の joininfo リストのコピーを作成し、各 RestrictInfo（rinfo）について以下の処理を行う。

  • 既存の結合節情報を関係リストから削除する。
  • join_plus_commute に対してプッシュダウン可能（RINFO_IS_PUSHED_DOWN）である場合、プレースホルダ変数（PHV）に起因する relid や ojrelid の参照を制限情報から取り除く。
  • アサート検証により、結合節自体が削除対象の relid や ojrelid を含まないことを確認した上で、再び結合情報リストへ分散配置する。

    • 5. **ベースリレーション配列とメタデータのクリーンアップ**:

  • root->simple_rel_array[relid] および root->simple_rte_array[relid] を NULL に設定し、再参照を防止する。
  • 不要になった RelOptInfo（rel）構造体を pfree で解放する。

    • 6. **属性必要性の再構築**: プレースホルダ、結合節、等価クラス、ラテラル結合の各属性必要性（attr_needed）再計算関数を順次呼び出し、プランナ情報を最新の状態に同期する。

失敗モードと境界条件

  • デバッグビルド時（USE_ASSERT_CHECKING 有効時）、プッシュダウンされた結合節が対象の relid または ojrelid を依然として参照している場合はアサート違反により失敗する。
