目的

ON CONFLICT 句の競合解決（アービタイザ）で指定された推論要素（InferenceElem）の照合順序（collation）および演算子クラス（opclass）が、対象インデックスの属性と正確に一致するかどうかを検証します。

シグネチャまたは形状

static bool infer_collation_opclass_match(InferenceElem *elem, Relation idxRel, List *idxExprs)

入力と出力

  • 入力:
  • InferenceElem *elem: 検証対象の推論要素。
  • Relation idxRel: 比較対象のインデックスリレーション。
  • List *idxExprs: インデックス式のリスト。
  • 戻り値:
  • bool: 推論要素の条件とインデックス側の属性（演算子ファミリ、入力型、照合順序、式）が一致する場合は true、そうでない場合は false を返します。

前提条件と不変条件

  • 推論仕様要素に照合順序（infercollid）も演算子クラス（inferopclass）も指定されていない場合（共に InvalidOid の場合）、無条件で厳密な一致確認は不要とみなされ true を返します。
  • インデックス定義およびインデックスの推論指定のいずれにおいても、RelabelType ノードは含まれないという前提のもと処理されます。

アルゴリズムまたは振る舞い

1. 初期チェック: elem->infercollid および elem->inferopclass が共に InvalidOid の場合は、そのまま true を返します。 2. 演算子クラス情報の取得: elem->inferopclass が指定されている場合、get_opclass_family および get_opclass_input_type を呼び出して、それぞれ対応する演算子ファミリ（inferopfamily）と入力型（inferopcinputtype）を取得します。 3. インデックス属性の走査: 1 から idxRel->rd_att->natts までの各属性インデックス natt について、インデックス側の演算子ファミリ、入力型、照合順序、属性番号（attno）を順に取得します。 4. 属性ごとの適合判定:

  • attno != 0 の場合はプレーンな属性として nplain カウントをインクリメントします。
  • elem->inferopclass が有効であり、インデックス側の演算子ファミリまたは入力型が一致しない場合は、この属性のループをスキップ（continue）します。
  • elem->infercollid が有効であり、インデックス側の照合順序と一致しない場合もループをスキップします。

    • 5. 式または変数の照合:

  • elem->expr が Var ノードの場合、その変数属性番号（varattno）がインデックスの attno と一致すれば true を返します。
  • elem->expr が式であり、かつ attno == 0 の場合、idxExprs から対応する式（nattExpr）を取り出し、equal 関数によって elem->expr と一致するか比較し、一致すれば true を返します。

    • 6. 不一致の返却: すべての属性を走査しても条件を満たす一致が見つからなかった場合は、最終的に false を返します。

失敗モードと境界条件

  • 無効な inferopclass や infercollid が指定されている場合、カタログ参照やID比較を通じて安全にミスマッチと判定され、インデックス候補から除外されます。
  • 該当する一致がどのインデックス属性にも見つからない場合は、エラーではなく単に false を返します。
