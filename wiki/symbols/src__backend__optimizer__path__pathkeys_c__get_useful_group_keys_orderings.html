目的

クエリのグループ化キーについて、クエリ指定の順序に加えて代替となる有用な順序（GroupByOrdering構造体のリスト）を生成・評価する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナーの大域的情報構造体。
  • Path *path: 評価対象のパス。
  • 戻り値:
  • List *: GroupByOrdering 構造体のリスト。常に少なくともクエリ本来のパスキーと句を持つ要素を1つ含み、条件を満たす場合は再順序付けされた代替要素が追加される。

前提条件と不変条件

  • enable_group_by_reordering が無効であるか、または parse->groupingSets が存在する場合には、代替の順序付けを行わずにクエリ指定の順序のみを含むリストを直ちに返す。
  • アサート有効時（USE_ASSERT_CHECKING）において、追加されたすべての代替 GroupByOrdering 構造体は、最初の要素と比較して句（clauses）とパスキー（pathkeys）の要素数が一致し、要素の差分がなく、かつ各パスキーの等価クラスが対応するソートグループ句の参照と一致している必要がある。

アルゴリズムまたは振る舞い

1. 初期処理として、root->group_pathkeys と root->processed_groupClause を保持する最初の GroupByOrdering ノードを作成し、結果リスト infos に格納する。 2. enable_group_by_reordering が偽である場合、またはクエリに groupingSets が存在する場合は、そのまま infos を返して終了する。 3. 対象の path が独自のパスキーを持ち、かつそのパスキーが root->group_pathkeys に含まれていない場合、group_keys_reorder_by_pathkeys を呼び出してグループキーの再順序付けを試行する。 4. 再順序付けによって得られた一致数 n が 0 より大きく、かつ（インクリメンタルソートが有効であるか、あるいは n がグループ化パスキーの総数 root->num_groupby_pathkeys に等しい）かつ、新しいパスキーと元の root->group_pathkeys が PATHKEYS_EQUAL でない場合に、新しい GroupByOrdering ノードを生成して infos リストに追加する。 5. アサート有効時には、2番目以降の要素について最初の要素との整合性（要素数、差分の不在、等価クラスとソートグループ句の対応）を検証する。 6. 最終的な infos リストを返す。
