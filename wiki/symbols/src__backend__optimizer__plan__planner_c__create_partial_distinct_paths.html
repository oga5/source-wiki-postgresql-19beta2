目的

入力リレーションの並列パスをベースにして、並列ワーカーごとに重複排除を行うための部分パス（partial paths）を構築する。

シグネチャまたは形状

  • シグネチャ: static void create_partial_distinct_paths(PlannerInfo *root, RelOptInfo *input_rel, RelOptInfo *final_distinct_rel, PathTarget *target)

入力と出力

  • 引数:
  • PlannerInfo *root: クエリ全体のプランニング情報を保持する構造体ポインタ
  • RelOptInfo *input_rel: 処理対象となる入力リレーション
  • RelOptInfo *final_distinct_rel: 最終的な重複排除リレーション
  • PathTarget *target: パスがターゲットとする式リストや出力仕様
  • 戻り値: なし (void)

前提条件と不変条件

  • 入力リレーションが並列考慮フラグ（consider_parallel）を持たない場合、または並列パスリスト（partial_pathlist）が空である場合は何も処理を行わずに早期リターンする。
  • パラレル DISTINCT ON クエリには対応していないため、parse->hasDistinctOn が真の場合は処理を行わずにリターンする。

アルゴリズムまたは振る舞い

1. 初期チェックとリレーション設定:

  • input_rel の並列有効性とパスリストの有無を検証する。また parse->hasDistinctOn をチェックする。
  • UPPERREL_PARTIAL_DISTINCT のアッパレル（UpperRel）を取得し、ターゲットや並列フラグ、および input_rel に由来する FDW 関連情報を設定する。

    • 2. DISTINCT 式と行数見積もり:

  • get_sortgrouplist_exprs を用いて処理対象の DISTINCT 式リストを抽出し、最安ワーカーパスの行数を基準に各ワーカーでの重複排除後の行数を estimate_num_groups で見積もる。

    • 3. ソートベースの重複排除パスの生成:

  • グループ化キーがソート可能な場合、input_rel の各並列パスに対して有用なパスキーを求め、make_ordered_path を呼び出して順序付きパスを生成する。
  • root->distinct_pathkeys が空（すべてのタプルが同一値を持つ場合）である場合は、各ワーカーのタプル数を 1 に制限するための LimitPath を作成し、add_partial_path で追加する。
  • それ以外の場合は、create_unique_path を用いて一意性パスを生成し、add_partial_path で追加する。

    • 4. ハッシュ集約ベースの重複排除パスの生成:

  • ハッシュ集約が有効かつハッシュ化可能な場合、create_agg_path を用いてハッシュベースの集約パスを生成し、部分パスとして追加する。

    • 5. 外部データラッパー（FDW）および拡張フックの適用:

  • 担当 FDW が GetForeignUpperPaths ルーチンを提供している場合にそれを呼び出す。
  • 拡張用フック create_upper_paths_hook が設定されている場合はこれを呼び出す。

    • 6. Gatherパスの生成と最終パス構築:

  • 部分パスリストが空でない場合、generate_useful_gather_paths で Gather パスを生成し、set_cheapest で最安パスを選定する。
  • 平行ワーカーからの結合結果に含まれる重複を最終的に取り除くための最終 distinct パス作成関数 create_final_distinct_paths を呼び出す。

失敗モードと境界条件

  • input_rel->consider_parallel が偽である場合や input_rel->partial_pathlist が NIL の場合は、処理を行わずに終了する。
  • クエリが DISTINCT ON を使用している場合（parse->hasDistinctOn が真）、並列 DISTINCT を実行できないため何もせずに終了する。
