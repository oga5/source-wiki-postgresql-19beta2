目的

クエリ内の全アクセスパスを探索・生成し、すべてのベースリレーションと外部結合リレーションを結合した単一の RelOptInfo を構築して返す。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報を保持する構造体。
  • List *joinlist: 結合すべきリレーションや条件のリスト。
  • 戻り値:
  • RelOptInfo *: クエリ全体の結合ツリーを表す最終的なリレーション情報。

前提条件と不変条件

  • 返却される RelOptInfo のリレーション識別子集合（relids）は、クエリ内の全ベースリレーションおよび外部結合リレーション (root->all_query_rels) と完全に一致する必要がある。

アルゴリズムまたは振る舞い

1. set_base_rel_consider_startup を呼び出し、各ベースリレーションに対して高速起動プランを考慮するかどうかのマーク付けを行う。 2. set_base_rel_sizes を呼び出し、各ベースリレーションのサイズ見積もりと並列フラグ（consider_parallel）を計算する。 3. setup_simple_grouped_rels を呼び出し、可能な場合はシンプルリレーション向けにグループ化リレーションを構築する。 4. ループ処理により、root->simple_rel_array 内の各ベースリレーションを走査する。スロットが空（NULL）の場合やダミーリレーション（IS_DUMMY_REL）はスキップし、シンプルリレーション（IS_SIMPLE_REL）のページ数を合計して root->total_table_pages に設定する。 5. set_base_rel_pathlists を呼び出し、各ベースリレーションのアクセスパスを生成する。 6. make_rel_from_joinlist を呼び出し、結合ツリー全体全体のアクセスパスを生成して結合リレーションを取得する。 7. 取得した結合リレーションの relids が root->all_query_rels と一致することをアサートで検証したあと、リレーションを返す。

失敗モードと境界条件

  • 配列スロットが NULL である非ベースリレーションの RTE や、ダミーリレーション（IS_DUMMY_REL）はページ数の合計計算から除外される。
  • 最終的なリレーションの relids がクエリの全ベースリレーション集合と一致しない場合、アサート違反により処理が失敗する。
