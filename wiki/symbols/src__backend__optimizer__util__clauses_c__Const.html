目的

Const は、PostgreSQLのオプティマイザにおいて定数値を表現するためのノードである。clauses.c における定数畳み込み（Constant Folding）や式変形の処理において、評価された式の結果や、バインドされたパラメータの置換結果を格納する先として生成・利用される。

入力と出力

  • 入力: 式評価器による評価対象の式、または ParamListInfo から取得されるパラメータ値。
  • 出力: 評価または置換の結果として生成される、具体的なデータ型と値（Datum）を保持する Const ノード。

前提条件と不変条件

  • eval_const_expressions や estimate_expression_value などの式単純化処理の過程で、引数がすべて定数である関数や演算子、あるいは解決可能なパラメータが存在する場合に、それらが Const ノードへと変換される。

アルゴリズムまたは振る舞い

定数畳み込みの制御フローにおいて、eval_const_expressions_mutator が式ツリーを再帰的に走査する。この走査中に、Param ノードは boundParams から値が取得可能であれば Const ノードに置換される。また、FuncExpr や OpExpr などの関数・演算子ノードは、そのすべての引数が Const ノードである場合、evaluate_expr を介して事前評価され、最終的に単一の Const ノードへと単純化される。

関連データ構造

  • eval_const_expressions_context: 定数畳み込みの再帰処理中に、バインドされたパラメータ (boundParams) やプランナ情報 (root)、評価モード（estimate）などの文脈情報を保持する構造体。
  • ParamListInfo: Const への置換対象となるパラメータのバインド情報を格納する。

失敗モードと境界条件

  • 定数畳み込みの過程で、非厳格（Non-strict）な関数や、実行時まで値が確定しない揮発性（Volatile）関数が含まれる場合、それらは安全に Const ノードへ畳み込むことができず、元の式ツリーのまま残される。
