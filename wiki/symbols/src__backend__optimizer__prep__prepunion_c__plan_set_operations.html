目的

集合演算（UNION、INTERSECT、EXCEPT）クエリのトップレベルのパス生成とプランニングを統括し、結果の RelOptInfo と処理済みターゲットリストを返す。

シグネチャまたは形状

  • シグネチャ: RelOptInfo * plan_set_operations(PlannerInfo *root)

入力と出力

  • 入力:
  • root: プランナ全体の情報を保持する PlannerInfo *
  • 出力:
  • 戻り値: 集合演算の計画済みリレーションを表す RelOptInfo *
  • 副作用として root->processed_tlist に最上位のターゲットリストが格納される

前提条件と不変条件

  • 最上位の集合演算ノード（topop）が存在しなければならない。
  • クエリの jointree->fromlist は空であり、quals、groupClause、havingQual、windowClause、distinctClause はすべて未設定（NIL または NULL）である。
  • 外部クエリレベルの等価クラス（eq_classes）は空であり、マージ処理の完了フラグ（root->ec_merging_done）が true に設定される。

アルゴリズムまたは振る舞い

1. 初期検証と前提条件の確認: パースツリーから SetOperationStmt を取得し、アサーションによってサポート対象外の節が含まれていないことを検証する。 2. 等価クラスとリレーション配列の準備: 等価クラスのマージ完了を設定した上で、リーフサブクエリ用の RelOptInfo を構築するために setup_simple_rel_arrays を呼び出す。 3. 左端クエリの特定: 集合演算ツリーの左端（larg）をたどって最左のコンポーネントクエリ（RangeTblRef）を見つけ、対応する leftmostQuery のターゲットリストを抽出する。 4. パス生成の分岐:

  • 再帰的クエリ（root->hasRecursion が真）の場合は、generate_recursion_path を呼び出して再帰的 UNION パスを生成する。
  • それ以外の場合は、recurse_set_operations を再帰的に呼び出して通常の集合演算パスを生成する。

    • 5. 結果の格納と返却: 生成されたトップレベルのターゲットリストを root->processed_tlist に設定し、構築された RelOptInfo を返す。

失敗モードと境界条件

  • topop が存在しない場合や、前提条件の各節（fromlist、quals、groupClause、havingQual、windowClause、distinctClause）のいずれかが空・NULLでない場合はアサーション違反により失敗する。
  • 左端のノードが RangeTblRef でない場合や、左端クエリ（leftmostQuery）が NULL の場合はアサーションによって検出される。
