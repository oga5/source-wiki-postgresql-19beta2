~~~c Plan * create_plan(PlannerInfo *root, Path *best_path) { Plan *plan;

/* plan_params should not be in use in current query level */ Assert(root->plan_params == NIL);

/* Initialize this module's workspace in PlannerInfo */ root->curOuterRels = NULL; root->curOuterParams = NIL;

/* Recursively process the path tree, demanding the correct tlist result */ plan = create_plan_recurse(root, best_path, CP_EXACT_TLIST);

/*

  • Make sure the topmost plan node's targetlist exposes the original
  • column names and other decorative info. Targetlists generated within
  • the planner don't bother with that stuff, but we must have it on the
  • top-level tlist seen at execution time. However, ModifyTable plan
  • nodes don't have a tlist matching the querytree targetlist.

    • */ if (!IsA(plan, ModifyTable)) apply_tlist_labeling(plan->targetlist, root->processed_tlist);

/*

  • Attach any initPlans created in this query level to the topmost plan
  • node. (In principle the initplans could go in any plan node at or
  • above where they're referenced, but there seems no reason to put them
  • any lower than the topmost node for the query level. Also, see
  • comments for SS_finalize_plan before you try to change this.)

    • */ SS_attach_initplans(root, plan);

/* Check we successfully assigned all NestLoopParams to plan nodes */ if (root->curOuterParams != NIL) elog(ERROR, "failed to assign all NestLoopParams to plan nodes");

/*

  • Reset plan_params to ensure param IDs used for nestloop params are not
  • re-used later

    • */ root->plan_params = NIL;

return plan; } ~~~

目的

オプティマイザが選択した最適なアクセスパスツリー（Path）を実行エンジンが処理可能な実行計画ツリー（Plan）へ変換する、プランニングフェーズのメインエントリポイントとして機能する。

シグネチャまたは形状

  • Plan * create_plan(PlannerInfo *root, Path *best_path)

入力と出力

  • 引数:
  • PlannerInfo *root: クエリ全体のプランニング情報を保持する構造体ポインタ
  • Path *best_path: 最も低コストと判定された最適なアクセスパスツリーの根ノード
  • 戻り値:
  • Plan *: 構築された最上位の実行計画ノード

前提条件と不変条件

  • 現在のクエリレベルにおいて、root->plan_params は NIL でなければならない。

アルゴリズムまたは振る舞い

1. root->plan_params が NIL であることを Assert で検証する。 2. モジュールのワークスペースとして root->curOuterRels を NULL に、root->curOuterParams を NIL に初期化する。 3. CP_EXACT_TLIST フラグを指定して create_plan_recurse を呼び出し、パスツリーを再帰的に処理して Plan ツリーを生成する。 4. 生成されたプランが ModifyTable ノードではない場合、apply_tlist_labeling を呼び出して最上位プランノードのターゲットリストに元の列名などの装飾情報を適用する。 5. SS_attach_initplans を呼び出し、このクエリレベルで作成された initPlan を最上位プランノードにアタッチする。 6. すべての NestLoopParam がプランノードに正常に割り当てられたか確認するため、root->curOuterParams が NIL であることを検査する。 7. 後続処理でのパラメータ ID の再利用を防ぐため、root->plan_params を NIL にリセットする。 8. 構築した最上位の Plan ノードを返す。

失敗モードと境界条件

  • root->curOuterParams が NIL でない（一部の NestLoopParam の割り当てに失敗した）場合、ERROR レベルの elog が発生し処理が中断される。
