目的

パーサーから渡された解析済みの Query ツリーを入力として受けて大域的状態の初期化、並列実行可能性の評価、パス生成戦略のマスク設定、サブクエリの計画化、物理計画への変換および最終的な参照解決を調整し、実行用の PlannedStmt を構築するオプティマイザの標準的なエントリポイントです。

入力と出力

  • 引数:
  • Query *parse: 最適化対象の解析済みクエリツリー（インプレースで変更される）
  • const char *query_string: 元のSQL文字列
  • int cursorOptions: カーソルのオプションフラグ（CURSOR_OPT_PARALLEL_OK, CURSOR_OPT_FAST_PLAN, CURSOR_OPT_SCROLL 等）
  • ParamListInfo boundParams: 外部からバインドされたパラメータ情報
  • ExplainState *es: EXPLAIN出力用の状態構造体
  • 戻り値:
  • PlannedStmt *: 構築された実行計画構造体

前提条件と不変条件

  • Query ツリーはインプレースで書き換えられるため、同一のツリーを複数回計画する場合は事前にコピーが必要とされる。
  • 並列ワーカーの内部やデータ変更を伴うコマンド、カーソル操作など、条件を満たさない場合は並列モードの評価が安全側に倒されて無効化される。

アルゴリズムまたは振る舞い

1. **大域的状態の初期化**: PlannerGlobal ノードを生成し、boundParams や各種リスト、カウンタ類を初期化する。 2. **並列モードの評価**: クエリの並列実行可能性（max_parallel_hazard）をスキャンし、parallelModeOK と parallelModeNeeded を決定する。 3. **タプル分画率の決定**: cursorOptions の CURSOR_OPT_FAST_PLAN フラグの有無に応じて、cursor_tuple_fraction をもとに最適化対象となるタプル割合 tuple_fraction を算出する。 4. **パス生成戦略マスクの構築**: 有効な GUC パラメータ設定に基づき、利用可能なスキャン・結合方式を表す glob->default_pgs_mask をビット演算で組み立てる。 5. **プラグインフックの呼び出し**: planner_setup_hook が存在する場合はこれを呼び出す。 6. **サブクエリおよび本体の計画生成**: subquery_planner を呼び出して、クエリ全体のプライマリ計画ツリーに対応する PlannerInfo ルート構造体を取得する。 7. **最安パスの選択と物理計画への変換**: UPPERREL_FINAL から最安のフラクショナルパスを取得し、create_plan により物理計画（Plan）へ変換する。 8. **スクロールカーソル対応**: CURSOR_OPT_SCROLL が指定されており逆方向スキャンをサポートしない場合は、トップに Material ノードを付加する。 9. **デバッグ用 Gather ノードの挿入**: debug_parallel_query が有効かつ並列安全な場合には、テスト用に Gather ノードを最上位に挿入し、必要に応じて initPlan の移替やコスト調整を行う。 10. **パラメータ集合の確定**: paramExecTypes が存在する場合は、サブプランおよびメインプランに対して SS_finalize_plan を実行して各プランノードのパラメータ集合を計算する。 11. **最終参照解決**: set_plan_references を呼び出してプランツリー全体の変数参照やプレースホルダ等の最終的な解決を行う。

失敗モードと境界条件

  • スタンドアロンバックエンド環境、データ変更を伴うコマンド、カーソル操作、非許可の GUC 設定、またはクエリツリー内に並列安全でない関数が含まれている場合、並列モードの利用は見送られ無効とされる。

保守担当者向けメモ

  • プラグイン作者向けに、本関数は渡された Query ツリーを直接書き換える仕様になっている点に注意が必要である。
