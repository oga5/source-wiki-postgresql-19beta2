目的

指定されたリレーション（RelOptInfo）のパスリストを走査し、起動コスト・トータルコストが最小のパス、およびパラメータ化された最適なパスを選出して、親リレーションの対応するフィールドに設定する。

入力と出力

  • 引数: RelOptInfo *parent_rel（処理対象のリレーション情報）
  • 戻り値: なし（void）

前提条件と不変条件

  • parent_rel は有効な RelOptInfo ノードでなければならない。
  • parent_rel->pathlist が空（NIL）である場合、クエリプランを構築できなかったとしてエラーが発生する。
  • 処理完了時、無パラメータの最安値トータルパスが存在するか、または最小パラメータ化された最良のパラメータ化パスが存在し、cheapest_total_path は必ず非 NULL になる。

アルゴリズムまたは振る舞い

1. **初期検証と初期化**:

  • parent_rel が RelOptInfo であることをアサートで確認し、pathlist が空であれば ERROR レベルのログを出力して終了する。
  • cheapest_startup_path、cheapest_total_path、best_param_path を NULL に、parameterized_paths を NIL に初期化する。

    • 2. **パスリストの走査**:

  • parent_rel->pathlist 内の各 Path ノードについて以下を繰り返す。
  • **パラメータ付きパスの場合 (path->param_info が存在)**:
  • parameterized_paths に当該パスを追加する。
  • 既に非パラメータ化の cheapest_total_path が確定している場合は、最適パラメータ化パスの追跡をスキップする。
  • best_param_path が未設定の場合は現在のパスを代入する。設定済みの場合は bms_subset_compare を用いて要求外部リレーションの包含関係を比較する：
  • BMS_EQUAL: 等しい場合はトータルコストがより低い方を維持する。
  • BMS_SUBSET1: 新規パスの方がパラメータ化の程度が少ない（部分集合）ため、best_param_path を更新する。
  • BMS_SUBSET2: 既存パスの方がパラメータ化が少ないため維持する。
  • BMS_DIFFERENT: 比較不能な場合は既存の best_param_path を維持する。
  • **非パラメータ化パスの場合**:
  • cheapest_total_path が未設定の場合、cheapest_startup_path と cheapest_total_path の両方に現在のパスを設定して次へ進む。
  • 既存の cheapest_startup_path とコスト・パスキーを比較し、より起動コストが低いか、コストが同等でソート順序（パスキー）が優れている場合に更新する。
  • 既存の cheapest_total_path についても同様にコストおよびパスキーを比較し、より優れている場合に更新する。

    • 3. **結果の確定と設定**:

  • 非パラメータ化の最安値トータルパスが存在する場合、それを parameterized_paths の先頭に結合する。
  • 非パラメータ化パスが存在しない場合は、best_param_path を cheapest_total_path として採用する（起動パスには採用しない）。
  • cheapest_total_path が非 NULL であることをアサートで確認する。
  • 最終的に得られた cheapest_startup_path、cheapest_total_path、および parameterized_paths を parent_rel の各フィールドへ格納する。

失敗モードと境界条件

  • parent_rel->pathlist が空である場合、クエリプランを構築できないとして ERROR がスローされる。
  • 有効な非パラメータ化パスが一切存在しない場合、cheapest_startup_path には NULL が設定され、cheapest_total_path には最適なパラメータ化パス（best_param_path）がフォールバックとして割り当てられる。
