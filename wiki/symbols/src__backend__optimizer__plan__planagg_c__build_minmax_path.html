目的

現在のクエリレベルの状態をクローンして改変することにより仮想的なサブクエリ（SELECT col FROM tab WHERE col IS NOT NULL ... ORDER BY col ... LIMIT 1）を構築し、インデックススキャンなどのプレソート済みパスを評価して、MIN/MAX 集約の最適化パスを生成する。

入力と出力

  • 引数:
  • PlannerInfo *root: 現在のクエリのプランナー情報
  • MinMaxAggInfo *mminfo: 対象の最小値・最大値集約情報
  • Oid eqop: 等価演算子 OID
  • Oid sortop: ソート演算子 OID
  • bool reverse_sort: 逆順ソートを行うかどうか
  • bool nulls_first: NULL を最初に配置するかどうか
  • 戻り値: bool - 最適なプレソートパスの取得と構築に成功した場合は true、失敗した場合は false を返す

前提条件と不変条件

  • サブクエリ生成時には結合情報リスト、同値クラス、プレースホルダー情報が未作成であること（アサーションで検証される）。
  • ターゲット式が行型ではないことが事前に保証されていること。

アルゴリズムまたは振る舞い

1. **サブクエリ用 PlannerInfo の初期化とクローン**:

  • 現在の root をメモリ領域にコピーして subroot を新しく割り当て、クエリレベルをインクリメントし、親ルートを設定する。
  • サブプラン関連のパラメータや集約情報フィールドをリセットする。
  • パースツリーおよびappendリレーションリストをコピーし、変数レベルの相対位置を IncrementVarSublevelsUp により 1 つ上のレベルへ調整する。

    • 2. **ターゲットリストと修飾句の変更**:

  • 集約対象式を唯一のエントリとして持つターゲットリストを作成し、subroot->processed_tlist およびパースツリーの targetList に設定する。
  • HAVING 句、DISTINCT 句、集約フラグをクリアする。
  • IS NOT NULL テストノードを構築し、既存の WHERE 句に含まれていない場合は結合ツリーの条件に前置する。

    • 3. **ソート句と LIMIT 1 の設定**:

  • ソートグループ句を作成し、指定された等価演算子・ソート演算子・フラグを設定したうえでパースツリーの sortClause に格納する。
  • LIMIT 1 (limitOffset = NULL, limitCount = 1) を設定する。

    • 4. **クエリプランの探索と調整**:

  • subroot のタプル分数と制限タプル数を 1.0 に設定し、query_planner を呼び出して final_rel を取得する。
  • 外部パラメータの特定（SS_identify_outer_params）および初期プランのコスト課金（SS_charge_for_initplans）を実行する。

    • 5. **パスの選択と確定**:

  • 取得したリレーションの行数に基づいて分数パスの割合を計算し、get_cheapest_fractional_path_for_pathkeys を使って最安のプレソート済みパス (sorted_path) を取得する。パスが存在しない場合は false を返す。
  • パスに対して射影適用（apply_projection_to_path）を行い、最初の行を取得するためのコスト（path_cost）を算出する。
  • 結果を mminfo（subroot, path, pathcost）に保存し、true を返す。

失敗モードと境界条件

  • get_cheapest_fractional_path_for_pathkeys が有効なプレソート済みパスを見つけられなかった場合、関数は早期に false を返す。

保守担当者向けメモ

  • 本関数はサブクエリプランナーを通さずに query_planner を直接操作するため、パラメータや初期プランに関するクリーンアップ処理を手動で補完している。
