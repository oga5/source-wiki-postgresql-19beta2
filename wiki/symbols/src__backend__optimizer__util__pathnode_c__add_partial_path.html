目的

親リレーション（RelOptInfo）の並列部分パスリスト（partial_pathlist）に対し、新規の並列部分パス（Path）を評価して追加または拒否・破棄する。

シグネチャまたは形状

  • シグネチャ: void add_partial_path(RelOptInfo *parent_rel, Path *new_path)

入力と出力

  • 引数:
  • RelOptInfo *parent_rel: 部分パスを追加する対象のリレーション情報
  • Path *new_path: 追加を試みる新規の並列部分パス
  • 戻り値: なし (void)

前提条件と不変条件

  • 追加される new_path は並列安全（parallel_safe が真）でなければならない。
  • 親リレーション parent_rel は並列処理を考慮可能（consider_parallel が真）でなければならない。

アルゴリズムまたは振る舞い

1. **前提チェックと割り込み確認**:

  • クエリの中断要求を確認する。
  • new_path->parallel_safe および parent_rel->consider_parallel のアサーションを満たしていることを検証する。

    • 2. **既存部分パスとの比較走査**:

  • parent_rel->partial_pathlist 内の既存パス（old_path）を順に走査し、パスキー（compare_pathkeys）およびファジィコスト比較（compare_path_costs_fuzzily）を実施する。
  • 新規パスが既存パスを支配（優越）している場合は、既存パスをリストから削除してメモリを解放（pfree）する。
  • 逆に既存パスが新規パスを支配している場合は、新規パスの受け入れフラグ（accept_new）を偽にして走査を中断する。
  • どちらでもない場合、無効化されたノード数（disabled_nodes）やトータルコストに基づいて新規パスの挿入位置（insert_at）を更新する。

    • 3. **リストへの反映または破棄**:

  • accept_new が真のままであれば、決定された位置に new_path を挿入する。
  • 拒否された場合は、new_path を破棄・メモリ解放（pfree）する。

失敗モードと境界条件

  • 既存パスによって支配された new_path は、リストに追加されず pfree によってメモリが回収される。
  • 新規パスによって支配された古いパスは、partial_pathlist から削除され pfree によってメモリが回収される。
