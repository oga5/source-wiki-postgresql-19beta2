目的

新規に構築しようとするパスが、リレーションの既存のパスリスト内に存在するどのパスからも完全に支配（ドミネート）され、早期に棄却可能であるかどうかを事前に判定する。

入力と出力

  • 引数:
  • RelOptInfo *parent_rel: 評価対象の親リレーション情報
  • int disabled_nodes: 無効化されたノード数
  • Cost startup_cost: 新規パスの起動コスト
  • Cost total_cost: 新規パスのトータルコスト
  • List *pathkeys: 新規パスのパスキーリスト
  • Relids required_outer: パスに必要な外部リレーション群
  • 戻り値:
  • bool: 新規パスの追加を検討すべき（保持すべき）場合は true、既存パスに支配されるため棄却してよい場合は false を返す

前提条件と不変条件

  • パラメータ化されたパス（required_outer が空でない場合）は、add_path のポリシーと同様に、パスキーを持たない（NIL として扱う）ものとして評価される。
  • 起動コストを考慮するかどうかは、パラメータ化パスの有無に応じて parent_rel->consider_param_startup または parent_rel->consider_startup から決定される。
  • 親リレーションの pathlist は、disabled_nodes の昇順、および同数の場合は total_cost の昇順にソートされている前提で走査される。

アルゴリズムまたは振る舞い

1. **初期化**:

  • required_outer が存在する場合は new_path_pathkeys を NIL に設定し、存在しない場合は引数の pathkeys をそのまま使用する。
  • required_outer の有無に応じて consider_startup フラグを parent_rel->consider_param_startup または parent_rel->consider_startup から取得する。

    • 2. **既存パスリストの走査**:

  • parent_rel->pathlist 内の各既存パス（old_path）を順番に検査する。

    • 3. **早期停止判定**:

  • old_path->disabled_nodes が引数の disabled_nodes と異なる場合で、新規パス側の disabled_nodes が既存パス側より小さいならば、以降のパスは条件を満たさないためループを抜ける（break）。
  • disabled_nodes が一致し、かつ新規パスの total_cost が old_path->total_cost * STD_FUZZ_FACTOR 以下である場合も、ソート順序の性質上それ以降のパスは新規パスを優越しないためループを抜ける。

    • 4. **コストおよびパスキーによる支配関係の評価**:

  • 新規パスの起動コストが old_path->startup_cost * STD_FUZZ_FACTOR より大きい、または consider_startup が偽である場合、新規パスは起動コストの面で優位に立てないため、次にパスキーの比較を行う。
  • old_path のパラメータ情報（param_info）の有無に基づき old_path_pathkeys を決定し、compare_pathkeys を用いて new_path_pathkeys と比較する。
  • パスキー比較の結果が PATHKEYS_EQUAL または PATHKEYS_BETTER2 であり、さらに required_outer と PATH_REQ_OUTER(old_path) が bms_equal により一致する場合、既存パスが新規パスを支配していると判定し false を返す。

    • 5. **完了**:

  • ループ内で支配する既存パスが見つからなかった場合は true を返す。

失敗モードと境界条件

  • 該当する有効な既存パスによって完全に支配されている（コストが同等以上であり、かつパスキーとパラメータ要件が一致または劣後する）場合は、新規パス構築を回避するために false が返される。
