目的

検証済みのチェック制約、NOT NULL 制約、およびパーティション制約を収集し、プランナ用に正規化したリストを返す。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報を格納する構造体ポインタ
  • Oid relationObjectId: 対象リレーションの OID
  • RelOptInfo *rel: 対象リレーションのプランナ用最適化情報構造体ポインタ
  • bool include_noinherit: NO INHERIT 付きチェック制約を含めるかどうかのフラグ
  • bool include_notnull: NOT NULL 制約を含めるかどうかのフラグ
  • bool include_partition: パーティション制約を含めるかどうかのフラグ
  • 戻り値:
  • List *: 正規化・展開された制約式（Expr または Node）のリスト

前提条件と不変条件

  • 対象リレーションは事前に安全にロックされているものと仮定する。
  • 完全に検証されていないチェック制約（ccvalid が偽のもの）は無視される。
  • 強制されていない（NOT ENFORCED）制約は無効としてマークされており、無視される（アサートでチェックされる）。

アルゴリズムまたは振る舞い

1. **リレーションのオープン**: table_open(relationObjectId, NoLock) を呼び出して対象リレーションの Relation 構造体を取得する。 2. **チェック制約の収集と正規化**:

  • リレーションのタプル制約（constr）が存在する場合、各チェック制約を順に走査する。
  • ccvalid が偽の制約や、ccnoinherit が真かつ include_noinherit が偽の制約はスキップする。
  • 制約式のツリーを stringToNode で文字列からノード表現に変換する。
  • varno が 1 でない場合、ChangeVarNodes を用いて式内の変数の varno を指定された rel->relid に置き換える（これは定数畳み込みの前に実行する必要がある）。
  • eval_const_expressions による定数畳み込みと、canonicalize_qual による正規化を適用する。
  • make_ands_implicit でインプリシット AND 形式のリストに変換し、結果リストに結合する。

    • 3. **NOT NULL 制約の追加**:

  • include_notnull が真かつリレーションに NOT NULL 制約が存在する場合、各属性を走査する。
  • 属性のナル可能性が有効（ATTNULLABLE_VALID）かつ破棄されていない場合、対応する NullTest 式（IS NOT NULL）を作成して結果リストに追加する。

    • 4. **パーティション制約の追加**:

  • include_partition が真かつリレーションがパーティションテーブル（relispartition）である場合、set_baserel_partition_constraint を呼び出してパーティション制約をセットアップし、結果リストに結合する。

    • 5. **生成列の展開**:

  • 結果リストが存在する場合、expand_generated_columns_in_expr を呼び出して制約式内の仮想生成列を展開する。

    • 6. **リレーションのクローズと返却**:

  • table_close(relation, NoLock) を呼び出してリレーションを閉じ、構築した制約リストを返す。
