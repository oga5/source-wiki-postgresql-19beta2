目的

入力リレーションの並列パスを元にして、一意性（ユニーク）制約やグループ化を満たす並列パスを構築する。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体の情報
  • RelOptInfo *input_rel: 入力リレーション
  • List *sortPathkeys: ソート用パスキーのリスト
  • List *groupClause: グループ化句のリスト
  • SpecialJoinInfo *sjinfo: 特殊結合情報
  • RelOptInfo *unique_rel: 一意化対象のリレーション
  • 戻り値: なし (void)

前提条件と不変条件

  • 入力リレーションが並列考慮 (consider_parallel) を有効にしており、かつ並列パスリスト (partial_pathlist) が空でないこと。
  • 一意化リレーションのターゲットリストに含まれる式がすべて並列セーフ (is_parallel_safe) であること。

アルゴリズムまたは振る舞い

1. 早期リターン判定: 入力リレーションが並列考慮対象外である場合、並列パスが存在しない場合、またはターゲットリストに並列制限（parallel-restricted）された式が含まれている場合は何もせずに終了する。 2. 部分一意リレーション (partial_unique_rel) の初期化:

  • input_rel の構造をコピーして新たな RelOptInfo ノードを作成する。
  • パス関連フィールド（pathlist, ppilist, partial_pathlist, cheapest系パス群）をクリアする。
  • estimate_num_groups を用いて出力行数を見積もり、ターゲットを unique_rel->reltarget に設定する。

    • 3. ソートベースの実装の検討 (sjinfo->semi_can_btree):

  • 入力リレーションの各並列パスを走査し、ソート済みか、最安の並列パスか、あるいはプレソート済みキーを持つかを判定する。
  • 必要に応じて射影パス (create_projection_path) を作成した上で、未ソートの場合はソートパス (create_sort_path) またはインクリメンタルソートパス (create_incremental_sort_path) を適用する。
  • create_unique_path を適用して一意化し、add_partial_path で部分パスとして追加する。

    • 4. ハッシュベースの実装の検討 (sjinfo->semi_can_hash):

  • 最安の並列部分パスに対して射影パスと集約パス (create_agg_path の AGG_HASHED) を作成し、部分パスとして追加する。

    • 5. 最終処理:

  • 部分パスリストが空でなければ、有用なギャザーパスの生成 (generate_useful_gather_paths) と最安パスの設定 (set_cheapest) を行い、さらに並列ワーカー間での重複行を除去するための最終一意パス生成 (create_final_unique_paths) を呼び出す。

失敗モードと境界条件

  • 入力リレーションに並列パスが存在しない場合や、ターゲットリストが並列非安全な式を含む場合は、パスを生成せず直ちに処理を中断する。
  • Bツリーベースまたはハッシュベースの半結合（semi-join）特性フラグ（semi_can_btree / sjinfo->semi_can_hash）が不成立の場合、それぞれのパス生成ロジックはスキップされる。
