目的

クエリプランナの構造体を走査し、継承関係を持つ範囲テーブルエントリ（RTE）に対応する子関係（その他の関係／otherrels）を展開・追加する。

シグネチャまたは形状

  • シグネチャ: void add_other_rels_to_query(PlannerInfo *root)

入力と出力

  • 引数: PlannerInfo *root: プランナ全体の状態と範囲テーブルを保持するデータ構造
  • 戻り値: なし（void）

前提条件と不変条件

  • root->simple_rel_array および root->simple_rte_array が正しく初期化されていること。
  • インデックス rti は 1 から root->simple_rel_array_size - 1 まで走査される。

アルゴリズムまたは振る舞い

  • root->simple_rel_array をインデックス 1 から最後まで走査する。
  • 各インデックス rti に対して RelOptInfo と RangeTblEntry を取得する。
  • 以下の条件に合致する場合は処理をスキップする:
  • rel が NULL である場合（ベース関係以外のRTEに対応する空スロット）。
  • rel->reloptkind が RELOPT_BASEREL 以外である場合（既に追加済みの otherrel を無視する）。
  • rte->inh が真（継承可能としてマークされている）である場合、expand_inherited_rtentry を呼び出して子関係を展開する。

関連データ構造

  • PlannerInfo: プラン生成全体の状態や単純リレーション配列を保持する。
  • RelOptInfo: リレーションの最適化情報を表す。
  • RangeTblEntry: 範囲テーブルのエントリを表し、継承フラグ（inh）を持つ。

失敗モードと境界条件

  • rel == NULL のスロットや、すでに RELOPT_BASEREL 以外に設定されているスロットは安全にスキップされる。
