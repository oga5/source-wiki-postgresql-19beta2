目的

関数呼び出しのインライン展開を試み、条件を満たす場合にSQL関数本体の式に置き換える。

入力と出力

  • 引数: Oid funcid, Oid result_type, Oid result_collid, Oid input_collid, List *args, bool funcvariadic, HeapTuple func_tuple, eval_const_expressions_context *context
  • 戻り値: Expr * （インライン展開された式、または展開できない場合は NULL）

前提条件と不変条件

  • 対象関数はSQL言語による通常関数（prolang == SQLlanguageId, prokind == PROKIND_FUNCTION）であり、セキュリティ定義関数、集合返却関数、レコード型返却関数、プロパティ設定を持つ関数、引数数不一致の関数ではないこと。
  • 再帰的関数呼び出しではないこと、および呼び出し元ユーザーが実行権限を持っていること。
  • 関数本体のクエリは単一の SELECT 式であり、集約、ウィンドウ関数、サブリンク、結合などを伴わない単純な構造であること。

アルゴリズムまたは振る舞い

1. 初期検証: 関数プロパティ (prolang, prokind, prosecdef, proretset, prorettype, proconfig, pronargs)、再帰呼び出し（active_fns 内の存在）、実行権限（object_aclcheck）、およびプラグインフックの有無をチェックし、条件を満たさない場合は NULL を返して終了する。 2. 一時コンテキストとエラー文脈の構築: 解析時のメモリリークを防ぐため一時的なメモリコンテキストを作成して切り替え、エラー発生時のトレース用コールバックを設定する。 3. 関数本体の取得と解析: prosqlbody が存在する場合はノードに復元し、存在しない場合は prosrc をパースおよび解析して単一の Query ツリー（select 文）を得る。 4. 構文制約の検証: 取得したクエリがアグリゲーション、ウィンドウ関数、サブリンク、結合、グループ化、ソート等を持たず、ターゲットリストの要素数が正確に1つであるかを検証する。 5. 型と戻り値の整合性チェック: get_expr_result_type および check_sql_fn_retval を用いて、関数宣言の戻り値型と返却式の結果型が一致することを確認する。 6. 揮発性と厳格性の検証: 関数のボラティリティ（PROVOLATILE_IMMUTABLE, PROVOLATILE_STABLE）と式の内包する関数特性、および proisstrict と非厳格関数の有無を検証する。 7. パラメータの置換と使用回数評価: substitute_actual_parameters を使って仮パラメータを実引数に置換し、各引数の使用回数（usecounts）を算出する。厳格性や高コスト・揮発性引数の複数回評価に関する追加制約を検証する。 8. クリーンアップと返却: 外側のメモリコンテキストへ戻り、変更された式をコピーして返し、作成した一時メモリコンテキストを削除する。

失敗モードと境界条件

  • 条件不一致（非SQL関数、セキュリティ定義、集合返却、再帰、権限不足、複雑なクエリ構造など）の場合はインライン化を放棄し NULL を返す。
  • パラメータが厳格な関数で未使用の場合、あるいは複数回使用される引数がサブプラン、高コスト（10オペレータ超）、または揮発性関数を含む場合は展開を失敗とする。

保守担当者向けメモ

  • 解析や変換処理で生成される一時的なメモリリークを防ぐため、専用のメモリコンテキスト（AllocSetContextCreate）を使用しており、成功時・失敗時のいずれの経路でも元のメモリコンテキストへの復帰とコンテキスト削除が行われる設計になっている。
