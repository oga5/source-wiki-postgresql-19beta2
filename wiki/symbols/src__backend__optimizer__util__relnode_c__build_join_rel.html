~~~c RelOptInfo * build_join_rel(PlannerInfo *root, Relids joinrelids, RelOptInfo *outer_rel, RelOptInfo *inner_rel, SpecialJoinInfo *sjinfo, List *pushed_down_joins, List **restrictlist_ptr) { RelOptInfo *joinrel; List *restrictlist;

/* This function should be used only for join between parents. */ Assert(!IS_OTHER_REL(outer_rel) && !IS_OTHER_REL(inner_rel));

/*

  • See if we already have a joinrel for this set of base rels.

    • */ joinrel = find_join_rel(root, joinrelids);

if (joinrel) { /*

  • Yes, so we only need to figure the restrictlist for this particular
  • pair of component relations.

    • */ if (restrictlist_ptr) *restrictlist_ptr = build_joinrel_restrictlist(root, joinrel, outer_rel, inner_rel, sjinfo); return joinrel; }

  • Nope, so make one.

    • */ joinrel = makeNode(RelOptInfo); joinrel->reloptkind = RELOPT_JOINREL; joinrel->relids = bms_copy(joinrelids); joinrel->rows = 0; /* cheap startup cost is interesting iff not all tuples to be retrieved */ joinrel->consider_startup = (root->tuple_fraction > 0); joinrel->consider_param_startup = false; joinrel->consider_parallel = false; joinrel->pgs_mask = root->glob->default_pgs_mask; joinrel->reltarget = create_empty_pathtarget(); joinrel->pathlist = NIL; joinrel->ppilist = NIL; joinrel->partial_pathlist = NIL; joinrel->cheapest_startup_path = NULL; joinrel->cheapest_total_path = NULL; joinrel->cheapest_parameterized_paths = NIL; /* init direct_lateral_relids from children; we'll finish it up below */ joinrel->direct_lateral_relids = bms_union(outer_rel->direct_lateral_relids, inner_rel->direct_lateral_relids); joinrel->lateral_relids = min_join_parameterization(root, joinrel->relids, outer_rel, inner_rel); ~~~

目的

親関係同士の結合に対する RelOptInfo ノードを検索、または新規作成し、制約リスト、ターゲットリスト、並列安全性、パーティション情報、およびサイズ見積もりを設定して返します。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナのグローバル情報およびコンテキスト
  • Relids joinrelids: 作成・検索対象の結合関係が持つベース関係IDの集合
  • RelOptInfo *outer_rel: 結合の外側関係
  • RelOptInfo *inner_rel: 結合の内側関係
  • SpecialJoinInfo *sjinfo: 特殊結合（外部結合など）のメタデータ
  • List *pushed_down_joins: プッシュダウンされた結合のリスト
  • List **restrictlist_ptr: 構成関係ペアに対する制約リストを受け取る出力ポインタ
  • 戻り値:
  • RelOptInfo *: 構築または取得された結合関係の RelOptInfo へのポインタ

前提条件と不変条件

  • outer_rel および inner_rel は、他の継承子リレーション（other rel）ではなく親関係である必要があります。

アルゴリズムまたは振る舞い

1. 前提条件の検証: !IS_OTHER_REL(outer_rel) && !IS_OTHER_REL(inner_rel) であることをアサートで検証します。 2. 既存結合関係の検索: find_join_rel を用いて、指定された joinrelids に一致する既存の結合関係が存在するか確認します。

  • 存在する場合: restrictlist_ptr が指定されていれば build_joinrel_restrictlist でこのペア特有の制約リストを計算して格納し、既存の結合関係を返します。

    • 3. 新規結合関係ノードの作成と初期化:

  • 存在しない場合、RelOptInfo ノードを新規作成し、reloptkind を RELOPT_JOINREL に設定し、relids をコピーします。
  • 起動コストの考慮有無、空のパスターゲット、各種パスリスト、およびラテラル関連のフィールド（direct_lateral_relids や lateral_relids）を初期化します。
  • その他の非ベース関係用フィールド（relid = 0、rtekind = RTE_JOIN など）を設定します。

    • 4. 外部関係プロパティとターゲット・プレースホルダの構築:

  • set_foreign_rel_properties を呼び出して外部関係に関する情報を計算します。
  • build_joinrel_tlist を外側関係と内側関係に対して呼び出し、結合から出力すべき変数やプレースホルダ変数（PHV）をターゲットリストに詰めます。
  • add_placeholders_to_joinrel を呼び出し、計算されたプレースホルダ変数の ph_lateral セットを direct_lateral_relids に反映させた後、bms_del_members で自身の relids を除外して direct_lateral_relids を確定させます。

    • 5. 制約と結合リスト、サイズ、並列性の評価:

  • build_joinrel_restrictlist により制限リストを構築し、必要に応じて restrictlist_ptr に格納します。
  • build_joinrel_joinlist で結合リストを構築し、has_relevant_eclass_joinclause で等価クラス結合句の有無を判定します。
  • set_joinrel_size_estimates によりサイズ見積もりを行います。
  • 内外関係が共に並列安全であり、かつ制約リストやターゲット式が並列安全である場合に、consider_parallel フラグを有効化します。

    • 6. フックとパーティション情報の適用:

  • joinrel_setup_hook が存在する場合はこれを呼び出してプロパティの編集を許可します。
  • build_joinrel_partition_info を呼び出してパーティション情報を格納します。

    • 7. プランナ管理構造への登録:

  • add_join_rel を呼び出して PlannerInfo に登録します。
  • 動的計画法による結合探索が有効な場合、root->join_rel_level の該当レベルのリストに新しい結合関係を追加します。

    • 8. 構築した joinrel を返します。

失敗モードと境界条件

  • outer_rel または inner_rel が他の継承子リレーションである場合、アサートにより異常終了します。
