~~~c int32 get_rel_data_width(Relation rel, int32 *attr_widths) { int64 tuple_width = 0; int i;

for (i = 1; i <= RelationGetNumberOfAttributes(rel); i++) { Form_pg_attribute att = TupleDescAttr(rel->rd_att, i - 1); int32 item_width;

if (att->attisdropped) continue;

/* use previously cached data, if any */ if (attr_widths != NULL && attr_widths[i] > 0) { tuple_width += attr_widths[i]; continue; }

/* This should match set_rel_width() in costsize.c */ item_width = get_attavgwidth(RelationGetRelid(rel), i); if (item_width <= 0) { item_width = get_typavgwidth(att->atttypid, att->atttypmod); Assert(item_width > 0); } if (attr_widths != NULL) attr_widths[i] = item_width; tuple_width += item_width; }

return clamp_width_est(tuple_width); } ~~~

目的

指定されたリレーションの全有効属性の平均幅を累積してタプル全体のデータ幅を見積もり、制限値のクランプ処理を適用した上で int32 として返します。

シグネチャまたは形状

  • シグネチャ: int32 get_rel_data_width(Relation rel, int32 *attr_widths)

入力と出力

  • 引数:
  • Relation rel: 対象リレーションの Relation 構造体ポインタ
  • int32 *attr_widths: 属性ごとの幅をキャッシュする配列ポインタ（NULL許容）
  • 戻り値:
  • int32: クランプ処理済みのタプルデータ幅の推定値

前提条件と不変条件

  • ループインデックス i は 1 から RelationGetNumberOfAttributes(rel) までを走査します。
  • 属性定義の取得において、タプル記述子上のインデックスは i - 1 を指定します。
  • 取得された各属性の平均幅 (item_width) は正の値でなければなりません。

アルゴリズムまたは振る舞い

1. tuple_width を 0 に初期化し、リレーションの属性数分だけ 1 からインデックス i でループを開始します。 2. 各反復で、対応する属性記述子 (Form_pg_attribute att) を取得します。 3. 属性が削除済み (att->attisdropped) である場合はスキップします。 4. attr_widths が NULL でなく、かつ attr_widths[i] > 0 の場合は、キャッシュされている幅を tuple_width に加算して次の属性へ進みます。 5. キャッシュがない場合、get_attavgwidth を呼び出して平均列幅を取得します。 6. 取得した幅が 0 以下である場合は、get_typavgwidth を呼び出して型とタイプリミットから平均幅を取得し、正であることの検証（Assert）を行います。 7. attr_widths が NULL でない場合は、求めた item_width を attr_widths[i] に格納します。 8. 決定した item_width を tuple_width に加算します。 9. ループ終了後、clamp_width_est を tuple_width に適用して最終的な幅を返します。

失敗モードと境界条件

  • 削除済み属性 (att->attisdropped が真) は計算から完全に除外されます。
  • 統計情報から得られた平均幅が非正値 (<= 0) の場合、型固有の平均幅取得関数へのフォールバックが行われます。
