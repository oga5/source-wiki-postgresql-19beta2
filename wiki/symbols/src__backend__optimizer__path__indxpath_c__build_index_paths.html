目的

指定されたリレーション、インデックス、および条件の組み合わせに基づき、順方向・逆方向の通常インデックススキャン (IndexPath) や、条件を満たす場合の並列インデックススキャン候補のリストを生成して返す。

入力と出力

  • 引数:
  • PlannerInfo *root: プランナー全体のグローバル情報を格納する構造体ポインタ
  • RelOptInfo *rel: 対象リレーションの情報を格納する構造体ポインタ
  • IndexOptInfo *index: スキャン対象のインデックス情報を格納する構造体ポインタ
  • IndexClauseSet *clauses: インデックス列ごとに分類されたインデックス句のセット
  • bool useful_predicate: 部分インデックスの述語が有効かどうかを示すフラグ
  • ScanTypeControl scantype: 実行するインデックススキャンの種別（ST_INDEXSCAN, ST_BITMAPSCAN, ST_ANYSCAN）
  • bool *skip_nonnative_saop: インデックスAMがネイティブサポートしない ScalarArrayOpExpr をスキップしたかを受け取るポインタ
  • 戻り値: 生成された IndexPath などのポインタを要素に持つ List *

前提条件と不変条件

  • skip_nonnative_saop が NULL でないこと、または scantype が ST_BITMAPSCAN であること。
  • 構築される index_clauses 内の句はインデックスキー順に並び、列番号が非減少シーケンスを形成する。

アルゴリズムまたは振る舞い

1. スキャン種別の検証: 引数 scantype に応じて、インデックスがタプル取得 (amhasgettuple) またはビットマップ取得 (amhasgetbitmap) をサポートしているか確認し、未対応であれば空リスト (NIL) を返す。 2. インデックス句の統合と外部リレーションの収集: 各インデックスキーカラムの clauses->indexclauses を走査し、必要に応じて非ネイティブ ScalarArrayOpExpr をスキップしつつ index_clauses リストと outer_relids（必要となる外部リレーションID）を構築する。最初のキーカラムに句がなくインデックスがオプションキー非対応 (amoptionalkey = false) の場合は NIL を返す。 3. ループ回数とパスキーの算出: コスト見積もり用の loop_count を計算し、必要に応じてインデックスの並び順や amcanorderbyop に基づく useful_pathkeys やオーダーバイ句を構築する。 4. インデックスオンリースキャンの判定: ビットマップスキャン以外の場合について、インデックスオンリースキャンが可能かどうかを判定する。 5. 順方向パスの生成: 関連する制限句、有用なパスキー、有用な述語、またはインデックスオンリースキャンのいずれかの条件を満たす場合、順方向の IndexPath を生成して結果リストに追加する。さらに並列インデックススキャンが許可され outer_relids が空であれば並列用パスも検討し、有効なら部分パスとして追加、不適ならメモリ解放する。 6. 逆方向パスの生成: インデックスが順序付けられておりパスキーが有用な場合、逆方向スキャンについても同様にパスキー構築、逆方向 IndexPath の生成、および必要に応じた並列インデックススキャンの検討と追加を行う。

失敗モードと境界条件

  • インデックスが要求されたスキャン種別（ST_INDEXSCAN または ST_BITMAPSCAN）のアクセスメソッド関数を実装していない場合は直ちに NIL が返される。
  • 最初のインデックス列に条件が存在せず、かつインデックスがオプショナルキーを許可しない (amoptionalkey = false) 場合はスキャンを構築できず NIL が返される。

保守担当者向けメモ

  • 生成された並列インデックススキャン用パスは、コスト見積もりの結果ワーカー数が 0 以下であれば pfree により明示的に解放される。
