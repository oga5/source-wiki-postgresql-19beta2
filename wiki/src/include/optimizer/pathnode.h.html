src/include/optimizer/pathnode.h

概要

PostgreSQLオプティマイザにおいて、プランの探索空間を構成するさまざまな Path ノードおよびリレーション構造（RelOptInfo）を生成・操作するための関数群、フック、データ構造を定義するヘッダーファイルです。

モジュール内での役割

src/backend/optimizer/util/pathnode.c および relnode.c に対する主要な公開インターフェースを提供します。パスのコスト比較、スキャン・結合・集約などの各種パス生成関数を網羅し、src/include/optimizer/paths.h や planner.h と連携してオプティマイザ全体のプラン構築を支えます。

責務

  • 各種スキャンパス（シーケンシャル、インデックス、Bitmap、TID 等）の生成関数の宣言。
  • 結合パス（ネストループ、マージ結合、ハッシュ結合）および集約・ソート・射影などの演算子パス生成関数の宣言。
  • リレーション操作やパラメータ化パス情報の構築・管理を行う関数の宣言。
  • プラグイン拡張用のフック（build_simple_rel_hook、joinrel_setup_hook）の定義。

重要なシンボル

  • AppendPathInput: Appendノードのサブパスや子Appendリレーション集合を保持する入力構造体。
  • build_simple_rel_hook_type / joinrel_setup_hook_type: プランナの各段階に割り込むためのプラグインフック。
  • スキャン系・結合系・演算子系の create_*_path 関数群: 具体的な実行計画候補を表す Path派生構造体 を構築する関数群。
  • リレーション管理系関数: build_simple_rel、build_join_rel、find_base_rel 等のリレーション構築・検索関数。

制御フローとデータフロー

本ファイルはヘッダーのため実処理を持ちませんが、提供する関数群は以下のフローでデータを受け渡します。 1. planner モジュールやパス探索ルーチンが build_simple_rel や build_join_rel を呼び出し、リレーション構造を構築する。 2. 最適なアクセス手段を決定するために create_index_path や create_nestloop_path などの生成関数を呼び出して Path ツリーを組み立てる。 3. 生成されたパスは add_path や set_cheapest を通じて比較・評価され、最終的な実行計画へと引き渡される。

直接依存

  • nodes/bitmapset.h: リレーションIDやパラメータ集合を表すビットマップ操作。
  • nodes/pathnodes.h: Path, RelOptInfo, PlannerInfo などの基底データ構造。

関連コード

  • src/backend/optimizer/util/pathnode.c: 本ヘッダーに対応する実装ファイル（パス操作・コスト比較等）。
  • src/backend/optimizer/util/relnode.c: リレーション構築・管理の実装ファイル。
  • src/include/optimizer/paths.h: パス探索のトップレベルエントリを提供する関連ヘッダー。

読者向けメモ

  • 新規のプランナ演算子やアクセスメソッドを追加する際は、ここに create_*_path のプロトタイプを追加し、対応する実装を pathnode.c に記述する必要があります。
  • パスの再パラメータ化（reparameterize_path）やコスト比較関数もここで宣言されており、コストモデルの挙動を追う際の起点となります。
