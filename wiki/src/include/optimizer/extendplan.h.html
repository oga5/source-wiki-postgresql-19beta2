src/include/optimizer/extendplan.h

概要

コアオプティマイザの主要なデータ構造（PlannerGlobal、PlannerInfo、RelOptInfo）に対し、ロード可能な拡張モジュールが独自のプライベート状態を格納・取得するためのインターフェースを提供するヘッダーファイルです。

モジュール内での役割

src/include/optimizer サブシステムの一部として、オプティマイザの内部構造を変更することなく外部フック（例: set_join_pathlist_hook）を利用する拡張モジュールに対して、効率的な状態保持の仕組みを公開します。

責務

  • 拡張モジュールの名前をバックエンド生存期間内で一意の整数 ID にマップする。
  • PlannerGlobal、PlannerInfo、RelOptInfo の各構造体に対する拡張状態の取得（インライン関数による高速化）および設定インターフェースを定義する。

重要なシンボル

  • GetPlannerGlobalExtensionState: PlannerGlobal から拡張固有の状態を取得するインライン関数。
  • GetPlannerInfoExtensionState: PlannerInfo から拡張固有の状態を取得するインライン関数。
  • GetRelOptInfoExtensionState: RelOptInfo から拡張固有の状態を取得するインライン関数。

制御フローとデータフロー

1. 拡張モジュールは起動時等に GetPlannerExtensionId(const char *extension_name) を呼び出し、拡張 ID を取得します。 2. オプティマイザの実行中、拡張モジュールは対応する Set...ExtensionState 関数を呼んでプライベートなデータポインタ（opaque）を各プランナーオブジェクトに登録します。 3. 以降のオプティマイザ処理において、Get...ExtensionState インライン関数を用いて登録済みの状態をO(1)で安全かつ高速に取得し、中間計算結果の再利用等に活用します。

直接依存

  • nodes/pathnodes.h: PlannerGlobal、PlannerInfo、RelOptInfo などのコアオプティマイザノード定義。

関連コード

  • src/backend/optimizer/util/extendplan.c: 拡張IDの割り当ておよび状態の設定処理を実装する対となるソースファイル。

読者向けメモ

  • 取得系関数はパフォーマンスのため static inline として実装されており、ID の範囲外アクセスに対しては NULL を返します。
  • 拡張 ID はバックエンドのライフタイム内でのみ有効であり、永続的なものではありません。
