src/include/lib/ilist.h

概要

src/include/lib/ilist.h は、PostgreSQL における統合型（インライン型）の単方向連結リスト（slist）および双方向連結リスト（dlist / dclist）のデータ構造と操作用インライン関数を提供する。リストのリンク用ノードがコンテナ構造体に直接埋め込まれる設計になっており、個別のノード動的割当や余分なメモリ管理オーバーヘッドを排除している。

モジュール内での役割

src/include/lib サブシステム内において、本ファイルは他の多くのコンテナやインデックス構造体（簡易ハッシュ、ツリー構造など）の基盤となる低レベルのリンク機構を提供する。大半の操作はヘッダー内の static inline 関数として実装され、コードサイズが大きい一部の検証・削除関数のみが src/backend/lib/ilist.c に委譲されている。

責務

  • 双方向連結リストの管理 (dlist): 循環参照構造を利用した高速な要素挿入・削除・移動機能の提供。
  • 要素数追跡付き双方向連結リストの管理 (dclist): dlist の機能に加え、要素数を O(1) で保持するカウント機能の提供。
  • 単方向連結リストの管理 (slist): NULL 終端による軽量な単方向リスト操作の提供。
  • コンテナ取得マクロの提供: offsetof を利用した、ノードポインタから親のコンテナ構造体への型安全な逆変換。
  • イテレータと安全な走査の提供: 通常走査および走査中の要素削除（ミュータブル走査）をサポートするイテレータ構造体とマクロの定義。

重要なシンボル

双方向リストの中核構造体とノード

  • struct dlist_node: prev および next ポインタを保持し、被管理構造体に埋め込まれる双方向リストの基本ノード。
  • struct dlist_head: リストの起点となるヘッダー。空リスト時は NULL または自己参照の循環構造をとる。
  • struct dlist_iter: 非破壊的走査のためのイテレータ。cur（現在位置）と end（終端ガード）を保持。
  • struct dlist_mutable_iter: 走査中の要素削除を安全に行うためのミュータブルイテレータ。next を保持することで削除後の破綻を防ぐ。
  • struct dclist_head: dlist_head と 32 ビットの count フィールドを内包し、要素数を常時追跡する双方向リストのヘッダー。

単方向リストの中核構造体とノード

  • struct slist_node: next ポインタのみを保持する単方向リストの基本ノード。
  • struct slist_head: 単方向リストの起点ヘッダー。空の場合は head.next が NULL。
  • struct slist_iter: 単方向リスト用の通常イテレータ。
  • struct slist_mutable_iter: prev, cur, next の 3 つのポインタを保持し、slist_delete_current による安全な要素削除を可能にするミュータブルイテレータ。

リスト操作関数群

  • function dlist_insert_after: 指定された after ノードの直後に、同一リスト内で node を挿入するインライン関数。
  • function dlist_insert_before: 指定された before ノードの直前に、同一リスト内で node を挿入するインライン関数。
  • function slist_delete: 指定された node を単方向リストから O(n) で探索・削除する実体関数（src/backend/lib/ilist.c に定義）。

制御フローとデータフロー

  • 初期化:
  • dlist は初期状態として NULL 許容、または dlist_init() による自己循環構造をとる。最初の追加操作時に NULL ヘッダーは自動的に循環構造へコンバートされる。
  • slist は初期状態で head.next = NULL となる。
  • コンテナ解決 (dlist_container / slist_container):
  • offsetof とポインタ演算を利用し、dlist_node * や slist_node * からそれを囲む上位の構造体アドレスを算出する。コンパイル時の型チェック (StaticAssertVariableIsOfTypeMacro) を経由して安全性を担保。
  • ミュータブル走査と削除:
  • dlist_foreach_modify や slist_foreach_modify では、次のノードを事前に退避または追跡 (prev, next) することで、ループ内でカレント要素の削除を行っても走査路がロストしない構造になっている。

直接依存

  • postgres.h（ペアファイル ilist.c 経由で読み込まれるが、ヘッダー自体は単体で完結し追加の外部インクルードを持たない）

関連コード

  • src/backend/lib/ilist.c: インライン化するには大きすぎる slist_delete や、デバッグ時のみ有効な整合性検証関数（dlist_check, slist_check など）の実装。

読者向けメモ

  • メモリ所有権: 本ヘッダーが扱うノードやヘッダーはすべて外部管理（呼び出し側が割り当てたメモリ）であり、リスト操作関数がメモリの確保や解放を行うことは一切ない。
  • ILIST_DEBUG: デバッグマクロを有効にすると、リストの循環整合性や所属チェック（dlist_member_check）が各操作時に実行され、構造破壊を早期検知できる反面、パフォーマンスコストが発生する。
