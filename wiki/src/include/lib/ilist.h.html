src/include/lib/ilist.h

概要

src/include/lib/ilist.h（および対となる src/backend/lib/ilist.c）は、PostgreSQL 内で使用される組み込み・インライン型の双方向連結リスト (dlist / dclist) および単方向連結リスト (slist) のデータ構造とインライン操作 API を提供します。リストのリンクノードを対象オブジェクトの内部に直接埋め込むことで、別途ノード用のメモリ割り当てを行うオーバーヘッドを排除しています。

モジュール内での役割

src/include/lib サブシステムにおいて、本ファイルはメモリ効率の高い基本コンテナとして機能します。独立したノード割当を行わないため、あらかじめ所属が固定されているオブジェクト群（キャッシュや管理構造体など）の連結リストとして広く利用されます。双方向カウント付きリスト (dclist) や通常の双方向 (dlist)、単方向 (slist) の各種マクロおよびインライン関数群の定義源となっています。

責務

  • **データ構造の定義**:
  • 双方向リスト（dlist_node, dlist_head, dlist_iter, dlist_mutable_iter）
  • カウント付き双方向リスト（dclist_head）
  • 単方向リスト（slist_node, slist_head, slist_iter, slist_mutable_iter）
  • **静的初期化マクロの提供**:
  • DLIST_STATIC_INIT, DCLIST_STATIC_INIT, SLIST_STATIC_INIT によるゼロ初期化・循環リスト初期化のサポート。
  • **インライン操作 API**:
  • リストへの要素追加（push head/tail、insert after/before）、削除（delete）、ポップ、移動、要素数・空判定、およびコンテナポインタ復元用マクロ (*_container) の提供。
  • **イテレーションのサポート**:
  • 通常走査および安全なイテレーション中削除をサポートするミュータブルイテレータの提供。
  • **デバッグ検証**:
  • ILIST_DEBUG 有効時の整合性チェック（dlist_check, slist_check, dlist_member_check）の実装。

重要なシンボル

データ構造・型

  • dlist_node, slist_node: それぞれ双方向・単方向リストのリンクを保持する構造体。対象構造体に埋め込んで使用する。
  • dlist_head, slist_head, dclist_head: リストの先頭管理構造体。dclist_head は要素数を追跡する uint32 count を内包する。
  • dlist_iter, dclist_iter, slist_iter: 走査専用のイテレータ。走査中のリスト構造変更は不可。
  • dlist_mutable_iter, slist_mutable_iter: 走査中に安全な要素削除を行うためのミュータブルイテレータ。

初期化・生成・静的初期化

  • DLIST_STATIC_INIT(name), DCLIST_STATIC_INIT(name), SLIST_STATIC_INIT(name): 静的変数宣言時の初期化マクロ。
  • dlist_init(head), dclist_init(head), slist_init(head): ランタイムでのリスト初期化関数。
  • dlist_node_init(node): ノード単体を独立状態（NULL 初期化）にする。

要素の挿入・追加

  • dlist_push_head, dlist_push_tail, dclist_push_head, dclist_push_tail, slist_push_head: リストの先頭または末尾へ要素を追加する。未初期化の NULL ヘッダの場合は自動的に循環リスト等へ変換する。
  • dlist_insert_after, dlist_insert_before, dclist_insert_after, dclist_insert_before, slist_insert_after: 既存の特定ノードの前後へ要素を挿入する。

要素の削除・取り出し

  • dlist_delete, dlist_delete_thoroughly, dlist_delete_from, dlist_delete_from_thoroughly: 双方向リストからのノード削除。_thoroughly 系はノードの prev/next を NULL に設定して非所属状態とする。
  • dclist_delete_from, dclist_delete_from_thoroughly: カウントをデクリメントしつつ dlist 側の削除関数を呼び出す。
  • slist_delete(head, node): 単方向リストから任意ノードを削除する（$O(n)$）。
  • slist_delete_current(iter): 単方向ミュータブルイテレータの現在位置の要素を効率的に削除する。
  • dlist_pop_head_node, dclist_pop_head_node, slist_pop_head_node: 先頭要素を削除して返す。

コンテナ変換マクロ

  • dlist_container(type, membername, ptr), dclist_container, slist_container: offsetof を利用して、リストノードポインタからそれを保持する外側構造体 (type) のポインタを逆算・取得する。

制御フローとデータフロー

  • **リストの表現状態**:
  • 双方向リストの空状態は、next が NULL であるか、ヘッダ自身を指す循環状態 (head.next == &head) の2通りを許容します。初回の push 時に NULL ヘッダは循環状態へ自動変換されます。
  • 単方向リストは終端が NULL となります。
  • **イテレーション制御**:
  • dlist_foreach / dlist_reverse_foreach はマクロによりインライン展開され、iter.end との比較によってループを継続します。
  • dlist_foreach_modify および slist_foreach_modify は、現在のノードだけでなく next や prev ポインタを保持することで、ループ内で安全に dlist_delete や slist_delete_current を呼び出して要素を破棄・離脱させることができます。
  • **デバッグフロー**:
  • ILIST_DEBUG が定義されている場合、dlist_check や slist_check が挿入され、双方向リンクの整合性（prev->next == cur かつ next->prev == cur）や単方向リストの循環・不正なポインタを検証します。非デバッグ時はマクロにより空の式に展開されます。

直接依存

  • postgres.h (paired file ilist.c にてインクルード)
  • lib/ilist.h (paired file ilist.c にてインクルード)
  • 注: ilist.h 自体は他のヘッダへの直接依存を持たない独立した設計になっています。

関連コード

  • src/backend/lib/ilist.c: インライン化するには大きすぎる関数（slist_delete や ILIST_DEBUG 有効時の検証関数群）の実装ファイル。
  • リストを利用する各種サブシステム（バックエンド内のマネージャ、キャッシュ、プランナー等）。

読者向けメモ

  • **メモリ所有権**: 本ファイルが提供する関数やマクロはメモリの割り当て・解放を一切行いません。ノードを含む構造体のライフサイクルは呼び出し側（または外部のメモリコンテキスト）が完全に管理する必要があります。
  • **境界条件**: dclist_head は最大 PG_UINT32_MAX 個の要素を格納可能であり、追加・削除時にオーバーフロー/アンダーフローの Assert 検証が行われます。
  • **未確認エリアの除外**: パフォーマンス上の理由から、一部のデバッグ用整合性チェックは標準ビルドでは無効化（no-op）されています。本ファイルは静的インライン展開を多用するため、実際のバイナリサイズと呼び出し箇所の最適化に注意してください。
