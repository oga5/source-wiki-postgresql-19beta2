src/include/lib/simplehash.h

概要

src/include/lib/simplehash.h は、マクロによるコード生成（テンプレート機構）を用いたオープンアドレス法（開放アドレス法）によるハッシュテーブル実装を提供するヘッダーファイルです。動的ハッシュ（dynahash）に比べて間接関数呼び出しがなく、CPUキャッシュやパイプライン処理に優れた特性を持ちます。また、削除時に「墓石（tombstone）」を残さず要素を前方または後方にシフトさせるロジックや、ロビンフッドハッシュ（Robin Hood Hashing）の概念を応用してクラスタリングを抑制しています。

モジュール内での役割

src/include/lib モジュール群の中でも、性能・空間効率が厳しく要求されるコアデータ構造のテンプレートとして位置づけられています。tidbitmap.c などのファイルローカル定義や、エグゼキュータ周辺の構造体で利用されます。他の汎用コンテナ（ilist.hやrbtree.hなど）と同様に、型安全かつオーバーヘッドの少ないコンテナ機能を提供します。

責務

  • **コード生成マクロの提供**: 利用側で SH_PREFIX、SH_ELEMENT_TYPE、SH_KEY_TYPE などのマクロを定義した上でインクルードすることで、型特化されたハッシュテーブルの型定義 (SH_DECLARE) および関数群の実装 (SH_DEFINE) を生成する。
  • **オープンアドレス法によるハッシュ管理**: 線形探索をベースに、ロビンフッドハッシュの距離比較や動的な拡張（SH_GROW）、削除時の逆方向シフトによる墓石レスを実現する。
  • **メモリ管理の抽象化**: PostgreSQL の MemoryContext を利用したアロケーション、または SH_RAW_ALLOCATOR による独自アロケーション（共有メモリ等への対応）をサポートする。

重要なシンボル

コアデータ構造とステータス

  • struct SH_TYPE: ハッシュテーブル全体の管理構造体。バッファ配列 data、要素数 members、バケット数 size、シズマスク sizemask、拡張閾値 grow_threshold、プライベートデータポインタを保持する。
  • enum SH_STATUS: バケットの使用状態を表す列挙型。SH_STATUS_EMPTY (0x00) と SH_STATUS_IN_USE (0x01) の2つを持つ。
  • struct SH_ITERATOR: イテレーションの状態を保持する構造体。逆方向への走査管理用メンバ cur、end、done を持つ。

メモリ・サイズ計算ヘルパー

  • function SH_ALLOCATE: ハッシュテーブルの要素配列や構造体のメモリを確保する。SH_RAW_ALLOCATOR が定義されている場合はそれを呼び、未定義の場合は MemoryContextAllocExtended を用いてゼロクリア・巨大アロケーションフラグ付きで確保する。
  • function SH_FREE: 割り当てられたメモリ領域を解放するデフォルトのラッパー（内部で pfree を呼ぶ）。
  • function SH_COMPUTE_SIZE: 指定されたサイズを基に、2の冪乗への切り上げや最大サイズ制限（SH_MAX_SIZE）の検証を行い、バケット配列に必要なサイズを計算する。

ハッシュ・バケット計算ヘルパー

  • function SH_UPDATE_PARAMETERS: ハッシュテーブルの size、sizemask、および拡張の閾値となる grow_threshold（通常 SH_FILLFACTOR または SH_MAX_FILLFACTOR に依存）を更新する。
  • function SH_NEXT / function SH_PREV: バケット配列のインデックスをインクリメント・デクリメントする。sizemask を用いたラップアラウンド処理を行う。
  • function SH_DISTANCE_FROM_OPTIMAL: あるバケットの位置と、その要素の本来の最適位置（initial bucket）との距離（Displacement from Optimal / DIB）を計算する。
  • function SH_INITIAL_BUCKET: ハッシュ値から対応する最初の最適バケットインデックス（hash & sizemask）を算出する。
  • function SH_ENTRY_HASH: 要素からハッシュ値を算出または取得する。SH_STORE_HASH が有効な場合は保存済みのハッシュを返し、そうでない場合は SH_HASH_KEY マクロを評価する。

制御フローとデータフロー

挿入フロー (SH_INSERT / SH_INSERT_HASH_INTERNAL)

1. キーからハッシュ値を計算し（または事前に計算されたハッシュを使用し）、SH_INITIAL_BUCKET で最適バケットを特定する。 2. テーブルの負荷率が閾値（grow_threshold）を超えている場合、SH_GROW を呼び出してバケット配列を2倍に拡張する。 3. 最適バケットから開始して線形探索を行い、空きバケット、既存キーの一致、あるいはロビンフッドハッシュの条件（挿入要素のDIBが既存要素のDIBより大きい場合）に基づく要素の押し出し（前方シフト）を行う。 4. 押し出しが発生した際、連続する衝突回数や移動コストが制限値（SH_GROW_MAX_DIB または SH_GROW_MAX_MOVE）を超えた場合は、強制的にテーブルをリサイズして restart する。

削除フロー (SH_DELETE / SH_DELETE_ITEM)

1. 削除対象の要素を検索またはポインタから特定し、ステータスを SH_STATUS_EMPTY に設定する。 2. 墓石を残さないため、削除したバケットの後続要素を順に走査し、空きバケットまたは「本来の最適位置にある要素」に遭遇するまで逆方向へ要素を memcpy でシフトさせる。 3. 最終的な空きバケットのステータスを SH_STATUS_EMPTY に更新する。

イテレーションフロー (SH_START_ITERATE / SH_ITERATE)

1. テーブル全体を走査し、最初に発見した空き要素の位置を起点（startelem）とする。 2. 削除時の逆方向シフトによる巻き込みを防ぐため、逆方向（インデックスのデクリメント）へ走査を行う。 3. SH_STATUS_IN_USE の要素を返しながら、開始点に戻った時点で終了フラグを立てる。これにより、イテレーション中の要素削除が安全に行える。

直接依存

  • port/pg_bitutils.h: 2の冪乗計算（pg_nextpower2_64）などに使用。
  • utils/memutils.h: バックエンド環境でのメモリコンテキスト操作（MemoryContextAllocExtended 等）に使用（SH_RAW_ALLOCATOR 未定義時）。

関連コード

  • src/backend/utils/hash/tidbitmap.c: simplehash.h を利用して内部ハッシュを実装している代表的なコード。

読者向けメモ

  • **インクルードの注意点**: 本ヘッダーファイルはインクルードガードを持たず、代わりに末尾で利用したマクロ群をすべて #undef する設計になっています。1つのソースファイル内で複数の異なる型・プレフィックスを持つハッシュテーブルを順次生成するためにこの構造が採用されています。
  • **メモリ所有権**: デフォルトでは指定された MemoryContext がハッシュテーブル構造体および要素配列のメモリを所有します。SH_RAW_ALLOCATOR を定義した場合は、メモリコンテキストをバイパスして独自のカスタムアロケータ（共有メモリ領域など）からバッファを取得できます。ただし、その場合でも要素配列の初期化（ゼロクリア）はアロケータ側の責務となります。
