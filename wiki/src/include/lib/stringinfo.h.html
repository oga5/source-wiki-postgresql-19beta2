src/include/lib/stringinfo.h

概要

PostgreSQL において可変長文字列やバイナリデータを効率的にバッファリングするための StringInfo データ構造と関連関数の宣言を提供するヘッダーファイルです。最大 1GB までのデータを扱えます。

モジュール内での役割

src/include/lib/ サブシステムに属し、文字列操作やバッファ管理の共通基盤を提供します。実装本体はペアとなる src/common/stringinfo.c に存在し、バックエンド・フロントエンドの両方から利用されます。

責務

  • 可変長文字列を表現するデータ構造 (StringInfoData, StringInfo) の定義。
  • 動的バッファの初期化、破棄、サイズ拡張、リセットを行う関数の宣言。
  • 書式付き文字列、C 文字列、単一文字、バイナリデータをバッファへ安全に追加するインターフェースの提供。
  • 既存バッファをコピーなしでラップする読み取り専用および書き込み可能なインライン初期化関数の提供。

重要なシンボル

  • struct StringInfoData: バッファへのポインタ、現在長 (len)、最大長 (maxlen)、カーソル位置 (cursor) を保持する構造体。
  • typedef StringInfo: StringInfoData * 型のエイリアス。
  • initReadOnlyStringInfo: 既存のバッファをコピーせず読み取り専用の StringInfo として初期化するインライン関数（maxlen = 0）。
  • initStringInfoFromString: 既存の palloc 済み NUL 終端バッファを再利用可能な StringInfo として初期化するインライン関数。
  • appendStringInfoCharMacro: バッファの容量不足がない場合に高速に 1 文字を追加するインラインマクロ。

制御フローとデータフロー

  • 初期化: makeStringInfo や initStringInfo 等により、palloc を用いてデフォルトサイズ（1024バイト）または指定サイズのバッファを確保します。
  • データ追加: appendStringInfo や appendBinaryStringInfo などの関数が呼び出されると、容量不足時に enlargeStringInfo が実行されて repalloc でバッファが拡張されます。
  • インライン最適化: パフォーマンスクリティカルなパスでは、initReadOnlyStringInfo や appendStringInfoCharMacro を用いてオーバーヘッドを最小化します。

直接依存

このファイル自体は他のインクルードファイルを直接持ちません（純粋なデータ構造とAPIの宣言）。

関連コード

  • src/common/stringinfo.c: StringInfo API の実体を実装するペアファイル。

読者向けメモ

  • 読み取り専用の StringInfoData（maxlen == 0）に対しては、appendStringInfo 系関数や resetStringInfo を呼び出してはならないという不変条件があります。
  • マクロ版の appendStringInfoCharMacro は引数を複数回評価するため、副作用のある式を引数に渡さないよう注意してください。
