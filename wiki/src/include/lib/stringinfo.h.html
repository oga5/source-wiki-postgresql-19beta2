src/include/lib/stringinfo.h

概要

src/include/lib/stringinfo.h は、PostgreSQL における可変長文字列バッファ型である StringInfo のデータ構造と操作関数を定義するヘッダーファイルです。C 言語の終端文字付き文字列（null-terminated text）および任意のバイナリデータを効率よく安全に扱うためのインターフェースを提供します。最大長は現在 1GB に制限されています。

モジュール内での役割

src/include/lib モジュール内に位置し、PostgreSQL のバックエンドおよびフロントエンドコード全般で利用される基本的なユーティリティライブラリの一つです。実体や実装コードはペアとなる src/common/stringinfo.c に記述されており、メモリ割り当てには主に palloc() / pfree() が使用されます。

責務

  • 可変長文字列を表現するデータ構造 StringInfoData および StringInfo 型の定義。
  • 動的バッファの初期化、サイズ拡張、および破棄を行う関数の宣言。
  • フォーマット付き文字列、プレーン文字列、単一文字、およびバイナリデータをバッファへ追加する API の提供。
  • 既存のメモリ領域をラップしてコピーを避ける、読み取り専用または文字列からの初期化インライン関数の提供。

重要なシンボル

  • struct StringInfoData: 文字列のデータポインタ、現在の長さ、最大バッファサイズ、カーソル位置を保持する構造体。
  • typedef StringInfo: StringInfoData * 型のエイリアス。
  • macro: STRINGINFO_DEFAULT_SIZE: デフォルトの初期バッファサイズ（1024バイト）。
  • function: initReadOnlyStringInfo: 既存のバッファをコピーせずに読み取り専用の StringInfo として初期化するインライン関数。
  • function: initStringInfoFromString: 既存の palloc 済みバッファから StringInfo を初期化するインライン関数。
  • macro: appendStringInfoCharMacro: バッファの容量に余裕がある場合に高速に1文字を追加するマクロ。

制御フローとデータフロー

  • **初期化フェーズ**: makeStringInfo() や initStringInfo() などの関数により StringInfoData が生成され、palloc() を介して初期サイズ分のメモリバッファが割り当てられます。
  • **データ追加フェーズ**: appendStringInfo() や appendBinaryStringInfo() などの関数を通じてデータがバッファに書き込まれます。容量が不足する場合は、内部で enlargeStringInfo() が呼び出され、バッファサイズが再割り当て（拡張）されます。
  • **破棄フェーズ**: 利用完了後は destroyStringInfo() によってバッファおよび構造体メモリが解放されます。

直接依存

このファイル自体には他のヘッダーファイルへの #include は記述されていません（純粋な型定義と関数宣言のみを含みます）。

関連コード

  • src/common/stringinfo.c: ヘッダーで宣言されている関数の実体および内部ヘルパー関数を実装するペアファイル。

読者向けメモ

  • 読み取り専用として初期化された StringInfoData（maxlen == 0）は、内容の変更や resetStringInfo() の呼び出しができません。
  • appendStringInfoCharMacro などのマクロを使用する際は、引数が複数回評価される副作用に注意してください。
