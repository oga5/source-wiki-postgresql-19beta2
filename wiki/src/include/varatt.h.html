src/include/varatt.h

概要

PostgreSQL の可変長データ型（varlena）および TOAST（The Oversized-Attribute Storage Technique）機構をサポートするためのヘッダーファイル。インライン圧縮、ショートヘッダー、および各種外部参照ポインタ（TOAST ポインタ）のレイアウト、マクロ、インライン関数を定義する。

モジュール内での役割

src/include/postgres.h やその他のデータ型定義の基盤として機能し、データがタプル内でどのように格納・参照されているかを解釈するための共通インターフェースを提供する。

責務

  • **可変長ヘッダーの定義**: 4バイト（通常および圧縮済み）、1バイト（ショート）、1バイト＋タグ（TOAST ポインタ）の各データ構造のレイアウト定義。
  • **エンディアン依存のビット操作**: ビッグエンディアンおよびリトルエンディアン環境におけるヘッダーフラグのマスク・シフト処理の隠蔽。
  • **TOAST ポインタの分類と管理**: オンディスク、インメモリ（間接参照）、および展開済みオブジェクト（RO/RW）のタグ付けとサイズ計算。
  • **アクセサおよびセッターの提供**: データのサイズ、データ本体へのポインタ、圧縮状態を安全に取得・設定するインライン関数の提供。

重要なシンボル

TOAST ポインタとタグ関連

  • function VARTAG_EXPANDED_RO: 読み取り専用の展開済みオブジェクト用 TOAST ポインタタグ。
  • function VARTAG_EXPANDED_RW: 読み取り読み書き可能な展開済みオブジェクト用 TOAST ポインタタグ。
  • function VARTAG_INDIRECT: メモリ上の別領域を指す間接参照ポインタのタグ。
  • enum vartag_external: TOAST ポインタの種類を表す列挙型（VARTAG_INDIRECT, VARTAG_EXPANDED_RO, VARTAG_EXPANDED_RW, VARTAG_ONDISK）。

データ構造とレイアウト

  • struct varatt_external: ディスク上の TOAST テーブルに格納された値へのポインタ（生データサイズ、拡張サイズ・圧縮法、値ID、TOASTリレーションIDを含む）。パディングなし。
  • struct varatt_indirect: インメモリの varlena へのポインタを保持する構造体。
  • struct ExpandedObjectHeader: 展開済みオブジェクトヘッダーの前方宣言（実体は src/include/utils/expandeddatum.h）。
  • struct varatt_expanded: 展開済みオブジェクトヘッダーへのポインタ (ExpandedObjectHeader *eohptr) を保持する構造体。
  • struct varattrib_4b: 4バイトヘッダーを持つ通常またはインライン圧縮された varlena のユニオン構造。
  • struct uint32: （文脈上のプリミティブ型定義の補助）。
  • struct varattrib_1b: 1バイトヘッダーを持つショート varlena の構造体。
  • struct varattrib_1b_e: 1バイトヘッダーとタグバイトを持つ外部 TOAST ポインタの構造体。

制御フローとデータフロー

  • **データ型判定のフロー**: VARATT_IS_EXTERNAL(PTR) により外部ポインタか判定され、外部である場合は VARTAG_EXTERNAL(PTR) でタグを取得して VARTAG_SIZE() でサイズを決定する。非外部の場合は VARATT_IS_SHORT(PTR) に応じて 4 バイトまたは 1 バイトのヘッダー解析に分岐する。
  • **アライメントとメモリコピー**: varatt_external や varatt_indirect などの構造体はタプル内でアライメントされていないため、フィールドにアクセスする前にローカル変数へ memcpy する必要がある（等価性比較には memcmp が利用される）。

直接依存

（ソース内に #include ディレクティブは存在しない）

関連コード

  • src/include/utils/expandeddatum.h: 展開済みオブジェクトヘッダー (ExpandedObjectHeader) の定義元。

読者向けメモ

  • **メモリ配置**: varatt_external や TOAST ポインタはタプル内で非アライメント（unaligned）に格納されるため、直接構造体キャストしてマルチバイトフィールドを読み取ることはアライメント違反を引き起こす可能性がある点に注意。
  • **エンディアン**: ヘッダーのフラグビットはビッグエンディアンとリトルエンディアンで配置が異なり、マクロによって切り替えられる。
