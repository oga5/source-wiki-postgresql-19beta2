src/include/fmgr.h

概要

src/include/fmgr.h は、PostgreSQL の関数マネージャ（Function Manager: FMGR）のコア定義と関数呼び出しインターフェースを提供するヘッダーファイルです。組み込み関数や動的ロードされる C 言語関数を安全かつ統一された規約で実行するためのデータ構造、マクロ、および API 宣言を所有しています。

モジュール内での役割

PostgreSQL バックエンド全体で、SQL 関数、演算子、インデックスサポート関数、データ型の入出力関数を呼び出すための共通基盤です。実行エンジン（Executor）やカタログシステムなど、関数実行を必要とするほぼすべてのモジュールからインクルードされます。

責務

  • 関数呼び出しに必要なメタデータを保持する FmgrInfo 構造体の定義と、その初期化・操作 API の提供。
  • 実引数や呼び出しコンテキストを渡すための FunctionCallInfoBaseData（FunctionCallInfo）と、スタック・動的割当用の補助マクロ（LOCAL_FCINFO, SizeForFunctionCallInfo）の提供。
  • C 言語で書かれた FMGR 互換関数を作成・補助するための引数取得マクロ（PG_GETARG_xxx）、戻り値設定マクロ（PG_RETURN_xxx）、および TOAST 処理・照合順序（Collation）取得マクロの提供。
  • バージョン 1 呼び出し規約および動的ロードモジュールのバイナリ互換性（ABI）を検証するためのマジックブロック定義（PG_MODULE_MAGIC 系列）の提供。
  • 直接関数呼び出し（DirectFunctionCallN）、情報つき関数呼び出し（FunctionCallN / OidFunctionCallN）、および型入出力や集約関数コンテキスト用のサポート宣言の提供。

重要なシンボル

コアデータ構造・ポインタ

  • PGFunction: 関数ポインタ型 Datum (*)(FunctionCallInfo fcinfo)。
  • FmgrInfo: 関数メタデータ（関数アドレス、OID、引数数、厳格性、メモリコンテキスト、式ツリーなど）を保持する構造体。
  • FunctionCallInfoBaseData / FunctionCallInfo: 実行時の引数配列、NULL フラグ、照合順序、結果情報などを保持する可変長構造体ベース。

ライフサイクル・初期化マクロ

  • InitFunctionCallInfoData(...): args 配列を除く FunctionCallInfoBaseData の各フィールドを初期化するマクロ。
  • LOCAL_FCINFO(name, nargs): スタック上にアライメントを保証した FunctionCallInfo 領域を安全に確保するマクロ。
  • fmgr_info(), fmgr_info_cxt(): 関数 OID から FmgrInfo を構築するルーチン。

引数取得・操作マクロ (C 関数用)

  • PG_FUNCTION_ARGS: FunctionCallInfo fcinfo 引数の省略形。
  • PG_GETARG_DATUM(n), PG_GETARG_INT32(n), PG_GETARG_POINTER(n) 等: 基本型の引数取得マクロ。
  • PG_ARGISNULL(n): 指定引数が NULL かどうかを判定するマクロ。
  • PG_DETOAST_DATUM(datum) / PG_DETOAST_DATUM_PACKED(datum): TOAST された varlena 型データをデストースト（必要に応じてメモリ展開）するマクロ。
  • PG_FREE_IF_COPY(ptr, n): デストーストによって新しく palloc されたコピーを解放するメモリ管理マクロ。

戻り値マクロ

  • PG_RETURN_NULL(): isnull を立てて Datum を返すマクロ。
  • PG_RETURN_INT32(x), PG_RETURN_POINTER(x) 等: 各種型の戻り値生成マクロ。

ABI・モジュール検証マクロ

  • PG_FUNCTION_INFO_V1(funcname): バージョン 1 呼び出し規約のメタデータ構造を定義するマクロ。
  • PG_MODULE_MAGIC: ロードされたモジュールの PostgreSQL バージョンやコンパイル時設定の互換性を検証するマジック関数を定義するマクロ。

制御フローとデータフロー

1. **ルックアップと初期化**: 呼び出し側は事前に fmgr_info(Oid, FmgrInfo*) を呼び出して対象関数のアドレスや属性をキャッシュします。 2. **引数の準備**: LOCAL_FCINFO マクロなどで FunctionCallInfo 構造体をスタック上に確保し、InitFunctionCallInfoData で初期化した上で args 配列に NullableDatum を詰めます。 3. **関数ディスパッチ**: FunctionCallInvoke(fcinfo) マクロ、あるいは FunctionCall1Coll などのラッパー関数を経由して、FmgrInfo 内の fn_addr（PGFunction 型）が直接または間接的に呼び出されます。 4. **関数実行と返却**: 呼び出された C 関数は PG_GETARG_xxx で引数を取り出し、演算・処理を行った後、PG_RETURN_xxx や PG_RETURN_NULL() を用いて Datum を返却します。

直接依存

  • 本ヘッダーファイル自体のインクルード部分には直接の #include は記述されていませんが、前方宣言として Node, Aggref, ExprContextCallbackFunction, StringInfoData が定義されています。実体や関連処理は対となる src/backend/utils/fmgr/fmgr.c および周辺のカタログ・エグゼキューターヘッダーに依存します。

関連コード

  • src/backend/utils/fmgr/fmgr.c: FMGR の本体実装（fmgr_info, キャッシュ機構、各種 DirectFunctionCall や型入出力関数の実体）。
  • src/include/postgres.h: PostgreSQL の基本型やシステム定義。

読者向けメモ

  • **メモリ所有権**: FmgrInfo 内の fn_extra や subsidiary データは指定された fn_mcxt（通常は呼び出し側のメモリコンテキスト）に割り当てられます。長時間保持する構造体に埋め込む場合は、適切な長寿命のメモリコンテキストを指定して fmgr_info_cxt を使用してください。
  • **アライメントとパック型**: varlena 型の操作において、アライメントが必要な構造体キャストを行う場合は PG_DETOAST_DATUM を、アライメント非依存の操作（memcpy や 1 バイトヘッダー処理）では PG_DETOAST_DATUM_PACKED を使い分ける必要があります。
