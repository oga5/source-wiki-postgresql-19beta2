src/include/nodes/primnodes.h

概要

src/include/nodes/primnodes.h は、PostgreSQLのクエリパイプラインにおける複数のステージ（解析、計画、実行）で共通して使用される「プリミティブ」なノード型の定義を提供します。主に実行可能な式ツリー、結合ツリー、ターゲットエントリ、および各種句（CASE、COALESCE、JSON操作、ウィンドウ関数など）の内部構造を定義しています。

モジュール内での役割

src/include/nodes サブシステムの一部として、抽象構文木（parsenodes.h）から生成され、のちに最適化（pathnodes.h / plannodes.h）および実行（execnodes.h）へ渡される中核的なデータ構造を供給します。式ノード群は共通のスーパークラス概念（Expr）から派生します。

責務

  • **式ノードの定義**: 変数 (Var)、定数 (Const)、パラメータ (Param)、関数呼び出し (FuncExpr)、演算子 (OpExpr) などの実行可能式要素を定義する。
  • **制御構文・特殊式の定義**: CaseExpr、CoalesceExpr、SubLink、SubPlan、XmlExpr、各種SQL/JSONコンストラクタおよび式を定義する。
  • **結合ツリーの表現**: RangeTblRef、JoinExpr、FromExpr を用いて FROM 句および結合構造を表現する。
  • **ターゲットとメタ情報の管理**: TargetEntry および各種の型キャスト・強制変換 (CoercionContext, CoercionForm, RelabelType 等) を保持する。

重要なシンボル

共通および基本式ノード

  • Expr: すべての実行可能式ノードの抽象的なスーパークラス（NodeTag type を保持）。
  • Var: テーブル列やサブプラン出力を表す変数ノード（varno, varattno, varlevelsup 等）。
  • Const: 定数値を表すノード（consttype, constvalue, constisnull 等）。
  • Param: パラメータを表すノード（ParamKind に応じて外部・内部・サブリンク等に分岐）。
  • TargetEntry: クエリのターゲットリスト内のエントリ（式、resno、resname、ressortgroupref等を保持）。

関数・演算子・条件分岐

  • FuncExpr: 関数呼び出しを表すノード（funcid, args 等）。
  • OpExpr / DistinctExpr / NullIfExpr: 演算子呼び出しおよび DISTINCT FROM / NULLIF。
  • ScalarArrayOpExpr: 「スカラー op ANY/ALL (配列)」形式の式。
  • BoolExpr: 論理演算 (AND, OR, NOT)。
  • CaseExpr / CaseWhen: CASE 式とその分岐。

サブクエリ・プラン関連

  • SubLink: 解析ツリーに現れるサブクエリ（EXISTS, IN, ANY など）。
  • SubPlan: プランナーによって SubLink から置換される、実行可能なサブプランノード。
  • AlternativeSubPlan: プラン時に選択肢となる複数の SubPlan を保持する一時的ノード。

型変換・コエルション

  • CoercionContext / CoercionForm: 型キャストの許可コンテキストと表示形式の列挙型。
  • RelabelType: 実行時ノーオペレーションの型ラベル変更ノード。
  • CoerceViaIO / ArrayCoerceExpr / ConvertRowtypeExpr / CoerceToDomain: 各種複雑な型変換ノード。

JSONおよびXML式

  • JsonExpr / JsonConstructorExpr / JsonIsPredicate / JsonValueExpr: SQL/JSON 関連の関数・述語・コンストラクタ表現。
  • XmlExpr: SQL/XML 関数群の表現。

結合ツリー構造

  • RangeTblRef: クエリのレンジテーブル（RT）への参照。
  • JoinExpr: SQL 結合式（JOIN ... ON / USING）。
  • FromExpr: 複数要素のクロスプロダクト結合（FROM ... WHERE ...）。

制御フローとデータフロー

本ファイルは純粋なヘッダーファイルであり、実行コードやヘルパー関数は持たず、データ構造のレイアウトのみを定義します。

  • **データフロー**: クエリ解析フェーズ（parsenodes.h の構文木から変換）において Var、FuncExpr、SubLink 等のプリミティブノードが生成され、プランナーフェーズを経て SubPlan や実行用式ツリーに書き換えられ、最終的にエグゼキューターへ渡されます。

読者向けメモ

  • **メモリ管理**: ここで定義されるすべてのノードは PostgreSQL のメモリコンテキスト上で割り当てられ、明示的な個別 pfree よりもコンテキスト単位の解放に依存します。
  • **Query Jumble 属性**: 各種ノードフィールドには pg_node_attr(query_jumble_ignore) や pg_node_attr(equal_ignore) などのマクロ属性が付与されており、正規化されたクエリハッシュ（pg_stat_statements 等）や等価性比較（equal()）の挙動を制御します。
