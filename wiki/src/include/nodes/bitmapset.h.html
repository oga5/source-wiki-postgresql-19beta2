src/include/nodes/bitmapset.h

概要

非負整数の集合を効率的に表現・操作するための汎用ビットマップセット（Bitmapset）パッケージを定義するヘッダーファイルです。主にプランナやオプティマイザなどで、少数〜数百程度までの整数集合を扱うために使用されます。

モジュール内での役割

src/include/nodes サブシステムの一部として、ノード構造体の一つである Bitmapset のデータ表現と公開関数を提供します。実体の実装は対となる src/backend/nodes/bitmapset.c に存在します。

責務

  • ポインタサイズ（32-bit または 64-bit）に応じた最適なビットワード型（bitmapword / signedbitmapword）および関連マクロの定義。
  • 空集合を NULL ポインタで表現する規約の下での Bitmapset 構造体の定義。
  • 集合演算（和、積、差）、要素の追加・削除、部分集合の比較、およびイテレーションを行うための関数群の宣言。
  • ハッシュテーブルのキーとして Bitmapset を利用するためのハッシュ関数および比較関数の宣言。

重要なシンボル

  • bitmapword / signedbitmapword: ビットマップのワードを構成する符号なしおよび符号付き整数型（ポインタサイズに応じて 32-bit または 64-bit）。
  • Bitmapset: 可変長配列のワード群を持つ PostgreSQL ノード構造体。
  • BMS_Comparison: 2つの集合の包含関係を比較する列挙型（BMS_EQUAL, BMS_SUBSET1, BMS_SUBSET2, BMS_DIFFERENT）。
  • BMS_Membership: 集合の要素数の大まかな状態を表す列挙型（BMS_EMPTY_SET, BMS_SINGLETON, BMS_MULTIPLE）。
  • bms_is_empty(a): 集合が空（NULL）であるかを高速に判定するマクロ。

制御フローとデータフロー

  • ヘッダーファイルであるため直接的な制御フローは持ちませんが、呼び出し元コードは集合操作関数（例: bms_add_member や bms_union）の結果を元のポインタに再代入するデータフロー規約に従う必要があります（インプレース変更とは限らないため）。
  • ワードサイズに応じたビット操作マクロ（bmw_leftmost_one_pos, bmw_rightmost_one_pos, bmw_popcount）がプラットフォームに応じて切り替わり、内部のビットスキャンや要素数カウント処理を効率化します。

直接依存

  • nodes/nodes.h: NodeTag などの基本ノード定義。

関連コード

  • src/backend/nodes/bitmapset.c: 本ヘッダーで宣言されているすべての関数および内部ヘルパーの実装ファイル。
  • src/include/nodes/nodes.h: PostgreSQL のノード基盤定義。

読者向けメモ

  • 空集合は必ず NULL として表現され、末尾のワードに 0 が含まれないという不変条件（invariant）があります。
  • 破壊的な変更を行う関数は新しいポインタを返す場合があるため、返り値の取り扱いに注意してください。
