src/include/nodes/nodes.h

概要

PostgreSQLのクエリツリー、プランツリー、および式木を構成する「タグ付きノード（Tagged Nodes）」の基盤定義を提供するヘッダーファイル。すべてのノードの共通プレフィックスである NodeTag と Node 構造体を定義し、ノードの生成、型キャスト、型判定を行うマクロやインライン関数を集約している。また、パーサー、プランナー、エクスキューター間で共通利用される各種の基本列挙型（CmdType, JoinType, AggStrategy など）を定義する。

モジュール内での役割

src/include/nodes モジュールの根幹をなすヘッダーであり、後続の専門的なノード定義ファイル（parsenodes.h, plannodes.h, primnodes.h, pathnodes.h など）が必要とする共通のプリミティブとメタデータ属性マクロを提供する。

責務

  • すべてのノードの識別子である NodeTag および基底構造体 Node の定義。
  • ノードの安全な動的割当て・型検査・キャストを行うマクロ／インライン関数の提供（newNode, makeNode, IsA, castNode）。
  • コード生成ツール（gen_node_support.pl）用のメタデータ属性マクロ pg_node_attr の定義。
  • パーサーとプランナー／エクスキューターの間で共有される共通列挙型（コマンド種別、結合種別、集約戦略、集合演算戦略など）および基本型エイリアス（ParseLoc, Selectivity, Cost, Cardinality）の提供。

重要なシンボル

コアノード基盤

  • enum NodeTag
  • すべてのノード型を識別する列挙型。先頭の T_Invalid = 0 に続き、nodes/nodetags.h をインクルードして全ノードのタグを定義する。
  • struct Node
  • すべてのノード構造体の先頭に配置される基底構造体。NodeTag type のみを持ち、ポインタを Node * にキャストすることで任意のノードのタグにアクセス可能にする。
  • macro makeNode / inline function newNode
  • newNode は指定サイズ（size_t）のメモリを palloc0 でゼロ初期化確保し NodeTag を設定する。makeNode(_type_) はこれをラップし、型サイズと対応する T_##_type_ を渡して安全にノードインスタンスを生成する。
  • macro IsA
  • ノードポインタのタグが指定した型と一致するかを判定する。
  • inline function castNodeImpl / macro castNode
  • アサート有効時は nodeTag(ptr) == type を検証した上でキャストを行い、無効時は直接キャストする。

属性マクロと共通型

  • macro pg_node_attr
  • ノード定義やフィールド定義に対して gen_node_support.pl 向けのメタ属性（abstract, no_copy, array_size 等）を付与するための空マクロ。
  • typedef ParseLoc
  • ソーステキスト内の位置情報を表す int 型のエイリアス。未指定時は -1。
  • typedef Selectivity, Cost, Cardinality
  • クルーズ選択率、実行コスト、行数見積もりを表す double 型のエイリアス。

クエリ・プラン共通列挙型

  • enum CmdType
  • クエリまたは PlannedStmt が表す操作の種別（CMD_SELECT, CMD_INSERT, CMD_UPDATE, CMD_DELETE, CMD_MERGE, CMD_UTILITY など）。
  • enum JoinType
  • リレーション結合のセマンティクスを定義する（JOIN_INNER, JOIN_LEFT, JOIN_FULL, JOIN_RIGHT, JOIN_SEMI, JOIN_ANTI など）。
  • macro IS_OUTER_JOIN
  • 指定された JoinType が外部結合（およびアンチ結合系）に該当するかを判定する。
  • enum AggStrategy
  • 集約プランノードの実行戦略（AGG_PLAIN, AGG_SORTED, AGG_HASHED, AGG_MIXED）。
  • enum AggSplit
  • 部分集約の分割モード（AGGSPLIT_SIMPLE, AGGSPLIT_INITIAL_SERIAL, AGGSPLIT_FINAL_DESERIAL）。
  • enum SetOpCmd, enum SetOpStrategy
  • 集合演算（Intersect/Except）のセマンティクスと実行戦略。
  • enum OnConflictAction, enum LimitOption
  • ON CONFLICT 句のアクションおよび LIMIT 句のオプション。

制御フローとデータフロー

本ファイルは純粋な型定義・マクロ・インライン関数のヘッダーであり、複雑な制御フローは持たない。

  • ノード生成フロー: makeNode(Type) が呼ばれると、内部で newNode(sizeof(Type), T_Type) が実行され、palloc0 によりヒープメモリが割り当てられ type フィールドが初期化される。メモリのライフサイクルは通常、メモリーコンテキスト（MemoryContext）によって管理される。
  • 型安全検査フロー: デバッグ有効時の castNode(Type, ptr) は、castNodeImpl を経由して ptr の NodeTag が予期された型と一致することをアサートで検証する。

直接依存

  • nodes/nodetags.h (NodeTag 列挙体の内包展開元)

関連コード

  • src/include/nodes/parsenodes.h, src/include/nodes/plannodes.h, src/include/nodes/primnodes.h (本ファイルで定義された列挙型や Node を継承する実際のノード群)
  • src/backend/nodes/nodeFuncs.c (ノード操作の共通実装)

読者向けメモ

  • ABIとノード番号: NodeTag の途中の値にノードを挿入・削除すると、既存のリリース済みモジュールとの間でABI互換性が破壊されるため、リリースブランチでの変更には nodetag_number(VALUE) 属性等を用いた慎重な配慮が必要となる。
  • メモリ所有権: newNode が割り当てるノードはすべて PostgreSQL の MemoryContext 基盤に依存しており、個別の pfree よりもコンテキスト単位の解放が前提となっている。
