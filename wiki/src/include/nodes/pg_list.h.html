src/include/nodes/pg_list.h

概要

PostgreSQL の汎用リストパッケージのインターフェースを定義するヘッダーファイルです。歴史的な名残（Lisp 風の cons セルによる実装）から List や ListCell という名称や用語が使われていますが、内部構造はシンプルで拡張可能な配列（expansible array）として実装されています。

モジュール内での役割

src/include/nodes サブシステムの一部として、構文木（parsenodes）、プラン（plannodes）、実行時ノード（execnodes）など、PostgreSQL のあらゆる場所で大量に使用されるデータ構造を提供します。ノード表現およびリスト操作の基盤となります。

責務

  • 4種類のリスト型（ポインタ用 T_List、整数用 T_IntList、OID用 T_OidList、トランザクションID用 T_XidList）のデータ構造定義。
  • 空リストを表現する一意の値 NIL（NULL ポインタ）の定義。
  • リストの走査、要素の参照、構築を行うためのインライン関数およびマクロ群の提供。
  • バックエンド側の実装（src/backend/nodes/list.c）で提供される変更・検索・結合・削除・解放・ソート関数の外部宣言。

重要なシンボル

データ構造・共通定義

  • ListCell: 各要素の値を格納する共用体（ptr_value, int_value, oid_value, xid_value）。
  • List: リストヘッダ構造体。NodeTag type, int length, int max_length, ListCell *elements, およびインライン確保用の initial_elements を保持する。
  • NIL: 空リストを表すマクロ（((List *) NULL)）。
  • ループ制御ステート構造体: ForEachState, ForBothState, ForBothCellState, ForThreeState, ForFourState, ForFiveState。

インラインアクセサ関数と値取得マクロ

  • セル位置取得: list_head, list_tail, list_second_cell, list_length, list_nth_cell, list_last_cell, lnext, list_cell_number。
  • 要素値参照マクロ: lfirst, lfirst_int, lfirst_oid, lfirst_xid, lfirst_node。
  • 先頭・インデックス指定参照マクロ: linitial*, lsecond*, lthird*, lfourth*, llast*。
  • Ｎ番目の要素取得: list_nth, list_nth_int, list_nth_oid, list_nth_node。

ループマクロ群

  • 単一リスト走査: foreach, for_each_from, for_each_cell, foreach_ptr, foreach_int, foreach_oid, foreach_xid, foreach_node。
  • 複数リスト同時走査: forboth, for_both_cell, forthree, forfour, forfive。
  • ループ操作ユーティリティ: foreach_delete_current, foreach_current_index。

リスト操作関数（宣言のみ）

  • 構築・追加: list_make1_impl 等、lappend*, lcons*, list_insert_nth*。
  • 結合・切詰・コピー: list_concat, list_concat_copy, list_truncate, list_copy*。
  • 検索・メンバー判定: list_member*。
  • 削除: list_delete*, list_delete_first, list_delete_last, list_delete_nth_cell, list_delete_cell。
  • 集合演算: list_union*, list_intersection*, list_difference*。
  • 重複排除・一意追加: list_append_unique*, list_concat_unique*, list_deduplicate_oid。
  • メモリ解放: list_free, list_free_deep。
  • ソート: list_sort, list_int_cmp, list_oid_cmp。

制御フローとデータフロー

  • **リストの表現とレイアウト**: 空リストは必ず NIL（NULL）です。非空リストは List ヘッダを持ちます。小規模なリストの場合、initial_elements 柔軟配列メンバーを利用してヘッダと同じメモリブロック内にセルをインライン配置し、動的な追加が発生した際に elements が再割り当てされたヒープ配列を指すように最適化されます。
  • **走査制御フロー**: foreach などのマクロは、対応する ForEachState 構造体をループ初期化時に生成し、インデックス i をインクリメントしながら elements[i] のアドレスを cell 変数へバインドします。
  • **データフロー（変更系）**: lappend や lcons などのリストを変更する関数は、pg_nodiscard 属性が付与されており、再割り当ての結果として新しいリストポインタ（または既存の拡張されたリストポインタ）を返すため、呼び出し側は戻し値を再代入する必要があります。

直接依存

  • nodes/nodes.h: ノードタグ（NodeTag）および castNode などの基礎定義。

関連コード

  • src/backend/nodes/list.c: 本ヘッダーで宣言されているすべての非インライン関数（追加、削除、ソート、メモリ解放等）の実装ファイル。
  • src/include/nodes/nodes.h: PostgreSQL のノード基盤定義。

読者向けメモ

  • **メモリ所有権**: list_free() はリストヘッダおよび要素配列を解放しますが、格納されているポインタ先（ノード等）は解放しません。ノードも含めて再帰的に解放したい場合は list_free_deep() を使用します。
  • **変更時の注意**: ループ中（foreach など）にリストの要素を削除する場合は、リスト構造を壊さないように専用の foreach_delete_current() マクロを使用する義務があります。勝手に他の削除関数を呼ぶと状態が同期しなくなります。
  • **型の選択**: T_List（汎用ポインタ）、T_IntList（整数）、T_OidList（OID）、T_XidList（トランザクションID）の型ミスマッチを防ぐため、用途に応じた専用のマクロおよび関数（_int, _oid 付き）を必ず使用してください。
