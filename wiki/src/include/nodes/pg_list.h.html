src/include/nodes/pg_list.h

概要

PostgreSQL の汎用リストパッケージのインターフェースを定義するヘッダーファイルです。歴史的には Lisp の cons セルに由来しますが、パフォーマンス改善のため、現在の内部実装はシンプルな拡張可能配列（expansible array）となっています。

モジュール内での役割

src/include/nodes サブシステムの一部として、パーサー、プランナー、エクゼキューターなど PostgreSQL のあらゆる場所で使用される基本データ構造を提供します。nodes/nodes.h を直接インクルードし、ノード機構全体の基盤を支えています。

責務

  • リスト構造体（List）およびセル共用体（ListCell）の定義。
  • ポインタ、整数（int）、OID、トランザクションID（TransactionId）の4種類のリストタイプのサポート。
  • 空リストを明示する NIL マクロの提供（空リストは常に NULL ポインタとして表現されます）。
  • ループ用のステート構造体（ForEachState やマルチリスト用ステート）と、それらを安全・効率的に走査するための各種マクロの提供。
  • リストの操作（作成、要素の追加・削除、連結、コピー、ソートなど）を行うバックエンド関数群の宣言。

重要なシンボル

コアデータ構造と型定義

  • ListCell
  • ポインタ、整数、OID、トランザクションIDのいずれかの値を保持する共用体。
  • List
  • リストのヘッダー構造体。リストの種類（NodeTag type）、現在の要素数（length）、確保された最大長（max_length）、セル配列へのポインタ（elements）、およびインライン領域（initial_elements）を保持します。

ループ用ステート構造体

  • ForEachState
  • 単一リストを走査するための状態を保持する構造体（対象リストと現在のインデックス）。
  • ForBothState
  • 2つのリストを同時に走査するための共通インデックス状態を保持する構造体。
  • ForBothCellState
  • 2つのリストを個別のインデックスで同時に走査するための状態を保持する構造体。
  • ForThreeState
  • 3つのリストを同時に走査するための状態を保持する構造体。
  • ForFourState
  • 4つのリストを同時に走査するための状態を保持する構造体。
  • ForFiveState
  • 5つのリストを同時に走査するための状態を保持する構造体。

リストのメモリ管理と要素削除関数

  • list_free
  • 指定されたリストのメモリ領域を解放します。
  • list_free_deep
  • リスト自体のメモリに加え、各要素が指す子ノード等も再帰的に深さ優先で解放します。
  • list_delete_cell
  • 指定されたセルをリストから削除し、必要に応じて配列を再割り当て・詰めて新しいリストポインタを返します。
  • list_delete_first
  • リストの最初の要素を削除し、新しいリストポインタを返します。
  • list_delete_last
  • リストの最後の要素を削除し、新しいリストポインタを返します。

制御フローとデータフロー

  • **リストの表現とレイアウト**: 空リストは必ず NIL（NULL）です。非空リストはヘッダーと拡張可能な配列を持ち、initial_elements によって小規模なリストであれば追加のメモリアロケーションを避ける最適化構造になっています。
  • **走査制御（foreach 系マクロ）**: ForEachState などの状態構造体を初期化し、ループ条件内で現在のセルポインタを評価・更新しながらインデックスをインクリメントします。
  • **ミューテーションの安全性**: foreach ループ中に要素を削除する場合は foreach_delete_current を使用してインデックスのズレやバグを防ぎます。また、要素の追加は安全ですが、走査中のセルポインタ自体は無効化される点に注意が必要です。
  • **エラーと不変条件**: list_nth_cell などのインライン関数では、Assert(list != NIL) や範囲チェックを行い、不正なアクセスを早期に検知します。

読者向けメモ

  • **メモリ所有権**: list_free はコンテナのみを解放し、list_free_deep は配下の要素も解放します。呼び出し側はポインタのライフサイクルに注意してください。
  • **API の歴史的背景**: lfirst() はセルから値を取り出しますが、linitial() はリストの最初のセルから値を取り出すなど、名称の歴史的経緯による差異があります。マクロ使用時は引数の型（セルかリストか）を確認してください。
