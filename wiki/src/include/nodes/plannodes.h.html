src/include/nodes/plannodes.h

概要

PostgreSQLのクエリプランツリーを構成するすべてのプランノード（Planノード群）および、エグゼキュータへ渡される最上位の文構造である PlannedStmt のデータ構造を定義するヘッダーファイルです。プランナの出力表現とエグゼキュータの入力表現のブリッジを提供し、ファイルサイズは大きいですが、クエリ実行計画の静的表現すべてを集約しています。

モジュール内での役割

src/include/nodes モジュールの一部として、parsenodes.h（構文解析・パースツリー）や pathnodes.h（最適化過程のパスツリー）の後続として位置づけられます。エグゼキュータ (src/backend/executor/) やプランナ (src/backend/optimizer/) の各ファイルから広くインクルードされ、実行計画のノード構造を定義する中核ファイルとして機能します。

責務

  • クエリプランの最上位ラッパーである PlannedStmt の構造定義。
  • すべてのプランノードの抽象基底である Plan 構造体の定義。
  • スキャン系、結合系、集約・ソート系、および変更系（ModifyTable等）の具体的なプランノード構造体の提供。
  • パーティションプルーニング（PartitionPruneInfo 等）や行ロック（PlanRowMark）といった、実行時最適化・制御構造の定義。

重要なシンボル

制御文・文ヘッダー

  • PlannedStmtOrigin: プランの由来（内部生成、標準、キャッシュ等）を示す列挙型。
  • PlannedStmt: 計画全体のルートノード。Plan ツリー、範囲テーブル (rtable)、依存関係などを保持。

抽象基底およびマクロ

  • Plan: すべてのプランノードが先頭に持つ共通の抽象基底構造体。コスト、行数見積もり、ターゲットリスト、lefttree/righttree を保持。
  • innerPlan(node) / outerPlan(node): それぞれ righttree および lefttree を型キャストして取得するマクロ。
  • exec_subplan_get_plan(plannedstmt, subplan): SubPlan ノードに対応する Plan を取得するマクロ。

スキャン系ノード群

  • Scan: すべてのリレーションスキャンの抽象基底（scanrelid を保持）。
  • SeqScan, SampleScan, IndexScan, IndexOnlyScan, BitmapIndexScan, BitmapHeapScan, TidScan, TidRangeScan, SubqueryScan, FunctionScan, ValuesScan, TableFuncScan, CteScan, NamedTuplestoreScan, WorkTableScan, ForeignScan, CustomScan: 各種スキャン操作を表現する構造体。

結合系・集約系・その他の演算ノード群

  • Join: 結合ノードの抽象基底（jointype, joinqual を保持）。
  • NestLoop, MergeJoin, HashJoin: 各種結合アルゴリズムを表す構造体。
  • Result, ProjectSet, ModifyTable, Append, MergeAppend, RecursiveUnion, BitmapAnd, BitmapOr: 行の生成・変更・合流を行う構造体。
  • Material, Memoize, Sort, IncrementalSort, Group, Agg, WindowAgg, Unique, Gather, GatherMerge, Hash, SetOp, LockRows, Limit: 中間処理・制御・集計を行う構造体。

補助・パーティション・ロック関連

  • RowMarkType / PlanRowMark: 行ロック（SELECT FOR UPDATE 等）および EvalPlanQual のためのプラン時表現。
  • PartitionPruneInfo, PartitionedRelPruneInfo, PartitionPruneStepOp, PartitionPruneStepCombine: 実行時パーティションプルーニングの詳細情報。
  • PlanInvalItem: syscache 無効化機構と連携するための依存オブジェクト情報。

制御フローとデータフロー

  • **データの流れ**: プランナは Query ツリーから Path ツリーを構築し、最終的に PlannedStmt でラップされた Plan ツリーを生成します。エグゼキュータは ExecutorStart / ExecutorRun においてこのツリーを再帰的にトラバースし、outerPlan() / innerPlan() マクロを経由して子ノードからタプルを受け取り、ターゲットリストや qual（評価条件）を適用しながら処理を進めます。
  • **パラメータとプルーニング**: Plan 内の extParam / allParam ビットマップや、PartitionPruneInfo に含まれるステップ情報は、実行時の再スキャンやパーティションスキップ（プルーニング）の制御データとしてエグゼキュータによって解釈されます。

読者向けメモ

  • **メモリ所有権・等価性**: PlannedStmt や各 Plan 構造体、および PlanRowMark 等の多くは pg_node_attr(no_equal, no_query_jumble) 属性が付与されており、equal() 関数やクエリジャムルによる比較はサポートされていません。通常、CurrentMemoryContext 上で割り当てられます。
  • **可変長配列**: MergeAppend, MergeJoin, Sort, Agg, WindowAgg などの構造体には pg_node_attr(array_size(...)) が指定された動的配列（AttrNumber * や Oid *）が含まれており、ノード構造体の末尾や別領域にサイズに応じたメモリがレイアウトされます。
