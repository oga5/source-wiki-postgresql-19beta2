src/include/nodes/plannodes.h

概要

PostgreSQLのクエリプランツリー構造および実行時プランのルートを定義するヘッダーファイルである。プランナが出力する全ノード（PlannedStmt、Plan、各種スキャン、結合、集約、変更系ノード、パーティションプルーニング情報など）のC構造体表現を提供する。

モジュール内での役割

src/include/nodes/ サブシステムの一部として位置づけられ、構文解析木 (parsenodes.h) やプリミティブ式 (primnodes.h) と、実行時ノード (execnodes.h) の中間に位置する。オプティマイザが生成したプラン構造を定義し、エグゼキュータがそれを解釈して実行するための基盤データ型を提供する。

責務

  • **プランのルート定義**: クエリ実行計画全体のコンテナである PlannedStmt の定義。
  • **抽象プラン基底**: 全プランノードの共通基底である Plan 構造体の定義と、innerPlan/outerPlan アクセスマクロの提供。
  • **物理プランノードの網羅**: スキャン、結合、ソート、集約、ウィンドウ関数、変更系（INSERT/UPDATE/DELETE/MERGE）などの各物理オペレータノードの定義。
  • **最適化・管理用補助構造体**: パーティションプルーニング (PartitionPruneInfo 等)、行ロック (PlanRowMark)、無効化情報 (PlanInvalItem) の提供。

重要なシンボル

プランルートと基底

  • **PlannedStmt**: プランナの出力ツリーのヘッド。コマンド種別、ランタイム情報、レンジテーブル (rtable)、サブプラン、依存関係などを保持する。
  • **Plan**: 全プランノードの抽象スーパーカラス。コスト見積もり、行数・幅の見積もり、ターゲットリスト (targetlist)、修飾条件 (qual)、子プラン (lefttree/righttree)、パラメータ依存関係 (extParam/allParam) を持つ。

スキャンノード群

  • **Scan**: すべてのリレーションスキャンノードの抽象基底（Scanrelid を保持）。
  • **SeqScan**: シーケンシャルスキャンを実行するノード。
  • **SampleScan**: テーブルサンプリング（TABLESAMPLE）を実行するノード。
  • **IndexScan**: インデックススキャン（ヒープアクセスを伴う）を実行するノード。
  • **IndexOnlyScan**: インデックスのみからタプルを回収するノード。
  • **BitmapIndexScan**: タプル位置のビットマップを生成するインデックススキャンノード。
  • **BitmapHeapScan**: ビットマップを使用してヒープからタプルをフェッチするノード。
  • **TidScan / TidRangeScan**: CTIDまたはCTID範囲に基づくタプル直接スキャンノード。
  • **SubqueryScan**: サブクエリの出力をスキャンするノード。
  • **FunctionScan / ValuesScan / TableFuncScan**: 関数、VALUESリスト、テーブル関数をスキャンするノード。
  • **CteScan / WorkTableScan / NamedTuplestoreScan**: 一時リレーションやCTE、再帰ワークテーブルをスキャンするノード。
  • **ForeignScan / CustomScan**: 外部データラッパー（FDW）やカスタム拡張によるスキャンを実行するノード。

結合ノード群

  • **Join**: 結合ノードの抽象基底。結合種別 (jointype) や結合条件 (joinqual) を保持。
  • **NestLoop / NestLoopParam**: ネステッドループ結合と、外部行から内部プランへ値を渡すパラメータ構造。
  • **MergeJoin**: ソート済み入力に対するマージ結合ノード。
  • **HashJoin**: ハッシュテーブルを用いたハッシュ結合ノード。

集約・ソート・その他演算ノード

  • **Result**: 外部プランを持たない定数評価、または外部プランに対する射影・ゲーティングを行うノード。
  • **ProjectSet**: 集合返却関数（SRF）を含む射影を外部プラン出力に適用するノード。
  • **ModifyTable**: 外部プランの行を対象テーブルへ挿入・更新・削除・マージするノード。
  • **Append / MergeAppend**: 複数サブプランの結果の単純結合、あるいはソート順序を維持したマージノード。
  • **RecursiveUnion**: 再帰的結合（WITH RECURSIVE）のためのノード。
  • **BitmapAnd / BitmapOr**: 複数のタプルビットマップの積集合・和集合を計算するノード。
  • **Material**: タプルをメモリー/ディスクにマテリアライズするノード。
  • **Memoize**: パラメータ化されたスキャンの結果をキャッシュするノード。
  • **Sort / IncrementalSort**: ソートおよびインクリメンタルソートを実行するノード。
  • **Group**: グループ化を実行するノード（プレソート済み入力前提）。
  • **Agg**: 通常またはグループ化集約を実行するノード。
  • **WindowAgg**: ウィンドウ関数演算を実行するノード。
  • **Unique**: 重複排除を行うノード。
  • **Gather / GatherMerge**: パラメータ化された並列ワーカーからの結果を収集・マージするノード。
  • **Hash**: ハッシュ結合用のハッシュテーブル構築ノード。
  • **SetOp**: 集合演算（UNION/INTERSECT/EXCEPT）を行うノード。
  • **LockRows**: 行ロック（FOR UPDATE/SHARE）を明示的に取得するノード。
  • **Limit**: OFFSET/LIMITによる行数制限を行うノード。

管理・プルーニング・行マーク構造体

  • **PlanRowMark**: SELECT FOR UPDATE/SHARE クエリにおける非ターゲットリレーションの行マーク情報のプラン時表現。
  • **PartitionPruneInfo / PartitionedRelPruneInfo / PartitionPruneStep / PartitionPruneStepOp / PartitionPruneStepCombine**: 実行時パーティションプルーニングを行うためのマップおよびステップ定義。
  • **PlanInvalItem**: 依存するシステムカタログキャッシュのエントリを追跡するための無効化アイテム。
  • **SubPlanRTInfo**: サブクエリプランサイクルとレンジテーブルエントリの対応情報。
  • **ElidedNode**: プラン最適化（setrefs処理）により削除されたノードの記録。

制御フローとデータフロー

  • **エントリーポイント**: プランナ（subplan.c や planner.c）がクエリツリーから PlannedStmt を構築する。
  • **プランツリーの走査**: エグゼキュータは PlannedStmt->planTree をルートとして持ち、各 Plan ノードの lefttree (outerPlan) および righttree (innerPlan) を辿ることでツリーを再帰的に実行する。
  • **パラメータ伝播**: NestLoopParam や extParam / allParam ビットマップを介して、外部プランノードから内部プランノードへ実行時パラメータ（PARAM_EXEC）が伝播される。
  • **パーティションプルーニング**: 実行時、Append ノード等の part_prune_index を通じて PartitionPruneInfo が参照され、動的に不要なパーティションサブプランが除外される。

直接依存

  • access/sdir.h: スキャン方向（ScanDirection）の定義。
  • access/stratnum.h: ストラテジー番号の定義。
  • nodes/bitmapset.h: ビットマップセット操作関数とデータ構造。
  • nodes/lockoptions.h: ロック強度およびポリシーの定義。
  • nodes/primnodes.h: 式、変数（Var）、演算子などのプリミティブノード定義。

関連コード

  • src/include/nodes/execnodes.h: 実行時エグゼキュータの状態構造体。
  • src/include/nodes/pathnodes.h: プラン作成前のパスツリー構造。
  • src/backend/executor/: プランノードを実際に実行するエグゼキュータの実装コード。

読者向けメモ

  • **メモリ所有権**: すべてのプランノード構造体は通常、プルーニングやクエリ計画を通じて CurrentMemoryContext またはそれに準ずる長寿命のメモリコンテキスト上に割り当てられる。
  • **構造体のキャスト保証**: すべての物理プランノードは先頭フィールドに Plan type または Scan scan を持っており、ジェネリックな Plan * ポインタへ安全にキャスト可能である。
  • **配列フィールド**: 可変長配列（例: MergeJoin の mergeFamilies や Sort の sortColIdx）は pg_node_attr(array_size(...)) 属性によってサイズが指定されており、コピーや直列化の際に参照される。
