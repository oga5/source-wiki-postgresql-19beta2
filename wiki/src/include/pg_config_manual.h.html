src/include/pg_config_manual.h

概要

PostgreSQLのビルド時における手動設定の設定値、リソース制限、および開発者向けのデバッグフラグを集約したヘッダーファイルです。ほとんどの設定値は稀な状況や開発目的でのみ変更されるべきものであり、変更時は再ビルドや initdb が必要となります。

モジュール内での役割

src/include モジュールに属し、ストレージサイズ、識別子の長さ、関数引数の最大数、バッファ境界、およびアサーションやValgrind連携などのデバッグ用マクロのデフォルト値を定義します。他のコアヘッダーやバックエンドのソースコードから参照され、コンパイル時定数を決定します。

責務

  • WALセグメントサイズやSLRUセグメントサイズなどのストレージ・バッファ関連定数の提供。
  • SQL識別子の最大長や関数の最大引数数などのデータベース制限値の定義。
  • プラットフォーム固有の挙動（Windowsの EXEC_BACKEND や POSIX の posix_fadvise など）の制御。
  • USE_ASSERT_CHECKING や USE_VALGRIND に連動したメモリ・キャッシュ・デバッグ関連マクロの条件付き有効化。

重要なシンボル

デバッグ・開発者向けフラグ

  • function USE_ASSERT_CHECKING (定義行 1): アサーションチェックが有効な場合に定義され、CLOBBER_FREED_MEMORY や MEMORY_CONTEXT_CHECKING、DISCARD_CACHES_ENABLED などの高度なデバッグ機能を自動的に有効化します。
  • function USE_VALGRIND (定義行 1): Valgrindクライアントリクエストを有効化し、メモリコンテキストの追跡やピンなしバッファアクセスの検出を可能にします（実行性能が低下します）。
  • function debug_discard_caches (定義行 1): キャッシュ無効化メッセージの送受信時にsyscache/relcache/relsynccacheのエントリを積極的に破棄するデバッグ用GUC (debug_discard_caches) の有効性を制御する基盤マクロ (DISCARD_CACHES_ENABLED) に寄与します。

リソース制限・ストレージ設定マクロ

  • DEFAULT_XLOG_SEG_SIZE: WALセグメントのデフォルトサイズ（16MB）。
  • SLRU_PAGES_PER_SEGMENT: SLRUセグメントあたりのページ数（32ページ / 256KB）。
  • NAMEDATALEN: SQL識別子（テーブル名・列名等）の最大長（64バイト）。
  • FUNC_MAX_ARGS: 関数に渡せる引数の最大数（100個）。
  • INDEX_MAX_KEYS: インデックスの最大列数（32列）。
  • PARTITION_MAX_KEYS: パーティションキーの最大列数（32列）。
  • MAXPGPATH: パス名バッファの標準サイズ（1024バイト）。

制御フローとデータフロー

本ファイルはプリプロセッサーのマクロ定義のみで構成されており、独自の関数や実行時制御フローは持ちません。

  • **条件分岐フロー**: USE_ASSERT_CHECKING や USE_VALGRIND の定義状態に基づき、CLOBBER_FREED_MEMORY や MEMORY_CONTEXT_CHECKING、DISCARD_CACHES_ENABLED、DEBUG_NODE_TESTS_ENABLED などの下位マクロがカスケード式に有効化されます。
  • **プラットフォーム依存フロー**: WIN32 マクロの有無により、EXEC_BACKEND や DEFAULT_PGSOCKET_DIR の値が分岐します。

直接依存

  • ソース内に直接の #include ディレクティブはありません（純粋なマクロ定義ファイル）。

関連コード

  • src/backend/utils/cache/inval.c: DISCARD_CACHES_ENABLED によって制御されるキャッシュ無効化メッセージ処理 (AcceptInvalidationMessages) が実装されています。
  • src/include/postgres.h: 本ファイルの定数や設定を取り込み、全体的な型定義や環境構築を行います。

読者向けメモ

  • **変更の影響**: NAMEDATALEN、INDEX_MAX_KEYS、SLRU_PAGES_PER_SEGMENT などの変更には initdb が必須です。また、FUNC_MAX_ARGS などの変更にはバックエンド全体の完全な再ビルドが必要です。
  • **パフォーマンスへの影響**: USE_VALGRIND や RANDOMIZE_ALLOCATED_MEMORY などのデバッグフラグはパフォーマンスを著しく低下させるため、通常の本番ビルドでは有効にすべきではありません。
