src/include/portability/instr_time.h

概要

src/include/portability/instr_time.h は、プラットフォーム固有の間隔計測（ハイパフォーマンスタイミング）の詳細を隠蔽するためのポータブルな抽象化レイヤーを提供するヘッダーファイルです。x86系アーキテクチャでは RDTSC/RDTSCP 命令を直接使用し、Unix系システムでは clock_gettime()、Windowsでは QueryPerformanceCounter() を用いる実装を統一されたマクロおよびインライン関数群を通じて提供します。

モジュール内での役割

src/include/portability モジュール内の中心的な存在であり、バックエンドおよびフロントエンドプログラム全体で一貫した時間計測・間隔計算の基盤となります。ペアとなる src/common/instr_time.c と協調して動作し、初期化やクロックソース切り替えのロジックを支えます。

責務

  • 型定義と抽象化: instr_time 構造体を定義し、内部表現（プラットフォーム固有のティック数）を隠蔽する。
  • プラットフォーム別計測の隠蔽: POSIX系、Windows系、x86 TSCそれぞれの差異を吸収し、pg_get_ticks() や pg_get_ticks_fast() などの統一された入口を提供する。
  • ティック・ナノ秒間変換: 固定小数点演算スケーリング (TICKS_TO_NS_SHIFT) を用いて、オーバーフローを回避しながらティック値をナノ秒単位へ相互変換する。
  • マクロによる演算インターフェース: INSTR_TIME_ADD や INSTR_TIME_GET_MILLISEC などの豊富なマクロを通じて、間隔計測や加算・比較操作を提供する。

重要なシンボル

コアデータ型とソース選択

  • struct instr_time: プラットフォーム固有の単位で時間を保持する int64 ticks をラップした不透明な構造体。
  • enum TimingClockSourceType: 利用可能なクロックソースの種類（TIMING_CLOCK_SOURCE_AUTO, TIMING_CLOCK_SOURCE_SYSTEM, TIMING_CLOCK_SOURCE_TSC）を定義する列挙型。
  • struct TscClockSourceInfo: TSCクロックソースの周波数や情報、キャリブレーション結果を保持する構造体。
  • function TIMING_CLOCK_SOURCE_AUTO / TIMING_CLOCK_SOURCE_SYSTEM / TIMING_CLOCK_SOURCE_TSC: クロックソース選択用の列挙子。

初期化と制御

  • function pg_current_timing_clock_source: 現在有効なタイミングクロックソースを返すインライン関数。
  • function pg_initialize_timing: タイミングインフラストラクチャを初期化する（計測マクロ利用前に必須）。
  • function pg_set_timing_clock_source: 指定されたクロックソースを設定する。

ティック・変換処理

  • function pg_get_ticks_system: システム固有のAPI（POSIXの clock_gettime または Windowsの QueryPerformanceCounter）経由で現在時刻のティックを取得する。
  • function pg_ticks_to_ns: プラットフォーム固有のティックを、スケーリングとオーバーフローガードを適用してナノ秒に変換する。
  • function pg_ns_to_ticks: ナノ秒をプラットフォーム固有のティックに逆変換する。
  • function pg_get_ticks: OOO（アウト・オブ・オーダー）実行の完了を待つ高精度な現在時刻取得関数（RDTSCP またはシステムクロック）。
  • function pg_get_ticks_fast: OOOの完了を待たずに高速に現在時刻を取得する関数（RDTSC またはシステムクロック）。

制御フローとデータフロー

1. 初期化: 呼び出し元が pg_initialize_timing() を呼び出し、内部状態を初期化します。 2. 時刻取得: INSTR_TIME_SET_CURRENT(t) または INSTR_TIME_SET_CURRENT_FAST(t) が実行されると、内部で pg_get_ticks() / pg_get_ticks_fast() が呼ばれます。

  • timing_tsc_enabled が有効な場合は、pg_rdtscp() または pg_rdtsc() によりCPUのTSC値を直接読み取ります。
  • 無効な場合、あるいは非x86環境では pg_get_ticks_system() を呼び出し、OSのAPI（clock_gettime や QueryPerformanceCounter）から時刻を取得します。

    • 3. 変換・計算: 蓄積された instr_time 同士の加算・減算・比較は、ラップされた int64 ticks に対して直接インラインで実行されます。ナノ秒やミリ秒への変換時のみ pg_ticks_to_ns() が呼び出され、必要に応じて ticks_per_ns_scaled と TICKS_TO_NS_SHIFT を用いた固定小数点演算によってオーバーフローを防ぎながら単位変換が行われます。

直接依存

  • <time.h> (非Windows環境でのシステムクロック用)
  • <intrin.h> (MSVC環境でのx86イントリンシック用、_MSC_VER 定義時)

関連コード

  • src/common/instr_time.c: 非インラインの初期化関数やTSCキャリブレーション処理の実装。
  • src/include/port/pg_cpu.h: CPU機能検出および関連する移植性マクロ。

読者向けメモ

  • メモリ所有権とライフタイム: instr_time は単純な値型（スタックまたは構造体内のメンバ）として扱われ、動的メモリ割り当てや解放のライフタイム管理はありません。
  • インライン最適化: pg_get_ticks や pg_get_ticks_fast は、GCCのインライン化ヒューリスティックの制約を回避するため pg_always_inline でマークされています。
  • GUCと実行時変更: timing_clock_source やスケーリング変数は実行時に変更可能ですが、計測中に変更すると不正な結果を招くため注意が必要です。
