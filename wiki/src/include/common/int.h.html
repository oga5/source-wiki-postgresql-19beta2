src/include/common/int.h

概要

src/include/common/int.h は、PostgreSQLにおけるオーバーフロー安全な整数演算および符号なし絶対値計算、符号付き・符号なし整数の比較処理を提供するヘッダーファイルです。コンパイラフラグ（-fwrapv など）への依存を排除し、C言語標準に準拠した安全かつ移植性の高い整数操作を実現しています。

モジュール内での役割

src/include/common/ ディレクトリ配下に位置し、バックエンドおよびフロントエンドの双方から共通して利用される低レベルの数値演算基盤を提供します。演算時のオーバーフロー検出をコンパイラビルトイン関数（可能なら __builtin_*_overflow）、128ビット整数、あるいは明示的な範囲チェックによって切り替える抽象化レイヤーとして機能します。

責務

  • オーバーフロー安全な算術演算: 16ビット、32ビット、64ビット、および size_t 型の符号付き・符号なし整数に対する加算、減算、乗算、および符号反転（否定）演算において、オーバーフローを確実に検出し、処理する。
  • オーバーフローフリーの絶対値計算: 負の最大値（例: INT_MIN）を含む符号付き整数を、オーバーフローを回避しながら対応する符号なし整数型へ変換する。
  • 安全な比較ルーチン: qsort() 等の比較関数で用いる、オーバーフローリスクのない整数大小比較（-1, 0, 1 の返却）を提供する。

重要なシンボル

1. size_t に関連するオーバーフロー関数のグループ

  • size_t (定義行 1): メモリサイズやアロケーション計算で多用される符号なし整数型。本ファイルでは size_t 型専用の加算・減算・乗算オーバーフロー検出関数（pg_add_size_overflow など）の対象型として扱われます。

2. INT16 オーバーフロー・絶対値関数のグループ

  • pg_sub_s16_overflow (定義行 84): int16 型の減算 (a - b) を行い、結果を *result に格納します。オーバーフロー時は true、正常時は false を返します。
  • pg_mul_s16_overflow (定義行 102): int16 型の乗算 (a * b) を行い、オーバーフローを検出します。
  • pg_neg_s16_overflow (定義行 120): int16 型の符号反転 (-a) を行います。PG_INT16_MIN の場合は反転時にオーバーフローするため、 true を返します。
  • pg_abs_s16 (定義行 136): int16 の引数を int32 に拡幅して abs() を適用し、最終的に uint16 で返却することでオーバーフローを完全に回避します。

3. INT32 オーバーフロー・絶対値関数のグループ

  • pg_sub_s32_overflow (定義行 168): int32 型の減算処理におけるオーバーフローを検出します。
  • pg_mul_s32_overflow (定義行 186): int32 型の乗算処理におけるオーバーフローを検出します。
  • pg_neg_s32_overflow (定義行 204): int32 型の否定演算を行います。PG_INT32_MIN でオーバーフローを検出します。
  • pg_abs_s32 (定義行 220): int32 を int64 に拡幅して i64abs() を適用し、uint32 型で絶対値を返します。

4. INT64 オーバーフロー・絶対値関数のグループ

  • pg_sub_s64_overflow (定義行 261): int64 型の減算処理を行います。ビルトイン、128ビット整数（HAVE_INT128）、または手動の範囲チェックのいずれかにフォールバックします。
  • pg_mul_s64_overflow (定義行 292): int64 型の乗算処理を行います。高価な除算を避けるため、事前にオペランドの大きさをチェックする最適化が含まれています。
  • pg_neg_s64_overflow (定義行 335): int64 型の否定演算を行います。PG_INT64_MIN の場合にオーバーフローを検出します。

制御フローとデータフロー

  • オーバーフロー判定の優先順位:

    • 1. HAVE__BUILTIN_OP_OVERFLOW が定義されている環境では、コンパイラビルトイン関数（__builtin_add_overflow 等）を直接呼び出して高速に処理します。 2. ビルトインが利用できない 64 ビット演算等の環境では、HAVE_INT128 があれば 128 ビット整数（int128 / uint128）へキャストして中間計算を行い、範囲チェックを実施します。 3. それ以外の場合は、算術演算を行う前にオーバーフロー条件を事前に検証するガード節を通します。

  • エラールーティング: オーバーフローを検知した場合、関数は true を返し、呼び出し元の変数 *result には不純な警告を防ぐためのダミー値 0x5EED が書き込まれます。呼び出し側はこの戻り値（布島値）を検査してエラーパスへ分岐する必要があります。

関連コード
