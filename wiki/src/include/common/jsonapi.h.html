src/include/common/jsonapi.h

概要

PostgreSQL の JSON パーサーおよびレキサーのインタフェース定義を提供するヘッダーファイルです。バックエンドおよびフロントエンド（libpq等）の両方から利用可能な共通の JSON 解析・検証の抽象化レイヤーを定義します。

モジュール内での役割

src/include/common モジュール内において、JSON/JSONB およびテキスト解析処理の中核を担います。文字列ベースの入力からトークンを切り出し、コールバック関数群（セマンティックアクション）を介して上位レイヤーへ構造化されたイベントを通知する契約を定義しています。

責務

  • **JSON トークンおよびエラーの定義**: トークン種別（JsonTokenType）と詳細なパースエラー種別（JsonParseErrorType）の宣言。
  • **レキサー状態の管理**: 入力テキスト、位置、エスケープ処理の状態を保持する JsonLexContext 構造体とフラグの定義。
  • **セマンティックアクションの契約**: JSON の構造（オブジェクト、配列、フィールド、スカラー値）を構築・処理するためのコールバック関数型群と JsonSemAction 構造体の提供。
  • **ライフサイクルおよびユーティリティ関数の公開**: レキサーの生成・破棄、インクリメンタルパース、配列要素数のカウント、数値検証関数の宣言。

重要なシンボル

列挙型 (Enums)

  • JsonTokenType: JSON の構文要素（文字列、数値、オブジェクト、配列、真偽値、null、区切り文字など）を表現する識別子。
  • JsonParseErrorType: 成功 (JSON_SUCCESS)、不完全 (JSON_INCOMPLETE)、メモリ不足、エスケープ不正、ネスト超過、各種期待値の不一致など、パース中に発生しうるエラーの詳細な分類。

データ構造 (Structs & Typedefs)

  • JsonLexContext: JSON 入力文字列、ポインタ（現在位置、トークン開始・終端）、エンコーディング、ネストレベル、フラグ、バッファ、エラーメッセージ用文字列バッファを保持するコンテキスト構造体。
  • JsonSemAction: オブジェクトや配列の開始・終了、フィールド名、配列要素、スカラー値の各イベントに対するコールバック関数ポインタをまとめたセマンティックアクション構造体。
  • コールバック型: json_struct_action, json_ofield_action, json_aelem_action, json_scalar_action。

ライフサイクル・初期化関数

  • makeJsonLexContextCstringLen: 指定された文字列と長さ、エンコーディングに基づき JsonLexContext を初期化またはアロケートする。
  • makeJsonLexContextIncremental: インクリメンタルパース用の JsonLexContext を生成する。
  • setJsonLexContextOwnsTokens: コールバックに渡されるトークンのメモリ所有権をコンテキスト側に持たせるか設定する。
  • freeJsonLexContext: コンテキストが保持する構造体および内部バッファのメモリを解放する。

パース・検証関数

  • pg_parse_json: レキサーコンテキストを入力とし、セマンティックアクションを呼び出しながら全体をパースする。
  • pg_parse_json_incremental: チャンク単位でインクリメンタルに JSON をパースする。
  • json_count_array_elements: 配列の要素数を高速に数えるセカンダリパース関数。
  • json_errdetail: パースエラーに応じた詳細なエラー文字列を構築する。
  • IsValidJsonNumber: 文字列が有効な JSON 数値フォーマットを満たしているか検証する。

制御フローとデータフロー

1. **初期化**: 呼び出し元が makeJsonLexContextCstringLen() または makeJsonLexContextIncremental() を呼び出して JsonLexContext を作成します。必要に応じて need_escapes を有効にし、文字列のエスケープ解除を行います。 2. **パース実行**: pg_parse_json() または pg_parse_json_incremental() にコンテキストと JsonSemAction 構造体を渡します。 3. **レキシングとディスパッチ**: レキサー (json_lex()) が入力ストリームからトークンを順次読み取り、対応するセマンティックアクション（例: object_field_start や scalar）を呼び出します。 4. **エラーハンドリング**: パースエラーやセマンティックアクションの失敗（JSON_SEM_ACTION_FAILED）が発生した場合、処理は中断され、エラーコードが返されます。必要に応じて json_errdetail() で詳細情報を取得します。

直接依存

  • ヘッダー自体には直接のインクルード文はありませんが、実装側 (jsonapi.c) ではプラットフォームに応じて postgres.h または postgres_fe.h、および文字列バッファ管理として stringinfo.h や pqexpbuffer.h に依存します。

関連コード

  • src/common/jsonapi.c: 本ヘッダーで宣言されているインターフェースの実装本体。
  • src/include/common/parse_manifest.h: 類似のテキスト/JSONパース構造を利用する関連モジュール。

読者向けメモ

  • **メモリ所有権**: setJsonLexContextOwnsTokens() により、コールバックに渡されるトークンの所有権を切り替えられます。特に libpq などの長期稼働クライアントでのパース失敗時のメモリリークを防ぐため、適切な設定と解放（freeJsonLexContext()）が必要です。
  • **エスケープ処理**: need_escapes フラグが有効な場合のみ strval バッファに非エスケープ済みの文字列値が格納されます。エスケープ解除はコストが高いため、構造検証のみの用途では無効にすることが推奨されます。
