src/include/port/atomics/generic.h

概要

PostgreSQLのプラットフォーム依存の低レベルアトミック操作をベースに、不足している高レベルのアトミック操作（32ビットおよび64ビットの演算、フラグ操作、メモリバリアなど）を補完・定義するヘッダーファイルです。直接インクルードすることは意図されておらず、atomics.h を経由してインクルードされます。

モジュール内での役割

src/include/port/atomics サブシステムにおいて、特定のCPUアーキテクチャ（x86, ARM, PPCなど）やコンパイラ（GCC, MSVC）固有の最小限のプリミティブから、共通して必要とされる高度なアトミック関数群（fetch_add, compare_exchange を用いたループ処理など）を組み立てるフォールバックおよび共通化レイヤーとして機能します。

責務

  • デフォルトのバリア・遅延マクロの定義: pg_read_barrier_impl や pg_write_barrier_impl が未定義の場合にフルメモリバリアに昇格させ、pg_spin_delay_impl のデフォルトを提供する。
  • 32ビット/64ビットアトミック操作のフォールバック実装: compare_exchange などのプリミティブが存在する場合に、それらを組み合わせて fetch_add, fetch_sub, fetch_and, fetch_or, exchange などの操作をループ構成で提供する。
  • アトミックフラグの提供: 32ビットアトミックサポートに基づいて pg_atomic_flag を定義し、テスト・セット・クリア操作の標準的な実装を提供する。
  • プラットフォーム特性に応じた最適化と制約の適用: 64ビットの単一コピーアトミティ（single-copy atomicity）の有無に応じた、安全な読み書き操作の切り替えとアラインメントの検証を行う。

重要なシンボル

型定義およびデータ構造

  • pg_atomic_flag: PG_HAVE_ATOMIC_FLAG_SUPPORT が未定義かつ PG_HAVE_ATOMIC_U32_SUPPORT が定義されている場合に、pg_atomic_uint32 のエイリアスとして定義されるフラグ用データ構造。
  • pg_atomic_uint32: 32ビットアトミック変数を保持するデータ構造（実体は低レベル層で定義され、本ファイルで操作される）。
  • pg_atomic_uint64: 64ビットアトミック変数を保持するデータ構造。

アトミック読み取り・書き込みおよび比較交換

  • compare_exchange: 低レベル層で提供される比較交換プリミティブ（pg_atomic_compare_exchange_u32_impl / u64_impl）。不一致時は期待値ポインタを更新し、成功時は真を返す。
  • pg_memory_barrier_impl: メモリバリアの基本実装。クリアフラグ操作時などに順序付けを保証するために呼び出される。
  • pg_atomic_read_u32_impl: 32ビットアトミック変数のインライン読み取り関数。

演算系フォールバック関数（32ビット・64ビット共通の設計パターン）

  • fetch_add: compare_exchange によるCASループを使用し、加算前の旧値を取得しつつ変数を更新する（pg_atomic_fetch_add_u32_impl / pg_atomic_fetch_add_u64_impl）。
  • add_fetch: fetch_add の結果に加算値を足して、更新後の値を返す（pg_atomic_add_fetch_u32_impl / pg_atomic_add_fetch_u64_impl）。
  • fetch_sub / sub_fetch: 減算版の fetch_add / add_fetch（pg_atomic_fetch_sub_u32_impl 等）。
  • fetch_and / fetch_or: ビット単位の論理演算をCASループで安全に実行する関数群。
  • exchange: 値を置き換えて旧値を返す操作。比較交換ループによって実現される（pg_atomic_exchange_u32_impl 等）。

制御フローとデータフロー

1. 初期化チェック: インクルードガード（INSIDE_ATOMICS_H）により、不正な直接インクルードをコンパイルエラーで弾きます。 2. バリア・遅延のフォールバック決定: pg_read_barrier_impl や pg_write_barrier_impl が定義されていない場合、pg_memory_barrier_impl にフォールバックします。 3. 演算の自動補完フロー:

  • プラットフォームが compare_exchange のみを提供し、fetch_add や exchange を持たない場合、本ファイルは ptr->value から旧値を読み取り、compare_exchange が成功するまで while (!compare_exchange(...)) ループを回す共通パターンを適用します。
  • 64ビット書き込み・読み込みにおいては、PG_HAVE_8BYTE_SINGLE_COPY_ATOMICITY の有無を確認し、アラインメント（8バイト境界）の検証（AssertPointerAlignment）を行うか、安全のために compare_exchange / exchange ベースのシミュレーション経路へフォールバックします。

直接依存

  • atomics.h: このファイル自体をインクルードするための親ヘッダー（INSIDE_ATOMICS_H マクロを定義する）。

関連コード

  • src/include/port/atomics.h: アトミックAPI全体の総合エントリポイント。
  • src/include/port/atomics/generic-gcc.h / generic-msvc.h: コンパイラ固有の組込み関数を提供する隣接ファイル。

読者向けメモ

  • メモリ安全性とアラインメント: 64ビット変数の操作において、プラットフォームが単一コピーアトミティを保証しない環境では、CASループやエクスチェンジを介した安全なアクセスに自動で切り替わります。
  • ロックフリーのCASループ: fetch_add や exchange などの高レベル関数は、ハードウェアが直接アトミック命令を提供していない場合、内部で while による CAS ループを実行するため、高競合下でのパフォーマンス特性に注意が必要です。
