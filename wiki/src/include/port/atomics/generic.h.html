src/include/port/atomics/generic.h

概要

低レベルなアトミック操作（コンパイラ組み込み関数やプラットフォーム固有のプリミティブ）を基礎として、より高レベルなアトミック操作やフォールバック実装を提供するヘッダーファイルである。直接インクルードすることは禁止されており、atomics.h を経由してインクルードされる。

モジュール内での役割

src/include/port/atomics/ モジュールの一部として、プラットフォーム固有の低レベル操作が提供していない補助的なアトミック関数（32ビット/64ビットの演算、フラグ操作、メモリバリアのアップグレードなど）を共通のインライン関数として補完する役割を持つ。

責務

  • **バリアのデフォルト昇格**: 未定義の読み取り/書き込みバリアを、完全メモリバリア（pg_memory_barrier_impl）にフォールバック・昇格させる。
  • **スピン遅延の定義**: PG_HAVE_SPIN_DELAY が未定義の場合に何もしないマクロを定義する。
  • **フラグ操作のフォールバック**: 32ビットアトミックサポートを基に、pg_atomic_flag の型定義とテスト・セット・クリア操作を提供する。
  • **32/64ビット汎用アトミック関数の提供**: pg_atomic_compare_exchange などのプリミティブをベースにして、exchange、fetch_add、fetch_sub、fetch_and、fetch_or などの操作をループ構造により実装する。
  • **64ビット読み書きの環境依存制御**: 単一命令でのアトミック性が保証されない環境に向けた 64 ビット読み込み（CASを利用）および書き込み（アトミック交換を利用）のフォールバックを提供する。

重要なシンボル

バリアおよびスピン制御

  • pg_read_barrier_impl: 未定義時に pg_memory_barrier_impl にマップされる。
  • pg_write_barrier_impl: 未定義時に pg_memory_barrier_impl にマップされる。
  • pg_spin_delay_impl: スピンロック待機時の遅延処理（デフォルトは空）。

フラグ操作ファミリ (pg_atomic_flag)

  • pg_atomic_init_flag_impl: フラグを 0 に初期化する。
  • pg_atomic_test_set_flag_impl: アトミックな交換または比較交換を用いてフラグをセットし、以前の状態がクリアされていたかを返す。
  • pg_atomic_unlocked_test_flag_impl: ロックなしでフラグの状態を読み取り検証する。
  • pg_atomic_clear_flag_impl: メモリバリアを発行した上でフラグを 0 にクリアする。

32ビット操作ファミリ (pg_atomic_uint32)

  • pg_atomic_read_u32_impl / pg_atomic_write_u32_impl: 単純な読み書き。
  • pg_atomic_unlocked_write_u32_impl: ロックフリー/アンロック時の書き込み。
  • pg_atomic_exchange_u32_impl: compare_exchange を用いた値の交換ループ。
  • pg_atomic_fetch_add_u32_impl / pg_atomic_fetch_sub_u32_impl: 加算・減算のフェッチおよび更新ループ。
  • pg_atomic_fetch_and_u32_impl / pg_atomic_fetch_or_u32_impl: ビット演算のフェッチおよび更新ループ。
  • pg_atomic_add_fetch_u32_impl / pg_atomic_sub_fetch_u32_impl: 更新後の値を返す演算。
  • pg_atomic_read_membarrier_u32_impl / pg_atomic_write_membarrier_u32_impl: メモリバリア付きの読み書き。

64ビット操作ファミリ (pg_atomic_uint64)

  • pg_atomic_read_u64_impl: 8バイト単一コピーアトミック性がない環境では CAS（値 0 との比較交換）で安全に読み取る。ある環境ではアラインメント検証付きで直接読み取る。
  • pg_atomic_write_u64_impl: アトミック性がない環境では pg_atomic_exchange_u64_impl を経由して書き込む。
  • その他、32ビットと同様の exchange, fetch_add, fetch_sub, fetch_and, fetch_or, add_fetch, sub_fetch, メモリバリア付き操作の 64 ビット版。

制御フローとデータフロー

  • **CASベースの演算ループ**: pg_atomic_fetch_add_u32_impl や pg_atomic_exchange_u32_impl などの関数は、現在の値を ptr->value から非アトミックに読み取った後、while (!pg_atomic_compare_exchange_u32_impl(ptr, &old, new_val)) のループを回す。CASが成功するまで old は最新の値に更新され続ける。
  • **64ビット読み込みのフォールバックフロー**: PG_HAVE_8BYTE_SINGLE_COPY_ATOMICITY が定義されていない場合、pg_atomic_read_u64_impl は old = 0 で初期化し、pg_atomic_compare_exchange_u64_impl(ptr, &old, 0) を呼び出す。これにより値が変更されるのは元が 0 の場合のみであり、既存の値が old に取得される。

読者向けメモ

  • **メモリ所有権とレイアウト**: 操作対象のポインタ（ptr）は volatile pg_atomic_uint32 * または volatile pg_atomic_uint64 * であり、呼び出し側がメモリの割り当てとライフサイクルを管理する。
  • **アラインメントの前提**: 64ビット操作において PG_HAVE_8BYTE_SINGLE_COPY_ATOMICITY が有効な場合、AssertPointerAlignment(ptr, 8) により 8 バイト境界へのアラインメントが検証される。
  • **未定義エラー**: PG_HAVE_ATOMIC_TEST_SET_FLAG がどのフォールバック経路（交換または比較交換）でも満たされない場合、コンパイル時にエラー (#error "No pg_atomic_test_and_set provided") となる。
