src/include/port/atomics/arch-x86.h

概要

Intel x86/x86-64 アーキテクチャ向けの低水準アトミック操作、メモリバリア、およびスピンディレイの実装を提供するインラインアセンブリヘッダーです。コンパイラとして主に GCC や Intel コンパイラ（および条件付きで MSVC）を対象とし、TSO（Total Store Order）メモリモデルの特性を活かした効率的なプリミティブを定義します。

モジュール内での役割

src/include/port/atomics モジュール内において、x86系プラットフォーム固有のハードウェア最適化されたアトミック命令 (lock cmpxchg, lock xadd, xchgb) や PAUSE 命令を抽象化し、汎用アトミックインターフェースへ供給するバックエンドとして機能します。

責務

  • メモリバリアの提供: TSO により再順序付けが制限される範囲において、コンパイラおよびアトミック加算を用いたメモリフェンスを定義する。
  • データ型とフラグの定義: pg_atomic_flag、32ビット、64ビット（x86-64のみ）のアトミックデータ構造を宣言する。
  • スピンロック最適化: ハイパースレッディング環境での競合を緩和するスピンディレイ（PAUSE / rep nop）の実装。
  • アトミック演算の実装: テスト・セット、比較・交換（CAS）、フェッチ・加算（Fetch-and-Add）操作をインラインアセンブリで提供する。

重要なシンボル

アーキテクチャ制御・メモリバリア

  • PAUSE: スピンウェイトループ内でパイプラインフラッシュを防ぎリソース消費を抑えるためのマクロまたはアセンブリ表現。
  • __x86_64__: 64ビット環境の判定用プリプロセッサシンボル。64ビット用アトミック構造体や cmpxchgq / xaddq の有効化を制御する。
  • cmpxchgl: 32ビットの比較・交換を行うインラインアセンブリ命令。
  • cmpxchgq: 64ビットの比較・交換を行うインラインアセンブリ命令（x86-64限定）。
  • xaddl: 32ビットの加算と値の取得をアトミックに行う命令。
  • xaddq: 64ビットの加算と値の取得をアトミックに行う命令（x86-64限定）。
  • xchgb: バイト単位の交換を行いテスト・セットを実現する命令。

データ構造

  • pg_atomic_flag: volatile char を内包し、フラグ操作をサポートする構造体 (PG_HAVE_ATOMIC_FLAG_SUPPORT)。
  • pg_atomic_uint32: volatile uint32 を内包し、32ビットアトミック操作をサポートする構造体 (PG_HAVE_ATOMIC_U32_SUPPORT)。
  • pg_atomic_uint64: volatile uint64 を内包し、64ビットアトミック操作をサポートする構造体。__x86_64__ 定義時のみ有効 (PG_HAVE_ATOMIC_U64_SUPPORT)。

操作・遅延関数

  • pg_spin_delay_impl: スピンロックのビジーウェイト時に呼び出され、rep; nop（PAUSE）を実行してプロセッサの性能低下を防ぐインライン関数。
  • pg_atomic_test_set_flag_impl: xchgb と lock プレフィックスを使い、フラグを原子的にセットして旧い値に基づいた成否を返す。
  • pg_atomic_clear_flag_impl: TSO アーキテクチャの特性を利用し、コンパイラバリアと通常の代入によってフラグをクリアする。
  • pg_atomic_compare_exchange_u32_impl: lock cmpxchgl と setz を用いて32ビット値の比較・交換を行い、成功時は expected を更新しブール値を返す。
  • pg_atomic_fetch_add_u32_impl: lock xaddl を用いて32ビット整数に値censを加算し、加算前の旧い値を取得する。
  • pg_atomic_compare_exchange_u64_impl: 64ビットポインタのアライメント（8バイト）を検証した上で、lock cmpxchgq により64ビット値の比較・交換を実行する。
  • pg_atomic_fetch_add_u64_impl: lock xaddq を用いて64ビット整数に対するアトミックな加算と旧値の取得を行う。

制御フローとデータフロー

1. 初期化と型解決: コンパイラ（GCC/Intel/MSVC）やビット数（__i386__ vs __x86_64__）に応じて、利用可能なデータ構造（pg_atomic_uint32, pg_atomic_uint64, pg_atomic_flag）が定義されます。 2. アトミック更新の実行:

  • 比較・交換系 (pg_atomic_compare_exchange_u32_impl / _u64_impl) は、expected の値をアセンブリの入力とし、lock cmpxchgl/q の実行結果（ゼロフラグ）を setz で ret 変数に格納して成否を判定します。不一致の場合は expected に実際のメモリ上の値が書き戻されます。
  • 加算系 (pg_atomic_fetch_add_u32_impl / _u64_impl) は、lock xaddl/q を呼び出し、一回の命令でメモリ上の加算とレジスタへの旧値返却をアトミックに完了させます。

    • 3. スピンウェイト: ロック獲得待ちが発生した際、pg_spin_delay_impl が呼ばれ、ハードウェアに対して PAUSE（rep nop）ヒントを送ることでパイプラインフラッシュや無駄なバス消費を回避します。

直接依存

  • ソースファイル内に直接の #include ディレクティブはありません。コンパイラ定義 (__GNUC__, __INTEL_COMPILER, _MSC_VER) およびアーキテクチャマクロに依存しています。

関連コード

  • src/include/port/atomics/generic.h: 本ファイルで定義された低水準プリミティブを受け取り、高水準のアトミックAPIを構築する共通ヘッダー。
  • src/include/port/atomics/arch-arm.h, src/include/port/atomics/arch-ppc.h: 他のアーキテクチャにおける同等層の実装。

読者向けメモ

  • メモリ順序（TSO）: x86 アーキテクチャは Total Store Order を持つため、ストア間の順序やロード間の順序がハードウェアレベルで保証されやすく、フラグクリアなどの解放セマンティクスでは重いフェンス命令ではなくコンパイラバリアのみで十分に機能します。
  • 64ビット制約: 32ビット（i386）環境では64ビットアトミック型のインラインアセンブリ実装が複雑化し性能上のメリットも薄いため、__x86_64__ が定義されている場合のみ pg_atomic_uint64 および関連関数が有効化されます。
  • アライメント: 64ビットの比較交換関数内では AssertPointerAlignment(expected, 8) により、8バイト境界のアライメントが前提条件として検証されます。
