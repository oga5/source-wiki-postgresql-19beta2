src/include/port/atomics/arch-x86.h

概要

Intel x86 アーキテクチャに特化したアトミック操作、メモリバリア、およびスピンディレイの実装を提供するヘッダーファイルです。GCC やコンパイラ拡張（__GNUC__、__INTEL_COMPILER、_MSC_VER）を用いたインラインアセンブリにより、低レベルなハードウェア命令を直接利用して効率的な並行処理プリミティブを定義しています。

モジュール内での役割

src/include/port/atomics/ モジュール群において、x86 および x86_64 アーキテクチャ固有の最適化されたバックエンドとして機能します。共通の汎用インターフェース（generic.h 等）から条件付きでインクルードされ、プラットフォーム固有のハードウェア機能を抽象化します。

責務

  • **メモリバリアの提供**: x86 の強力なメモリ順序付けモデルを活かしつつ、必要に応じたメモリバリア・コンパイラバリアのマクロを提供。
  • **アトミックデータ型の定義**: pg_atomic_flag、pg_atomic_uint32、および x86_64 環境では pg_atomic_uint64 の型定義と対応機能フラグ（PG_HAVE_ATOMIC_*）の提供。
  • **アトミック操作の実装**: テスト・セット、フラグクリア、比較・交換（CAS）、フェッチ加算などのインラインアセンブリによる低レベル実装。
  • **スピンロック待機最適化**: ハイパースレッディング環境向けの PAUSE（rep; nop / _mm_pause）命令を用いたスピンディレイ関数の提供。

重要なシンボル

メモリバリア・スピンディレイ群

  • pg_memory_barrier_impl(): lock; addl 命令を用いたフルメモリバリア。
  • pg_read_barrier_impl() / pg_write_barrier_impl(): x86 の TSO（Total Store Order）モデルに基づき、コンパイラバリアにフォールバック。
  • pg_spin_delay_impl(): スピンウェイトループ内でパイプラインフラッシュを防止するための PAUSE 命令ラッパー。

データ型とサポートフラグ

  • pg_atomic_flag: volatile char を保持するフラグ構造体（PG_HAVE_ATOMIC_FLAG_SUPPORT）。
  • pg_atomic_uint32: volatile uint32 を保持する32ビット整数構造体（PG_HAVE_ATOMIC_U32_SUPPORT）。
  • pg_atomic_uint64: 64ビットプラットフォーム（__x86_64__）限定の64ビット整数構造体（ライブラリ側でアラインメント保証、PG_HAVE_ATOMIC_U64_SUPPORT）。

アトミック演算インライン関数

  • pg_atomic_test_set_flag_impl(): xchgb 命令を用いてフラグをセットし旧値を返す。
  • pg_atomic_clear_flag_impl(): コンパイラバリアとストアによりフラグをクリア。
  • pg_atomic_compare_exchange_u32_impl() / pg_atomic_compare_exchange_u64_impl(): cmpxchgl / cmpxchgq 命令による比較・交換。
  • pg_atomic_fetch_add_u32_impl() / pg_atomic_fetch_add_u64_impl(): xaddl / xaddq 命令によるアトミック加算と旧値の取得。

制御フローとデータフロー

1. **アトミック演算の呼び出し**: 上位の汎用関数から _impl サフィックスがついたインライン関数へ処理がディスパッチされます。 2. **インラインアセンブリの実行**:

  • lock プレフィックスを伴うアセンブリ命令（cmpxchg, xadd, xchg）がプロセッサのバスロックまたはキャッシュロックを引き起こし、アトミック性を保証します。
  • 条件フラグ（Zero Flag 等）の状態を setz 命令などで char 型の戻り値や成功判定用変数（ret）にマッピングします。

    • 3. **メモリ順序の維持**: memory クラベリスタにより、コンパイラおよびCPUによるメモリアクセスの不正な並べ替えを防ぎます。

直接依存

  • ソースファイル内に直接の #include ディレクティブはありません。コンパイラ定義のマクロ（__GNUC__, __x86_64__, _MSC_VER 等）および外部から提供される pg_compiler_barrier_impl() や AssertPointerAlignment() に依存します。

関連コード

  • src/include/port/atomics/generic.h: 本ファイルが提供する低レベル実装を受け取り、上位の公開 API を構築する共通ヘッダー。

読者向けメモ

  • **メモリモデルの前提**: x86 は TSO（Total Store Order）を採用しているため、ロード・ストアの順序付けに関して緩やかなアーキテクチャに比べバリア命令のコストが低くなっています。
  • **64ビット制限**: 32ビット x86 環境では 64ビットアトミック操作や 64ビット構造体（pg_atomic_uint64）のインライン実装は除外されます（32ビット環境での64ビットアトミックは複雑さとハードウェア制限のため）。
  • **アラインメント**: pg_atomic_compare_exchange_u64_impl では AssertPointerAlignment(expected, 8) により、期待値ポインタの8バイト整列が検証されます。
