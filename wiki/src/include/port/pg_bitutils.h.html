src/include/port/pg_bitutils.h

概要

src/include/port/pg_bitutils.h は、プラットフォーム非依存のビット操作ユーティリティを提供するヘッダーファイルです。最上位/最下位ビットの検索、2の冪乗への切り上げ・切り下げ、対数計算 (ceil(log2))、およびバッファ内のビットカウント (popcount) をインライン関数および最適化された関数群として提供します。

モジュール内での役割

src/include/port モジュールの一部として、コンパイラ組み込み関数 (__builtin_clz, __builtin_ctz) や MSVC イントリンシック (_BitScanReverse, _BitScanForward) を抽象化し、ポータブルなフォールバック実装とともに PostgreSQL 全体に統一されたビット操作インターフェースを提供します。対応する実装ファイル src/port/pg_bitutils.c と連携します。

責務

  • 最上位セットビット（左端）および最下位セットビット（右端）の位置を 32 ビット・64 ビット整数に対して計算する。
  • 指定された数値に対する 2 の冪乗の算出（次/前）および 2 の底の対数切り上げ (ceil(log2)) を行う。
  • バッファ全体またはマスク適用済みのバイト列に対する 1 ビットの数（popcount）を効率的に計算する。
  • MSVC や各種コンパイラの組み込み関数の有無に応じたマクロ定義と条件付きコンパイルの隠蔽を行う。

重要なシンボル

ビット位置検索・冪乗・対数演算

  • pg_leftmost_one_pos32 / pg_leftmost_one_pos64: 32/64ビット符号なし整数の最上位セットビットの位置を返す。word != 0 の不変条件を持つ。
  • pg_rightmost_one_pos32 / pg_rightmost_one_pos64: 32/64ビット符号なし整数の最下位セットビットの位置を返す。
  • pg_nextpower2_32 / pg_nextpower2_64: 引数 num 以上で最小の 2 の冪乗を返す。0 および PG_UINT32_MAX / 2 + 1 超過をアークで弾く。
  • pg_prevpower2_32 / pg_prevpower2_64: 引数 num 以下で最大の 2 の冪乗を返す。

ルックアップテーブルとポータブル変数

  • pg_leftmost_one_pos: 各バイト値（0-255）の左端セットビット位置を格納する定数配列（pg_bitutils.c で定義）。
  • pg_number_of_ones: 各バイト値の 1 ビット数を格納する定数配列。
  • pg_popcount_optimized / pg_popcount_masked_optimized: ハードウェア最適化された popcount 関数への関数ポインタ（または直接関数）。

制御フローとデータフロー

1. ビット位置の検索: コンパイラが HAVE__BUILTIN_CLZ / HAVE__BUILTIN_CTZ または MSVC の _BitScanReverse/_BitScanForward をサポートしている場合はハードウェア命令を直接利用します。未サポート環境では、8ビットずつのシフトと pg_leftmost_one_pos / pg_rightmost_one_pos テーブルを用いたフォールバック処理にフォールスルーします。 2. 2の冪乗計算: pg_nextpower2_* は、入力がすでに 2 の冪乗であるかを (num & (num - 1)) == 0 で判定し、該当する場合はそのまま返します。そうでない場合は pg_leftmost_one_pos の結果からビットシフトで次の冪乗を構築します。 3. Popcount の閾値分岐: pg_popcount および pg_popcount_masked は、処理バイト数が 8 未満の場合は関数呼び出しオーバーヘッドを避けるため、pg_number_of_ones テーブルを用いたインラインループで直接計算します。8 バイト以上の場合は最適化されたポインタ経由のルーチンに処理を委譲します。

直接依存

  • intrin.h: MSVC 環境下でのビットスキャンイントリンシック用（_MSC_VER 定義時）。

関連コード

  • src/port/pg_bitutils.c: ルックアップテーブル（pg_leftmost_one_pos, pg_rightmost_one_pos, pg_number_of_ones）およびポータブル版 popcount の実体が定義されているペアファイル。

読者向けメモ

  • 入力値の制約: pg_leftmost_one_pos32 や pg_nextpower2_* などの多くのインライン関数は、引数が 0 でないこと（あるいは許容範囲内であること）を Assert で強制しています。呼び出し側で事前に 0 チェックを行う必要があります。
  • メモリ安全性: バッファ処理関数（pg_popcount など）は渡されたポインタとバイト数に従ってメモリを読み取るため、呼び出し側で適切なバッファ長を渡す責任があります。
