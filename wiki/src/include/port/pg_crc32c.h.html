src/include/port/pg_crc32c.h

概要

PostgreSQL において CRC-32C チェックサムを効率的に計算するためのインターフェースとマクロ定義を提供するヘッダーファイルです。プラットフォームごとのハードウェアアクセラレーション（Intel SSE 4.2, AVX-512, ARMv8, LoongArch など）と、汎用的な Slicing-by-8 アルゴリズムを抽象化します。

モジュール内での役割

src/include/port ディレクトリに属し、CPU 依存の最適化やポータビリティを提供する低レベルユーティリティ群の一部として機能します。データ構造の永続化やWAL（Write-Ahead Log）などで必要となる高速なチェックサム計算の共通 API を呼び出し元に提供します。

責務

  • チェックサム計算の公開インターフェース（INIT_CRC32C, COMP_CRC32C, FIN_CRC32C, EQ_CRC32C）のマクロ定義。
  • コンパイル時および実行時の環境に応じた、最適な CRC-32C 実装（ハードウェア命令またはソフトウェアフォールバック）へのディスパッチ。
  • 小さな定数長データに対するインライン展開による最適化の提供（SSE 4.2 や ARMv8 環境など）。

重要なシンボル

  • pg_crc32c: チェックサム値を表す uint32 のエイリアス。
  • INIT_CRC32C: アキュムレータを初期値（0xFFFFFFFF）に設定するマクロ。
  • COMP_CRC32C: バイト列を蓄積してチェックサムを更新するマクロ。
  • FIN_CRC32C: 計算結果をファイナライズするマクロ。
  • EQ_CRC32C: 2つのチェックサムの同値性を比較するマクロ。
  • pg_comp_crc32c_dispatch: コンパイル時ターゲットや定数長最適化を考慮して計算経路を選択するインライン関数（SSE 4.2有効時）。

制御フローとデータフロー

1. 初期化: 呼び出し元が INIT_CRC32C(crc) を呼び出し、内部アキュムレータを 0xFFFFFFFF にセットします。 2. 蓄積: COMP_CRC32C(crc, data, len) により、データブロックが順次計算されます。

  • コンパイル時に SSE 4.2 が直接有効な場合、pg_comp_crc32c_dispatch が定数かつ短小な入力（< 32バイト）に対して _mm_crc32_u64 等の組み込み関数をインライン展開して処理します。
  • それ以外の場合や大きなデータ長では、関数ポインタ経由または直接、最適化されたバックエンド実装（AVX-512、ARMv8、LoongArch、または Slicing-by-8 の pg_comp_crc32c_sb8）へディスパッチされます。

    • 3. 終了と比較: FIN_CRC32C(crc) でビット反転（必要に応じてビッグエンディアン向けのバイトスワップ）を行い、最終的な CRC 値を確定させます。必要に応じて EQ_CRC32C で比較します。

直接依存

  • port/pg_bswap.h: エンディアン変換（バイトスワップ）ユーティリティ。
  • <nmmintrin.h>: Intel SSE 4.2 組み込み関数用ヘッダー（SSE 4.2 有効時）。

関連コード

  • src/port/pg_crc32c_sse42.c / src/port/pg_crc32c_sb8.c: 各種アルゴリズムの実体を提供するソースファイル群。
  • src/include/port/pg_bswap.h: バイトスワップ処理の依存元。

読者向けメモ

  • ハードウェアアクセラレーションの有無やコンパイラの設定（--with-llvm やターゲットフラグ）によって、有効になるコードパスが大きく変わるため #if defined の分岐に注意してください。
  • ビッグエンディアン環境では Slicing-by-8 実行時のバイト順序の扱いに差異があるため、FIN_CRC32C 内でエンディアン補正が行われます。
