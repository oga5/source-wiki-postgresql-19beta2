src/include/port/pg_iovec.h

概要

src/include/port/pg_iovec.h は、プラットフォーム間の差異を吸収しながらベクトル化 I/O（分散・集約 I/O）機能を提供するポータビリティヘッダーファイルです。標準の <sys/uio.h> の代替として機能し、Windows 環境向けの互換構造体定義や、未定義環境向けのフォールバック処理を含みます。

モジュール内での役割

src/include/port モジュールの一部として、OS 固有の差異を隠蔽する役割を持ちます。特に POSIX の preadv/pwritev や iovec が直接利用できない環境（Windows や一部の非標準プラットフォーム）に対して、一貫したインターフェースを提供します。

責務

  • POSIX 互換の struct iovec 定義の提供（Windows 環境向け）。
  • IOV_MAX が未定義の環境における安全なフォールバック値（16）の定義。
  • スタック上での安全な配列確保を考慮した、適切な上限値 PG_IOV_MAX（最大 128）の定義。
  • ネイティブな preadv/pwritev または個別読み書きのループを切り替える、インラインラッパー関数 pg_preadv と pg_pwritev の提供。

重要なシンボル

  • struct iovec: バッファのベースポインタ (iov_base) と長さ (iov_len) を保持する構造体。
  • IOV_MAX: 一度のベクトル I/O で扱えるセグメント数の上限。
  • PG_IOV_MAX: スタック割り当て等に安全な最大セグメント数（Min(IOV_MAX, 128)）。
  • pg_preadv: オフセットを指定して複数バッファへ読み込むインライン関数。
  • pg_pwritev: オフセットを指定して複数バッファから書き出すインライン関数。

制御フローとデータフロー

1. **プラットフォーム分岐**: 非 Windows 環境では標準の <sys/uio.h> をインクルードし、Windows 環境では独自の struct iovec を定義します。 2. **上限値の解決**: システムヘッダーで IOV_MAX が定義されていない場合は 16 にフォールバックし、それを基に PG_IOV_MAX を決定します。 3. **I/O 実行の分岐**:

  • ネイティブ機能（HAVE_DECL_PREADV / HAVE_DECL_PWRITEV）が有効な場合、iovcnt == 1 のときは単一の pread/pwrite に最適化し、それ以外はシステム標準の preadv/pwritev を呼び出します。
  • ネイティブ機能がない場合、pg_pread/pg_pwrite を用いたフォールバックループによって各バッファを順次処理し、部分的な読み書きやエラーを安全に集約します。

直接依存

  • <sys/uio.h> （非 Windows 環境のみ）
  • <unistd.h> （非 Windows 環境のみ）
