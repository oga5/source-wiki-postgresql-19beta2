src/include/port/pg_iovec.h

概要

src/include/port/pg_iovec.h は、プラットフォーム間で一貫した分散（ベクター）I/O インターフェースを提供するヘッダーファイルです。標準の <sys/uio.h> のラッパーとして機能し、Windows などのプラットフォーム差異を吸収します。

モジュール内での役割

src/include/port ディレクトリに属し、オペレーティングシステムの差異を隠蔽する移植性レイヤーの一部を構成します。ストレージやネットワーク層などの上位モジュールが、プラットフォーム依存の制限を意識せずにベクター I/O を利用できるようにします。

責務

  • POSIX 互換の iovec 構造体および関連マクロ（IOV_MAX, PG_IOV_MAX）の定義と提供。
  • プラットフォーム側での preadv / pwritev の有無に応じたフォールバック実装の提供。
  • 単一の iovec 要素に対する効率的な最適化や、部分読込・書込時のオフセット管理。

重要なシンボル

  • struct iovec: バッファへのポインタ（iov_base）と長さ（iov_len）を保持する構造体（非 Windows 環境では <sys/uio.h> から提供）。
  • PG_IOV_MAX: スタック上での安全な配列確保を考慮し、システム制限と 128 の小さい方を選択するマクロ。
  • pg_preadv: オフセットを指定して複数のバッファへ読み込むインライン関数。ネイティブ機能がない場合はループによるフォールバックを実行。
  • pg_pwritev: オフセットを指定して複数のバッファから書き込むインライン関数。

制御フローとデータフロー

1. 呼び出し元がファイルディスクリプタ、iovec 配列とその要素数、およびファイルオフセットを指定して pg_preadv または pg_pwritev を呼び出します。 2. ネイティブの preadv / pwritev が利用可能な場合：

  • iovcnt == 1 のときは、カーネルの引数コピーオーバヘッドを避けるため pread / pwrite を直接呼び出します。
  • iovcnt > 1 のときは、ネイティブの preadv / pwritev に処理を委譲します。

    • 3. ネイティブ機能がない場合：

  • ループ処理により各 iovec 要素に対して pg_pread / pg_pwrite を順次実行します。
  • 途中でエラーが発生した場合や、要求サイズより少ないバイト数しか処理されなかった場合は、それまでの累積バイト数を返して処理を終了します。

直接依存

  • <limits.h>
  • <sys/uio.h> （非 Windows 環境）
  • <unistd.h> （非 Windows 環境）

関連コード

  • src/include/port/win32.h: Windows 環境におけるポート依存の定義。
  • ストレージおよびファイルアクセスのサブシステム（ベクター I/O を活用する上位モジュール）。

読者向けメモ

  • Windows 環境では、この関数群を実行すると現在のファイル位置（ファイルポインタ）が変更される副作用があるため注意が必要です。
