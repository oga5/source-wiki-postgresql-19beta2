src/include/utils/queryenvironment.h

概要

src/include/utils/queryenvironment.h は、クエリ実行時や計画時にコンテキスト固有の値（一時名前付きリレーション / Ephemeral Named Relations: ENR）を管理するためのクエリ環境インターフェースを定義するヘッダーファイルである。主に、AFTERトリガーの遷移テーブルのようなカタログに永続化されない一時的なタプルストア等をクエリ内で参照・操作する仕組みを提供する。

モジュール内での役割

src/include/utils モジュール内において、本ファイルはクエリのパース、計画、実行フェーズをまたいで一時的な名前付きリレーションを安全に解決するためのデータ構造と関数群を定義している。実装実体は src/backend/utils/misc/queryenvironment.c に存在する。

責務

  • **クエリ環境のライフサイクル管理**: クエリ固有の状態を保持する QueryEnvironment 構造体の生成インターフェースを提供する。
  • **一時名前付きリレーション（ENR）のメタデータ定義**: 名前、タプルディスクリプタ、元となるカタログリレーションのOID、推定タプル数などを保持するメタデータ構造体を定義する。
  • **ENRの登録・検索・登録解除**: 環境内に対するENRのエントリ追加、名前による検索、および削除のための関数プロトタイプを公開する。
  • **タプル記述子の動的解決**: メタデータから TupleDesc（TupleDesc またはカタログリレーションのOID）を安全に取得する経路を提供する。

重要なシンボル

型・データ構造定義

  • enum EphemeralNameRelationType:

    • 一時リレーションの種類を識別する列挙型。現在は ENR_NAMED_TUPLESTORE（デルタ情報などの名前付きタプルストア）のみが定義されている。

  • struct EphemeralNamedRelationMetadataData / typedef ... EphemeralNamedRelationMetadata:

    • 一時リレーションのメタデータ。識別用の name、カタログリレーションのOID（reliddesc）または直接保持するタプル記述子（tupdesc）のいずれか一方、リレーション種別（enrtype）、および推定タプル数（enrtuples）を保持する。

  • struct EphemeralNamedRelationData / typedef ... EphemeralNamedRelationData:

    • ENRの実データ構造。メタデータ（md）に加え、実行時アクセス用の構造体ポインタ（reldata、例: タプルストア等へのポインタ）を持つ。

  • struct QueryEnvironment:

    • クエリ環境を表す不透明（opaque）な構造体。内部で namedRelList（List*）を保持し、登録されたENRをリスト管理する。

関数インターフェース

  • create_queryEnv:

    • 新しい QueryEnvironment 構造体をメモリ上に割り当てて初期化・返却する（内部で palloc0_object を使用）。

  • register_ENR:

    • 指定されたクエリ環境に新しい EphemeralNamedRelation を登録する。重複登録がないことをアサートで検証する。

  • get_ENR:

    • 指定された名前（name）に一致するENRを環境内から線形探索し、見つかった場合はそのポインタを、見つからない場合は NULL を返す。

  • get_visible_ENR_metadata:

    • 参照名に対応するENRが存在する場合、そのメタデータ（EphemeralNamedRelationMetadata）へのポインタを取得して返す。

  • unregister_ENR:

    • 名前を指定してクエリ環境から該当するENRを削除・登録解除する。

  • ENRMetadataGetTupDesc:

    • メタデータに保持されている情報から TupleDesc を解決して返す。tupdesc が直接設定されている場合はそれを返し、未設定で reliddesc がある場合はカタログからリレーションを開いてタプルディスクリプタを取得する。

制御フローとデータフロー

1. **環境の生成**: クエリの解析・計画の初期段階で create_queryEnv() が呼ばれ、メモリコンテキスト上に QueryEnvironment が確保される。 2. **ENRの登録**: トリガーの実行や特定コンテキストの構築に伴い、register_ENR() を用いて EphemeralNamedRelationData が QueryEnvironment->namedRelList に追加される。 3. **リレーションの解決**: パーサーやプランナーが名前付きリレーションに遭遇した際、get_ENR() または get_visible_ENR_metadata() を呼び出して該当するENRやメタデータを取得する。 4. **型情報の取得**: 必要に応じて ENRMetadataGetTupDesc() が呼び出され、キャッシュまたはカタログ参照経由で TupleDesc が抽出される。

直接依存

  • access/tupdesc.h: タプル記述子（TupleDesc）の定義を利用するためにインクルードしている。

関連コード

  • src/backend/utils/misc/queryenvironment.c: 本ヘッダーで宣言された関数の実装ファイル。

読者向けメモ

  • **メモリ所有権とライフスタイル**: QueryEnvironment およびそれに登録される EphemeralNamedRelation は、通常、生存期間が短いクエリ用のメモリコンテキスト上で管理される。
  • **実装の選択に関する注意**: 現在の実装では登録数が少ないという前提の下、リスト構造（List）による線形探索を採用している。将来的に数が増加した場合は、呼び出し側への影響なしに内部実装（ハッシュ等）を変更できるよう不透明構造体としてカプセル化されている。
  • **排他・ロック要件**: ENRMetadataGetTupDesc() 内でカタログのリレーション（reliddesc）を参照して TupleDesc を取得する際、適切なロックはすでに呼び出し側で保持されていることが前提となっている（関数内では NoLock でオープンされる）。
