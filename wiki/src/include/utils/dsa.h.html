src/include/utils/dsa.h

概要

src/include/utils/dsa.h は、動的共有メモリ（Dynamic Shared Memory: DSM）セグメント上に構築される動的共有メモリ領域（DSA: Dynamic Shared Area）の公開インターフェースを定義するヘッダーファイルです。システムヒープとは異なり、プロセス間で共有可能な「擬似ポインタ（dsa_pointer）」を用いた小オブジェクトの割り出しと管理を実現します。

モジュール内での役割

src/backend/utils/mmgr/dsa.c のペアファイルとして機能し、複数バックエンド間で共有されるデータ構造（ハッシュテーブルやタプルストアなど）向けのメモリ管理APIを提供します。DSMセグメント単体では扱いにくい小規模な動的割り当てを効率的に処理する抽象レイヤーを定義しています。

責務

  • 動的共有エリアを表現する不透明構造体 dsa_area およびプロセス間共有可能なポインタ型 dsa_pointer（およびそのアトミック版）の定義。
  • エリアのライフサイクル管理（作成、インプレース作成、アタッチ、デタッチ、ピン止め）を行う関数の宣言。
  • 拡張フラグつき割り当てや解放、ポインタからローカルメモリアドレスへの変換を行うメモリ操作APIの宣言。
  • セグメントサイズやオフセット幅、ポインタサイズ（32-bit / 64-bit切り替え）に関する構成マクロの提供。

重要なシンボル

型定義・マクロ・構造体

  • **struct dsa_area**: DSAエリア全体の状態を管理する不透明構造体。
  • **dsa_pointer**: DSA領域内の相対ポインタ。プロセス間で共有可能ですが、デリファレンス前にローカルアドレスへの変換が必要です（32-bitまたは64-bit）。
  • **dsa_pointer_atomic**: アトミック操作をサポートする dsa_pointer 型。対応する初期化・読み書き・加算・比較交換マクロが定義されています。

ライフサイクル管理関数

  • **dsa_create_ext**: 新規のDSAエリアを指定した初期セグメントサイズと最大セグメントサイズで動的に作成します。
  • **dsa_create_in_place_ext**: 既存の共有メモリ領域内（またはDSMセグメント内）にDSAエリアを構築します。
  • **dsa_attach**: 既存の dsa_handle を指定して、他プロセスが作成したDSAエリアにアタッチします。
  • **dsa_detach**: アタッチしたDSAエリアからデタッチし、必要に応じてリソースを解放します。
  • **dsa_pin / dsa_unpin**: DSAエリアのピン止め（アタッチ状態の維持・保護）および解除を行います。
  • **dsa_pin_mapping**: DSAエリアのマッピングをピン止めします。

メモリ割り当て・変換関数

  • **dsa_allocate_extended**: 拡張フラグ（DSA_ALLOC_HUGE, DSA_ALLOC_NO_OOM, DSA_ALLOC_ZERO）を指定してメモリを割り当て、dsa_pointer を返します。
  • **dsa_free**: dsa_pointer が指す動的メモリ領域を解放します。
  • **dsa_get_address**: 共有可能な dsa_pointer を自プロセスの仮想アドレス空間上のローカルポインタ（void *）に変換します。

制御フローとデータフロー

1. **エリアの生成またはアタッチ**:

  • プロセスは dsa_create / dsa_create_ext で新規エリアを作るか、dsa_attach に dsa_handle を渡して既存エリアに参加します。

    • 2. **メモリの割り当て**:

  • クライアントが dsa_allocate（内部で dsa_allocate_extended を呼び出し）を実行すると、DSAは必要に応じてDSMセグメントを追加し、フリーページマネージャやプールから領域を切り出して dsa_pointer を返します。

    • 3. **ポインタの変換と利用**:

  • 取得した dsa_pointer は他バックエンドと共有可能です。アクセスする際は dsa_get_address を介してローカルポインタに変換してから読み書きを行います。

    • 4. **解放**:

  • 不要になった領域は dsa_free で返却され、エリア全体は dsa_detach によって解放または切り離されます。

直接依存

  • port/atomics.h: アトミック操作とアトミック型定義のため。
  • storage/dsm.h: 動的共有メモリ（DSM）セグメントおよび dsm_handle の利用のため。

読者向けメモ

  • **ポインタの有効性**: dsa_pointer の値 0 は InvalidDsaPointer として予約されており、割り当て失敗や無効な状態を示します。
  • **アーキテクチャ依存のサイズ**: 32-bitプラットフォーム、または64-bitアトミック非対応環境では、dsa_pointer は強制的に32-bit (uint32) にフォールバックします。これにより最大アドレス空間やセグメント数に制限がかかります。
