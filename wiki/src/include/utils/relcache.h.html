src/include/utils/relcache.h

概要

PostgreSQLのリレーション記述子キャッシュ（リレーションキャッシュ、通称 relcache）のエントリ構造、初期化、構築、およびライフサイクル管理に関する公開インターフェースを定義するヘッダーファイルです。

モジュール内での役割

  • src/include/utils サブシステムの一部として、カタログメタデータをメモリ上に保持するデータ構造と関数群を提供します。
  • バックエンドの実装本体である src/backend/utils/cache/relcache.c と対をなし、外部モジュールから利用される型定義や公開関数シグネチャを定めます。

責務

  • リレーション構造体（Relation および RelationPtr）の型定義と、高速化のための初期化ファイル名（pg_internal.init）のマクロ定義。
  • リレーションのオープン・クローズ、およびインデックス・制約・属性情報などの追加キャッシュを取得する API の提供。
  • バックエンド起動時の段階的初期化、およびトランザクション境界（EoXact / EoSubXact）でのキャッシュ無効化・同期制御の宣言。

重要なシンボル

  • struct RelationData *Relation: リレーション記述子を表す不透明ポインタ型のエイリアス。
  • RelationIdGetRelation: 指定された Oid からリレーションキャッシュエントリを取得します。
  • RelationClose: 使用済みのリレーション記述子を閉じます。
  • IndexAttrBitmapKind: インデックスの対象列を取得する際のビットマップ種別を指定する列挙型。
  • RelationCacheInitialize: バックエンド起動時にリレーションキャッシュを初期化します。

制御フローとデータフロー

  • バックエンドの起動プロセスにおいて、RelationCacheInitialize から始まり、フェーズ 2 および 3 を経て共有カタログや通常カタログのキャッシュが構築されます。
  • クエリ実行やプランナの処理において、RelationIdGetRelation() でキャッシュ済みエントリを取得し、利用後は RelationClose() で解放するフローが基本となります。
  • キャッシュが無効化される局面では、RelationCacheInvalidate やトランザクション終了時の AtEOXact_RelationCache が呼び出され、エントリの破棄や再構築が行われます。

関連コード

読者向けメモ

  • ヘッダー内の多くの関数はバックエンド内部向けですが、リレーションの属性情報やインデックス構成にアクセスするオプティマイザやエグゼキュータの開発において頻繁に参照されます。
  • アサート有効時には AssertCouldGetRelation() によりリレーション取得が可能かどうかの検証が行われます。
