src/include/utils/elog.h

概要

PostgreSQLのエラー報告、ログ出力、および例外処理機構を定義するヘッダーファイルです。バックエンド全体で使用される ereport および elog マクロのインターフェース、エラーレベルの定数、SQLSTATEエンコーディングマクロ、例外のキャッチ/スローを制御する PG_TRY ブロック群、およびエラー情報を保持する ErrorData 構造体を定義しています。

モジュール内での役割

src/include/utils モジュールおよびバックエンド全般において、診断と例外制御の基盤を提供します。ペアとなる src/backend/utils/error/elog.c と協調し、トランザクションの中断、ログ出力先（stderr、syslog、csvlog、jsonlog等）へのディスパッチ、およびリカバリを管理します。

責務

  • **エラーレベルの定義**: DEBUG5 から PANIC に至るまでの重要度コードの定義。
  • **エラー報告APIの提供**: ereport および elog マクロによる、詳細な属性（エラーコード、メッセージ、詳細、ヒント等）を持つ例外の構築。
  • **例外制御の提供**: PG_TRY、PG_CATCH、PG_FINALLY、PG_END_TRY マクロによる sigjmp_buf ベースの例外捕捉と再スロー機構。
  • **データ構造の定義**: エラー情報を保持する ErrorData およびコンテキストコールバック用の ErrorContextCallback の宣言。
  • **SQLSTATE 操作**: 文字列と数値の間でSQLSTATEを変換するビット演算マクロの提供。

重要なシンボル

エラーレベル

  • DEBUG5 〜 DEBUG1: デバッグ用メッセージ（値 10〜14）。
  • LOG, LOG_SERVER_ONLY, COMMERROR: サーバ運用ログ向けメッセージ（値 15〜16）。
  • INFO, NOTICE, WARNING: ユーザ向けの情報・警告メッセージ（値 17〜19）。
  • ERROR, FATAL, PANIC: トランザクション中断、プロセス終了、またはクラスタ全体のクラッシュを引き起こす重大エラー（値 21〜24）。

エラー報告マクロ

  • ereport(elevel, ...): ドメインを指定してエラー処理の起点を呼び出し、補助関数群を実行するラッパーマクロ。
  • elog(elevel, ...): 内部メッセージとして簡易的にエラーを報告する旧来のインターフェース。
  • errcode(sqlerrcode): SQLSTATE エラーコードの設定。
  • errmsg(...), errdetail(...), errhint(...): プライマリメッセージ、詳細、ヒントの設定。

例外ハンドリングマクロ

  • PG_TRY() / PG_CATCH() / PG_FINALLY() / PG_END_TRY(): sigsetjmp / siglongjmp を用いたC言語レベルのtry-catch-finallyブロック。
  • PG_RE_THROW() / pg_re_throw(): キャッチした例外を外側のハンドラへ再スローする。

構造体

  • ErrorData: 1回の ereport() サイクルで蓄積されるすべてのエラー情報を保持する構造体。
  • ErrorContextCallback: エラー発生時にスタックトレースや追加のコンテキスト情報を付与するためのコールバック構造体。

制御フローとデータフロー

1. **報告の開始**: ereport(elevel, ...) が呼び出されると、まず errstart(elevel, domain) が実行され、エラーがログ出力やクライアント通知の対象か判定されます。 2. **情報の蓄積**: errstart が真を返した場合、カンマ区切りで連鎖された補助関数（errcode, errmsg, errdetail など）が評価され、内部のエラー状態が構築されます。 3. **終了処理とディスパッチ**: ブロックの末尾で errfinish(filename, lineno, funcname) が呼び出され、エラーレベルに応じた処理（トランザクションのアボート、プロセス終了、または通常のログ出力完了）が実行されます。 4. **例外の捕捉**: PG_TRY ブロック内で ERROR 以上のエラーが発生した場合、制御は PG_CATCH または PG_FINALLY へジャンプし、スタックされた sigjmp_buf を通じて復旧または再スローが行われます。

直接依存

  • <setjmp.h>: sigjmp_buf の定義のため。
  • "lib/stringinfo.h": 文字列バッファ操作のため。
  • "utils/errcodes.h": SQLSTATE エラーコード定数のインクルード。

関連コード

  • src/backend/utils/error/elog.c: ereport, errstart, errfinish, 例外スロー・捕捉の実体。

読者向けメモ

  • **メモリ所有権**: ErrorData 内の非定数ポインタ（メッセージ、詳細など）は原則として palloc で割り当てられたメモリ領域を指します。
  • **割り込み禁止と再入の安全性**: エラー処理中（特に ERROR 処理中）のメモリ枯渇や再帰的エラーに対しては、ErrorContext のリセットなどのエスケープハッチが用意されていますが、ハンドラ内での新たなエラー発生には厳格な制限があります。
