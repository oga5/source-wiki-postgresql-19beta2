src/include/utils/typcache.h

概要

データ型に関するメタデータ（pg_type 行の基本情報、演算子クラス、比較関数、ハッシュ関数、複合型のタプルデスク、範囲型・マルチ範囲型情報、ドメイン制約など）をキャッシュし、高速に取得するための公開インターフェースを定義するヘッダーファイルです。実体は対応する src/backend/utils/cache/typcache.c に実装されています。

モジュール内での役割

src/include/utils サブシステムの一部として、SQL データ型を扱うあらゆるモジュール（エグゼキュータ、プランナ、配列・レコード処理関数、インデックスサポートなど）に対して型情報のルックアップ機能を提供します。

責務

  • 型キャッシュのエントリ構造体（TypeCacheEntry）およびドメイン制約参照構造体（DomainConstraintRef）の定義。
  • キャッシュ要求の粒度を制御するためのビットフラグ（TYPECACHE_* マクロ）の提供。
  • 型キャッシュの検索、ドメイン制約の初期化・更新、行型タプル記述子の取得、および共有レコード型モッドレジストリに関する関数群の宣言。

重要なシンボル

型キャッシュエントリと定義データ

  • TypeCacheEntry:

    • 特定のデータ型（type_id）に関するキャッシュ情報を保持する中心的な構造体。基本属性、演算子／関数の OID、FmgrInfo、タプルデスク、範囲／ドメイン固有の情報を含みます。

  • DomainConstraintCache:

    • ドメインの制約データを保持する不透明（opaque）構造体。typcache.c の内部でのみ詳細が定義されます。

  • DomainConstraintRef:

    • 長寿命のドメイン制約参照を維持するための構造体。呼び出し側が制約セットを保持するために使用し、初期化や更新用の関数を伴います。

  • SharedRecordTypmodRegistry:

    • 共有レコード型モッドレジストリのための不透明構造体。

検索および初期化関数

  • lookup_type_cache:

    • 指定されたデータ型（type_id）のキャッシュエントリを取得し、flags で要求された情報が未計算であれば動的にロード・計算して返します。

  • InitDomainConstraintRef / UpdateDomainConstraintRef:

    • ドメイン制約参照の初期化および更新を行います。

  • DomainHasConstraints:

    • 指定された型が制約を持つかどうかを判定します。

行型（Composite/Record）およびレコード型関数

  • lookup_rowtype_tupdesc:

    • 指定された行型 OID と typmod に対応する参照カウント付きのタプル記述子（TupleDesc）を取得します。エラー時はエラーを送出します。

  • lookup_rowtype_tupdesc_noerror:

    • エラー時に例外を送出せず、必要に応じて NULL を返すタプルデスク取得関数。

  • lookup_rowtype_tupdesc_copy:

    • タプルデスクのコピーを返します。

  • lookup_rowtype_tupdesc_domain:

    • ドメイン型を考慮した行型タプルデスクの取得を行います。

  • assign_record_type_typmod / assign_record_type_identifier:

    • レコード型の typmod 割り当てや識別子の管理を行います。

その他ユーティリティ・ライフサイクル管理関数

  • compare_values_of_enum:

    • 列挙型（enum）の値を比較します。

  • SharedRecordTypmodRegistryEstimate / SharedRecordTypmodRegistryInit / SharedRecordTypmodRegistryAttach:

    • パラレルワーカー間等での共有レコード型モッドレジストリの管理関数。

  • AtEOXact_TypeCache / AtEOSubXact_TypeCache:

    • トランザクションおよびサブトランザクション終了時のキャッシュクリーンアップ処理。

制御フローとデータフロー

1. クライアントコードが lookup_type_cache(Oid type_id, int flags) を呼び出します。 2. typcache.c 内のハッシュテーブル（TypeCacheHash）から type_id に該当する TypeCacheEntry が検索されます。エントリが存在しない場合は新規作成されます。 3. flags（例: TYPECACHE_EQ_OPR, TYPECACHE_TUPDESC, TYPECACHE_RANGE_INFO など）で指定された各フィールドが未設定の場合、システムカタログ（pg_type, pg_opclass, pg_range など）から必要な情報が読み出され、対応する FmgrInfo のセットアップやタプルデスクのキャッシュが行われます。 4. 構築された TypeCacheEntry へのポインタが返され、以後はバックエンドの寿命期間中キャッシュとして再利用されます。

読者向けメモ

  • 一度作成された TypeCacheEntry はバックエンドの終了まで破棄されずに存続するため、長寿命なポインタ保持が安全に行えます。
  • メモリリークを防ぐため、比較やハッシュ計算に必要な FmgrInfo はエントリ内に予めセットアップされています。
