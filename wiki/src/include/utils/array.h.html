src/include/utils/array.h

概要

PostgreSQL の配列データ型（標準の「フラット」な varlena 配列、拡張オブジェクト表現である expanded 配列、およびそれらを統一的に扱うインターフェース）のデータ構造、定数、マクロ、および関数プロトタイプを定義するヘッダーファイルです。

モジュール内での役割

src/include/utils モジュール内において、配列の内部メモリレイアウト規定、関数呼び出し管理（FMGR）マクロ、および配列構築・操作・反復処理のための API 群を各サブシステムへ提供します。

責務

  • **配列レイアウトの定義**: 標準 varlena 配列 (ArrayType) のヘッダー構造（次元数、データオフセット、要素型 OID、軸長、下限バウンド、ヌルビットマップ）の規定。
  • **拡張配列の管理**: メモリコンテキスト上に構築される脱構築済み配列表現 (ExpandedArrayHeader) の定義。
  • **統一アクセス層の提供**: フラット配列と拡張配列の両方を透過的に扱うための共用体 (AnyArrayType) とアクセス用マクロ (AARR_*) の提供。
  • **構築用状態構造体の定義**: 集約や関数結果生成時に使用するビルド状態構造体 (ArrayBuildState, ArrayBuildStateArr, ArrayBuildStateAny) の提供。
  • **関数プロトタイプの公開**: arrayfuncs.c, arrayutils.c, array_expanded.c で実装される配列操作・検証・イテレータ関数の宣言。

重要なシンボル

配列構造体と型定義

  • ArrayType: フラットな varlena 配列の物理ヘッダー（vl_len_, ndim, dataoffset, elemtype）。
  • ExpandedArrayHeader: 拡張オブジェクトインフラを使用するメモリ上の脱構築済み配列の制御構造体。
  • AnyArrayType: ArrayType と ExpandedArrayHeader を内包する共用体。フラット/拡張のどちらの入力も受け付ける関数で使用。
  • ArrayBuildState, ArrayBuildStateArr, ArrayBuildStateAny: スカラー値、配列、またはその両方から配列結果を蓄積・構築するための作業状態構造体。
  • ArrayMetaState, ArrayMapState: 型メタデータのキャッシュおよび array_map 用のプライベート状態構造体。

FMGR アクセスマクロ

  • DatumGetArrayTypeP(X) / DatumGetArrayTypePCopy(X): Datum から標準配列ポインタへの変換（必要に応じてデトースト）。
  • PG_GETARG_ARRAYTYPE_P(n) / PG_GETARG_ARRAYTYPE_P_COPY(n): 関数引数からの配列取得マクロ。
  • PG_GETARG_EXPANDED_ARRAY(n) / PG_GETARG_EXPANDED_ARRAYX(n, metacache): 引数からの拡張配列取得。
  • PG_GETARG_ANY_ARRAY_P(n): フラットまたは拡張配列のいずれかとして取得。

配列ヘッダーアクセスマクロ

  • ARR_SIZE(a), ARR_NDIM(a), ARR_HASNULL(a), ARR_ELEMTYPE(a): フラット配列の基本属性抽出。
  • ARR_DIMS(a), ARR_LBOUND(a), ARR_NULLBITMAP(a), ARR_DATA_PTR(a): 寸法配列、下限、ヌルビットマップ、実データへのポインタ計算。
  • AARR_NDIM(a), AARR_HASNULL(a), AARR_ELEMTYPE(a), AARR_DIMS(a), AARR_LBOUND(a): AnyArrayType 入力に対する透過的アクセスマクロ。

主要な関数 API

  • **要素・スライス操作**: array_get_element, array_set_element, array_get_slice, array_set_slice, array_ref, array_set
  • **構築・脱構築**: construct_array, construct_md_array, deconstruct_array, deconstruct_array_builtin, expand_array, deconstruct_expanded_array
  • **集約ビルド**: initArrayResult, accumArrayResult, makeArrayResult, makeMdArrayResult（および Arr / Any バリアント）
  • **イテレータ**: array_create_iterator, array_iterate, array_free_iterator
  • **ユーティリティ**: ArrayGetOffset, ArrayGetNItems, ArrayCheckBounds, array_map

制御フローとデータフロー

  • **入力の受け取り**: PostgreSQL の関数呼び出しインターフェース（FMGR）を経由して渡された Datum は、マクロ（PG_GETARG_ARRAYTYPE_P や PG_GETARG_ANY_ARRAY_P など）により評価され、物理的な ArrayType またはメモリ上の ExpandedArrayHeader として解釈されます。
  • **透過的アクセス**: AARR_* マクロは引数が拡張形式であるかフラット形式であるかを VARATT_IS_EXPANDED_HEADER で判定し、対応する構造体フィールドへ直接ルーティングします。
  • **集約処理の流れ**: クエリ実行中の配列構築では、initArrayResult* で状態構造体を初期化し、行ごとに accumArrayResult* で値を蓄積、最終的に makeArrayResult* を呼び出すことでメモリコンテキスト上に最適化された配列 Datum を生成します。

直接依存

  • fmgr.h: 関数マネージャの基本型（FmgrInfo, Datum 等）の定義。
  • utils/expandeddatum.h: 拡張オブジェクト（TOAST インフラ）の基底構造体 ExpandedObjectHeader の定義。

関連コード

  • src/backend/utils/adt/arrayfuncs.c: 配列の構築、スライス、比較、および反復処理の実装。
  • src/backend/utils/adt/arrayutils.h / arrayutils.c: 配列のインデックス計算や次元チェックなどの低レベル数値計算補助。
  • src/backend/utils/adt/array_expanded.c: 拡張配列の展開・再構築・管理ロジックの実装。

読者向けメモ

  • **メモリ配置**: 標準 varlena 配列の実データは必ず MAXALIGN 境界に配置されます。トースト可能なデータ型の配列要素は、個別にトーストされてはならず、配列全体としてのみトーストされる必要があります。
  • **制限事項**: 配列の最大次元数 (MAXDIM) は 6 に制限されています。また、要素数の上限 (MaxArraySize) は MaxAllocSize / sizeof(Datum) のおよそ 4 分の 1 に抑えられており、メモリーアロケーション時のオーバーフローを防いでいます。
