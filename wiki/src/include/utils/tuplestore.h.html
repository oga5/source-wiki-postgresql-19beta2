src/include/utils/tuplestore.h

概要

src/include/utils/tuplestore.h は、PostgreSQLの実行時における一時的なタプル（行）の格納・再取得メカニズム（Tuplestore）の公開インターフェースを定義するヘッダーファイルです。Materializeノードやハッシュジョインのバッチファイルなど、順序を維持したまま一時的なタプル列を保持し、書き込みの完了を待たずに読み取りを開始したり、複数の独立した読み取りポインタを用いてランダムアクセスを行う用途に使用されます。内部実装の詳細は不透明型（opaque type）として隠蔽されています。

モジュール内での役割

src/include/backend/utils/sort/tuplestore.c とペアをなし、src/backend/executor/ などのエグゼキューター層やクエリ処理エンジンに対し、MinimalTuple 形式の行データを効率よく一時保存・走査する機能を提供します。同系統の tuplesort.h がソートを伴う処理を対象とするのに対し、本モジュールはソートを行わずストリームの保存と巻き戻し・複数ポインタ走査に特化しています。

責務

  • 不透明な状態管理構造体 Tuplestorestate の型宣言の提供。
  • Tuplestore の初期化・終了・クリアのライフサイクル管理インターフェースの定義。
  • 様々な形式（TupleTableSlot, HeapTuple, Datum 配列）でのタプル書き込みインターフェースの提供。
  • 単一または複数の読み取りポインタの割り当て、選択、複製、位置移動を行う API の提供。
  • 前方・後方スキャンや EOF 判定、タプル件数取得などの走査制御インターフェースの提供。

重要なシンボル

ライフサイクルおよび状態管理

  • struct Tuplestorestate: 内部のメモリバッファや一時ファイルの状態を保持する不透明な構造体（定義のみ提供）。
  • tuplestore_begin_heap: ランダムアクセスの可否、トランザクション跨ぎの有無、許容メモリサイズ（KB）を指定して新しい Tuplestore を生成・初期化する。
  • tuplestore_end: Tuplestore が保持するメモリおよび一時ファイルなどの全リソースを解放する。

タプル書き込み

  • tuplestore_puttupleslot: TupleTableSlot から MinimalTuple を抽出してストアに書き込む。
  • tuplestore_puttuple: 従来の HeapTuple をストアに書き込む。
  • tuplestore_putvalues: Datum 配列と isnull 配列、およびタプル記述子（TupleDesc）から直接値を書き込む。

読み取りポインタ管理

  • tuplestore_alloc_read_pointer: 新しい独立した読み取りポインタを割り当て、その識別子（整数）を返す。
  • tuplestore_select_read_pointer: 以降の読み取り操作の対象となるアクティブな読み取りポインタを切り替える。

タプル取得および走査

  • tuplestore_gettupleslot: 指定された方向（前方/後方）へ進みながら、タプルを TupleTableSlot に読み出す。

制御フローとデータフロー

本ヘッダーファイルで宣言される関数を通じた典型的な利用フローは以下の通りです。

1. 初期化: 実行計画のノード開始時に tuplestore_begin_heap() を呼び出して Tuplestorestate を取得する。必要に応じて tuplestore_alloc_read_pointer() で追加の読み取りポインタを確保する。 2. 書き込みフェーズ: エグゼキューターからタプルが生成されるたびに、tuplestore_puttupleslot() や tuplestore_putvalues() を用いて次々とストアに投入する。メモリ制限（maxKBytes）を超過した場合は、裏側で一時ファイル（Buffile）へ自動的に溢れさせる。 3. 読み取りフェーズ: 書き込みの完了を待たず、あるいは書き込みと並行して、tuplestore_select_read_pointer() でポインタを選択し、tuplestore_gettupleslot() によりタプルをスキャン・取得する。 4. 終了: 処理の完了に伴い tuplestore_end() が呼び出され、メモリコンテキストおよび一時ファイル領域がクリーンアップされる。

直接依存

  • executor/tuptable.h: TupleTableSlot 構造体の定義を提供し、スロットベースの入出力インターフェースを支える。

関連コード

  • src/backend/utils/sort/tuplestore.c: ペアとなる実装ファイル。インメモリ配列と一時ファイルの切り替え、状態遷移（TSS_INMEM, TSS_WRITEFILE, TSS_READFILE）の実体を網羅。
  • src/include/utils/tuplesort.h: ソート機能を備えた類似のテンポラリストレージ機構。
  • src/include/utils/sharedtuplestore.h: プロセス間で共有可能な Tuplestore の拡張実装。

読者向けメモ

  • メモリとストレージの自動切り替え: 指定された maxKBytes 以内ではメモリ上の配列に保持され、超過すると一時ファイルにダンプされる。利用者はこの切り替えを意識せず統一された API で操作できる。
  • MinimalTuple の制限: 格納されるデータは MinimalTuple 形式であるため、再取得されたタプルからシステム列（ctid や xmin など）を取り出すことはできない仕様になっている。
