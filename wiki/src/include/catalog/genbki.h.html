src/include/catalog/genbki.h

概要

PostgreSQL のシステムカタログヘッダーファイルを C コンパイラとビルドツール（genbki.pl）の双方が解釈できるようにするためのマクロ定義を提供するヘッダーファイルです。カタログ定義構造体のレイアウト調整や、BKI（Backend Interface）生成用のメタデータマクロを定義しています。

モジュール内での役割

src/include/catalog サブシステムにおいて、各 pg_*.h カタログ定義ヘッダーの基礎となるメタ構文を定義します。C コンパイラに対しては通常のC言語構造体として解釈させつつ、ビルドスクリプトにはスキーマ定義、OID、インデックス、TOAST、外部キーなどの情報を伝える二重の役割を持ちます。

責務

  • **構造体レイアウトの制御**: AIX などのプラットフォームにおけるアライメント差（ALIGNOF_DOUBLE < ALIGNOF_INT64_T）を吸収し、タプル形成規則と互換性を持たせるための構造体パディング（BEGIN_CATALOG_STRUCT / END_CATALOG_STRUCT）の定義。
  • **カタログ定義メタマクロの提供**: カタログ名、OID、ブートストラップ、共有リレーション等を宣言する CATALOG 関連マクロの提供。
  • **属性修飾マクロの提供**: 列の NULL 制約強制、デフォルト値、配列デフォルト、OID 参照（ルックアップ）を指定する BKI_* マクロの定義。
  • **補助構造・インデックス定義の宣言**: TOAST テーブル、インデックス、一意制約、プライマリキー、手動定義 OID マクロ、外部キー、シスキャッシュを宣言するためのプレースホルダーマクロの提供。
  • **クライアント露出制御**: バックエンド専用コードとクライアント共通ヘッダー（_d.h）へのコード共有を制御する境界マーカーの提供。

重要なシンボル

構造体アライメント制御

  • BEGIN_CATALOG_STRUCT / END_CATALOG_STRUCT:
  • ライフサイクル: カタログ構造体定義の直前と直後に配置。
  • レイアウト: AIX 環境で int64 フィールドを 4 バイト境界に強制配置 (pack(push,4)) し、それ以外の環境では無効化。

カタログおよび属性修飾マクロ（ダミー/パーサ用）

  • CATALOG(name,oid,oidmacro): カタログ構造体の定義（typedef struct FormData_name）を開始。
  • BKI_BOOTSTRAP, BKI_SHARED_RELATION, BKI_ROWTYPE_OID, BKI_SCHEMA_MACRO: カタログ属性の修飾。
  • BKI_FORCE_NULL, BKI_FORCE_NOT_NULL, BKI_DEFAULT, BKI_ARRAY_DEFAULT: フィールド単位の制約・初期値修飾。
  • BKI_LOOKUP(catalog), BKI_LOOKUP_OPT(catalog): 指定カタログの OID 参照およびオプショナル参照を定義し、初期データの名前解決やテスト検証に利用。

構築・スキーマ宣言マクロ

  • DECLARE_TOAST, DECLARE_TOAST_WITH_MACRO: システムカタログ用の TOAST テーブルとインデックスの OID 割当てを指定。
  • DECLARE_INDEX, DECLARE_UNIQUE_INDEX, DECLARE_UNIQUE_INDEX_PKEY: インデックスおよびプライマリキーの作成文を生成。
  • DECLARE_OID_DEFINING_MACRO: カタログ .dat ファイルに存在しない手動割り当て OID 用のマクロ定義を生成。
  • DECLARE_FOREIGN_KEY, DECLARE_FOREIGN_KEY_OPT, DECLARE_ARRAY_FOREIGN_KEY, DECLARE_ARRAY_FOREIGN_KEY_OPT: カタログ間の外部キー関係を機械可読な形式で記録。
  • MAKE_SYSCACHE: 指定された名前、インデックス、バケットサイズでシスキャッシュを作成。

制御フローとデータフロー

本ファイルは純粋なプリプロセッサマクロおよび C 言語の型定義定義ファイルであり、実行時の制御フローやデータフローを持ちません。

  • **ビルド時フロー**:

    • 1. genbki.pl スクリプトが pg_*.h ヘッダーを走査し、本ファイルで定義される各種 CATALOG や DECLARE_* マクロをパースする。 2. パース結果から .bki ブートストラップファイルや *_d.h クライアント用ヘッダーが生成される。

  • **コンパイル時フロー**:
  • C コンパイラがバックエンドをビルドする際、DECLARE_* や BKI_* マクロは extern int no_such_variable や空定義に展開され、実コードに影響を与えずに構造体定義（FormData_*）のみがコンパイルされる。

直接依存

  • なし（他のヘッダーをインクルードしない基礎ヘッダー）。

関連コード

  • src/backend/catalog/genbki.pl: 本ファイルのマクロ群を解釈して BKI ファイルや派生ヘッダーを生成する Perl スクリプト。
  • src/include/catalog/pg_*.h: 本ファイルのマクロを利用して定義されている個別のシステムカタログヘッダー群。

読者向けメモ

  • **C構造体の不ビジビリティ**: 可変長カタログフィールドは原則として C 構造体から隠蔽されるため、CATALOG_VARLEN は未定義（#undef）として文書化されています。
  • **EXPOSE_TO_CLIENT_CODE**: クライアントとバックエンドの両方で共有すべきコード片を囲むために使用され、genbki.pl によって _d ヘッダーへ選択的にコピーされます。
