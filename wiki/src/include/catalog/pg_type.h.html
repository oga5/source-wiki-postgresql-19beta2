src/include/catalog/pg_type.h

概要

PostgreSQL のシステムカタログ pg_type のスキーマ定義と、データ型操作に関連する関数・マクロを提供するヘッダーファイルです。C 構造体定義、BKI（Backend Interface）メタデータ、システムキャッシュ定義、およびクライアント向けのマクロを含み、データベース内のすべてのデータ型（基本型、複合型、ドメイン、列挙型、範囲型、擬似型など）のメタデータを規定します。

モジュール内での役割

src/include/catalog モジュールの一部として、PostgreSQL の型システムの中核を担います。Catalog.pm によってパースされてブートストラップ用スキーマを生成し、バックエンドの src/backend/catalog/pg_type.c や型定義コマンド (commands/typecmds.h) と連携してデータ型の作成・変更・依存関係管理をサポートします。

責務

  • pg_type テーブルの物理行レイアウト (FormData_pg_type および Form_pg_type) の定義。
  • pg_type_oid_index および pg_type_typname_nsp_index による一意制約・インデックス構造の宣言とシステムキャッシュ (TYPEOID, TYPENAMENSP) の登録。
  • 型の分類、カテゴリ、アライメント、ストレージ戦略を表す定数マクロ (TYPTYPE_*, TYPCATEGORY_*, TYPALIGN_*, TYPSTORAGE_*) の提供。
  • 多態性型 (Polymorphic types) や真の配列型を判定するヘルパーマクロの提供。
  • 型のシェル作成、型本体の作成、依存関係生成、配列・マルチレンジ型名生成などの関数プロトタイプの宣言。

重要なシンボル

型定義およびレコード構造

  • FormData_pg_type: pg_type カタログの1行分の物理レイアウトを定義する C 構造体。Oid、型名、名前空間、所有者、長短、値渡しフラグ、型の種類 (typtype)、カテゴリ、I/O関数、アライメント、ストレージ、ドメイン定義などを格納します。
  • Form_pg_type: FormData_pg_type * 型のエイリアス。カタログタプルへのポインタとして使用されます。

型の作成および操作関数

  • TypeShellMake: pg_type にプレースホルダー（シェル）となる未定義の型タプルを挿入し、前方参照やI/O関数からのリンクを可能にします。
  • TypeCreate: 完全な定義を持つ新しいデータ型を pg_type に作成し、必要な属性や関数Oidを結び付けます。
  • GenerateTypeDependencies: 作成または変更された型タプルに対する依存関係（要素型、名前空間、所有者、拡張など）を構築します。
  • RenameTypeInternal: 型の名称を内部的に変更します。

名称生成・管理関数

  • makeArrayTypeName: 指定された型名と名前空間に対応する配列型の名前を動的に生成します。
  • moveArrayTypeName: 配列型の名前や名前空間を変更・移動します。
  • makeMultirangeTypeName: 範囲型に対応するマルチレンジ型の名前を生成します。

判定・評価マクロ (EXPOSE_TO_CLIENT_CODE)

  • EXPOSE_TO_CLIENT_CODE: クライアントコードへ公開するマクロ群を条件付きコンパイルするためのガード。
  • TYPTYPE_BASE, TYPTYPE_COMPOSITE, TYPTYPE_DOMAIN, TYPTYPE_ENUM, TYPTYPE_MULTIRANGE, TYPTYPE_PSEUDO, TYPTYPE_RANGE: 型の種類を識別する文字マクロ。
  • TYPCATEGORY_ARRAY, TYPCATEGORY_BOOLEAN, TYPCATEGORY_COMPOSITE, TYPCATEGORY_DATETIME, TYPCATEGORY_ENUM, TYPCATEGORY_GEOMETRIC, TYPCATEGORY_NETWORK: 型のカテゴリを識別する文字マクロ。
  • IsPolymorphicType, IsPolymorphicTypeFamily1, IsPolymorphicTypeFamily2: Oid が多態性擬似型（anyelement, anyarray 等）であるかを判定します。
  • IsTrueArrayType: 指定された Form_pg_type が有効な要素型と配列サブスクリプトハンドラー (F_ARRAY_SUBSCRIPT_HANDLER) を持ち、「真の配列型」であるかを判定します。

制御フローとデータフロー

1. **型定義のライフサイクル**:

  • 新規カスタム型の作成時、まず TypeShellMake が呼ばれて typisdefined = false のシェルタプルが pg_type に挿入されます。
  • その後、TypeCreate が呼び出されて完全な型属性（I/O関数、アライメント、ストレージなど）でレコードが更新され、typisdefined = true に設定されます。
  • 最後に GenerateTypeDependencies が呼び出され、pg_depend などのカタログに依存関係レコードが登録されます。

    • 2. **配列・レンジ型の連動**:

  • 配列型やマルチレンジ型が必要な場合、makeArrayTypeName や makeMultirangeTypeName を用いて対応する一意の型名文字列が算出され、自動的に関連付けられます。

直接依存

  • catalog/genbki.h: BKI スクリプト生成マクロ群。
  • catalog/objectaddress.h: ObjectAddress 構造体の定義。
  • catalog/pg_type_d.h: pg_type に関する定義値（Oid定数など）。
  • nodes/nodes.h: ノードツリー表現 (pg_node_tree) の基礎定義。

関連コード

  • src/backend/catalog/pg_type.c: 本ヘッダーで宣言された関数群の実装および binary_upgrade_next_pg_type_oid などのグローバル変数を定義。
  • src/include/catalog/pg_type_d.h: TypeRelationId, TypeOidIndexId などのOid定数を提供。
  • src/backend/commands/typecmds.h: CREATE TYPE などのコマンドを処理するバックエンド実装。

読者向けメモ

  • **構造体レイアウトの厳密性**: FormData_pg_type のフィールド順序やサイズ、アライメントはシステムカタログとして永続化されるため、変更時はカタログバージョン (CATVERSION) の更新が必須です。
  • **可変長フィールド**: CATALOG_VARLEN が定義されている場合、構造体の末尾に typdefaultbin, typdefault, typacl などの可変長フィールドが続きます。
