src/include/parser/parse_node.h

概要

クエリ解析フェーズにおいて、構文木（Raw Parse Tree）からクエリツリー（Query Tree）への変換中に必要となる内部状態、名前空間、式コンテキストなどを定義するヘッダーファイルです。ペアとなる実装ファイル src/backend/parser/parse_node.c と共に、パーサー全体で共有されるコンテキスト管理の基盤を提供します。

モジュール内での役割

src/include/parser モジュール内において、他のほぼすべての解析フェーズ（式、関係、関数、ターゲット、句の変換など）が参照するデータ構造の定義元として機能します。特に、クエリのスコープ、レンジテーブル（RTE）、名前空間、およびエラー位置追跡を管理する ParseState を中心に据えています。

責務

  • **解析状態の管理**: サブクエリのネストをサポートする ParseState 構造体およびそのライフサイクル関数の定義。
  • **式コンテキストの分類**: 文脈依存のエラーメッセージや制約のために式が記述された場所を識別する ParseExprKind の定義。
  • **名前空間と可視性の管理**: 修飾名・非修飾名・LATERAL 参照・RETURNING 節の OLD/NEW 状態を解決するための ParseNamespaceItem および ParseNamespaceColumn の提供。
  • **エラー位置の追跡**: バイトオフセットから1ベースの文字位置への変換やエラーコンテキストコールバックを補助する ParseCallbackState の定義。
  • **パーサーフックの定義**: カラム参照やパラメータ参照の解釈を拡張するための関数ポインタ型の提供。

重要なシンボル

ライフサイクルと管理関数

  • ParseState *make_parsestate(ParseState *parentParseState): 新しい ParseState を割り当て、親ポインタやフック、クエリ環境を引き継いで初期化します。
  • void free_parsestate(ParseState *pstate): ParseState が持つリソース（ターゲットリレーションのクローズなど）を解放し、属性番号の範囲チェックを行います。
  • int parser_errposition(ParseState *pstate, int location): ソーステキストのバイトオフセットを1ベースの文字インデックスに変換し、エラーレポート用の位置情報を設定します。
  • void setup_parser_errposition_callback(ParseCallbackState *pcbstate, ParseState *pstate, int location) / void cancel_parser_errposition_callback(ParseCallbackState *pcbstate): パーサー外のコードで発生したエラーに構文解析位置のコンテキストを付与するためのコールバックを設定・解除します。

データ構造と型

  • ParseState: クエリ解析中のグローバルな状態を保持する中央集権的な構造体。レンジテーブル、名前空間、式構築フラグ、ウィンドウ定義、フック状態を含みます。
  • ParseExprKind: 式が置かれたコンテキスト（WHERE, SELECT_TARGET, JOIN_ON など）を識別する列挙型。
  • ParseNamespaceItem: 名前解決のための名前空間の1要素。RTEへのリンクや可視性フラグを持ちます。
  • ParseNamespaceColumn: 名前空間アイテム内の各カラムのセマンティック参照先（p_varno, p_varattno）や構文的参照先を管理する構造体。
  • GraphTableParseState: GRAPH_TABLE 参照中のラベル、プロパティ、変数名前空間を保持する構造体。
  • ParseCallbackState: エラー位置コールバック用の状態構造体。

制御フローとデータフロー

  • **解析の初期化**: 解析の開始時（またはサブクエリへの突入時）に make_parsestate() が呼ばれ、親 ParseState の環境（ソーステキスト、フック、クエリ環境など）を継承した新しいコンテキストが構築されます。
  • **名前解決フロー**: クエリ内のカラムやテーブルが参照される際、ParseState の p_namespace リストにある ParseNamespaceItem が走査され、ParseNamespaceColumn を通じてベースリレーションの Var ノード（p_varno, p_varattno）へマッピングされます。
  • **エラー処理フロー**: 解析中にエラーが発生した場合、parser_errposition または ParseCallbackState を通じて p_sourcetext から正確な文字位置が計算され、クライアントに返されるエラーメッセージに反映されます。

直接依存

  • nodes/parsenodes.h: 生のパーサツリーノード定義への依存。
  • utils/queryenvironment.h: クエリ環境（QueryEnvironment）の定義への依存。
  • utils/relcache.h: リレーションキャッシュ（Relation）の定義への依存。

関連コード

  • src/backend/parser/parse_node.c: make_parsestate, free_parsestate, parser_errposition などの実装。
  • src/include/parser/analyze.h: クエリ解析のエントリポイント。
  • src/include/nodes/parsenodes.h: レンジテーブル（RTE）や式ノードの基盤定義。

読者向けメモ

  • **メモリ管理**: ParseState は palloc0_object によりアロケートされ、呼び出し元が free_parsestate() を介して明示的に解放するライフサイクルを持ちます。
  • **マルチバイト文字の扱い**: エラー位置（parser_errposition）の計算では、PostgreSQLのマルチバイト文字列長関数（pg_mbstrlen_with_len）を使用し、バイトオフセットを正しい文字インデックスに変換しています。
  • **LATERALと可視性**: p_lateral_active フラグや p_lateral_only 属性により、相関参照や LATERAL サブクエリのスコープ制御を厳密に実装しています。
