src/include/funcapi.h

概要

PostgreSQL の関数マネージャ（fmgr）において、集合返却関数（SRF: Set Returning Function）、複合型を返す関数、および可変長引数（VARIADIC）を処理するためのデータ構造、マクロ、関数宣言を提供するヘッダーファイル。

モジュール内での役割

src/include サブシステムの一部として、C言語で記述された拡張関数や内部関数が PostgreSQL の型システムやエグゼキュータと安全に連携するための公開インターフェースを定義する。実装ファイルである src/backend/utils/fmgr/funcapi.c とペアをなし、関数結果の型解決やステート管理の共通基盤を提供する。

責務

  • 複合型（レコードや行）を C の文字列配列から構築するための AttInMetadata 構造体の定義。
  • 値を呼び出し間で維持しながら集合を返す Value-Per-Call モードのための FuncCallContext 構造体と、制御用マクロ群（SRF_FIRSTCALL_INIT 等）の提供。
  • 関数や式の戻り値の型情報を解析・分類する API（get_call_result_type 等）の宣言。
  • 可変長引数（VARIADIC）を解析・抽出する extract_variadic_args の宣言。

重要なシンボル

  • FuncCallContext: SRF の呼び出し間でカウンターやユーザ定義コンテキストを保持するための構造体。
  • AttInMetadata: C 文字列からタプルを構築するために必要な属性メタデータや入力関数情報を保持する構造体。
  • TypeFuncClass: 関数や式の戻り値の型分類（スカラー、複合、レコード等）を表す列挙型。
  • SRF_FIRSTCALL_INIT / SRF_RETURN_NEXT / SRF_RETURN_DONE: SRF のライフサイクル（初期化、次要素返却、終了）を記述するための標準マクロ群。
  • InitMaterializedSRF: 一括マテリアライズドモードの SRF を初期化するためのヘルパー関数。

制御フローとデータフロー

1. **関数呼び出しの初期化**:

  • SRF の初回の呼び出しでは SRF_IS_FIRSTCALL() が真を返し、SRF_FIRSTCALL_INIT()（内部で init_MultiFuncCall を呼び出し）によって FuncCallContext とマルチコール用メモリコンテキストが初期化される。

    • 2. **データ生成と返却**:

  • 2回目以降の呼び出しでは SRF_PERCALL_SETUP() により既存のコンテキストが復元される。
  • ユーザー関数はループまたはカウンターに基づき、SRF_RETURN_NEXT を用いて 1 行ずつ Datum を返却する。

    • 3. **終了処理**:

  • すべての行を返し終えた場合、SRF_RETURN_DONE を呼び出して end_MultiFuncCall を実行し、割り当てられたコンテキストのクリーンアップと終了状態（ExprEndResult）の設定を行う。

直接依存

  • access/tupdesc.h: タプル記述子（TupleDesc）の定義と操作。
  • executor/executor.h: エグゼキュータ関連の型（FunctionCallInfo 等）。
  • executor/tuptable.h: タプルテーブル関連の定義。
  • fmgr.h: 関数マネージャの基本定義（Datum, PG_FUNCTION_ARGS 等）。

関連コード

  • src/backend/utils/fmgr/funcapi.c: funcapi.h で宣言された関数の実体を実装するペアファイル。
  • src/include/windowapi.h: ウィンドウ関数用の類似したAPI定義。

読者向けメモ

  • Value-Per-Call モードの SRF はクエリの途中で中断される可能性がある（LIMIT 句など）ため、メモリコンテキスト外の非メモリリソース（ファイルディスクリプタ等）を呼び出し間で維持しないこと。
  • 一括マテリアライズドモードが必要な場合は、InitMaterializedSRF と tuplestore を使用する設計が推奨される。
