src/include/c.h

概要

PostgreSQL の全ソースファイル (.c) にインクルードされる基盤ヘッダーファイル。コンパイラ特性の抽象化、標準データ型の定義、メモリ整列・アライメント計算、アッセション機構、およびプラットフォーム固有の差異を吸収するためのマクロや型定義を提供する。

モジュール内での役割

src/include ディレクトリ内における最も基礎的なヘッダーであり、postgres.h または postgres_fe.h を経由してすべてのバックエンド・フロントエンドモジュールから最初に参照される。他のすべてのインクルードファイルやソースコードに対して、一貫した型システムとプラットフォーム非依存のマクロ環境を供給する。

責務

  • 環境設定とシステムヘッダーの統括: pg_config.h 系統の構成ファイルおよび標準 C ライブラリヘッダーの取り込み。
  • コンパイラ特性の抽象化: inline、アトリビュート (pg_attribute_unused, pg_nodiscard, pg_noreturn 等)、分岐予測 (likely, unlikely) などのマクロ化。
  • 基本データ型と型の拡張: Pointer, int8-int64, uint8-uint64, int128, uint128、および可変長データ型 (varlena) や識別子型 (NameData) の定義。
  • アライメントとメモリ管理補助: MAXALIGN、MemSet などのメモリアライメント計算および高速ゼロクリアマクロの提供。
  • アサーションと検証機構: Assert, StaticAssertDecl などのデバッグおよびコンパイル時検証マクロの提供。

重要なシンボル

関数ポインタおよびポインタ型

  • pg_funcptr_t: 警告 (-Wcast-function-type) を回避しつつ任意の関数ポインタをキャストするための汎用関数ポインタ型 (void (*)(void)).
  • Pointer: メモリ上の任意のオブジェクトのアドレスを保持する型 (void *)。歴史的な名称。

整数型および拡張型

  • int128: コンパイラがサポートしアライメント条件を満たす場合に定義される 128 ビット符号付き整数型。
  • uint128: コンパイラがサポートしアライメント条件を満たす場合に定義される 128 ビット符号なし整数型。

可変長・システムデータ構造

  • varlena: すべての可変長データ型（bytea, text 等）が共有する物理ヘッダー構造体。先頭 4 バイトの長さを保持する vl_len_ と可変長データの本体 vl_dat を持つ。
  • int2vector: 1次元の int16 配列を表現し、システムカタログ等で使用される特殊配列型。
  • oidvector: 1次元の Oid 配列を表現し、主にシステムカタログのプライマリキー等で使用される特殊配列型。
  • NameData: カタログ上の識別子（名前）を格納するため、厳密に NAMEDATALEN バイトにパディングされた C 文字列ラッパー構造体。

アライメントブロック

  • PGAlignedBlock: BLCKSZ バイトの領域を持ち、MAXIMUM_ALIGNOF でアライメントされたページバッファ用構造体。
  • PGIOAlignedBlock: BLCKSZ バイトの領域を持ち、ダイレクト I/O 等で要求される PG_IO_ALIGN_SIZE でアライメントされたページバッファ用構造体。
  • PGAlignedXLogBlock: XLOG_BLCKSZ バイトの領域を持ち、ダイレクト I/O に対応した WAL ログバッファ用構造体。

シグナル情報

  • pg_signal_info: シグナル送信元のプロセス ID (pid) とユーザー ID (uid) を保持するプラットフォーム非依存の構造体。

制御フローとデータフロー

c.h は実行コードを持つ .c ファイルではなくヘッダーファイルであるため、特定の制御フローやデータフローの主導権は持たない。しかし、このファイルで定義されるマクロ群が以下のデータフロー最適化を駆動する：

  • MemSet / MemSetAligned: 小規模かつ size_t アライメントされたメモリ領域のゼロクリア時に、関数呼び出しオーバヘッドを伴う標準ライブラリの memset をバイパスし、インラインのループ展開による高速初期化パスを選択する。
  • likely / unlikely: ホットパスにおける条件分岐の最適化ヒントをコンパイラに提供する。

関連コード

  • src/include/postgres_fe.h: フロントエンド側で c.h を内包し、クライアント用定義を追加するファイル。
  • src/include/varatt.h: varlena 構造体および TOAST 圧縮・展開に関連する操作マクロ群を提供するファイル。

読者向けメモ

  • メモリ配置とアライメント: MAXALIGN や BUFFERALIGN などのマクロは、CPU アーキテクチャの制約（特に 8 バイト境界やキャッシュライン境界）に依存するため、バッファやディスクブロックを扱う際には必ず対応するアライメント構造体（PGAlignedBlock 等）を使用する必要がある。
  • マルチプラットフォーム対応: Windows (WIN32/CYGWIN)、GCC、Clang、MSVC などの差異を吸収するため、多くのプリプロセッサ分岐が含まれている。
  • フロントエンド・バックエンド共通性: 本ファイルは両者からインクルードされるため、原則として通常の extern 変数宣言は行わず、マクロと型定義を中心に構成されている。
