src/include/access/tupmacs.h

概要

src/include/access/tupmacs.h は、インデックスおよびヒープタプル双方の内部データ構造を操作・分解・構築するために用いられる低レベルのマクロおよびインライン関数群を定義するヘッダーファイルです。タプル内の属性単位での型アラインメント、可変長データ（TOAST 含む）のサイズ計算、NULL ビットマップの検査、および Datum 値の読み書きを高速かつ安全に行うための基本機能を提供します。

モジュール内での役割

PostgreSQL のアクセスメソッド（Heap、Index 等）やタプル処理サブシステムにおいて、ストレージ上のバイナリ表現と上位レイヤーが扱う Datum 値や属性配列との橋渡しを行います。特に src/include/access/htup_details.h やタプル変形処理などの基盤となり、データアラインメントや NULL 判定の共通ロジックを集約することでコードの重複を排除しています。

責務

  • **NULL 判定と配列変換**: タプルヘッダの NULL ビットマップを検査し、特定の属性が NULL かどうかを判定する (att_isnull, first_null_attr)。また、ビットマップを一括してブール配列へ効率的に展開する (populate_isnull_array)。
  • **アラインメント計算**: PostgreSQL のデータ型定義 (TYPALIGN_xxx) を実際のバイト境界にマッピングし、固定長・可変長（varlena）属性のオフセット位置を計算・調整する (typalign_to_alignby, att_align_datum, att_align_pointer, att_align_nominal 系)。
  • **属性の取得と格納 (Datum 変換)**: タプル上の物理バッファ位置から Datum を取り出す、または書き戻す (fetch_att, fetch_att_noerr, fetchatt, align_fetch_then_add, store_att_byval)。
  • **可変長データの長官管理**: 可変長属性（-1）や C 文字列（-2）のサイズを動的に加算・追跡する (att_addlength_pointer, att_addlength_datum)。

重要なシンボル

NULL ビットマップ関連

  • static inline bool att_isnull(int ATT, const uint8 *BITS)
  • 属性番号 ATT が NULL かどうかを判定します。ビットが 0 ならば NULL（true）、1 ならば非 NULL（false）を返します。
  • static inline void populate_isnull_array(const uint8 *bits, int natts, bool *isnull)
  • NULL ビットマップを 8 バイト単位のマスク処理とビット拡散（SPREAD_BITS_MULTIPLIER_32）を用いて高速に bool 配列へ一括変換します。
  • static inline int first_null_attr(const uint8 *bits, int natts)
  • ビットマップをスキャンし、最初に現れる NULL 属性の 0-based 属性番号を返します。

アラインメント・オフセット計算関連

  • static inline uint8 typalign_to_alignby(char typalign)
  • カタログの typalign 文字（c, s, i, d 等）を実際の数値バイト境界 (sizeof(char), ALIGNOF_SHORT, ALIGNOF_INT, ALIGNOF_DOUBLE) に変換します。
  • att_align_datum, att_align_pointer, att_align_nominal (および *_alignby マクロ群)
  • 属性の型定義や実際のポインタ位置（1 バイトヘッダの varlena かどうかの判定を含む）を考慮して、次の属性のための正しいオフセットアラインメントを計算します。

属性の取得・格納 (Datum) 関連

  • #define fetchatt(A,T)
  • Form_pg_attribute または CompactAttribute の情報をもとに、タプル上のポインタ T から Datum を取得します。
  • static inline Datum fetch_att(const void *T, bool attbyval, int attlen)
  • attbyval が真の場合は指定長（1, 2, 4, 8 バイト）に応じたプリミティブ値を Datum に変換し、偽の場合はポインタをそのまま Datum として返します。
  • static inline Datum fetch_att_noerr(const void *T, bool attbyval, int attlen)
  • エラーチェックを省略した軽量版の属性取得関数です。
  • static inline Datum align_fetch_then_add(const char *tupptr, uint32 *off, bool attbyval, int attlen, uint8 attalignby)
  • アラインメント調整、fetch_att_noerr による値の取得、およびオフセットの更新（att_addlength_pointer 相当）を一度に行います。
  • static inline void store_att_byval(void *T, Datum newdatum, int attlen)
  • 値渡し（byval）の Datum を指定されたタプル内のアドレスに格納します。

制御フローとデータフロー

タプルから全属性を分解（デフォーム）する際の一般的なデータフローは以下のヘルパー連携によって成り立っています： 1. **NULL チェック**: ループ内で att_isnull() を呼び出すか、事前に populate_isnull_array() で配列化して各属性の存在有無を確認します。 2. **位置合わせと取得**: タプルデータ領域のポインタとオフセットに対し、align_fetch_then_add()（または att_align_pointer と fetch_att の組み合わせ）を適用します。

  • 固定長データの場合、attalignby に従って *off をアラインし、型長分を読み取って Datum に変換後、オフセットを進めます。
  • 可変長データ（attlen == -1）の場合、VARATT_IS_SHORT() や VARATT_NOT_PAD_BYTE() を用いて 1 バイトヘッダか 4 バイトヘッダかを判定し、パディングをスキップせずに位置を特定、VARSIZE_ANY() でサイズを取得してオフセットを進めます。

直接依存

  • "varatt.h" (可変長属性のマクロ VARATT_IS_SHORT, VARSIZE_ANY 等)

関連コード

  • src/include/access/htup_details.h: ヒープタプルの詳細構造とタプル変形関数の本体を定義。
  • src/include/access/tupdesc.h: タプル記述子（TupleDesc, CompactAttribute）の定義。

読者向けメモ

  • **メモリ安全性とアラインメント**: 本ファイルのインライン関数やマクロは、CPU のアラインメント制約を直接満たす必要があるため、入力ポインタ T やオフセットが適切に調整されていることが前提となります。
  • **フロントエンドとバックエンドの切り替え**: #ifndef FRONTEND ガードにより、PostgreSQL バックエンド内部でのみ使用されるエラー処理（elog(ERROR, ...)）やアサーションが、フロントエンド（libpq 等）向けビルドでは除外されます。
