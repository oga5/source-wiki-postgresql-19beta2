src/include/access/table.h

概要

src/include/access/table.h は、特定のテーブルアクセスメソッド（Table AM）に依存しない、テーブル全般のオープンやクローズなどの汎用ルーチンを提供します。

モジュール内での役割

本ファイルは src/include/access サブシステムの構成要素であり、インデックスや複合型を除外して、リレーションがテーブルとして正しく扱えるかを検証しながら開閉する共通インターフェースを定義しています。実体実装はペアファイルである src/backend/access/table/table.c に存在します。

責務

  • テーブルリレーションのオープンおよびクローズ関数（table_open, table_close 等）の宣言。
  • RangeVar やリレーション OID を用いた柔軟なテーブルオープン手段（拡張版や存在しない場合のエラー抑制を含む）の提供。
  • 開かれたリレーションがインデックス等ではないテーブル系のオブジェクトであるかの種別検証。

重要なシンボル

  • table_open: Oid とロックモードを指定してテーブルリレーションを開く。
  • try_table_open: 存在しない場合にエラーとせず NULL を返す、table_open の安全版。
  • table_openrv: RangeVar ノードを指定してテーブルを開く。
  • table_openrv_extended: RangeVar ノードと missing_ok フラグを指定して拡張オープンを行う。
  • table_close: 指定したロックモードでテーブルリレーションを閉じる。

制御フローとデータフロー

1. 呼び出し元が OID または RangeVar とロックモードを指定して table_open または関連関数を呼び出します。 2. ペアファイル側の実体処理が下位のリレーション機構（relation_open 等）を呼び出してリレーション構造体（Relation）を取得します。 3. 取得したリレーションに対して validate_relation_as_table 内で relkind を検証し、テーブル、シーケンス、ビュー、外部テーブル等として有効であるか確認します。 4. 検証に成功した Relation ポインタを呼び出し元に返却します。エラー時は ereport(ERROR) が発生します。

直接依存

  • nodes/primnodes.h (RangeVar 等の定義のため)
  • storage/lockdefs.h (LOCKMODE の定義のため)
  • utils/relcache.h (Relation の定義のため)

関連コード

  • src/backend/access/table/table.c: 本ヘッダーで宣言されている関数の実装ファイル。

読者向けメモ

  • 本ファイルで定義される関数は、通常のインデックスオープン関数とは異なり、対象がテーブル（およびビューやパーティション等）であることを保証するための検証ステップを含んでいます。
