src/include/executor/instrument_node.h

概要

パラレルクエリ実行におけるノード固有の統計情報（EXPLAIN ANALYZE 用）のデータ構造と、ワーカー間の統計集約を支えるインライン関数を定義するヘッダーファイルです。ポインタを持たない設計になっており、プロセス間でのメモリコピーや動的共有メモリ（DSM）経由での集約を容易にしています。

モジュール内での役割

src/include/executor サブシステムにおいて、クエリ実行ノード（集約、各種スキャン、ソート、ハッシュ、Memoizeなど）の性能計測および並列ワーカーからの統計情報収集を標準化する役割を持ちます。リーダープロセスが各ワーカーの実行結果を集約して表示するための基盤を提供します。

責務

  • ノード別統計構造体の提供: 集約（Aggregate）、インデックススキャン、Bitmap Heapスキャン、Memoize、ソート、ハッシュ、インクリメンタルソート、順次スキャン、TID範囲スキャン等の統計データを保持する構造体を定義する。
  • 並列共有コンテナの提供: ワーカーごとの情報を格納するため、FLEXIBLE_ARRAY_MEMBER を持つ共有メモリ用コンテナ構造体（Shared*Info）を定義する。
  • I/O統計の集約処理: IOStats 構造体および、複数の統計をマージするためのインライン関数 AccumulateIOStats を提供する。
  • DSMキーオフセットの定義: スキャン計測用のTOCキーを生成するオフセットマクロ PARALLEL_KEY_SCAN_INSTRUMENT_OFFSET を提供する。

重要なシンボル

集約・Memoize・ハッシュ関連

  • AggregateInstrumentation: ハッシュのピークメモリ使用量、ディスク使用量（kB）、バッチ数を保持する。
  • SharedAggInfo: AggregateInstrumentation のワーカー数および可変長配列を持つ並列共有コンテナ。
  • MemoizeInstrumentation: キャッシュヒット、ミス、エビクション、オーバーフロー、ピークメモリ使用量を保持する。
  • SharedMemoizeInfo: MemoizeInstrumentation を格納する並列共有コンテナ。
  • HashInstrumentation: バケット数、バッチ数（実行時および計画時）、ピークメモリ使用量を保持する。
  • SharedHashInfo: HashInstrumentation を格納する並列共有コンテナ。

スキャンおよびI/O関連

  • IOStats: プレフェッチ数、距離の合計/最大、待機数、I/O回数・ブロック数・進行中I/Oを保持する共通のI/O統計構造体。
  • TableScanInstrumentation: IOStats を内包し、テーブルスキャン系のI/O計測を担う。
  • AccumulateIOStats: src の IOStats フィールドを dst に加算し、最大値を適切に更新するインラインヘルパー関数。
  • IndexScanInstrumentation: インデックスの検索回数（nsearches）を保持する。
  • SharedIndexScanInstrumentation: IndexScanInstrumentation を格納する並列共有コンテナ。
  • BitmapHeapScanInstrumentation: 確実なページ数、損失ページ数、および TableScanInstrumentation を保持する。
  • SharedBitmapHeapInstrumentation: BitmapHeapScanInstrumentation を格納する並列共有コンテナ。
  • SeqScanInstrumentation: 順次スキャン用の TableScanInstrumentation ラッパー構造体。
  • SharedSeqScanInstrumentation: SeqScanInstrumentation を格納する並列共有コンテナ。
  • TidRangeScanInstrumentation: TID範囲スキャン用の TableScanInstrumentation ラッパー構造体。
  • SharedTidRangeScanInstrumentation: TidRangeScanInstrumentation を格納する並列共有コンテナ。

ソート関連

  • TuplesortSpaceType: ソート領域の種類（ディスクまたはメモリ）を表す列挙型。
  • TuplesortMethod: ソートアルゴリズムの種類（進行中、ヒープソート、クイックソート、外部ソート、外部マージ）を表すビットマスク用列挙型。
  • TuplesortInstrumentation: ソート手法、領域タイプ、使用量（kB）を保持する。
  • SharedSortInfo: TuplesortInstrumentation を格納する並列共有コンテナ。
  • IncrementalSortGroupInfo: インクリメンタルソートの各グループ（フルソート／プレフィックスソート）におけるグループ数、ディスク・メモリ使用量の最大／合計、ソート手法のビットマスクを保持する。
  • IncrementalSortInfo: フルソートとプレフィックスソートの IncrementalSortGroupInfo をまとめた構造体。
  • SharedIncrementalSortInfo: IncrementalSortInfo を格納する並列共有コンテナ。

制御フローとデータフロー

本ファイルはデータ構造の定義が主であり、唯一の関数である AccumulateIOStats がデータフローの中核を担います。 1. データ収集: 各並列ワーカーが自身の実行ノード内でローカルな IOStats や各種 Instrumentation 構造体を更新します。 2. プロセス間転送: シャットダウン時に、ポインタを含まない純粋なバイナリデータとして各ワーカーの構造体が共有メモリ上のコンテナ（Shared*Info）にコピーされます。 3. 集約: リーダープロセスが Shared*Info からデータを読み出し、AccumulateIOStats などのヘルパーを用いて統計情報を合算し、EXPLAIN ANALYZE の出力として構築します。

直接依存

  • なし（純粋なデータ型定義およびインライン関数のみで構成され、明示的な #include を持たない）。

関連コード

  • src/include/executor/instrument.h: 標準的な非並列実行の計測インフラ（Instrumentation 構造体など）を定義する関連ファイル。
  • src/backend/executor/: 各実行ノード（nodeSeqscan.c, nodeAgg.c など）において、ここで定義された構造体インスタンスの更新や並列集約が行われます。

読者向けメモ

  • メモリレイアウトとポインタの不在: 構造体はプロセス間で安全にコピー（または共有メモリ上に配置）できるよう、一切のポインタを含まず、可変長配列（FLEXIBLE_ARRAY_MEMBER）を利用したレイアウトになっています。
  • インライン関数の挙動: AccumulateIOStats は単純なカウンタ加算に加え、distance_max や distance_capacity などの最大値追跡を適切に比較・更新するため、呼び出し時に値の取りこぼしが発生しないよう設計されています。
