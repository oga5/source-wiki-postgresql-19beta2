src/include/executor/instrument_node.h

概要

PostgreSQL の並列クエリ実行時におけるノード固有の計測（instrumentation）データ構造を定義するヘッダーファイルです。EXPLAIN ANALYZE の結果表示のため、ワーカープロセスが自身の計測情報をプロセス間で安全にコピー・共有するためのコンテナ構造体を定義しています。

モジュール内での役割

src/include/executor サブシステムの一部として、実行時ノード（集計、ソート、各種スキャン、ハッシュ結合など）のパフォーマンス計測および並列ワーカー間の情報集約を支えます。基盤的な計測機構である executor/instrument.h を補完し、ノード固有の詳細なメトリクスを提供します。

責務

  • 各種実行ノード（Aggregate, IndexScan, BitmapHeapScan, Memoize, Tuplesort, Hash, IncrementalSort, SeqScan, TidRangeScan）向けの計測用構造体の定義。
  • 並列クエリ実行時にワーカーごとの計測データを格納する共有メモリコンテナ構造体（Shared*Info / Shared*Instrumentation）の定義。
  • IOStats のような共通 I/O 統計を統合・集約するためのインラインヘルパー関数の提供。
  • プロセス間で安全にコピーできるよう、ポインタを含まないデータレイアウトの維持。

重要なシンボル

共通・I/O 統計関連

  • PARALLEL_KEY_SCAN_INSTRUMENT_OFFSET: プランノード ID に加算し、スキャン計測用 TOC キーを生成するためのオフセット値（0xD000000000000000）。
  • IOStats: プリフェッチ、距離、待機回数、I/O 回数・ブロック数などの読み取りストリーム・I/O 統計を保持する構造体。
  • AccumulateIOStats: ソース側の IOStats を宛先側へ加算・統合するインライン関数。

ノード別計測および共有コンテナ構造体

  • **Aggregate**: AggregateInstrumentation（ハッシュメモリピーク、ディスク使用量、バッチ数）、SharedAggInfo
  • **IndexScan**: IndexScanInstrumentation（検索回数 nsearches）、SharedIndexScanInstrumentation
  • **BitmapHeapScan**: BitmapHeapScanInstrumentation（正確なページ数、損失ページ数、TableScanInstrumentation）、SharedBitmapHeapInstrumentation
  • **Memoize**: MemoizeInstrumentation（キャッシュヒット/ミス、エビクション、オーバーフロー、メモリピーク）、SharedMemoizeInfo
  • **Tuplesort / Sort**: TuplesortSpaceType, TuplesortMethod（ソート手法のビットマスク）, TuplesortInstrumentation, SharedSortInfo
  • **Hash**: HashInstrumentation（バケット数、バッチ数、メモリピーク）、SharedHashInfo
  • **IncrementalSort**: IncrementalSortGroupInfo, IncrementalSortInfo, SharedIncrementalSortInfo
  • **SeqScan**: SeqScanInstrumentation, SharedSeqScanInstrumentation
  • **TidRangeScan**: TidRangeScanInstrumentation, SharedTidRangeScanInstrumentation

制御フローとデータフロー

  • **データ収集**: 並列クエリの実行中、各ワーカープロセスは自身のローカルメモリ上で対応するノードの計測構造体（例: AggregateInstrumentation, TuplesortInstrumentation 等）を更新します。
  • **データ集約**: エグゼキューターのシャットダウン時に、各ワーカーは自身の計測情報を共有メモリコンテナ（Shared*Info などの sinstrument / winstrument 配列）の自プロセス担当スロットへコピーします。
  • **リーダー側表示**: リーダープロセスは共有メモリ上の各ワーカーの計測情報を読み取り、AccumulateIOStats などのヘルパーや集計処理を介して結合し、EXPLAIN ANALYZE 出力としてユーザーに提示します。

直接依存

  • なし（純粋なデータ構造とインライン関数のみで構成され、外部インクルードを持たない）。

関連コード

  • src/include/executor/instrument.h: 標準的な実行ノード全体の計測基盤（Instrumentation 構造体など）。
  • src/backend/executor/node*.c: 各種エグゼキューターノードの実装ファイル（ここで定義された構造体を使用して統計を記録）。

読者向けメモ

  • **メモリ所有権とライフタイム**: 定義されているすべての構造体はポインタを一切含みません。これは、DSM（動的共有メモリ）等を介してプロセス間で安全に一括コピー（シリアライズなしのバイナリ転送）するためです。
  • **フレキシブル配列**: 共有コンテナ構造体（SharedAggInfo など）の末尾には FLEXIBLE_ARRAY_MEMBER を用いた配列が定義されており、ワーカー数に応じた可変長の領域として確保されます。
  • **不変条件**: TuplesortMethod において、SORT_TYPE_STILL_IN_PROGRESS は値 0 を取り、ワーカーが未実行であることを示します。その他の手法はビットフラグとして定義されており、NUM_TUPLESORTMETHODS（4）と同期している必要があります。
