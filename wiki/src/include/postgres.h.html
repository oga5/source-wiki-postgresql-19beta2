src/include/postgres.h

概要

src/include/postgres.h は、PostgreSQLのバックエンド用ソースファイルが最初にインクルードすべき主要なヘッダーファイルです。フロントエンド向けコードが postgres_fe.h を使用するのに対し、本ファイルはバックエンド環境全体で広く必要とされる型定義、マクロ、およびインライン変換関数を提供します。主に Datum 型とそのサポート関数、およびバックエンド固有のユーティリティ定義をカプセル化しています。

モジュール内での役割

src/include モジュール内において、本ファイルは基本型定義を行う c.h と、エラー処理の utils/elog.h、メモリ管理の utils/palloc.h をまとめ上げる基盤の役割を果たします。バックエンド特有の表現（Datum など）を定義し、型安全性やプラットフォーム間の差異を吸収する中核となります。

責務

  • **Datum 型の定義と管理**: 8バイトの汎用値コンテナである Datum 型およびそのサイズ定数 (SIZEOF_DATUM) を提供する。
  • **型変換・マッピング**: C言語の基本型（bool, char, 整数型, 浮動小数点数型, ポインタなど）と Datum 間を相互変換するインライン関数およびマクロ群を提供する。
  • **複合型・ユーティリティの提供**: 値とNULL状態を効率的に保持する NullableDatum 構造体や、三値論理を表す pg_ternary 型、EXEC_BACKEND 向けの NON_EXEC_STATIC マクロなどを定義する。

重要なシンボル

型・データ構造

  • Datum: 64ビット符号なし整数 (uint64_t)。値渡し型または参照渡し型へのポインタを格納する汎用コンテナ。
  • NullableDatum: Datum value と bool isnull を保持する構造体。空間的局所性を高めて配列等で効率的に扱われる。
  • pg_ternary: PG_TERNARY_FALSE (0), PG_TERNARY_TRUE (1), PG_TERNARY_UNSET (-1) を定義する三値論理用列挙型。

変換関数ファミリ (Datum 相互変換)

  • **真偽値・文字・整数**: DatumGetBool, BoolGetDatum, DatumGetChar, CharGetDatum, DatumGetUInt8, UInt8GetDatum, DatumGetInt16, Int16GetDatum, DatumGetUInt16, UInt16GetDatum, DatumGetInt32, Int32GetDatum, DatumGetUInt32, UInt32GetDatum, DatumGetInt64, Int64Get64Datum（および関連する 64-bit/OID/TransactionId/CommandId 用の各関数）。
  • **ポインタ・文字列**: DatumGetPointer, PointerGetDatum (マクロによるポインタ型チェック付き), DatumGetCString, CStringGetDatum, DatumGetName, NameGetDatum。
  • **浮動小数点数**: DatumGetFloat4, Float4GetDatum, DatumGetFloat8, Float8GetDatum (共用体 union を用いてビット列としての変換を保証)。

制御フローとデータフロー

本ファイルは関数定義の大半が static inline 関数やマクロで構成されているため、ファイル単体の独立した実行制御フローは持ちません。

  • **データフロー**: クライアントやストレージから渡された各種Cデータ型は、各 *GetDatum 関数（またはマクロ）を通じて Datum に変換され、エグゼキューターや関数マネージャー (fmgr) へ引き渡されます。演算や処理が終わると、対応する DatumGet* 関数によって元のCデータ型へと復元されます。浮動小数点数変換では、アライメントや表現の差異を安全に吸収するため union を介したビット再解釈フローを経ます。

直接依存

  • c.h: 基本型定義（bool, uint8, Oid, Pointer など）
  • utils/elog.h: エラーログ・メッセージ出力機能
  • utils/palloc.h: メモリ割り当て機能

関連コード

  • src/include/postgres_fe.h: クライアント（フロントエンド）側で使用される対応ヘッダー。
  • src/backend/tcop/postgres.c: 本ヘッダーをインクルードし、バックエンドのトラフィックコップのメイン処理を行う対向ファイル。

読者向けメモ

  • **メモリ所有権・ライフタイム**: CStringGetDatum や NameGetDatum などで扱われる参照渡し型のポインタ（C文字列や NameData）は、呼び出し元が適切なライフタイムを保証する必要があります。
  • **プラットフォーム仮定**: Datum は一貫して 8 バイト（64ビット）として扱われ、ポインタ幅がこれを超えるプラットフォームは想定していません。
  • **コンパイル時の型安全性**: PointerGetDatum マクロは true ? (X) : NULL の条件式を用いることで、引数 X がポインタ型でない場合にコンパイルエラーを発生させる仕組みになっています。
