src/include/storage/smgr.h

概要

PostgreSQL のストレージマネージャー（Storage Manager）スイッチの公開インターフェースを定義するヘッダーファイルです。ファイルシステム上のリレーションファイルに対するすべての操作は、このストレージマネージャー層を介してディスパッチされます。

モジュール内での役割

  • src/backend/storage/smgr/smgr.c とペアをなし、バックエンド全体で使用されるストレージ操作の共通 API を提供します。
  • relfilelocator.h や block.h などの低レベルなストレージ型定義を利用し、バッファマネージャーやアクセス手法層と物理ストレージの仲立ちをします。

責務

  • 物理リレーションファイルを開く・閉じる・破棄するといったライフサイクル管理のデータ構造（SMgrRelationData）を定義する。
  • キャッシュされたファイルハンドルやピン留め（Pinning）機構のインターフェースを宣言する。
  • 読み込み、書き込み、拡張、同期などのストレージ操作関数およびインラインヘルパー（smgrread, smgrwrite）を提供する。

重要なシンボル

  • struct SMgrRelationData: 物理リレーションの識別子、フォークごとのキャッシュサイズ、ストレージマネージャーのセレクター、ピン留め情報を保持するキャッシュ済みファイルハンドル構造体。
  • typedef SMgrRelation: SMgrRelationData * へのエイリアス。
  • macro: SmgrIsTemp(smgr): 指定されたストレージ関係が一時リレーションかどうかを判定するマクロ。
  • function: smgrread / function: smgrwrite: 単一ブロックの読み書きを行うためのインラインヘルパー関数（内部でベクトル処理関数を呼び出す）。

制御フローとデータフロー

  • リレーションが最初にアクセスされる際、smgropen() が呼び出されてハッシュテーブルから（または新規に）SMgrRelation エントリを取得します。
  • 通常のクエリ処理ではリレーションキャッシュを介して SMgrRelation が参照され、トランザクション終了時にピン留めされていないエントリが自動解放されます。
  • 読み書き要求は smgrread や smgrwrite などの公開関数から、より汎用的な smgrreadv / smgrwritev へ渡され、最終的に個別のストレージ実装（磁気ディスク用モジュール md.c など）へディスパッチされます。

読者向けメモ

  • SMgrRelationData の先頭フィールドである smgr_rlocator はハッシュテーブルのルックキーとして機能するため、順序の変更ができません。
  • トランザクション境界でのクリーンアップや、割り込み処理に伴うファイルディスクリプタの解放（PROCSIGNAL_BARRIER_SMGRRELEASE）の仕組みに注意してください。
