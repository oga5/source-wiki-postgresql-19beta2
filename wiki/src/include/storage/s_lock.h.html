src/include/storage/s_lock.h

概要

PostgreSQLのスピンロック機構の定義と、アーキテクチャ依存のアトミック操作（TAS: Test-And-Set）およびプラットフォーム非依存のスピン待機ループのインターフェースを提供するヘッダーファイルである。実際のC実装は src/backend/storage/lmgr/s_lock.c に存在する。

モジュール内での役割

src/include/storage モジュール内において、最も低レベルな同期プリミティブであるスピンロックの定義を担当する。軽量ロック（LWLock）や他の高レベルロック機構の下層基盤として位置づけられる。

責務

  • 各サポートプラットフォームに応じたアトミックなテスト＆セット（TAS / TAS_SPIN）、スピンロック解除（S_UNLOCK）、初期化（S_INIT_LOCK）、CPU遅延（SPIN_DELAY）のマクロおよびインライン関数を提供する。
  • コンパイラやハードウェアによるメモリ再順序付け（メモリバリア）を防ぎ、クリティカルセクション前後のアクセス順序を保証する。
  • 競合が激しい場合のプラットフォーム非依存なバックオフ・スリープ制御（SpinDelayStatus、s_lock）を定義する。

重要なシンボル

  • 型定義・定数:
  • slock_t: プラットフォームごとのスピンロック変数の型（例: unsigned char, int, LONG 等）。
  • SpinDelayStatus: スピン待機ループの状態を追跡する構造体（試行回数 spins、遅延回数 delays、現在の遅延時間 cur_delay、呼び出し元情報等を保持）。
  • コアインターフェースマクロ:
  • S_LOCK(lock): スピンロックを獲得する（失敗時はプラットフォーム非依存の待機・タイムアウト処理へ移行）。
  • S_UNLOCK(lock): スピンロックを解放する。
  • S_INIT_LOCK(lock): スピンロックを初期化（未取得状態に）する。
  • TAS(lock) / TAS_SPIN(lock): アトミックにテスト＆セットを実行し失敗時に非ゼロを返す低レベルマクロ（直接呼び出し禁止）。
  • SPIN_DELAY(): スピン待機中のCPU負荷軽減用遅延（x86の rep; nop / PAUSE や ARM の isb 等）。
  • サポート関数:
  • s_lock(): 競合時のプラットフォーム非依存スピン待機ループの実装関数。
  • init_spin_delay() / init_local_spin_delay(): SpinDelayStatus を初期化するインライン関数・マクロ。
  • perform_spin_delay() / finish_spin_delay(): スピン待機の進行と終了処理を行う関数。

制御フローとデータフロー

1. 呼び出し元が SpinLockAcquire 等を介して S_LOCK(&lock) を実行する。 2. マクロ S_LOCK は内部で TAS(&lock) を試行する。一発で取得できればそのまま制御を返す。 3. TAS(&lock) が失敗（競合）した場合、s_lock(&lock, ...) が呼び出される。 4. s_lock 内では init_spin_delay() で状態を初期化し、ループ内で TAS_SPIN() と perform_spin_delay() を繰り返す。 5. 一定回数スピンプバックしても獲得できない場合、pg_usleep() によるバックオフ遅延（ランダム増加）を挟み、最大試行回数（NUM_DELAYS）を超えると s_lock_stuck() により PANIC（またはテスト時はエラー終了）となる。 6. ロック解放時は S_UNLOCK(&lock)（ハードウェアバリア付きのストアまたは *lock = 0）により即座にロックをクリアする。

直接依存

  • intrin.h: MSVC環境におけるコンパイライントリンシック用（Windows環境）。

関連コード

  • src/backend/storage/lmgr/s_lock.c: スピン待機のバックオフアルゴリズムやタイムアウト処理 (s_lock, perform_spin_delay 等) の実体。
  • src/include/storage/spin.h: s_lock.h のマクロをラップし、外部から使用する公開APIを提供する。

読者向けメモ

  • フロントエンドコード（FRONTEND 定義時）からのインクルードは厳禁である。
  • コンパイラの最適化によるメモリ参照の再順序付けを防ぐため、アセンブラブロックや組み込み関数には必ず "memory" クローバーまたは適切なバリア（_ReadWriteBarrier, lwsync, membar 等）が組み込まれている。
