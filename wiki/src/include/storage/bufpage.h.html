src/include/storage/bufpage.h

概要

PostgreSQLの標準的なバッファページ（スロット付きページ）のデータ構造、ヘッダー定義、およびインライン／外部関数群を定義するヘッダーファイルです。ディスクブロック上に構築されるスロット付きページのレイアウトを規定し、タプル、行ポインタ（ItemId）、空き領域、特殊スペース（AM固有の領域）を管理するための基盤を提供します。

モジュール内での役割

src/include/storage モジュールの一部として、バッファ管理サブシステムとストレージエンジンの中核を担います。伴うCソースファイル src/backend/storage/page/bufpage.c（GUC変数や PageInit, PageIsVerified などの実体を定義）と密接に連携し、アクセスメソッド（HeapやIndexなど）が共通して依存するページ構造の抽象化レイヤーを形成します。

責務

  • **ページレイアウトの定義**: PageHeaderData 構造体を通じて、LSN、チェックサム、フラグ、空き領域境界（pd_lower, pd_upper）、特殊スペース、ページサイズ／バージョン情報、行ポインタ配列を定義する。
  • **ページ状態の判定と操作**: ページが空か、新規か、フルか、すべて可視か、チェックサムが有効かなどを判定・設定するためのインラインアクセサを提供する。
  • **領域とアイテムの管理**: ページ内のタプル、行ポインタ、特殊スペースの位置解決、空き容量計算、およびフラグメンテーション修復やアイテム追加・削除（拡張関数）のためのインターフェースを宣言する。

重要なシンボル

データ構造と型

  • PageData, Page: ページデータを表す char 配列およびそのポインタ型。
  • LocationIndex: ページ内のバイトオフセット（最大 2^15、ItemId のフィールド制限に起因）。
  • PageXLogRecPtr: 64ビットのLSN値を格納し、アトミックなロード／ストアを可能にする構造体。
  • PageHeaderData, PageHeader: ページのヘッダー構造体とそのポインタ型。行ポインタのフレキシブル配列（pd_linp）を含む。

ライフサイクル・初期化・検証関数

  • PageInit(Page page, Size pageSize, Size specialSize): ページ内容をゼロクリアし、ヘッダーフィールド（lower, upper, special, サイズ・バージョン）を初期化する。
  • PageIsVerified(PageData *page, BlockNumber blkno, int flags, bool *checksum_failure_p): 読込直後のページの妥当性（ヘッダーとチェックサム）を検証する。

ページ状態アクセサとマクロ

  • PageIsEmpty(const PageData *page): アイテム識別子が割り当てられていない場合に真を返す。
  • PageIsNew(const PageData *page): PageInit による初期化が行われていない場合に真を返す。
  • PageGetPageSize(const PageData *page) / PageGetPageLayoutVersion(const PageData *page): ページのサイズおよびレイアウトバージョンを取得する。
  • PageSetPageSizeAndVersion(Page page, Size size, uint8 version): ページサイズとバージョンを設定する。

アイテム・領域アクセサ

  • PageGetItemId(Page page, OffsetNumber offsetNumber): 指定オフセットの行ポインタ（ItemId）を取得する。
  • PageGetContents(Page page): 行ポインタを含まないページのデータ領域先頭を指すポインタを返す（MAXALIGN 調整済み）。
  • PageGetSpecialPointer(page): 特殊スペース（AM固有のトレーラー）へのポインタを返す。
  • PageGetMaxOffsetNumber(const PageData *page): ページ内で使用されている最大のオフセット番号（＝アイテム数）を返す。

LSN およびフラグ操作

  • PageGetLSN(const PageData *page) / PageSetLSN(Page page, XLogRecPtr lsn): ページの最終変更LSNを取得・設定する。
  • PageHasFreeLinePointers / PageSetHasFreeLinePointers / PageClearHasFreeLinePointers: 未使用行ポインタのヒントフラグ（PD_HAS_FREE_LINES）を操作する。
  • PageIsFull / PageSetFull / PageClearFull: ページフル状態のヒントフラグ（PD_PAGE_FULL）を操作する。
  • PageIsAllVisible / PageSetAllVisible / PageClearAllVisible: 全可視フラグ（PD_ALL_VISIBLE）を操作する。

制御フローとデータフロー

  • **ページ初期化フロー**: 上位レイヤー（バッファマネージャやアクセスメソッド）が新規ページを獲得した際、PageInit() を呼び出して pd_lower を SizeOfPageHeaderData に、pd_upper および pd_special を pageSize - specialSize に設定し、領域をゼロクリアする。
  • **ページ検証フロー**: ディスクからページを読み込んだ際、PageIsVerified() が呼び出され、まず PageIsNew() でゼロクリアページか判定し、必要に応じて pg_checksum_page() により計算されたチェックサムと pd_checksum を比較して整合性を確認する。
  • **データ追加・参照フロー**: アクセスメソッドは PageGetItemId() と PageGetItem() を通じて行ポインタ経由でタプルにアクセスする。タプル追加時は PageAddItem / PageAddItemExtended が pd_lower（行ポインタ側）と pd_upper（タプルデータ側、逆順に伸長）の間の空き領域を利用して配置する。

読者向けメモ

  • **メモリレイアウト**: スロット付きページは、先頭に PageHeaderData があり、その直後に行ポインタ配列（pd_linp）が成長（pd_lower が増加）する。一方、実際のタプルデータはページ末尾側から逆順に配置（pd_upper が減少）され、末尾一定領域はAM固有の「特殊スペース」として予約される。
  • **エンディアン依存性**: PageXLogRecPtr はCPUのエンディアンに応じて64ビットLSNのロード／ストア時にバイト順序の入れ替えを行うインライン関数（ビッグエンディアンか否かで分岐）を使用しているため、マルチプラットフォーム間の互換性が維持される。
  • **チェックサムの設計**: ページヘッダー内の pd_checksum フィールドは、チェックサムが無効な場合や古いバージョンからのアップグレード時に非ゼロである可能性があり、ページ自体には「チェックサムが有効か否か」のフラグは保持されない設計になっている。
