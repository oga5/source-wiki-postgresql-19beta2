src/include/storage/lwlock.h

概要

src/include/storage/lwlock.h は、PostgreSQL の軽量ロック（LWLock）マネージャの公開インターフェースとデータ構造を定義するヘッダーファイルです。フロントエンドコードからのインクルードは禁止されており、バックエンドの共有メモリや内部データ構造へのアクセスを排他的または共有モードで保護するために使用されます。

モジュール内での役割

src/include/storage モジュール内において、他のロック機構（lock.h など）の下層に位置し、共有メモリ上のデータ構造やバッファプール（bufmgr.h）などを直接保護する基礎的な同期プリミティブを提供します。また、storage/lwlocknames.h や storage/lwlocklist.h と連携して、ビルドインおよび動的に割り当てられるロックの識別子を管理します。

責務

  • 軽量ロックの構造体（LWLock）およびキャッシュラインパディング済み共用体（LWLockPadded）の定義。
  • ロックモード（排他・共有・変数待機）および待機状態の定義。
  • 固定配置されるメイン LWLock 配列および各サブシステム（バッファ、ロックマネージャ、述語ロック）のオフセット定義。
  • ロックの取得、解放、変数監視、トランシェ管理を行うバックエンド向け外部関数の宣言。

重要なシンボル

コアデータ構造と型

  • struct LWLock: トランシェID、アトミックな状態カウンタ（state）、待機中の PGPROC リスト（waiters）を保持する構造体。外部コードは直接内部メンバを操作せず、ポインタ経由で扱う。
  • typedef union LWLockPadded: LWLock をキャッシュラインサイズ（PG_CACHE_LINE_SIZE）にパディングした共用体。キャッシュコンテンションを軽減する。
  • enum LWLockWaitState: バックエンドの待機プロセス状態（LW_WS_NOT_WAITING, LW_WS_WAITING, LW_WS_PENDING_WAKEUP）を定義。
  • enum LWLockMode: ロックの取得モード。LW_EXCLUSIVE（排他）、LW_SHARED（共有）、および変数待ち用の LW_WAIT_UNTIL_FREE を定義。
  • typedef LWLock *LWLockId: 旧コードとの互換性のための typedef。新コードでは LWLock * を直接使用する。

グローバル変数とインデックスオフセット

  • MainLWLockArray: 事前割り当てされたパディング済み LWLock 配列へのポインタ。
  • NUM_BUFFER_PARTITIONS / NUM_LOCK_PARTITIONS / NUM_PREDICATELOCK_PARTITIONS: 各種共有ハッシュテーブルおよびロックテーブルのパーティション数。
  • BUFFER_MAPPING_LWLOCK_OFFSET / LOCK_MANAGER_LWLOCK_OFFSET / PREDICATELOCK_MANAGER_LWLOCK_OFFSET / NUM_FIXED_LWLOCKS: メイン LWLock 配列内における固定割り当て領域のオフセットと総数。

ロック操作関数

  • LWLockAcquire: 指定したモード（排他または共有）でロックを獲得する。
  • LWLockRelease: 保持しているロックを解放し、必要に応じて待機中のプロセスを起こす。
  • LW_EXCLUSIVE / LW_SHARED / LW_WAIT_UNTIL_FREE: ロック取得・待機時に指定するモード定数。
  • PG_CACHE_LINE_SIZE: キャッシュラインの境界合わせに用いるサイズ定義。

制御フローとデータフロー

本ファイルはインターフェース定義のため実体を持ちませんが、対となる lwlock.c との間で以下のようなデータと制御のフローを規定しています： 1. **ロック取得**: 呼び出し元が LWLock * と LWLockMode（LW_EXCLUSIVE または LW_SHARED）を指定して LWLockAcquire を呼び出す。 2. **アトミック状態更新**: lwlock.c 側で LWLock->state に対するアトミック操作（Compare-And-Exchange）を行い、競合がない場合は即座にリターンする。 3. **待機キューイング**: 競合が発生した場合、自バックエンドのプロセス構造体を LWLock->waiters リストに登録し、OS レベルまたはラッチを使った待機状態へ移行する。 4. **解放と通知**: LWLockRelease により state が更新され、待機中のプロセスが LW_WS_PENDING_WAKEUP を経由して再開される。

直接依存

  • port/atomics.h: アトミック操作（pg_atomic_uint32 など）の提供。
  • storage/lwlocknames.h: 軽量ロック名の定義。
  • storage/proclist_types.h: プロセスリストの型定義。
  • storage/lwlocklist.h: ビルドインのトランシェおよびロックのリスト（インクルードによるマクロ展開用）。

関連コード

  • src/backend/storage/lmgr/lwlock.c: LWLock マネージャの実装本体。
  • src/include/storage/lwlocklist.h: ビルドインのトランシェ定義。
  • src/include/storage/bufmgr.h: バッファ管理における LWLock の主要な利用者。

読者向けメモ

  • **メモリ配置**: 各 LWLock はキャッシュライン境界にパディングされており、CPU キャッシュのバウンシング（キャッシュライン競合）を最小限に抑える設計になっています。
  • **フロントエンド制約**: フロントエンドコードからのインクルードは #error によって厳格に禁止されています。
  • **割愛された領域**: 動的トランシェの割り当て関数群（RequestNamedLWLockTranche, GetNamedLWLockTranche など）の詳細なアロケーションアルゴリズムは、実装ファイル側に依存するため本ヘッダーでは宣言のみに留めています。
