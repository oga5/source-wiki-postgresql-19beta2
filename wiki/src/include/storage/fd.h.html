src/include/storage/fd.h

概要

PostgreSQLの仮想ファイル記述子（VFD）プールおよび低レベルファイルアクセス機構のインターフェースを定義するヘッダーファイルです。オペレーティングシステムのファイル記述子制限を回避するため、LRU方式で管理される仮想ファイル層を提供します。

モジュール内での役割

src/backend/storage/file/fd.c とペアをなし、ストレージサブシステム全般（バッファマネージャ、一時ファイル、WAL出力など）に対して標準のCライブラリ関数（open, fopen, opendir 等）の代替APIを提供します。

責務

  • OSのオープンファイル制限を超えるのを防ぐための File 型（VFD）インターフェースの公開。
  • サブトランザクション終了時に自動クリーンアップされるラッパー関数（AllocateFile, OpenTransientFile, AllocateDir 等）の宣言。
  • プラットフォーム依存の差異（Windowsの EACCES 処理や O_DIRECT のシミュレーションなど）の吸収。
  • 非同期I/OやベクトルI/O（FileReadV, FileWriteV 等）およびファイル同期・拡張ユーティリティのプロトタイプ提供。

重要なシンボル

  • File: 仮想ファイル記述子を表す int 別の型。
  • FileRead / FileWrite: 単一バッファ用のインラインI/O関数（内部で FileReadV/FileWriteV を呼び出し）。
  • PathNameOpenFile / FileClose: 長期保有する仮想ファイルのオープンとクローズ。
  • AllocateFile / FreeFile: サブトランザクションと連動する FILE* ラッパー。
  • OpenTransientFile / CloseTransientFile: 自動クリーンアップ付きの生カーネルFDラッパー。

制御フローとデータフロー

  • サーバーコードは直接 open(2) や fopen(3) を呼び出す代わりに、PathNameOpenFile や AllocateFile を呼び出してファイルハンドルを取得します。
  • 読み書き操作時は FileRead / FileWrite を経由し、最終的に FileReadV / FileWriteV を通じてVFDプールから実際のOSファイル記述子を割り当てられて実行されます。
  • 一時ファイルや一時ディレクトリの作成・削除、および外部FDの明示的管理（AcquireExternalFD / ReleaseExternalFD）により、ファイルリソースの枯渇（EMFILE）を防止します。

直接依存

関連コード

  • src/backend/storage/file/fd.c: ペアとなる実装ファイル。
  • src/include/storage/sharedfileset.h: 共有一時ファイルのクリーンアップ機構。

読者向けメモ

  • サーバ内ですべてのファイル操作を直接OSルーチンで行うとファイル記述子が枯渇するため、原則として本ヘッダーで定義されるAPIを使用してください。
  • File 型変数は通常のファイル記述子ではないため、直接標準の read(2) や write(2) に渡さないよう注意してください。
