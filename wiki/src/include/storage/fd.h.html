src/include/storage/fd.h

概要

src/include/storage/fd.h は、PostgreSQLの仮想ファイル記述子（VFD）キャッシュ機構および関連するファイルI/O制御インターフェースを定義するヘッダーファイルです。システム全体のファイルオープン数制限（EMFILE エラーなど）を回避するため、C標準ライブラリやOSの直接的なファイル操作関数の代わりにVFDやトランザクション連動型のラッパー関数を使用する規則とAPI群を提供します。実体となる実装は src/backend/storage/file/fd.c にあります。

モジュール内での役割

ストレージサブシステム内において、本ヘッダーはすべてのファイルアクセス（データファイル、一時ファイル、WAL、ログ、設定ファイルなど）の抽象化境界を規定します。物理的なOSのファイル記述子（fd）を直接枯渇させないための管理レイヤーであり、後続のバッファマネージャやストレージマネージャ（smgr）などの基盤となります。

責務

  • **仮想ファイル記述子（VFD）の抽象化**: File 型および関連する読み書き・同期インターフェースの提供。
  • **一時ファイル管理**: トランザクション終了時やプロセス終了時に自動クリーンアップされる一時ファイル作成・削除APIの提供。
  • **トランザクション連動型標準ライブラリラッパー**: サブトランザクションのアボート時に自動クローズされる AllocateFile（fopen 代替）や AllocateDir（opendir 代替）などの提供。
  • **一時的OSファイル記述子管理**: 自動クローズ機構を持つ OpenTransientFile などの提供。
  • **直接I/Oおよび拡張制御**: IO_DIRECT フラグやファイル拡張方法（FileExtendMethod）の定義。

重要なシンボル

型・定数・列挙型

  • **File (typedef int)**: VFDプール内のエントリを指す抽象ファイル識別子。実際のOSファイル記述子ではなく、fd.c が管理するキャッシュインデックスとして機能します。
  • **FileExtendMethod (enum)**: ファイルを拡張する際の手法を定義する列挙型。FILE_EXTEND_METHOD_POSIX_FALLOCATE または FILE_EXTEND_METHOD_WRITE_ZEROS を選択します。

VFD操作関数

  • **PathNameOpenFile**: 指定パスとフラグで仮想ファイルを開き、管理下のエントリ（File）を返します。長期保持するリレーションファイル等で使用されます。
  • **FileClose**: 指定した仮想ファイルを閉じ、VFDプールリソースを解放します。
  • **FileRead / FileReadV**: 仮想ファイルから指定オフセット・サイズを読み込むインライン関数および分散読み込み関数。内部でベクタ（iovec）形式に変換し FileReadV を呼び出します。
  • **FileWrite / FileWriteV**: 仮想ファイルへ指定オフセット・サイズを書き込むインライン関数および分散書き込み関数。

一時リソース・ラッパー管理関数

  • **AllocateFile**: 標準の fopen のラッパー。ファイルハンドルをサブトランザクションに登録し、アボート時に自動クローズさせます。
  • **FreeFile**: AllocateFile で開いたファイルを閉じます（fclose の代替）。
  • **OpenTransientFile**: OSのプレーンなファイル記述子を開きつつ、管理対象として登録するラッパー。
  • **CloseTransientFile**: OpenTransientFile で開いた記述子を閉じます。

制御フローとデータフロー

1. **仮想ファイルI/Oのフロー**:

  • 呼び出し元は PathNameOpenFile 等で File ハンドルを取得します。
  • 読み書き時には FileRead / FileWrite を呼び出します。これらは内部で struct iovec を構築し、実質的なI/O処理を行う FileReadV / FileWriteV へ処理を委譲します。
  • 不要になった時点で FileClose を呼び出し、VFDスロットおよびOSファイル記述子を解放します。

    • 2. **トランザクション保護付きラッパーのフロー**:

  • AllocateFile や OpenTransientFile を通じて開かれた外部リソース（FILE* や生 fd）は、カレントサブトランザクションに紐付けられます。
  • トランザクションのアボートやコミット時には、AtEOXact_Files や AtEOSubXact_Files によって自動的にクローズ処理が実行され、ファイルリークが防止されます。
