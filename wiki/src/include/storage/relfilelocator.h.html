src/include/storage/relfilelocator.h

概要

PostgreSQL のリレーション（テーブルやインデックスなど）に対する物理的なアクセス情報を定義するヘッダーファイルです。ファイルシステム上の位置を特定するために必要な識別子（テーブルスペース、データベース、リレークラス番号）を提供します。

モジュール内での役割

src/include/storage サブシステムにおいて、バッファ管理やストレージマネージャ（smgr.h, md.h など）が対象ファイルを特定するための基礎データ構造および比較用マクロを提供します。

責務

  • リレーションの物理ロケーションを一意に特定する RelFileLocator 構造体の定義。
  • 一時リレーションやバックエンドローカルなリレーションを識別するための RelFileLocatorBackend 構造体の定義。
  • ハッシュテーブルのキー等での効率的な比較・判定を行うための各種インラインマクロの提供。

重要なシンボル

  • struct RelFileLocator: spcOid（テーブルスペース）、dbOid（データベース）、relNumber（リファイルノード）を保持するコア構造体。パディングを含まない設計。
  • struct RelFileLocatorBackend: RelFileLocator にバックエンドのプロセス番号（ProcNumber）を付加し、一時・ローカルリレーションの物理配置を解決する構造体。
  • RelFileLocatorEquals / RelFileLocatorBackendEquals: 2つのロケーター構造体が同一かを高速に判定するマクロ。識別力の高い relNumber を最初に比較する最適化を含む。
  • RelFileLocatorBackendIsTemp: バックエンドローカル（一時）リレーションであるかを判定するマクロ。

制御フローとデータフロー

本ファイルは構造体定義とマクロのみを提供するインヘッダーであるため、直接的な関数制御フローを持ちません。

  • データフローとしては、カタログキャッシュやプランナから取得した Oid 群を RelFileLocator に集約し、それをバッファプールやストレージマネージャ（smgr）へ渡すことで、ファイルパスの生成やディスクI/Oの起点となります。

直接依存

  • common/relpath.h: リレーションパス関連の共通定義
  • storage/procnumber.h: バックエンドプロセス番号 (ProcNumber) の定義

関連コード

  • src/backend/storage/smgr/md.c: 物理フォークやセグメント分割を扱うモジュール
  • src/backend/catalog/relmapper.c: マップされたリレーションのファイルノード解決ロジック

読者向けメモ

  • RelFileLocator の各フィールドはハッシュテーブルのキーとして使用されるため、コンパイラのパディングバイトを含まないように設計されています。
  • pg_class.reltablespace == 0 のような省略値は RelFileLocator 構造体内部では許容されず、必ず実テーブルスペース ID を設定する必要があります。
