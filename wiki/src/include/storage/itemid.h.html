src/include/storage/itemid.h

概要

PostgreSQLのバッファページ内で使用される、アイテム識別子（Line Pointerとも呼ばれる）のデータ構造と操作マクロを定義するヘッダーファイルです。各タプルへの間接参照や状態管理の基礎を提供します。

モジュール内での役割

src/include/storage モジュールの一部として、データベースページ（bufpage.h など）の内部構造を構成する基本要素を提供します。タプルストレージの位置と状態を抽象化し、アクセスメソッドやバッファマネージャー層から利用されます。

責務

  • **データ構造の定義**: ページ内のタプルオフセット、フラグ、長さをパックしたビットフィールド構造体 ItemIdData およびポインタ型 ItemId の定義。
  • **状態定数の提供**: ラインポインタの状態（未使用、通常、HOTリダイレクト、デッド）を表す定数マクロの提供。
  • **アクセサおよび検証マクロ**: 各フィールドの取得、ポインタの有効性や状態（使用中、ノーマル、リダイレクト、デッド、ストレージ有無）を判定するマクロの提供。
  • **ミューテーターマクロ**: ラインポインタの状態変更や初期化を行うマクロの提供。

重要なシンボル

データ構造

  • ItemIdData: 32ビット（4バイト）相当のビットフィールド構造体。
  • lp_off（15ビット）: ページ先頭からのタプルオフセット、またはHOTリダイレクト時の次ラインポインタ番号。
  • lp_flags（2ビット）: ラインポインタの状態。
  • lp_len（15ビット）: タプルのバイト長。
  • ItemId: ItemIdData * 型のエイリアス。

状態フラグマクロ

  • LP_UNUSED (0): 未使用状態。直ちに再利用可能（lp_len == 0）。
  • LP_NORMAL (1): 通常の使用状態（lp_len > 0）。
  • LP_REDIRECT (2): HOT（Heap-Only Tuple）リダイレクト状態（lp_len == 0）。
  • LP_DEAD (3): デッド状態。ストレージを持つ場合と持たない場合がある。

アクセサ・判定マクロ

  • ItemIdGetLength(itemId): タプルの長さを取得。
  • ItemIdGetOffset(itemId) / ItemIdGetRedirect(itemId): オフセットまたはリダイレクト先を取得。
  • ItemIdGetFlags(itemId): フラグを取得。
  • ItemIdIsValid(itemId): ポインタが非 NULL かを判定。
  • ItemIdIsUsed(itemId) / ItemIdIsNormal(itemId) / ItemIdIsRedirected(itemId) / ItemIdIsDead(itemId): 各種状態を判定。
  • ItemIdHasStorage(itemId): ストレージ（バイト長 > 0）を持つかを判定。

ミューテーターマクロ

  • ItemIdSetUnused(itemId): LP_UNUSED に設定し、オフセットと長さを 0 クリア。
  • ItemIdSetNormal(itemId, off, len): LP_NORMAL に設定し、指定したオフセットと長さを割り当て。
  • ItemIdSetRedirect(itemId, link): LP_REDIRECT に設定し、リンク先をオフセット部に格納。
  • ItemIdSetDead(itemId): LP_DEAD に設定し、オフセットと長さを 0 クリア。
  • ItemIdMarkDead(itemId): 既存のストレージを保持したまま LP_DEAD フラグのみを設定。

制御フローとデータフロー

本ファイルは関数や複雑な制御フローを含まず、すべてマクロによるインライン展開で処理されます。

  • **データ取得フロー**: ページ内のインデックスから ItemId を取得し、ItemIdGetLength や ItemIdGetOffset を通じて実タプルの位置やサイズを導出します。
  • **状態更新フロー**: ItemIdSetNormal や ItemIdSetUnused などのマクロを呼び出すことで、ItemIdData 内のビットフィールドが一括して書き換えられます。マクロの実装上、引数の itemId が複数回評価される副作用に注意が必要です。

読者向けメモ

  • **メモリレイアウト**: ItemIdData は1つのページヘッダー配列の一部として密に配置され、ビットフィールドによってサイズが最適化されています。
  • **インバリアント**:
  • LP_UNUSED および LP_REDIRECT のラインポインタは、原則としてストレージを持たないため lp_len == 0 となります。
  • LP_NORMAL のラインポインタは有効なストレージを持つため lp_len > 0 となります。
  • **並行性**: ItemIdMarkDead はヒントビット的なメカニズムとして機能し、複数プロセスの並行実行下でも安全にマークできる設計になっています。
