src/include/storage/itemid.h

概要

PostgreSQLのバッファページ内における「行ポインタ（Line Pointer / Item Identifier）」のデータ構造と、それを操作・検査するためのインラインマクロ群を定義するヘッダーファイルです。ページ上のタプル位置を特定するための基礎的なビットレイアウトを提供します。

モジュール内での役割

src/include/storage サブシステムにおいて、bufpage.h（バッファページ構造）やタプルアクセス機構の下支えを行います。ページ内の個々のタプルへアクセスする際のインデクス（Line Pointer配列の要素）として直接利用されます。

責務

  • **行ポインタのデータ構造定義**: ページ先頭からのオフセット、状態フラグ、タプルのバイト長をパックしたビットフィールド構造体 (ItemIdData) の定義。
  • **状態の定義**: 行ポインタが取りうる4つの状態（UNUSED, NORMAL, REDIRECT, DEAD）の定数提供。
  • **アクセサおよび状態判定マクロの提供**: オフセット、長さ、フラグ、および各種状態（有効か、使用中か、リダイレクトか等）を判定・取得・設定するためのマクロ群の提供。

重要なシンボル

データ構造と型定義

  • **struct ItemIdData**: 4バイト（32ビット）の固定長ビットフィールド構造体。15ビットのオフセット（lp_off）、2ビットの状態フラグ（lp_flags）、15ビットのバイト長（lp_len）を保持し、ページあたりのメモリフットプリントを最小化します。
  • **typedef ItemId**: ItemIdData * 型のエイリアス。
  • **typedef ItemOffset**: ページ内オフセットを表す uint16 型。
  • **typedef ItemLength**: タプルの長さを表す uint16 型。

ヘルパー関数およびマクロ群

  • **lp_off / lp_len / lp_flags**: 構造体 ItemIdData 内の各ビットフィールド要素。
  • **取得系マクロ (ItemIdGetLength, ItemIdGetOffset, ItemIdGetFlags, ItemIdGetRedirect)**: 行ポインタからそれぞれの属性を取り出します。ItemIdGetRedirect は lp_off を次の行ポインタのオフセット番号として解釈します。
  • **状態判定マクロ (ItemIdIsValid, ItemIdIsUsed, ItemIdIsNormal, ItemIdIsRedirected, ItemIdIsDead, ItemIdHasStorage)**: 行ポインタの有効性や、LP_UNUSED / LP_NORMAL / LP_REDIRECT / LP_DEAD の状態、ストレージ保有有無を返します。
  • **設定系マクロ (ItemIdSetUnused, ItemIdSetNormal, ItemIdSetRedirect, ItemIdSetDead, ItemIdMarkDead)**: 行ポインタの状態やオフセット、長さを書き換えます。ItemIdMarkDead は既存のストレージ長を保持したままフラグのみを LP_DEAD に変更します（インデックス等におけるヒントビット的利用を想定）。

制御フローとデータフロー

本ファイルは関数や複雑な制御フローを含まず、純粋なデータ構造の定義とインラインマクロによるビット操作を提供します。

  • **データフロー**: バッファページ (PageData) のヘッダー直後に配置される ItemIdData 配列に対し、タプルスキャンや更新を行うコードが本ファイルのマクロを介して lp_off や lp_len を読み取り、実際のタプル実体（バイト列）の位置を割り出します。
  • **メモリレイアウト・不変条件**:
  • LP_UNUSED および LP_REDIRECT の行ポインタは、原則としてストレージを持たないため lp_len == 0 である必要があります。
  • LP_NORMAL の行ポインタは lp_len > 0 を満たす必要があります。
  • マクロの一部（ItemIdSetNormal 等）は引数 itemId を複数回評価するため、副作用を持つ式を渡さないよう注意が必要です。
