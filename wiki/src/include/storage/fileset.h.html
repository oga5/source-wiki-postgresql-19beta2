src/include/storage/fileset.h

概要

名前付きの一時ファイルを管理するための FileSet 構造体と、それらを操作する公開 API のインターフェースを定義するヘッダーファイルです。

モジュール内での役割

src/include/storage ストレージサブシステムにおいて、単一または複数のバックエンドプロセス間でライフサイクルにまたがり、複数回のオープン・クローズが可能な名前付き一時ファイルのネームスペースを提供します。

責務

  • 名前付き一時ファイルのグループ管理を行う FileSet データ構造の定義。
  • FileSet の初期化、ファイルの作成、オープン、削除、および一括削除を行う関数シグネチャの提供。
  • 一時ファイル配置先のテーブルスペース情報の保持と構成。

重要なシンボル

  • FileSet: 作成プロセスの PID、識別子、および利用するテーブルスペースの Oid 配列を保持する構造体。
  • FileSetInit: FileSet 構造体を初期化し、一時テーブルスペースを割り当てる関数。
  • FileSetCreate / FileSetOpen: FileSet 内で一時ファイルを新規作成またはオープンする関数。
  • FileSetDelete / FileSetDeleteAll: 個別または一括で一時ファイルを削除する関数。

制御フローとデータフロー

  • 呼び出し元はまず FileSetInit を呼び出して構造体を初期化し、利用可能な一時テーブルスペースの Oid を確定させます。
  • ファイル操作時には FileSetCreate または FileSetOpen に FileSet とファイル名を渡し、実体パスを解決して File ハンドルを取得します。
  • 不要になったファイルは FileSetDelete または FileSetDeleteAll によって明示的に削除されます。

直接依存

  • storage/fd.h: ファイル記述子および File 型の定義に依存。

関連コード

  • src/backend/storage/file/fileset.c: FileSet API の実際のロジックとパス解決・ディレクトリ作成を実装するペアファイル。
  • src/include/storage/sharedfileset.h: 複数プロセス間で共有されるファイルセット機能を提供する関連ヘッダー。

読者向けメモ

  • FileSet に属するファイルはトランザクションを跨いで生存できるため、不要になった際は呼び出し元が責任を持って FileSetDelete や FileSetDeleteAll でクリーンアップする必要があります。
  • テーブルスペースの割り当てには temp_tablespaces GUC 設定が利用されます。
