src/test/regress/sql/jsonb.sql

概要

PostgreSQLの jsonb データ型および関連する演算子、関数、集約、型キャスト、インデックス（GIN、B-tree）、全文検索（tsvector/ts_headline）、レコード/配列へのマッピング機能に対する総合的な回帰テストスイート。

モジュール内での役割

src/test/regress/sql/ ディレクトリに位置し、pg_regress テストハーネスによって実行される SQL スクリプト群の一つ。C言語で実装された jsonb バックエンド機能（パース、バイナリ表現、演算子、インデックス演算子クラス）の仕様適合性と堅牢性を検証する。

責務

  • **構文検証**: 文字列、数値、配列、オブジェクト、真偽値、null、および不正な JSON 構文に対するエラー報告の確認。
  • **データ抽出とナビゲーション**: ->, ->>, #>, #>> 演算子やオブジェクトキー取得、配列要素走査の挙動検証。
  • **包含関係と検索**: @>, <@, ?, ?|, ?&, @@, @? 演算子による高度なクエリとインデックス（GIN/B-tree）の動作確認。
  • **構造変更**: jsonb_set, jsonb_insert, jsonb_delete, jsonb_strip_nulls, || 演算子による非破壊的/インプレース風の更新テスト。
  • **レコード・コレクション変換**: jsonb_populate_record, jsonb_populate_recordset, jsonb_to_record, jsonb_object_agg 等を用いた複合型やドメイン制約との相互運用テスト。
  • **全文検索連携**: to_tsvector, jsonb_to_tsvector, ts_headline によるテキスト検索機能の統合テスト。

制御フローとデータフロー

  • 外部ファイル data/jsonb.data を COPY コマンドで一時テーブル testjsonb にロードし、以降の検索・インデックス・集約テストの共通データソースとして利用。
  • 各テストケースは単発の SELECT、UPDATE、INSERT 文で構成され、期待される出力結果は対応する .out ファイルと比較される。
  • インデックス性能・挙動テストでは enable_seqscan = off などを一時的に設定し、GIN（標準および path_ops）や B-tree インデックススキャンが強制的に使われるパスを通す。
  • max_stack_depth を一時的に縮小（100kB）して、過度にネストした JSONB の再帰パース時にスタックオーバーフローエラーが正しく発生するかを検証する制御フローを含む。

直接依存

  • PG_ABS_SRCDIR/data/jsonb.data: テスト用の実データファイル。
  • PostgreSQL バックエンドの jsonb データ型ハンドラおよび関連関数群。
