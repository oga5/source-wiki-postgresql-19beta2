src/test/regress/sql/update.sql

概要

PostgreSQLの回帰テスト用SQLスクリプトファイルであり、UPDATE構文、UPSERT（ON CONFLICT DO UPDATE）、およびパーティションテーブルにおける行移動（Row Movement）に関する動作・制約・エラーパスを網羅的に検証する。

モジュール内での役割

PostgreSQLの src/test/regress/ ディレクトリに位置し、エンジン本体のクエリ実行・オプティマイザ・パーティショニング・トリガー・RLS（行レベルセキュリティ）機能に対するSQLインタフェースの統合テストとして機能する。

責務

  • 基本的な UPDATE 構文とターゲットテーブルのエイリアス（修飾エラーの検証含む）のテスト。
  • VALUES 句やマルチセット句（SET (c,b,a) = ...）、相関・非相関サブクエリを用いた更新の検証。
  • ON CONFLICT DO UPDATE（UPSERT）における、複数パーティションやシステム属性（xmin, xmax, tableoid）の振る舞い確認。
  • 範囲（Range）・リスト（List）・ハッシュ（Hash）パーティションにおける、パーティションキー更新時の行移動（DELETE+INSERT への変換とタプルルーティング）の検証。
  • 行移動を伴う場合の各種トリガー（Statement/Row/Before/After）、CHECK制約、UPDATABLE VIEW、および RLS ポリシーの適用検証。

制御フローとデータフロー

1. 基本・拡張UPDATEフロー:

  • 単一テーブルの単純更新から、FROM 句に VALUES や副問合せを持つ複数列同時更新を実行し、結果を SELECT で検証する。

    • 2. UPSERTフロー:

  • 一意制約違反が発生するデータを挿入し、ON CONFLICT DO UPDATE 節を起動してターゲット行を更新、RETURNING 句でシステム列や変更結果を取得する。

    • 3. パーティション行移動フロー:

  • パーティションキーが更新された際、行が所属する古いパーティションからの削除と、新しい制約を満たす子パーティションへのルーティング（挿入）が実行される。
  • トリガー（例: BEFORE UPDATE によるキーの書き換え）や BEFORE INSERT トリガーが介入する経路、および CHECK 制約・RLSポリシーの違反によるアボートパスを検証する。
