src/test/isolation/specs/tuplelock-update.spec

概要

PostgreSQLの分離テストスイート（isolation tester）で使用されるテスト仕様ファイルです。複数セッション間でタプルロック（FOR KEY SHARE）と通常更新（UPDATE）が競合する際の挙動、およびアドバイザリロックを介した実行順序の制御を検証します。

モジュール内での役割

src/test/isolation/specs/ ディレクトリに配置される他の .spec ファイルと同様に、PostgreSQLの同時実行制御（Concurrency Control）とロック獲得・解放の正当性をテストするための入力定義です。isolation テストランナーによって解析され、C言語のテストドライバプログラムへと変換・実行されます。

責務

  • テスト用テーブル pktab の作成と初期データの投入（setup）およびクリーンアップ（teardown）。
  • 4つの独立したセッション（s1 から s4）におけるSQLステップの定義。
  • アドバイザリロックとブロッカーアノテーションを活用した、非決定的な動作を防ぐための厳密な実行順序（permutation）の定義。

制御フローとデータフロー

  • 初期状態：pktab テーブルに主キー id = 1 の行が1件存在します。
  • セッション1 (s1) はアドバイザリロックの取得、UPDATE、トランザクション開始、および FOR KEY SHARE によるキー共有ロックの取得を行います。
  • セッション2〜4 (s2, s3, s4) は、それぞれ異なるアドバイザリ共有ロックの取得を伴う UPDATE ステップを実行し、セッション1のロックや更新処理と競合・待機状態を作ります。
  • 順序制御：permutation において、s1_advunlock1(s2_update) のようにブロッカーアノテーションを指定することで、セッション2の更新が確実に完了してからセッション1のアドバイザリロック解除が進むよう同期をとります。これにより、テスト出力の安定性を保証します。

直接依存

  • ソースファイル内にC言語のインクルードや直接のファイル依存はありません。PostgreSQLのisolationテスト仕様書フォーマットに依存しています。

関連コード

  • src/test/isolation/: 本テストファイルを実行する isolation テストランナーおよびその他の並行性テスト仕様群。
  • PostgreSQLのロックマネージャ関連ソースコード（src/backend/storage/lmgr/）：タプルロックやアドバイザリロックの実装本体。

読者向けメモ

  • このファイルは直接実行されるスクリプトではなく、isolation テストスイートのビルドプロセスにおいてパースされるDSL（ドメイン固有言語）ファイルです。
  • s1_advunlockN に付与されているブロッカーアノテーション（例: (s2_update)）の仕組みを理解することが、テストの意図（どの競合状態を意図的に再現・検証しているか）を読み解くカギとなります。
