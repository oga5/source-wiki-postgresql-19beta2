src/backend/utils/adt/jsonfuncs.c

概要

src/backend/utils/adt/jsonfuncs.c は、PostgreSQL における JSON および JSONB データ型の処理、検索、展開、構築、および型変換（json_populate_record や jsonb_set など）を実装する中心的なソースファイルです。ファイルサイズが非常に大きく多様な機能を抱えているのは、テキスト形式の JSON 解析（common/jsonapi.h のセマンティックアクションを使用）とバイナリ形式の JSONB 操作（イテレータベースの処理）の両方をサポートし、SQL インターフェース、パス抽出、レコードや配列への変換、削除・挿入などの高度なユーティリティをすべてこの 1 ファイルに集約しているためです。

モジュール内での役割

src/backend/utils/adt モジュール内に位置し、src/include/utils/jsonfuncs.h とペアを組んでいます。JSON/JSONB 関連の基盤処理を提供する json.c や jsonb.c、jsonb_util.c、および式実行に関わる jsonpath_exec.c 等と連携しつつ、ユーザー定義関数（UDF）から直接呼び出される高レベルな演算子ハンドラおよびデータ変換ロジックを担当します。

責務

  • **JSON/JSONB 抽出およびパス検索**: ->, ->>, #>, #>> などの演算子および json_extract_path や jsonb_get_element を通じたネストした値の取得。
  • **コレクション解体 (SRF)**: json_object_keys, json_each, json_array_elements（およびそれぞれの jsonb 版）による行集合（Set-Returning Functions）の提供。
  • **レコード・配列へのマッピング**: json_populate_record, json_populate_recordset, および json_to_record 系関数を通じた、JSON/JSONB から PostgreSQL の複合型（Composite / Record）や配列への再帰的デシリアライズ。
  • **変更・編集系操作**: jsonb_set, jsonb_insert, jsonb_delete, jsonb_concat, jsonb_strip_nulls などによる JSONB 文書の構造変更。
  • **反復・変換ユーティリティ**: iterate_json_values や transform_json_string_values による値の走査と文字列変換。

重要なシンボル

JSON 解析・走査用状態構造体

  • struct OkeysState: json_object_keys の実行中状態。トップレベルのキー文字列を一時格納するための可変長配列を維持する。
  • struct IterateJsonStringValuesState: iterate_json_values の状態。走査対象のフラグ（JsonToIndex）とコールバックアクションを保持する。
  • struct TransformJsonStringValuesState: transform_json_string_values の状態。変換結果を組み立てるための StringInfo バッファを保持する。
  • struct GetState: json_extract_path などの JSON パス検索状態。パス配列、ネスト深度、各階層のインデックスや一致状態 (pathok, array_cur_index) を追跡する。
  • struct AlenState: json_array_length の状態。レベル 1 の配列要素数をインクリメントしてカウントする。
  • struct EachState: json_each の状態。マテリアライズド SRF のタプルストアと、1 行ごとにクリアされる一時メモリコンテキスト (tmp_cxt) を管理する。
  • struct ElementsState: json_array_elements の状態。EachState と同様に一時コンテキストとタプルストアを利用して配列要素を展開する。
  • struct JHashState: get_json_object_as_hash の状態。JSON オブジェクトをハッシュテーブルに展開する際のパーサーステート。
  • struct JsonHashEntry: JSON オブジェクトのハッシュエントリ。キー文字列 (fname、先頭必須)、値文字列、および JsonTokenType を保持する。

レコード・配列マッピング用メタデータ構造体

  • struct ColumnIOData: カラムの型情報 (typid, typmod, typcat) と、スカラー入出力、配列 (ArrayIOData)、複合型 (CompositeIOData)、ドメイン (DomainIOData) のいずれかのメタデータ共用体を保持する。
  • struct RecordIOData: レコード型情報と、可変長メンバーとして各カラムの ColumnIOData 配列を保持するメタデータキャッシュ。
  • struct ArrayIOData: 配列要素の型 ID と ColumnIOData へのポインタをキャッシュする。
  • struct CompositeIOData: 複合型やドメイン型 over 複合型のタプルデスク (TupleDesc) やベース型情報をキャッシュする。
  • struct DomainIOData: ドメイン型のベース型入出力キャッシュと検証用情報を保持する。
  • struct PopulateRecordCache: クエリライフサイクル全体で再利用される PopulateRecordCache。
  • struct PopulateRecordsetState: json_populate_recordset の実行時状態。タプルストア、キャッシュ、カレントレコードを保持する。
  • struct PopulateArrayContext / struct PopulateArrayState: 配列の再帰的デシリアライズ (populate_array) における次元数、サイズカウンタ、ビルダー状態を管理する。

ヘルパー値カプセル化構造体

  • struct StripnullState: json_strip_nulls においてヌル値フィールドや配列要素をスキップしつつ StringInfo を構築する状態。
  • struct JsValue: プレーンテキスト JSON (json 共用体) とバイナリ JSONB (jsonb ポインタ) の両方を統一的に扱うためのラップ構造体。
  • struct JsonTokenType / struct JsObject: JSON トークン型やハッシュ/コンテナを統一的に扱う補助構造体。

制御フローとデータフロー

1. **パス抽出フロー (json_extract_path / jsonb_get_element)**:

  • 入力されたパス配列 (text[]) を deconstruct_array_builtin で C の配列に分解する。
  • テキスト形式の場合は get_worker がパーサを駆動し、GetState を用いて指定された深さのキー (path_names) または配列インデックス (path_indexes) に到達した時点で結果のテキスト切り出しを開始・終了する。
  • JSONB 形式の場合は jsonb_get_element が反復的にコンテナを辿り、指定パスの JsonbValue を取得してテキストまたは JSONB として返す。

    • 2. **レコードマッピングフロー (json_populate_record)**:

  • 初回呼び出し時に fcinfo->flinfo->fn_extra に PopulateRecordCache が構築され、対象レコードのタプルデスクと各列の ColumnIOData が初期化される。
  • JSON 入力は JsValueToJsObject を経由してハッシュテーブル（テキスト JSON の場合）または JsonbContainer（JSONB の場合）に変換される。
  • populate_record が各カラム名 (attname) に一致するフィールドをハッシュまたはコンテナから検索し、populate_record_field を通じてスカラー、配列、または複合型として再帰的にデシリアライズしてヒープタプルを構築する。

    • 3. **JSONB 構造変更フロー (jsonb_set / jsonb_insert)**:

  • setPath 関数が再帰的に JsonbIterator を走査し、パスに一致する位置で setPathObject または setPathArray を呼び出す。
  • 操作フラグ（JB_PATH_CREATE, JB_PATH_DELETE, JB_PATH_REPLACE, JB_PATH_FILL_GAPS など）に応じて、既存ノードの置換、削除、あるいはギャップへの NULL 補完や新規オブジェクト/配列チェーンの構築（push_path）を行い、最終的に JsonbInState から新しい Jsonb を生成する。

読者向けメモ

  • **メモリ管理**: SRF（json_each, json_array_elements など）やレコードセット処理では、各タプル構築後に一時メモリコンテキスト (tmp_cxt) を MemoryContextReset で明示的に解放し、メモリリークと断片化を防ぐ設計になっています。
  • **スタック保護**: 再帰的な JSONB コンテナ走査やネストした populate_record_field 呼び出し、setPath 処理では、スタックオーバーフローを防ぐため随所に check_stack_depth() が挿入されています。
  • **ソフトエラー処理**: escontext（ErrorSaveContext）が渡された場合、パースエラーや型変換エラーは ereport(ERROR) による中断ではなく、ソフトエラーとして記録され、安全に false や NULL を返す経路がサポートされています（例: jsonb_populate_record_valid）。
