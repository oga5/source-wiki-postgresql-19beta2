src/backend/executor/nodeHash.c

概要

src/backend/executor/nodeHash.c は、PostgreSQLのハッシュ結合（Hash Join）における内部関係（Inner Relation）のハッシュテーブル構築、ハッシュバケット管理、およびパラレルハッシュ結合の協調処理を実装するソースファイルです。バックエンドプライベートなハッシュテーブルと、DSA（Dynamic Shared Area）を活用した共有ハッシュテーブルの両方をサポートし、メモリ制限（work_mem と hash_mem_multiplier）に応じた多段階バッチ分割（Hybrid Hash Join）やスキュー最適化を行います。

モジュール内での役割

実行子モジュール（src/backend/executor）の一部として、Hash プランノードのライフサイクルとハッシュテーブルの構築を担います。通常、プランツリーの親である nodeHashjoin.c から MultiExecHash を通じて呼び出され、構築された HashJoinTable はハッシュ結合のプローブ段階で参照されます。

責務

  • ハッシュテーブルの作成・破棄: ExecHashTableCreate および ExecHashTableDestroy によるメモリコンテキスト（hashCxt, batchCxt, spillCxt）および構造体の管理。
  • タプルの挿入とバッチ分割: プライベートおよびパラレル環境下でのタプルハッシュ値計算、ハッシュバケットへの格納、メモリ超過時のファイルスピル（バッチ分割）制御。
  • パラレルハッシュの協調制御: 複数バックエンドによるバリア同期（Barrier）、動的なバッチ数・バケット数拡張、およびワークキュー管理。
  • スキュー最適化: 最頻出値（MCV）に基づくスキューバケットの構築と、メモリ圧迫時の段階的退避。
  • インストルメンテーション: EXPLAIN ANALYZE 向けの統計情報集計とDSM（Dynamic Shared Memory）経由の収集。

重要なシンボル

ハッシュライフサイクル管理

  • HashState: Hash プランノードの実行時状態を保持する構造体。
  • HashJoinTable: ハッシュ結合テーブル全体の制御ブロック（バケット配列、バッチ数、メモリ使用量、ファイルポインタ等を保持）。
  • ExecInitHash: Hash ノードの初期化を行い、式コンテキストと子ノードを準備する。
  • MultiExecHash: ハッシュ結合のためのハッシュテーブル構築エントリポイント。パラレル状態に応じてプライベート版またはパラレル版をディスパッチする。
  • ExecHashTableCreate: 指定された見積もり行数とメモリ制限を基に、初期バケット数とバッチ数を決定し、ハッシュテーブル構造体を生成する。

テーブル操作・メンテナンス

  • HashJoinTable (ファンクション群):
  • ExecHashTableReset: バッチ切り替え時に batchCxt をリセットし、バケットヘッダを再初期化する。
  • ExecHashTableResetMatchFlags: テーブル全体およびスキューバケットの HeapTupleHeaderHasMatch フラグをクリアする。

パラレルハッシュ管理

  • ExecHashInitializeDSM: 並列クエリ実行時のDSMセグメントにインストルメンテーション領域を確保する。
  • ExecHashInitializeWorker: ワーカープロセス用の共有情報ポインタを設定する。
  • ExecParallelHashTupleAlloc: 共有DSAメモリ上の密記憶領域からタプル用領域を割り当てる。空間不足や拡張要求時はリトライを促す。
  • ExecParallelHashTableAlloc: 指定バッチ用の共有ハッシュバケット配列を割り当て、アトミックポインタを初期化する。

制御フローとデータフロー

1. 初期化:

  • ExecInitHash でプラン状態が作られ、親の nodeHashjoin.c から ExecHashTableCreate が呼ばれて HashJoinTable とメモリコンテキスト（hashCxt, batchCxt, spillCxt）が構築される。

    • 2. 構築フェーズ (MultiExecHash):

  • パラレル非依存 (MultiExecPrivateHash): 外側サブプランからタプルをフェッチし、ハッシュ値を計算。スキューバケットまたは通常バケットに挿入（ExecHashTableInsert）。メモリ上限を超えた場合は ExecHashIncreaseNumBatches によりバッチ数を倍増させ、溢れたタプルを一時ファイル（innerBatchFile）へスピルする。
  • パラレル対応 (MultiExecParallelHash): バリア同期（build_barrier）を用いて複数バックエンドで協調動作。共有ハッシュテーブル（バッチ0）への挿入（ExecParallelHashTableInsert）を行い、必要に応じてバッチ数やバケット数を拡大・再パーティション化する。

    • 3. プローブおよび後処理:

  • 構築完了後、親のハッシュ結合ノードがバケットスキャン（ExecScanHashBucket 等）を行い結合を実行する。終了時は ExecEndHash および ExecShutdownHash でリソースとインストルメンテーションが回収される。

読者向けメモ

  • メモリ管理: すべてのハッシュテーブル用ストレージは親の hashCxt から派生する batchCxt や spillCxt に割り当てられ、クエリ終了時やバッチリセット時にコンテキスト単位で効率的に解放される。
  • 並行性の安全性: パラレルハッシュでは、Dsaポインタとアトミック操作（dsa_pointer_atomic）、および pstate->lock（LWLock）を用いて複数ワーカー間の競合を防ぎながらバケットやチャンクを操作する。
