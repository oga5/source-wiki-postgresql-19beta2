src/backend/executor/nodeHashjoin.c

概要

ハイブリッドハッシュジョイン（Hybrid Hash Join）アルゴリズムを実装する実行ノードソースファイルです。内側（インナー）リレーションからハッシュテーブルを構築し、外側（アウター）リレーションのタプルをスキャンしてハッシュルックアップや外部結合の補完を行います。シリアル実行（parallel-oblivious）と並列実行（parallel-aware / Parallel Hash）の両方をサポートし、メモリ制限（work_mem）を超える場合に備えたマルチバッチ処理やスキューバッチの最適化、バリア同期機構を備えています。

モジュール内での役割

src/backend/executor モジュール内において、結合演算（Join）のうちハッシュ結合を担当する独立した実行ノードです。内側の子ノードである nodeHash.c と緊密に連携し、ハッシュテーブルの構築・管理（ExecHashTableCreate, ExecHashTableInsert 等）を委譲・利用しながら、実行時のタプル照合・射影を行います。

責務

  • **ハッシュ結合の状態管理**: ExecHashJoinImpl によるステートマシン（ビルド、バッチ遷移、バケツスキャン、外部/内部結合の欠損行補完）の駆動。
  • **並列およびシリアル実行の抽象化**: 同一のロジックをインライン関数 ExecHashJoinImpl で共有し、シリアル(ExecHashJoin)および並列(ExecParallelHashJoin)のエントリポイントを提供。
  • **マルチバッチおよびメモリ超過のハンドリング**: メモリに収まらない場合のバッチ分割（ExecHashJoinNewBatch, ExecParallelHashJoinNewBatch）と一時ファイル（BufFile / SharedTuplestore）へのスピル処理。
  • **結合種別に応じた null 補完**: LEFT, RIGHT, FULL, ANTI, SEMI 等の各種結合セマンティクスに基づく、マッチしなかった行や null キー行の補完・出力。

重要なシンボル

  • **実行エントリポイント / ステートマシン**:
  • ExecHashJoin(PlanState *pstate): シリアル実行用エントリポイント。
  • ExecParallelHashJoin(PlanState *pstate): 並列実行用エントリポイント。
  • ExecHashJoinImpl(PlanState *pstate, bool parallel): 核心のハイブリッドハッシュジョインアルゴリズムを実装するインライン関数。
  • **ライフサイクル / 初期化・終了**:
  • ExecInitHashJoin(...): HashJoinState の構築、ハッシュ関数の設定、結合種別に応じた null スロットやハッシュ式（ExecBuildHash32Expr）の初期化。
  • ExecEndHashJoin(...): ハッシュテーブルや一時タプルストアの破棄、子ノードの終了。
  • ExecReScanHashJoin(...): 再スキャン時のハンドリング（シングルバッチ時のハッシュテーブル再利用または破棄と再構築）。
  • **並列共有メモリ（DSM）管理**:
  • ExecHashJoinEstimate, ExecHashJoinInitializeDSM, ExecHashJoinReInitializeDSM, ExecHashJoinInitializeWorker: 並列クエリ実行時の ParallelHashJoinState およびバリア・ファイルセットの初期化・再初期化。
  • **補助関数**:
  • ExecHashJoinOuterGetTuple, ExecParallelHashJoinOuterGetTuple: 外側リレーションからのタプル取得（初回の直実行またはバッチ一時ファイルからの読み出し）。
  • ExecHashJoinNewBatch, ExecParallelHashJoinNewBatch: 次のバッチへの切り替えと内側バッチのハッシュテーブル再ロード。
  • ExecHashJoinSaveTuple: メモリからあふれたタプルを一時ファイルへ保存する。

制御フローとデータフロー

1. **初期化 (ExecInitHashJoin)**:

  • 結合条件（joinqual）、フィルタ条件（otherqual）、ハッシュキーとハッシュ関数を初期化します。
  • outerPlan と innerPlan（Hashノード）を初期化し、必要に応じて欠損行（null fill）用のスロットを割り当てます。

    • 2. **実行ループ (ExecHashJoinImpl のステートマシン)**:

  • HJ_BUILD_HASHTABLE: 初回のみ、Hashノードを実行してハッシュテーブルを構築します。並列の場合はバリア（build_barrier）を用いて協調動作します。
  • HJ_NEED_NEW_OUTER: 外側リレーションからタプルを取得し、ハッシュ値を計算します。現在のバッチに属さない場合は一時ファイルへスポート（ExecHashJoinSaveTuple）し、次の外側タプルへ進みます。
  • HJ_SCAN_BUCKET: ハッシュテーブルの対応するバケツをスキャンして候補タプルを探し、結合条件（joinqual）および非結合条件（otherqual）を評価してマッチすれば射影結果（ExecProject）を返します。
  • HJ_FILL_OUTER_TUPLE / HJ_FILL_INNER_TUPLES / HJ_FILL_OUTER_NULL_TUPLES / HJ_FILL_INNER_NULL_TUPLES: 外部結合やアンチ結合において、マッチしなかった行や null キー行を補完・出力します。
  • HJ_NEED_NEW_BATCH: 現在のバッチが終了した場合、次のバッチが存在すれば ExecHashJoinNewBatch（または並列版）を呼び出して次の内側バッチをハッシュテーブルに再ロードし、外側ファイルを開き直します。

読者向けメモ

  • **メモリ管理とライフサイクル**: ハッシュテーブルやスピル用の一時ファイルは、専用のメモリコンテキスト（hashCxt, spillCxt）上で管理され、クエリ終了時や ExecEndHashJoin / ExecHashTableDestroy で明示的に解放されます。
  • **並列処理のデッドロック回避**: デッドロックを防ぐため、他のバックエンドが待機しないことが保証されるフェーズ（PHJ_BUILD_RUN や PHJ_BATCH_PROBE）以外では、バリア待機中にタプルを emit しない設計になっています。
