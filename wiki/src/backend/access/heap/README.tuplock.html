src/backend/access/heap/README.tuplock

概要

PostgreSQLにおけるヒープタプルレベルのロックメカニズム、マルチトランザクション（MultiXact）、およびインプレース更新（inplace update）時の競合制御に関する設計思想と実装ルールを解説するドキュメントファイルです。

モジュール内での役割

src/backend/access/heap/ サブシステムにおいて、同時実行制御（Concurrency Control）の基盤となる行レベルの排他制御・共有制御の仕様を定義しています。ソースコードではなく解説ドキュメントとして、周辺のタプルアクセス・ロック関連コードの背景情報を提供します。

責務

  • タプルヘッダと標準ロックマネージャを組み合わせた2段階ロックプロトコルの説明。
  • 単一のタプルに対して複数トランザクションがロックを保持するための MultiXact 機構の定義。
  • タプルヘッダ内のインフォマスク（Infomask）ビットによるロック強度・状態の表現方法の規定。
  • システムカタログ等のインプレース更新時における特別なロック要件と論理デコーディング時の制約の提示。

重要なシンボル

該当するソースコードのシンボル定義はありません（テキストドキュメントのため）。

制御フローとデータフロー

  • **タプルロック取得フロー**:

    • 1. LockTuple() を呼び出し、標準ロックマネージャを介してウェイター間の調停を行う。 2. XactLockTableWait() 等により既存のXMAXトランザクションの終了を待つ。 3. タプルヘッダーに自身のXIDやロック強度を記録する。 4. UnlockTuple() でロックマネージャ上の待機を解除する。

  • **マルチXactへの昇格**: タプルヘッダに収まりきらない複数のロックが競合する場合、XIDを MultiXactId に置き換えて拡張領域で管理する。
  • **インプレース更新のガード**: pg_class や pg_database などのインプレース更新対象では、更新前に LOCKTAG_TUPLE を取得して不整合やロストを防ぐ。

直接依存

ソースコードではなくテキスト文書のため、直接の言語レベルの依存関係はありません。

関連コード

  • src/backend/access/heap/heapam.c: ヒープアクセスメソッドとタプル操作の実装。
  • src/backend/storage/lmgr/: 標準ロックマネージャ。
  • src/backend/access/transam/multixact.c: マルチトランザクションの管理実装。

読者向けメモ

  • タプルロックはテーブル全体のロックとは異なり、メモリ消費量を抑えるために2段階の仕組み（ヘッダ記録 ＋ ロックマネージャ）を採用しています。
  • インプレース更新はMVCCの原則（バージョン管理）の例外となるため、論理デコーディング時やキャッシュ参照時の挙動に注意が必要です。
