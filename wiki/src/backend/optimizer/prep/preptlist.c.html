src/backend/optimizer/prep/preptlist.c

概要

src/backend/optimizer/prep/preptlist.c は、パーサーや書き換えフェーズ（rewriter）から渡されたクエリのターゲットリスト（TargetEntry のリスト）を、プランナが処理できる形式に前処理するルーチン群を提供します。INSERT、UPDATE、DELETE、MERGE、および SELECT FOR UPDATE など、文の種別に応じた属性の補完、ターゲット列番号の抽出、行識別子（row-identity）や行ロック用の「resjunk」列の追加を担当します。

モジュール内での役割

src/backend/optimizer/prep/ モジュールの一部として、クエリツリーの最適化前段階における構文木・ターゲットリストの変形を担います。SQL セマンティクスを扱うリライタと、物理アクセスやプラン作成を扱うオプティタイザのパイプラインを仲介し、リレーションの物理構造に密接したターゲットリストの調整を行います。

責務

  • **ターゲットリストドライバ**: preprocess_targetlist を通じて、クエリ全体のターゲットリスト構造を構築し root->processed_tlist に格納する。
  • **INSERT ターゲットリストの展開**: テーブルの全属性が正しい順序で含まれるようにし、欠落している属性に対しては NULL、デフォルト、ドメイン制約、生成列（generated column）のルールに応じた式を補完する。
  • **UPDATE ターゲットリストの列番号抽出**: 更新対象の列番号（colnos）を抽出して root->update_colnos に保存し、非ジャンクな resno を連番に再割り当てする。
  • **ジャンク列の追加**:
  • UPDATE / DELETE / MERGE における行識別子列。
  • SELECT FOR UPDATE / SHARE 等における行ロック用 TID、全行変数（wholerow）、テーブル OID（tableoid）。
  • RETURNING 節で必要な外部リレーションの Var。
  • MERGE アクションや結合条件で参照される外部リレーションの Var / PlaceHolderVar。

重要なシンボル

公開関数 (Public Functions)

  • void preprocess_targetlist(PlannerInfo *root)
  • クエリのターゲットリスト前処理のメインドライバ。コマンド種別（INSERT, UPDATE, DELETE, MERGE, SELECT）に応じたターゲットリストの拡張と resjunk 列の付与を行い、結果を root->processed_tlist に設定する。
  • List *extract_update_targetlist_colnos(List *tlist)
  • UPDATE クエリのターゲットリストから、更新対象となるテーブル列番号のリストを抽出し、ターゲットリストのエントリを 1 から始まる連番に再割り当てする。
  • PlanRowMark *get_plan_rowmark(List *rowmarks, Index rtindex)
  • 指定されたレンジテーブルインデックス（rtindex）に対応する PlanRowMark を検索して返す。見つからない場合は NULL を返す。

内部静的関数 (Static Functions)

  • static List *expand_insert_targetlist(PlannerInfo *root, List *tlist, Relation rel)
  • INSERT クエリのターゲットリストを指定されたリレーションの全属性数・順序に一致させる。欠落列には、ドロップ列、生成列、通常列（ドメイン制約・定数評価含む）に応じた NULL 式を生成・挿入する。

制御フローとデータフロー

1. **初期化**:

  • parse->resultRelation が存在する場合、対応する RangeTblEntry を取得し、table_open でリレーションを開く（ロックは既に取得済みと仮定）。

    • 2. **コマンド別処理**:

  • **INSERT**: expand_insert_targetlist を呼び出し、リレーションの全属性を網羅するターゲットリストを構築する。
  • **UPDATE**: extract_update_targetlist_colnos で更新対象列番号を抜き出し、root->update_colnos に格納する。
  • **非継承 UPDATE / DELETE / MERGE**: add_row_identity_columns を呼び出し、行一意性の特定に必要な列を追加する。
  • **MERGE**: 各 MergeAction の INSERT / UPDATE を個別に処理し、アクションの qual や targetList、さらに mergeJoinCondition から外部リレーションの Var / PlaceHolderVar を抽出して resjunk 列として追加する。

    • 3. **行ロック・rowmark の処理**:

  • root->rowMarks をスキャンし、必要に応じて TID（ctid%u）、全行変数（wholerow%u）、tableoid%u の resjunk エントリをターゲットリストに追加する。

    • 4. **RETURNING 節の処理**:

  • returningList が存在する場合、結果リレーション以外を参照する Var を抽出し、未追加のものであれば resjunk エントリとして追加する。

    • 5. **クリーンアップ**:

  • 開いていた target_relation を table_close で閉じる。メモリ上の構築済みリストは PostgreSQL のメモリコンテキストによって管理される。

読者向けメモ

  • **メモリ管理**: 新規作成されるターゲットエントリやリストは現在のメモリコンテキスト上でアロケートされ、クエリライフサイクル終了時に一括解放される。文字列（resname や属性名）は適宜 pstrdup される。
  • **ドロップ列と生成列の扱い**: expand_insert_targetlist において、ドロップ列には型不整合を避けるためダミーの INT4 型 NULL が設定され、生成列（generated column）ではベース型の NULL が設定される。
