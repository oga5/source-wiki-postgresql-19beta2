src/backend/optimizer/prep/preptlist.c

概要

src/backend/optimizer/prep/preptlist.c は、パーサおよびリライタが生成したパースツリーのターゲットリスト（TargetList）をオプティマイザの入力用に前処理するルーチン群を提供します。物理的なテーブルアクセスやアトリビュート順序の整合性に密接に関わっています。

モジュール内での役割

src/backend/optimizer/prep サブシステムの一部として、クエリのオプティマイズ前段階でターゲットリストを補正・拡張し、後続のプラン生成やエグゼキュータが要求する形式（INSERT の全列順序、UPDATE の列番号抽出、ROW-MARK / RETURNING / MERGE に必要なジャンク列の付加など）へ整えます。

責務

  • **INSERT ターゲットリストの拡張**: ターゲットテーブルの全属性に対応するエントリが正しい順序で存在することを保証し、欠落している列に対してはデフォルト、ドメイン制約（NOT NULL 等）、生成列（generated columns）、またはドロップされた列に応じた適切な NULL 定数を挿入する。
  • **UPDATE ターゲットリストの処理**: 更新対象の列番号（update_colnos）を抽出・分離し、残りのターゲットエントリの resno を連続値に振り直す。
  • **ジャンク列の管理**: UPDATE, DELETE, MERGE、FOR UPDATE/SHARE ロッキング（PlanRowMark）、および RETURNING 句において、エグゼキュータが行識別や再チェックを行うために必要な「resjunk」エントリをターゲットリストに追加する。
  • **プラン行マークの検索**: 指定されたレンジテーブルインデックス（RTインデックス）に対応する PlanRowMark を取得するユーティリティを提供する。

重要なシンボル

ドライバ関数

  • preprocess_targetlist: パースツリーターゲットリスト前処理のエントリポイント。クエリ種別（CMD_INSERT, CMD_UPDATE, CMD_DELETE, CMD_MERGE, CMD_SELECT）に応じてターゲット関係を開き、expand_insert_targetlist や extract_update_targetlist_colnos を呼び出したのち、必要なジャンク列を root->processed_tlist に蓄積する。

リスト拡張・列抽出ヘルパー

  • expand_insert_targetlist: （静的関数）INSERT クエリ用にターゲットリストを走査し、リレーションの属性定義と照合しながら、欠落している属性に対して適切な NULL 式（ドロップ列、生成列、ドメイン制約付き列など）を持つターゲットエントリを補う。
  • extract_update_targetlist_colnos: UPDATE クエリの非ジャンク TLE から代入先カラム番号をリストとして抽出し、同時に TLE の resno を 1 から始まる連続番号に振り直す。

行マークとランタイム関連

  • PlanRowMark: プラン内の行ロック・EvalPlanQual再チェック対象リレーションを表す構造体（本ファイル内のヘルパーや走査対象として参照される）。
  • get_plan_rowmark: 指定されたレンジテーブルインデックス（rtindex）に一致する PlanRowMark を root->rowMarks リストから線形探索し返す。
  • rtindex: レンジテーブルインデックスを表す識別子（Index 型）。get_plan_rowmark などの引数や PlanRowMark のメンバとして用いられる。

クエリ種別の主要シンボル

  • INSERT: クエリ種別（CmdType）の一つ。ターゲットテーブルの全属性順への強制展開やドメイン制約の適用を引き起こす。
  • UPDATE: クエリ種別（CmdType）の一つ。ターゲット列番号の抽出と行識別ジャンク列の追加を引き起こす。

制御フローとデータフロー

1. **初期化**: preprocess_targetlist が root->parse からコマンドタイプと結果リレーション（resultRelation）を取得。リレーションが存在する場合は table_open でオープンする。 2. **コマンド別の分岐**:

  • CMD_INSERT: expand_insert_targetlist を呼び出し、リレーションの TupleDesc を基準に不足している属性を補完。 dropped column や generated column に応じた定数・式を構築して順序を整える。
  • CMD_UPDATE: extract_update_targetlist_colnos を呼び出して更新列番号を root->update_colnos に格納し、resno を連続化。
  • CMD_MERGE: 各 MergeAction ごとに INSERT/UPDATE の処理を行いつつ、アクションの条件やターゲットリスト、結合条件に含まれる他表の Var / PlaceHolderVar を resjunk エントリとして追加。

    • 3. **ジャンク列の追加**:

  • 非継承の UPDATE / DELETE / MERGE に対して add_row_identity_columns を実行。
  • root->rowMarks を走査し、ROW_MARK_COPY や TID、tableoid が必要な場合に対応する ctidN、wholerowN、tableoidN といった resjunk ターゲットエントリを追加。
  • returningList が存在する場合、別リレーションを参照する Var を resjunk として追加。

    • 4. **完了**: 最終的なターゲットリストを root->processed_tlist に格納し、開いていたリレーションをクローズする。

読者向けメモ

  • **メモリ管理**: 新規に作成されるターゲットエントリや文字列（リレーション名やジャンク列名 pstrdup(resname)）は、通常 Planner のメモリコンテキスト上で割り当てられます。
  • **インバリアント**: INSERT クエリの processed_tlist は、対象リレーションの物理属性順と完全に一致していなければなりません。また、UPDATE の non-resjunk エントリの resno は 1 からの連番に正規化されます。
