src/backend/optimizer/prep/prepagg.c

概要

src/backend/optimizer/prep/prepagg.c は、クエリ内の集約関数呼び出し（Aggref）の前処理を行い、同一の集約や状態を共有できる遷移状態（Transition State）を検出・まとめ上げる機能を提供する。計画ツリー構築の初期段階において、root->agginfos および root->aggtransinfos に情報を収集し、個々の Aggref ノードへ一意な識別子（aggno, aggtransno）をインプレースで割り当てることで、無駄な再計算を削減する。

モジュール内での役割

src/backend/optimizer/prep モジュールの一部として、クエリ最適化のプリプロセスフェーズに属する。ジョイントリーやクオリティ、ターゲットリストの変形と並行して、集約演算のコスト見積もりや重複排除の基盤データ構造を構築する役割を担う。

責務

  • **集約の重複排除と状態共有**: 同一の集約関数呼び出しや、同じ引数・遷移関数・初期値を持つ異なる集約の間で、計算結果や遷移状態（transno）を共有させる。
  • **型解決**: 多態性（Polymorphic）を持つ集約の遷移型（aggtranstype）を実際のデータ型へ解決する。
  • **部分集約（Partial Aggregation）の可否判定**: combinefn や serialfn/deserialfn の有無、あるいは順序付き集約の存在を検査し、部分集約やシリアライゼーションの制約フラグを PlannerInfo に設定する。
  • **集約コストの計算**: agginfos と aggtransinfos を走査し、遷移関数・結合関数・最終関数・引数評価・フィルタ評価のコストや、ハッシュ集約用のメモリ空間見積もりを算出する。

重要なシンボル

集約前処理のエントリポイント

  • preprocess_aggrefs(PlannerInfo *root, Node *clause): クエリ内の集約参照を再帰的に走査し、前処理を実行する公開関数。

解析・Walkerヘルパー

  • preprocess_aggrefs_walker(Node *node, PlannerInfo *root): 式ツリーを走査し、Aggref ノードを発見して個別処理へディスパッチする。
  • preprocess_aggref(Aggref *aggref, PlannerInfo *root): 単一の Aggref に対してシステムカタログ（pg_aggregate）から情報を取得し、型解決、重複・共有判定を行って agginfos/aggtransinfos に登録する。

適合性検索

  • find_compatible_agg(PlannerInfo *root, Aggref *newagg, List **same_input_transnos): 既存の AggInfo リストから完全に同一の集約呼び出しを検索する。一致しない場合でも、同じ入力を持つ共有可能な遷移状態のリストを収集する。
  • find_compatible_trans(PlannerInfo *root, Aggref *newagg, bool shareable, Oid aggtransfn, Oid aggtranstype, int transtypeLen, bool transtypeByVal, Oid aggcombinefn, Oid aggserialfn, Oid aggdeserialfn, Datum initValue, bool initValueIsNull, List *transnos): 入力が一致する既存の遷移状態の中から、遷移関数、シリアライズ関数、結合関数、初期値が一致するものを探して再利用する。

値取得・コスト見積もり

  • GetAggInitVal(Datum textInitVal, Oid transtype): テキスト形式の初期値表現を、指定された遷移型の Datum に変換する。
  • get_agg_clause_costs(PlannerInfo *root, AggSplit aggsplit, AggClauseCosts *costs): aggtransinfos と agginfos の内容を元に、遷移コスト・結合コスト・最終関数コスト・メモリ見積もり（transitionSpace）を累積する。

制御フローとデータフロー

1. **走査開始**: preprocess_aggrefs が preprocess_aggrefs_walker を呼び出し、クエリ内の式ツリーから Aggref を探索する。 2. **カタログ参照**: preprocess_aggref が AGGFNOID システムキャッシュを引いて pg_aggregate の関数群（trans, final, combine等）や初期値、型情報を取得する。 3. **型解決**: get_aggregate_argtypes と resolve_aggregate_transtype により、多態的トランジション型を具体化する。 4. **重複・共有判定**:

  • find_compatible_agg で完全一致する Aggref があれば、既存の aggno を流用する。
  • 一致しない場合、find_compatible_trans で同じ入力パラメータを持ちつつ状態共有が可能な transno を探す。見つからなければ新規に AggTransInfo を作成して root->aggtransinfos に追加する。

    • 5. **インプレース更新**: 決定された aggno と aggtransno を Aggref 構造体に書き込む。 6. **コスト集計**: 後続のプラン作成フェーズにおいて get_agg_clause_costs が呼ばれ、各種関数の実行コストやハッシュテーブル用のメモリ所要量が計算される。

読者向けメモ

  • **インプレース書き換え**: 本ファイルでの処理は入力された Aggref ツリーのフィールド（aggno, aggtransno, aggtranstype）を直接書き換える。
  • **ライフサイクル**:ここで生成される AggInfo および AggTransInfo 構造体は、クエリの計画フェーズの生存期間のみ有効であり、エグゼキュータ起動時には破棄される（エグゼキュータは独自に初期値や関数ルックアップを行う設計になっている）。
  • **メモリ・空間の推計**: INTERNAL 型や非パスバイバリュー（Pass-by-reference）の遷移型については、aggtransspace やデフォルトの割り当てサイズ（ALLOCSET_SMALL_INITSIZE, ALLOCSET_DEFAULT_INITSIZE）を用いてハッシュ集約等のメモリ見積もりを行っている。
