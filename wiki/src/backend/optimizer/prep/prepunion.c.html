src/backend/optimizer/prep/prepunion.c

概要

src/backend/optimizer/prep/prepunion.c は、UNION、INTERSECT、EXCEPT などの集合演算（Set Operation）クエリに対するパス生成およびプランニングを担当するモジュールです。歴史的な経緯からファイル名は prepunion.c ですが、現在はすべての集合演算のクエリ最適化を取り扱います。

モジュール内での役割

src/backend/optimizer/prep サブディレクトリに属し、パーサーが生成した SetOperationStmt ツリーを入力として受け取り、オプティマイザの RelOptInfo や Path（Append、MergeAppend、HashAgg、SetOp、RecursiveUnion など）に変換します。隣接する prepjointree.c や allpaths.c が行う下位クエリの調整と連携し、セット演算全体の実行計画を構築する中核を担います。

責務

  • **集合演算ツリーの再帰的解析**: plan_set_operations および recurse_set_operations を通じて SetOperationStmt の階層を辿り、各階層の RelOptInfo とターゲットリストを構築する。
  • **UNION および UNION ALL のパス生成**: generate_union_paths と plan_union_children を使って、複数ブランチの結合（Append / MergeAppend / Gather）や重複排除（HashAgg / Unique）のパスを列挙する。
  • **非UNION演算のパス生成**: generate_nonunion_paths を使い、INTERSECT や EXCEPT（各 ALL 付きを含む）のハッシュおよびソートベースのプランを構築する。
  • **再帰的 UNION の処理**: generate_recursion_path を通じて、CTE や再帰的クエリに必要な RecursiveUnion パスを生成する。
  • **ターゲットリストと型制約の管理**: 入力と出力のデータ型やコレーションの不一致を検出し、必要なキャストや RelabelType を適用して一貫した PathTarget を維持する。

重要なシンボル

エントリポイント

  • plan_set_operations(PlannerInfo *root): 集合演算クエリのプランニングを開始するトップレベル関数。

再帰・ツリー構造トラバーサル

  • recurse_set_operations(...): 集合演算ツリーの1ステップを再帰的に処理し、サブクエリまたは演算ノードの RelOptInfo を返す。
  • plan_union_children(...): 同一プロパティを持つ UNION ノードをフラット化してマージし、個別のサブツリーをプランニングする。

パス生成関数

  • generate_union_paths(...): UNION および UNION ALL ノード用のパス（Append, Gather, HashAgg, Unique, MergeAppend）を構築する。
  • generate_nonunion_paths(...): INTERSECT および EXCEPT ノード用のパスを構築する。
  • generate_recursion_path(...): 再帰的 UNION クエリ用の RecursiveUnion パスを生成する。
  • build_setop_child_paths(...): 集合演算のリーフとなるサブクエリ（RTE_SUBQUERY）に対して SubqueryScan パスやソートパスを構築する。

ユーティリティ・ターゲット生成

  • generate_setop_tlist(...): 集合演算ノード用の子孫参照ターゲットリストを生成し、必要に応じて型キャストやコレーション調整を行う。
  • generate_append_tlist(...): Append プラン用の varno=0 のシンプルな Var ベースのターゲットリストを構築する。
  • generate_setop_grouplist(...): グルーピング・ソート節（SortGroupClause）に正しい tleSortGroupRef を設定する。
  • create_setop_pathtarget(...): 子パスの行数で加重平均された推定幅を持つ PathTarget を生成する。
  • postprocess_setop_rel(...): 拡張フックの呼び出しと最安パス（cheapest path）の選定を行う。

制御フローとデータフロー

1. **エントリー**: plan_set_operations が root->parse->setOperations から SetOperationStmt を取得し、初期化を行う。 2. **再帰トラバーサル**: recurse_set_operations が呼び出され、ノードが RangeTblRef（リーフ）の場合は subquery_planner を実行し、SetOperationStmt の場合は UNION 系 (generate_union_paths) または非UNION系 (generate_nonunion_paths) に分岐する。 3. **子パスの構築**: 各サブクエリや子リレーションに対して build_setop_child_paths が呼び出され、ソート済みパスや並列パス（Parallel Append / Gather）が生成される。 4. **演算特有のパス追加**:

  • UNION では、ソート＋Unique、ハッシュ集約、または MergeAppend のパスを評価して add_path する。
  • INTERSECT / EXCEPT では、ハッシュまたはソートを伴う SetOp パスを構築する。

    • 5. **完了**: 最上位の RelOptInfo と root->processed_tlist が設定され、上位のクエリプランナへ制御が戻る。

読者向けメモ

  • **スタックオーバーフロー対策**: recurse_set_operations の先頭で check_stack_depth() が呼ばれており、過度にネストした集合演算クエリによるスタック枯渇を防いでいる。
  • **Varno 0 ハัก**: generate_append_tlist や generate_setop_tlist では、上位ノード向けに varno 0 の Var ノードを生成することがある。これにより estimate_num_groups などで一部のメタデータ推定が複雑化する場合がある点に注意。
