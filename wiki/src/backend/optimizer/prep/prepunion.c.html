src/backend/optimizer/prep/prepunion.c

概要

prepunion.c は、PostgreSQLオプティマイザにおいて、UNION、INTERSECT、EXCEPT といった集合演算（Set Operation）クエリのプラン作成を担当するモジュールです。ファイル名は初期の実装に由来しますが、現在は複雑な複数階層の集合演算ツリー全体の最適化とパス生成を網羅しています。

モジュール内での役割

src/backend/optimizer/prep サブシステムの一部として、構文解析木上の SetOperationStmt ノード群を入力にとり、UPPERREL_SETOP に対応する RelOptInfo と、それに対応する実行パス（Append, MergeAppend, HashAgg, Sort/Unique, SetOp など）を構築します。単なる UNION ALL の連鎖が「アペンドリレーション」として他モジュールで扱われるのに対し、重複排除や非UNION演算を伴う一般的な集合演算の大部分はこのファイル内のコードによって処理されます。

責務

  • **集合演算ツリーの再帰的走査**: plan_set_operations をエントリーポイントとして、SetOperationStmt ノードの階層構造を再帰的に解析し、各階層のプランを組み立てる。
  • **子クエリおよびリーフの計画生成**: 葉にあたるサブクエリ（RTE_SUBQUERY）の計画を subquery_planner で生成させ、build_setop_child_paths を通じて必要なスキャンやソートパスを付与する。
  • **UNION系パスの生成**: generate_union_paths および plan_union_children により、同一プロパティを持つ UNION / UNION ALL を統合し、Append、MergeAppend、または Gather/Parallel Append パスを構築する。
  • **非UNION系パスの生成**: generate_nonunion_paths により、INTERSECT および EXCEPT（ALLを含む）に対するハッシュベース、ソートベースのプランを作成する。
  • **再帰的 UNION の処理**: generate_recursion_path を使用して、CTEなどで使われる再帰的 UNION / UNION ALL のワークテーブル要件を満たすパスを作成する。
  • **ターゲットリスト（Tlist）の生成と型調整**: 異なるデータ型やコレーションを持つ子クエリ間を調停するため、generate_setop_tlist や generate_append_tlist で適切な Var、キャスト、RelabelType を持つ出力ターゲットリストを作成する。

重要なシンボル

エントリーポイントと駆動関数

  • function plan_set_operations: 集合演算クエリに対する外部からの入口。再帰的クエリかどうかを判定し、最上位の recurse_set_operations または generate_recursion_path を呼び出す。
  • function recurse_set_operations: 集合演算ツリーの 1 ステップを再帰的に処理する中核関数。リーフ（RangeTblRef）の場合はサブクエリの計画とターゲットリスト構築を行い、演算子ノードの場合は対応する生成関数を呼ぶ。

パス・リレーション構築

  • function generate_recursion_path: 再帰的 UNION クエリに対して、非再帰項と再帰項のパスをそれぞれ構築し、RecursiveUnion パスノードを生成する。
  • function build_setop_child_paths: 集合演算の子にあたるサブクエリリレーション（RTE_SUBQUERY）に対し、必要なソートやインクリメンタルソート、並列実行用の SubqueryScan パスを構築する。
  • function generate_union_paths: UNION または UNION ALL ノードの各子パスを集約し、Append、MergeAppend、HashAgg、または Unique を組み合わせたパス群を生成する。
  • function generate_nonunion_paths: INTERSECT および EXCEPT ノードに対し、左右の子入力のサイズ見積もり、必要に応じた順序入れ替え、および SetOp パス（ハッシュまたはソートベース）を生成する。
  • function plan_union_children: 同一のプロパティを持つ連続した UNION ノードを検出し、フラットに折りたたむことで冗長な Append ノードの生成を抑制する。

ターゲットリスト・メタデータヘルパー

  • function generate_setop_tlist: 集合演算ノード用の子クエリ出力ターゲットリストを生成。データ型の不一致に対する暗黙的キャストの挿入や、コレーションの調整（RelabelType）を行う。
  • function generate_append_tlist: Append プランノード用のシンプルな Var ベースのターゲットリストを生成し、共通の型・型修飾子（typmod）を調停する。
  • function generate_setop_grouplist: 集合演算の出力カラムに対するソート・グルーピングプロセスの基準となる SortGroupClause リストを構築する。
  • function create_setop_pathtarget: 子パスの行数で加重平均した推定幅を設定しつつ、通常の PathTarget を作成する。

*(注：要求仕様に基づき言及義務のある記号のうち、PathTarget, RecursiveUnion, RelOptInfo, SortGroupClause, SubqueryScan, Var は、本ファイル内の関数が操作・生成・参照するコア型・ノード構造体である)*

制御フローとデータフロー

1. **初期化**: plan_set_operations が root->parse->setOperations からルートの SetOperationStmt を取得し、最も左側にあるリーフ（leftmostQuery）のターゲットリストから出力列名情報を取得する。 2. **再帰処理**: recurse_set_operations がツリーを降り、葉（RangeTblRef）に到達すると subquery_planner を呼び出してサブクエリの内部パスを確定させる。 3. **パス生成と子構築**: 演算子の種類に応じて generate_union_paths や generate_nonunion_paths が呼び出され、必要に応じて build_setop_child_paths が子リレーションのソート済みパスや並列パス（Parallel Append / Gather）を補う。 4. **型・コレーション調整**: 各階層で入力側と期待される出力型の間に差異がある場合、generate_setop_tlist 内でキャストや RelabelType が追加され、必要に応じて Result プロジェクションパスが親パスに適用される。 5. **最終結果**: 最上位の RelOptInfo（UPPERREL_SETOP）とその最安パスが返され、処理されたターゲットリストが root->processed_tlist に格納される。

読者向けメモ

  • **メモリ管理**: クエリ計画中に生成される Path、PathTarget、List などのオブジェクトは、通常のオプティマイザ用メモリコンテキスト（Planner Context）上で割り当てられ、プラン作成完了後に一括解放されるため、個別解放の必要はない。
  • **スタックオーバーフロー対策**: recurse_set_operations では、極端にネストした集合演算クエリによるＣスタック枯渇を防ぐため、check_stack_depth() を各再帰の先頭で実行している。
  • **varno 0 のハック**: Append や集合演算のターゲットリストの一部生成において、入力変数を参照するために varno 0 の Var ノードが使用される。これが原因で estimate_num_groups 等が直接利用できない箇所があり、周囲のコードで注意深いハンドリングが行われている。
