src/backend/optimizer/path/allpaths.c

概要

src/backend/optimizer/path/allpaths.c は、PostgreSQLオプティマイザにおいてクエリの処理経路（Path）を探索・生成するための中心的なルーチン群を提供する。ベースリレーション（テーブル、サブクエリ、関数など）のサイズ見積もり、スキャンパス・並列パス・インデックスパス・アペンドパスの構築、およびサブクエリへの修飾子（qual）プッシュダウンや未使用出力列の削除といった最適化パスを統括する。

モジュール内での役割

src/backend/optimizer/path サブシステムの一部として、コスト計算子（costsize.c）や等価クラス管理（equivclass.c）などと連携し、クエリツリー全体または各リレーション単体の RelOptInfo に対して実際のアクセスパスを割り当てる。プランナのメインエントリポイントから呼び出され、結合探索（standard_join_search）や単一リレーションのパス生成（make_one_rel）を結ぶ中核の責務を持つ。

責務

  • **ベースリレーション処理**: クエリ内の各ベースリレーション（プレーンテーブル、外部テーブル、サンプルテーブル、アペンドリレーション等）のサイズ見積もり、並列スキャン適格性の判定、およびアクセスパスの構築。
  • **アペンド／マージアペンドパス生成**: 継承ツリーやパーティションテーブルのための Append / MergeAppend パス、並列アペンド、順序付きアペンドパスの構築。
  • **サブクエリ最適化とプッシュダウン**: サブクエリがプッシュダウン安全（subquery_is_pushdown_safe、qual_is_pushdown_safe）か判定し、安全な WHERE / HAVING 条件をサブクエリ内へ押し下げる。また、未使用のサブクエリ出力列の除去。
  • **結合探索のオーケストレーション**: ジョインリスト（joinlist）を基に、プラグイン・GEQO・標準動的計画法（standard_join_search）を介して結合ツリー全体のパスを探索する。
  • **グループ化・集約パス生成**: 早期集約（eager aggregation）やパーティションワイズ結合・集約パスの生成制御。

重要なシンボル

中核オーケストレーション

  • make_one_rel(PlannerInfo *root, List *joinlist): クエリ実行のための全アクセスパスを探索し、全ベースリレーションの結合を表す単一の RelOptInfo を返す。
  • standard_join_search(PlannerInfo *root, int levels_needed, List *initial_rels): 動的計画法アルゴリズムを用い、下位リレーションを段階的に結合して結合パスを探索する。

ベースリレーション・アペンドパス管理

  • set_base_rel_sizes(PlannerInfo *root) / set_base_rel_pathlists(PlannerInfo *root): 各ベースリレーションのサイズ見積もりとパスリスト構築を反復実行する。
  • set_rel_size(...) / set_rel_pathlist(...): リレーションの種類（RTE種類、継承の有無など）に応じたサイズ見積もり・パス構築へのディスパッチ。
  • add_paths_to_append_rel(PlannerInfo *root, RelOptInfo *rel, List *live_childrels): 非ダミーの子リレーション群から、通常・並列・パラメータ化・順序付きの Append/MergeAppend パスを生成する。

プッシュダウン・安全性検証

  • subquery_is_pushdown_safe(...): サブクエリが修飾子のプッシュダウンに対して安全かを検証する（LIMIT、EXCEPT、DISTINCT、ウィンドウ関数等の制約を確認）。
  • qual_is_pushdown_safe(...): 個別の制限条項（RestrictInfo）がサブクエリへのプッシュダウンに安全か、あるいはウィンドウ関数の実行条件（PUSHDOWN_WINDOWCLAUSE_RUNCOND）として利用可能かを判定する。
  • subquery_push_qual(...): 安全と判定された修飾子をサブクエリの WHERE または HAVING に実際に対象変数置換を行いながらプッシュダウンする。

制御フローとデータフロー

1. **初期化とサイズ見積もり**: make_one_rel が呼び出されると、まず set_base_rel_consider_startup と set_base_rel_sizes により各ベースリレーションのサイズ（行数・幅）および並列実行可否（consider_parallel）が計算される。 2. **グループ化リレーションの準備**: setup_simple_grouped_rels により、早期集約が可能な場合にグループ化リレーション（grouped rel）が構築される。 3. **パスリストの構築**: set_base_rel_pathlists が各ベースリレーションの set_rel_pathlist を呼び出し、シーケンシャルスキャン、インデックススキャン、TIDスキャン、あるいはサブクエリ／Fdw固有のパスを登録する。 4. **結合探索**: make_rel_from_joinlist および standard_join_search が動的計画法（レベリング 2 から levels_needed まで）を用いて、各レベルの結合リレーションに対するパス、パーティションワイズ結合パス、Gather/Gather Merge パスを順次構築する。 5. **最終リレーションの返却**: 全ベースリレーションを結合したトップレベルの RelOptInfo が構築され、プランナの後続処理へ渡される。

読者向けメモ

  • **メモリ管理**: subquery_push_qual や set_subquery_pathlist では入力の Query 構造体が破壊されないよう copyObject を用いて複製される。pushdown_safety_info の unsafeFlags などは palloc0 で確保され適宜解放される。
  • **並列安全性**: set_rel_consider_parallel は一時テーブルや非安全な関数・FDW、LIMIT/OFFSETを含むサブクエリを厳格に検出し、安全なリレーションのみに並列ワーカーの適用を許可する。
