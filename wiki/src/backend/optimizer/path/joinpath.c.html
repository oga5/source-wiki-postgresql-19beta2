src/backend/optimizer/path/joinpath.c

概要

src/backend/optimizer/path/joinpath.c は、PostgreSQLのオプティマイザサブシステムにおいて、指定された結合関係（RelOptInfo）を構築するために利用可能なすべての物理結合パス（ネストループ、マージ結合、ハッシュ結合）を探索・生成する責務を持つ。外部プラグイン向けのフック変数や、パーティション分割結合を判定するためのマクロ群も提供する。

モジュール内での役割

src/backend/optimizer/path モジュールに属し、joinrels.c や allpaths.c から呼び出されて具体的な結合方式のパス候補（Path）を構築する。コスト見積もり関数（costsize.c）やノード生成関数（pathnode.h）と連携しながら、利用可能な制限条項や等価クラスをもとに最適な実行プランの候補を網羅する。

責務

  • **結合パスの総称的エントリポイント**: add_paths_to_joinrel を中心として、外部・内部リレーションの組み合わせから各種結合パスを生成する。
  • **ネストループ結合パスの生成と最適化**: 通常のネストループ、マージノード、マテリアライズ、およびメモ化（Memoize）を活用したパスの検討。
  • **マージ結合パスの生成**: ソート済みの入力や明示的なソート、および部分的なマージ節の切り捨て（truncation）を伴うパスの構築。
  • **ハッシュ結合パスの生成**: 通常のハッシュ結合および並列ハッシュ（parallel_hash）に対応する部分的・完全なハッシュ結合パスの検討。
  • **プラグイン連携**: set_join_pathlist_hook や join_path_setup_hook を介した、拡張機能による結合パスのカスタマイズインターフェースの提供。

重要なシンボル

フックとマクロ

  • set_join_pathlist_hook: 結合パスリスト構築の最後に割り込むプラグインフック。
  • join_path_setup_hook: 結合パス構築の初期段階で extra.pgs_mask などを調整するプラグインフック。
  • PATH_PARAM_BY_PARENT, PATH_PARAM_BY_REL_SELF, PATH_PARAM_BY_REL: 親子パーティション関係におけるパラメータ化を判定するマクロ。

エントリポイントと統括関数

  • add_paths_to_joinrel: 外部リレーションと内部リレーションのペアから、利用可能なすべての結合方式のパスを網羅的に生成し、joinrel に登録する主関数。

結合方式別の生成・試行ヘルパー

  • try_nestloop_path / try_partial_nestloop_path: ネストループ結合パスの妥当性検証および追加。
  • try_mergejoin_path / try_partial_mergejoin_path: マージ結合パスの妥当性検証および追加。
  • try_hashjoin_path / try_partial_hashjoin_path: ハッシュ結合パスの妥当性検証および追加。
  • get_memoize_path: 条件を満たす場合に、ネストループの内側に Memoize パスを構築する。

探索・準備ヘルパー

  • sort_inner_and_outer: 両側のリレーションを明示的にソートするマージ結合パスを生成する。
  • match_unsorted_outer: 既にソート済みの外側パスを利用するネストループおよびマージ結合パスを生成する。
  • hash_inner_and_outer: ハッシュ結合可能な条項を抽出し、ハッシュ結合パスおよび並列ハッシュパスを生成する。
  • select_mergejoin_clauses: 結合条項からマージ結合に使用可能な RestrictInfo のリストを選別する。
  • generate_mergejoin_paths: 外側パスに対して、インナー側のソート済みパスや切り捨てられたマージ節を用いたマージ結合パス群を生成する。

制御フローとデータフロー

1. **初期化とフックの呼び出し**:

  • add_paths_to_joinrel が呼び出されると、JoinPathExtraData 構造体を初期化し、join_path_setup_hook があれば実行して制御フラグ（pgs_mask）や一意性（inner_unique）を確定する。

    • 2. **結合条項の選別**:

  • select_mergejoin_clauses により、マージ結合に利用可能な制限条項のリスト（extra.mergeclause_list）を作成する。

    • 3. **各種結合パスの検討**:

  • **ソートを伴うマージ結合**: sort_inner_and_outer を呼び出し、利用可能なマージ順序ごとに両側をソートするパスを試行する。
  • **ソート済みの外側を利用する結合**: match_unsorted_outer を呼び出し、ネストループ（必要に応じ Memoize や Materialize を含む）および既存ソート済みインナーによるマージ結合を試行する。
  • **ハッシュ結合**: hash_inner_and_outer を呼び出し、ハッシュ結合可能な条件に基づきハッシュ結合および並列ハッシュパスを試行する。
  • **FDWプッシュダウン**: joinrel->fdwroutine->GetForeignJoinPaths が存在する場合はリモート結合のプッシュダウンを試みる。

    • 4. **プラグインによる後処理**:

  • set_join_pathlist_hook を呼び出し、拡張機能が最終的なパスリストを変更・追加できるようにする。

読者向けメモ

  • 本ファイルの関数群は、コスト見積もりの初期チェック（add_path_precheck など）を利用して、明らかに非効率なパスの完全な構築を早期に破棄し、プランナのメモリとCPU使用量を抑制している。
  • JOIN_UNIQUE_OUTER や JOIN_UNIQUE_INNER などの特殊な結合型は add_paths_to_joinrel の内部で一時的に通常の内部結合（JOIN_INNER）等へ正規化され、外部へ露出しないようカプセル化されている。
