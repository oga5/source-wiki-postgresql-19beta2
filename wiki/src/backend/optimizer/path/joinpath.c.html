src/backend/optimizer/path/joinpath.c

概要

PostgreSQLオプティマイザの一部として、指定された結合リレーション（joinrel）に対して利用可能なすべての結合パス（Nested Loop、Merge Join、Hash Join、およびそれぞれの並列・Memoize対応版）を生成・評価し、最適なパスを選択・追加するルーチン群を提供します。クエリ最適化における結合方式の網羅的な列挙とコスト評価の起点を担う極めて重要なソースファイルです。

モジュール内での役割

src/backend/optimizer/path モジュールに属し、他ファイル（pathnode.h, cost.h, restrictinfo.h など）が定義するコスト計算やノード作成関数を利用して、外側（outer）と内側（inner）のリレーションをどのように結合すべきかの具体的な Path を構築します。また、拡張機能向けのエントリポイントフックを提供します。

責務

  • 結合パスの総括制御: add_paths_to_joinrel を中心に、指定された結合リレーションに対する各結合手法（Nestloop、Mergejoin、Hashjoin、FDWプッシュダウン）の適用可否を判定・実行する。
  • 特殊結合および一意性のハンドリング: JOIN_SEMI, JOIN_ANTI, JOIN_FULL, ならびに一意化されたリレーション（JOIN_UNIQUE_OUTER, JOIN_UNIQUE_INNER）に対する補正係数や制約の管理。
  • Memoizeパスの検討: ネストループのパフォーマンスを改善するための Memoize ノード適用可能性の評価とキャッシュキー抽出。
  • 並列結合の評価: ワーカプロセスを活用した並列ネストループ、並列マージ結合、並列ハッシュ結合（共有ハッシュテーブル対応）のパス生成。

重要なシンボル

結合エントリポイントと制御

  • add_paths_to_joinrel:

    • 外側・内側のリレーションから結合リレーションを構成するあらゆるパスを網羅的に検討し、有効なものを joinrel->pathlist に追加する主関数。拡張用フックや一意性判定、各種結合手法へのディスパッチを統括します。

Memoizeおよびパラメータ抽出

  • Memoize:

    • ネストループの内側スキャンを高速化するため、外部パラメータに対する内部スキャン結果をキャッシュする機構（直接の関数定義というより本ファイルで構築・制御される概念）。

  • paraminfo_get_equal_hashops:

    • パラメータ情報やラテラル変数からハッシュ可能な等価演算子を収集し、Memoizeキャッシュのキーとして利用可能か判定します。

  • extract_lateral_vars_from_PHVs:

    • プレースホルダー変数（PHV）内からラテラル参照を抽出し、Memoizeのキャッシュキー候補を作成します。

  • get_memoize_path:

    • 条件を満たす場合に inner_path の上に Memoize パスを構築して返します。

結合方式別パス生成ヘルパー（試行・検証）

  • try_nestloop_path / try_partial_nestloop_path:

    • ネストループ結合パスを生成し、事前チェック（add_path_precheck）を通過したものを joinrel に追加します。

  • try_mergejoin_path / try_partial_mergejoin_path:

    • マージ結合パスの生成とコスト事前チェック、およびインクリメンタルソートの適用要否の判断を行います。

  • try_hashjoin_path / try_partial_hashjoin_path:

    • ハッシュ結合パス（並列ハッシュ含む）の生成・追加を行います。

補助判定・最適化ヒューリスティック

  • allow_star_schema_join:

    • スタースキーマシナリオにおいて、パラメータソース制約（param_source_rels）を緩和してネストループを許可すべきかを判定するインライン関数。

  • have_unsafe_outer_join_ref:

    • アサートビルド時において、不安全な外部結合の参照が含まれていないかを検証します（アサーションによる安全性担保）。

制御フローとデータフロー

1. 初期化とフック: add_paths_to_joinrel が呼ばれると、join_path_setup_hook を呼び出して拡張機能による設定変更を受け付けます。 2. 一意性・パラメータの解決: 内側リレーションの一意性（innerrel_is_unique）を評価し、セミ/アンチ結合の補正係数を計算します。また、クエリ全体の join_info_list から param_source_rels を構築します。 3. 結合手法の網羅的適用:

  • sort_inner_and_outer: 明示的なソートを伴うマージ結合の検討。
  • match_unsorted_outer: ソート済み外側パスを活用するネストループ（Memoize や Materialize の適用含む）およびマージ結合の検討。
  • hash_inner_and_outer: ハッシュ結合（および enable_parallel_hash に応じた並列ハッシュ）の検討。
  • FDWプッシュダウンや set_join_pathlist_hook による拡張。

    • 4. プルーニング: 各 try_*_path 関数内で add_path_precheck / add_partial_path_precheck を行い、劣るパスを早期に排除してから add_path / add_partial_path で登録します。

読者向けメモ

  • メモリ管理: パス拒否時に不要となった Relids（required_outer や unsatisfied など）は bms_free() により即座に解放され、大規模な結合ツリー構築時のメモリリークを防ぎます。
  • インラインマクロ: PATH_PARAM_BY_PARENT, PATH_PARAM_BY_REL_SELF, PATH_PARAM_BY_REL はパーティション分割された継承ツリー（partitionwise joins）を跨ぐパラメータ依存関係を効率的に判定するため頻繁に使用されます。
