src/backend/optimizer/path/clausesel.c

概要

src/backend/optimizer/path/clausesel.c は、PostgreSQLのクエリプレーニラにおいて、述語句（Clause）の選択度（Selectivity: 条件に一致する行の割合、0.0 〜 1.0）を計算するルーチン群を所有するファイルです。単一の式、AND/ORで結合された条件リスト、範囲クエリ（Range Query）、および拡張統計情報（Extended Statistics）の適用やキャッシュ機構を管理します。

モジュール内での役割

src/backend/optimizer/path モジュールの一部として、オプティマイザがパス生成やコスト見積もり（costsize.c など）を行う際に必要な、述語の絞り込み能力の数値化を提供します。実際の統計学的計算アルゴリズムの多くは utils/selfuncs.h や statistics/statistics.h に委譲しつつ、このファイルは条件の構造解析、拡張統計のディスパッチ、および範囲条件のペアリングやAND/OR合成のロジックを担います。

責務

  • **暗黙的ANDリストの選択度計算**: clauselist_selectivity および clauselist_selectivity_ext による、複数条件の積としての選択度算出。
  • **暗黙的ORリストの選択度計算**: clauselist_selectivity_or による、複数条件の和集合としての選択度算出（包含排除の原理）。
  • **範囲クエリ（Range Query）の最適化**: 同一変数の下限・上限条件（例: x > 34 AND x < 42）を検出し、独立確率の単純な掛け合わせではなく幾何学的範囲として再計算・重複排除を行う。
  • **個別句の選択度計算とキャッシュ管理**: clause_selectivity および clause_selectivity_ext による、様々な式ノード（Var, Const, Param, OpExpr, FuncExpr, ScalarArrayOpExpr 等）のディスパッチと、RestrictInfo への結果キャッシュ。
  • **制限句か結合句かの判定**: treat_as_join_clause による、指定されたコンテキストでの評価モード決定。

重要なシンボル

データ構造

  • **RangeQueryClause**: 範囲クエリのペアリング情報を蓄積するための連結リスト用構造体。
  • next: リスト内の次の要素へのポインタ。
  • var: 共通の変数式。
  • have_lobound / have_hibound: 下限・上限の条件が見つかったかのフラグ。
  • lobound / hibound: それぞれの選択度。

公開関数（Public Functions）

  • **clauselist_selectivity(PlannerInfo *root, List *clauses, int varRelid, JoinType jointype, SpecialJoinInfo *sjinfo)**: use_extended_stats = true で clauselist_selectivity_ext を呼び出すラッパー。
  • **clauselist_selectivity_ext(...)**: 拡張統計情報の適用を制御しつつ、ANDリストの選択度を算出。範囲クエリのペアを見つけて hisel + losel + null_frac - 1.0 の補正を行う。
  • **clause_selectivity(...)**: use_extended_stats = true で clause_selectivity_ext を呼び出すラッパー。
  • **clause_selectivity_ext(...)**: 単一の clause（RestrictInfo または生式）の選択度を計算。RestrictInfo の場合は norm_selec または outer_selec に結果をキャッシュする。

内部ヘルパー関数（Internal Helpers）

  • **clauselist_selectivity_or(...)**: ORで結合された条件リストの選択度を s1 + s2 - s1 * s2 の式で近似計算する。
  • **addRangeClause(...)**: 範囲クエリの条件を RangeQueryClause リストに追加・マージし、より厳い制約（tighter constraint）を保持する。
  • **find_single_rel_for_clauses(...)**: 条件リストがすべて単一の関係（Relation）を参照しているかを検証し、該当する RelOptInfo を返す。
  • **treat_as_join_clause(...)**: 与えられた演算子句を制限句（Restriction clause）として扱うべきか、結合句（Join clause）として扱うべきかを判定する。

制御フローとデータフロー

1. **エントリポイント（clause_selectivity_ext / clauselist_selectivity_ext）**:

  • 呼び出し元から PlannerInfo、評価対象の clauses または単一の clause、およびコンテキスト情報を受け取る。
  • RestrictInfo の場合、有効なキャッシュ（norm_selec または outer_selec）が存在すれば即座にそれを返す。

    • 2. **拡張統計の適用**:

  • 対象が単一リレーションに対する複数条件である場合、find_single_rel_for_clsuses を経由してリレーションを特定し、statext_clauselist_selectivity を呼び出して相関統計や多変量統計による選択度を優先的に取得する。

    • 3. **個別条件および範囲クエリの処理（ANDリストの場合）**:

  • 拡張統計でカバーされなかった残りの条件をループで走査し、clause_selectivity_ext で個別選択度（s2）を計算。
  • 片側に疑似定数を持つ比較演算子（<, <=, >, >=）かつ特定の估算子である場合、addRangeClause を使って rqlist に登録。
  • ループ終了後、rqlist をスキャンし、同一変数に対する上下限のペアが揃っていれば hisel + lobound - 1.0 + nulltestsel(...) による精密な範囲選択度を適用。揃っていなければ個別に掛け合わせる。

    • 4. **型ごとのディスパッチ（単一条件の場合）**:

  • clause_selectivity_ext 内で nodeTag(clause) に応じて分岐（Var, Const, Param, NotExpr, BoolExpr (AND/OR), OpExpr, DistinctExpr, FuncExpr, ScalarArrayOpExpr, RowCompareExpr, NullTest, BooleanTest, CurrentOfExpr 等）。
  • それぞれ専用の推定量関数（boolvarsel, restriction_selectivity, join_selectivity, function_selectivity, scalararraysel, rowcomparesel, nulltestsel, booltestsel など）へディスパッチする。

    • 5. **キャッシュの書き戻し**:

  • 計算結果を cacheable な RestrictInfo のキャッシュフィールドに格納し、選択度（Selectivity 型の double 値）を返却する。

読者向けメモ

  • **メモリ管理**: RangeQueryClause リストは palloc_object で一時的にメモリコンテキスト上に割り当てられ、clauselist_selectivity_ext の処理完了時に pfree によって解放される。
  • **キャッシュの不変条件**: RestrictInfo の norm_selec と outer_selec は、varRelid == 0 または変数群がそのリレーション内に収まる場合にのみキャッシュされる（外部変数が混ざる場合はコンテキスト依存で結果が変わるためキャッシュされない）。
  • **丸め誤差対策**: 範囲クエリの計算結果 s2 がゼロ以下になった場合、微小な負数であれば丸め誤差とみなして 1.0e-10 に丸め、過度に負の値であればデフォルト値（DEFAULT_RANGE_INEQ_SEL）にフォールバックする安全策が組まれている。
