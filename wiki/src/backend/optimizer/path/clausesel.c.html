src/backend/optimizer/path/clausesel.c

概要

src/backend/optimizer/path/clausesel.c は、PostgreSQLのオプティマイザがクエリ内の述語句（Clause）の選択率（Selectivity）を計算するためのルーチン群を所有するソースファイルです。暗黙的AND/ORリスト、範囲検索（Range Query）、単一・複数リレーション、および拡張統計情報（Extended Statistics）を考慮したコスト見積もりの基盤を提供します。

モジュール内での役割

src/backend/optimizer/path サブシステムにおいて、本ファイルはプラン作成やパスのコスト見積もりに不可欠なフィルタの選択率算出を担当します。costsize.c や indxpath.c などの他のパスモジュールが、スキャンやジョインの絞り込み度合いを評価する際に呼び出されます。

責務

  • **AND/OR句の選択率計算**: 複数条件の積（AND）および和（OR）の確率的結合を、拡張統計情報や独立性の仮定に基づいて算出する。
  • **範囲クエリの最適化**: 同一変数に対する大小比較（例: x > 34 AND x < 42）を RangeQueryClause リストでペアリングし、重なりを考慮した正確な選択率を算出する。
  • **単一リレーション判定**: 複数句が単一の関係を参照しているかを検証し、拡張統計情報の適用を試みる。
  • **個別句の選択率ディスパッチ**: RestrictInfo のキャッシュ機構を利用しつつ、Var, Const, FuncExpr, OpExpr などの各種式ノードに応じた適切な選択率関数を呼び出す。

重要なシンボル

構造体

  • RangeQueryClause: 範囲クエリのペア情報を蓄積する連結リストの要素。変数 (var)、下限/上限の有無フラグ (have_lobound, have_hibound)、およびそれぞれの選択率 (lobound, hibound) を保持する。

選択率計算・統計処理関数

  • clauselist_selectivity: 暗黙的ANDで結合された句リストの選択率を計算するエントリポイント（use_extended_stats = true で clauselist_selectivity_ext を呼び出す）。
  • clauselist_selectivity_ext: 拡張版AND句選択率計算。拡張統計の適用を制御し、範囲クエリのペアリング処理（hisel + losel + null_frac - 1 の補正）や一般句の乗算を行う。
  • clauselist_selectivity_or: 暗黙的ORで結合された句リストの選択率を計算する。拡張統計を適用後、確率的包含排除則（s1 + s2 - s1*s2）でマージする。
  • find_single_rel_for_clauses: 句リストが単一のリレーションのみを参照しているかを判定し、該当する RelOptInfo を返す。

句の分類・評価関数

  • treat_as_join_clause: 演算子句が制限（Restriction）として評価されるべきか、ジョイン（Join）として評価されるべきかを判定する。
  • clause_selectivity: 一般的なブール式句の選択率を計算する基本エントリポイント。
  • clause_selectivity_ext: 拡張版の単一句選択率計算。RestrictInfo のキャッシュ（norm_selec, outer_selec）の参照と更新を行い、式ノードの種類（Var, Const, Param, OpExpr, FuncExpr, NullTest等）に応じた見積もり関数へディスパッチする。
  • addRangeClause: 範囲クエリ句を RangeQueryClause リストに追加・マージし、同一変数に対するより制限的な境界を保持する。

制御フローとデータフロー

1. **エントリ**: コスト見積もりプロセスから clauselist_selectivity または clause_selectivity が呼び出される。 2. **統計情報の適用**:

  • リストが単一リレーションを対象とする場合、find_single_rel_for_clauses で RelOptInfo を取得し、可能であれば statext_clauselist_selectivity によりクロス列依存関係などの拡張統計を適用する。

    • 3. **個別句の走査と範囲クエリのペアリング**:

  • clauselist_selectivity_ext 内で各句をループ処理する。
  • 比較演算子がスカラ大小比較（F_SCALARLTSEL 等）で擬似定数と比較している場合、addRangeClause を呼び出して RangeQueryClause リストに蓄積する。
  • 蓄積された範囲クエリはループ後に評価され、hisel + losel - 1.0 をベースに NULL 考慮の補正と丸め誤差の処理を行って全体へ乗算される。

    • 4. **キャッシュの活用**:

  • RestrictInfo が渡された場合、条件（varRelid やベースリレーション数）が満たされていれば、計算済み結果を norm_selec または outer_selec にキャッシュし、二重計算を回避する。

読者向けメモ

  • **メモリ管理**: RangeQueryClause などの動的構造体は、ローカルなリンクリストとして palloc/pfree を用いて関数スコープ内で明示的に解放される。
  • **インバリアント**: RestrictInfo のキャッシュ変数（norm_selec, outer_selec）は、無効値として負数が初期値に設定されており、条件に一致する場合のみ更新・再利用される。
