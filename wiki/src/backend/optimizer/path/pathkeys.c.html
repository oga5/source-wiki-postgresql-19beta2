src/backend/optimizer/path/pathkeys.c

概要

pathkeys.c は、PostgreSQLのオプティマイザにおいて、ソート順序や等価性を抽象化したデータ構造である **PathKey** の構築、マッチング、冗長性判定、および比較を行うユーティリティ群を所有しています。 ポインタ比較による高速な等価性判定ができる「正規化された PathKey (canonical pathkey)」の管理を基盤とし、インデックススキャン、パーティションスキャン、ソート句、マージ結合、サブクエリ、GROUP BY 処理における順序要件の伝播や評価を統合的に支えています。

モジュール内での役割

src/backend/optimizer/path モジュールの一部として、パス生成フェーズにおける「順序の整合性と最適化」の基盤を提供します。 隣接する equivclass.c（等価クラス管理）と密に連携し、等価制約やソート情報から一意の PathKey を生成・共有します。また、joinpath.c や indxpath.c などのパス探索部に対して、特定の PathKey を満たす最安パスの選択や結合用マージ句の構築機能を提供します。

責務

  • **PathKey の正規化と構築**: EquivalenceClass と演算子ファミリーを基に重複のない一意な PathKey を生成・キャッシュする。
  • **冗長性テスト**: 定数を含む等価クラスや重複する等価クラスに基づく冗長なソートキーを検出し排除する。
  • **順序比較と包含関係判定**: 2つのパスキーリストの同値性、サブセット関係、共通接頭辞長を計算する。
  • **特殊スキャン/結合のパスキー生成**: インデックス (build_index_pathkeys)、パーティション (build_partition_pathkeys)、サブクエリ (convert_subquery_pathkeys)、マージ結合 (make_inner_pathkeys_for_merge, select_outer_pathkeys_for_merge) における入出力パスキーを組み立て・変換する。
  • **有用性評価とトリミング**: 上位の要件（ORDER BY、GROUP BY、マージ結合など）に照らして不要なパスキーを切り捨てる (truncate_useless_pathkeys)。

重要なシンボル

パスキーの構築・管理

  • **make_canonical_pathkey**: 指定された等価クラス、演算子ファミリー、比較型、NULL配置から既存の正規化済み PathKey を検索するか、新規作成して root->canon_pathkeys に登録する。
  • **make_pathkey_from_sortinfo / make_pathkey_from_sortop**: ソート式や演算子情報から対応する EquivalenceClass を解決・作成し、make_canonical_pathkey を呼び出す。
  • **append_pathkeys**: ターゲットのパスキーリストに、冗長でないソースのパスキーを追加する。

パスキー比較と判定

  • **compare_pathkeys**: 2つのパスキーリストを比較し、一致、異なる、あるいは一方が他方を含むか (PATHKEYS_BETTER1/PATHKEYS_BETTER2) を判定する。
  • **pathkeys_contained_in / pathkeys_count_contained_in**: パスキーの包含関係や共通接頭辞の長さを計算する。
  • **pathkey_is_redundant**: 指定された PathKey が既存のリスト内で冗長（定数クラス、または既に同じ EC が使用されている）か判定する。

特殊用途のパスキー生成・変換

  • **build_index_pathkeys**: インデックス定義とスキャン方向からインデックススキャンの出力パスキーを構築する。
  • **build_partition_pathkeys**: パーティション化されたリレーションの順序付きスキャンに対するパスキーを構築する。
  • **convert_subquery_pathkeys**: サブクエリの出力パスキーを外部クエリのコンテキストに変換・マッピングする。
  • **build_join_pathkeys**: 結合種別（INNER, LEFT など）に応じて結合リレーションのパスキーを構築または破棄（FULL, RIGHT 等）する。
  • **make_inner_pathkeys_for_merge / select_outer_pathkeys_for_merge**: マージ結合の左右の入力に必要なパスキーを構築・調整する。

有用性・再順序付け

  • **truncate_useless_pathkeys**: ORDER BY、GROUP BY、DISTINCT、ウィンドウ関数、マージ結合などの上位要件に照らし、役に立たない末尾のパスキーを切り詰める。
  • **get_useful_group_keys_orderings**: GROUP BY キーの再順序付けの可能性を評価し、インクリメンタルソート等の最適化候補を生成する。
  • **get_cheapest_path_for_pathkeys / get_cheapest_fractional_path_for_pathkeys**: 指定されたパスキーとパラメータ制約を満たす最安パスを探索する。

制御フローとデータフロー

1. **正規化の保証**: プランナは等価クラスのマージ完了後、全ての PathKey を make_canonical_pathkey 経由で生成する。これにより、PathKey 同士の比較は単なるポインタ比較 (pathkey1 == pathkey2) で行える。 2. **インデックス・パーティションからの生成フロー**:

  • build_index_pathkeys や build_partition_pathkeys は、キー列を走査しながら make_pathkey_from_sortinfo で各列の PathKey を生成する。
  • pathkey_is_redundant により既知の冗長キーや定数化されたキーを即座に除外する。

    • 3. **結合時のマージ句対応フロー**:

  • find_mergeclauses_for_outer_pathkeys は外側パスのパスキー順序に従って一致するマージ制限条項（RestrictInfo）を収集する。
  • make_inner_pathkeys_for_merge はそれらのマージ句と外側パスキーから内側リレーションが満たすべきパスキーリストを決定する。

    • 4. **プルーニング（トリミング）**:

  • パスが生成されるたび truncate_useless_pathkeys が呼ばれ、root->sort_pathkeys や root->group_pathkeys などの大域的な要求に寄与しない余分な末尾の PathKey は捨てられ、無駄なパス異体字の爆発を防ぐ。

読者向けメモ

  • **ポインタ比較の前提**: 正規化された PathKey はクエリのプランニングコンテキスト (root->planner_cxt) に割り当てられ、同一クエリ内では一意であるため、== による高速比較が設計上の前提となっています。
  • **メモリ管理**: 生成される PathKey やリストはプランナのメモリコンテキスト上に構築され、クエリ終了時に一括解放されます。部分的な割り当て (palloc) では、select_outer_pathkeys_for_merge 内の一時配列などが適切に pfree されています。
