src/backend/optimizer/path/pathkeys.c

概要

pathkeys.c は、PostgreSQLのクエリプレナにおいて、パスのソート順序や等価性を表現・比較・構築するための中心的なユーティリティ群を提供する。同モジュールは、EquivalenceClass（等価クラス: EC）と連携しながら、インデックス、パーティション、ソート句、結合（マージ結合）などの各種処理におけるソート順序（PathKey）の整合性判定や冗長性排除、最適化を担う。

モジュール内での役割

src/backend/optimizer/path サブシステムに属し、主にコストベースオプティマイザ（CBO）が生成する Path ノード群の順序特性（pathkeys リスト）を管理する。equivclass.c で構築・統合された同値関係を基に、インデックススキャンやマージ結合、グループ化、各種順序要求（ORDER BY, GROUP BY, DISTINCT, ウィンドウ関数など）の突合や再構築を仲介する。

責務

  • **PathKey の生成と管理**: ソート情報、ソート演算子、インデックス、パーティション情報から「正規化された (canonical)」PathKey をキャッシュ・構築する。
  • **冗長性の排除**: 定数を含むクラスや既存の同値クラスと重複する PathKey を検出・排除し、無駄なソートや結合条件を削減する。
  • **PathKey の比較と包含判定**: 2つの PathKey リストの等価性や、一方が他方を包含（あるいは優位）しているかを評価する。
  • **結合およびグループ化の適応**: マージ結合の条件（左側・右側の外部/内部リレーション）や GROUP BY キーの並び順を、入力パスやクエリ要求に合わせて適応・再順序付けする。
  • **有用性評価**: 上位のプランナ要件（ORDER BY, GROUP BY, MERGEJOIN など）に照らして、パスが持つ PathKey が有用かどうかを判定し不要なキーを切り捨てる。

重要なシンボル

パスキーの比較・評価グループ

  • PATHKEYS_BETTER1, PATHKEYS_BETTER2: compare_pathkeys の結果、一方のキーリストが他方を包含しつつより長い（あるいは優位な）場合に返される比較列挙値。
  • compare_pathkeys: 2つの PathKey リストを先頭から走査し、完全一致、不一致、あるいは一方が他方を包含しているかを判定する。
  • pathkeys_contained_in: keys2 が keys1 と同等以上にソートされているかを判定する特殊ケース。
  • pathkeys_count_contained_in: 2つの PathKey リストの共通プレフィックス長を数え上げ、包含関係を同時に判定する。

パスキーの構築・正規化グループ

  • make_canonical_pathkey: 指定された等価クラス、演算子ファミリ、比較種別、Null配置に基づいて、既存の正規化済み PathKey を検索するか、新規作成して root->canon_pathkeys に登録する。
  • make_pathkey_from_sortinfo: ソート情報（式、演算子ファミリ、照合順序、逆順フラグ等）から、EquivalenceClass を経由して正規化された PathKey を生成する。
  • make_pathkey_from_sortop: 単一のソート演算子と式から特性を抽出し、make_pathkey_from_sortinfo を呼び出して PathKey を生成する。
  • append_pathkeys: target リストへ source リストの非冗長な PathKey を順次追加し、更新されたリストを返す。

グループ化および結合・外部クエリ適応グループ

  • group_keys_reorder_by_pathkeys: 入力パスの PathKey に合わせて GROUP BY キーと節を再順序付けし、一致した件数を返す。
  • get_useful_group_keys_orderings: GROUP BY キーの有用な順序付け（クエリ指定順、パス順）のリストを決定・生成する。

制御フローとデータフロー

1. **初期化と正規化**: プラン生成の過程で、各アクセスパス（インデックススキャンやパーティションスキャン）は build_index_pathkeys や build_partition_pathkeys を通じて make_pathkey_from_sortinfo を呼び出し、正規化された PathKey リストを構築する。 2. **冗長性の排除**: 新しい PathKey を追加・結合する際、pathkey_is_redundant() により、その等価クラスが定数を含むか、すでにリスト内に存在するかを確認し、冗長であれば除外する。 3. **結合処理における相互変換**:

  • マージ結合では、find_mergeclauses_for_outer_pathkeys や make_inner_pathkeys_for_merge により、外側リレーションの PathKey に合致するマージ制限条項（RestrictInfo）と内側リレーション用の PathKey を対応付ける。

    • 4. **プルーニング（不要なキーの削除）**:

  • truncate_useless_pathkeys が呼び出され、root->sort_pathkeys, root->group_pathkeys, root->mergejoins 等の要件に基づいてプレフィックスの一致度を評価し、後続の処理で不要な PathKey を切り捨てる。

読者向けメモ

  • **メモリ所有権**: すべての正規化された PathKey (PathKey) は、GEQOなどのコンテキスト切り替えに対応するため、明示的に root->planner_cxt メモリコンテキスト上に割り当てられる。
  • **不変条件 (Invariants)**: 本ファイル内の関数に渡される PathKey は、原則としてすべて「正規化済み（canonical）」であることを前提としており、等価クラスの比較はポインタ比較（==）で安全に行われる。
