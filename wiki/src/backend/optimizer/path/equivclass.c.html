src/backend/optimizer/path/equivclass.c

概要

PostgreSQLのオプティマイザにおける同値クラス（EquivalenceClass, EC）の管理、構築、導出句の生成、およびそれらの照合を行う中心的なソースファイルです。マージ結合、インデックススキャン、およびプラン作成時に必要となる式や変数の等価関係（推移律を含む）を管理し、最適化パスの探索効率と精度を支えています。

モジュール内での役割

src/backend/optimizer/path モジュールに属し、主に allpaths.c や initsplan.c などのクエリ初期化・パス生成フェーズと連携します。RestrictInfo の表現する等価条件を EquivalenceClass および EquivalenceMember (EM) 構造体へ落とし込み、ベース制約や結合制約を自動的に導出する責務を持ちます。

責務

  • **同値関係の登録・マージ**: process_equivalence により、マージ結合可能な条件を評価し、既存のECへの追加や異なるEC同士の統合（UNION-FIND的アプローチ）を行う。
  • **式と位置の正規化**: canonicalize_ec_expression を通じて、式が期待されるデータ型や照合順序（collation）を正しく暴露するように調整する。
  • **派生等価句の生成**:
  • ベース関係向けの制限句生成（定数含む、または含まないケース）。
  • 結合関係向けの等価句（generate_join_implied_equalities）の動的生成。
  • **検索と照合**:
  • ソート式、関数、インデックス列、外部キー列に対する等価メンバーの探索 (get_eclass_for_sort_expr, find_computable_ec_member, match_eclasses_to_foreign_key_col)。
  • 派生句の効率的なルックアップのためのハッシュテーブル管理（simplehash.h を用いた ec_derives_hash と閾値制御）。
  • **外部結合の再考慮**: reconsider_outer_join_clauses により、左・右・完全外部結合で留保された条件から定数伝播などの推論を行う。

重要なシンボル

  • **データ構造**
  • ECDerivesKey: 派生句を特定するためのハッシュキー構造体（em1, em2, parent_ec）。
  • ECDerivesEntry: ec_derives_hash で使用されるハッシュテーブルエントリ。
  • **主要な公開関数**
  • process_equivalence: 等価条件をECに登録・マージするエントリポイント。
  • canonicalize_ec_expression: 式の型と照合順序を正規化する。
  • get_eclass_for_sort_expr: ソート式に対応するECを検索、または必要に応じて新規作成する。
  • find_computable_ec_member: 指定された式（Vars等）から計算可能なECメンバーを探索する。
  • generate_base_implied_equalities: ベース関係から導出される制約句を生成する。
  • generate_join_implied_equalities: 結合ノードで必要な等価結合句を生成する。
  • reconsider_outer_join_clauses: 外部結合の除外条件から定数伝播や等価関係を再評価する。
  • setup_eclass_member_iterator / eclass_member_iterator_next: 親メンバーおよび子メンバー（AppendRel等）を横断するためのイテレータ。

制御フローとデータフロー

1. **初期登録フェーズ (process_equivalence)**:

  • クエリ内の結合条件（RestrictInfo）から左辺・右辺の式と型、演算子ファミリ、照合順序を抽出。
  • 既存の root->eq_classes を走査し、一致するECがないか探索。
  • 両方既存なら何もしないか、別々であればECをマージ。片方のみならメンバーを追加。どちらもなければ新規ECを作成。

    • 2. **ベース制約導出フェーズ (generate_base_implied_equalities)**:

  • プランナがパス探索を開始する直前に呼び出される (root->ec_merging_done = true)。
  • ECに定数が含まれる場合は generate_base_implied_equalities_const により「変数 = 定数」の制限句を生成。
  • 定数が含まれない場合は generate_base_implied_equalities_no_const により、同一ベースリレーション内のメンバー間で最小限の「変数 = 変数」の派生句を生成し、process_implied_equality 経由でリレーションに登録。

    • 3. **結合制約導出フェーズ (generate_join_implied_equalities)**:

  • 結合の左右の入力リレーションに含まれるEMと、新しく計算可能になるEMを識別。
  • 最適な等価演算子を選択し、create_join_clause を通じて RestrictInfo を構築して返す。多数の派生句がある場合、EC_DERIVES_HASH_THRESHOLD（32件）を超えると simplehash ベースのハッシュテーブルに切り替えて高速に重複チェック・再利用を行う。

読者向けメモ

  • **メモリ管理**: 新規作成される EquivalenceClass や EquivalenceMember、派生した RestrictInfo は通常 root->planner_cxt コンテキスト上で割り当てられます。GEQOなどの複数サイクル実行時におけるメモリリークや構造体の破損を防ぐため、コンテキストスイッチの規則に注意してください。
  • **不変条件 (Invariants)**:
  • ec_merging_done = true になった後は、既存の非volatileなEC同士をマージすることは禁止されます（パスキーやリレーションのインデックス破壊を防ぐため）。
  • 子メンバー (em_is_child = true) は通常の ec_members リストには直接含まれず、ec_childmembers 配列またはイテレータ経由で扱われます。
