src/backend/optimizer/path/joinrels.c

概要

src/backend/optimizer/path/joinrels.c は、PostgreSQLのクエリプレーナーにおける結合関係（RelOptInfo）の網羅的探索と構築を担当する中心的なソースファイルです。動的計画法（Dynamic Programming）によるレベルごとの結合探索を制御し、特殊結合（アウタージョイン、セミジョイン、アンチジョインなど）の適法性検証、およびパーティション分割されたリレーション同士のパーティション単位の結合（パーティションワイズ結合）の調整を行います。

モジュール内での役割

オプティマイザの path モジュール内に位置し、基本リレーションや下位の結合リレーションから、より大きな結合リレーション階層（join_rel_level）を組み立てる中核ロジックを提供します。周辺の joinpath.c（個々の結合パスの生成）や allpaths.c（パス探索全体のコーディネーション）と連携します。

責務

  • **動的計画法による結合探索**: 指定されたサイズ（level）の結合関係を網羅的に生成する（左／右側プランおよびブッシー（bushy）プランの構築）。
  • **結合の適法性検証**: クエリの結合順序制約、特殊結合（SpecialJoinInfo）、および LATERAL 参照が提案された結合を許可するかどうかを判断する。
  • **結合関係の構築と初期化**: 新規結合関係（joinrel）の検索または生成、およびダミー特殊結合情報の補完。
  • **最適化ヒューリスティックの適用**: アグリゲーションを早期に適用する eager aggregation（グループ化結合関係の構築）や、制約による定数偽（constant false）フィルターの適用。
  • **パーティションワイズ結合の調整**: パーティション構造を持つリレーション同士の結合において、一致するパーティションペアごとの子結合（child-joins）の探索と計画を統括する。

重要なシンボル

結合探索およびルート制御

  • join_search_one_level: 指定されたサイズ（level）を持つすべての結合関係を1パス分構築する。joinrels[level - 1] の要素から左／右側プラン、ブッシープラン、および最悪の場合のデカルト積（cartesian product）を試行して joinrels[level] を満たす。
  • make_rels_by_clause_joins: 結合条項や順序制約を共有する old_rel と other_rels の間で結合関係を構築する。
  • make_rels_by_clauseless_joins: 結合条件を持たない場合にデカルト積結合を生成する。

結合の適法性・制約管理

  • LATERAL: クエリツリーまたは式において先行リレーションの列を参照する LATERAL 構文の処理に絡む制御状態・参照関係を示す識別マクロ／概念。
  • SpecialJoinInfo: 特殊結合（アウター、セミ、アンチ、フル）の最小左辺・右辺および可換性、制限事項を保持する構造体定義（および関連ヘルパー）。
  • join_is_legal: 提案された2つのリレーションの結合が、SpecialJoinInfo の制約、LATERAL 参照の方向、およびパラメータ化の要件に照らして合法かを判定し、結合タイプを決定する。
  • init_dummy_sjinfo: 通常の内部結合（JOIN_INNER）に対して、選択率推定などで必要となる最低限の情報を持つダミーの SpecialJoinInfo を初期化する。
  • has_join_restriction: リレーションが結合順序制約、LATERAL 参照、あるいはマルチリレーショナルなプレースホルダー変数（PHV）に起因する制約を持つか検出する。

結合リレーション構築・パス付加

  • make_join_rel: 2つのリレーション間の結合を表す RelOptInfo を検索または構築し、有効なパス情報を付加して返す。無効な結合の場合は NULL を返す。
  • add_outer_joins_to_relids: アウタージョイン識別子（ojrelid）および外延的・内包的にプッシュダウンされたアウタージョインの relid をターゲットの Relids セットに追加する。
  • make_grouped_join_rel: アグリゲーションとグループ化が存在する場合に、早期アグリゲーション（eager aggregation）を適用したグループ化結合関係を構築する。
  • populate_joinrel_with_paths: 結合タイプ（インナー、レフト、フル、セミ、アンチなど）に応じたパスを結合リレーション（joinrel）に追加し、定数偽（constant false）の条件がある場合はダミーリレーションとしてマークする。

制御フローとデータフロー

1. **探索フェーズ開始**: allpaths.c 等から呼ばれたオプティマイザが、level ごとに join_search_one_level を呼び出し、ボトムアップの動的計画法を実行。 2. **候補ペアの評価**: 各 old_rel に対し、make_rels_by_clause_joins（結合条件あり）または make_rels_by_clauseless_joins（条件なし・デカルト積）を介して相手候補を選定。 3. **適法性チェック**: make_join_rel 内で join_is_legal を呼び出し、join_info_list 内の SpecialJoinInfo や LATERAL の依存関係、方向を検証。 4. **リレーションとパスの作成**: 適法な場合、build_join_rel で結合 RelOptInfo を取得し、make_grouped_join_rel（グループ化の考慮）および populate_joinrel_with_paths（各結合タイプのパス生成呼び出し、add_paths_to_joinrel）を実行。 5. **パーティションワイズ結合の分岐**: リレーションがパーティション化されている場合、try_partitionwise_join が呼び出され、子パーティション間の結合構造（build_child_join_rel等）へ再帰的にディスパッチされる。

読者向けメモ

  • **メモリ管理**: パーティション数が数千に及ぶパーティションワイズ結合では、ループ内で生成される一時的な AppendRelInfo や子 SpecialJoinInfo がメモリを圧迫するため、各反復の末尾で厳密な解放（pfree, bms_free, free_child_join_sjinfo）が行われています。
  • **不変条件（Invariants）**: 結合する2つのリレーション（rel1 と rel2）の relids は、ビットマップの論理積が空（重複がない）でなければなりません（Assert(!bms_overlap(rel1->relids, rel2->relids))）。
