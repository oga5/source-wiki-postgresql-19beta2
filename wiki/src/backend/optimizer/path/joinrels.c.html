src/backend/optimizer/path/joinrels.c

概要

src/backend/optimizer/path/joinrels.c は、PostgreSQLのオプティマイザにおけるジョイン探索（動的計画法によるバス・プランや左・右側プランの構築）の主要アルゴリズムを担当するソースファイルです。どのリレーション同士をどの順序で結合すべきかを決定し、結合関係（RelOptInfo）の作成、有効性検証、および通常またはパーティション分割されたジョイン（Partitionwise Join）に対するパスの追加を統括します。

モジュール内での役割

src/backend/optimizer/path モジュール内において、本ファイルは joinpath.c（個々のジョインパス評価）や allpaths.c（プラン全体のパス生成オーケストレーション）と密接に連携します。allpaths.c から呼び出される動的計画法の 1 レベル分の探索（join_search_one_level）や、結合可能なリレーション対の抽出を行い、クエリツリーの結合順序空間を網羅・枝刈りします。

責務

  • **ジョイン探索レベルの制御**: 指定されたレベルのジョイン候補ペア（左・右側プランおよびブッシュプラン、クラスレス結合）を列挙する。
  • **結合の有効性・制約検証 (join_is_legal, 制限チェック)**: 特殊結合（外結合、半結合、アンチ結合）の順序制約、LATERAL 参照、プレースホルダ変数（PHV）、および冗長な条件の矛盾（定数 FALSE や NULL）をチェックする。
  • **結合関係の生成とパスの網羅**: make_join_rel を通じてジョインリレーションを特定または構築し、外結合の種類に応じたパスや一意化パスを生成する。
  • **アグリゲーションの早期プッシュダウン (make_grouped_join_rel)**: 可能であればジョイン前の部分集約（Eager Aggregation）を適用する。
  • **パーティション分割結合 (try_partitionwise_join)**: パーティション同士の対応関係を計算し、子ジョインの生成や境界マージを行う。

重要なシンボル

1. 探索・エントリポイント関数

  • join_search_one_level(PlannerInfo *root, int level): 指定された level のジョイン関係を網羅的に探索し、root->join_rel_level[level] に格納する。

2. 結合の構築・検証ヘルパー

  • make_join_rel(PlannerInfo *root, RelOptInfo *rel1, RelOptInfo *rel2): 2つのリレーション間のジョイン関係を検索または新規構築し、パスを追加する。無効な場合は NULL を返す。
  • join_is_legal(...): クエリの結合順序制約、特殊結合の構造、および LATERAL 参照に照らして提案されたジョインが合法か判定する。
  • init_dummy_sjinfo(SpecialJoinInfo *sjinfo, Relids left_relids, Relids right_relids): 通常の内結合用にダミーの SpecialJoinInfo を初期化する。
  • add_outer_joins_to_relids(...): 外結合の結合関係（ojrelid および外結合の推移的合流）をリレーションID集合に追加する。

3. グループ化・パス移譲

  • make_grouped_join_rel(...): 部分集約が適用可能な場合にグループ化されたジョイン関係を構築・管理する。
  • populate_joinrel_with_paths(...): ジョイン種別（INNER, LEFT, FULL, SEMI, ANTI）に応じて適切なパスを add_paths_to_joinrel 経由で追加する。

4. パーティション分割結合 (Partitionwise Join)

  • try_partitionwise_join(...): パーティション同士の結合が可能か評価し、子ジョインリレーション群とそのパスを生成する。
  • compute_partition_bounds(...): 入力リレーションのパーティション境界をマージ、または比較して一致を確認する。
  • get_matching_part_pairs(...): 結合セグメントに対応する子リレーションのペアを生成する。

5. 制限・検証判定

  • have_join_order_restriction(...): 特殊結合や LATERAL 参照を満足するための結合順序上の制約があるか検出する。
  • has_join_restriction(PlannerInfo *root, RelOptInfo *rel): 指定リレーションが外部結合や LATERAL に絡む結合制限を持っているか判定する。
  • is_dummy_rel(RelOptInfo *rel) / mark_dummy_rel(RelOptInfo *rel): リレーションが空（データ無し）であることの判定およびマーク。
  • restriction_is_constant_false(...): 制限リスト内に定数 FALSE や NULL が含まれているかを検出し、無駄な結合探索をショートカットする。

制御フローとデータフロー

1. **レベル単位の駆動**: allpaths.c から join_search_one_level(root, level) が呼ばれる。 2. **ペアの列挙**:

  • レベル $k-1$ のリレーションと初期リレーション（レベル1）の結合を make_rels_by_clause_joins（結合句がある場合）または make_rels_by_clauseless_joins（デカルト積が必要な場合）で試行する。
  • レベル 2 以上のブッシュプラン（$k$ と level - k の結合）を have_relevant_joinclause / have_join_order_restriction に基づいて試行する。

    • 3. **合法性チェック (make_join_rel 内)**:

  • join_is_legal により、root->join_info_list 内の SpecialJoinInfo や LATERAL 参照との整合性を検証する。
  • 不適合であれば NULL を返却して破棄する。

    • 4. **関係・パスの生成**:

  • build_join_rel で RelOptInfo を取得・構築。
  • make_grouped_join_rel で集約の早期適用を試みる。
  • populate_joinrel_with_paths が sjinfo->jointype をスイッチ文で評価し、add_paths_to_joinrel を呼び出して具体的な物理パス（NestLoop, HashJoin, MergeJoin 等）を構築。
  • 必要に応じて try_partitionwise_join を呼び出し、パーティション単位の子ジョインを再帰的に処理する。

読者向けメモ

  • **メモリ管理**: パーティション数が数千に及ぶ場合、ループ内でアロケートされる appinfos などの動的メモリは各イテレーションの終わりに明示的に解放（pfree）され、メモリリークや肥大化を防いでいる。
  • **不変条件 (Invariants)**: 結合対象の2つのリレーションの relids は互いに素（オーバーラップしない）でなければならず、コード冒頭の Assert(!bms_overlap(rel1->relids, rel2->relids)) で厳格に保証されている。
