src/backend/optimizer/plan/planner.c

概要

src/backend/optimizer/plan/planner.c は、PostgreSQLクエリ最適化器（オプティマイザ）の外部インターフェースおよび上位クエリ処理の主制御部です。パーサーから渡された解析済みの Query ツリーを受け取り、大域的状態の初期化、サブクエリの計画化、グループ化・集約・ウィンドウ関数・DISTINCT・ORDER BYなどの上位階層のパス生成、そして最終的な実行計画 (PlannedStmt) への変換を調整します。

モジュール内での役割

src/backend/optimizer/plan モジュール内において、本ファイルはクエリ全体のライフサイクルを統括する中核です。下位の探索エンジン（query_planner など）や物理計画生成部（create_plan.c, setrefs.c）と密に連携し、SQLの論理構造から実行パスを構築するオーケストレータとして機能します。

責務

  • **外部インターフェース**: planner() および standard_planner() を通じて、オプティマイザの主要なエントリポイントを提供する。
  • **プラグインフック管理**: planner_hook、planner_setup_hook、planner_shutdown_hook、create_upper_paths_hook を介したサードパーティ製プラグインによるプラン生成への介入点を提供する。
  • **大域的・局所的コンテキストの構築**: PlannerGlobal の初期化、並列クエリ可否の判定（max_parallel_hazard）、カーソル用タプル分画（cursor_tuple_fraction）の調整を行う。
  • **式の前処理 (Preprocessing)**: ターゲットリスト、WHERE句、HAVING句、ウィンドウ句などの式評価前処理、定数畳み込み、SubLinkからSubPlanへの変換（preprocess_expression）を行う。
  • **上位関係 (Upper Rel) のパス生成**:
  • グループ化および集約（create_grouping_paths, create_ordinary_grouping_paths, create_partitionwise_grouping_paths）
  • ウィンドウ関数（create_window_paths）
  • DISTINCT（create_distinct_paths）
  • ORDER BY（create_ordered_paths）
  • **ユーティリティ処理**: CLUSTER のソート適性判定（plan_cluster_use_sort）や、インデックス作成時の並列ワーカー数決定（plan_create_index_workers）を支援する。

重要的シンボル

エントリポイント・フック

  • planner(): プラグインフックを考慮したオプティマイザの最上位入口。
  • standard_planner(): 標準の計画生成処理を実行し、PlannerGlobal を管理して PlannedStmt を構築する。
  • subquery_planner(): サブクエリ、CTE、リライト処理、式の前処理、および grouping_planner の呼び出しを行う。
  • planner_hook, planner_setup_hook, planner_shutdown_hook, create_upper_paths_hook: プラグイン拡張用フック変数。

上位パス生成・グループ化関連

  • grouping_planner(): スキャン／結合パスの上にグループ化、ウィンドウ、DISTINCT、ソート、LIMIT、ModifyTable等の処理を積み上げる。
  • create_grouping_paths(): 集約・グループ化を行うためのupperrelパス群を構築する。
  • consider_groupingsets_paths(): グルーピングセットに対するソート・ハッシュ混在パスを検討・生成する。
  • create_window_paths() / create_one_window_path(): ウィンドウ関数評価のためのパス群を構築する。
  • create_distinct_paths() / create_final_distinct_paths() / create_partial_distinct_paths(): DISTINCT のソート／ハッシュベースのパスを構築する。
  • create_ordered_paths(): ORDER BY のソートおよびインクリメンタルソートパスを構築する。

前処理・補助関数

  • preprocess_expression(): 式の種類（EXPRKIND_QUAL, EXPRKIND_TARGET 等）に応じた定数畳み込み、SubLink展開、相関変数置換を行う。
  • preprocess_grouping_sets() / extract_rollup_sets(): グルーピングセットの構造を解析し、二部グラフ最大マッチング（BipartiteMatch）を用いて最小のロールアップチェーンに分解する。
  • make_group_input_target() / make_window_input_target() / make_sort_input_target(): 各ステップの入力に必要な PathTarget を生成・最適化する。

制御フローとデータフロー

1. **初期化**: planner() が呼ばれると、プラグインフックを確認後 standard_planner() に委譲する。standard_planner() は PlannerGlobal を確保し、並列実行の安全性（max_parallel_hazard）やタプル分画率を決定する。 2. **サブクエリ・式の前処理**: subquery_planner() によりCTEやJOINの展開、SubLinkからSubPlanへの変換が行われ、preprocess_expression() で式が正規化・定数畳み込みされる。 3. **スキャン／結合の計画**: query_planner() が呼び出され、FROM/WHERE句に基づくベースラインのアクセスパス（RelOptInfo）が生成される。 4. **上位リレーションの構築 (Grouping/Window/Distinct/Order)**: grouping_planner() が順次上位の RelOptInfo（UPPERREL_GROUP_AGG, UPPERREL_WINDOW, UPPERREL_DISTINCT, UPPERREL_ORDERED, UPPERREL_FINAL）を作成し、それぞれの最適パス（ソート、ハッシュ、インクリメンタルソート、部分集約など）を追加する。 5. **最終計画への変換**: 最安パス（cheapest_total_path）に対し、必要に応じて LockRows、Limit、ModifyTable ノードを重ね合わせ、create_plan() で物理プラン木（Plan）へ変換する。最後に set_plan_references() で参照関係を解決し PlannedStmt を返す。

読者向けメモ

  • **メモリ管理**: クエリ最適化中のデータ構造は、通常 PlannerInfo が持つメモリコンテキスト（CurrentMemoryContext）上で割り当てられ、クエリ終了時に一括解放される。GEQOなど特例のコンテキスト切替え箇所では明示的な制御が行われる。
  • **副作用**: standard_planner() および関連する前処理関数は渡された Query ツリーの一部を直接書き換える（インプレース変更）ため、プラグインなどで同一のクエリを複数回計画する場合は Query ツリーのコピーが必要となる。
