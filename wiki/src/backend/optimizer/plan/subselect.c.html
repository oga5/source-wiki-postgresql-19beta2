src/backend/optimizer/plan/subselect.c

概要

src/backend/optimizer/plan/subselect.c は、PostgreSQLのクエリ最適化フェーズにおいて、サブリンク（SubLink）、共通テーブル式（CTE）、および相関参照を計画ノードやサブプラン（SubPlan / InitPlan）へ変換・統合する処理を所有するコアファイルである。サブクエリ（FROM 句内のサブSELECT）自体の処理は扱わず、式や句の中に埋め込まれた副問い合わせや結合変換、さらに完了した実行計画に対するパラメータ依存関係の最終確定（extParam / allParam の計算）を担う。

モジュール内での役割

src/backend/optimizer/plan モジュール内において、本書で扱う subselect.c は、パーサが生成した SubLink や CommonTableExpr を具体的なプラン構造へブリッジする。planner.c や createplan.c が全体の最適化を進める中で、サブクエリのインライン化、結合への変換（Semi/Anti Join）、および InitPlan のコスト評価と結合を担当し、最終段階では setrefs.c などに渡すためのパラメータ汚染・スコープ検証を行う。

責務

  • **サブリンクの処理とサブプラン構築**: SubLink ノードを解析し、subquery_planner を用いて副問い合わせを計画化した上で SubPlan または InitPlan ノードを生成する。
  • **結合変換 (Sublink-to-Join)**: EXISTS や ANY のサブリンクを、セマンティクスが一致する場合に JOIN_SEMI や JOIN_ANTI の JoinExpr へ引き上げる（プルアップ）。
  • **CTE 処理とインライン化**: WITH 句（CTE）の参照カウンタや副作用・再帰性を評価し、単一参照や非同期・非修飾クエリのインライン化（RTE_SUBQUERY への変換）または初期化計画（InitPlan）への変換を行う。
  • **相関変数とパラメータの置換**: 上位レベルへの参照（uplevel var, PlaceHolderVar, Aggref など）をパラメータ（PARAM_EXEC 等）に置換する。
  • **プラン最終化 (Plan Finalization)**: 完成したプランツリーを再帰的に走査し、各ノードが参照する外部パラメータ（extParam）およびすべてのパラメータ集合（allParam）を確定・検証する。

重要なシンボル

コントテキスト構造体

  • struct convert_testexpr_context: テスト式内の PARAM_SUBLINK を対応するサブクエリ出力の Param または Var に置換するための mutator コンテキスト。
  • struct process_sublinks_context: 表現木を走査して SubLink を見つけ、トップレベルの修飾（qual）であるかどうか（isTopQual）を伝播させながらサブプランに置き換えるためのコンテキスト。
  • struct finalize_primnode_context: プラン木のプライマリノード（ターゲットリストや修飾式）を走査し、非ローカルな PARAM_EXEC の paramid をビットマップに収集するコンテキスト。
  • struct inline_cte_walker_context: 指定された CTE 名とネスティングレベルに基づき、RTE_CTE を RTE_SUBQUERY にインライン化するための走査コンテキスト。

主要関数

  • function SS_process_ctes: クエリの WITH リスト（cteList）を走査し、未使用 CTE の無視、条件に応じたインライン化、あるいは独立した InitPlan への変換（cte_plan_ids の構築）を統括するエントリポイント。
  • function SS_replace_correlation_vars: 式木内の上位レベル変数（Var, PlaceHolderVar, Aggref, GroupingFunc, ReturningExpr）を対応する実行時パラメータに置換する。
  • function SS_process_sublinks: 式木内の SubLink を検出し、make_subplan を呼び出して SubPlan / InitPlan に変換する起点となるエントリポイント。
  • function SS_identify_outer_params: 上位クエリレベルから渡されるパラメータ群（plan_params、上位の init_plans の出力、再帰クエリの worktable ID）を集約し、root->outer_params に記録する。
  • function PARAM_EXEC: subselect.c 内の式やプランで実行時パラメータの種別（paramkind == PARAM_EXEC）として頻繁に参照・生成される定数・概念。
  • function PARAM_SUBLINK: パーサが生成した段階のサブリンク用パラメータ種別であり、convert_testexpr 等によって一意な PARAM_EXEC や Var に置換される。
  • function InitPlan: サブプランのうちクエリ開始時（あるいはパラメータ変更時）に一度だけ（または必要に応じて）評価され、上位プランに結果を提供する初期化計画としての SubPlan の属性・分類。
  • function Path / function Plan / function SubPlan / function AlternativeSubPlan: サブクエリの経路（Path）、実行計画（Plan）、それを埋め込む SubPlan、およびハッシュプラン等の複数の実行方式を動的に切り替えるためのラッパー構造体。
  • function RTE_SUBQUERY / function VALUES / function WITH / function DISTINCT / function LIMIT / function EXISTS / function ANY / function ScalarArrayOpExpr / function Param / function Var / function allParam / function extParam: サブセレクト最適化の各過程（インライン化、ハッシュ化、結合変換、パラメータ集合計算）で扱われるノードおよび属性。

制御フローとデータフロー

1. **プロセス開始**: planner() から呼ばれる過程で、まず SS_process_ctes() が実行され、WITH 句の各 CTE がインライン化可能か検証されるか、subquery_planner によってサブプランへと変換される。 2. **サブリンクの処理**: クエリの WHERE 句やターゲットリストの解析中に SS_process_sublinks() が呼び出され、式木を再帰的に走査して SubLink ノードに到達する。 3. **プラン生成**: make_subplan() はサブリンク内の Query を取り出して subquery_planner に渡し、得られた最良の Path を create_plan() で Plan に変換する。相関パラメータがある場合は args および parParam に結び付けられる。条件を満たす場合はハッシュテーブルの利用（useHashTable）や Material ノードの付加が行われる。 4. **結合変換の試行**: convert_ANY_sublink_to_join や convert_EXISTS_sublink_to_join により、条件が揃った EXISTS や IN (ANY) はセミ結合（JOIN_SEMI）やアンチ結合（JOIN_ANTI）の JoinExpr に変換され、オプティマイザのジョイントリーに組み込まれる。 5. **最終化 (Finalization)**: クエリ最適化の終盤で SS_finalize_plan() が呼び出され、finalize_plan() がプランツリーを再帰走査。各ノードが参照する PARAM_EXEC のIDを収集し、extParam と allParam のビットマップを構築・検証してスコープ違反がないことを確認する。

読者向けメモ

  • **メモリ管理**: クエリツリーやプラン構造体の複製には copyObject() が多用される。パーサが生成した共有クエリノードをプランナが破壊的に書き換えないようにするため、必要に応じてディープコピーが行われる点に注意。
  • **不変条件 (Invariants)**: 相関変数やパラメータのレベルサップ（varlevelsup, phlevelsup 等）は、SS_replace_correlation_vars や SS_process_sublinks の厳密な実行順序に依存している。順序を誤ると上位レベルへの参照解決が崩れ、実行時エラーや不正なパラメータIDに繋がる。
