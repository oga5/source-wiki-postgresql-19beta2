src/backend/optimizer/plan/createplan.c

概要

クエリの最適化フェーズにおいて選択された最適な Path ツリーを、実際の実行エンジンが処理可能な Plan ツリーへ変換するルーチン群を提供します。

モジュール内での役割

src/backend/optimizer/plan サブシステムの一部であり、オプティマイザのコストベース選択（planner.c や各種パス生成）と、最終的な実行用ツリーの参照解決・最適化（setrefs.c）の間に位置します。

責務

  • **プラン再帰的生成**: Path ノードのタグを判定し、対応する Plan ノードをボトムアップまたはトップダウン的に構築する。
  • **ターゲットリスト（tlist）の管理**: 必要な列のみを伝播させる最適化や、CP_EXACT_TLIST・CP_SMALL_TLIST・CP_LABEL_TLIST・CP_IGNORE_TLIST フラグを通じた射影要件の伝達。
  • **スキャン・結合・修飾の統合**: 各種ベーススキャン、結合（Nested Loop, Merge Join, Hash Join）、集約、ソートなどのプランノードへの変換と、擬似定数（pseudoconstant）条件に対するゲーティング（Gating）Result ノードの挿入。
  • **インデックスおよびネストループパラメータの解決**: インデックス参照変数の置換や、ラテラル結合・ネストループ用の Param 割り当て。

重要なシンボル

エントリポイントとトップレベル制御

  • function create_plan: クエリ全体に対するプラン生成のエントリポイント。root->plan_params の初期化、最上位での apply_tlist_labeling や SS_attach_initplans の適用を行う。
  • function create_plan_recurse: best_path->pathtype に応じて適切なプラン生成関数へディスパッチする再帰関数。

結合プラン生成

  • function HashJoin: HashPath から HashJoin プランノードを構築する関数。
  • function MergeJoin: MergePath から MergeJoin プランノードを構築する関数。
  • function NestLoop: NestPath から NestLoop プランノードを構築する関数。

基本スキャンおよび補助プラン

  • function Hash: HashJoin の内側用ハッシュテーブル構築プランノードを生成する。
  • function Sort: ソート処理を行う Sort プランノードを構築・調整する。
  • function Result: 射影や単一ローの返却、ゲーティング条件の評価を行う Result ノードを作成する。
  • struct QualItem: order_qual_clauses 内で修飾句の評価コストやセキュリティレベルを保持するために用いる内部構造体。

変数および参照解決

  • function Var: クエリツリー内の変数ノードを表す。
  • function Param: 実行時に渡されるパラメータノード。
  • function PlaceHolderVar: 結合の過程で保持されるプレースホルダ変数。
  • function INDEX_VAR: インデックススキャン時における特殊な varno 識別子。
  • function SS_attach_initplans: クエリレベルで生成された InitPlan を最上位プランノードにアタッチする。

制御フローとデータフロー

1. **初期化**: create_plan が呼び出され、root->curOuterRels や root->curOuterParams を初期化した上で create_plan_recurse を CP_EXACT_TLIST フラグ付きで起動します。 2. **再帰的ディスパッチ**: create_plan_recurse は best_path->pathtype（スキャン、結合、集約など）をスイッチ文で評価し、対応する create_xxx_plan ヘルパーへ処理を委譲します。 3. **ターゲットリストと制約の伝播**:

  • スキャン系では use_physical_tlist により物理タプル構造をそのまま返すか、build_path_tlist で必要な式を組み立てます。
  • 結合やソート、ウィンドウ関数などの親ノードは、必要に応じて CP_SMALL_TLIST や CP_LABEL_TLIST などのフラグを子へ伝えます。

    • 4. **パラメータと修飾句の調整**: replace_nestloop_params や fix_indexqual_references により、外部リレーションの変数やインデックス列の参照位置が実行時パラメータや INDEX_VAR に書き換えられます。 5. **最終仕上げ**: 最上位に到達したプランに対して apply_tlist_labeling や SS_attach_initplans が適用され、実行エンジンへ引き渡される Plan ツリーが完成します。

読者向けメモ

  • **メモリ管理**: 本ファイル内の構築関数は基本的に現在のメモリコンテキスト（CurrentMemoryContext）上で palloc を使用してメモリを割り当てます。生存期間はプランニングフェーズ全体に依存します。
  • **未解決のインデックス参照**: ここで生成されるツリー時点では、変数はパーサ番号のまま残されており、実際の実行前に関係番号のオフセットや参照解決が setrefs.c によって行われます。
