src/backend/optimizer/plan/planmain.c

概要

planmain.c は、PostgreSQLのクエリ最適化フェーズにおいて、基本的な結合（Join）および単一リレーションに対するパス生成の中心的な処理を行うソースファイルです。サブクエリ、継承、集約、グループ化などの複雑な上位機能を除外したコアのクエリプランニングを担当します。

モジュール内での役割

src/backend/optimizer/plan モジュール（オプティマイザのプラン構築フェーズ）に属しています。

  • 親エントリポイントである planner.c から呼び出され、結合木をもとに RelOptInfo やパスを構築します。
  • 実際のベースリレーションの追加、ジョインツリーの分解、等価クラス（Equivalence Classes）の統合といった下位モジュール群（initsplan.c や pathnode.h 等）の処理を統合するハブとして機能します。

責務

  • プランナー関連のリストや構造体(PlannerInfo)の初期化。
  • RTE_RESULT などの極めてシンプルなクエリケースの最適化バイパス処理。
  • ベースリレーションの構築、ターゲットリストの設定、プレースホルダーおよびラテラル参照の解決。
  • 外部結合の再考、等価クラスに基づく制限条項の生成、および不要な結合の削除。
  • 最終的な結合リレーションを構築するための make_one_rel の呼び出しと結果の検証。

重要なシンボル

  • query_planner: 基本クエリに対するパス（簡易プラン）を生成するトップレベル関数。結合対象のトップレベル RelOptInfo を返す。
  • query_pathkeys_callback: クエリの出力順序（Pathkeys）を計算するためのコールバック関数型。

制御フローとデータフロー

1. **初期化**: PlannerInfo の各種結合リストやハッシュテーブルを空に初期化し、setup_simple_rel_arrays でベースリレーション用配列をセットアップします。 2. **高速パス（RTE_RESULT）**: ジョインツリーが単一の RTE_RESULT リレーション（SELECT 2+2 や INSERT ... VALUES() など）の場合、結合処理をバイパスして自前の Result パスと単一の RelOptInfo を直ちに生成してリターンします。 3. **メタデータ構築**:

  • add_base_rels_to_query でジョインツリーからベースリレーションを収集します。
  • build_base_rel_tlists と deconstruct_jointree により変数や結合リストを構築します。

    • 4. **等価クラスと最適化**:

  • reconsider_outer_join_clauses や generate_base_implied_equalities で等価クラスを構築・拡張し、コールバック経由で query_pathkeys を確定させます。
  • remove_useless_joins や reduce_unique_semijoins により、不要な結合やセミジョインを削減します。

    • 5. **最終結合パス生成**:

  • add_other_rels_to_query でパーティション等の子リレーション（otherrels）を展開します。
  • make_one_rel(root, joinlist) を呼び出し、最終的な結合リレーションと最適なパスを求めて返します。

読者向けメモ

  • ファイル名からオプティマイザ全体のトップレベルエントリーポイントと誤認されやすいですが、上位の統括は planner.c が行い、このファイルは純粋な基本結合・単一クエリの計画に特化しています。
  • qp_callback は等価クラスの統合が完了して正規化されたパスキー（query_pathkeys）を安全に計算するために遅延実行されます。
