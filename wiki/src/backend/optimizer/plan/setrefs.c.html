src/backend/optimizer/plan/setrefs.c

概要

src/backend/optimizer/plan/setrefs.c は、PostgreSQLのクエリプランナーにおける最終処理パス（Post-processing pass）を実装するソースファイルです。構築が完了したプランツリーを受け取り、エグゼキュータ（Executor）が実行しやすいように内部表現の調整、変数参照の解決、およびプランキャッシュ無効化のための依存関係追跡を行います。

モジュール内での役割

src/backend/optimizer/plan モジュールにおいて、プラン生成フェーズ（createplan.c など）で作成された抽象的なプランツリーを、実際の実行エンジンが解釈可能な物理的表現へと変換する最終関門として機能します。特に、複数レベルのサブクエリにまたがる変数（Var）参照の再番号付けや、不要になったプランノード（SubqueryScan、Append、MergeAppend など）の除去（Elision）を担います。

責務

役割グループごとに整理した主な責務は以下の通りです。

1. レンジテーブルの平坦化と最適化

  • **グローバルレンジテーブルの構築**: 階層化されたサブクエリのレンジテーブル（RTE）を単一のグローバルなリスト（glob->finalrtable）に統合します。
  • **不要な構造のパージ**: エグゼキュータでのメモリ節約とキャッシュプランのコピーコスト削減のため、平坦化されたRTEから実行に不要なフィールド（subquery、joinaliasvars、securityQuals など）を NULL または NIL にクリアします。
  • **未計画サブクエリの処理**: 実行時の権限チェック漏れを防ぐため、制約除外などにより計画されなかったサブクエリからもRTEを抽出して平坦化リストに追加します。

2. 変数参照（Var）の解決と書き換え

  • **スキャンノードの調整**: スキャンノード内の Var の varno に、平坦化後のレンジテーブルにおけるオフセット（rtoffset）を加算します。
  • **結合・上位ノードの調整**: 結合ノード（Join）や上位ノード（Agg、Group、Result など）の式に含まれる Var や PlaceHolderVar を、子プランのターゲットリスト（tlist）内の位置に対応する OUTER_VAR、INNER_VAR、または INDEX_VAR に置換します。
  • **インデックスオンリースキャンの変換**: IndexOnlyScan において、ヒープを参照する Var をインデックス列を参照する INDEX_VAR に変換します。

3. 不要なプランノードの削除（Elision）

  • **トリヴィアルなSubqueryScanの削除**: 独自のフィルタ（qual）を持たず、ターゲットリストが単に子ノードの出力をそのまま通すだけの SubqueryScan を削除し、子プランを直接引き上げます。
  • **単一子ノードのAppend/MergeAppendの削除**: 子プランが1つだけで、並列実行属性が一致する Append や MergeAppend ノードを安全に剥ぎ取ります。
  • **コンテキストの引き継ぎ**: 削除された親ノードの initPlan やターゲットリストのラベル情報を子プランにマージし、削除されたノード情報（ElidedNode）をグローバル状態に記録します。

4. 式およびメタデータの解決

  • **演算子・関数のOID解決**: OpExpr や FuncExpr などの演算子・関数に対して、実行時に必要な regproc（関数OID）をルックアップして設定します。
  • **AlternativeSubPlanの選択**: 見積もり評価回数（num_exec）に基づいて最適な代替プランを選択し、不要な代替プランを NULL 化します。
  • **PARAM_MULTIEXPRの置換**: PARAM_MULTIEXPR パラメータを、対応する実行用パラメータ（PARAM_EXEC）に置換します。

5. クエリ依存関係の追跡

  • **キャッシュ無効化アイテムの収集**: プランが依存するリレーションOID（relationOids）や、ユーザー定義関数・ドメインなどのキャッシュ無効化アイテム（PlanInvalItem）を収集し、プランキャッシュ機構（plancache.c）に提供します。

重要なシンボル

エントリポイント

  • set_plan_references(PlannerInfo *root, Plan *plan): プランツリー全体の参照解決と後処理を行う最高位のエントリポイント。
  • extract_query_dependencies(Node *query, List **relationOids, List **invalItems, bool *hasRowSecurity): 未計画のクエリから依存関係を抽出する外部向けユーティリティ。

プランノード処理（再帰走査とディスパッチ）

  • set_plan_refs(PlannerInfo *root, Plan *plan, int rtoffset): プランノードの型に応じて分岐し、再帰的に参照解決を行う中心的な内部関数。
  • set_indexonlyscan_references(PlannerInfo *root, IndexOnlyScan *plan, int rtoffset): IndexOnlyScan 用の特殊な参照解決。
  • set_subqueryscan_references(PlannerInfo *root, SubqueryScan *plan, int rtoffset): SubqueryScan の処理と、トリヴィアルな場合の削除。
  • set_append_references(PlannerInfo *root, Append *aplan, int rtoffset) / set_mergeappend_references(PlannerInfo *root, MergeAppend *mplan, int rtoffset): Append / MergeAppend の処理と、単一子ノード時の削除。
  • set_join_references(PlannerInfo *root, Join *join, int rtoffset): 結合ノードの変数参照を OUTER_VAR / INNER_VAR に書き換える。
  • set_upper_references(PlannerInfo *root, Plan *plan, int rtoffset): 上位ノード（Agg、Group など）の変数参照を OUTER_VAR に書き換える。

式書き換えとコンテキスト

  • fix_scan_expr(PlannerInfo *root, Node *node, int rtoffset, double num_exec): スキャンレベルの式を書き換える。
  • fix_join_expr(...) / fix_upper_expr(...): 結合および上位ノード用の式書き換え。
  • fix_scan_expr_context / fix_join_expr_context / fix_upper_expr_context (struct): 式走査時に引き回されるコンテキスト構造体。
  • NullingRelsMatch (enum): varnullingrels の一致条件（NRM_EQUAL、NRM_SUBSET、NRM_SUPERSET）を制御する。

ターゲットリストのインデックス化と検索

  • indexed_tlist (struct): ターゲットリスト内の Var を高速に検索するためのインデックス構造体。
  • build_tlist_index(List *tlist): indexed_tlist を構築する。
  • search_indexed_tlist_for_var(...): インデックス化されたターゲットリストから特定の Var を検索し、書き換えた Var を返す。
  • search_indexed_tlist_for_phv(...) / search_indexed_tlist_for_non_var(...): PlaceHolderVar や非 Var 式の検索。

依存関係管理

  • record_plan_function_dependency(PlannerInfo *root, Oid funcid): 関数への依存関係を glob->invalItems に記録する。
  • record_plan_type_dependency(PlannerInfo *root, Oid typid): 型（ドメイン）への依存関係を記録する。

制御フローとデータフロー

1. グローバルレンジテーブルの構築

set_plan_references が呼び出されると、まず add_rtes_to_flat_rtable を実行し、現在のクエリレベルおよび再帰的にサブクエリレベルから RangeTblEntry (RTE) を収集します。

  • 各 RTE は add_rte_to_flat_rtable でコピーされ、不要なフィールドがクリアされた上で glob->finalrtable に追加されます。
  • リレーション RTE の場合、その OID が glob->relationOids に追加され、RT インデックスが glob->allRelids に記録されます。
  • root->rowMarks や root->append_rel_list の RT インデックスも、現在の finalrtable の長さをベースとした rtoffset を用いて調整されます。

2. プランツリーの再帰的走査

set_plan_refs がプランノードを再帰的に走査します。

  • 各プランノードに一意の plan_node_id を割り当てます。
  • ノードのタイプに応じて、ターゲットリストや qual などの式を書き換えます。
  • **スキャンノード**: fix_scan_list（fix_scan_expr のマクロ）を呼び出し、Var の varno に rtoffset を加算します。
  • **結合ノード**: 左右の子プランのターゲットリストから build_tlist_index で indexed_tlist を作成し、fix_join_expr を用いて式中の Var を OUTER_VAR または INNER_VAR に書き換えます。
  • **上位ノード**: 子プランのターゲットリストから indexed_tlist を作成し、fix_upper_expr を用いて Var を OUTER_VAR に書き換える。
  • 式の書き換え中、fix_expr_common が呼び出され、演算子の opfuncid 設定や、関数・型・regclass 定数の依存関係が glob->relationOids や glob->invalItems に記録されます。
  • 最後に、子プラン（lefttree、righttree）に対して再帰的に set_plan_refs を呼び出します。
  • **重要**: 子プランの再帰処理は、現在のノードの式書き換えの*後*に行われます。これは、ボトムアップで書き換えてしまうと、親ノードが子ノードの元のターゲットリストとマッチングできなくなるためです。

3. 不要ノードの削除と引き上げ

  • SubqueryScan の処理中、trivial_subqueryscan が true を返した場合、clean_up_removed_plan_level を呼び出して SubqueryScan ノード自体を削除し、その subplan を直接返します。
  • Append や MergeAppend も、子が1つだけで並列実行属性が一致する場合、同様に削除されて子が直接引き上げられます。
  • 引き上げの際、削除された親ノードの initPlan やターゲットリストのラベル情報（apply_tlist_labeling）が子ノードにマージされます。また、削除された情報は record_elided_node を通じて glob->elidedNodes に記録されます。

読者向けメモ

メモリ管理と破壊的変更

  • **プランノード**: インプレース（破壊的）に修正されます。これは、プランナーによって新規作成されたノードであり、他から多重参照されていないことが保証されているためです。
  • **式ツリー**: ターゲットリストや qual などの式ツリーは、多重参照されている可能性があるため、破壊的変更は行わず、expression_tree_mutator を用いてコピーを作成しながら変更を適用します。
  • **最適化パス**: rtoffset == 0 かつ特定の置換対象がない単純なケースでは、コピーを避けるため、インプレースで式ツリーを走査（fix_scan_expr_walker）して opfuncid のみを設定します。

不変条件と前提条件

  • set_plan_references が実行される時点では、プランツリーは完全に構築されている必要があります。
  • OUTER_VAR や INNER_VAR への書き換えは、子プランのターゲットリスト（tlist）が正しく構築されていることに依存しています。

NullingRelsMatch の役割

  • 結合におけるヌル化リレーション（varnullingrels）の導入に伴い、変数マッチング時にこれらの一致を厳密にチェックします。基本的には NRM_EQUAL（完全一致）を期待しますが、パラメータ化されたパスやアウタージョインの上位など、一部の複雑なケースでは NRM_SUBSET や NRM_SUPERSET を許容します。
