src/backend/optimizer/plan/setrefs.c

概要

setrefs.c は、PostgreSQLオプティマイザの最終段階であるプランツリーのポストプロセス（後処理）を担当するファイルです。計画作成が完了したプランツリーを受け取り、エグゼキューター（実行エンジン）が解釈しやすい形へと詳細を調整します。具体的には、サブクエリや結合をまたぐ変数（Var）の参照インデックスの変換（グローバルなレンジテーブル空間への適合や OUTER_VAR/INNER_VAR への置き換え）、演算子の実行用関数OID（regproc）の決定、プラン依存オブジェクト（リレーションや関数）の記録、不要なプランノード（冗長な SubqueryScan や Append など）の除去を行います。

モジュール内での役割

src/backend/optimizer/plan サブシステム内において、本ファイルはプラン生成のコア処理（planner.cやcreateplan.cなど）の後に位置する最終関門です。オプティマイザ内部のクエリレベル固有の変数番号（varnos）を、エグゼキューターが単一の名前空間として扱うグローバルなレンジテーブル上のインデックスへ正確にマップし直します。また、プランキャッシュが無効化されるべき条件（スキーマ変更や関数定義変更）を検出するための依存関係リストを構築します。

責務

  • **レンジテーブルの平坦化**: 複数階層のサブクエリが持つレンジテーブル（RTE）を1つのグローバルな配列に結合し、不要なサブ構造を削除してキャッシュ効率を高める。
  • **変数参照の修正**: スキャンノード、結合ノード、上位集約ノードにおける Var ノードの varno および varattno を、フラット化されたレンジテーブルまたはサブプランのターゲットリスト上の位置（OUTER_VAR, INNER_VAR, INDEX_VAR）に書き換える。
  • **演算子と関数のバインディング**: 演算子や関数呼び出しノード（OpExpr, FuncExpr, Aggref 等）に対して、実際の実行時関数OID（opfuncid 等）を付与する。
  • **プラン依存関係の追跡**: プランが依存するリレーションOIDや、ユーザー定義関数・ドメイン等のキャッシュ無効化項目（PlanInvalItem）を収集する。
  • **冗長プランノードの削除**: 実質的な処理を行わない単一子プランの SubqueryScan, Append, MergeAppend ノードを検出し、プランツリーから安全に脱落（elide）させる。

重要なシンボル

変数・マッチング・定数表現

  • enum NullingRelsMatch: 外部結合等における varnullingrels（ヌリング関係）の照合モードを規定する列挙型。NRM_EQUAL（完全一致）、NRM_SUBSET（部分集合）、NRM_SUPERSET（上位集合）を選択する。
  • function INNER_VAR, function OUTER_VAR, function NRM_EQUAL, function NRM_SUBSET, function NRM_SUPERSET: 変数参照の解決やヌリング関係の整合性検証に用いるマクロおよび列挙値。

インデックス付きターゲットリスト構造体

  • struct tlist_vinfo: ターゲットリスト中の個々の単純変数（Var）に関する位置情報（varno, varattno, resno, varnullingrels）を保持する軽量構造体。
  • struct indexed_tlist: 子プランのターゲットリストを高速に検索するためにインデックス化した構造体。フレキシブル配列 vars を持ち、PHV（PlaceHolderVar）や非変数式の有無フラグを保持する。

式変換コンテキスト構造体

  • struct fix_scan_expr_context: スキャンレベルの式ツリー走査および変換時に使用するコンテキスト（PlannerInfo *root, int rtoffset, double num_exec）。
  • struct fix_join_expr_context: 結合式や ON CONFLICT, MERGE の条件式を修正する際に、外側・内側のインデックス付きターゲットリストや許容リレーションを保持するコンテキスト。
  • struct fix_upper_expr_context: 上位プランノード（Agg, Group等）やインデックスオンリースキャンにおける式変換用のコンテキスト。
  • struct fix_windowagg_cond_context: WindowAggの実行条件（runCondition）内で WindowFunc を対応する Var に置き換えるためのコンテキスト。
  • struct flatten_rtes_walker_context: 未計画サブクエリのレンジテーブルを平坦化するウォーカー用のコンテキスト。

制御フローとデータフロー

1. **エントリーポイント (set_plan_references)**:

  • プランツリー全体のルートから呼び出され、まず add_rtes_to_flat_rtable() を実行して全サブクエリの RangeTblEntry をグローバルな root->glob->finalrtable へマージ・平坦化する。
  • PlanRowMark や AppendRelInfo のインデックスに rtoffset を加算する。
  • 再帰関数 set_plan_refs() を呼び出し、プランノードの種別ごとにターゲットリストや修飾句（qual）の参照関係を修正する。

    • 2. **ノード種別ごとの参照修正**:

  • **スキャン系**: fix_scan_list() / fix_scan_expr() を介し、ベースリレーションの scanrelid に rtoffset を加算し、式中の Var の varno をシフトする。
  • **結合系 (set_join_references)**: 左右の子プランのターゲットリストから build_tlist_index() で indexed_tlist を構築し、fix_join_expr() を用いて結合条件や出力式の Var を OUTER_VAR または INNER_VAR に置き換える。
  • **上位集約系 (set_upper_references)**: 子プランのターゲットリストをインデックス化し、fix_upper_expr() により親プランの式を子プランの出力位置（スロット番号）を参照する OUTER_VAR へ変換する。

    • 3. **不要プランのストリップ**:

  • SubqueryScan, Append, MergeAppend において、子プランが単一であり並列性等の条件を満たす場合、clean_up_removed_plan_level() を呼び出して親プランを削除し、子プランを直接引き上げる（同時に record_elided_node() でメタデータを記録）。

読者向けメモ

  • **インメモリの破壊的変更 vs コピー**: プランノード自体の構造体は原則としてインプレースで書き換えられます（一意な plan_node_id の付与やオフセットの加算など）。しかし、ターゲットリストやクオリティなどの式ツリーに対しては、安全性を考慮して expression_tree_mutator を用いたコピー＆モディファイが行われます。
  • **メモリ管理**: build_tlist_index 等で一時的に割り当てられた indexed_tlist 構造体は、各変換関数のスコープ内で使い捨てられ、処理の終了時に速やかに pfree() さえればメモリリークは発生しません。
  • **ROWID_VAR や特殊な varno**: システム列や一部の行識別子など、通常のレンジテーブルに属さない特殊な varno (ROWID_VAR 等) は通常の fix_scan_expr では例外として扱われ、必要に応じて定数への置換や個別処理が行われます。
