src/backend/optimizer/plan/analyzejoins.c

概要

analyzejoins.c は、初期クエリ解析（特に initsplan.c の完了後）の後に実行され、無駄な結合や冗長な結合を簡素化・排除するための最適化ルーチンを所有するファイルです。主に「不要な外部結合（Left Join）の削除」「一意性が証明される半結合（Semi Join）の内部結合への格下げ」「同一リレーションに対する自己結合（Self-Join）の排除（SJE）」を担当します。クエリ構造を変更した後にプランナの派生データ構造（RestrictInfo, EquivalenceClass, PlaceHolderVar, joinlist など）を整合させる複雑な後処理を受け持ちます。

モジュール内での役割

src/backend/optimizer/plan モジュール内において、このファイルはプラン作成の前段階としてクエリツリーのサイズと結合コストを削減する前処理フェーズに位置します。prep/prepjointree.c で行われる初期の結合単純化を補完し、詳細な述語・一意性情報が利用可能になった段階で高度な結合削除を行います。

責務

  • **不要な左結合の削除**: 右辺が単一のベースリレーションであり、結合条件によって高々1行しかマッチせず、かつ上流で必要とされない左結合（Left Join）を特定して削除する。
  • **一意な半結合の縮約**: 右辺リレーションが一意であると証明できる半結合（Semi Join）を通常の内部結合に格下げする。
  • **自己結合の排除（SJE）**: 同一の物理リレーションを参照する複数のベースリレーションが結合されている場合、一意性と結合条件を検証して一方を削除し、変数参照を統合する。
  • **プランナデータ構造の整合性維持**: 結合削除に伴い、PlannerInfo 内の all_baserels, all_query_rels, join_info_list, placeholder_list, eq_classes, simple_rel_array, simple_rte_array などの参照やビットマップセット（Relids）を書き換える。

重要なシンボル

グローバル変数

  • bool enable_self_join_elimination: 自己結合排除最適化を有効にするかどうかのフラグ。

主要エントリーポイント関数

  • List *remove_useless_joins(PlannerInfo *root, List *joinlist): join_info_list をスキャンし、条件を満たす不要な左結合を除去して更新された joinlist を返す。
  • void reduce_unique_semijoins(PlannerInfo *root): 右辺の一意性が証明できる半結合の SpecialJoinInfo を削除し、実質的な内部結合への縮約を行う。
  • List *remove_useless_joins(PlannerInfo *root, List *joinlist) (正確には remove_useless_self_joins): 自己結合排除のエントリーポイント。候補をソート・グループ化し、冗長な結合を排除する。

結合削除・一意性判定ヘルパー群

  • static bool join_is_removable(PlannerInfo *root, SpecialJoinInfo *sjinfo): 左結合が削除可能か（右辺の一意性、変数やPHVが上流で必要とされないか）を判定する。
  • static bool rel_supports_distinctness(PlannerInfo *root, RelOptInfo *rel): リレーションが一意性（distinctness）を持つ可能性を素早く事前チェックする。
  • static bool rel_is_distinct_for(PlannerInfo *root, RelOptInfo *rel, List *clause_list, List **extra_clauses): 指定された条件リストに基づき、リレーションが一意な行を返すか検証する。
  • static bool query_is_distinct_for(Query *query, List *distinct_cols): サブクエリ（RTE_SUBQUERY）の出力が特定の列について一意であるか検証する。
  • static bool innerrel_is_unique(PlannerInfo *root, Relids joinrelids, Relids outerrelids, RelOptInfo *innerrel, JoinType jointype, List *restrictlist, bool force_cache): 内部リレーションが一意であるかを判定し、結果をキャッシュするフロントエンド。

クエリ書き換え・構造調整ヘルパー群

  • static void remove_leftjoinrel_from_query(PlannerInfo *root, int relid, SpecialJoinInfo *sjinfo): 左結合の削除に伴うクエリおよびメタデータの更新を実行する。
  • static void remove_rel_from_query(PlannerInfo *root, int relid, int subst, SpecialJoinInfo *sjinfo, Relids joinrelids): 結合削除における共通基盤。リレーションIDの置き換えや all_baserels, placeholder_list などの調整を行う。
  • static void remove_self_join_rel(PlannerInfo *root, PlanRowMark *kmark, PlanRowMark *rmark, RelOptInfo *toKeep, RelOptInfo *toRemove, List *restrictlist): 自己結合排除において、削除対象の情報を保持対象に転写し、クエリ全体の変数参照を置き換える。
  • static bool replace_relid_callback(Node *node, ChangeVarNodes_context *context): ChangeVarNodesExtended 用のコールバック。RangeTblRef をスキップしつつ RestrictInfo 内の varno や述語を書き換え、自己結合時の t1.a = t1.a を IS NOT NULL テストに変換する。

制御フローとデータフロー

1. **左結合の削除フロー (remove_useless_joins)**:

  • root->join_info_list を走査し、各 SpecialJoinInfo が JOIN_LEFT かつ join_is_removable() を満たすか確認する。
  • join_is_removable 内で、リレーションが一意インデックスを持つか（rel_supports_distinctness / rel_is_distinct_for）、上流やPlaceHolderVarで必要な属性が含まれていないかを検証する。
  • 削除可能な場合、remove_leftjoinrel_from_query を呼び出し、対象ベースリレーションの破棄、joininfo の再配分、attr_needed の再構築（rebuild_*_attr_needed）を行う。
  • remove_rel_from_joinlist で joinlist から対象の RangeTblRef を除外する。

    • 2. **自己結合の排除フロー (remove_useless_self_joins)**:

  • enable_self_join_elimination が有効な場合、remove_self_joins_recurse がジョインツリーから対象ベースリレーションを収集する。
  • SelfJoinCandidate 配列を構築し、reloid（テーブルのOID）でソートして同一テーブルを参照するペア・グループをまとめる。
  • remove_self_joins_one_group で各ペアに対し結合述語を分離（split_selfjoin_quals）、一意性を検証した上で remove_self_join_rel を実行する。
  • remove_self_join_rel では、削除対象の結合・制限条件を保持対象にマージし、ChangeVarNodesExtended と replace_relid_callback を用いてクエリ全体（root->parse, processed_tlist, RestrictInfo 等）の relid を書き換える。

読者向けメモ

  • **メモリ管理とライフタイム**: リレーション削除時に pfree(rel) や pfree(toRemove) を行い、古い RelOptInfo や RangeTblEntry（simple_rel_array, simple_rte_array を NULL に設定）を安全に破棄する。キャッシュされる UniqueRelInfo は root->planner_cxt に割り当てられる。
  • **不変条件（Invariants）**: 自己結合排除（SJE）において、Query->resultRelation や Query->mergeTargetRelation（MERGE/UPDATE/DELETEのターゲット）となるリレーションは、EPQ（EvalPlanQual）メカニズムや構文上の制約を壊さないために候補から除外される。
  • **コールバックの注意点**: replace_relid_callback は、自己結合排除時に t1.a = t2.a が t1.a = t1.a に変化した際、それを自明な真ではなく IS NOT NULL テスト（NullTest）に置換するという高度な安全化処理を行う。
