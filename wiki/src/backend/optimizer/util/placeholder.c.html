src/backend/optimizer/util/placeholder.c

概要

src/backend/optimizer/util/placeholder.c は、PostgreSQLオプティマイザにおけるプレースホルダ（PlaceHolderVar および PlaceHolderInfo）の生成、検索、ジョイントリーからの検出、評価レベルの調整、および不要なプレースホルダの除去を管理するソースファイルです。サブクエリの引き上げ（pullup）や外部結合の最適化に伴う式評価の位置決定を支えています。

モジュール内での役割

src/backend/optimizer/util ディレクトリ配下に位置し、クエリツリー内の複雑な式やサブクエリ境界をまたぐ式評価のスコープをオプティマイザが追跡できるようにします。式操作 (clauses.c) やリレーション管理 (relnode.c) と連携して、プレースホルダが必要とされる評価レベル (ph_eval_at) や依存関係 (ph_lateral) を計算します。

責務

  • **プレースホルダ式生成**: PlaceHolderVar ノードを生成し、一意なプレースホルダID（phid）を割り振る。
  • **メタデータ管理 (PlaceHolderInfo)**: クエリプランナ開始後に PlaceHolderInfo を作成・キャッシュし、評価可能なリレーション集合 (ph_eval_at) やラテラル参照 (ph_lateral) を算出する。
  • **ジョイントリー解析**: ジョイントリー（FromExpr / JoinExpr）を再帰的に走査し、含まれるすべての PlaceHolderVar を収集・登録する。
  • **入力依存レベルの調整**: プレースホルダの評価に必要な変数や他のプレースホルダが、その評価レベルで確実に利用可能になるようターゲットリストや属性必要度を更新する。
  • **ベースリレー・結合リレへの組込**: プレースホルダを計算可能なベースリレルや結合リルのターゲットリスト (reltarget) に追加し、コストや幅を見積もる。
  • **不要プレースホルダの除去**: 外部結合などで無効化されない（phnullingrels が空の）不要な PlaceHolderVar をスキャンレベルの式から剥がし、インデックスやパーティションキーとのマッチングを容易にする。

重要なシンボル

ライフサイクル・生成

  • **make_placeholder_expr(PlannerInfo *root, Expr *expr, Relids phrels)**: 与えられた式と構文上の位置（phrels）から新しい PlaceHolderVar ノードを生成する。
  • **find_placeholder_info(PlannerInfo *root, PlaceHolderVar *phv)**: phv に対応する PlaceHolderInfo を取得する。存在しない場合は、プレースホルダ集合が凍結されていなければ新規作成し、placeholder_list と placeholder_array の両方に登録する。

走査・検出

  • **find_placeholders_in_jointree(PlannerInfo *root)**: クエリのジョイントリーからプレースホルダの探索を開始するエントリーポイント。
  • **find_placeholders_recurse(PlannerInfo *root, Node *jtnode)**: FromExpr や JoinExpr を再帰的にたどり、各修飾節（quals）内のプレースホルダを検出する。
  • **find_placeholders_in_expr(PlannerInfo *root, Node *expr)**: 式から変数を抽出し、含まれる PlaceHolderVar ごとに PlaceHolderInfo を作成する。

レベル調整・リレーション統合

  • **fix_placeholder_input_needed_levels(PlannerInfo *root)**: プレースホルダの評価に必要な入力を、評価位置（ph_eval_at）で必要とマークする。
  • **rebuild_placeholder_attr_needed(PlannerInfo *root)**: 不要な外部結合の除去後、属性の必要度セットを再構築する。
  • **add_placeholders_to_base_rels(PlannerInfo *root)**: ベースリレルで計算可能なプレースホルダをそのターゲットリストに追加する。
  • **add_placeholders_to_joinrel(...)**: 結合リレルで新たに計算可能になったプレースホルダをターゲットリストに追加し、コスト計算や direct_lateral_relids の更新を行う。

ユーティリティ・検証

  • **contain_placeholder_references_to(PlannerInfo *root, Node *clause, int relid)**: 指定した式に含まれる PlaceHolderVar が特定のリレルを参照しているかを判定する。
  • **get_placeholder_nulling_relids(PlannerInfo *root, PlaceHolderInfo *phinfo)**: プレースホルダをヌル化（nulling）する外部結合リレルの集合を計算する。
  • **strip_noop_phvs(Node *node)**: スキャンレベルの式から、ヌル化されない（phnullingrels が空の）無効な PlaceHolderVar を再帰的に剥がす。

制御フローとデータフロー

1. **初期検出**: クエリの最適化初期段階において、find_placeholders_in_jointree がジョイントリーを再帰走査 (find_placeholders_recurse) し、修飾節内の式からプレースホルダを特定する。 2. **情報のキャッシュ**: 見つかった各 PlaceHolderVar に対して find_placeholder_info が呼ばれ、root->placeholder_array および root->placeholder_list に PlaceHolderInfo が格納される。この際、ph_eval_at（評価位置）や ph_lateral（ラテラル参照）が算出される。 3. **評価レベル・ターゲットリストへの統合**:

  • fix_placeholder_input_needed_levels により、評価に必要な変数がスキャン/結合レベルで利用可能になるよう保証される。
  • add_placeholders_to_base_rels や add_placeholders_to_joinrel によって、条件を満たすリレルの reltarget->exprs にプレースホルダ式が追加され、コストと幅が累積される。

    • 4. **最適化・クリーンアップ**: 不要な外部結合が削除された場合は rebuild_placeholder_attr_needed で属性必要度が再計算され、式マッチング時には strip_noop_phvs が軽量ウォーカー（contain_noop_phv_walker）とミューータ（strip_noop_phvs_mutator）を用いて不要な PlaceHolderVar を透過的に除去する。

読者向けメモ

  • **メモリ管理と重複格納**: PlaceHolderInfo は root->placeholder_list（リスト）と root->placeholder_array（動的配列）の両方にポインタが格納されます。そのため、このリストを直接 expression_tree_mutator 等で走査・変更することは安全ではなく、配列側の再構築が必要になる点に注意してください。
  • **不変条件 (Invariants)**: find_placeholder_info の呼び出し時、プレースホルダ集合が凍結されている状態（root->placeholdersFrozen == true）で新規作成を行うと elog(ERROR) が発生します。また、ベースリレル追加時や結合リレル追加時、初期状態の phnullingrels は空（NULL）であることが前提となっています。
