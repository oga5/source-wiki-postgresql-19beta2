src/backend/optimizer/util/placeholder.c

概要

PostgreSQLオプティマイザにおいて、PlaceHolderVar（PHV）および PlaceHolderInfo（PHI）の生成、検索、評価レベルの調整、ベースリレーションやジョインリレーションへの組込みを管理するソースファイルです。サブクエリの引き上げ（pullup）や外側結合（OJ）の最適化に関連するプレースホルダのライフサイクル全体を担います。

モジュール内での役割

src/backend/optimizer/util ディレクトリの一部として、式評価やリレーション構築を補助するユーティリティ機能を提供します。クエリツリー内のジョイントリーや式をスキャンしてプレースホルダを抽出し、それらをオプティマイザのコスト見積もりやプラン作成フェーズで利用可能な状態に変換します。

責務

  • **プレースホルダの生成と管理**: 式から PlaceHolderVar を作成し、一意なID (phid) を付与する。
  • **情報構造体の構築**: まだ凍結（frozen）されていないクエリに対して PlaceHolderInfo を遅延作成し、評価位置 (ph_eval_at) やlateral参照 (ph_lateral) を計算する。
  • **ジョイントリーからの検出**: FromExpr や JoinExpr を再帰的に走査し、クエリ内に存在するすべてのPHVを洗い出す。
  • **リレーションへの組込み**: ベースリレーションやジョインリレーションのターゲットリスト (reltarget->exprs) に対して、計算可能かつ上位で必要なPHVを追加し、コストと幅（width）を更新する。
  • **不要なPHVの除去**: ヌリング関係を持たない「no-op」なPHVを式から安全に剥離する（strip_noop_phvs）。

重要なシンボル

プレースホルダ作成および情報管理

  • **make_placeholder_expr**: 与えられた式と構文上の位置（phrels）から PlaceHolderVar ノードを新規作成し、グローバルなカウンタから phid を割り当てます。
  • **find_placeholder_info**: 指定された PlaceHolderVar に対応する PlaceHolderInfo を取得します。未作成かつプレースホルダ集合が凍結されていなければ新規作成し、placeholder_list と placeholder_array の両方に登録します。

ジョイントリーおよび式からの検出

  • **find_placeholders_in_jointree**: クエリのトップレベルジョイントリーから再帰探索を開始し、PHVの検出プロセスをキックします。
  • **find_placeholders_recurse**: FromExpr や JoinExpr を再帰的に下りながら、各構造体の結合条件やフィルタ条件内の式を評価します。
  • **find_placeholders_in_expr**: 指定された式から変数やPHVを抽出し、未登録のPHVがあれば find_placeholder_info を呼び出して登録します。

入力レベルおよびターゲットリストの調整

  • **fix_placeholder_input_needed_levels**: 各PHVの評価レベル確定後、その評価に必要な変数やPHVがスキャンまたはジョインレベルで確実に利用できるようマークします。
  • **rebuild_placeholder_attr_needed**: 不要な外側結合の削除後に、attr_needed/ph_needed 集合を再構築します。
  • **add_placeholders_to_base_rels**: ベースリレーションで計算可能であり、かつ上位で必要とされるPHVをベースリレーションのターゲットリストに追加します。
  • **add_placeholders_to_joinrel**: ジョインリレーションで新たに計算可能になったPHVをターゲットリストに追加し、コストとタプル幅、および direct_lateral_relids を調整します。

参照検出と最適化ヘルパー

  • **contain_placeholder_references_to**: 指定された句内のPHVが特定のrelid（外側結合のrelidなど）に対する参照を含んでいるかを検出します。
  • **get_placeholder_nulling_relids**: プレースホルダをnull化する可能性のある外側結合のrelid集合を計算します。
  • **strip_noop_phvs**: ヌリング関係を持たない実質無効な（no-op）PHVを式から再帰的に取り除き、インデックスやパーティションキーとのマッチングを容易にします。

制御フローとデータフロー

1. **検出フェーズ**: find_placeholders_in_jointree() がクエリのジョイントリー（FromExpr / JoinExpr）を走査し、find_placeholders_recurse() と find_placeholders_in_expr() を通じて式中の PlaceHolderVar を発見します。 2. **構造体登録**: 発見されたPHVごとに find_placeholder_info() が呼ばれ、root->placeholder_array（O(1)高速ルックアップ用）と root->placeholder_list に PlaceHolderInfo が格納されます。同時に、含まれる式（phexpr）内の下位PHVも再帰的に登録されます。 3. **評価レベル決定と配備**: オプティマイザの計画作成過程において、add_placeholders_to_base_rels() や add_placeholders_to_joinrel() が呼び出され、条件を満たすPHVが各リレーションの reltarget->exprs に追加されます。 4. **メモリ管理・不変条件**:

  • placeholder_array は動的配列として palloc0_array / repalloc0_array で管理され、サイズが不足した場合は倍増（または十分な大きさまで拡大）されます。
  • root->placeholdersFrozen が真になった後に新しい PlaceHolderInfo を作成しようとするとエラーになります。

読者向けメモ

  • **パフォーマンス最適化**: strip_noop_phvs では、高価な式ミューレータを走らせる前に軽量なウォーカー（contain_noop_phv_walker）で対象の存在を事前チェックし、不要なメモリ割り当てとツリーコピーを回避しています。
  • **重複管理の注意点**: PlaceHolderInfo は placeholder_list と placeholder_array の2つのデータ構造でポインタを共有しているため、これらを expression_tree_mutator 等で直接複製・変更する際は安全性の考慮が必要です。
