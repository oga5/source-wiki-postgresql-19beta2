src/backend/optimizer/util/relnode.c

概要

src/backend/optimizer/util/relnode.c は、PostgreSQLのオプティマイザ内部で使用されるリレーションノード（RelOptInfo）およびパラメータ化パス情報（ParamPathInfo）の検索、構築、管理を行う中心的なソースファイルです。ベースリレーション、結合リレーション（Join）、子分割リレーション、グループ化リレーション、アッパーリレーションの生成ロジックを集約しており、クエリ計画木全体の骨組みを形作るためのデータ構造を多数所有しているためファイル規模が大きくなっています。

モジュール内での役割

src/backend/optimizer/util モジュール内において、本書はリレーション（RelOptInfo）のライフサイクル管理の根幹を担います。パス生成を担当する pathnode.c や、条件評価を管理する restrictinfo.c、句の操作を行う clauses.c と緊密に連携し、オプティマイザが参照するリレーション構造体の実体を提供します。

責務

  • **リレーション配列・ハッシュの管理**: PlannerInfo 内のベースリレーション配列（simple_rel_array, simple_rte_array, append_rel_array）の初期化・動的拡張、および結合リレーション用の補助ハッシュテーブル（JoinHashEntry）の構築と検索。
  • **リレーションノード（RelOptInfo）の構築**:
  • ベースリレーションおよび「その他」リレーションの構築（build_simple_rel）。
  • 結合リレーションの新規作成および再利用（build_join_rel）。
  • 継承・パーティション分割に伴う子結合リレーションの構築（build_child_join_rel）。
  • グループ化リレーション（build_simple_grouped_rel, build_grouped_rel）やアッパーリレーション（fetch_upper_rel）の作成。
  • **結合条件・ターゲットリストの構築**: 結合時のターゲットリスト（build_joinrel_tlist）、制限条項（build_joinrel_restrictlist）、結合条項（build_joinrel_joinlist）の導出とフィルタリング。
  • **パーティションワイズ結合のサポート**: パーティションキーの等価結合判定（have_partkey_equi_join）、式のマッチング（match_expr_to_partition_keys）、およびパーティションキー式の初期化。
  • **パラメータ化パス情報（ParamPathInfo）の管理**: ベースリレーションおよび結合リレーションのパラメータ化パス情報の取得・キャッシュ生成（get_baserel_parampathinfo, get_joinrel_parampathinfo, get_appendrel_parampathinfo）。
  • **早期集約（Eager Aggregation）の評価**: 部分集約をプッシュダウン可能かどうかの判定と RelAggInfo の作成。

重要なシンボル

リレーション検索・配列管理

  • setup_simple_rel_arrays(PlannerInfo *root): RTインデックスベースの高速アクセスクリニック用配列（simple_rel_array, simple_rte_array, append_rel_array）を初期化する。
  • expand_planner_arrays(PlannerInfo *root, int add_size): 追加のRTE領域に合わせてプランナー配列を動的に拡張する。
  • find_base_rel(PlannerInfo *root, int relid): 指定された relid のベース／その他リレーションエントリを返す（存在しない場合はエラー）。
  • find_base_rel_noerr(PlannerInfo *root, int relid): エラーを出さずにベースリレーションエントリを返し、存在しない場合は NULL を返す。
  • find_base_rel_ignore_join(PlannerInfo *root, int relid): 外部結合を参照している場合にエラーではなく NULL を返す。
  • find_join_rel(PlannerInfo *root, Relids relids): 結合リセットに対応する RelOptInfo を線形探索またはハッシュ検索で返す。

リレーション構築ファミリー

  • build_simple_rel(PlannerInfo *root, int relid, RelOptInfo *parent): ベースリレーションまたは子（other）リレーション用の RelOptInfo を構築し、プラグインフック build_simple_rel_hook を呼び出す。
  • build_join_rel(PlannerInfo *root, Relids joinrelids, RelOptInfo *outer_rel, RelOptInfo *inner_rel, SpecialJoinInfo *sjinfo, List *pushed_down_joins, List **restrictlist_ptr): 2つのリレーションの結合ノードを検索または新しく生成し、外部プロパティやターゲットリスト、パーティション情報を設定する。
  • build_child_join_rel(...): 子パーティション間の結合リレーションを生成する。
  • fetch_upper_rel(PlannerInfo *root, UpperRelationKind kind, Relids relids): スキャン／結合後のクエリ処理を表すアッパーリレーションを取得または構築する。
  • build_simple_grouped_rel(...) / build_grouped_rel(...): グループ化されたリレーション表現を構築する。

パラメータ化パス情報（PPI）ファミリー

  • get_baserel_parampathinfo(PlannerInfo *root, RelOptInfo *baserel, Relids required_outer): ベースリレーションのパラメータ化パス情報を取得または新規構築する。
  • get_joinrel_parampathinfo(...): 結合リレーションのパラメータ化パス情報を取得・構築し、移動可能な結合条項をマージする。
  • get_appendrel_parampathinfo(RelOptInfo *appendrel, Relids required_outer): アプリケーション（Append）リレーション用のPPIを作成する。
  • find_param_path_info(RelOptInfo *rel, Relids required_outer): 既存のPPIを検索する。
  • get_param_path_clause_serials(Path *path): パス内で強制されるプッシュダウン条件の一意識別子（rinfo_serial）のビットマップを返す。

フック変数

  • build_simple_rel_hook: build_simple_rel() 内でプラグインが介入するためのフック関数ポインタ。
  • joinrel_setup_hook: 結合リレーションのセットアップ中にプラグインが制御を取得するためのフック関数ポインタ。

制御フローとデータフロー

[クエリツリー / RTE]
       │
       ▼ setup_simple_rel_arrays()
[simple_rel_array / rtable] ──> build_simple_rel() ──> [Base RelOptInfo]
                                                              │
       ┌──────────────────────────────────────────────────────┘
       ▼
[build_join_rel()] ──(キャッシュヒット?)──> [既存の Join RelOptInfo]
       │ (ヒットしない場合)
       ├─ makeNode(RelOptInfo)
       ├─ set_foreign_rel_properties()
       ├─ build_joinrel_tlist() ────(Vars / PHVs の複写と nulling 処理)
       ├─ build_joinrel_restrictlist() ──(subbuild_joinrel_restrictlist + EC)
       ├─ set_joinrel_size_estimates()
       ├─ build_joinrel_partition_info() ──(パーティションワイズ結合の判定)
       └─ add_join_rel() ──> [join_rel_list / join_rel_hash]
  • **データフロー**:

    • 1. プランナー初期化時に setup_simple_rel_arrays が呼ばれ、RTインデックスをキーとした高速アクセス配列が割り当てられる。 2. 計画作成が進むにつれ build_simple_rel が各ベースリレーションの RelOptInfo を生成。 3. 結合探索の過程で build_join_rel が呼び出され、既存の結合リレーションがハッシュ（find_join_rel）またはリストから検索される。存在しない場合は新規作成され、入力リレーションのターゲットリストから build_joinrel_tlist を介して必要な Var および PlaceHolderVar が引き継がれる。 4. 結合条件は build_joinrel_restrictlist と subbuild_joinrel_restrictlist によって、現在の結合レベルで評価すべきものと、さらに上層に持ち越すもの（build_joinrel_joinlist）に振り分けられる。

読者向けメモ

  • **メモリ管理**: 本ファイル内で生成される RelOptInfo や ParamPathInfo、各種リストは、原則としてプランナーの実行コンテキスト（CurrentMemoryContext / Planner Context）上に割り当てられ、クエリの計画フェーズ終了時に一括解放されます。
  • **ハッシュ最適化**: 結合リレーションの検索において、join_rel_list の要素数が 32 を超えると、自動的に JoinRelHashTable（build_join_rel_hash）を用いたハッシュ検索に切り替わり、O(1)に近い検索性能を実現します。
  • **ナル化（Nulling）処理**: 外部結合（Outer Join）や pushed_down_joins の文脈において、Var や PlaceHolderVar が copyObject を介して複製され、varnullingrels や phnullingrels が適切に更新される複雑なフローが含まれています。
