src/backend/optimizer/util/tlist.c

概要

src/backend/optimizer/util/tlist.c は、PostgreSQLのオプティマイザにおけるターゲットリスト（TargetEntryのリスト）および PathTarget 構造体の操作、検索、比較、およびセット返却関数（SRF）の多段階評価への分割を行う中核的なソースファイルです。

モジュール内での役割

src/backend/optimizer/util モジュールの中で、プランノードやパス間で持ち回る出力列（式、型、照合順序、ソート/グループ化参照）を一元的に管理します。隣接する clauses.c や pathnode.c が生成・評価するパスのターゲット表現を支える基盤ユーティリティとして機能します。

責務

  • **ターゲットリストの検索と操作**: 式の一致によるメンバー検索 (tlist_member, tlist_member_match_var)、フラットなターゲットリストへの追加 (add_to_flat_tlist)、式やジャンク列の抽出。
  • **ターゲットリスト間の比較**: 式の一致 (tlist_same_exprs)、データ型の一致 (tlist_same_datatypes)、照合順序の一致 (tlist_same_collations) の検証。
  • **ソート・グループ化句の解決**: SortGroupClause とターゲットリストのエントリ (TargetEntry) を結びつけるメタデータ（Oid、照合順序、列番号、ソート/ハッシュ可能性）の抽出と検証。
  • **PathTarget の管理**: PathTarget と通常ターゲットリスト間の相互変換、列の追加、コピー、およびラベル付け。
  • **SRF（Set-Returning Function）の分解**: エクゼキュータの制約を満たすために、ネストした SRF を持つ PathTarget を複数段階に安全に分割する (split_pathtarget_at_srfs, split_pathtarget_at_srfs_grouping)。

重要なシンボル

検索・構築・比較ファミリー

  • tlist_member: 指定した式が一致する最初の TargetEntry を検索する。
  • tlist_member_match_var: Var ノード同士を varno/varattno/varlevelsup/vartype のみに基づいてマッチさせる。
  • add_to_flat_tlist: 重複を除外してフラットなターゲットリストに式を追加する。
  • tlist_same_exprs: 2つのターゲットリストが順序と式において同一か検証する（ラベルやジャンク属性は無視）。
  • tlist_same_datatypes / tlist_same_collations: ターゲットリストの出力型および照合順序が指定リストと一致するか検証する。

ソート・グループ化補助ファミリー

  • get_sortgroupref_tle: SortGroupRef インデックスに一致する TargetEntry を返す（見つからない場合は ERROR）。
  • extract_grouping_ops / extract_grouping_collations / extract_grouping_cols: グループ化句から演算子 Oid、照合順序、列番号の配列を抽出する。
  • grouping_is_sortable / grouping_is_hashable: グループ化句がソートまたはハッシュで実装可能か判定する。

PathTarget 操作ファミリー

  • make_pathtarget_from_tlist / make_tlist_from_pathtarget: PathTarget と List *（TargetEntryリスト）の間で相互変換を行う。
  • copy_pathtarget: PathTarget の浅いコピーを作成し、式リストや sortgrouprefs 配列を複製する。
  • add_column_to_pathtarget / add_new_column_to_pathtarget: カラム（式とオプショナルな sortgroupref）を PathTarget に追加する。
  • apply_pathtarget_labeling_to_tlist: PathTarget の sortgrouprefs を一致するターゲットリストエントリに適用する。

SRF 分割ファミリー

  • IS_SRF_CALL(node): 指定ノードが FuncExpr または OpExpr のセット返却関数呼び出しであるか判定するマクロ。
  • split_pathtarget_at_srfs / split_pathtarget_at_srfs_grouping: ネストした SRF を評価するための複数階層の PathTarget リストを構築するラッパー。
  • split_pathtarget_at_srfs_extended: SRF の深さを解析し、中間的な ProjectSet や Result ノード用のターゲット群を構築する実体関数。
  • split_pathtarget_walker: 式ツリーを再帰的に走査し、必要な入力変数、入力 SRF、および各階層の SRF を分類するツリーウォーカー。

制御フローとデータフロー

1. **SRF 分割のフロー**:

  • split_pathtarget_at_srfs_extended は、与えられた target の各式を split_pathtarget_walker で走査する。
  • ウォーカーはノードが input_target_exprs に含まれるか Var/Aggref 等であれば current_input_vars に記録し、IS_SRF_CALL であれば再帰的に下位を探索して srf_depth を決定する。
  • 決定された最大深度 (max_depth) と追加プロジェクションの要否に基づき、下位から上位へ向かう複数段階の PathTarget リスト (targets) と、各段階が SRF を含むかどうかのフラットリスト (targets_contain_srfs) を組み立てる。

    • 2. **グループ化境界をまたぐ処理**:

  • split_pathtarget_at_srfs_grouping はグループ化前後でターゲットが異なる場合に呼び出され、remove_nulling_relids を用いてグループ化のヌリングビットを除外した上で等価性を評価する。

読者向けメモ

  • **メモリ所有権**: PathTarget の exprs リストや sortgrouprefs 配列、および extract_* 系関数が返す配列は、現在のメモリコンテキスト上に palloc で割り当てられる。
  • **制約と不変条件**: split_pathtarget_walker 内の IS_SRF_CALL マクロは split_pathtarget_at_srfs() 専用であり、任意の式に含まれるネストした SRF の検出には expression_returns_set() を使用する必要がある。
