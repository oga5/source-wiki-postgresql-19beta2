src/backend/optimizer/util/tlist.c

概要

src/backend/optimizer/util/tlist.c は、PostgreSQLのクエリ最適化フェーズにおいてターゲットリスト（TargetEntryのリスト）および PathTarget 構造体を操作・変換・検索するためのユーティリティ関数群を所有する。

モジュール内での役割

src/backend/optimizer/util ディレクトリ配下に位置し、プラン作成やコスト見積もり、セレクティビティ・グルーピング処理の前段階で必要となるターゲット列の管理、ソート／グループ化キーの抽出、およびセット返却関数（SRF: Set-Returning Function）を安全に実行するための複数階層へのプラン分割（ProjectSet / Result ノードの構築補助）を提供する。

責務

  • ターゲットリスト操作: メンバー検索、重複排除付き追加、データ型・照合順序の一致確認。
  • SortGroupClause 連携: グループ化・ソート句（SortGroupClause）とターゲットリストのエントリを突き合わせ、対応する演算子 OID、照合順序、列番号（resno）の配列を抽出する。
  • PathTarget 管理: フルなターゲットリストを軽量な PathTarget へ変換、コピー、列追加、およびプラン間でのラベル付けを行う。
  • SRF の多段階分割: ネストまたは複数存在する SRF を安全に実行するため、split_pathtarget_at_srfs を通じて単一のターゲットを複数階層の PathTarget へ分解する。

重要なシンボル

ターゲットリスト検索と操作

  • tlist_member: 指定された式ノードと equal() が一致する最初の TargetEntry を返す。
  • tlist_member_match_var: varno、varattno、varlevelsup、vartype のみに基づいて Var ノードをマッチさせる（厳密な typmod 一致が不確実な場合に使用）。
  • add_to_flat_tlist: フラットなターゲットリストに既存に含まれていない式を追加する。

SortGroup / グループ化属性の抽出

  • extract_grouping_ops: SortGroupClause リストから等価演算子 OID の配列を割り当て・抽出する。
  • extract_grouping_collations: グループ化列の照合順序 OID の配列を抽出する。
  • extract_grouping_cols: グループ化列の属性番号（resno）の配列を抽出する。
  • grouping_is_sortable / grouping_is_hashable: グルーピング仕様がソートまたはハッシュで実装可能か判定する。

PathTarget ライフサイクルと SRF 分割

  • PathTarget: 評価コスト、出力幅、式リスト、ソートグループ参照を持つ軽量ターゲット構造体。
  • split_pathtarget_at_srfs / split_pathtarget_at_srfs_grouping / split_pathtarget_at_srfs_extended: SRF が含まれる PathTarget を、深さに応じて複数段階の PathTarget リストへと安全に分割する。
  • split_pathtarget_item: 式とその sortgroupref インデックスをペアで追跡する構造体。
  • split_pathtarget_context: split_pathtarget_walker のトラバーサル状態（レベルごとの SRF や入力変数）を保持するコンテキスト構造体。
  • FuncExpr / OpExpr / Var / TargetEntry / Result / ProjectSet / SortGroupRef: 式木の分析やプランノード構築時に参照・判定される主要な PostgreSQL ノード型。
  • ERROR: エラー発生時に elog を通じてシステムログや例外を発生させる。

制御フローとデータフロー

1. SRF 分割のフロー:

  • split_pathtarget_at_srfs は内部で split_pathtarget_at_srfs_extended を呼び出す。
  • 各ターゲット式に対して split_pathtarget_walker が再帰的に適用され、式内の SRF のネスト深度（srf_depth）と必要な入力変数（Var やインプット側ですでに計算済みの式）を収集する。
  • 収集された情報に基づき、context.level_srfs および context.level_input_vars に沿って、最も低い階層から順に PathTarget を構築する。
  • グループ化境界を跨ぐ場合は is_grouping_target フラグが立ち、remove_nulling_relids によってグループ化の nullingrels ビットが一時的に除外されて入力側との一致判定が行われる。

2. メモリ所有権とライフサイクル:

  • extract_grouping_ops などの抽出関数は palloc_array を用いてメモリを割り当てる。
  • copy_pathtarget は PathTarget のスローコピーを行い、exprs リストは list_copy() で浅いコピーを作成しつつ、sortgrouprefs 配列は新しくメモリを確保して複製する。

読者向けメモ

  • SRF のマクロ制約: IS_SRF_CALL マクロは split_pathtarget_at_srfs() 内での使用に限定されている。式内部にネストされた SRF に対して他の場所で適用すると誤動作するため、一般的なケースでは expression_returns_set() を使用すること。
  • グループ化の Nulling ビット: グループ化ターゲットを扱う際、プレグループとポストグループの間で nullingrels の差異が生じるため、一致判定時に除外処理が必要となる点に注意。
