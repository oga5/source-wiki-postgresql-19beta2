src/backend/optimizer/util/inherit.c

概要

src/backend/optimizer/util/inherit.c は、PostgreSQLのオプティマイザにおいて、継承ツリーやパーティションテーブル、および UNION ALL サブクエリ（appendrel）の子関係を処理するルーチン群を提供します。inh フラグが設定された範囲テーブルエントリ（RTE）を拡張し、子テーブルの RTE、AppendRelInfo、RelOptInfo、および必要に応じて PlanRowMark を構築します。

モジュール内での役割

src/backend/optimizer/util モジュール内に位置し、クエリ計画作成の初期段階で継承関係やパーティショニング構造を解決する中核ファイルを構成します。ペアとなるヘッダーファイルは src/include/optimizer/inherit.h です。

責務

  • **継承・パーティション展開**: expand_inherited_rtentry により、通常のテーブル継承、パーティションテーブル、UNION ALL サブクエリの各展開パスをディスパッチする。
  • **パーティションツリーの再帰処理**: パーティション記述子やパーティションプルーニング（prune_append_rel_partitions）を利用して、ライブなパーティションを再帰的に特定し、子 RelOptInfo を構築する。
  • **子関係メタデータの構築**: expand_single_inheritance_child を通じて、個々の子テーブルに対する RTE、AppendRelInfo、行マーク、結果リレーション識別子（all_result_relids, leaf_result_relids）の登録を行う。
  • **列権限・属性の変換**: 親リレーションの更新対象列や権限ビットマップ（updatedCols）を、子リレーションの列番号へとマッピング・変換する。
  • **ベース制約条件の適用**: 親リレーションの基本制限条件（baserestrictinfo）を子リレーションへ適合させ、定数畳み込みやセキュリティレベルの調整を行って適用する。

重要なシンボル

エントリポイント・公開関数

  • expand_inherited_rtentry(PlannerInfo *root, RelOptInfo *rel, RangeTblEntry *rte, Index rti): inh が設定された RTE を拡張するメインエントリーポイント。
  • get_rel_all_updated_cols(PlannerInfo *root, RelOptInfo *rel): 指定されたシンプルリレーションで更新される列のセットを返し、必要に応じてマルチレベルで列番号を変換する。
  • apply_child_basequals(PlannerInfo *root, RelOptInfo *parentrel, RelOptInfo *childrel, RangeTblEntry *childRTE, AppendRelInfo *appinfo): 親リレーションのベース制限条件を子リレーションへ変換・適用し、定数 FALSE / NULL になった場合に false を返す。

内部ヘルパー関数

  • **パーティション・継承展開**:
  • expand_partitioned_rtentry: パーティションテーブルの再帰的展開とプルーニングを行う。
  • expand_single_inheritance_child: 単一の子継承メンバに対する RTE、AppendRelInfo、行マーク、結果リレーション設定を行う。
  • expand_appendrel_subquery: UNION ALL サブクエリの append_rel_list に基づいて子 RelOptInfo を構築する。
  • **権限・列変換**:
  • translate_col_privs: 親リレーションの列権限ビットマップを子リレーションの列番号へ変換する。
  • translate_col_privs_multilevel: 多段階の継承階層にわたって列権限ビットマップを再帰的に変換する。

制御フローとデータフロー

1. **ディスパッチ**: expand_inherited_rtentry が呼び出されると、RTE の種類（RTE_SUBQUERY または RTE_RELATION）を検証する。

  • サブクエリの場合は expand_appendrel_subquery へ委譲。
  • リレーションの場合は、パーティションテーブル（RELKIND_PARTITIONED_TABLE）か従来型継承かを確認。

    • 2. **従来型継承のフロー**: find_all_inheritors で全 OID を取得し、expand_planner_arrays でプランナ配列を拡張した上で、ループ内で expand_single_inheritance_child と build_simple_rel を実行する。 3. **パーティション展開のフロー**: PartitionDirectoryLookup でディスクリプタを取得し、prune_append_rel_partitions でパーティションプルーニングを実施。生存するパーティションに対して、expand_single_inheritance_child と build_simple_rel を呼び出し、再帰的に下位パーティションを処理する。 4. **制約の伝播**: apply_child_basequals が親の baserestrictinfo を adjust_appendrel_attrs で子属性に調整し、eval_const_expressions で定数評価した上で、子側の baserestrictinfo に登録する。

読者向けメモ

  • **メモリ管理**: 新規に作成される RTE、AppendRelInfo、RelOptInfo、および PlanRowMark は、通常プランナのメモリコンテキスト（PlannerInfo が使用するコンテキスト）上に割り当てられます。
  • **ロック管理**: 親リレーションはオープン済み（リライトフェーズでロック取得済み）を前提とし、子リレーションに対しては table_open / try_table_open により必要なロックモード（親と同じ lockmode）を明示的に取得します。
  • **一時テーブルのエッジケース**: 他のバックエンドの一時テーブル（RELATION_IS_OTHER_TEMP）は、バッファリング上の問題から安全にアクセスできないため、暗黙的にスキップまたはエラー処理されます。
