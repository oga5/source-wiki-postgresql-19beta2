src/backend/optimizer/util/restrictinfo.c

概要

src/backend/optimizer/util/restrictinfo.c は、PostgreSQLのクエリ最適化において、述語や結合条件を表す RestrictInfo ノードの構築、変換、および移動性判定を担当するソースファイルです。式（Expr）をラップして最適化に必要なメタデータ（参照される関係、コスト、選択率、等価クラスへの所属など）を付与し、プッシュダウンやパラメータ化の判定を支えます。

モジュール内での役割

src/backend/optimizer/util モジュール内において、本書は RestrictInfo 構造体のライフサイクルを直接管理する中核ファイルとして位置づけられます。周辺の clauses.c や predtest.c、pathnode.c などのオプティマイザコンポーネントと密に連携し、構築された条件ツリーを安全に評価・移動・抽出するためのヘルパーを提供します。

責務

  • **RestrictInfo構築**: 生の式（Expr）または OR 構造から RestrictInfo ノードおよびそのサブノードを再帰的に構築する。
  • **メタデータの初期化**: 参照関係（left_relids, right_relids, clause_relids）、リークプルーフ性、揮発性、セキュリティレベルなどの基本属性を設定する。
  • **条件の変換**: 比較演算子の可換性（Commutation）を考慮した RestrictInfo の複製と変換を行う。
  • **条件の抽出**: RestrictInfo リストから実際の式リストや、プッシュダウン有無・疑似定数性を考慮した結合条件を抽出する。
  • **移動可能性の判定**: 結合条件が特定のベース関係や結合コンテキストへ移動可能（パラメータ化に利用可能）かを検証する。

重要なシンボル

  • **構築・ファクトリ関数**
  • make_restrictinfo: メインのエントリポイント。必要に応じて OR 構造を分解しつつ RestrictInfo を生成。
  • make_plain_restrictinfo: RestrictInfo の各フィールド（関係のビットマップ、シリアル番号、初期キャッシュ値）を設定する共通処理。
  • make_sub_restrictinfos: OR / AND 構造を再帰的にたどり、適切な位置に RestrictInfo を挿入する内部関数。
  • **変換関数**
  • commute_restrictinfo: 指定された可換演算子（comm_op）に基づき、左右のオペランドと関係を入れ替えた新しい RestrictInfo を生成する。
  • **述語判定・抽出関数**
  • restriction_is_or_clause: orclause が存在するか判定する。
  • restriction_is_securely_promotable: セキュリティレベルとリークプルーフ性に基づき、早期評価の安全性を判定する。
  • get_actual_clauses: RestrictInfo リストから生の式リストを取り出す。
  • extract_actual_clauses: 疑似定数フラグや定数 TRUE をフィルタリングしながら式を抽出する。
  • extract_actual_join_clauses: 外部結合コンテキストにおいて、プッシュダウンされた条件（otherquals）と通常の結合条件（joinquals）に分離・抽出する。
  • **移動性検証関数**
  • join_clause_is_movable_to: 結合条件が指定されたベース関係の走査にパラメータ化として移動可能か検証する。
  • join_clause_is_movable_into: 指定された現在の結合コンテキスト内で条件が評価可能か検証する。
  • **インライン・静的ヘルパー**
  • clause_sides_match_join: 2項演算子の左右が外側・内側リレーションのサブセットに合致するか判定し、outer_is_left を設定する（ヘッダーで定義）。
  • rinfo_is_constant_true: 定数 TRUE の式を検出する。

制御フローとデータフロー

1. **構築フロー**:

  • オプティマイザが条件節を受け取り make_restrictinfo を呼び出す。
  • is_orclause(clause) が真の場合、make_sub_restrictinfos が再帰的に呼び出され、AND/OR 構造の各サブ節に RestrictInfo が付与される。
  • 最終的に make_plain_restrictinfo が呼ばれ、pull_varnos による変数抽出、ベース関係数のカウント、一意なシリアル番号（rinfo_serial）の付与、およびキャッシュ値の初期化（-1 や InvalidOid）が行われる。

    • 2. **抽出フロー**:

  • 最適化の各段階で get_actual_clauses や extract_actual_join_clauses が RestrictInfo のリストを走査し、内部の clause（Expr）を取り出して実行可能なプランツリーへ渡す。

    • 3. **移動性判定フロー**:

  • パス生成時に join_clause_is_movable_to / join_clause_is_movable_into が呼び出され、clause_relids、outer_relids、nulling_relids、および lateral_referencers のビットマップ演算（bms_is_subset, bms_overlap 等）により、条件を安全に下位や別のコンテキストにプッシュダウンできるかを検証する。

  • optimizer/restrictinfo.h: 自身のペアヘッダー。

関連コード

  • src/include/optimizer/restrictinfo.h: 対応するヘッダーファイル。構造体定義および clause_sides_match_join インライン関数を含む。
  • src/backend/optimizer/util/clauses.c: 条件式の解析や操作を行う親和性の高いモジュール。
  • src/backend/optimizer/path/joinpath.c: パス生成時に join_clause_is_movable_to などの移動性判定を利用するコード。

読者向けメモ

  • **メモリ管理**: 生成される RestrictInfo およびその内部フィールドは、現在のメモリコンテキスト（通常は Planner のワークスペースコンテキスト）に割り当てられる。
  • **クローンとコピー**: commute_restrictinfo などでは memcpy によるフラットコピーを用い、一部のポインタやキャッシュ（関係ビットマップや演算子ID）を適切に反転・再設定するが、サブ構造の一部を共有するため元データの変更には注意が必要である。
  • **不変条件**: 構築直後の RestrictInfo は、未計算のキャッシュフィールドが -1 または InvalidOid で初期化されていることが前提となる。
