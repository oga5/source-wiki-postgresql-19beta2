src/backend/optimizer/util/extendplan.c

概要

src/backend/optimizer/util/extendplan.c は、ロード可能なモジュール（プランナー拡張）が、コアのプランナーデータ構造内部に独自のプライベート状態を格納できるようにするためのインターフェースを提供するソースファイルです。

モジュール内での役割

src/backend/optimizer/util モジュールにおいて、このファイルはオプティマイザの内部データ構造を拡張するためのインフラを担います。set_join_pathlist_hook などのフックを利用する拡張機能が、中間計算結果などを効率的にキャッシュ・保持できるようにします。

責務

  • 拡張機能名から一意の整数 ID (extension_id) への動的な割り当てと管理を行う。
  • PlannerGlobal、PlannerInfo、RelOptInfo の各データ構造に対して、拡張機能固有の状態ポインタ配列の動的確保・拡張・保存を行う。
  • 状態取得のためのインライン関数（ヘッダー側で定義）と連携し、安全なアクセス機構を支える。

重要なシンボル

  • GetPlannerExtensionId: 拡張機能名に対応する整数 ID を取得（未登録の場合は新規割り当て）する。
  • SetPlannerGlobalExtensionState: PlannerGlobal に拡張固有の状態を格納する。
  • SetPlannerInfoExtensionState: PlannerInfo に拡張固有の状態を格納する。
  • SetRelOptInfoExtensionState: RelOptInfo に拡張固有の状態を格納する。

制御フローとデータフロー

1. **ID 取得フロー**: GetPlannerExtensionId(extension_name) が呼ばれると、静的配列 PlannerExtensionNameArray から既存の名前を検索し、存在すればそのインデックス（ID）を返します。未登録の場合は配列を初期化または pg_nextpower2_32 を用いてサイズを拡張し、新しい ID を割り当てて登録します。 2. **状態保存フロー**: SetPlanner*ExtensionState 系関数は、対象構造体の extension_state 配列が未初期化であれば TopMemoryContext やプランナーコンテキストからメモリを確保してゼロクリアします。指定された extension_id が現在の割り当てサイズを超えている場合は、repalloc0_array を用いて配列を拡張し、ポインタ (opaque) を格納します。

関連コード

読者向けメモ

  • 割り当てられる拡張機能 ID (extension_id) はバックエンドのライフタイム内でのみ有効であり、永続的ではありません。
  • 状態の取得 (GetPlannerGlobalExtensionState 等) はヘッダー内でインライン展開されるためオーバーヘッドが小さく設計されています。
