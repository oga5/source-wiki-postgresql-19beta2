src/backend/optimizer/util/clauses.c

概要

src/backend/optimizer/util/clauses.c は、PostgreSQLのオプティマイザにおいて、クエリの修飾句（qualification clauses）や式ツリー（expression trees）の走査、解析、変形、および定数畳み込み（constant folding）を行うための極めて重要なユーティリティファイルです。

このファイルは、プランナが実行時オーバーヘッドを削減するために、静的に評価可能な式を事前に計算して定数（Const）に置き換えたり、不要な論理分岐を削除したり、SQL関数をインライン展開したりするための多彩なロジックを実装しています。

モジュール内での役割

src/backend/optimizer/util ディレクトリに属し、プランニングの初期段階（前処理フェーズ）からパス生成、コスト見積もりに至るまで、オプティマイザ全体から広く呼び出される共通の式処理エンジンとして機能します。

パーサから出力された生のクエリツリーや、プランナ内部で構築される Expr ノードを走査・変形し、後続のプラン作成処理がより単純かつ最適化された式を扱えるように下地を整える役割を担います。

責務

本ファイルが持つ責務は、大きく以下の5つの役割グループに分類されます。

1. 定数畳み込みと事前評価 (Constant Folding & Evaluation)

  • **静的評価**: 実行前に値が確定可能な部分式（例: 2 + 2 や不変関数の定数引数呼び出し）を検出し、エグゼキュータを一時的に起動して事前評価（evaluate_expr）し、Const ノードに置き換えます。
  • **論理式の簡約**: AND/OR 節のネスト平坦化や、短絡評価（例: x OR true -> true）による不要な枝の刈り込みを行います。
  • **見積もり評価**: コスト見積もり用の特殊モード（estimate_expression_value）では、安定（stable）関数やプレースホルダも含めて、よりアグレッシブに定数化を試みます。

2. 関数のインライン展開 (Function Inlining)

  • **式レベルのインライン化**: 単一の SELECT 式のみで構成される単純なSQL言語関数を、呼び出し元の式ツリーに直接展開（inline_function）します。
  • **FROM句のインライン化**: FROM句内のテーブル関数（RTE_FUNCTION）をサブクエリとして展開（inline_function_in_from）し、結合最適化の対象にします。

3. ヌル可能性解析 (Nullability Analysis)

  • **非NULL制約の伝播解析**: 与えられた式が TRUE を返すために、どのリレーション（find_nonnullable_rels）や変数（find_nonnullable_vars）が非NULLでなければならないかを解析します。これは外部結合を内側結合に変換する最適化（Outer Join Simplification）の基礎データとなります。
  • **強制NULL変数の特定**: 式が TRUE を返すために NULL であることが強制される変数（find_forced_null_vars）を特定します（例: var IS NULL）。

4. 並列処理安全性・ハザード評価 (Parallel Safety Assessment)

  • **並列ハザードの走査**: クエリツリーや式ツリーを再帰的に走査し、並列実行を阻害する要素（揮発性関数、特定のパラメータ、ウィンドウ関数など）が含まれていないかを検証し、並列安全度（SAFE / RESTRICTED / UNSAFE）を判定します。

5. 式構造の探索と属性判定 (Expression Scanning)

  • **特定ノードの検出**: 集約関数（Aggref）、ウィンドウ関数（WindowFunc）、サブプラン（SubPlan / SubLink）などの特定のノードが式ツリー内に存在するかを高速に判定します。
  • **セキュリティ・リーク対策**: 非リークプローフ（non-leakproof）関数にセキュリティバリアを越えて変数が渡されないよう、リークの危険性がある式を検出（contain_leaked_vars）します。

重要なシンボル

定数畳み込み・評価ファミリー

  • eval_const_expressions(PlannerInfo *root, Node *node)
  • 式の定数畳み込みを行うメインエントリポイント。
  • eval_const_expressions_mutator(Node *node, eval_const_expressions_context *context)
  • 式ツリーを再帰的に走査し、各ノード（FuncExpr, OpExpr, BoolExpr, CaseExpr 等）を個別に簡約する主要なミューテータ。
  • evaluate_expr(Expr *expr, Oid result_type, int32 result_typmod, Oid result_collation)
  • 一時的なエグゼキュータ状態（EState）を構築し、実際に式を実行して結果を Const ノードとして返します。
  • estimate_expression_value(PlannerInfo *root, Node *node)
  • プランナの見積もり用に、安定（stable）関数なども定数とみなして評価するアグレッシブな定数畳み込み。

インライン展開ファミリー

  • inline_function(...)
  • SQL言語関数を式ツリー内にインライン展開可能か検証し、可能であれば展開します。
  • inline_function_in_from(PlannerInfo *root, RangeTblEntry *rte)
  • FROM句の RTE_FUNCTION をサブクエリに展開するためのエントリポイント。
  • inline_sql_function_in_from(...)
  • SQL言語のセットリターン関数をFROM句にインライン展開する実体処理。

ヌル可能性解析ファミリー

  • find_nonnullable_rels(Node *clause) / find_nonnullable_vars(Node *clause)
  • 式が TRUE を返すために非NULLでなければならないリレーションID集合（Relids）または変数（Var）のリストを返します。
  • expr_is_nonnullable(PlannerInfo *root, Expr *expr, NotNullSource source)
  • 指定された式が確実に SQL NULL を返さない（NOT NULL である）ことをカタログや制約情報から判定します。
  • find_forced_null_vars(Node *node) / find_forced_null_var(Node *node)
  • 式が TRUE を返すために NULL であることが強制される変数を特定します。

安全性・属性検査ファミリー

  • max_parallel_hazard(Query *parse) / is_parallel_safe(PlannerInfo *root, Node *node)
  • 対象クエリまたはノードの並列実行安全性を判定します。
  • contain_volatile_functions(Node *clause) / contain_mutable_functions(Node *clause)
  • 式の中に揮発性（volatile）または可変（mutable/stable）関数が含まれているかを判定します。
  • contain_leaked_vars(Node *clause)
  • 非リークプローフ関数に渡されている Var ノードを検出し、行セキュリティ（RLS）などのバリアを越えたデータ漏洩を防ぐために使用されます。

制御フローとデータフロー

1. 定数畳み込みの制御フロー (eval_const_expressions)

[外部呼び出し] eval_const_expressions(root, node)
  │
  ▼
context の初期化 (boundParams, active_fns, case_val 等)
  │
  ▼
[再帰] eval_const_expressions_mutator(node, context)
  │
  ├─► [T_FuncExpr / T_OpExpr の場合]
  │     │
  │     ▼
  │   simplify_function() を呼び出し
  │     │
  │     ├─► 引数の再帰的簡約 (expand_function_arguments -> mutator)
  │     ├─► evaluate_function() による定数評価の試み
  │     │     └─► すべての引数が Const かつ不変関数なら evaluate_expr() へ
  │     ├─► サポート関数による簡約の試み (prosupport)
  │     └─► inline_function() によるインライン展開の試み
  │
  ├─► [T_BoolExpr (AND/OR) の場合]
  │     │
  │     ▼
  │   simplify_and_arguments() / simplify_or_arguments()
  │     ├─► ネストした AND/OR の平坦化
  │     └─► 短絡評価による定数化 (例: FALSE AND x -> FALSE)
  │
  └─► [T_CaseExpr の場合]
        │
        ▼
      テスト式が定数の場合、CaseTestExpr を定数に置換して WHEN 節を評価・削減

2. 式の実行評価フロー (evaluate_expr)

1. CreateExecutorState() により、評価専用の EState を作成。 2. メモリリークを防ぐため、コンテキストを estate->es_query_cxt に切り替え。 3. ExecInitExpr() で式を実行可能な ExprState に初期化。 4. ExecEvalExprSwitchContext() を呼び出して、実際の Datum 値と NULL フラグを取得。 5. 取得した Datum が参照渡し（pass-by-reference）または varlena（TOASTの可能性あり）の場合、呼び出し元のメモリコンテキストに安全にコピー（datumCopy / PG_DETOAST_DATUM_COPY）。 6. FreeExecutorState() でエグゼキュータ状態を解放し、結果を Const ノードに包んで返却。

直接依存

本ファイルは、式評価やメタデータアクセスのために以下のモジュールに直接依存しています。

  • **ノード操作基盤**: nodes/nodeFuncs.h (expression_tree_walker, expression_tree_mutator)
  • **エグゼキュータ**: executor/executor.h (CreateExecutorState, ExecInitExpr, ExecEvalExprSwitchContext)
  • **システムカタログキャッシュ**: utils/syscache.h, utils/lsyscache.h (pg_proc, pg_operator, pg_type などのメタデータ取得)
  • **パーサ・リライタ**: parser/analyze.h, rewrite/rewriteHandler.h (インライン展開時の再パースおよびルール適用)

関連コード

  • src/backend/nodes/nodeFuncs.c: 式ツリーを走査するための汎用的なウォーカー/ミューテータの実装。

読者向けメモ

メモリ管理とライフタイム

  • evaluate_expr や inline_function などの処理は、一時的なメモリ割り当てを大量に行うため、専用の短期ライフタイムコンテキスト（AllocSetContextCreate で作成する inline_function コンテキストや、EState のクエリコンテキスト）を明示的に作成し、処理終了時に一括破棄する設計になっています。これにより、プランニング中のメモリリークを防止しています。

再帰とスタックオーバーフロー対策

  • 式ツリーはユーザー入力に依存して極めて深くなる可能性があり、またSQL関数のインライン展開によってツリーが急激に肥大化することがあります。
  • そのため、主要な再帰処理の入り口（eval_const_expressions_mutator, inline_function_in_from, expr_is_nonnullable など）では、必ず check_stack_depth() を呼び出してスタックオーバーフローを防止しています。

破壊的変更（インプレース変更）

  • CommuteOpExpr などの一部のユーティリティは、渡されたノードを破壊的に（インプレースで）書き換えます。呼び出し側で元のツリーを保持する必要がある場合は、事前に copyObject を行う必要があります。
