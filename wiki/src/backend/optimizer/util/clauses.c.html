src/backend/optimizer/util/clauses.c

概要

src/backend/optimizer/util/clauses.c は、PostgreSQL のオプティマイザサブシステムにおいて、検索条件（Qualification Clauses）や式（Expressions）を操作・解析・定数畳み込み・インライン化するためのコアロジックを提供する大規模ファイルです。オプティマイザがクエリを最適化・プランツリーへ変換する過程で必要となる、式の特性判定や変数の追跡、関数展開の多くの基盤ルーチンを所有しています。

モジュール内での役割

src/backend/optimizer/util モジュール群（appendinfo.c, predtest.c, restrictinfo.c, var.c 等）の中で、clauses.c は「式ツリーの構造解析と変形」の中心的な役割を果たします。特に eval_const_expressions や contain_mutable_functions、各種 nullability 解析など、プラン作成の初期段階からファイナライズに至るまで広範囲の最適化パスから呼び出されます。

責務

  • **式および条件の解析と特性判定**: 集約関数、ウィンドウ関数、サブプラン、可変／揮発性関数、並列安全性（Parallel Safety）、漏洩防止（Leakproof）変数、非厳格（Non-strict）関数の有無を式ツリーから検出する。
  • **定数畳み込みと式変形**: eval_const_expressions および estimate_expression_value を通じて、定数式や論理式（AND/OR）、CASE 式、Coalesce 式などを評価・単純化・定数化する。
  • **関数のインライン展開**: 単純な SQL 関数や FROM 句内の関数をインライン展開し、パラメータの置換や依存関係の記録を行う。
  • **Nullability（ヌル可能性）解析**: どのリレーションや変数、クエリ出力が絶対に NULL にならないかを追跡・証明し、結合の最適化や制約除外を支援する。
  • **グループ化の競合検出**: ウィンドウ関数や GROUP BY などの集約/グループ化機構を跨いで式をプッシュダウンする際、値の同一性を壊す競合（Grouping Conflict）がないかを検証する。

重要なシンボル

抽象構文・実行状態ノード

  • BoolExpr (定義 1): 論理演算（AND, OR, NOT）を表現するノード。本ファイルでは引数の単純化や論理構造の平坦化処理の対象となる。
  • CaseExpr (定義 1): CASE 条件分岐式を表現するノード。定数条件の評価による分岐の除去や CaseTestExpr の置換最適化が行われる。
  • Const (定義 1): 定数値を保持するノード。式評価の結果やパラメータ置換によって生成される。
  • EState (定義 1): エグゼキュータの状態を管理する構造体。evaluate_expr 内で定数式の事前評価を行うために一時的な実行状態を構築する際に使用される。
  • FuncExpr (定義 1): 関数呼び出しを表現するノード。引数の位置引数化、型キャスト、インライン展開、定数畳み込みの主要なターゲットとなる。
  • RTE_FUNCTION (定義 1): 関数呼び出しを含むレンジテーブルエントリ（RangeTblEntry）。inline_function_in_from において FROM 句内の関数をインライン展開する際の対象となる。

コンテキスト構造体

  • eval_const_expressions_context (定義 67): eval_const_expressions および estimate_expression_value の実行中に使用されるコンテキスト。バインドされたパラメータ (boundParams)、依存関係記録用の PlannerInfo、アクティブな関数スタック、評価モード（安全な変換のみか、見積もり用の積極的な変換か）を保持する。
  • substitute_actual_parameters_context (定義 76): 関数インライン展開時に、仮パラメータ（Param）を実際の引数式に置換するための walker コンテキスト。引数の数、実引数リスト、使用回数を管理する。
  • substitute_actual_parameters_in_from_context (定義 83): FROM 句内の関数インライン展開において、サブクエリの階層（sublevels_up）を考慮しながらパラメータを置換するためのコンテキスト。
  • inline_error_callback_arg (定義 90): SQL 関数のインライン展開時に、エラー発生時のコールバック（sql_inline_error_callback）へ渡される引数。関数名とソースコードを保持し、スタックトレース上の位置情報を補正する。
  • max_parallel_hazard_context (定義 96): クエリ全体の並列安全性（Parallel Hazard）を判定する walker のコンテキスト。検出された最悪の危険度レベル、興味のある危険度閾値、安全とみなす PARAM_EXEC の Param ID リストを保持する。
  • grouping_walker_ctx (定義 108): expression_has_grouping_conflict で使用されるコンテキスト。グループ化の等価演算子を取得するコールバック関数 (get_eqop) とその不透明なコンテキストポインタをラップする。

制御フローとデータフロー

1. **式の前処理と定数畳み込み (eval_const_expressions)**:

  • エントリポイント eval_const_expressions から eval_const_expressions_mutator が呼び出され、式ツリーを再帰的に走査する。
  • Param ノードは boundParams から値が取得できれば Const に置換される。
  • FuncExpr や OpExpr は simplify_function を経由して、全引数が定数であれば evaluate_expr（エグゼキュータの ExecEvalExpr を利用）で事前評価される。条件を満たす単純な SQL 関数は inline_function により本体の式に置換される。
  • BoolExpr（AND/OR）は、子孫のネストを平坦化しつつ simplify_and_arguments / simplify_or_arguments で不要な定数項を除去する。

    • 2. **Nullability 解析 (find_nonnullable_vars, query_outputs_are_not_nullable)**:

  • ボトムアップおよびトップダウンの走査により、指定された式やクエリがどのリレーション/変数（Var）を NULL 不許可（Non-nullable）に強制しているかをビットマップセットのリスト（multibitmapset）として構築する。
  • 生のパースツリーに対しては、カタログ上の NOT NULL 制約（NOTNULL_SOURCE_CATALOG）や WHERE 句の安全な条件（find_subquery_safe_quals）を組み合わせて出力の非 NULL 性を証明する。

    • 3. **並列安全性チェック (max_parallel_hazard, is_parallel_safe)**:

  • max_parallel_hazard_walker がクエリツリー内の関数や構文を走査し、PROPARALLEL_UNSAFE, PROPARALLEL_RESTRICTED, PROPARALLEL_SAFE のいずれのレベルに該当するかを判定・伝播させる。

読者向けメモ

  • **メモリ管理**: inline_function や evaluate_expr などでは、一時的な処理によるメモリリークを防ぐために明示的な一時メモリコンテキスト（AllocSetContextCreate / MemoryContextDelete）が多用されている。計算結果は必要に応じて外側のコンテキストへ copyObject や datumCopy で退避される。
  • **再帰とスタックオーバーフロー対策**: 多くの walker / mutator 関数が式ツリーを深く再帰的に走査するため、随所で check_stack_depth() が呼び出されている。
