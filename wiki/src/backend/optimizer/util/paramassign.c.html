src/backend/optimizer/util/paramassign.c

概要

src/backend/optimizer/util/paramassign.c は、PostgreSQLのクエリ最適化フェーズにおいて、実行時パラメータ（PARAM_EXEC スロット）の割り当てと管理を行うモジュールです。サブクエリやネストループ間での変数（Var）やプレースホルダ（PlaceHolderVar）の授受に伴うパラメータIDの採番、および関連するデータ構造（paramExecTypes, plan_params, curOuterParams）の更新を担います。

モジュール内での役割

オプティマイザ配下のユーティリティ群（src/backend/optimizer/util/）の一部として位置づけられ、主にプラン作成フェーズ（createplan.c やサブクエリの計画化）で呼び出されます。上位クエリレベルや外部リレーションからの参照を解決し、エグゼキュータが参照する Param ノードとパラメータ型リスト（paramExecTypes）を一元的に結び付けます。

責務

  • **PARAM_EXEC スロットの管理**: 全プラン共通の root->glob->paramExecTypes リストを管理し、パラメータ型（またはシグナル用の InvalidOid）のOidを割り当てる。
  • **プランパラメータの追跡（plan_params）**: 下位サブクエリへ供給すべき Var や PlaceHolderVar などの式を PlannerParamItem として一時記録する。
  • **ネストループパラメータの追跡（curOuterParams）**: ネストループの外部側から内部側へ引き渡すべきパラメータを NestLoopParam として管理し、適切な NestLoop プランノード作成時に回収する。
  • **各種式に対する Param 置換**: Var, PlaceHolderVar, Aggref, GroupingFunc, MergeSupportFunc, ReturningExpr などの上位参照式を PARAM_EXEC 型の Param ノードに置換する。

重要なシンボル

パラメータ割当・式置換関数 (Tier 1 含む)

  • **replace_outer_var** (function): varlevelsup > 0 の非ローカルな Var を受け取り、assign_param_for_var を用いて plan_params に登録または既存IDを再利用した上で、対応する PARAM_EXEC 型の Param ノードを生成・返却する。
  • **replace_outer_placeholdervar** (function): phlevelsup > 0 の非ローカルな PlaceHolderVar を受け取り、assign_param_for_placeholdervar を経由して PARAM_EXEC の Param ノードに置換する。
  • **replace_outer_agg** (function): 上位クエリを参照する Aggref を PARAM_EXEC の Param に置換する（集約参照の重複排除は行わず毎回新規スロットを割り当てる）。
  • **replace_outer_grouping** (function): 上位クエリを参照する GroupingFunc を PARAM_EXEC の Param に置換する。
  • **replace_outer_merge_support** (function): MERGE クエリの RETURNING リストに含まれる MergeSupportFunc を上位クエリの PARAM_EXEC スロットに割り当てる。
  • **replace_outer_returning** (function): 上位クエリを参照する ReturningExpr を PARAM_EXEC の Param に置換する。
  • **replace_nestloop_param_var** (function): ネストループ外部から供給される Var を curOuterParams と照合し、既存であればそのスロットIDを再利用、新規であれば generate_new_exec_param でスロットを確保して NestLoopParam として登録する。
  • **replace_nestloop_param_placeholdervar** (function): replace_nestloop_param_var と同様に、ネストループ外部から供給される PlaceHolderVar を PARAM_EXEC に置換して curOuterParams に登録する。
  • **Aggref, GroupingFunc, PlaceHolderVar, Var, ReturningExpr, MergeSupportFunc** (symbol): 置換対象となる各種式ノードのデータ構造および型定義。
  • **PARAM_EXEC** (symbol): エグゼキュータ実行時に内部パラメータ配列から値を取得することを示すパラメータ種別マクロ。
  • **Param** (symbol): クエリツリー内でパラメータ参照を表すノード構造体。
  • **PlannerParamItem** (symbol): サブクエリレベル間で受け渡される式と paramId の対応を保持する構造体。
  • **NestLoopParam** (symbol): ネストループの左側（外側）から右側へ渡されるパラメータの情報を保持する構造体。
  • **InvalidOid** (symbol): 実行時に値を持たずシグナル目的でのみ使用される PARAM_EXEC スロット等で用いられる無効なOid値。
  • **MERGE, RETURNING** (symbol): MERGE コマンドおよび RETURNING 句に関連する定数・コマンド種別。

内部ヘルパーおよび補助関数

  • **assign_param_for_var**: 指定された Var に対応する plan_params 内のエントリを探すか、なければ新規に PlannerParamItem を作成し paramExecTypes に追加する。
  • **assign_param_for_placeholdervar**: PlaceHolderVar 版のパラメータ割当ヘルパー。
  • **process_subquery_nestloop_params**: FROM句内のパラメータ付きサブクエリ要求を処理し、LATERAL参照が外部ネストループの対象リレーションから供給されることを検証した上で curOuterParams に追加する。
  • **identify_current_nestloop_params**: 指定された左側リレーション（leftrelids）および要求外側リレーションから供給可能な NestLoopParam を curOuterParams から抽出して削除・返却する。
  • **generate_new_exec_param**: 重複しない新規の PARAM_EXEC 用 Param ノードを生成し、paramExecTypes に型を登録する。
  • **assign_special_exec_param**: 実行時に実際の値を運ばない特殊なシグナル用（再帰unionのワークテーブルスキャンやEPQ用など）の PARAM_EXEC スロット（InvalidOid）を割り当てる。

制御フローとデータフロー

1. **上位参照の置換**:

  • プランナが下位のサブクエリや式を処理する際、外側の変数（Var, PlaceHolderVar, Aggref 等）に遭遇すると、対応する replace_outer_* 関数を呼び出す。

    • 2. **スロットの割り当てと記録**:

  • 各置換関数は対象のクエリレベルまで parent_root を辿り、既存の plan_params に同一の式が登録されているか確認する。
  • 既存であれば既存の paramId を流用し、新規であれば root->glob->paramExecTypes に型のOidを追加して新しい paramId（リスト長ベース）を採番する。

    • 3. **ネストループパラメータの伝播**:

  • createplan.c 等でネストループプランを構築する際、identify_current_nestloop_params が呼ばれ、curOuterParams から該当する Var や PlaceHolderVar が回収される。
  • サブクエリ内のLATERALパラメータについては process_subquery_nestloop_params によって検証され、親の curOuterParams に引き継がれる。

読者向けメモ

  • **メモリ所有権とライフタイム**: root->glob->paramExecTypes はプラン全体（PlannerGlobal）に属し、プランニング中永続的に保持される。一方 root->plan_params は各サブクエリの計画化完了後にリセットされ、root->curOuterParams はネストループプランノードが生成される際に消費・削除される。
  • **重複排除のポリシー**: Var と PlaceHolderVar については同一クエリレベル内での plan_params による重複排除（デデュプリケーション）が行われるが、Aggref や ReturningExpr などは重複排除を行わず毎回新規の PARAM_EXEC スロットを割り当てる設計になっている。
