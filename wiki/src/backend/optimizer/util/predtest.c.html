src/backend/optimizer/util/predtest.c

概要

PostgreSQLのオプティマイザにおいて、述語式（predicate expressions）および制限節（restriction clauses）の間の論理的含意（implication）や反駁（refutation）を証明するためのルーチン群を提供する。WHERE 節の絞り込み、チェック制約（CHECK constraints）の包含関係、パーティションプルーニングの検証において、式が他の式を論理的に満たすか、あるいは矛盾するかを判断する役割を担う。

モジュール内での役割

src/backend/optimizer/util ディレクトリ配下に位置し、式ツリーの操作や最適化を支える。clauses.c などの周辺モジュールと協調し、インデックス述語とクエリ条件の重複排除や不要な制約チェックの省略を判定する。

責務

  • 含意証明 (Implication Proofs): ある節リストが与えられたとき、対象の述語が真（または非偽）になることを証明する（predicate_implied_by）。
  • 反駁証明 (Refutation Proofs): ある節リストが与えられたとき、対象の述語が偽（または非真）になることを証明する（predicate_refuted_by）。
  • 式構造の分類と反復処理: AND、OR、アトム、ScalarArrayOpExpr などの複雑な式を抽象化し、共通のイテレータ機構で走査する。
  • Bツリー演算子キャッシュ: 演算子ファミリーに基づく推論結果とテスト演算子の検索結果をキャッシュし、システムカタログ (pg_amop) の変更時に無効化する。

重要なシンボル

分類と反復機構

  • enum PredClass (定義線 51): 式の論理構造を CLASS_ATOM（アトム）、CLASS_AND（AND構造）、CLASS_OR（OR構造）に分類する。
  • struct PredIterInfo / PredIterInfoData (定義線 58, 60): ノード型固有の反復状態 (state) と、初期化 (startup_fn)・次要素取得 (next_fn)・クリーンアップ (cleanup_fn) の関数ポインタを保持する。
  • function CLASS_AND / CLASS_ATOM / CLASS_OR (定義線 1): PredClass の列挙子。式分類の結果として返される。
  • macro MAX_SAOP_ARRAY_SIZE (定義线 34): ScalarArrayOpExpr を配列要素の展開による AND/OR 構造として扱う上限サイズ（100）。これを超える場合はアトムとして扱う。

配列展開型イテレータ

  • struct ArrayConstIterState (定義線 950): 定数配列を伴う ScalarArrayOpExpr を要素単位の OpExpr に展開しながら走査するための作業状態。
  • struct ArrayExprIterState (定義線 1037): 1次元の ArrayExpr を伴う ScalarArrayOpExpr を走査するための状態。

演算子証明キャッシュ

  • struct OprProofCacheKey (定義線 2076): 述語演算子 (pred_op) と節演算子 (clause_op) を組み合わせたハッシュ検索キー。
  • struct OprProofCacheEntry (定義線 2082): 演算子ペアごとの含意・反駁の判定結果やテスト演算子（implic_test_op, refute_test_op）の OID を保持するキャッシュエントリ。
  • function InvalidateOprProofCacheCallBack (定義線 2347): pg_amop の変更に伴うシステムキャッシュ無効化コールバック。ハッシュエントリのキャッシュ状態をリセットする。

制御フローとデータフロー

1. エントリーポイント: クエリ最適化プロセスから predicate_implied_by() または predicate_refuted_by() が呼び出され、トップレベルのリスト構造が単一要素かどうかの正規化が行われる。 2. 再帰的評価: predicate_implied_by_recurse() / predicate_refuted_by_recurse() が呼び出される。predicate_classify() を用いて両辺の式を CLASS_AND、CLASS_OR、CLASS_ATOM に分類し、定義された論理規則に従ってインターリーブされた再帰処理を行う。 3. 単純節の証明: アトム同士の比較に達すると、predicate_implied_by_simple_clause() または predicate_refuted_by_simple_clause() に移行する。 4. 演算子推論: 同一のサブ式や定数比較を含む二項演算子に対しては、operator_predicate_proof() が実行され、Bツリーのオプファミリとキャッシュ (lookup_proof_cache) を介してテスト用演算子を特定し、エグゼキュータで定数評価を行う。

読者向けメモ

  • メモリ管理: operator_predicate_proof() 内でのテスト評価には一時的な EState を作成し、クエリコンテキストで評価後に FreeExecutorState で解放することでメモリリークを防いでいる。
  • 不変性（Immutability）の制約: 述語や演算子は原則として不変（IMMUTABLE）であることが前提とされる。プラン作成時と実行時での評価の不整合を防ぐため、安定（STABLE）なクロスタイプ演算子は推論から除外される。
  • インタラプト安全性: 長大な再帰的証明や配列展開時に CHECK_FOR_INTERRUPTS() が適宜呼び出され、クエリのキャンセル要求に応答できるよう配慮されている。
