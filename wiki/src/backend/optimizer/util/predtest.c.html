src/backend/optimizer/util/predtest.c

概要

predtest.c は、述語式（predicate expressions）と制限句（restriction clauses）の論理的含意（Implication）や反駁（Refutation）を証明するためのルーティンを提供する。オプティマイザが不要なチェック制約を排除したり、インデックス条件の包含関係を検証したりするために使用される。

モジュール内での役割

src/backend/optimizer/util サブシステムの一部として、節（clause）同士の関係性を静的に解析し、クエリの最適化や制約除外（constraint exclusion / partition pruning）を支える判定ロジックを担う。

責務

  • **含意の判定 (predicate_implied_by)**: ある条件リストが指定の述語を強・弱の定義で満たす（含意する）かを再帰的に判定する。
  • **反駁の判定 (predicate_refuted_by)**: ある条件リストが指定の述語を偽にする（反駁する）かを再帰的に判定する。
  • **式構造の分類とイテレーション**: PredClass と PredIterInfo を用いて、AND/OR、リスト、および ScalarArrayOpExpr（配列定数や配列式）を統一的にイテレートする。
  • **演算子関係のキャッシュと証明**: B-tree演算子ファミリや可換・否定関係、定数比較を用いた単項・二項の証明 (operator_predicate_proof) を行い、結果をハッシュキャッシュ (OprProofCacheHash) で管理する。

重要なシンボル

公開エントリポイント

  • bool predicate_implied_by(List *predicate_list, List *clause_list, bool weak)
  • bool predicate_refuted_by(List *predicate_list, List *clause_list, bool weak)

内部反帰・分類シンボル

  • enum PredClass: 式の分類（CLASS_ATOM, CLASS_AND, CLASS_OR）。
  • struct PredIterInfoData: イテレーション用コールバックとステートを保持する構造体。
  • macro iterate_begin, macro iterate_end: イテレーションを抽象化する制御マクロ。
  • static bool predicate_implied_by_recurse(Node *clause, Node *predicate, bool weak)
  • static bool predicate_refuted_by_recurse(Node *clause, Node *predicate, bool weak)
  • static PredClass predicate_classify(Node *clause, PredIterInfo info)

配列・演算子処理関連

  • struct ArrayConstIterState, struct ArrayExprIterState: ScalarArrayOpExpr 展開時のステート。
  • static bool operator_predicate_proof(Expr *predicate, Node *clause, bool refute_it, bool weak)
  • struct OprProofCacheEntry, struct OprProofCacheKey: B-tree証明結果のルックアップキャッシュ構造体。
  • static void InvalidateOprProofCacheCallBack(...): pg_amop のカタログ変更に伴うキャッシュ無効化コールバック。

制御フローとデータフロー

1. **トップレベル評価**: predicate_implied_by または predicate_refuted_by がリストを受け取り、単一要素のアンラップを経て _recurse 関数に渡す。 2. **分類と走査**: predicate_classify() が式を CLASS_AND, CLASS_OR, CLASS_ATOM に分類し、必要に応じて PredIterInfo にカスタムスタートアップ・ネクスト関数を設定する。 3. **ツリー横断**: iterate_begin / iterate_end マクロを介して、AND/OR 構造をインターリーブしながら再帰的にマッチングを行う。 4. **アトム評価**:

  • 単純な同値性 (equal()) やブール比較の検証。
  • 厳格性（Strictness）のチェック (clause_is_strict_for)。
  • 2つの二項演算子式の場合、B-tree演算子ファミリの含意/反駁テーブル (RC_implies_table, RC_refutes_table) とキャッシュを参照するか、定数同士の比較テスト (get_btree_test_op) を実行する。

読者向けメモ

  • **パフォーマンスと制限**: MAX_SAOP_ARRAY_SIZE（100）を超える要素を持つ ScalarArrayOpExpr は、O(N^2) の肥大化を防ぐためにアトムとして扱われ、含意証明から除外される。
  • **メモリ管理**: operator_predicate_proof 内では一時的な EState を生成して式評価を行い、クエリコンテキストや MemoryContextSwitchTo を用いてメモリリークを防いでいる。また、キャッシュエントリは AMOPOPID のシステムキャッシュ無効化時にリセットされる。
