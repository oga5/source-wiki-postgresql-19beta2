src/backend/optimizer/util/pathnode.c

概要

src/backend/optimizer/util/pathnode.c は、PostgreSQLのクエリ最適化フェーズにおいて、実行計画の候補となるパス（Path ノードおよびその派生構造体）を生成し、操作・管理するための主要な関数群を提供するソースファイルである。オプティマイザのサブシステム内において、各リレーションに対する多様なアクセス方式や結合方式のパスを構築し、それらを比較・トーナメント評価して最適なものを選択する責務を持つ。

モジュール内での役割

src/backend/optimizer/util モジュール配下において、本書はパスノードのファクトリ、コスト比較、およびパスリストの管理（add_path, set_cheapest）を担当する中核ファイルである。

  • ヘッダファイル src/include/optimizer/pathnode.h とペアをなし、他のオプティマイザコンポーネント（path/ や plan/ 配下）に対してパス生成APIを公開する。
  • スキャン系、結合系、および各種修飾（ソート、集約、射影等）の Path ノードを生成し、コストモデル（cost.c）を呼び出してコストと行数を見積もる。

責務

  • **パスの生成 (Path Creation)**:
  • スキャンパス（SeqScan, IndexScan, BitmapHeap, Tid, Function, CTE, Foreign 等）の生成。
  • 結合パス（NestPath, MergePath, HashPath）の生成。
  • 上位処理パス（Append, GroupResult, Material, Memoize, Gather, Sort, Agg, WindowAgg, SetOp, Limit 等）の生成。
  • **パストーナメントとフィルタリング (Path Management)**:
  • add_path() および add_partial_path() による、冗長または劣後するパスの排除（ドミネーション判定）。
  • 無駄になった Path ノードのメモリ解放（pfree）。ただし IndexPath は共有される場合があるため除外する。
  • **コスト比較とファジィ判定 (Cost Comparison & Fuzziness)**:
  • compare_path_costs() および compare_path_costs_fuzzily() による、浮動小数点誤差を考慮したコスト評価。
  • **リパラメータライゼーション (Reparameterization)**:
  • パーティション分割や継承テーブルに関連する、子リレーションへのパラメータ付きパスの変換 (reparameterize_path_by_child 等)。

重要なシンボル

パス管理・比較ファミリー

  • PathCostComparison (enum): コスト比較の結果（COSTS_EQUAL, COSTS_BETTER1, COSTS_BETTER2, COSTS_DIFFERENT）。
  • compare_path_costs(): 2つのパスの指定されたコスト基準（起動コストまたはトータルコスト）を比較する。
  • compare_fractional_path_costs(): 指定されたタプル取得割合を考慮してパスコストを比較する。
  • set_cheapest(): リレーションの pathlist から最小コストの起動・トータルパス、およびパラメータ化パスのリストを抽出し、RelOptInfo に設定する。
  • add_path() / add_partial_path(): 新規パスが既存パスを支配しているか、または支配されているかを判定し、pathlist / partial_pathlist を更新する。
  • add_path_precheck() / add_partial_path_precheck(): パス本体を構築する前に、下限コスト等を用いて早期に棄却可能かを判定する。

アクセスパス生成ファミリー

  • create_seqscan_path(): シーケンシャルスキャンパスを作成。
  • create_index_path(): インデックススキャンパス（IndexPath）を作成。
  • create_bitmap_heap_path(), create_bitmap_and_path(), create_bitmap_or_path(): ビットマップスキャン関連のパスを作成。
  • create_tidscan_path(), create_tidrangescan_path(): TIDスキャンパスを作成。
  • create_foreignscan_path(), create_foreign_join_path(), create_foreign_upper_path(): 外部データラッパー（FDW）用のパスを作成。

結合パス生成ファミリー

  • calc_nestloop_required_outer() / calc_non_nestloop_required_outer(): ネストループやハッシュ／マージ結合における要求外部リレーション（required_outer）を計算。
  • create_nestloop_path(): ネストループ結合パス（NestPath）を作成。
  • create_mergejoin_path(): マージ結合パス（MergePath）を作成。
  • create_hashjoin_path(): ハッシュ結合パス（HashPath）を作成。

上位・処理パス生成ファミリー

  • create_append_path(), create_merge_append_path(): Append / MergeAppend パスを作成し、必要に応じてコスト順にソート。
  • create_sort_path(), create_incremental_sort_path(): ソートおよびインクリメンタルソートパスを作成。
  • create_agg_path(), create_group_path(), create_groupingsets_path(): 集約・グループ化パスを作成。
  • create_limit_path(): LIMIT / OFFSET 処理パスを作成。
  • reparameterize_path_by_child(): 親リレーション用のパラメータ化パスを、子リレーション（パーティション）用に変換・調整する。

制御フローとデータフロー

1. **パス生成の起点**: オプティマイザの各探索フェーズ（例: query_planner や結合探索）から、各種 create_*_path 関数が呼び出される。これらは対応する makeNode() でメモリを確保し、cost_* 関数を呼び出してコストフィールドを埋める。 2. **パスの登録 (Tournament)**: 生成されたパスは add_path() に渡される。

  • add_path() は既存の pathlist 内の各パスと compare_path_costs_fuzzily() および compare_pathkeys() を用いて比較を行う。
  • 新規パスが既存パスを優越（ドミネート）していれば、既存パスを pathlist から削除し、不必要な構造でなければ pfree() でメモリを回収する（例外として IndexPath は子として共有されるため解放しない）。
  • 逆に既存パスが新規パスを優越していれば、新規パスの追加を拒否して解放する。

    • 3. **最終選択**: すべてのパスが出揃った後、set_cheapest() が呼ばれ、リレーションごとの最安値パス（cheapest_total_path, cheapest_startup_path 等）が確定される。

読者向けメモ

  • **メモリ管理**: 破棄される Path オブジェクトは即座に pfree() される。ただし、複数箇所から参照されうる IndexPath などは、意図的にこの即時解放の対象外とされている。
  • **ファジィコスト比較**: 浮動小数点の丸め誤差に起因するプラットフォーム依存の不安定なプラン変動を防ぐため、僅かな差は STD_FUZZ_FACTOR（1.01）などを用いたファジィ比較によって等価とみなされる。
  • **並列処理の前提**: add_partial_path() は並列ワーカーで実行可能な部分パスを管理し、非パラメータ化かつ並列安全なパスのみを対象とする。
