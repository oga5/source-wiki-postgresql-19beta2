src/backend/optimizer/util/pathnode.c

概要

PostgreSQLのクエリパーサ/オプティマイザにおいて、実行計画の候補を表す Path ノードの生成、コスト比較、およびリレーションへの登録・選抜を行う。クエリツリーの走査過程で作成されるスキャンパス、ジョインパス、および各種演算子パス（ソート、集約、ウィンドウ関数など）の構築を一手に引き受ける。

モジュール内での役割

src/backend/optimizer/util/ ディレクトリ配下に位置し、近隣の relnode.c（リレーション構造の管理）や clauses.c（条件式の操作）と密接に連携する。pathnode.h とペアをなし、オプティマイザが具体的な実行計画のツリー構造へ落とし込む前段階として、どのアルゴリズムと順序でデータを取得・処理すべきかを評価する基盤を提供する。

責務

  • 各種スキャン（SeqScan, IndexScan, BitmapScan, TidScan, ForeignScan等）の Path ノード生成。
  • 各種ジョイン（NestLoop, MergeJoin, HashJoin）および上流演算（Agg, Group, Sort, Limit, WindowAgg等）の Path ノード生成。
  • パス間のコスト比較（ファジィ比較を含む）と、リレーションの pathlist / partial_pathlist への最適パス選抜登録 (add_path, add_partial_path)。
  • パーティション分割統治（Partitionwise Join）や Append 処理に伴うパスの再パラメータ化 (reparameterize_path, reparameterize_path_by_child)。

重要なシンボル

コスト比較・パス選択関連

  • PathCostComparison: 2つのパスのコスト優劣関係（COSTS_EQUAL, COSTS_BETTER1, COSTS_BETTER2, COSTS_DIFFERENT）を表す列挙型。
  • COSTS_BETTER1 / COSTS_BETTER2 / COSTS_DIFFERENT / COSTS_EQUAL: compare_path_costs_fuzzily 内で使われる比較結果の判定マクロ／定数。これらは add_path および add_partial_path のパス淘汰トーナメントの根幹をなす。

主要なパスノード構造体生成・管理

  • RelOptInfo: クエリ内の単一または結合リレーションの計画状態を保持する中央データ構造。pathlist や cheapest_total_path などの管理対象となる。
  • IndexPath: インデックススキャンを表すパスノード。create_index_path で生成される。他のパスとは異なり、BitmapHeapPath 等の子として共有参照されるため、破棄時に即座に pfree されない例外処理を持つ。
  • NestPath: ネストループ結合を表すパスノード。
  • MergePath: マージ結合を表すパスノード。
  • HashPath: ハッシュ結合を表すパスノード。
  • pathlist: リレーションが持つ通常パスのリスト。disabled_nodes と total_cost の昇順でソートを維持される。
  • partial_pathlist: 並列実行可能な部分的パスのリスト。

制御フローとデータフロー

1. パスの生成: オプティマイザの各フェーズ（例: gplsa.c や joinrels.c）が create_XXX_path() を呼び出し、必要なパラメータや PathTarget を元に特定の Path ノードを割り当てる。 2. パスの追加と選抜 (add_path / add_partial_path):

  • 生成された new_path は parent_rel->pathlist に既存する old_path と比較される。
  • compare_path_costs_fuzzily を用いて、一定の許容誤差（STD_FUZZ_FACTOR = 1.01）内でコスト優劣や支配関係を評価する。
  • new_path が既存の old_path を支配する場合、old_path は pathlist から削除され、不要になったメモリは pfree される（IndexPath を除く）。
  • 逆に old_path が優る場合は新規パスが破棄される。
  • 生存したパスは disabled_nodes および total_cost の順序を保つ位置に挿入される。

    • 3. 最安パスの確定 (set_cheapest):

  • パス探索が完了した後、set_cheapest が pathlist を走査し、最安コストのトータルパス (cheapest_total_path)、最安起動コストパス (cheapest_startup_path)、およびパラメータ化されたパスの集合を選出して RelOptInfo に格納する。

読者向けメモ

  • メモリ管理の注意点: add_path および add_partial_path において、劣ったと判定された Path ノードは即座に pfree() される。ただし、IndexPath のみ BitmapHeapPath から参照共有される可能性が残るため、誤解放を防ぐ例外処理（!IsA(old_path, IndexPath)）が組み込まれている。
  • ファジィ比較: 浮動小数点計算による環境依存の計画変動を抑えるため、厳密な等価ではなく STD_FUZZ_FACTOR（1%の許容差）を用いたファジィコスト比較が標準採用されている。
