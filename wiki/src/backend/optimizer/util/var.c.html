src/backend/optimizer/util/var.c

概要

src/backend/optimizer/util/var.c は、PostgreSQLのオプティマイザにおいて Var ノードおよび関連する式要素（PlaceHolderVar、CurrentOfExpr、ReturningExpr 等）の操作、抽出、および置換を行うルーチン群を提供するソースファイルです。式ツリーの走査を通じて変数の参照関係を解析する機能や、結合（JOIN）やグループ化（GROUP BY）のエイリアス変数を元の式へと展開する機能を所有しています。

モジュール内での役割

src/backend/optimizer/util モジュール内において、本ファイルは式に含まれる変数や相関参照の特定・書き換えを担うユーティリティ基盤です。プラン生成前の前処理や、プランナ内部での条件式の押し下げ（pushdown）、定数畳み込み、および結合・グループ化の抽象化レイヤと密接に連携します。

責務

  • **変数・リレーションIDの抽出**: パースツリーや式ツリーから、特定のクエリレベルに属する Var ノードや参照先リレーションID（varnos）、属性番号（varattnos）をビットマップ（Relids / Bitmapset）として収集する。
  • **変数の存在・レベル判定**: 指定されたクエリレベルの変数や、OLD/NEW 戻り値を持つ変数が式内に含まれているかを再帰的に判定・探索する。
  • **エイリアス展開 (Flattening)**:
  • 結合（RTE_JOIN）を参照する Var ノードを、元のベースリレーションや式に展開する (flatten_join_alias_vars)。
  • グループ化（RTE_GROUP）を参照する Var ノードを、基底となるグループ化式に置き換える (flatten_group_exprs)。
  • **NULLing関係の維持**: 外部結合やグループ化による外部化（varnullingrels / phnullingrels）を、展開された式や PlaceHolderVar に対して適切に伝播・付与する。

重要なシンボル

コンテキスト構造体

  • struct pull_varnos_context: pull_varnos および pull_varnos_of_level で使用される走査コンテキスト。収集されたリレーションID集合（varnos）、PlannerInfo ポインター（root）、および対象のクエリ階層差（sublevels_up）を保持する。
  • struct pull_varattnos_context: 特定のリレーション（varno）に対する属性番号のビットマップ（varattnos）を蓄積するためのコンテキスト。
  • struct pull_vars_context: 指定されたクエリレベルの Var および PlaceHolderVar ノードのリスト（vars）を収集する。
  • struct locate_var_of_level_context: エラー報告用に、指定レベルの変数のソースコード上のパース位置（var_location）を特定・保持する。
  • struct pull_var_clause_context: pull_var_clause において集約関数、ウィンドウ関数、プレースホルダーなどの扱いを指定するフラグ（flags）と、抽出されたノードのリスト（varlist）を管理する。
  • struct flatten_join_alias_vars_context: 結合やグループ化のエイリアス展開を行う際に、クエリ構造（query）、プランナ情報（root）、現在の階層差、およびサブリンクの有無に関するフラグを保持する。

主要な関数（Tier 1）

  • function Var: PostgreSQLのクエリツリーにおけるテーブル列参照を表すノード構造体、およびその操作の基本単位。
  • function Relids: リレーションIDの集合を表す Bitmapset * の型エイリアス。
  • function PlaceHolderVar: 式の評価位置を遅延・固定化するためのプレースホルダーノード。本モジュールでは varnos 抽出やエイリアス展開時に特別な位置計算の対象となる。
  • function RowExpr: 結合の全体行参照（whole-row Var）を展開する際に生成される行構築式ノード。
  • function sublevels_up: 変数ノードがどのクエリレベル（サブクエリの深さ）から参照されているかを示す Var などのフィールド。
  • function ph_eval_at: プレースホルダー変数が実際に評価されるべきリレーションの集合を表す PlaceHolderInfo のフィールド。

制御フローとデータフロー

本ファイルの多くの関数は、PostgreSQLの共通インフラストラクチャである expression_tree_walker / query_tree_walker（または query_or_expression_tree_walker）を利用した再帰的なウォーカー・モテーターパターンを採用しています。

1. **抽出フロー (pull_*)**:

  • pull_varnos や pull_vars_of_level などのエントリポイントは、対応するコンテキスト構造体を初期化し、query_or_expression_tree_walker を呼び出します。
  • ウォーカー関数（例: pull_varnos_walker）は、ノードが Var や PlaceHolderVar であれば対象の sublevels_up と一致するか検証し、一致すれば結果の集合やリストに追加します。
  • Query ノードに出会った場合は sublevels_up をインクリメントしてサブクエリ内へ再帰します。

2. **エイリアス展開フロー (flatten_*)**:

  • flatten_join_alias_vars や flatten_group_exprs は、式ツリーを _mutator 関数で走査します。
  • Var ノードが RTE_JOIN または RTE_GROUP を指している場合、レンジテーブルエントリ（rtable）から対応する式リスト（joinaliasvars または groupexprs）を取得し、元の変数や式に置き換えます。
  • 展開された式に対して、元の変数が持っていた外部結合やグループ化によるヌル化情報（varnullingrels）を add_nullingrels_if_needed または mark_nullable_by_grouping を通じて再適用します。標準的な式構造であれば直接 Var や PlaceHolderVar のフラグを更新し、複雑な式であれば PlaceHolderVar でラップします。

直接依存

  • postgres.h: 基本的なPostgreSQLの型定義、マクロ、メモリ管理、エラー報告（elog, Assert）のインフラ。
  • access/sysattr.h: システム属性（OID等）の低位無効属性番号（FirstLowInvalidHeapAttributeNumber）の定義。
  • nodes/nodeFuncs.h: ノードツリーの走査・変形を行う expression_tree_walker, query_tree_walker, IncrementVarSublevelsUp 等の関数群。
  • optimizer/clauses.h: 節（clause）の解析や集約・ウィンドウ関数の検出関数。
  • optimizer/optimizer.h: PlannerInfo 構造体の定義とオプティマイザ共通定義。
  • optimizer/placeholder.h: プレースホルダー式（PlaceHolderVar, PlaceHolderInfo）の作成・管理関数。
  • optimizer/prep.h: クエリ前処理に関連する関数群。
  • parser/parsetree.h: Query, RangeTblEntry, Var 等のパーサ/プランナの基本ノード構造体定義。
  • rewrite/rewriteManip.h: ルール書き換え・操作ユーティリティ。

関連コード

  • src/backend/optimizer/util/clauses.c: 式や節の性質を評価・操作する、本ファイルと並ぶ主要なユーティリティ。
  • src/backend/optimizer/util/placeholder.c: プレースホルダーのライフサイクルと評価位置を管理するモジュール。

読者向けメモ

  • **メモリ管理**: 本ファイル内の抽出関数（pull_vars_of_level, pull_var_clause 等）が返すリストや、ウォーカーが集積する Bitmapset は、呼び出し元のコンテキストメモリ（通常は CurrentMemoryContext）上でアロケートされます。また、ノード自体のディープコピーには copyObject が使用されます。
  • **上位レベル変数（Uplevel references）**: varlevelsup > 0 を持つ変数は相関サブクエリの参照を表します。一部の関数（例: pull_var_clause）では、特定のフェーズ以降に出現してはならない上位レベル変数を検出した際に elog(ERROR) で異常終了する不変条件（invariant）を持っています。
