src/backend/optimizer/util/var.c

概要

src/backend/optimizer/util/var.c は、PostgreSQLのオプティマイザにおいて、式木（Expression Trees）やクエリツリー（Query Trees）に含まれる Var（変数）ノード、PlaceHolderVar（プレースホルダ変数）ノード、および CurrentOfExpr などの変数参照ノードを走査、抽出、検査、および置換（フラット化）するためのユーティリティ関数群を提供するファイルである。

モジュール内での役割

src/backend/optimizer/util サブシステムに属し、プランナやオプティマイザの各フェーズ（特に式の正規化、プッシュダウン、結合やグループ化の最適化）において、式木からどのリレーションや属性が参照されているかを特定するための低水準な基盤を提供する。また、パーサやリライタが生成した結合エイリアスやグループ化出力を、プラン作成前に元のベースリレーションや式へと展開する役割を担う。

責務

本ファイルの責務は、以下の3つの役割グループに大別される。

1. 変数・リレーション情報の抽出 (Extraction & Collection)

  • 式木やクエリツリーから、参照されているリレーションID（varno）の集合（Relids ビットマップ）を収集する。
  • 特定の varno に対する属性番号（varattno）の集合（Bitmapset）を収集する。システム属性（OIDなど）を処理するため、属性番号は FirstLowInvalidHeapAttributeNumber でオフセットされる。
  • 指定されたクエリ階層レベル（sublevels_up）に合致する Var や PlaceHolderVar のポインタリストを構築する。

2. 存在検査と位置特定 (Inspection & Location)

  • 式木内に特定のクエリレベルの変数が含まれているかを高速に判定する。
  • エラー報告などのために、指定されたレベルの変数がパースされたソースコード上の位置（location）を探索する。
  • VAR_RETURNING_OLD や VAR_RETURNING_NEW などの特殊な返却型を持つ変数の存在を検出する。

3. 結合エイリアスおよびグループ化式のフラット化 (Flattening & Substitution)

  • RTE_JOIN（結合）の出力を参照する Var ノードを、元のベースリレーションの変数や RowExpr（全体行参照の場合）へと再帰的に置換する。
  • RTE_GROUP（グループ化）の出力を参照する Var ノードを、元のグループ化式へと置換する。
  • 置換の際、外部結合やグループ化セットによって生じるヌル化情報（varnullingrels）を適切に維持・伝播させる。

重要なシンボル

コンテキスト構造体

  • struct pull_varnos_context: pull_varnos 走査時に、収集した varnos、プランナ情報 root、および現在の相対クエリレベル sublevels_up を保持する。
  • struct pull_varattnos_context: pull_varattnos 走査時に、対象の varno と収集した属性番号のビットマップ varattnos を保持する。
  • struct pull_vars_context: pull_vars_of_level 走査時に、合致した Var / PlaceHolderVar のリストを保持する。
  • struct pull_var_clause_context: pull_var_clause 走査時に、抽出フラグ（flags）と抽出されたノードリスト（varlist）を保持する。
  • struct flatten_join_alias_vars_context: 結合エイリアスやグループ化式の置換処理において、プランナ情報、クエリツリー、相対クエリレベル、およびサブリンクの有無を追跡する。

抽出・検査関数 (API)

  • pull_varnos(PlannerInfo *root, Node *node) / pull_varnos_of_level(PlannerInfo *root, Node *node, int levelsup): 式木から重複のないリレーションIDのビットマップセット（Relids）を生成する。PlaceHolderVar の評価位置（ph_eval_at）も考慮する。
  • pull_varattnos(Node *node, Index varno, Bitmapset **varattnos): 指定された varno に対応する属性番号をビットマップに蓄積する。
  • pull_vars_of_level(Node *node, int levelsup): 指定されたクエリレベルの Var および PlaceHolderVar のリストを返す。
  • contain_var_clause(Node *node) / contain_vars_of_level(Node *node, int levelsup): 指定レベルの変数が含まれるかを判定する。
  • locate_var_of_level(Node *node, int levelsup): 指定レベルの変数のパース位置（location）を返す。
  • pull_var_clause(Node *node, int flags): PVC_INCLUDE_... などのフラグ制御に基づき、式木から変数、集約関数、ウィンドウ関数、プレースホルダを抽出する。

置換・フラット化関数 (API)

  • flatten_join_alias_vars(PlannerInfo *root, Query *query, Node *node): 結合出力を参照する Var を元のベースリレーション変数や RowExpr に置換する。
  • flatten_join_alias_for_parser(Query *query, Node *node, int sublevels_up): パーサ段階で結合エイリアスを展開するための root を持たないバリアント。
  • flatten_group_exprs(PlannerInfo *root, Query *query, Node *node): グループ化出力を参照する Var を元のグループ化式に置換する。
  • add_nullingrels_if_needed(PlannerInfo *root, Node *newnode, Var *oldvar) / mark_nullable_by_grouping(PlannerInfo *root, Node *newnode, Var *oldvar): 置換後の式に対して、元の Var が持っていた varnullingrels をマージするか、必要に応じて PlaceHolderVar でラップしてヌル化情報を付与する。

制御フローとデータフロー

1. ウォーカーパターンによる再帰走査 (Walker Pattern)

pull_varnos_walker や pull_vars_walker などの内部ヘルパー関数は、query_or_expression_tree_walker または expression_tree_walker を用いて、式木を深さ優先で再帰走査する。

[API: pull_varnos]
       │
       ▼
[query_or_expression_tree_walker] ──(再帰走査)──► [pull_varnos_walker]
                                                        │
       ┌────────────────────────────────────────────────┴────────────────────────┐
       ▼ (Varノード)                                    ▼ (Queryノード: サブクエリ)
  対象レベルなら                                       sublevels_up をインクリメント
  varno と varnullingrels を                           [query_tree_walker] で再帰
  context->varnos に追加                               sublevels_up をデクリメント

2. ミューテーターパターンによる木構造の書き換え (Mutator Pattern)

flatten_join_alias_vars_mutator および flatten_group_exprs_mutator は expression_tree_mutator / query_tree_mutator を用いて、式木を走査しながら書き換える。

[API: flatten_join_alias_vars]
       │
       ▼
[flatten_join_alias_vars_mutator]
       │
       ├─► [Varノードかつ対象レベルかつRTE_JOINの場合]
       │         │
       │         ├─► [InvalidAttrNumber (全体行参照) の場合]
       │         │         RTEの joinaliasvars を走査し、各要素をコピーして再帰的にフラット化
       │         │         非ドロップ列から RowExpr を構築
       │         │
       │         └─► [通常の属性参照の場合]
       │                   RTEの joinaliasvars から対応する式を取得し、copyObject で複製
       │                   必要に応じて IncrementVarSublevelsUp でレベル調整し、再帰的にフラット化
       │
       └─► [add_nullingrels_if_needed] によるヌル化情報の付与

3. ヌル化情報の伝播フロー (Nullingrels Propagation)

結合やグループ化のフラット化において、元の Var が持っていた varnullingrels（ヌル化情報）を置換後の式に伝播させる。

[add_nullingrels_if_needed]
       │
       ├─► [is_standard_join_alias_expression] が真の場合
       │         │ (Var, PlaceHolderVar, 暗黙キャスト, CoalesceExpr など)
       │         ▼
       │   [adjust_standard_join_alias_expression]
       │         末端の Var や PlaceHolderVar の nullingrels フィールドに直接マージ
       │
       └─► 偽の場合 (変数を含まない定数式などの場合)
                 ▼
           [make_placeholder_expr]
                 式を新しい PlaceHolderVar でラップし、そこにヌル化情報を付与

読者向けメモ

メモリ所有権と生存期間

  • pull_vars_of_level や pull_var_clause などの抽出関数は、ノードの複製（ディープコピー）を行わず、**元のツリー内のノードへのポインタを直接リストに格納して返す**。そのため、呼び出し側でこれらのノードを破壊的に変更すると、元の式木が破損する。
  • 一方、flatten_join_alias_vars や flatten_group_exprs などの置換関数は、置換対象の式を copyObject で複製した上で書き換えを行うため、呼び出し側は安全に結果を変更できる。

不変条件とエラーパス

  • pull_var_clause は、サブリンクがサブプランに削減された**後**の式に対して使用されることを想定している。そのため、走査中に想定外の階層レベル（varlevelsup > 0）の Var や Aggref、PlaceHolderVar に遭遇した場合は elog(ERROR) をスローする。

PlaceHolderVar の評価位置（ph_eval_at）の解決

  • pull_varnos はプラン生成前の式に対しても呼び出される。この時点では PlaceHolderInfo がまだ構築されていない場合があり、その場合は phv->phrels を代替として使用する。また、アペンドリレーション（継承テーブルなど）の子テーブル用に翻訳された PlaceHolderVar の場合は、親と子のリレーションIDの差分を計算して評価位置を動的に翻訳する複雑なエッジケース処理が含まれている。
