src/backend/optimizer/geqo/geqo_erx.c

概要

src/backend/optimizer/geqo/geqo_erx.c は、遺伝的クエリ最適化（GEQO）における辺組換え交叉（Edge Recombination Crossover, ERX）アルゴリズムを実装するソースファイルです。Genitor アルゴリズムをベースとしており、2つの親ツアーからエッジ（都市間の接続関係）のテーブルを構築し、共有エッジや残りエッジの少ない候補を優先しながら新しい子ツアーを生成します。ファイル全体が #if defined(ERX) によって条件付きコンパイルされます。

モジュール内での役割

src/backend/optimizer/geqo モジュール内の交叉バリアントの一つとして機能します。親ツアーの順列からエッジ情報を抽出して Edge 構造体を組み立て、局所的な接続パターンを維持した子ツアーを作成する責務を持ちます。

責務

  • **エッジテーブルの管理**: 1 から num_gene までのノードを直接インデックスできるようにメモリ確保 (alloc_edge_table) および解放 (free_edge_table) を行う。
  • **エッジテーブルの構築**: 2つの親ツアーの循環エッジを走査し、双方向のエッジを登録、重複エッジを負の値としてマークして共有エッジを識別する (gimme_edge_table, gimme_edge)。
  • **ツアーの生成**: エッジテーブルから遺伝子を選択して新しいツアーを構築する。共有エッジへの優先付与や、エッジ切れ時のフォールバック処理を行う (gimme_tour, gimme_gene, edge_failure)。
  • **遺伝子の除去**: ツアーに組み込まれた遺伝子をエッジテーブルから動的に削除し、関連する参照を更新する (remove_gene)。

重要なシンボル

メモリライフサイクル管理

  • alloc_edge_table(PlannerInfo *root, int num_gene): num_gene + 1 個の Edge 配列を palloc_array で確保する（1-based indexing 対応のため 0 番目は未使用）。
  • free_edge_table(PlannerInfo *root, Edge *edge_table): 確保されたエッジテーブルのメモリを pfree で解放する。

エッジテーブル構築

  • gimme_edge_table(PlannerInfo *root, Gene *tour1, Gene *tour2, int num_gene, Edge *edge_table): 2つの親ツアーからエッジテーブルを初期化・充填し、平均エッジ数/都市を返す。
  • gimme_edge(PlannerInfo *root, Gene gene1, Gene gene2, Edge *edge_table): gene1 から gene2 へのエッジを登録する。既存の場合は負の値（共有エッジ）にマークし 0 を返し、新規追加時は 1 を返す。

ツアー生成と遺伝子選択

  • gimme_tour(PlannerInfo *root, Edge *edge_table, Gene *new_gene, int num_gene): ランダムな開始遺伝子から始めてツアーを構築し、エッジ障害の総数を返す。
  • gimme_gene(PlannerInfo *root, Edge edge, Edge *edge_table): 負の共有エッジや、残り未消費エッジ数が最小の候補を優先して次の遺伝子を選択する。
  • remove_gene(PlannerInfo *root, Gene gene, Edge edge, Edge *edge_table): 指定された遺伝子を他のエッジリストから削除し、unused_edges をデクリメントする。
  • edge_failure(PlannerInfo *root, Gene *gene, int index, Edge *edge_table, int num_gene): エッジの枯渇（デッドロック）が発生した際、総エッジ数が4のノード、残りのエッジを持つノード、または最後の未試行ノードをフォールバックとして選択する。

制御フローとデータフロー

1. **初期化**: alloc_edge_table が呼び出され、num_gene + 1 サイズの Edge 配列が割り当てられる。 2. **エッジ抽出**: gimme_edge_table が 2 つの親ツアー (tour1, tour2) を受け取り、各循環ペアに対して gimme_edge を双方向（計4回/ステップ）に呼び出してエッジリストを構築する。重複エッジは負の値に変換され「共有エッジ」となる。 3. **ツアー組み立て (gimme_tour)**:

  • ランダムに選んだ最初の遺伝子を new_gene[0] とする。
  • ループ内で remove_gene を呼び出して直前の遺伝子をエッジテーブルから除外し、edge_table[...] の状態を更新する。
  • unused_edges > 0 の場合は gimme_gene を呼び出して次の遺伝子を選択する。
  • unused_edges == 0 の場合は edge_failure にフォールバックし、代替の遺伝子を復旧選択する。

    • 4. **クリーンアップ**: 処理完了後、free_edge_table でエッジテーブルのメモリが解放される。

読者向けメモ

  • **メモリレイアウト**: 1-based indexing を前提としており、num_gene + 1 のアロケーションを行いインデックス 0 は使用されない。
  • **イン方バリアント**: 組み込まれたノードは unused_edges = -1 に設定されることで、再訪問や誤選択から除外される。
  • **エラー処理**: gimme_gene や edge_failure で予期せぬ状態に陥った場合は elog(ERROR) または elog(LOG) により異常終了またはログ出力が行われる。
