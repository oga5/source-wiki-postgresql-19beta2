src/backend/optimizer/geqo/geqo_pool.c

概要

遺伝的アルゴリズム（GEQO）の個体群プール（Pool）および個体（Chromosome）のメモリ管理、初期化、ソート、およびプール内への個体挿入を管理します。

モジュール内での役割

src/backend/optimizer/geqo サブシステムにおいて、遺伝的アルゴリズムが探索空間を効率的に探索するための個体群（Pool）の基盤データ構造とライフサイクルを担います。評価関数や突然変異、組み換え処理と連携します。

責務

  • **プールと個体のメモリ管理**: Pool および Chromosome 構造体、内部の遺伝子配列（Gene 配列）の動的割当（palloc系）と解放（pfree系）。
  • **プールの初期化**: ランダムな初期ツアーの生成と評価を行い、有効な個体群でプールを満たす。
  • **プールの整列**: 評価値（worth）に基づくプールの昇順ソート。
  • **個体の挿入と置換**: 新しい個体をプール内の適切な位置にバイナリサーチで挿入し、最も評価の低い既存個体を押し出す。

重要なシンボル

プール・個体のメモリ管理とライフサイクル

  • alloc_pool: 指定されたプールサイズと文字列長に基づき、Pool 構造体、個体配列、および各個体の遺伝子配列領域を一括して割り当てます。
  • free_pool: プールが保持するすべての個体の遺伝子配列、個体配列、およびプール構造体自体のメモリを解放します。
  • alloc_chromo: 単体の Chromosome 構造体と遺伝子文字列領域を割り当てます。
  • free_chromo: 単体の Chromosome とその遺伝子文字列のメモリを解放します。

プールの初期化と評価

  • random_init_pool: init_tour と geqo_eval を用いてプール内をランダムな個体で満たします。無効な個体（評価値が DBL_MAX）は破棄され、10,000回連続して有効な個体が作れない場合はエラーとなります。
  • geqo_eval: 外部関数。個体の遺伝子配列のコスト（評価値）を算出します。
  • init_tour: 外部関数。遺伝子配列をランダムな初期ツアーで初期化します。
  • DBL_MAX: 無効な個体やコスト上限を判定するための浮動小数点数の最大値。

プールの操作とソート

  • sort_pool: qsort と compare 関数を呼び出し、プール内の個体をコストの小さい順（最良から最悪）にソートします。
  • compare: qsort 用の比較関数。2つの Chromosome の worth を比較します。
  • spread_chromo: 新しい個体をバイナリサーチでプール内の順位位置に挿入し、あふれた最悪の個体をプールから除外します。新個体が既存の最悪個体より劣る場合は何もしません。
  • Chromosome: 遺伝子配列（string）と評価コスト（worth）を保持する個体データ構造。
  • Pool: 複数の Chromosome（data）とプールサイズ、文字列長を保持するデータ構造。

制御フローとデータフロー

1. **プールの生成**: alloc_pool が呼び出され、PostgreSQLのメモリコンテキスト上に Pool と配下の Chromosome 群が確保されます。 2. **初期化フロー**: random_init_pool がループを回し、init_tour で遺伝子を生成後、geqo_eval でコストを評価します。有効なコスト（< DBL_MAX）を持つ個体のみがプールに登録されます。 3. **ソートと維持**: プールは sort_pool によりコスト順に並べ替えられます。探索の過程で新しい個体が生成されると、spread_chromo がバイナリサーチで挿入位置を特定し、ワースト個体を押し出す形でプールを更新します。 4. **解放フロー**: 終了時に free_pool が呼ばれ、個体の文字列領域からプール本体まで逆順にメモリが解放されます。

読者向けメモ

  • **メモリ所有権**: プールが保持する個体の文字列配列は alloc_pool 内で個別に確保されるため、free_pool では個体ごとに pfree を実行してメモリリークを防いでいます。
  • **エラーパス**: random_init_pool では、無効なツアーが10,000回連続した場合に無限ループを防ぐため elog(ERROR, ...) で処理を中断します。
