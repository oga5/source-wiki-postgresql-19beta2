src/backend/optimizer/geqo/geqo_main.c

概要

src/backend/optimizer/geqo/geqo_main.c は、遺伝的アルゴリズム（GA）を用いた問い合わせ最適化（GEQO）のエントリポイントおよびメインループを提供するファイルです。制約付き巡回セールスマン問題（TSP）に似たアプローチで、結合順序の探索空間から最適なクエリツリーを決定します。

モジュール内での役割

  • GEQOモジュールの中核として機能し、周辺の選択、再結合、評価、プール管理などのサブコンポーネントを統合します。
  • geqo() 関数を通じて PostgreSQL の標準オプティマイザから呼び出され、最終的な最適化済み RelOptInfo を返します。
  • コンパイル時のマクロ定義（ERX, PMX, CX, PX, OX1, OX2）に基づき、多様な交叉メカニズムの切り替えを隠蔽します。

責務

  • 遺伝的アルゴリズムのパラメータ（世代数やプールサイズ）を初期化・決定する。
  • 遺伝的プールのメモリ割り当て、ランダム初期化、および初期フィットネスソートを行う。
  • 選択、交叉、評価、世代交代（プールへの組み込み）を反復するメインループを実行する。
  • 最適な遺伝子配列（ツアー）を復元し、クエリツリー（RelOptInfo）を構築して返却する。

重要なシンボル

  • geqo: クエリ最適化問題を解くためのメインエントリー関数。
  • gimme_pool_size: 設定値や関係数に基づいて遺伝的プールのサイズを計算・決定する補助関数。
  • gimme_number_generations: プールサイズや設定値に基づき実行世代数を決定する補助関数。
  • Geqo_effort / Geqo_pool_size / Geqo_generations / Geqo_selection_bias / Geqo_seed: GAの挙動を制御するグローバル設定変数。

制御フローとデータフロー

1. 初期化: geqo() が呼ばれると、プライベート拡張状態を設定し、乱数シードを初期化します。 2. パラメータとプール構築: gimme_pool_size() と gimme_number_generations() でパラメータを決定し、alloc_pool と random_init_pool で初期プールを作成・ソートします。 3. 世代ループ: 指定された世代数だけ以下を繰り返します。

  • geqo_selection を用いて親（momma, daddy）を選択する。
  • コンパイル時マクロに応じた交叉アルゴリズムを実行し、子（kid）を生成する。
  • geqo_eval で子のフィットネス（worth）を評価する。
  • spread_chromo でプール内の劣った個体を新しい子で置き換える。

    • 4. 結果の抽出: ループ終了後、プール内の最良個体（pool->data[0]）を取り出し、gimme_tree を介して最終的なクエリツリー（RelOptInfo）を構築して返します。

読者向けメモ

  • 交叉方式はコンパイル時オプション (ERX, PMX, CX, PX, OX1, OX2 のいずれか) によって決定され、未定義の場合はコンパイルエラーとなります。
  • メモリリークを防ぐため、ループ内で動的に確保された染色体、エッジテーブル、都市テーブル、およびプールは、関数終了時に確実に解放されます。
