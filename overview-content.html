  7. File: src/backend/optimizer/geqo/geqo_erx.c制御フローとデータフロー

    1. **初期化**: alloc_edge_table が呼び出され、num_gene + 1 サイズの Edge 配列が割り当てられる。 2. **エッジ抽出**: gimme_edge_table が 2 つの親ツアー (tour1, tour2) を受け取り、各循環ペアに対して gimme_edge を双方向（計4回/ステップ）に呼び出してエッジリストを構築する。重複エッジは負の値に変換され「共有エッジ」となる。 3. **ツアー組み立て (gimme_tour)**:

    • ランダムに選んだ最初の遺伝子を new_gene[0] とする。
    • ループ内で remove_gene を呼び出して直前の遺伝子をエッジテーブルから除外し、edge_table[...] の状態を更新する。
    • unused_edges > 0 の場合は gimme_gene を呼び出して次の遺伝子を選択する。
    • unused_edges == 0 の場合は edge_failure にフォールバックし、代替の遺伝子を復旧選択する。

      • 4. **クリーンアップ**: 処理完了後、free_edge_table でエッジテーブルのメモリが解放される。

  8. File: src/backend/optimizer/geqo/geqo_eval.c制御フローとデータフロー

    1. **エントリー（geqo_eval）**:

    • geqo_main.c 等から呼び出され、専用の GEQO メモリコンテキストを作成。
    • PlannerInfo 内の join_rel_list の長さを保存し、join_rel_hash を一時的に退避（評価中の破壊的変更を防ぐため）。

      • 2. **ツリー構築（gimme_tree）**:

    • ツアー内の各遺伝子（リレーションID）を順に読み込み、サイズ1の Clump を作成。
    • merge_clump を呼び出し、desirable_join が真（結合条件あり）となる既存クランプと優先的にマージ。

      • 3. **強制マージ（Force Join）**:

    • ツアー走査後、複数のクランプが残っている場合（結合条件がない孤立したリレーションなど）、force = true で merge_clump を再実行し、直積を許容して1つのクランプに強制結合。

      • 4. **コスト算出とクリーンアップ**:

    • 最終的に1つの結合リレーションに統合できれば、その最安パスのコスト（cheapest_total_path->total_cost）を適応度として返却。失敗した場合は DBL_MAX を返却。
    • 退避していた join_rel_list を元の長さに切り詰め、GEQO メモリコンテキストを削除。
  9. File: src/backend/optimizer/geqo/geqo_main.c制御フローとデータフロー

    1. **初期化フェーズ**:

    • GetPlannerExtensionId を通じて拡張IDを取得し、プライベートデータと乱数シード（geqo_set_seed）を設定。
    • gimme_pool_size と gimme_number_generations でGAの規模を決定。
    • alloc_pool と random_init_pool により個体群プールを作成し、sort_pool で適合度順にソート。

      • 2. **世代交代ループ**:

    • geqo_selection を呼び出し、親個体（momma, daddy）を選択。
    • 条件付きコンパイル（ERX, PMX, CX, PX, OX1, OX2 のいずれか）に応じて、対応する交叉関数を実行して子個体（kid）を生成。
    • geqo_eval で子個体のフィットネス（コスト）を評価し、spread_chromo でプールへ挿入。

      • 3. **終了フェーズ**:

    • プールの先頭（最良の個体）から gimme_tree を使って最適な RelOptInfo クエリツリーを復元。
    • 割り当てられた個体・プール・テーブル等のメモリを解放し、結果のプランを返却。
  10. File: src/backend/optimizer/geqo/geqo_misc.c制御フローとデータフロー

    1. **呼び出し元からの制御流入**: geqo_main.c などのメインループから、世代の節目やデバッグ要求時に print_gen や print_pool が呼び出されます。 2. **データの集計**:

    • print_gen は、ソート済みの Pool 構造体から、最良（インデックス 0）、最悪（インデックス size - 2 ※最後尾はバッファ）、中央値（インデックス size / 2）を直接取得します。
    • 平均値の算出は avg_pool に委譲され、プール内の全個体の worth を走査して集計します。

      • 3. **ストリームへの書き出し**: 集計されたデータや遺伝子配列は、指定された FILE *fp ストリームへ fprintf を用いて書き出され、fflush によって即座に出力バッファがフラッシュされます。
