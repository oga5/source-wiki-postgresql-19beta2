Postgresの継続的インテグレーション (CI)

Postgresには2つの形式のCIがあります。

1) メインのpostgresリポジトリでサポートされているすべてのブランチは、 buildfarmを介して継続的にテストされます。これはメインリポジトリのみを 対象としているため、機能の開発中には使用できません。

詳細は https://buildfarm.postgresql.org/ を参照してください。

2) まだマージされていない開発作業については、一部のgitホスティング プロバイダでCIを有効にすることができます。これにより、開発者は パッチがマージされる（あるいは提出される）前に、多数のプラットフォームで テストすることができます。

個人リポジトリでのCIの設定

現在、postgresにはGitHub Actionsを利用したCIサポートが含まれています。

GitHubリポジトリでのCI利用の設定

GitHub ActionsベースのCIワークフローは、リポジトリがいつフォークされたかに応じて、 デフォルトで有効になっている場合とそうでない場合があります。

リポジトリでCIワークフローを無効にするには、 https://github.com/<username>/<reponame>/actions/workflows/pg-ci.yml にアクセスし、右上にある「...」をクリックして「Disable workflow」を選択します。

ワークフローを有効にするには、同じページに移動し、上部にある「Enable workflow」をクリックします。

ただし、postgres/postgresリポジトリの何千ものフォークが、次回postgres/postgresと再同期したときに一斉にCIを実行し始めるという問題を避けるため、各リポジトリは完全なCIテストを実際に実行するために明示的にオプトインする必要があります。

CIにオプトインするには、 https://github.com/<username>/<reponame>/settings/variables/actions にアクセスし、 値が 1 の PG_CI_ENABLED という名前の新しいリポジトリ変数を作成します。

GitHubリポジトリでのCI結果の表示

CIの実行結果は https://github.com/<username>/<reponame>/actions で確認できます。

パブリックリポジトリでのワークフロー実行の概要ステータスは、GitHubにログインしていなくても表示されますが、ログを含む詳細を表示するにはログインが必要です。

CIで使用されるコンテナ / イメージ

CIの実行時間を許容範囲内に抑えるため、いくつかのプラットフォームでは事前に生成されたコンテナ / イメージを使用しています。コンテナとイメージはCIの実行とは別に生成されます。そうしないと、テスト対象の各gitリポジトリが独自のコンテナセットをビルドする必要があり、スペースと時間の両面で無駄が生じるためです。

これらのコンテナ / イメージは、github.com/anarazel/pg-vm-images/ の仕様から毎日ビルドされています。

コミットメッセージによるCIの制御

CIの動作は、コミットメッセージ内の特別な記述によって制御できます。現在、以下の制御が利用可能です。

  • ci-os-only: {(compilerwarnings|linux|macos|mingw|sanitycheck|windows)}

指定されたオペレーティングシステムでのみCIを実行します。これは、プラットフォームの一部にのみ影響する移植性の問題に対処する場合に便利です。
