src/tools/pginclude/README

このディレクトリには、PostgreSQLのソースコードにおけるヘッダファイルとインクルードを管理するためのスクリプトと情報が含まれています。

include-what-you-use

include-what-you-use (IWYU) (<https://include-what-you-use.org/>) は、Cソースファイル内の不足している、または余分なインクルードを見つけるためのツールです。

コンパイルデータベース（mesonによって生成される compile_commands.json）を使用すると、ソースツリー全体に対して以下のように実行できます。

iwyu_tool.py -p build .

（これはおそらく非常にノイズが多くなります）または、個々のファイルに対して実行できます。

iwyu_tool.py -p build src/bin/psql/startup.c

他にも様々な起動オプションが利用可能です。

少なくともバージョン0.23を使用することをお勧めします。それより前のバージョンでは、コンパイラの警告オプション -Wmissing-variable-declarations と互換性のないアドバイスが提供されます。

clangd（言語サーバー）は、自動的にIWYUスタイルのアドバイスを提供できます。 <https://clangd.llvm.org/guides/include-cleaner> を参照してください。

ソースコードには、PostgreSQLのインクルードファイルの規約（特定のソースファイルで使用されるシンボルを提供しない場合でも、"postgres.h" などのヘッダを常にインクルードする必要があるなど）をIWYUに伝え、修正が困難な少数の警告を抑制するための「IWYU pragma」コメントが含まれています。これらに関するドキュメントについては、<https://github.com/include-what-you-use/include-what-you-use/blob/master/docs/IWYUPragmas.md> を参照してください。

もちろん、このツールや他のツールによって提案されたインクルードの変更は、慎重にチェックして検証する必要があります。一部のインクルードは特定のプラットフォームや特定のコンパイルオプションでのみ使用されるため、出力されたアドバイスに盲目的に従うことはお勧めしません。

headerscheck

このスクリプトを実行すると、すべてのPostgresインクルードファイルが、プロジェクトの規約である「スタンドアロン」でコンパイルできること、つまり、postgres.h（または必要に応じて postgres_fe.h や c.h）以外の前提条件となるヘッダなしでコンパイルできることを検証できます。

少数のヘッダファイルはこの要件から除外されており、headerscheck スクリプトによってスキップされます。

スクリプトを実行する簡単な方法は、ビルド完了後にトップレベルのビルドディレクトリで "make -s headerscheck" を実行することです。configure オプションに少なくとも以下を含めておく必要があります。

--with-llvm --with-perl --with-python

そうしないと、関連するヘッダが見つからないというエラーが発生する可能性があります。

mesonを使用する場合は、"meson compile -C build headerscheck" または "ninja -C build headerscheck" を実行します。

現在のスクリプトの制限事項として、どのヘッダがフロントエンド用で、どのヘッダがバックエンド用であるかを正確に把握できないことが挙げられます。疑わしい場合は、postgres_fe.h や c.h の方が適切であっても、前提条件として postgres.h を使用します。また、マクロの内容はチェックされません。これは意図的なものです。

headerscheck --cplusplus

--cplusplus モードの headerscheck を実行すると、すべてのPostgresインクルードファイルが、C++コードとしてコンパイルできるというプロジェクトの規約を満たしていることを検証できます。プロジェクトの開発言語はCですが、C++で拡張機能を作成する人もいるため、インクルードファイルがC++クリーンであることは有用です。

少数のヘッダファイルはこの要件から除外されており、--cplusplus モードではスクリプトによってスキップされます。

スクリプトを実行する簡単な方法は、ビルド完了後にトップレベルのビルドディレクトリで "make -s cpluspluscheck" を実行することです。configure オプションに少なくとも以下を含めておく必要があります。

--with-llvm --with-perl --with-python

そうしないと、関連するヘッダが見つからないというエラーが発生する可能性があります。

mesonを使用する場合は、"meson compile -C build cpluspluscheck" または "ninja -C build cpluspluscheck" を実行します。

現在のスクリプトの制限事項として、どのヘッダがフロントエンド用で、どのヘッダがバックエンド用であるかを正確に把握できないことが挙げられます。疑わしい場合は、postgres_fe.h や c.h の方が適切であっても、前提条件として postgres.h を使用します。また、マクロの内容はチェックされません。これは意図的なものです。
