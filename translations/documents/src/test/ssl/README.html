src/test/ssl/README

SSL回帰テスト

このディレクトリには、SSLサポート用のテストスイートが含まれています。サーバー証明書の検証などのクライアント側の機能と、証明書による認可などのサーバー側の機能の両方をテストします。

注意：このテストで実行されるテストサーバーは、localhost上のTCP接続を監視するように構成されています。テストの実行中、同じホスト上の任意のユーザーがテストサーバーにログインできます。すべてのローカルユーザーを信頼できないマルチユーザーシステムでは、このスイートを実行しないでください！

テストの実行

注意：configureに--enable-tap-tests引数を指定している必要があります。また、"make installcheck"を使用するには、コアコードに加えてcontrib/sslinfoをビルドしてインストールしておく必要があります。

以下を実行します。 make check PG_TEST_EXTRA=ssl または make installcheck PG_TEST_EXTRA=ssl 以前に"make install"を実行している場合は、"make installcheck"を使用できます。その場合、インストールツリー内のコードがテストされます。"make check"を使用すると、現在のソースから一時的なインストールツリーがビルドされ、それがテストされます。

どちらの方法でも、このテストは他のローカルユーザーがアクセス可能なテスト用Postgresクラスターを初期化、起動、および停止します！

これらのテストの実行に関する詳細については、src/test/perl/READMEを参照してください。

証明書

テストスイートを実行するには、一連の公開鍵/秘密鍵のペアと証明書が必要です。

root_ca ルートCA。サーバーおよびクライアントのCA証明書の署名に使用されます。

server_ca サーバー証明書の署名に使用されるCA。

client_ca クライアント証明書の署名に使用されるCA。

server-cn-only server-cn-and-alt-names server-single-alt-name server-multiple-alt-names server-no-names サーバー証明書。証明書に含まれるホスト名にわずかなバリエーションがあります。server_caによって署名されています。

server-password server-cn-onlyと同じですが、パスワードで保護されています。

client ユーザー"ssltestuser"用のクライアント証明書。client_caによって署名されています。

client-revoked "client"と同様ですが、クライアントCAのCRLで失効としてマークされています。

さらに、さまざまな証明書を同じファイルに結合したファイルがいくつかあります。

both-cas-1 root_ca.crt、client_ca.crt、server_ca.crtの順で含まれています。

both-cas-2 root_ca.crt、server_ca.crt、client_ca.crtの順で含まれています。

root+server_ca root_crtとserver_ca.crtが含まれています。クライアントの"sslrootcert"オプションとして使用します。

root+client_ca root_crtとclient_ca.crtが含まれています。サーバーの"ssl_ca_file"として使用します。

client+client_ca client.crt、client_ca.crtの順で含まれています。クライアントの証明書チェーンとして使用します。

各CAのCRL（root.crl、server.crl、client.crl）もあります。

便宜上、これらのキーペアと証明書はすべてssl/サブディレクトリに含まれています。また、Makefileには、変更を加える必要がある場合にこれらを再作成するためのルール"make sslfiles"が含まれています。キーペアと証明書の完全なセットを再作成するには、"make sslfiles-clean"が必要です。個別のファイルを再構築するには、該当するファイルをtouch（または削除）して"make sslfiles"を実行します。この手順には、少なくともOpenSSL 1.1.1が必要です。

注意

これらの証明書は、LDAPテストなど、他のテストでも使用されます。
