libpq のテストプログラムとライブラリ

Test::Differences がインストールされている場合、トレースファイルの差異は標準フォーマットよりも読みやすい形式で表示されます。

このモジュールは libpq の「パイプライン」モードをテストするために開発されましたが、特殊な C コードを必要とする libpq のテストであればどのようなものでも使用できます。

"make check" を実行すると、モジュール内のすべてのテストが一時的なサーバーインストールに対して実行されます。

特定のテストを手動で実行するには、次のように実行します。

./libpq_pipeline <name of test> [ <connection string> ]

これにより新しいサーバーは起動せず、接続文字列で指定されたサーバー、または省略した場合はデフォルトのサーバーに接続します。利用可能なテスト名を確認するには、次を実行します。

./libpq_pipeline tests

このモジュールに新しいテストを追加するには、libpq_pipeline.c を編集する必要があります。テストを実行する関数を追加し、新しいテストの名前がプログラムに渡されたときに main() がそれを呼び出すように手配します。テストの名前を print_test_list() 関数に追加するのを忘れないでください。忘れると TAP テストがそれを実行しません。

テストにおける Postgres プロトコルメッセージの送信順序が決定論的な場合は、TAP テストによってメッセージシーケンスが検証されるように手配する必要があります。まず、次のようなコマンドを使用して、リファレントレースファイルを生成します。

./libpq_pipeline -t traces/mynewtest.trace mynewtest

次に、t/001_libpq_pipeline.pl ファイルの $cmptrace 定義にあるリストにテストの名前を追加します。"make check" を数回実行して、トレース出力が実際に安定していることを確認してください。
