test_regex は、正規表現パッケージをテストするためのモジュールです。 主に、Tcl の正規表現テストスイートを取り込めるようにすることを意図しています。 そのため、現在 PostgreSQL によって SQL レベルで公開されていない正規表現機能を検証するための仕組みが含まれています。

現在、1つの関数が提供されています。

test_regex(pattern text, string text, flags text) returns setof text[]

パターンが無効な正規表現である場合はエラーを報告します。それ以外の場合、出力の最初の行には部分式の数が含まれ、その後に正規表現の re_info フィールドにあるセットされたビットを報告する単語が続きます。 パターンが文字列に一致しない場合は、それだけで終了します。 パターンが一致する場合、次の行には最初の配列要素として全体の一致が含まれます。括弧で囲まれた部分式がある場合、後続の配列要素にはそれらの部分式への一致が含まれます。 "g" (グローバル) フラグが設定されている場合、追加の出力行でも同様に追加の一致が報告されます。

"flags" 引数は、正規表現パッケージまたはテスト関数の動作を変更する、0個以上の1文字のフラグからなる文字列です。Tcl の reg.test ファイルに記載されているように、以下のようになります。

フラグ文字は複雑で、少し折衷的です。一般的に言って、 小文字はコンパイルオプション、大文字は期待される re_info ビット、 非アルファベット文字は一致オプション、テストの実行方法の制御、またはテストオプションです。 ちょっとした意外な点として、ARE がデフォルトであり、より下位のフレーバーの RE を明示的に要求する必要があることです。 フラグは以下の通りです。一部はあまり覚えやすくないことを認めます。

  • 何もしない (プレースホルダー)

    • 0 実際の文字列ではなくインデックスを報告する (これは Tcl の -indices スイッチの代わりになります) ! 部分一致を期待し、とにかく開始位置を報告する % マッチャー内の小さな状態セットキャッシュを強制する (キャッシュ置換をテストするため) ^ 文字列の先頭は行の先頭ではない $ 文字列の終端は行の終端ではない

  • テストは Unicode 固有であり、大きな文字セットが必要

    • + 偽の xy 同値クラスと ch 照合要素を提供する (注意: 同値クラスは実装されていますが、 照合要素は実装されていないため、[.ch.] への参照は失敗します) , REG_PROGRESS を設定する (REG_DEBUG ビルドでのみ有効) . REG_DUMP を設定する (REG_DEBUG ビルドでのみ有効) : REG_MTRACE を設定する (REG_DEBUG ビルドでのみ有効) ; REG_FTRACE を設定する (REG_DEBUG ビルドでのみ有効)

& ARE と BRE の両方としてテストする (Postgres では実装されておらず、個別のテストを使用します) b BRE e ERE a 高度な機能ビットをオンにする (ERE でない限りエラー) q リテラル文字列、メタ文字は一切なし

g グローバルマッチ (すべての一致を検索) i 大文字小文字を区別しない一致 o ("不透明" - opaque) 一致位置を返さない p 改行文字は半マジックであり、. と [^ のみから除外される w 改行文字は半マジックであり、^ と $ のみに意味を持つ n 改行文字は完全マジックであり、両方の効果を持つ x 拡張 RE 構文 t 不完全一致の報告 c canmatch (Postgres 実装における "t0!" と同等) s 先頭のみで一致 (REG_BOSONLY)
