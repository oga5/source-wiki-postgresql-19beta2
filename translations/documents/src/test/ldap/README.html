src/test/ldap/README

LDAP機能のテスト

このディレクトリには、LDAP機能のテストスイートが含まれています。これには、サーバーおよびクライアントツールを含む完全なOpenLDAPのインストールが必要であるため、別個に管理され、デフォルトでは実行されません。想定されていない場所にOpenLDAPがある場合、それを見つけられるようにテストファイル内のいくつかのパスを調整する必要があるかもしれません。

また、このテストスイートは、実質的なアクセス制御なしでlocalhost上のTCP/IP接続を監視するLDAPサーバーを作成するため、信頼できないローカルユーザーが存在する可能性のあるシステムでこれを実行することは安全ではありません。

テストの実行

注意: configureに--enable-tap-tests引数を指定しておく必要があります。

以下を実行します。 make check PG_TEST_EXTRA=ldap または make installcheck PG_TEST_EXTRA=ldap 以前に"make install"を実行している場合は、"make installcheck"を使用できます。その場合、インストールツリー内のコードがテストされます。"make check"を使用すると、現在のソースから一時的なインストールツリーが構築され、テストされます。

どちらの方法でも、このテストはテスト用のPostgresクラスターとテスト用のLDAPサーバーを初期化、起動、および停止します。

これらのテストの実行に関する詳細については、src/test/perl/READMEを参照してください。

要件

LDAPサーバーとクライアントツールが必要です。

Debian/Ubuntuパッケージ: slapd ldap-utils

RHEL/CentOS/Fedoraパッケージ: openldap-clients openldap-servers （ビルドにはすでにopenldapとopenldap-develが必要であったはずです。）

FreeBSD: openldap-server （ビルドにはすでにopenldap-clientが必要であったはずです。portsソースツリーからビルドする場合は、net/openldap24-clientとnet/openldap24-serverをビルドすることになります。）

macOS: Appleが提供するバージョンのOpenLDAPを使用することはお勧めしません。非常に古く、さらにAppleはslapdの起動規約を変更したようです。テストファイル内のパスは、HomebrewまたはMacPortsを使用してOpenLDAPをインストールしたという前提で設定されています。
