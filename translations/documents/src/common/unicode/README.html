Translation complete.

このディレクトリには、新しいUnicodeデータファイルをダウンロードし、静的テーブルを生成するためのツールが含まれています。これらのテーブルは、Unicodeデータの正規化や、さまざまなプロパティの判定に使用されます。

生成されたヘッダーファイルは src/include/common/ にコピーされ、ソースツリーに含まれるため、通常、PostgreSQLのビルドにこれらのツールは必要ありません。

Unicodeバージョンの更新 ----------------------

src/Makefile.global.in と src/common/unicode/meson.build を編集して、UNICODE_VERSION と CLDR_VERSION を更新します。

その後、以下を実行して新しいヘッダーファイルを生成します。

make update-unicode

または、mesonを使用している場合：

ninja update-unicode

これらはソースツリーのトップレベルから実行します。結果を確認して、変更内容が妥当であること（つまり、差分のサイズと範囲が前回の更新以降のUnicodeの変更に見合っていること）を確認し、コミットします。

テスト -----

正規化テスト：

Unicodeコンソーシアムは、NormalizationTest.txt というファイルで、正規化アルゴリズムの包括的なテストスイートを公開しています。このディレクトリには、NormalizationTest.txt 内のすべてのテスト文字列を使用して、私たちの正規化コードを実行するためのPerlスクリプトとCコードも含まれています。NormalizationTest.txt をダウンロードしてテストを実行するには、以下のようにします。

make normalization-check

これは update-unicode ターゲットの一部としても実行されます。

カテゴリ、プロパティ、大文字小文字のテスト：

case_test.c と category_test.c ファイルは、ICUとの結果を網羅的に比較することで、Unicodeのカテゴリ、プロパティ、大文字小文字のマッピングをテストします。これらのテストを効果的に行うには、Unicodeデータファイルのバージョンが、ICUがベースにしているUnicodeのバージョンと類似している必要があります。Unicodeのバージョンが一致していない場合、一方のバージョンで割り当てられていて他方では割り当てられていないコードポイントがテストでスキップされ、誤って失敗が報告される可能性があります。このテストは update-unicode ターゲットの一部として実行されます。
