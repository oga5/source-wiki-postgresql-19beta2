このディレクトリには、バックエンド内のどこでも使用できる汎用的なデータ構造が含まれています。

bipartite_match.c - 二部グラフのためのホップクロフト・カープ最大マッチングアルゴリズム

bloomfilter.c - 確率的で空間効率の良い集合メンバーシップテスト

dshash.c - 動的共有メモリ領域をバックエンドとする並行ハッシュテーブル

hyperloglog.c - ストリーミングカーディナリティ推定器

ilist.c - 単方向および双方向連結リスト

integerset.c - 大きな整数の集合を保持するためのデータ構造

knapsack.c - ナップサック問題のソルバー

pairingheap.c - ペアリングヒープ

rbtree.c - 赤黒木

データ構造が持つ固有の特性のほかに、バイナリヒープとペアリングヒープの間にはいくつかの実用的な違いがあります。バイナリヒープは作成時に完全に割り当てられ、割り当てられたサイズを超えて拡張することはできません。一方、ペアリングヒープには固有の最大サイズはありませんが、呼び出し側はヒープに格納される各要素を割り当てる必要があり、バイナリヒープは通常の Datum やポインターを扱います。

ilist.c の連結リストは、nodes/pg_list.h の List インターフェースとは対照的に、他の構造体に直接埋め込むことができます。
