拡張統計情報

様々な量（例：条件の選択率）を推計する際、デフォルトのアプローチは独立性の仮定に依存しています。実践ではそれが成り立たないことが多く、推計エラーを引き起こします。

拡張統計情報は列間の様々なタイプの依存関係を追跡し、推計を改善してより良い計画を作成することを期待させます。

統計情報のタイプ

現在、いくつかの種類の拡張統計情報があります：

(a) ndistinct 係数

(b) 緩やかな関数従属 (README.dependencies)

(c) MCV リスト (README.mcv)

互換性のある句のタイプ

それぞれの統計情報のタイプは、句のタイプのいくつかのサブセットを推計するために使用される場合があります。

(a) 関数従属 - 等価句 (AND)、場合により IS NULL

(b) MCV リスト - 等価および非等価句 (AND、OR、NOT)、IS [NOT] NULL

現在、Var op Const または Const op Var の形式の OpExpr のみがサポートされていますが、将来的にコードを拡張して Var op Var などの句の選択率も推計できるようにすることは実行可能です。

複雑な句

また、より複雑な句（基本的には (Var op Const) を葉とする AND/OR 句）の推計もサポートしています。ただし、参照されるすべての属性が単一の統計情報オブジェクトによってカバーされている場合に限ります。

例えば、この条件

(a=1) AND ((b=2) OR ((c=3) AND (d=4)))

は、(a,b,c,d) の統計情報を使用して推計される場合があります。(b,c,d) の統計情報しかない場合は、後半部分を推計し、単純な統計情報を使用して (a=1) を推計することができます。

(a,b,c) の統計情報しかない場合は現時点ではまったく適用できませんが、clauselist_selectivity() は再帰的に動作し、後半部分（OR 句）を処理する際には統計情報を適用できるようになるという点は指摘する価値があります。

注意: 複数統計情報の推計パッチにより、一部の句を「条件」として式ツリーのより深い部分に渡すことも可能になります。

選択率の推計

プランナ全体を通して、clauselist_selectivity() が依然としてほとんどの選択率推計リクエストを担当しています。clauselist_selectivity() は、指定された RelOptInfo に対する拡張統計情報の利用を試みるよう指示されることがあり、それは以下の場合に行われます：

(a) 実際に有効な RelOptInfo が渡された場合。結合リレーションは NULL として渡されるため、無効です。

(b) 渡されたリレーションに、実際に構築されている拡張統計情報が定義されている場合。

上記の条件が満たされた場合、clauselist_selectivity() はまず、句のリストを拡張統計情報の選択率推計関数に渡そうとします。この関数は、推計を実行できる句を全く見つけられない場合があります。そのような場合、これらの句は単に無視されます。これらの関数で実際の推計作業が行われる場合、他の推計を実行する関数がどの句をスキップすべきかを把握できるように、どの句に対して推計を実行したかをマークすることが期待されます。

ANALYZE におけるサンプルのサイズ

ANALYZE を実行する際、サンプリングする行数は次のように決定されます：

(300 * statistics_target)

これは個別の列の統計情報に対してはそこそこうまく機能しますが、拡張統計情報に対しては十分ではないかもしれません。推計エラーを分析した論文では、すべてテーブルに比例したサンプルを使用しています（通常、正確な統計情報を構築するにはテーブルの 1〜3% で十分であることがわかっています）。

サンプルサイズを決定する際には、要求される精度（MCV 項目の数またはヒストグラムのビンの数）も考慮されるべきであり、拡張統計情報ではそれらは必ずしも statistics_target によって制限されません。

しかしながら、これはさらなる議論に値します。なぜなら、サンプルの収集は非常に負荷が高く、さらにそれを増やすと ANALYZE がさらに苦痛なものになるためです。現在の実装による実験から判断すると、固定サイズは今のところそこそこうまく機能しているように見えるため、これは将来の課題として残しておきます。
