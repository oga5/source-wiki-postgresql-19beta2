これは実装に関するいくつかのメモと未解決の問題です...

まず、実装では相関Varsを処理するために、新しいタイプのパラメータであるPARAM_EXECを使用します。query_planner()が呼び出されると、まず現在のクエリで参照されているすべての上位クエリのVarをこのタイプのParamに置き換えようとします。VarsからParamsへのマッピング、およびParamsからVarsへのマッピングを保持するために、いくつかのグローバル変数が使用されます。

この後、現在のクエリのすべてのSubLinkが処理されます。クエリのqualで見つかった各SubLinkに対して、対応するサブクエリを計画するためにunion_planner()（古いplanner()関数）が呼び出されます（union_planner()は「単純な」クエリに対してquery_planner()を呼び出し、UNIONをサポートします）。サブクエリが計画された後、オプティマイザはこれが相関、非相関、または_間接_相関（祖先のVarsを参照しているが、親のVarsは参照していない：親の観点からは非相関）クエリであるかを認識します。

EXPRessionまたはEXISTSタイプの非相関および間接相関サブクエリの場合、SubLinkはSubLink->Operリスト（このリストを単なるOperノードではなく、EXPRノードのリストに変更しました）からの「通常の」句に置き換えられます。これらのノードの右側はPARAM_EXECパラメータに置き換えられます。これが新しいパラメータタイプの2番目の用途です。実行時に、これらのパラメータはサブクエリ評価の結果（すなわち、サブクエリのターゲットリスト）から値を取得します。サブクエリ自体の実行計画は、親クエリの初期計画（init plan）になります。InitPlanは、どのパラメータがサブクエリの結果から値を取得するかを認識しており、「オンデマンド」で実行されます（クエリ select * from table where x > 0 and y > (select max(a) from table_a) では、x > 0 のタプルが存在しない、_かつ_ y がインデックススキャンで使用されていない場合、サブクエリはまったく実行されません）。

他のすべてのタイプのサブクエリのSubLinkは、新しいタイプのExprノードであるSUBPLAN_EXPRに変換されます。Expr->argsは親（_parent_）クエリからの単なる相関変数です。Expr->operは新しいSubPlanノードです。

このノードはInitPlanにも使用されます。これは、サブクエリのレンジテーブル、親（_parent_）クエリのVars（すなわちExpr->args）から値を取得するParamsのインデックス、サブクエリの結果が代入されるParamsのインデックス（これはInitPlans用です）、SubLink、およびサブクエリの実行計画を保持します。

Planノードは、親クエリおよびInitPlansからのParamsへの依存関係を認識し、変更されたParamsのリスト（上記より）を保持し、このリストがNULLでない場合に再スキャンされるように変更されました。また、InitPlansのリスト（実際には、現在のクエリのすべてのInitPlansは現在、最上位のplanノードにあります）および他のSubPlans（plan->qualから）が追加され、これらを初期化し、変更されたParams（彼らの「関心」リストから）について通知します。

すべてのSubLinkが処理された後、query_planner()はqualの正規化処理（canonificator）を呼び出し、「通常の」処理を行います。Paramsを使用することにより、オプティマイザはほとんど変更されません。

さて、Executor（実行部）です。ExecutorStart()やExecutorEnd()を呼び出すことなく（リレーションやインデックスのオープン・クローズを行わず、また多くのpalloc()やpfree()を行うことなく。これはSQL関数が呼び出しごとに行うことです）、サブプランを再評価できるようにするため、ExecReScan()は現在、ほとんどのPlanタイプをサポートしています...

EXPLAINの説明。

vac=> explain select * from tmp where x >= (select max(x2) from test2 where y2 = y and exists (select * from tempx where tx = x)); NOTICE: QUERY PLAN:

Seq Scan on tmp (cost=40.03 size=101 width=8) SubPlan ^^^^^^^ サブクエリはSeq Scanのqualにあり、その計画は以下です -> Aggregate (cost=2.05 size=0 width=0) InitPlan ^^^^^^^^ EXISTSサブサブクエリはサブクエリのInitPlanです -> Seq Scan on tempx (cost=4.33 size=1 width=4) -> Result (cost=2.05 size=0 width=0) ^^^^^^ EXISTSサブサブクエリはParamに変換されたため、 ここにResultノードがあります -> Index Scan on test2 (cost=2.05 size=1 width=4)

いくつかのテスト結果。TMPはx, y（int4）を持つテーブルで、xは0〜9、y = 100 - x、1000タプル（各タプルの重複が10個）。TEST2はx2, y2（int4）を持つテーブルで、x2は1〜99、y2 = 100 - x2、10000タプル（重複100個）。

試行：

select * from tmp where x >= (select max(x2) from test2 where y2 = y);

および

begin; select y as ty, max(x2) as mx into table tsub from test2, tmp where y2 = y group by ty; vacuum tsub; select x, y from tmp, tsub where x >= mx and y = ty; drop table tsub; end;

test2(y2)にインデックスがない場合：

SubSelect -> 320秒 一時テーブルの使用 -> 32秒

インデックスがある場合：

SubSelect -> 17秒 (2Mのメモリ) 一時テーブルの使用 -> 32秒 (12Mのメモリ: -S 8192)
