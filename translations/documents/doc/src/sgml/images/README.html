画像

このディレクトリには、ドキュメントで使用する画像が含まれています。

画像の作成

画像の作成には、さまざまなツールを使用できます。適切な選択は画像の性質によって異なります。私たちは、diff（差分）が取りやすいソースファイルを使用するワークフローを好みます。

以下のツールが使用可能です。

  • Graphviz (https://graphviz.org/)
  • Ditaa v0.11.0以降 (https://github.com/stathissideris/ditaa)

ドキュメントの最終的な出力フォーマット（HTML、PDFなど）に画像を統合するためのフォーマットとして、SVGを使用します。したがって、使用するツールはSVGを出力できる必要があります。

このディレクトリには、一般的な入力フォーマットから共通のスタイリングを適用してSVGをビルドするためのmakefileおよびmesonルールが含まれています。

fixup-svg.xslは、これらの外部ツールによって生成されたSVGファイルにいくつかの後処理を適用し、さまざまな問題に対処します。そこにあるコメントを参照し、必要に応じて調整および拡張してください。

ソースファイルと出力されるSVGファイルの両方がこのディレクトリにコミットされます。これにより、すべての開発者がすべてのツールをインストールしておく必要がなくなります。特定のツールによってはSVG出力に不要な差分が生じる可能性があることは許容しますが、それを監視し、最小限に抑えるようにしましょう。

DocBookでの画像の使用

DocBookで画像を使用する例を以下に示します。

<figure id="gin-internals-figure"> <title>GIN Internals</title> <mediaobject> <imageobject> <imagedata fileref="images/gin.svg" format="SVG" width="100%"/> </imageobject> </mediaobject> </figure>

注意：

  • 実際の処理は <mediaobject> 要素で行われますが、通常はそれを <figure> で囲み、テキストのどこかにその図への <xref> を配置する必要があります。リンクや説明なしに、単に画像をドキュメントに配置することは避けてください。
  • 異なる出力フォーマットであっても、1つの <imagedata> 要素のみが必要となるように設定されています。
  • 属性 format="SVG" が必須です。省略しても動作するように見えますが、画像が明示的にSVGとして宣言されている方が、スタイルシートがより適切に処理を行います。
  • width は何らかの値に設定する必要があります。これにより、PDF出力で画像がページに収まるようにスケーリングされます。（100% 以外の幅が適切な場合もあります。）
